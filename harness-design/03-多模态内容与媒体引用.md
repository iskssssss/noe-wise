# Agent Runtime 多模态内容与媒体引用契约

本文是[核心对象模型与状态机](03-核心对象模型与状态机.md)的专题，定义已批准的通用图片输入、工具回图、模型请求与上下文管理目标。文档不证明这些能力已经实现；宿主上传与展示接口归[接口与事件契约](../docs/02-架构与设计/04-接口与事件契约.md)，图片压力处理与现有文字缩减的组合归[上下文专题](03-上下文视图与执行优化.md)。

## 1. 范围与职责

首期提供有序 Text/Image 内容、可信持久 MediaRef、用户上传与工具回图共用的媒体路径、通用 `read_image`、实际请求变体计量及容量触发的历史图像卸载。图片是独立平台基础能力；BrowserSkill、截图工具、文件读取与其他图片工具均为消费者，不能分别建立图片模型输入通道。首期不扩展音频、视频或模型生成图片协议，不为未来模态预建注册框架。

Runtime API 定义供应商无关的内容和媒体引用语义；Core 组合与选择模型视图；Session 协调持久事实、模型准备和恢复；Provider 内部 Codec 编码实际协议。宿主保存图片字节、执行媒体访问与转换，并提供上传、鉴权展示及工具结果注册。图片调用沿用现有 Tool、Action、权限、预算与未知结果规则。

## 2. 有序内容与图片出现位置

通用消息和工具结果的模型可见内容使用有序 Text/Image 列表。Text 保留原文字，Image 持有可信 MediaRef 与显式展示/请求选项；同一消息中的文字与图片交错顺序不可改变，工具回图不能先转为说明字符串而丢失图片。纯图片输入合法；没有文字、图片或合法业务数据的输入才缺少可准备内容。

MediaRef 标识媒体事实，出现位置标识它在一次已提交消息或工具结果中的使用。出现位置由来源事件、内容项序号和调用关联共同定位，同一媒体多次出现仍是多个独立位置，不能按 SHA 或图片相同去重而改变语义。用户文字、工具文字和图片保持原可信度；工具或图片中存在指令不授予系统权限。

Canonical Conversation IR 的 Message 和 ToolResult 内容承载这些项，ToolCall 与对应 ToolResult 仍以原调用身份配对。协议专有 block、URL、Base64 和供应商 DTO 只在 Provider 内部生成，不成为 Runtime 通用内容或持久媒体身份。

## 3. 可信持久 MediaRef

MediaRef 由宿主完成字节保存、图片类型与尺寸解析及来源归属后发布，包含不透明媒体身份、内容摘要、实际 MIME、字节数、宽高及来源关联等受控元数据。客户端自填 URL、文件路径、MIME 或摘要不能成为可信媒体事实；供应商工具返回的图片字节同样先注册，不能因来自工具而跳过这一步。

媒体记录绑定租户与所属 Session、来源输入或工具 invocation；知道引用不等于有读取权。用户上传和工具回图共享这一存储和读取边界，每次新读取或新模型准备核验当前访问权。成员或委派会话需要明确授权传递，不能隐式继承父会话全部媒体。

只有媒体持久化完成才发布可读 Image 内容。工具业务结果已确定而媒体保存失败时保留真实动作结果与媒体不可用事实，不因此重执行工具；无法满足当前视觉输入时明确停止相关准备。引用和被采用的变体按来源事实、上下文材料及冻结请求的有效引用保留，不能直接套用普通下载产物的短期过期策略。

宿主以租户内单一不可变正文保存图片与普通输入附件的二进制，同租户的相同字节可复用正文；复用须核对完整字节，不能只凭摘要相同。正文身份同时绑定租户、摘要、长度与存储格式，不跨租户共享。每张原图、规范化图、裁剪图和请求变体仍保留各自媒体身份、owner、MIME、来源及转换事实，正文复用不合并这些元数据或改变出现位置。

## 4. 原图、规范化与请求变体

原图保存输入字节与完整性事实，不被后续转换覆盖。规范化图处理图片方向及统一解码结果，与原图保留派生关联。模型请求变体在规范化图基础上按当前冻结模型和协议需要生成尺寸、编码、质量或显式裁剪后的图片，记录变换参数、结果摘要、尺寸、MIME 和字节数。

不同请求变体分别标识；同一原图可以对应多个变体，不能用原图大小或上传压缩比例代替实际请求成本。规范化和变体转换完成后再计量、冻结；恢复使用原已采用变体，不以当前转换配置重新生成历史请求。上传展示缩略图不自动成为模型输入，模型请求变体也不覆盖用户原图。

## 5. 模型与协议能力

模型准备分别核验当前具体冻结模型的视觉输入能力与选定 Provider/Codec 在实际消息位置表达图片的能力。用户消息可发图片不证明原生 ToolResult 也可表达图片，协议支持图片也不证明当前模型可看图；模型发现结果与供应商品牌不能替代能力证据。

Provider 对其支持的消息和工具结果图像位置实现明确编码。协议要求图片以关联消息承载时，Codec 保留原 tool call 关联、内容顺序和来源，不把关联消息误认为新的用户输入。无法正确表达的模型/协议组合明确拒绝；不隐式切换模型，不以 OCR、描述或摘要替代本应发送的图片，也不静默删除 Image 项。文字说明只能作为已有文字事实，不能声称代表未被读取的像素。

## 6. 通用 read_image

`read_image` 接受已授权 MediaRef 和可选裁剪区域，返回有序文字元数据与 Image 内容，走正常 Tool 调用、结果持久化与模型回放路径。默认读取当前媒体的完整规范化图；裁剪以规范化图的像素坐标和明确矩形表达，校验非空且位于图像范围，不静默修正越界区域。

读取结果保留原媒体、裁剪参数及派生变体关联，模型随后按当前请求目标再选择实际发送变体。`read_image` 的裁剪映射明确以裁剪图像素为坐标空间；准备视图在实际 Image 前披露源图/请求图尺寸与请求像素边界到源像素的精确比例，缩放后不能继续声称 1:1。映射说明参与文字计量及冻结。工具不接受任意远程 URL 或宿主路径作为媒体身份，不直接绕过 Provider 向模型发图。历史已卸载图片可通过同一工具显式重载，重载产生新的出现位置和调用事实，继续计入当前请求及工具预算。

## 7. 请求计量与容量

候选计量在实际请求变体确定后进行：文字使用明确 tokenizer 与协议 framing，图片按冻结模型的明确视觉成本口径计量；同时核验图像数量、尺寸约束和实际协议 wire bytes。Base64 编码膨胀计入 wire bytes，不能按普通文字 token 冒充视觉 token。无法取得视觉计量依据时明确拒绝该视觉准备，不用零值或从模型名推测成本。

冻结模型、Codec、图像变体及视觉计量版本，并将逐出现位置成本和请求合计保存到准备事实。Provider 实际 usage 是结算事实，准备视觉 token 是请求预算依据，两者分别报告；总输入成本包含文字、视觉及协议开销，各分量只计一次。数量和 wire bytes 是物理准入维度，不能靠文字摘要证明图片已满足这些限额。具体额度由发布配置与实际模型能力确定，本文不捏造统一图片上限。

持久正文容量独立于模型请求计量和单文件上限。会话累计同一正文只计一次，机构累计包含尚待回收的无引用正文；默认仅观察容量，不设猜测的生产额度。部署配置 `skillforge.chat-storage.max-session-bytes` 与 `skillforge.chat-storage.max-tenant-bytes` 默认均为 `0`，明确表示观测；负数非法，正值分别拒绝超额新增的会话正文归属或机构新正文。同租户跨会话复用既有正文不重复增加机构占用，已绑定的精确重试不因后来调低限额失效。正文注册、容量核算和引用创建共享同一租户锁及外层事务，拒绝或引用创建失败不能留下额外正文。授权会话入口只观察该会话容量，机构累计观察须复核当前机构成员权限及全数据范围。

## 8. 容量触发批量卸载

当完整候选请求的 token 压力、图像数量、wire bytes 或图片桥接派生消息/文字容量达到相应容量处理条件时，一次选择可卸载的历史图像批次，按来源顺序移除其模型视图中的 Image payload，并保留受控媒体引用、出现位置、来源及真实卸载说明，再对完整请求重测。tokenizer 仅以明确的消息/文字物理容量信号触发可恢复卸载，其他配置或计量错误原样失败。无需每张图单独持久化一次视图，也不把近期条数或固定保留图片数当作信息丢弃规则。

当前用户输入中的图片、最新明确纠正涉及的图片和当前决策必须使用的工具图片受保护。保护集合及依据随当次准备冻结；不能为降低成本而静默丢弃当前必要图像。批量卸载不能破坏原调用组或把工具结果变成缺失；文字和调用关联仍按[完整调用组](03-上下文视图与执行优化.md#8-完整调用组)处理。受保护内容仍超硬限时明确失败。

卸载不修改原图、原消息或 SessionLog，也不是图片语义摘要。摘要可以处理已存在的安全文字及媒体定位，不得据此声称已经读懂未发送的图片。需要视觉细节时通过 `read_image` 显式重载；同次读取的新出现位置作为当前必要工具图像参与准备，后续变为历史时才可再次按容量处理。

## 9. SessionLog、冻结与恢复

入站与工具结果事件保存有序内容、可信 MediaRef 和准确出现位置。上下文视图采用事实保存批量卸载范围、保留引用、保护集合与来源版本；模型准备快照保存最终有序内容、实际请求变体、转换与计量版本及成本。事件的名称和 schema 在实施时进入现有封闭注册表，不建立独立媒体事件总线或第二个会话序列。

模型可见内容先取得对应 SessionLog 提交证明，再进入调用准备。相同准备操作重放保持原变体、顺序、卸载结果与计量，不重新查询当前模型能力或重组历史；当前访问权与发送许可仍沿用调用边界校验。缺失媒体或变体明确失败，不能以重新转换、空图片或文字替代修补旧快照。

容量变化或显式重载形成新的准备与视图采用事实，不改写已冻结请求。原失败、未知和成功事实保持各自语义；恢复不重执行已完成的回图工具，不把图片卸载当作外部调用重试许可。

### 9.1. 媒体保护与未使用资源退役

首次读取、公开展示、冻结输入、模型准备、裁剪或工具结果注册形成持久媒体保护；pin 记录第一次引用且不能清空或改写，工具图片的 Run 绑定不能退回未使用状态。原图还受有效来源后代保护，同租户其它媒体或附件对共享正文的引用继续保护该正文。模型视图卸载、普通展示历史退役和终态 Run 均不解除这些保护。

未使用上传图片可以按精确资源闭包退役：原图从未 pin、没有 Run 绑定，其规范化后代也没有实际读取、冻结、恢复、发布、调查或其它有效保护引用，且相关真实 owner 已 `CLOSED` 满 30 天、原图已保存至少 30 天。活跃、等待或 `UNKNOWN` 效果继续保护；没有可靠 Runtime owner 终态事实的分支不能从空表或年龄推断可回收。有效裁剪、模型变体或其它受保护后代阻止其来源退役。

所有合法冻结输入、模型准备、读取及工具回图入口在发布完整媒体引用前遵循同一 pin/Run 与租户锁协议；下游 input、checkpoint、journal 和发布事实继承这个持久保护。原图没有被引用时，同 Session 中无关的永久幂等及恢复历史不构成该图的保留理由。这个证明限于新目标 schema，不引入通用 opaque 历史扫描器，也不以未解析材料推定旧数据没有媒体引用。

资源退役在同一事务先锁 owner 并复核关闭与保护条件，再锁租户和媒体后代元数据，重查实际 pin、Run、来源与正文引用后解除可退役闭包的正文外键。新受理、读取或绑定与该过程互斥；退役后到达的同键上传或引用必须拒绝，不能重新绑定原 UUID。元数据墓碑保留原身份、摘要、长度及来源转换事实，只有全部媒体和附件引用消失后才回收共享正文。原 input receipt、journal、checkpoint 及重放有效性不因媒体资源退役改变。

共享正文与精确外键见 [V284](../backend-java/skillforge-migration/src/main/resources/db/migration/V284__session_media_attachment_body_storage.sql)，Runtime 关闭事实与专属门禁的 schema 归 [V286](../backend-java/skillforge-migration/src/main/resources/db/migration/V286__runtime_session_storage_lifecycle.sql)；媒体引用消费与资源退役分别由 [SessionMediaService](../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/media/SessionMediaService.java) 和 [SessionMediaReclamation](../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/media/SessionMediaReclamation.java)承担，日常有界续接见 [SessionMediaCleanup](../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/media/SessionMediaCleanup.java)。普通输入附件仍按七天到期禁读及有界引用解除处理，环境清理、迁移与存量转换的授权归[清理与保留规范](../docs/04-指南与运维/11-数据清理与保留规范.md)，本文不授权存量环境操作。

## 10. 实施验收边界

按模块集中验证有序 Text/Image 与纯图输入、用户/工具媒体归属、原图和变体分离、Codec 消息与 ToolResult 图片表达、实际变体计量、容量批量卸载及旧快照恢复的直接路径。保留必要的能力不足、越权和受保护内容超限拒绝场景，不扩展为全仓审计。

真实验收分别证明当前具体模型消费图片及所用协议的工具图片回放；Mock 或请求编码检查只证明各自范围。文档完成不代表这些调用已经通过，未实施和未验证范围须在交付说明中如实记录。

媒体存储与退役另需证明同租户正文复用、配置限额拒绝的原子性、跨租户隔离、pin/Run 单调保护、来源后代与共享引用保护、真实 owner/tenant/metadata 锁竞争，以及退役后墓碑防重绑和原幂等回执的精确重放。正式 schema、受限数据库与实际事务行为须以对应验证证据确认；维护代码或测试入口存在不表示这些验收已通过。


### 独立真实视觉验收入口

机构模块提供 `:skillforge-institution-service:liveVisionAcceptanceClasses`（仅编译）和 `:skillforge-institution-service:liveVisionAcceptance`（显式执行）。验证当前发布路由时设置 `LIVE_VISION_MODE=published`，安全加载根环境，并设置 `SKILLFORGE_LIVE_VISION_ACCEPTANCE=1`、`LIVE_VISION_SOURCE_TENANT_ID`、`LIVE_VISION_SOURCE_MODEL_ID`、`LIVE_VISION_SOURCE_MODEL_REVISION` 与 `LIVE_VISION_EVIDENCE_DIR`；指定模型必须是该机构当前选择的精确发布版本。来源数据库事务只读，不自动增加视觉策略、改选模型或修改凭据。

验收图片的形状、颜色和随机码仅存在于像素，经过实际图片准备、`OpenAiModelPort` 与 Provider Codec；保存模型识别结果、实际请求尺寸和供应商 usage。媒体存储与调用许可使用明确的隔离夹具，因此通过仅证明该配置的真实 transport 视觉链路，不能替代完整生产 Session、HTTP 入站和官方浏览器扩展验收。缺少已发布视觉策略时记录明确 `BLOCKED`，在解密和外网发送之前停止。


用户明确授权临时模型配置时，可指定 `LIVE_VISION_MODE=explicit`，同时提供 `LIVE_VISION_SOURCE_TENANT_ID`（仅隔离 owner）、`LIVE_VISION_ENDPOINT`、进程环境中的 `LIVE_VISION_API_KEY` 与证据目录。该模式明确采用百炼 `qwen3-vl-plus` 的文档化视觉策略，独立记录路由来源；不读写共享模型目录，不由 published 模式失败自动进入。两个场景依次验证纯图 USER 与历史 TOOL 图片，首场失败停止，不尝试其他模型或 endpoint。两种模式的结论分别保存，不能用隔离路由通过来声称现有默认模型已具备视觉能力。
