# Agent Runtime 上下文视图与执行优化契约

群上下文沿用本专题的冻结准备和事件重放机制，归属、真实作者/请求者及服务 Agent 见[核心对象 §5.1.1](03-核心对象模型与状态机.md#511-群归属与执行身份目标契约)，群 MemoryOwner、选择/注入和当前治理复验见[架构 §5.8.1](02-微内核插件架构实现思路.md#581-群记忆归属与冻结目标契约)。冻结输入保留历史原样不等于允许继续使用已撤权或已禁止的材料；默认记忆组在该 Run 首次准备选定后固定，按需查询保存自己的稳定选择，恢复不重新检索。普通新偏好用于新 Run，遗忘/退出/禁止使用在材料实际使用前失败关闭，受控重建不重放业务副作用。

本文是 [03-核心对象模型与状态机](03-核心对象模型与状态机.md)的专题，承接已批准的上下文与执行优化决策。它定义目标契约，不证明实现完成；模块归属见 [02 §5.7](02-微内核插件架构实现思路.md#57-会话状态记忆与生命周期)，实施批次及验收见 [06 §10](06-MVP-0技术底座实施方案.md#10-上下文与执行优化实施批次)。

优化目标是消除普通聊天的任务维护前置调用、减少历史信息截断、工具结果膨胀、重复消息转换、串行只读调用和 reasoning 逐片段落库。权限、来源、安全投影、任务隔离、幂等、租约和未知结果边界不因优化而弱化。不新增完整提示词覆盖、独立缓存服务或可观测平台，不预设性能改善比例。

执行与存储粒度统一遵循 [02 §1.5](02-微内核插件架构实现思路.md#15-执行与持久化重构) 与 [03 §10.1](03-核心对象模型与状态机.md#101-执行与持久化的最小权威模型)。本文的视图来源、计量、消息配对和安全语义不要求保留旧 `ModelPreparation`、Session checkpoint、prepare/consume journal 或实例票据；实际请求由 Session 执行程序冻结一次，恢复读取原不可变材料。

## 1. 任务维护边界

普通聊天直接调用主模型，不在入站前执行任务分类、搜索、来源修复或维护模型调用，也不在回复、暂停或外部动作前自动创建、更新或保存任务。`SessionTaskContext v3` 只表达可选的只读任务选择，不再以 `TurnMode` 决定聊天、记忆、Skill 或工具的可用性。

只有入站 `extraParameters.task_id` 显式指定任务时，Runtime 才校验其 tenant/endUser/agent 归属、读取该任务并将快照冻结到本轮；缺少该字段时不得读取“当前”任务或把旧任务强行续接。冻结快照只提供参考，不能授予外部动作权限、替代当前身份校验或让历史任务结果冒充新的用户确认。

主模型可在实际需要时调用 `search_tasks`、`read_task` 与 `update_task` 管理持续目标；这些调用各自走当前权限、来源、revision 与幂等校验。机构端显式管理操作中的 `correct` 仍可使用 `task-context` 系统用途处理受控纠正，但它不是普通聊天的前提，也不引入已删除的任务路由或来源修复资源。

## 2. 证据、模型视图与冻结请求

| 层次 | 所有权与内容 | 不变量 |
| :-- | :-- | :-- |
| 证据层 | 各事实域保存原用户输入、决策、工具结果及已授权安全投影 | 压缩不改写事实，不绕过 Provider 原始结果的安全投影 |
| 模型视图层 | Session 组合显式选择的任务快照、近期消息、历史摘要、工具预览、引用、记忆与 Skill | 保存精确来源、覆盖区间、视图/策略版本及持久摘要 |
| 冻结请求层 | 模型准备冻结实际 messages、tools、模型配置及计量 | 同一调用按原请求恢复，不重新检索、摘要或组装 |

冻结请求的持久表达遵循[执行材料契约](03-核心对象模型与状态机.md#101-执行与持久化的最小权威模型)：多轮 Agent 以固定一层 manifest 引用精确消息和 tool-set 正文，恢复后重建的模型输入与原冻结值一致。这只减少重复持久正文，不执行摘要、截断或新的视图选择；有序引用列表仍随请求历史增长，不能据此宣称持久字节或 SQL 参数传输严格线性。

图片证据、模型视图和冻结请求按[多模态专题](03-多模态内容与媒体引用.md)分层：原图不改写，图像变体先生成后计量，快照保存实际采用变体与出现位置。图片卸载只改变新模型视图，不修改原消息或旧快照。

来源门禁可以按冻结版本确定性重建并与原准备逐字比对；该校验不生成新的调用请求，不读取实时配置重排历史。渲染或视图持久格式升级不为旧格式增加兼容实现，旧请求不能用新布局改写后重发；升级的在途处理范围与恢复验证必须在交付记录中明确。

摘要只是模型背景，不能创建任务事实、操作权限或执行成功证据。模型通过受控分页读取恢复细节，权限和安全投影不能因摘要含有引用而绕过。原 SessionLog 与跨会话任务保持各自事实源，不以会话摘要替代任务或长期记忆。

## 3. 输入预算与压力管线

有效输入预算 `B = 模型 contextWindow − 本次冻结 max output tokens − ceil(contextWindow × 5%)`。运营不再配置额外输入上限；B≤1 时拒绝准备。输出预留与安全余量只扣一次。完整候选请求的压力为 `估算 Tokens / B`，包括 tools、角色/framing、记忆、Skill、任务、按 Provider 协议回放的 reasoning 和实际图像请求变体的视觉成本；字符、解析节点及深度只用于候选解析和物理资源保护，不构成第二个业务窗口。例如窗口 327,680、输出 32,768 时，B 为 278,528 Tokens。

图片请求同时核验实际变体的数量与协议 wire bytes；达到图片容量处理条件时按[多模态专题 §8](03-多模态内容与媒体引用.md#8-容量触发批量卸载)批量卸载可回读的历史图像，再测完整请求。文字压力管线不替代图片物理准入，受保护内容仍超限则拒绝。

1. 低于 75% 直接准备；达到 75% 先外置旧的大结果并重测。
2. 确定性缩减后低于 75% 即可继续，不为达到 50% 额外调用模型。
3. 仍达到 75% 时，每次准备最多生成一次独立摘要，以 50% 为尽力目标。
4. 摘要不可用、失败、无辅助额度或处于冷却时，将连续完整旧调用组保存为精确原文材料，冻结引用与真实状态。它是确定性回收，不标记为模型摘要。
5. 摘要或原文引用视图有效且不超硬限制时允许继续；不可替代内容仍超限则明确失败，不丢必要规则、最新约束或执行事实。

分离候选计量资源上限与请求准入上限，避免计量器先拒绝候选导致无法触发压缩。通过大结果外置、有界渲染和持久历史分页控制资源，不无界加载历史；也不在摘要覆盖前以分页/条数上限直接丢弃历史。策略及模型配置冻结，现有 Run 累计输入、输出、总 token、时长和动作预算保留。

默认策略版本为 `context-policy.v2`，压力阈值、尽力目标和近期比例分别为 75/50/20。实际请求使用已冻结的发布策略；代码默认或运营种子变化不改写既有发布配置与准备。宿主准备配置身份纳入完整策略摘要，策略变化取得新的配置身份。

## 4. 确定性缩减与独立摘要模型

优先预览、引用及当前快照替换。已知结构保留状态、错误、产物等契约字段；未知 MCP 结构使用通用预览包装及原文引用，不猜业务重要字段，不将残缺 JSON 当完整结果。不同执行的相同内容不能按文本去重；仍以调用呈现的消息保留完整参数、代码及 Provider 必需字段。

普通压力的头尾预览是目标大小，不是硬窗口下的最小保留量。最新普通工具结果仍使实际请求超限时，允许继续收缩该完整组的安全正文预览，保留结果身份、完整参数、原文引用及采集/省略状态，再执行完整旧组引用回收；首次尚未呈现的成功原文回读不适用这一补救。实际视图与计量一起冻结，不增加摘要或主模型决策回合。

工具适配层通过明确的有序 `content` 声明业务正文，正文优先于状态与续接回执进入模型视图；原结构结果和真实状态继续保留。同一结果中的文字或 JSON 与原生内容精确重复时，模型结构视图可以引用对应内容项以避免重复计量，不能改变原事件、图文顺序或跨调用去重。浏览器按操作协议提取正文；代码结果仅采用已通过公开检查的文字与表格业务块，stdout/stderr 和私有诊断不因此成为公开正文。

摘要通过现有系统用途机制独立配置 `context-summary`，与 `task-context` 分离，不提供业务工具或任务写入能力。冻结模型版本、配置与输出，不隐式回退主模型。摘要 attempt 归辅助模型次数，全部消费仍归根总账；辅助额度耗尽不借业务身份继续摘要。缺失、失败或无额度时尝试确定性原文引用回收，再验最终硬窗口；同一准备的来源和策略不变时不重复生成。

摘要结果明确区分 `AVAILABLE`、`UNAVAILABLE`、`FAILED` 和 `REJECTED`，使用安全固定原因码；已受理调用的配置和 invocation 引用在失败或拒绝时仍保留。`AVAILABLE` 只表示有候选，采用仍须满足 §9。诊断分别记录摘要状态、原因、配置和调用引用，确定性引用回收成功不能覆盖摘要不可用的原原因；异常正文与供应商细节不进入该诊断。

摘要模型窗口不足时，只选择其可容纳的连续旧历史前缀，保持完整调用组及覆盖范围，不截断源消息或递归调用摘要。没有可安全处理的范围则按硬限制处理。摘要输出预算取硬输入上限扣除必要上下文和近期区域后的余量，并以摘要目标比例预算、旧历史成本及独立模型输出上限约束。不能把软目标与固定内容之间的微小正差额直接用作生成上限；超时受该模型配置及 Run 剩余时间约束。

摘要选区中的新旧消息按原位置恢复其已提交、经过安全治理的完整模型投影，不能直接用主模型的头尾预览代替原正文；角色、调用身份、完整参数与覆盖位置保持一致。已有 SUMMARY/REFERENCES 沿用当前冻结值，不递归展开已覆盖历史。普通消息缺少对应原来源时拒绝，不把预览作为完整输入；输出收益仍按主模型当前视图的旧区成本计算。

独立摘要另接收 `currentContext`，包含被冻结的当前用户输入及参数、纠正、只读任务快照、任务边界和最近对话锚点。它只提供历史相关性数据，不包含工具调用或工具结果，不改变授权及指令优先级，不计入 `history`、`coveredMessages` 或可回收覆盖范围。摘要优先保留当前目标所需的正文事实、精确数值、来源和缺口；无关旧操作及已解决传输步骤压成必要状态，不能因旧区没有当前用户输入而把实际目标写为未知。

完整安全历史与 `currentContext` 合计受原材料字符安全上限 `profile.maxCharacters` 约束。完整选区超过该上限时，按原顺序及完整调用组边界选择其中最长可容纳、且包含完整新增来源的连续历史前缀，避免把仍可处理的来源与后续长正文一起跳过；不裁剪源消息、拼接不连续来源或递归展开旧 SUMMARY/REFERENCES。只有不存在包含完整新增来源的闭合前缀时，才以 `SUMMARY_SOURCE_CAPACITY_EXCEEDED` 跳过独立摘要并走原引用回收，不累计摘要失败冷却。材料选区不使用主模型的 target、tokenizer 或输入 Token 上限预裁剪独立摘要输入。

来源 digest 以 `context-summary-input.v2` 同时绑定实际所选完整历史前缀和 `currentContext`，`coveredMessages` 上界只能是该前缀的消息数，不能用原完整选区大小接受越界覆盖。未选入的历史继续按原模型视图的来源、保护及回收规则处理，不以摘要覆盖冒称已承接其正文。主模型输入 Token 上限决定主视图压力、摘要回填 allowance 及主请求最终准入；独立摘要输入 Token 准入由宿主按冻结摘要模型的实际窗口、输出预留及完整请求计量，并选择可容纳的连续闭合历史前缀。两者不共享输入 Token 上限；`currentContext` 保留在独立输入但永不增加覆盖数量，输出 allowance 不代替输入容量检查，预算归属及前缀选择不增加调用或改变任一模型窗口。

## 5. 可恢复的内部原文引用

普通工具、MCP、代码输出统一支持内部不可变引用；优先复用已持久化且已授权的安全内容，否则保存内部对象。引用绑定 source、tenant、user、Agent/Session 访问边界，不接受任意 URL、浏览器票据或宿主路径。

受控 `read_context_reference` 的 `limit` 默认 4096，允许请求上界为 32,768 个 Unicode 字符；`limit` 只声明上界，不保证页大小。模型消费的实际单页最多 4096 个 Unicode 字符，避免首次回读保护一次锁住长篇全文。按实际页计算 `next_offset` 与 `end`，短页不等于全文结束，`source_complete` 独立表达原来源采集完整性。正常分页不限制读取总量。每次读取重验当前权限，按实际工具调用及上下文计量，不因历史已授权而直接放行。

已知原文标识时，可对同一 `reference_id` 或 `source_event_id`（二选一）追加 `find` 定位；不接受跨引用搜索。`find` 为 1–200 个有效 Unicode code point 的非空白、大小写敏感字面文本，不解释正则。输入 `offset` 表示从原文该位置向后寻找首次精确命中，返回的 `offset` 为实际页起点，并以 `match_found` 明确结果。命中页从匹配位置开始，仍受模型单页 4096 字符上限约束，可按真实 `next_offset` 继续普通分页。未命中返回 `match_found=false`、空 `content`、`offset=next_offset=source_characters` 和 `end=true`；这只表示指定起点之后已搜索到末尾，不表示整份原文已被模型读取。定位与普通回读执行相同的来源和实时权限验证，不新增索引或外部采集调用。已明确 `source_event_id` 的分页与字面定位直接读取当前 Session 的该提交事件，再核原 Run 的完整 owner 和安全投影，不扫描同会话其他事件；`reference_id` 与 `mode=history` 仍按其引用定位和集合查询语义读取。

完整旧对话或调用组的确定性回收以类型化 `agent.context-material` 事件保存消息正文、完整参数及准确来源；只在同一 owner 的原来源已提交、调用组闭合后允许冻结。索引的对象标签和正文摘录共同受完整请求预算约束，不通过删除来源行求准入；可直接回读的来源保留精确事件定位，整段材料引用在根字段保留，不必逐行重复。`agent.context-view` 分别标记 `SUMMARY` 与 `REFERENCES`，不能把原文定位冒称摘要。引用无法持久化时保留原视图，让最终硬窗口判定，不丢事实或重执行。该材料和引用随原 SessionLog 生命周期保留。

`REFERENCES` 使用 `deterministic-context-reference.v4`，逐来源保留事件身份、来源类型、真实状态、操作及参数对象标签、正文头尾摘录和可回读定位。索引根字段声明 `factColumns`、`excerptColumns` 和 `locatorColumns`，各来源、摘录及定位按对应列序保存完整行值，字段名不逐来源重复；`null`、`false`、准确读取区间及来源行均不省略。摘录注明原 Unicode 字符数与省略字符数，不按业务关键词猜重要性。索引、前次有效摘要及封装一同纳入完整请求计量，按收益与硬窗口收缩每来源摘录，不按固定条数删来源行。没有可采用的候选则保留原视图并执行硬窗口判定。工具预览使用 `tool-preview.v2`；预览与索引的 `readToolWireName` 冻结本次已显示且绑定 PLATFORM 原文读取能力的实际函数名，回读提示和恢复均沿用该名称，不把逻辑名作为可调用别名。

原文回读回执的来源、页正文、起止 Unicode 偏移、源字符数、源完整性及 `end` 必须在同一 owner 下重验，才能作为已读范围进入索引；历史扫描游标不冒充原文范围。来源采集完整、当前预览完整、页已读到末尾分别表达；预览省略、未回读或未覆盖均不能推导为原页面没有资料。最新成功回读的完整调用组至少进入一次模型请求后才允许老化回收，保护判断只依据先前请求实际呈现的 observation，摘要或索引列出来源不算正文已呈现。

`end=true` 仅证明当前页范围抵达来源末尾；完整读取必须从 offset=0 按真实 next_offset 连续覆盖到末尾，跳页不能推导已读完整。只有检索具体证据的任务可在找到证据后停止，用户要求完整阅读时继续补齐未覆盖区间。

执行历史通过同一工具的 `mode=history` 定位，可选 `history_run_id` 仅在当前完整 SessionOwner 内过滤，不覆盖调用身份中的 Run；`after_sequence` 使用原会话游标，默认每页扫描 20 条执行事件、最多 100 条。过滤后的空页不表示结束，必须以 `end` 判断。记录携带 `source_event_id`，可用它回读注册的安全投影；来源事件与内部引用两种定位互斥，不接受管理端 trace、任意路径或跨会话源。每页开始及返回前重验身份。

历史页可用 `query` 对安全记录的完整内容做大小写无关的字面匹配，最多 200 个 Unicode 字符，不对全部原始 trace 做全文检索，不调用模型重新摘要。每条 `content` 返回最多 128 个 Unicode 字符的开头预览，整页正文预算 4096 个 Unicode 字符，按返回记录数均分并向下取整；`content_truncated` 标示省略。有查询时 `query_match_in_content` 表示关键词是否出现在预览，`false` 仍表示完整内容命中。原文通过该记录的 `source_event_id` 分页回读。元数据不计入正文预算，不能以此推断 JSON 或 token 有固定上界。已知 `source_event_id` 时可用 `around_source_event_id` 定位，`window` 默认 20、范围 1–50，表示锚点前后 Session 序号跨度，不保证返回记录数；最多扫描 101 个序号位置。锚点须属于当前 owner、可见执行事实及指定 Run；窗口模式不与 `query`、`after_sequence`、`limit` 混用，返回的 `end` 只代表窗口读完。

历史页支持 `from_time`、`to_time`，使用含时区的 ISO 时间和已提交事件 `occurredAt` 做闭区间过滤，可以与关键词、Run 和游标组合，不与锚点窗口混用。响应保留 `occurred_at`；时间过滤不改变真实扫描游标，未匹配不等于历史不存在。

代码执行在机构端生成内部预览前保存 Sandbox 已捕获输出；stdout/stderr 各捕获 4 MiB，采集截断事实保留，不承诺无限原文。预览省略与源采集不完整分别表达，二进制继续作为文件。原始诊断日志不自动成为聊天公开过程正文，公开内容采用工具明确的业务结果通道。

只有内容持久化成功才发布可读引用。保存失败保留真实业务动作结果，不以输出存储故障伪造业务失败或重执行；内容无法满足输入上限时明确上下文准备失败。内部原文跟随来源证据保留，不能直接套用普通产物 7 天过期；清理检查仍被引用的来源、摘要及冻结请求。

图片不应用文字头尾截断，工具图像先持久注册为 MediaRef，按容量批量卸载并通过 `read_image` 显式重载；以下两级规则只处理文字输出。

## 6. 两级工具输出缩减

| 阶段 | 触发 | 模型可见内容 |
| :-- | :-- | :-- |
| 立即外置 | 单个结果超过配置的 12,500 估算 token | 先保存原文，扣除提示/引用成本，再将剩余内联预算大致均分给头尾 |
| 压力裁剪 | 请求压力达到 75%，历史结果超过 8192 Unicode 字符 | 保留头 4096、尾 1024 字符，加省略、完整性及引用信息 |

多个正文栏位共享单个结果预算。保留明确的结构化状态和错误标识，长错误同样有界，不按关键词猜测。原文分页读取结果不立即再次外置；变成较旧历史后允许压缩。确定性处理后重测，再决定摘要。

立即外置阈值必须小于有效输入预算；较小窗口由配置明确调整，否则配置校验报错，不静默改模型容量。原生调用参数不可按结果预览规则裁剪。不增加独立于有效输入预算的额外 headroom。

## 7. 历史摘要与近期完整区域

近期区域目标是有效输入预算 B 的 20%，例如 B=278,528 时目标约为 55,705 Tokens，并延伸到完整消息/调用组边界。这是软目标；确定性预览及正常回收后仍超过本地硬窗口时，允许在完整组边界内继续扩大引用回收前缀，直至候选满足硬窗口或抵达保护边界。当前输入、最新约束、最新真实完整调用组及首次尚未呈现的成功原文回读仍受保护，普通压力不降低近期目标。完整意味着不做语义摘要，其中大工具结果仍适用外置与预览；图片出现事实与调用关联保持完整，图像 payload 可按[多模态容量规则](03-多模态内容与媒体引用.md#8-容量触发批量卸载)从新视图卸载，当前必要图像受保护。

本地硬超限时先在最新完整组及首次回读保护之前确定可回收的完整前缀，再统一计算摘要资格、来源 digest、固定区域与生成额度；不能按扩展前的软近期边界认定没有新旧区，随后只用引用吞入新增已读正文。该准备仍最多尝试一次独立摘要，失败或冷却后的引用路径不在循环内再次调用摘要；CLOSING 与最终预算提示补救保持只做确定性回收。

老化内容形成一份当前合并摘要，后续将前次摘要与新老化部分合并，不叠加摘要栈。固定内容包括目标及范围变化；确认、纠正与约束；动作结果的成功/失败/未知；待办与开放问题；精确标识、数值、日期、产物和证据引用。

摘要不可用而采用确定性引用回收时，逐字承接前次有效摘要；再次回收展开本协议的既有包装，不递归堆叠 JSON 摘要。后续有效摘要同时合并前次摘要与新老化部分，采用后以新覆盖范围承接，不能再用旧历史范围覆盖新候选。该过程只维护模型背景，不自动写入长期 Memory 或创建持久任务。

摘要区分用户实际要求及后续纠正、带来源的已完成事实、未完成用户要求、助手自行提出而未经用户要求的计划。计划不升级为用户目标。跨 Run 视图由摘要覆盖前缀加未覆盖后续事实组成，包括失败或取消 Run 中已经提交的工具结果；摘要只覆盖连续的已提交区间，保留区间尾部而不缓存整个 Run，生成后迟到的结果必须留在未覆盖尾部等待后续合并。整个 Run 的失败或取消不覆盖单次工具成功，领取仅表示准备且外调未确认，结果未知保持未知；同一 invocation 的状态记录不能重复计为多次调用。执行短记录保留状态、完整性、有限预览和原文定位，不每轮重塞完整结果；工具提供已验证文字内容时优先以文字形成预览，避免结果封装占用预览预算，省略结构化结果仍标明预览不完整。没有文字内容的普通结果保持有界安全投影，图片载荷不进入文字预览。完整来源继续通过原定位回读，工具专用续接信息由工具所属适配层提供，不进入 Runtime 业务解析。

最近请求和它所对应的上轮回答原文作为独立锚点参与来源校验、冻结与预算，但不进入可摘要历史集合，使“这份信息”等引用可解析。锚点不把其后的全部工具历史锁成受保护后缀；工具历史仍按近期预算和完整调用组选择连续可摘要前缀。跨 Run 对话覆盖游标仍只推进到确实被摘要覆盖的连续对话前缀，不能跨越保留的原文锚点。将已有信息转换为页面或文档默认保持原范围，只有缺少必要内容、用户要求更新或业务要求核验时补查；分页标志只证明可继续，不产生全量查询义务。

当前用户输入、最新纠正、现行系统规则、任务快照、活动 Skill 正文、预算阶段、精确等待身份与 Goal/CAS 不进入历史摘要。历史读取依据摘要或引用覆盖范围加未覆盖尾部，最近 20 条不作为信息丢弃边界。原日志不删除；摘要不自动恢复历史待办，不自动写长期记忆。必要上下文过大导致 50% 不可达时保留必要信息并遵循硬上限。

## 8. 完整调用组

以精确调用 ID、来源和结果关联校验调用组，不能用调用/结果数量相等代替。调用与对应结果共同保留、共同摘要或共同保存为原文引用，边界落在组内向前扩展，允许超过 20%。一个多调用 assistant 消息与全部结果不可分割。

同样保护 Skill/资源/知识动作及已验证的 HITL 交互配对。未完成、暂停和未知不能转为已完成历史，失败保留失败，不制造缺失结果。非法配对拒绝视图，不静默删除修复。没有可压缩完整范围时跳过；仍超硬限制则失败。

## 9. 摘要采用与版本一致性

使用主目标 tokenizer 与图像视觉计量口径计量包含摘要封装/引用的完整替换请求，不能比较摘要模型输出 token 与主模型输入 token。采用必须同时满足：总 Tokens 严格下降、摘要或原文引用结构及调用协议有效、相关来源版本未变。最终候选仍受解析和物理资源保护；字符不是额外的业务准入或摘要收益指标。

来源、覆盖及调用组合法且具有 Token 收益的摘要，与当前保留区域组合后仍超硬窗口时，允许先在未提交候选中将该新摘要作为 `retainedSummary`，继续执行确定性引用回收并计量完整组合请求。只有最终组合满足收益、来源及硬窗口准入才一次性采用，不能因摘要单独替换后的中间候选超限而直接退回旧摘要；不得持久化超限中间视图、提前扩大覆盖或为这一组合再调用模型。组合无收益、来源失效或最终仍无法准入时保留原有效视图并使用原 fallback，原文、首次回读保护与引用来源行不因这一补救丢弃。

冻结视图来源、策略及摘要模型版本，以预期版本/CAS 采用。相关输入、任务、指令变化使候选失效，无关心跳/usage 日志不使其失效。无效摘要转确定性原文引用回收，不加 LLM 审查或最低缩减百分比；采用不要求达到 50%，发送前仍验硬上限。持久视图在崩溃恢复中复用。供应商以 `length` 结束时，即使正文为空也保留确定的截断事实；系统模型任务拒绝采用截断正文，并持久化 `system_agent_output_truncated`，不将其降为通用执行失败或网络结果未知。

`skillforge.runtime.context-view.v3` 的摘要及引用 ContextBlock 同时关联视图事件与其覆盖的原来源事件，用于冻结来源追溯；知识 `EvidenceRef` 保持原知识证据域。来源关系不表示正文已经完整呈现，也不新增读取授权。

压缩尝试以不含用户正文的 `agent.context-compaction-attempt` 事件持久化到原 Session 的执行账本。失败或无可用摘要首次冷却 30 秒，连续两次无效则冷却 5 分钟；采用后请求低于压力阈值，或本次回收区域已达到其实际生成预算（完整请求不超过固定区域加本批 allowance），均清零。固定规则和工具目录无法摘要，不能仅因其成本使整体长期高于压力线就把有效摘要计作失败；未达本批目标的低收益采用仍计入无效次数。冷却到期允许下一次探测。范围绑定完整 owner、准备配置、目标模型、输入上限与工具 schema，同范围的新 Run 和进程重建复用冷却；同准备操作及来源摘要重放沿用原调用身份和冷却期限。冷却只禁止新摘要尝试，不放宽硬限制，也不改变摘要覆盖区间或冻结请求。记录损坏时拒绝继续，不能用默认计数无限调用摘要。

宿主读取冷却时，只查询完整 owner 关联的压缩事件族，并按原序号验证 schema、配置范围和正文；不能只取最新记录而跳过更早的非法匹配事实。该读取不加载无关 MODEL、工具或等待事件正文，也不依靠完整旧 Run 的逐项水合。

## 10. Provider 溢出补救

适配器只将供应商明确的上下文溢出归类为可补救；普通 400、鉴权、额度、超时或输出 `length` 不属此类。确认后绕过 75% 门槛，先确定性缩减，最多一次独立摘要；摘要不可用或仍在冷却时继续原文引用回收，冷却不阻止确定性回收。紧急情况下近期区域可低于 20%，仍保护当前输入、最新约束、现行规则、任务及最新完整调用组。

仅当新视图提交成功、确实缩小、协议有效且时间/token/取消检查允许时，额外调用一次主模型，该窗口补救归辅助次数与根 Tokens。原失败冻结请求不修改；新准备和请求有独立稳定身份并关联原失败决策链，不用原 preparation 键承载不同内容。该新请求是已确认拒绝后的补救，不是未知外调重试，不放宽主文档 permit/ActionLedger 约束。

每条失败决策链最多一次额外主模型调用，补救计数持久化，重启或新 ID 不重置；主模型成功才使后续决策获得新的补救机会。完成工具不重执行。已有用户可见部分回答或已采用决策时不盲目重发，遵循既有未知结果约束；失败/耗尽明确终结，额度不足停止真实测试。

### 10.1 确定限流的有限重试

供应商 429 拒绝携带 `retryAt` 时，Runtime 在原 Action 已收口为 FAILED 后保存 `agent.model-rate-limit` 事实，再以新 Action 身份采用同一个冻结模型请求。消息、工具、模型目标、binding revision 与生成参数全部保持；冷却期间到达的纠正保留至后续正常准备。HTTP 层不重发，未知结果、网络中断、408 与普通 5xx 不授予重试权，401/403 直接拒绝。

一条失败链最多三次调用，从第一次拒绝采用起最长 60 秒；Retry-After 优先于 X-RateLimit-Reset，不截短服务端等待要求。计数、可调用时间和截止时间进入 SessionLog 并参与 checkpoint 来源校验，恢复不会重新选模型或重置预算。Inbox 最多每秒唤醒检查取消，只有持久可调用时间到达后才能发送下一请求。沿用 Run 总预算与每次调用的实时授权，不新增执行模式或后台重试线程。

### 10.2 确定内容拒绝

Provider 根据明确的协议错误码及所属供应商的严格拒绝识别策略，将确定的输入内容拒绝映射为 `model_content_rejected`。普通 `invalid_request_error` 或错误正文中的 `content` 关键词不能据此分类；同步及流式共用识别规则，日志只保留固定分类及字段命中，不输出供应商回显、正文或凭据。

内容拒绝按原失败路径终结当前 Run，不触发窗口补救、限流重试、删改材料或自动换模型。宿主的实时、历史及重连过程投影提供固定安全提示，保留已接收的回答与已完成工具事实。旧失败只记录通用 HTTP 原因时不推断并回填内容拒绝；供应商接受后续请求需以真实调用结果确认。

## 11. 具名提示词模块

平台规则、Agent 指令、Runtime 协议、能力目录、任务、历史/摘要、记忆和 Skill 使用稳定名称、类型、顺序、来源版本和内容，关联计量归属。复用 ContextBlock 与冻结请求，不新增提示词插件平台。

平台系统提示词只约束平台与模型如何协作：指令优先级、信任与权限边界、工具调用协议、执行状态、失败与未知处理、证据真实性和成果生命周期。跨行业通用不等于系统级；去重、汇总、差额计算、网页组织、文件制作和业务验收方法不作为所有 Agent 的常驻规则，也不借工具描述或拒绝反馈重新注入。

机构和 Agent 业务上下文承载行业角色、范围、术语、流程、制度及输出要求，保留业务发布来源；Skill 承载领域知识、操作方法、计算规则、模板、示例和脚本；当前任务承载用户目标、输入资料、约束与本次成功条件。摘要和记忆抽取等专用系统用途只在对应调用链承载其任务契约，不装入通用聊天规则。个别任务失败沉淀为相应回归样本或 Skill 改进，只有暴露平台通用契约缺口时才修改系统规则；该边界同样适用于条件能力模块、桌面宿主、动态提示、工具说明和错误反馈。

消息角色映射与顺序由程序固定，重复模块拒绝。tools schema 仅放原生 tools，不在正文重复。模块顺序不代表权限，不把事实提升为指令。

当前执行输入与历史按真实 Run 来源区分：历史中其他等待或执行中的任务仍由各自 Run 处理，当前执行的范围由原始输入及该 Run 已采用的受控用户回复共同确定，其他 Run 的最新 Session 消息不能替代当前任务输入。当前输入保持原值并参与准备与预算，不靠未装配的说明资源建立边界。原生控制动作历史重放保留已严格解码的完整参数，包括非终结动作的 `commentary`，不能用缺少必填字段的历史示例引导后续调用。经恢复日志和采用结果核验的 Workflow 反馈明确说明原流程已经暂停并恢复，避免将“当前已完成”误述为“从未等待”。

Workflow HITL 恢复在完成采用时，把恢复来源已核验的原人工输入事件显式加入当前 checkpoint 观察链，排在相应 Workflow 结果之前。来源必须匹配原 owner、Run、Agent、恢复 journal、suspendRef、checkpointRevision 和 Workflow revision；既有受理事实与恢复 Action winner 校验仍负责授权证明。模型准备将该事件渲染为独立 USER 消息，携带真实 sourceEventId 并纳入现有冻结重放、压缩与预算计算。工具结果保持 TOOL 数据身份，外部回调不提升为用户输入；已填写事实更新最初输入中的未知值。当前输入渲染版本与布局见 §12。

平台宿主自有的固定系统正文与组合入口归 [skillforge-prompts](../backend-java/skillforge-prompts/README.md)；独立桌面宿主自有的行为正文归 [agent-runtime-desktop-host](../backend-java/agent-runtime-desktop-host/README.md) 的 classpath 资源。共享动作、工具声明、执行语义及运行机制必需的正文归 Runtime，实际动态事实、工具说明与诊断由 [agent-runtime-session](../backend-java/agent-runtime-session/) 的对应生产入口提供，不打包没有装配入口的会话情境正文；不能因正文面向模型就移入平台宿主模块。`SessionPrompt.Type` 只表达组合分类，不决定资源的物理模块，也不要求调整公共枚举。正文使用标准 classpath 资源直接加载，不使用自定义标记、包装围栏、拆分解析器或构建生成任务；Runtime 不依赖宿主源码、生成目录、构建任务或提示词 JAR，独立桌面宿主也不依赖平台提示词 JAR。工具及字段说明、标签和短回执归实际工具或协议代码。非系统 Agent 与业务模板正文只存在数据库，经所属管理、发布与冻结流程传入，源码资源、数据库迁移及启动流程不注入业务角色正文。使用 `system` 消息角色不改变业务内容的归属。桌面正文的来源冻结与新 Run 历史处理见[宿主设计 §11](../docs/02-架构与设计/01-技术架构.md#11-独立桌面宿主原型)。

聊天分别装配 `HOST` 核心边界、运营策略、数据库 Agent 正文与 `RUNTIME` 通用交互和回复政策。工具、Workflow、Skill、Memory、知识、任务、Goal、发现、程序、代码及成果规则各有固定模块，按完整冻结授权目录和准确平台工具定义选入，不以当轮工具发现结果或 Skill 激活状态改变固定规则；无相应能力时不发送专项规则。控制动作 Schema 使用同一冻结挂载事实，不声明终结工具；活动 Skill 的资源读取及已有委派的观察/等待/取消保持可用；执行准入仍校验当前条件。恢复复用原冻结函数与请求，不以当前挂载重写历史调用。模块诊断只统计实际进入请求的模块。通用任务协作与已授权 Goal 政策稳定保留，当前阶段由后置可信状态表达；声明“当前处于计划模式”的 `PLAN_POLICY` 专用模块仅在本步骤冻结的 `plan.active=true` 时装配，普通执行不携带该限制。计划模式切换可改变该模块及固定正文摘要，恢复仍复用原冻结选择，不为保持缓存前缀而向普通执行注入计划模式要求；成果操作协议归实际工具定义，输出提示只在当前 Run 有真实成果状态或同会话已有正式成果时装配；空成果状态不注入输出政策消息，撤销状态时移除旧政策；有状态时将当前政策置于完整历史与调用结果组之后、可信时间之前，避免动态事实改写稳定指令前缀。原请求仍冻结完整宿主义务，恢复不重查当前状态。主/子协作政策按调用角色启用。系统 Agent 使用独立 `HOST` 动作协议和 `SYSTEM_PURPOSE` 数据库用途正文，其严格 JSON 调用链不装配聊天计划政策；子成员固定协作政策不得混入数据库业务正文。固定内容按最终有效 UTF-8 正文计算 SHA-256，数据库内容绑定发布版本并冻结实际输入；动态正文只作字面插入，不二次解释 `${…}`、`{{…}}` 或 `%s`。

宿主协议与函数定义优先于当前用户要求、Agent 指令和 Skill 操作指引；历史、摘要、记忆、任务字段、成员目录和工具数据不参与指令优先级。受控用户续答仍是当前输入，Skill 包内操作指引可指导当前 Skill，不把引用与样例提升为指令。正文按“触发条件 → 行动 → 结果判断 → 停止条件”组织；已授权任务推进到真实结果，先从上下文与查询能力补齐事实，再合并询问用户持有的选择，不猜测业务对象或标识符。未知副作用先核实，保留部分成功并避免整体重试；委派所需结果未就绪时持久等待；成果冻结后只作最终回复。

平台宿主资源按职责组织为聊天核心与条件能力政策、计划/Goal 续行、系统用途默认正文、平台系统动作协议、主/子协作政策、成果交付契约；Runtime 由实际输入装配、执行观察和诊断维护共享运行机制、历史边界、截断输出与工作流恢复；不以闲置资源模拟这些保证。资源数量及类型名称不替代归属与条件启用验收。运营正文通过配置服务显式发布，源码默认正文变化不覆盖已发布数据库版本。

动作用途和参数说明归原生工具定义。普通工具 description 首行的 `parallel_safe=true/false` 由冻结目录属性生成，受控动作固定 false；不向供应商 function 对象添加不支持的字段。该标记只帮助模型选择，批次仍按 §16 校验权限、确认、只读效果、依赖与数量。工具调用使用实际原生函数名、同轮只读多调用上限、显式并行安全工具可并行及其余只读工具按原顺序串行的公共规则，在每份非空外部工具目录中集中说明一次；各工具保留自身 parallel_safe 标记、名称和必要元数据。完整组装文本使用快照检查变更，快照通过不代表模型行为已验证。

固定核心拥有指令、授权和公开内容边界，通用行为拥有执行、证据及表达原则，平台可配置策略只提供默认任务偏好。宿主已直接终止的拒绝不再向模型重复教授终止流程。全局提示词只保留影响任务、授权、真实性与证据的行为原则。具体批次数量留在工具 description 和运行时校验，原文分页数字留在读取工具定义及默认参数，脚本读取语义留在资源工具描述。模板维护分类分为运行时强制、模型软约束、业务特定、文档说明；分类标签不进入模型正文。业务指令、Skill 和工具说明按已有配置、激活状态与本轮工具集合提供，不新增通用规则注入框架。渲染与供应商说明保留在 `RUNTIME_ONLY`；实际函数 description 与参数 Schema 仍随 tools 发送。

平台通用策略与 Runtime 固定指令不预设角色身份，也不指定回复语言；角色由智能体自身配置提供。完整请求快照以占位符展示模型参数、主 system 正文、会话状态、历史与压缩摘要、当前输入、任务、动作观察、分层记忆、活动 Skill 和原生 tools，并说明可选项、重复项及压缩后的实际位置。主 system 正文保留固定指令，以 `{{agent.system_prompt}}`、`{{agent.role_description}}` 和 `{{runtime.capabilities_json}}` 展示动态配置；其边界内文本由拼装测试核对。章节标记、说明和占位符仅供阅读，不发送给模型；实际请求使用本轮冻结内容。回答格式只约束用户可见正文，不改变原生工具协议：普通聊天不默认要求 JSON；明确请求 JSON 时保持所需顶层类型与原始内容，不增加 Markdown 包装。绑定知识证据的 `respond.output` 仍为字符串，其内容遵循用户要求的格式，证据 ID 独立写入 `evidence_item_ids`。自然语言自检不替代结构化消费端的 Schema 校验，不据此承诺模型必然输出合规内容。

最终答复阶段复用已有可信 `finalResultRef` 准入事实，同时收窄原生工具与指令投影，不能由模型自报阶段。执行阶段将纯动作推进、工具发现、调用、代码及能力使用指导归 `RUNTIME_ACTIONS` 与相应 `RUNTIME_*` 专项模块；可信最终准入后关闭工具调用并冻结 `NONE`，允许正常正文进入同一 Respond 检查，不继续注入这些已关闭动作的操作指导或能力目录。`HOST`、平台和 Agent 业务指令、`RUNTIME` 的证据真实性与回复规则、已激活 Skill、主子委派政策及全部相关事实保留，不删除历史调用、结果、计算观察、任务约束或来源来制造简短正文。

宿主输出契约通过 [PreparationHint](../backend-java/agent-runtime-session-spi/src/main/java/com/skillforge/runtime/session/spi/SessionOutputContract.java) 分别提供执行阶段的 `stableInstructions`、最终阶段的 `finalAnswerInstructions` 与事实性的 `runContext`。最终阶段选择公共呈现指导，正文聚焦已核验业务结果和真实限制，正式发布事实仍归宿主成果服务；`finalResultRef` 或清单冻结不表示当前版本已发布、可下载或 Goal 已完成。该分工不新增模型回合、不以禁词或事后清洗保证表达合规，也不承诺模型必然遵从。 带 `task_result` 的原Run完成事实与最终公开正文分开，宿主按精确发布事实控制历史、activity和SSE的公开时序；pending不公开最终正文或completed，正式合同见[宿主成果交付 §8](../docs/02-架构与设计/12-代码执行沙箱与产物交付.md#8-多形态成果与官方-skill-package)。

阶段选择及实际指令按原准备冻结，恢复使用原 `finalResultRef`、模块选择和正文，不按当前配置重选。同一会话执行指令头部发生阶段变化时，复用 §13.1 既有 REBASE/REPLACE 机制替换当前固定首部，完整事实与来源按原投影保留；不另建最终阶段状态机，也不把空工具目录或 `NONE` 本身当作可信准入来源。指令阶段是可信准入的投影，不是新的权限或发布状态。

Skill 发现目录从已冻结挂载投影 `activationMode`，区分 ALWAYS 与 ON_DEMAND，不为发现注入未激活正文。已激活 Skill 正文及受控包内操作指引提供业务指导；普通工具结果、引用资料与样例数据不因此成为指令。Skill 内容不改变宿主调用协议、当前任务范围或能力授权。

回复呈现规则归完整通用行为政策：先给结果与必要说明，遵守用户与 Agent 的格式优先级，提供真实可访问产物链接，准确区分计划、受理、执行、发布和目标达成。修改成果时，当前明确格式使用 `user_explicit`；未指定新格式时可以从核验过的原成果继承 `previous_explicit`，不把历史消息 ID 当作当前输入。平台可运营策略维护任务推进，不重复规定排版；工具参数类型与证据字段由原生函数定义和解码校验负责。宿主没有相应能力时，不引入其他客户端的文件卡片、预览工具或本地路径链接约定。

## 12. 动态上下文当前快照

新视图替换当前动态模块，历史变更留在日志，必要时显式呈现清空或无活动任务状态。内容与来源均未变时复用渲染；来源变化即使文本相等也更新版本。必要模块被移出视图后必须重新注入，不能以此前发送过为理由遗漏。

任务快照只来自显式 `task_id` 选择；每份新请求均包含完整有效上下文，同一调用恢复原冻结请求；不缓存实时权限、租约或取消状态。

记忆使用策略归完整通用行为政策，三层动态消息只带 `[memory layer=...]` 标签和事实 JSON；layer 不是事实的授权 scope。能满足当前请求且无失效或冲突迹象的信息默认复用；仅实时状态、明确过期、冲突或业务要求时按需核验。

`SessionMemorySource` 默认不自动查询三层记忆。主模型需要记忆时调用 `search_memory`，由工具按当前身份与查询参数返回受权事实；保留显式启用的自动注入 SPI，但它必须自行声明并冻结选入结果。历史恢复重放完整冻结组，不按当前索引重新筛选；候选、选入与注入仍按原事件冻结，后续纠正或停用不改写历史冻结输入。

`input-log.v29` 的新会话呈现顺序为固定主 SYSTEM 指令（含核心、业务配置和完整授权模块规则）→ 对话状态及历史 → 可选任务快照 → 当前任务边界说明 → 可选附加业务参数 → 当前 USER 输入原文 → 可选的当前 Run 可信 SYSTEM 上下文 → 可选的冻结记忆组 → 本轮观察 → 运行中纠正、调用进展及预算阶段 → 冻结时间样本。已有会话按 §13.1 复用已采用的完整前缀，再追加首次出现或改变的当前消息；新 Run 不将当前输入、时间或阶段插入已采用历史之前。只有业务参数的有效输入把记忆放在参数消息之后。活动 Skill 正文按 §14 插入其成功激活来源之后，不统一插入过去对话之前。原生业务工具直接使用已冻结的业务输入 schema 和参数对象，历史调用按原 `callId` 回放相同业务参数；不添加进度字段或外层参数包装，不重定位业务 schema 的本地 JSON Pointer 或 `$id`。预算计量包含实际工具定义与参数。公开进度来自真实模型、工具及计划状态；独立控制函数保留自身可选说明，普通业务调用不为生成工作摘要增加字段或模型请求。仅改变模型视图，不修改来源事件顺序；摘要或原文引用仍只替换合法历史前缀，调用与结果保持成组。Workflow 结果在模型视图中把已核验终态提示置于完整安全业务 `output` 之前，原 payload 保持不变；历史交互不表示当前仍待确认，投影不改变原 `callId` 或 ledger。渲染版本和宿主准备引用由 [SessionPreparations](../backend-java/agent-runtime-session-spi/src/main/java/com/skillforge/runtime/session/spi/SessionPreparations.java) 的共同版本定义，旧冻结调用不能据新布局重新解释。完整请求模板用 `LLM_VISIBLE` 与 `RUNTIME_ONLY` 区分正文和说明。

宿主动态收尾在最终请求冻结前使用同一实际模型及输出上限测量。Session 保留不可替代规则、输入、约束、Skill 和准确事实，将旧完整组外置后形成紧凑候选；确定阶段后冻结 `agent.preparation-budget`，再将预算来源与最终视图一同计量和冻结。CLOSING 只提供宿主批准的必要成果收尾工具，不提供其他业务动作入口；75% 提醒与阶段是宿主事实，不接受模型声明。恢复只读取原预算事件与请求，不重新用实时余额改变同一准备。

CLOSING 保留冻结近期比例及完整调用组，不因进入收尾就把近期预算置零；本地硬窗口回收按 §7、已确认的供应商上下文溢出补救按 §10 降低近期区域。模型在业务工具关闭前按用户要求核对结果范围、精确事实和未读缺口，必要时显式回读；最终回复复用既有回合，工具关闭后仍携带已保留事实、来源及缺口，不增加主模型决策调用，也不把用户的 TopN 等业务范围硬编码到 Runtime。

原生聊天将入站 `text` 逐字投影为 user 消息，不把 `{text, extraParameters}` 传输对象当作用户正文，也不解析用户亲自输入的 JSON。附加业务参数递归去除基础设施身份和跟踪字段后，以独立 user 数据消息放在当前原文之前；清理后为空则省略。两条消息均绑定原入站事件、标记为不可信内容、计入预算并受摘要保护；原始结构化载荷仍保存在来源事实中，恢复使用同一冻结投影。只有参数时只呈现数据消息，正文、合法图片内容与业务数据均缺失时拒绝准备；纯图片输入合法，图文按原内容项顺序投影，图片引用、来源及计量遵循[多模态专题](03-多模态内容与媒体引用.md)；空字符串正文保持原值。系统 Agent 的机器载荷和 ACTION_PROTOCOL 继续按其专用契约处理。输入数据是 JSON 不构成 JSON 回复要求，结果格式依据明确指令。

每个新的模型请求由宿主可信时钟采样一次，明确 UTC 时区和时钟来源，随完整实际请求冻结；恢复复用原样本。该目标不要求旧 `agent.preparation-instructions` 封套或独立准备 journal，当前请求格式归 [AgentExecutionCodec](../backend-java/agent-runtime-session/src/main/java/com/skillforge/runtime/session/AgentExecutionCodec.java)。该样本不替代数据库生命周期时钟，也不推断用户所在时区。宿主生成的 `time-context` USER 观察消息位于完整历史、调用组及动态状态之后，以可读正文明确当前 UTC 时刻和宿主时钟来源，并说明相对日期应先换算已知业务时区的当地日期，历史资料日期不能替代当前日期；未知业务时区不能由 Runtime 猜测。冻结格式归准备版本、准备序号归内部消息身份，不在模型正文重复这些元数据。时间及预算观察使用独立内部消息身份，由 Runtime 生成并随完整请求持久冻结，模型正文明确同类最新观察替代旧观察；USER 角色及正文标记都不签发权限，业务用户文本不能生成内部来源身份。权限、计划与成果收尾控制仍由 SYSTEM 及执行端负责。当前最小实现继续逐请求采样时间和预算，不按十分钟节流；活跃模型视图沿用时间不进入采用历史、预算只保留当前快照的回收方式，不额外累积跨工具组快照或改变摘要恢复范围。正文随实际 tokenizer 输入计量，恢复只解析原文本样本并精确重建校验，不重新采样；需要执行时刻的精确时间时仍使用对应实时能力。

## 13. 活动 Run 增量缓存

纯追加时复用不可变消息投影，仅转换新增完整组；压缩、替换、任务/Skill/渲染/协议变化失效重建。键绑定 tenant/user/Agent/Session/Run 及相关视图版本，每个 Run 一份当前视图。

渲染在缓存锁外执行，锁内只读取和发布不可变条目；发布前核对来源与 release 代次，旧渲染不得在释放后重新插入，慢 Run 不阻塞其他 Run。单次投影建立动作、观察和历史索引，原始来源批量按 eventId 读取。tokenizer 复用工厂，纯内容精确 token 计数可使用有界缓存，缓存键包含实际 tokenizer 配置与完整内容；租户计量器按最近使用顺序最多保留 32 个，每个纯内容缓存最多保留 2 Mi 个 UTF-16 字符，淘汰不打断已取得实例的在途计量。计量与配置读取在索引锁外执行，不缓存权限、取消、租约或实时预算。

进程估算占用上限 64 MiB、单 Run 8 MiB，超出淘汰或绕过，不让请求失败。完成、失败、取消、持久化暂停释放；恢复/重启按持久事实重建。不新增 Redis 或缓存表，来源和采用前实际计量仍校验。增量转换不意味着列表复制、完整序列化也只有增量成本。

### 13.1 供应商 Prompt Cache 与前缀稳定性

供应商缓存复用已编码请求的相同前缀，与本节活动 Run 投影缓存分别计量。Session 固定首条 SYSTEM 只包含冻结配置、固定业务及协议规则和完整授权模块；当前 input、Run、时间和预算阶段不得格式化到首部。宿主输出契约分离固定规则与当前 Run 事实，当前输入 ID 等事实位于本次 USER 输入之后并保持可信 SYSTEM 角色；历史、工具、记忆、任务和 Skill 的可信边界不因缓存改变。固定配置下，新 Run 和相同能力集合的阶段变化保持首条 SYSTEM 全值相同；配置变化、撤权和压缩允许重建，不承诺所有请求严格追加。

普通工具拥有者提供独立于 input/Run 的稳定模型身份，wire name 从该身份确定性派生；完整授权目录的输入/输出 Schema 原值、身份到精确执行目标的一对一映射及目标摘要冻结为准备来源，发现结果只选择当次实际 tools；未选中的授权 Schema 仍可从原控制来源完整回读。Workflow 的模型别名来自冻结挂载 ID，原模型决策保留该别名，采用动作绑定同一 Snapshot 中的 input-scoped 精确目标；历史恢复同时校验原准备引用、模型决策和已采用执行动作。模型不能把内部执行句柄当作别名，未知或歧义身份拒绝，不按句柄文本切割或当前目录反推。稳定声明不扩大权限，每次外调仍校验实时授权和原精确目标。

独立控制工具按冻结挂载声明，Skill 工具不随当前加载状态抖动；原生 Agent 使用 NativeConversation，需要操作时调用实际可用工具，能够回答时直接输出正文。普通请求有工具时冻结 `AUTO`、无工具或阶段禁止工具时冻结 `NONE`，不以推理开关要求模型必须调用函数。完整正常停止且没有工具调用的正文经 Session 解析引用，再由 Runtime 核对原注入来源、未解决动作和宿主成果门禁，通过后结束 Run。正文与工具调用共存时继续处理调用，不提前完成；截断不执行该响应中的调用。控制工具各有严格参数 schema，模型不填内部 type/operation；名称匹配原冻结工具，不授予额外能力。无终结工具、额外回答准备请求或正文专属协议，恢复使用原冻结请求与完整原生事实，引用语法和采纳边界归[对象与状态契约](03-核心对象模型与状态机.md#561-headless-模型准备与提交协议)。

前缀能力由 [ModelPort](../backend-java/agent-runtime-api/src/main/java/com/skillforge/runtime/api/port/ModelPort.java) 的类型化 `PromptPrefixCapabilities` 持有，下面定义其语义；精确 Java ABI 归源码。`SUPPORTED`、`UNSUPPORTED` 和 `UNVERIFIED` 分别表示已核实支持、已核实不支持和未核实，未知不能提升为支持。

| 能力字段 | 有效值与启用条件 |
| :-- | :-- |
| `systemUpdatesInHistory` | 采用上述三态；仅 `SUPPORTED` 允许通过历史内可信 SYSTEM 更新固定上下文，其他状态走明确的重建边界，不将控制指令降为 USER 或工具数据；时间及预算观察依 §12 使用独立 USER 快照，不属于 SYSTEM 指令更新 |
| `toolUpdates` | `NONE` 表示只支持完整声明重建；`ADDITION_ONLY` 只允许追加；`ADD_REMOVE` 允许追加与移除；`UNVERIFIED` 不启用更新协议。不能把普通每请求 tools 数组等同于历史增删协议 |
| `retainToolsWithToolChoiceNone` | 采用上述三态；仅 `SUPPORTED` 允许需要 NONE 的调用同时保留完整工具声明。普通 Agent 没有可用工具或当前阶段禁止工具时使用空目录与 NONE，不为缓存保留已关闭工具 |

Provider 在精确 Service/Profile/Protocol/endpoint/模型范围内声明能力，宿主登记不能扩大 Provider 已核实范围。能力随不可变 binding、内容摘要、`FrozenModelTarget`、context snapshot 与 invocation snapshot 一起冻结和逐层全值校验；恢复从原持久绑定读取，不访问当前目录补齐、重新判定或回填未知能力。格式缺失、字段损坏或 capability 漂移拒绝恢复，升级按[切换与引用闭包规则](../docs/04-指南与运维/11-数据清理与保留规范.md#连续上下文与模型能力格式切换)处理。

SessionLog 持久保存连续投影的 APPEND、REBASE、REPLACE 及每次准备的选择快照，引用不可变 preparation 的精确消息位置或原最终结果，不重复存储整份 prompt，也不以全局可变 head 决定历史。空选择同样冻结；固定正文变化、正文撤销或完整组压缩以明确 REBASE/REPLACE 表达。纯追加保持已经发送的角色、媒体、完整参数、callId 和顺序，仅追加首次出现或实际改变的消息；已采用摘要覆盖的来源不能再次注入长原文。动态记忆、任务、运行约束、进度或预算源完全消失时，追加明确清空状态，原内容仅作为历史事实；来源已为空时不重复追加。推理 continuation 仅在原冻结绑定、策略、推理配置均相同且推理未关闭时继承；配置变化或来源未知只清理新请求的 reasoning，不改写原模型结果与工具事实。摘要及完整调用组仍按 §§7–9 处理，正文撤权不得为命中率继续保留。

每份投影须由当前权威 Run checkpoint 的 adoptedOperations、原 journal/CAS 命令、准备/结果摘要及精确 SessionLog append 同时证明；日志或 journal 存在本身不授予采用权。准备前按每个相关 Run 的权威采用集合协调已发布但尚未采用的事实，未采用或失败 CAS 的分支不进入候选；同 Run 恢复优先保留自身分支，新 Run 初次选择最近的已采用事实，随后晚到采用不改写该准备已经冻结的选择。完整 owner、tenant、endUser 和实际执行 Agent 隔离所有引用。缺来源或篡改引用拒绝，不借当前配置重组，不重发已经确定的模型或工具调用；进程重建从上述闭包恢复。

ModelPort 在调用许可、租户与冻结绑定校验之后，按完整 SessionOwner、绑定 revision、目标模型、Provider/Service/Profile/Protocol/Auth/Dialect 和 endpoint 派生不含原始标识的稳定 SHA-256 范围。新 Run、input 或 attempt 不单独改变同一范围，凭据和正文不进入范围值。该值只供 Provider 支持的缓存路由字段使用，不替代任何实时授权，也不宣称能控制供应商内部缓存分区。

保留各供应商 Provider 入口；Provider 按具体服务、端点和模型选择类型化原生协议编码与缓存策略，共享传输只执行所选策略。缓存字段不能由 OpenAI-compatible、模型名称相似或模型发现结果推定，不向其他供应商透传。缓存写入收费或保留期变化由独立可选服务声明，未启用服务不受影响；服务状态与实际支持清单以目录和 Provider 实现为准。供应商的 system 合并、最小缓存 token、构建延迟和到期策略属于端点能力限制，尾部放置不证明服务端已经保留相同前缀；不得为缓存省略时间、改变 Skill 权限或降级可信指令。使用方法见[开发指南](../docs/04-指南与运维/01-开发与部署指南.md#442-供应商缓存服务选择与验证)。

缓存读写 token 按供应商实际返回归一化，未返回仍为 UNKNOWN，合法零值保留。验证分别记录同一冻结场景的编码消息与工具前缀、input/cache read/cache write tokens、费用和首 token 时延；本地协议测试只能证明编码与治理正确，不能证明真实命中率改善。不新增 Prompt Cache 数据表或独立缓存服务，生命周期见[数据清理与保留规范](../docs/04-指南与运维/11-数据清理与保留规范.md#23-关联存储登记)。

协议由任务所需能力及真实验证选择，不以已有传输实现限制候选。对采用“最新 SYSTEM 替代早期系统提示词”的 Messages 路由，Provider 将内部累积指令投影为完整有效快照，相邻更新合并；不支持历史更新的模型使用前置完整快照。投影保留可信角色、完整工具调用组与原调用身份，不能仅发送末尾动态事实而丢失核心规则。协议派生文本和消息容量由同一投影来源计入准备预算，供应商实际计量另行落账。文本、结构化响应、工具、推理及媒体能力分别校验，不将 JSON 输出能力作为所有 LLM 登记的前置条件，也不向缺少能力的协议降级强制响应契约。

### 13.2 原生状态与推理档位约束

Chat、Messages 与 Responses 分别由协议适配边界承载。Messages 的 thinking/signature、Responses 的 encrypted reasoning 与完整原生 items 属于受控私有续接事实，不进入公开正文、事件或日志。同一 Run 的恢复和工具续接使用原冻结请求与完整原生事实；新 Run 从公开历史建立新 series，不跨 Run 自动继承私有状态，也不通过重发 UNKNOWN 请求补齐状态。原生状态的完整性校验与公开历史投影分别负责，不能只用可见文本重建私有工具回合。

推理档位由 SDK 的服务、协议及模型能力交集约束，reasoningOptions 保留官方 source/sourceUrl，宿主按有效选项展示并冻结；DEFAULT 表示遵循该服务的明确语义，不表示统一关闭。配置变化不得改写原结果，显式不支持的档位在发送前拒绝。原生 Responses 的 plaintext `reasoning.content` 已实现。工具 arguments 与原生状态按 JSON 语义比较，不因无语义差异的空白拒绝回放；Messages 的带 signature 空 thinking 允许保存与回放，不要求每轮具有非空推理文字。

## 14. Skill 按需加载与释放

保留 ALWAYS/ON_DEMAND、冻结包版本与受权资源机制；未激活只给目录，活动入口正文仅一份且完整、不语义摘要。长示例/脚本/资料放资源，资源大输出使用引用。

活动正文定位到当前 Run 首次经过校验并已提交的成功加载结果之后；重复 use_skill 返回 ALREADY_ACTIVE，不增加正文、不改变原来源或版本。原生多调用组把正文放在全部结果之后，ALWAYS 也以自动加载事实为来源。加载来源被合法摘要或原文引用覆盖时，完整有效正文置于对应替代视图之后；来源缺失或不匹配则拒绝准备，不为保持缓存遗漏正文。

Native 使用 `use_skill(skill_handle)` 加载当前 Run 冻结版本的主正文，内部规范动作仍为 ActivateSkill；没有模型主动停用或重新激活。加载集合在 Run 内只增加，Run 结束自然释放；新 Run 按新的合法受理冻结状态。权限、精确依赖、冲突组、model_invocable 与挂载预算在首次加载时检查，资源按已加载指引调用 read_skill_resource 读取。加载超硬预算先压缩合格历史，仍不容纳则拒绝采用，不截断正文。历史压缩不改变已加载集合，恢复继续使用原版本、原首次成功来源和完整正文，不额外调用模型判断是否有用。

## 15. 统一计量与诊断

图像按实际请求变体记录视觉 token、图像数量与 wire bytes，冻结计量版本；上传大小和 Base64 字符数不充当视觉 token，Provider 实际 usage 仍作为独立结算事实。

请求压力、上下文组成、Provider 实际 usage 分开记录。系统/Agent、tools、任务、Skill、记忆、摘要、近期历史及 framing 归属不得重计，跨块 token 边界差异显式归账。后端发送与诊断使用同一度量版本，前端不自行分词。

记录压缩触发/前后/采用或拒绝/耗时、溢出补救、回读及缓存命中/失效；摘要尝试或跳过结果独立于最终压缩采用结果，采用原文引用后仍保留摘要未采用的原因。阶段覆盖准入/排队、`TASK_SELECTION`、上下文、摘要、主模型、工具和完成。`TASK_SELECTION` 只记录显式任务选择；不再记录 `TASK_MAINTENANCE` 或 `FINAL_TASK_SAVE`。SSE connected、首个模型流事件、首个用户可见回答及完成分别记录，重叠阶段不相加冒充端到端耗时。

主模型、显式任务选择、摘要、重试关联原根请求，分别记账后汇总。未知 usage 不填零，Provider 缓存子集按其口径归一化。保留现有 Run 预算计数语义，辅助调用独立记账并受冻结配置与剩余时间约束，不重复计入主模型计数。只有阶段级事件，不逐 token 遥测；技术信息进入现有诊断界面，普通聊天仅显示必要进度。

诊断仅在宿主 DEBUG 日志开启或现有 tenant／Run／截止时间采集范围匹配时构造。关闭时直接执行原操作，不进行阶段计时、关联摘要、诊断 JSON／hash、上下文分项计量或恢复聚合，也不打开诊断 JDBC scope；业务 token 计量、进度心跳、续租与停滞检测独立保留。无显式诊断 Sink 时不隐式写入业务 SessionLog。

显式采集的诊断事件通过有界后台队列按完整 owner 合并事务，入队时重新核验采集范围、截止时间、关闭状态和容量；DEBUG 日志本身不授权持久化。事件时间保留采集时刻，队列接收不冒充持久化成功，丢失和写入失败显式计数。仅诊断可异步，输入、工具结果、取消、终态和公开输出仍按其原持久提交契约执行。诊断可能晚于业务完成落库，缺失项不能填零或作为恢复依据。

驱动分段另记录 `MODEL_PREPARATION`、`MODEL_PREPARATION_COMMIT`、`DECISION_DECODE_AND_COMMIT` 与 `CHECKPOINT_LOAD_AND_RENEW`。可选 JDBC 观察通过 `jdbcObserved` 表示是否启用，`jdbcScope=current-thread-inclusive` 说明仅含当前线程及嵌套区间；启用时记录连接获取尝试数与耗时、JDBC execute 调用数与耗时，未启用时字段缺省。连接获取耗时包括驱动开销，不是独立池等待；execute 耗时包含数据库等待，不能拆作锁等待。跨线程调用不归入父线程，嵌套区间重叠，不将分段相加推导端到端或完整 SQL/锁成本；观察不采集 SQL、参数、凭据，不改变事务和连接关闭所有权。

### 15.1 驱动期限与停止

执行驱动使用任务活跃时间预算、已冻结的单次调用期限、取消信号及租约写权分别控制推进，不提供独立的 Session 无进展超时配置。单调活动计时用于累计实际执行时长；等待用户或外部回调按其持久等待契约处理，不能将 Worker 补扫或租约续期当作业务进展、外部请求重试或预算重置。

Worker 领取、直接唤醒与持久到期恢复只安排原 Run。续租未确认、取消或失去写权后停止新派发；已有确定结果从原请求、Attempt 及结果事实采纳，无确定结果保留 UNKNOWN，不能因重新领取而重发。模型、MCP 和其他能力的传输等待及正文读取仍受原 InvocationControl 与所属适配器控制；单次调用期限、任务活跃预算和持久等待有效期不能合并成一个全局 timeout。

批次停止后不启动新的调用，在途操作按真实结果收敛。线程中断不能证明外部副作用未发生，也不能强制终止拒绝响应中断的 Provider 或数据库驱动；执行池保持有界，恢复从原持久事实决定可继续范围，不以补建线程或盲目重试掩盖停滞。期限和取消责任见[共用调用契约](03-核心对象模型与状态机.md#761-共用身份引用与失败契约)，宿主配置归属见[技术架构](../docs/02-架构与设计/01-技术架构.md#3-宿主边界)。

### 15.2 运行中用户纠正与重复调用

用户纠正以 `user.steer` 原文追加到当前 owner/Run 的 SessionLog。每次准备冻结一份包含空选择的视图，位于完整工具结果组之后，作为 USER 消息参与预算；旧摘要不能覆盖它，旧准备重放不吸收迟到纠正。PENDING 表示尚未进入请求，INCLUDED 表示已提交到冻结准备，CONSUMED 表示对应模型结果已被 Session 采用，均不代表业务动作成功。与终态并发接收的内容保留未消费；下一轮只由用户显式发送，运行时不合成新请求。

重复检查最多读取最近 20 个动作，比较冻结工具版本、规范参数及真实结果，识别长度 1–4 的周期；3 次重复警告，5 次且全部是只读成功或确定失败时停止。成功写入最多警告，结果变化或用户新纠正打断旧证据。只读轮询通过工具 inputSchema 的 `x-skillforge-polling: true` 明确豁免，不能仅凭名称猜测。判断与来源引用进入冻结准备，恢复重新验证；模型正文只接收进展事实，动作指导由 skillforge-prompts 维护。阈值属于当前版本的运行策略，调整须发布新版本。

原生同轮混合业务工具与 Skill 资源读取时，窗口仍只计业务工具动作；每个工具样本附带该模型回合按原始槽序采纳的资源身份，其反馈由同一 Run 的冻结包确定。资源内容或顺序变化打断原有相同周期，相同资源不豁免工具重复治理；资源读取不新增外部 Tool Action 或工具预算。仅资源读取的回合沿非工具动作规则清空旧周期。进展准备采用 v3；依赖 v2 的在途运行和需要重新构建的存量终态不兼容，环境切换须先收敛或隔离相关运行，不能修改或重派旧事实。

## 16. 只读多工具批次

模型同轮生成多个调用与 Runtime 实际并行执行分别声明。冻结模型工具的 `batchEligible` 表示允许同轮多调用：普通工具满足只读、无需确认且可由模型调用即可，`read_skill_resource` 是唯一原生资源读取例外；`parallelSafe` 仍只决定实际调度方式。OpenAI 兼容协议的 `parallel_tool_calls` 按当前原生目录是否存在上述声明开启，不能因只读工具必须串行而关闭；仅写工具、需确认工具或其他控制函数的目录仍关闭。该生成开关不授予调用权限，完整响应仍经过原整组校验，恢复沿用原冻结声明。

模型在同一轮可以返回多个普通 READ_ONLY 且无须确认的工具调用，整组默认上限 8，沿用同一 decoder、动作、子操作身份、checkpoint 与回放。仅当整组工具均由可信平台配置显式声明 `parallelSafe=true` 且 Runtime 判断独立时并行；否则整组按原调用顺序串行，`parallelSafe=false` 不拒绝同轮只读多调用。调度方式从原冻结目录推导，恢复与等待续跑不改用当前配置。统一数量由 `ToolCallLimits` 维护，MCP hint 不能直接授予并行资格。写、代码、确认、Skill 激活、HITL/Workflow 等控制动作仍按原单调用与审批规则执行，存在结果依赖的调用分模型步骤。

`read_skill_resource` 只读取已激活 Skill 的原冻结包，可与普通只读工具同轮请求，也可同轮读取多个资源，共同受上述整组数量限制。它仍使用原生 AGENT_ACTION 身份，不伪装外部 Tool 或产生 Provider Attempt。整组先核对冻结声明、参数和普通工具资格，再在原模型结果采用时提交资源加载事实；业务工具沿原单工具或批次持久执行路径推进。完整 assistant 调用组按原 callId 和顺序配对资源反馈与真实工具回执，全部结清后才进入下一次模型调用；恢复从原模型结果及冻结包重建资源反馈，复用已完成外部子调用。资源加载不增加工具授权，依赖尚未读取正文才能构造参数的业务调用仍应在后续模型步骤生成。

批次数量的最小值、上限和工具子序号范围由 API 所属 `ToolCallLimits` 集中定义，解码、路由提交、执行池及安全结果冻结共同采用。各消费者不得另设更小的同属性门槛；数量合法仍须通过完整冻结决策、逐项来源、权限及计量证明。

整批先做结构及资格校验，冻结顺序、参数与子 ID；预算到期先按原预算契约终结。任一调用的资格或参数不合格时整批不派发，通过明确决策拒绝结果正常收口，不以未处理异常遗留 RUNNING，不拆分暗中执行。派发每项仍验当前权限和资源，计费/工具额度按子项，遵守机构与 Provider 上限。

子结果完成即持久化，模型视图按原请求顺序，批次结清才进入下一模型调用。单项失败保留失败及其他成功结果；重启复用已完成子项不重执行。取消阻止未启动项，已启动调用先保存返回结果，不能合成成功。已终结的工具未知结果不阻止本轮停止调度；执行记录继续显示未知，取消不撤销已执行操作。多调用组按 §8 压缩，不以隐藏并行大工具绕过契约。

批次属于统一 Agent Loop 的 `batch` 决策能力，不绑定 Plan 或 Todo。整批先冻结顺序、参数、子调用身份和原决策，并在任何子调用派发前完成结构、资格、权限和预算检查；任一项不合格则整批拒绝，不拆分暗中执行。每个子调用完成后持久化真实结果，Core 只从真实提交结果生成对应 `actionReceipt`，不创建聚合 Action 或伪造聚合回执。Todo 如被模型另行写入，只是独立的 SessionLog 协作投影，不推进、确认或回写批次状态；`pending`、`unknown` 和取消结果均按各自 Action/Session 契约处理。

## 17. reasoning 小批次持久化

首期只改 reasoning 路径，不改变回答发布或工具决策校验。相同尝试、相同类型按 100ms 或 2048 Unicode 字符任一先到刷新；首个符合已有展示规则的片段立即提交。计时器独立触发，不依赖下一片段到达。

每批先提交后发布/回放，记录 attempt 与来源序列范围。正常结束、受控错误和取消先刷新已接收片段，再发终止状态。每尝试缓冲上限 65,536 Unicode 字符，大输入分批，满时背压且刷新串行，不静默丢弃。崩溃最多损失未发布尾部，不盲目重放模型。完整结果、最终 usage 和协议状态仍走既有终结流程。

Native 最终正文整体通过校验后随原 Run 结果持久提交，取消独立正文流 Journal 及其累计前缀快照。执行过程继续使用已有 Action/Observation 与 Outbox 事件；完整结果和过程分别按原身份恢复，不为展示拆分最终正文或重新调用模型。正文持久化成本按实际结果测量，不沿用历史增量快照的行数或空间估算。

## 18. 通用稳定前缀

固定模块顺序、序列化及未变化内容，不把请求时间或随机 ID 加入稳定 system 正文及其缓存键。可信当前时间按 §12 放在动态末尾，稳定指令投影只按实际固定内容复用。真实状态、配置、权限变化优先于缓存，压缩可形成新前缀。仍发完整请求，缓存 token 仍占输入窗口；实际缓存 usage/延迟用于观察，未知不计零，相同前缀不是命中证明。供应商缓存字段及历史 SYSTEM 更新仅按前述冻结协议能力启用，不为追逐主模型缓存更换独立摘要模型。

## 19. 不开放完整提示词替换

现有 Agent、平台、系统用途配置加具名模块满足配置需求。Runtime 交互协议由程序维护，并与批次、释放和引用读取一致；业务 Markdown/JSON 呈现要求不覆盖执行协议。不增加 complete-prompt 或业务模板整份替换入口。

## 20. 配置与发布边界

上述数值是已批准的首期目标默认值，实际生效值由版本化配置与 schema 证明，不能仅凭设计声明已部署。摘要用途使用独立发布模型，无隐式 fallback；运行冻结策略及模型配置。保留现有累计 Run 预算，并发与预留空间只使用本项目已发布配置。

不增加旧协议/数据库格式兼容分支。schema 集中调整，旧活动 Run 不跨新协议继续，发布前排空或明确终止并保留未知结果。撤销只针对该批代码/配置差量，数据库与外部结果不能靠 Git 回退；启动和发布核查见[部署指南 §5.3](../docs/04-指南与运维/01-开发与部署指南.md#53-本地启动)。

## 21. 按需工具发现

本节定义按需披露的目标契约。当前 `AgentExecutionProgram` 主执行链仍向模型提供完整工具定义，`search_tools` 只返回冻结授权目录的搜索摘录，尚未接入下述搜索结果驱动的定义展开。模型可见说明必须反映当前可执行能力。

仅当 Agent 显式挂载 `search_tools`，且授权目录超过 12 项或工具 schema 与描述合计超过 16000 字符时，模型准备阶段缩小初始目录。核心工具常驻，小目录保持直接显示；未挂载搜索工具时不隐藏能力。

搜索仅在当前完整 owner 的授权目录内匹配，返回句柄、名称和短描述。下一次模型准备只采用当前 Run 已提交、来源验证为平台搜索工具的成功结果，最多保留最近 24 个发现句柄，并与当前授权目录取交集后显示完整定义。搜索本身不能授权、执行工具或把任意正文升级为发现结果。

冻结准备保存实际选入的完整目录，重放不重新搜索。执行仍逐次验证冻结目标、当前挂载与 IAM；撤权、版本漂移不能借旧搜索结果恢复调用资格。

## 22. 程序化工具调用

`run_code` 是普通 PLATFORM Tool，在独立 Node 沙箱中执行程序。程序通过 `tools.call(handle, arguments)` 串行请求本次父动作所属模型准备中已显示的工具；发现新能力须先结束当前程序，在后续模型步骤使用已展开的定义。宿主凭据不进入沙箱，程序不能直接调用 Provider。

每个父动作最多 1,024 个子调用，序号映射到独立子 Action，程序子序号 9–1,032 区别于原生模型批次的 1–8，单动作仍为 0；边界由 `ToolCallLimits` 统一维护。子请求先以完整 invocation、参数、策略和截止时间写入 SessionLog，再进入原 Core ToolCycle 的 claim、permit、结果登记、投影与终结流程。相同请求只能回放相同内容，参数变化拒绝；禁止递归程序调用、计划与目标控制、需要交互确认的工具。

投影持久化明确区分普通动作准备与程序请求事件，两种来源互斥，并通过外键绑定同一租户、Run 的原事实。工具执行时限由 Core 在 Provider 发送时裁剪，结果落账仍使用父动作的有效窗口。宿主切换执行线程只传递经父范围核验的 Run；父范围关闭后子请求失去资格，嵌套租户绑定结束时恢复原值。

普通动作计数与已登记的程序子请求共同占用原 Run 工具预算。子请求失败、结果未知或登记后未发送均不退还额度；程序不拥有独立的无限预算。子调用继承父动作的取消与有效窗口，不能延长父 deadline；结果未知或权限失效后停止程序，不整体重跑或自动重试子动作。已成功的子结果保持独立执行事实，可经受控历史回读定位，模型只接收程序明确输出的内容。

## 23. 持续 Goal

Goal 只由用户显式创建，状态与完整 owner 绑定，并以 SessionLog 中的完整快照和 revision CAS 为唯一事实。状态为 `ACTIVE`、`PAUSED`、`COMPLETE`、`BLOCKED`；后续自动轮次上限为 1–20，不包含初始用户 Run。首轮输入等待创建日志提交后才执行；预留下一输入不消耗已启动轮次，仅真实输入接受后计数。暂停清除旧预留，旧输入不能重新取得执行资格。

宿主驱动只在用户创建或显式恢复后启用，复用统一 Loop、可信输入准入和现有 Run 预算。会话空闲且前轮完成后才发起下一轮；失败、取消、终止和额度耗尽停止自动续行。用户恢复可为前次失败或取消的 Run 开启一次新轮，后续失败仍停止。重复控制命令只回放其结果，不替换正在执行的登记或重启已停用的排队。

服务重启保留 Goal 事实，但不凭持久 `ACTIVE` 状态恢复后台许可；用户必须重新显式恢复。普通消息到达时停止后续自动排队，当前已接受轮次仍可收尾；用户暂停则进入取消协议。`get_goal` 只读当前状态，`update_goal` 仅允许当前目标所属 Run 标记完成或受阻，不创建目标或开启续行。指令正文归 `skillforge-prompts`，模型不能以剩余额度为理由扩大任务。

### 23.1 成果发布后的完成请求

`SessionGoal` 日志独占 Goal 状态；成果服务独占所选真实文件核验、冻结与正式发布事实。已有冻结成果待发布时，`update_goal(COMPLETE)` 拒绝提前完成；仅存在中间候选不强制交付，模型在最后一次 `finalize_task_outputs` 提交可选 `goal_completion: { expected_revision: 正整数 }`。主 Agent 直接依据原用户任务、当前 Goal 目标和适用批准计划判断内容与完成情况，不在首轮接受专属自然语言要求契约，也不由宿主证明未遗漏语义义务。无成果目标可以依据真实验收直接完成。模型只能提供预期 revision，Goal、owner、Run、result_ref 和稳定操作 ID 由宿主构造并绑定可信身份。完成请求纳入冻结指纹；精确重放复用原结果，异内容冲突，放弃成果与完成 Goal 不得同时提交。冻结后仍只允许最终回复，不另开 Goal 工具通道。

宿主校验 Goal 为 ACTIVE、revision 精确匹配且当前 Run 归属有效；文件核验、冻结结果、完成请求与 `pending` 处理标记在同一成果事务提交。发布前 Goal 保持 ACTIVE，查询返回与当前 Goal/revision 匹配的派生 `completion_pending`，界面显示“收尾中”。查询还返回精确 Run/result_ref 的 `pending|published|failed|cancelled` 发布事实、稳定原因及正式 revision 引用。该投递进度不构成另一个 Goal 状态机。

Run 真正完成后，成果服务发布并提交事务；宿主在发布事务提交后读取权威事实，通过独立 SessionGoal CAS 提交 COMPLETE，最后记录 `settled`。成果事务与 SessionLog 事务独立，不能在未提交的发布事务内完成 Goal。有效完成请求待处理期间，驱动不排入下一模型轮；最后允许轮次也可自动收尾，不增加模型验收调用。

Run 或发布明确失败时，原 Goal/revision 仍匹配则提交 BLOCKED 和稳定原因；技术异常保留 pending 并由现有发布恢复任务重试。用户暂停、恢复、替换或其他 revision 推进胜出时记 `superseded`，不得以新 revision 重试旧完成动作。恢复先检查原操作回执，再判断竞争，覆盖“发布已提交、Goal 未提交”与“Goal 已提交、处理回执未写入”两个窗口。恢复扫描包含已 finalized/abandoned 且完成请求仍 pending 的记录；服务重启只收敛既有请求，不恢复模型许可或提交轮次。未收尾请求及其来源文件受清理保护。

系统可以证明实际执行与已声明成果的正式发布；自然语言目标的专业验收由模型及业务契约负责。


## 24. 共享任务预算与持久结算

宿主在受理任务时从真实产品目标及已授权冻结能力选择 STANDARD、DELEGATION 或 TEAM；维护任务使用独立 MAINTENANCE 域。团队优先于委派，普通 Agent 只有启用委派并存在已授权目标才进入委派档。场景、根身份、配置版本与七个资源维度一起冻结；成员、精确恢复及同 Goal 续轮沿用根，不由客户端或模型声明。

累计治理模式显式区分 Enforced（有限额度）与 ObserveOnly（只计量），随原 Run 的预算登记冻结。子 Run 必须与真实原根的场景和模式一致，各 Run 保留自身受理时冻结的来源版本，不从版本字符串猜测模式。平台机构和系统 Agent 使用 Enforced，独立桌面普通任务使用 ObserveOnly；后者没有数值限额或平台继承，不通过零值、null 或极大整数表示。只计量仍保存调用预留、发送、结果、结算、UNKNOWN 和活跃区间；不因累计额度自动进入收尾，宿主显式收尾、权限、取消、租约、单次调用期限和物理限制保持有效。不支持该模式的宿主或适配器明确拒绝，不能伪装成有限大额度。以下根、角色、阶段与自动收尾分配规则适用于 Enforced；计量、去重和未知事实保留规则适用于两种模式。

业务和辅助模型次数独立。正常推理与网络重试计业务；摘要、前台记忆、Embedding、Rerank 和明确协议修复计辅助。全部输入、输出、总 Tokens 及活跃时间扣根总账；缓存和 reasoning 子集不重复加总。辅助耗尽不能借业务身份。程序内工具逐次计工具次数，外层也计一次。供应商 usage 是结算事实，压力估算与 UTF-8 请求保守上界分别使用，不称为精确计费。

平台只编辑普通、协作、团队三个场景各五项根额度：业务模型次数、工具次数、知识次数、累计总 Tokens、活跃时长。默认依次为 256/1,024/2,048 次业务模型，1,024/8,192/16,384 次工具，256/1,024/2,048 次知识，8,000,000/32,000,000/64,000,000 总 Tokens，7,200/14,400/28,800 秒；时长最多七天。根辅助次数为业务次数的一半向上取整。输入、输出分别计量，但每层上限均采用该层总 Tokens，不再单独配置份额。源码默认只作用于缺少既有运营修订的默认读取及之后的新受理，不覆盖数据库中已有 `task_budget` 修订；试运行数值不证明生产容量。

对外 Agent 覆盖使用 `max_business_model_calls` 表达业务模型调用次数，内部 LoopBudget 与 LoopUsage 使用相同业务口径；辅助模型次数独立治理，不占用该本地业务计数。覆盖省略或为 null 时继承，旧 `max_iterations` 字段即使显式为 null 也拒绝，不设置别名或双协议。Workflow 的步骤与节点回访保护仍由自身引擎控制，分别使用 `WORKFLOW_MAX_STEPS_REACHED` 与 `WORKFLOW_NODE_REVISIT`，不能解释为 Agent 业务模型次数耗尽。

角色额度由代码中的显式 Allocation 比例管理，不从随版本变化的默认根反推比例；精确比例归 [ChatBudgetSettings](../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/runtimeconfig/ChatBudgetSettings.java)。根变化后各维按已批准比例缩放，向下取整，原正额度最低 1，不超根并防溢出。主 Agent 继承根时长；成员按角色时长比例派生，来源为实际已冻结父根。Agent 五项显式覆盖可提高或降低派生额度，超根明确拒绝。该次策略来源为 `budget-policy.v4`；后端返回只读派生说明，前端不实现算法。

维护额度由代码固定为辅助 1,024 次、总 Tokens 20,000,000、活跃 12 小时。阶段默认业务 256、辅助 128、工具 1,024、知识 256、总 Tokens 5,000,000，输入/输出同总量；初始有效档受最终 Run 限额约束。首次及后续调用先测量，再在根锁事务中扩展当前阶段，阶段扩额不改写首次冻结的基础档。提高累计额度不改变模型窗口、权限、计费或原冻结预算。新建 Goal 的界面与命令默认 256，显式范围为 1..1,024 轮，轮数不重置根预算；该默认不意味着已实现 Harness 的连续阻塞三轮提醒或桌面 Goal 插件。

运营配置整组移除 run_budget 与 context；task_budget 保留单修订、冲突检测、历史及回滚。上下文版本由代码只读展示，75/50/20、历史分页 100、工具立即外置 `min(12,500, B−1)`、压力字符 8,192、预览头尾 4,096/1,024 同属代码策略。预览实际包装与裁剪标记也必须计入 8,192 字符阈值。候选内容和 tokenizer 共用部署资源上限，默认 32 Mi 字符；解析深度、节点、消息数量及传输载荷仍由所属边界保护。Redis 热视图独立默认 100 条。

NewRun 先完成预算登记与准备 Profile，再在宿主受理事务写入完整冻结引用；预算登记加入宿主事务，准备或最终写入失败回滚登记。Run 保存精确 Profile 引用，不复制整套技术策略；新动作与恢复读取原引用及账本，不按现行策略重算。新格式直接替换旧配置和旧冻结格式，缺失完整引用明确拒绝。

根和 Run 的资源预留拒绝在原根锁事务中保存准确范围与首个超限维度，维度按资源枚举的固定顺序选择；消费者使用同一稳定原因，不在事务结束后读取余额猜测。原因格式为 `execution_budget_{root|run}_{resource}_limit`，resource 区分业务模型、辅助模型、工具、知识、输入、输出和总 Tokens；活跃时间、收尾要求与请求冲突继续使用各自原因，不伪造资源维度。阶段额度按现有派生与扩展机制管理，缺报或 UNKNOWN 的预留保持原事实，不能为显示剩余额度而归零。

每次主模型准备以宿主真实收尾事实构造紧凑请求，测量保守输入及实际冻结输出上限，保护普通任务一次最终回答，文件任务最多两次收尾模型与一次 finalize。输出与普通单次调用一致，默认32,768。收尾模型次数及各次输入、输出和总 Tokens 分别预留；时间保护采用一个共享收尾模型窗口，加上来自真实配置的本地核验、传输等处理窗口，不按模型调用次数乘以完整模型超时。多个收尾调用共享该模型时间窗口，实际消耗持久累计，后续调用及恢复不重置窗口；每次外调同时受单次模型超时和共享剩余窗口裁剪。业务调用的有效 deadline 扣除仍需保护的收尾窗口，不能先用尽业务时间再要求完整收尾。需求缩减可归还多余保护，根及当前主 Run 均保护最低需求；成员不能借用。

例如文件收尾需要两次模型调用，冻结单次 `modelTimeout=120s`、本地处理窗口为 `120s` 时，未来收尾时间为共享模型窗口 `120s + 120s = 240s`。两次调用仍各占一次模型次数与各自 Token，时间不计算为 `2 × 120s + 120s = 360s`。若 Agent 总时长为 `300s`，且尚无已耗时或更紧的有效期限，则业务可使用的时间为 `60s`。该算例只说明同一冻结配置的计算口径，不修改现有 Agent 配置或历史执行事实。

下一业务动作无法在保护收尾的前提下受理，但收尾本身仍可容纳时，持久进入 CLOSING，只允许真实收尾工具及最终回复，不再委派、检索、Workflow、Skill 扩展或 Goal 业务续轮。保护本身确实不足时以原事实失败，不用进入 CLOSING 隐藏不足。75% 软提醒随模型准备冻结，恢复不读取变化中的提示内容。

阶段内再次准入采用[对象模型的未来需求契约](03-核心对象模型与状态机.md#561-headless-模型准备与提交协议)：成果冻结工具已派发时，剩余保护包括当前核验窗口、后续最终模型和新增回执输入，不重复保护已经占账的当前模型、停止及冻结调用。需求缩减不释放历史消耗或未知预留。

真实收尾不足在原 `execution.completed` 事件的 `skillforge.runtime.execution.completed.v2` 载荷内原子保存 `budget_failure`，不另建一次终态或在展示时读取当前余额重算。预算失败使用 `skillforge.runtime.execution.closing-budget-failure.v1`，稳定码为 `execution_output_closing_budget_insufficient`，保存实际 `phase`、各作用域的 `shortfalls` 及原冻结 `time_calculation`。不足项 `required` 表示包含已用量的总需求，`available` 表示该作用域原总额度；`consumed` 与 `reserved` 分别保留，不把总额度解释为扣除消耗后的余额。`time_calculation.required_ms` 则只表示未来仍需保护的共享模型窗口与本地窗口之和，两种 required 口径不得混用。各数量以精确十进制字符串公开，具体字段由类型化契约与 codec 拥有。

两个后台从同一原终态读取具体不足及已登记的业务模型、工具、辅助模型尝试次数，展示规则见[会话观测设计](../docs/02-架构与设计/17-平台会话观测设计.md#21-turn-与-step-观察视图)。尝试登记、实际发送、供应商返回和业务成功分别表达；历史原事件没有不足数值时明确未记录，不使用当前配置补算。原预算及调用账本仍独占预留、消耗、UNKNOWN 和结算，公开终态中的事实不产生新执行权限。

调用顺序为冻结请求及权限 → 原子预留 → 持久许可 → 标记发送 → 保存终态和用量 → 幂等结算 → Session采用。JDBC根锁同时校验根、Run、阶段、收尾资源与时间。相同attempt只复用原指纹和预留，不再次发送；同身份异请求拒绝。用量分维度结算，未知、缺报、超时不释放预留；已保存结果未结算可恢复结算，已结算未采用仍复用原事实，不再外调。活跃时间以可信驱动区间并集计算，成员重叠只算一次根时间，暂停和等待不计时，服务重启不重置或把停机时间算作执行。

预算账不拥有Run、Goal、权限、计费或成果状态。正式发布提交后Goal CAS的完成顺序保持不变；新独立任务或明确替换Goal建立新根，旧未知attempt仍归旧根。新目标版本不回填历史预算、不双读旧格式、不重放失败业务。

## 25. 模型可见控制信息

内部执行契约与模型阅读文本分别维护：阶段、门禁和失败反馈用简短行动说明表达原因、未完成事项与下一步，诊断仍保留原原因码和回执身份；不能将失败推断为未执行，UNKNOWN 不提示盲目重发。计划、委派、Workflow 和业务查询的结构化结果保持原字段，在必要处说明受理、完成及未知的区别。

MCP 明确返回的参数拒绝可映射为封闭安全原因，保留原失败及结果引用，提示模型依据已授权 Schema 修正参数；不把错误当零值，也不透传服务器自由异常正文。修正后的不同参数属于新决策，不改变原失败、不授予自动重试或额外权限。MCP 端公开业务规则与模型实际收到的分类分别核验，不能仅凭服务端错误文本已改善就声称模型已能看到该文本。

Skill 已加载入口及资源正文直接呈现原文，附精确包内路径、版本身份和资源范围；不得把包内路径当成宿主文件路径，工具声明和脚本正文不赋予执行权限。时间、知识引用和业务 Schema 的既有结构化信息保留明确的解释与数据边界。

同工具同参数命中已有确定结果时，模型反馈明确说明复用原结果、未重新执行，保留原安全内容和本次 tool_call_id 配对；成功、失败及覆盖范围不因复用改变。单调用、整批复用及新旧混合批次使用相同说明，不新增工具派发或工具消耗。MCP 同时提供结构化正文和文本时，仅省略与已呈现结构化正文逐字一致的文本，保留额外说明、不同数据及多模态内容。

每次新主模型准备读取真实预算账本的观察快照，展示共享根与当前执行较紧的余额，扣除消耗及全部预留，并说明当前收尾保护、业务余额和活跃时间。该观察采样在本次请求计量及预留之前，收尾保护随本次实际请求重新计算，余额不是派发许可；ObserveOnly 明确未定义限额。模型结果采纳及恢复只复用原请求中的预算消息，不重查当前账本或改写历史观察。

收尾阶段同步约束模型请求：仅提供当前冻结允许的收尾工具；没有收尾工具时工具集合为空且 toolChoice 为 NONE。阶段在准备中发生变化时重新投影并计量最终实际消息与工具，冻结调用和恢复采用同一投影；后端输出护栏继续验证模型返回，不以提示词代替执行治理。
