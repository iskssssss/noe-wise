# 错误处理与恢复

## 错误与处理责任

能不用 `try/catch` 就不用，默认让异常沿既有调用链传播到负责处理的边界。只有当前边界确实需要恢复、转换错误契约或履行失败处理责任时才捕获；不为包一层、重复记日志或原样重抛增加 `catch`。资源释放优先使用既有生命周期机制或 `try-with-resources`，必要的 `finally` 不要求附带 `catch`。

业务失败使用稳定错误码或明确类型及必要上下文，不解析消息字符串决定分支。技术异常保留原因链，在能够决定后续行为的边界处理；HTTP 映射归[API 契约](../nw-engineering/references/engineering-standards.md#响应与错误分类)，日志与脱敏归[观测规范](../nw-engineering/references/engineering-standards.md#事务日志与可观测性)。

区分错误传播、结果记录与恢复责任。捕获异常不会撤销已发生的写入或外部副作用，记录日志也不等于恢复；由状态所有者判断不变量、事务结果与可继续范围。后台任务、异步回调和事件监听同样要有结果归属，不能吞掉异常后报告成功。

向调用方提供安全且可操作的原因与后续入口。流式和降级结果区分完整、部分、失败与未知，响应、完成事件及持久状态一致，计量依据实际用量；不能只记 WARN 后把部分结果当完整成功。

## 重试与未知结果

| 已知事实 | 处理要求 |
|---|---|
| 确定在派发前拒绝 | 保留拒绝原因，不伪造已执行或未知结果；按拒绝条件判断能否再次请求 |
| 已有确定失败回执 | 按失败类别、幂等契约及已发生副作用判断，失败不等于没有副作用 |
| 已发出但结果未知 | 保留原操作身份，查询原回执或对账；无安全恢复契约时不得盲目重发，新请求成功不消除历史 UNKNOWN |
| 同幂等键重复受理 | 同内容读取原进度或结果，异内容返回冲突，不生成新业务操作 |

前端显式“核对原操作”须复用原命令与操作身份，且接口契约明确保证返回原进度或回执；同键 POST 只有满足该契约才可用于核对。没有安全核对接口或稳定创建身份时，保留 UNKNOWN，提供只读列表核对和显式人工关联，不能把再次无 ID 创建当作恢复。

UNKNOWN 的解除依据原操作的确定回执或已核实的派发前拒绝；不能仅凭 HTTP 状态、关闭提示或修改字段清除。核对请求自身失败、409 或非终态回执均按实际契约解释，不能覆盖此前 UNKNOWN。

未显式声明策略时不自动重试。策略明确唯一业务责任方、适用失败、最大尝试次数（含首次）、退避上限、抖动及整体预算；SDK、客户端和网关尝试计入同一策略。等待含适用的 `Retry-After` 计入预算，不能每次重置期限；预算不足则结束或交给既有持久调度，取消后不继续派发重试。

状态码、超时、断连或 `retryable` 标记不能单独证明重放安全。Runtime 恢复沿用 Harness 状态机；传输期限、取消和资源释放见[外部调用规则](../nw-engineering/references/engineering-standards.md#外部调用超时与重试)。

## 验证失败后的事实

针对改变的失败路径核对最终状态、副作用、可见结果和必要资源释放，不能只断言异常被捕获。测试范围由[验证技能](../nw-verification/SKILL.md)选择；现有故障的根因定位由[排障技能](../nw-debugging/SKILL.md)处理。
