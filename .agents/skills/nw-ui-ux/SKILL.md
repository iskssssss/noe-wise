# UI 与交互体验

先确认用户在当前界面要完成的动作、结果和可能的失败，再选相关规则。后台采用[视觉规范](../../../docs/02-架构与设计/09-前端视觉与交互规范.md)及受影响的[交互与控件规格](../../../docs/03-规范与术语/06-后台逐控件规格.md)；独立会话端沿用[自身组件和样式](../../../frontend-chat/README.md)。本技能补充设计判断，不复制尺寸、颜色值或业务状态。桌面渲染层沿用这些共同交互原则，保留自身组件、样式和宿主接口。

## 状态与恢复入口

修改前先确定当前身份、业务对象、动作、认证阶段、草稿及原请求分别由谁拥有，按[前端状态规则](../nw-engineering/references/engineering-standards.md#前端状态与接口消费)处理页面重建、保存回执、跨文件编辑和迟到反馈；写结果核对按[错误处理](../nw-error-handling/SKILL.md#重试与未知结果)执行，不为单页另建恢复协议。

先查实际使用的组件与框架版本，再判断表单禁用继承、编辑器历史、路由守卫及原生模态层级。共享组件能力只有通过真实页面接线才能形成保护；不能因简化测试遗漏接线，就增加重复拦截或平行状态框架。

## 复用与视觉层级

新增前先查目标页面和同类页面的布局、组件、图标与 token。后台直接组合 Element Plus，会话端复用本地控件，不跨应用搬运样式或另建同类基础组件；确有缺口才扩展对应组件。单页内容或组合问题在所属页面解决；共享组件自身违反契约，或多个直接消费者存在同因问题时，在共享层修复并核对受影响消费者。按问题来源选择修改位置，不以只发现一处为由绕过共享缺陷，也不修改全局 token 或层级来修一个页面。

标题、正文、辅助信息和主操作有可辨识的层级；同级内容保持字号、间距和对齐一致，图标与文字比例协调。使用已有排版尺度，不用不断增大字重、颜色、阴影或边框制造强调；危险操作与主要任务动作清楚区分。

内容区宽度与密度按[任务布局](../../../docs/02-架构与设计/09-前端视觉与交互规范.md#22-内容宽度与信息密度)选择，具体视觉值按[令牌选择规则](../../../docs/02-架构与设计/09-前端视觉与交互规范.md#23-视觉值与令牌选择)确定；现有令牌不覆盖局部需求时，不强行套值或预建全局配置。

新增或调整内容容器时，按[内容容器与留白](../../../docs/02-架构与设计/09-前端视觉与交互规范.md#21-内容容器与留白)明确提供内边距的层级，检查组件默认值、样式继承和嵌套后的实际留白，再决定局部覆盖；不以全局加大 padding 修补局部贴边。

修改颜色或容器时同时核对受影响的明暗主题，包括边框、禁用文字、选中、错误、编辑器和弹层。对比度、点击区域及文字适配采用[可访问性尺度](../../../docs/02-架构与设计/09-前端视觉与交互规范.md#31-可访问性尺度)；依据实际前景、背景与透明度核对，不靠截图颜色相近推定通过。

## 视觉对齐

对齐以实际渲染的可见轮廓、文字基线和视觉重心判断，不能仅凭 `align-items: center`、相同宽高或 DOM 边界相等宣称对齐。SVG 的 viewBox 留白、图形不对称、描边粗细及字体升降部都可能造成视觉偏移。

- 先选择合适的对齐参照：文字之间按基线，单行按钮或菜单中的图标与文字按可见重心协调；多行说明旁的图标通常对应首行，不机械居中于整个文本块。箭头、状态点和尾部操作保持各自在同组控件中的位置一致。
- 先修正来源与排版：复用同一图标体系，核对图标可见尺寸、viewBox 留白、字体、行高和容器布局；同尺寸图标不一定具有相同视觉重量。比较相邻按钮、菜单行和表单标签，避免只看一个孤立元素。
- 排版正确后仍有光学偏差，允许在所属图标或组件中做小幅局部位移或尺寸校正，并就近说明非直观原因；同类用法复用该修正，不逐页面散落偏移值，不统一给所有图标加 `top` 或 `translateY`。位移不能改变点击区域、裁切图形、遮挡焦点环或破坏文本换行。
- 在真实字体加载后，以正常显示比例观察受影响组合，再用放大图或辅助线定位原因。按改动核对实际中文、英文、数字或多行文本，以及相关尺寸、状态和缩放；不把单张放大截图或几何坐标一致当成视觉验收。没有实际渲染证据时保留待视觉确认。

## 反馈与加载

所有操作反馈统一使用页面顶部 Message，同一反馈只展示一次；字段校验、静态说明与长期业务记录按下表保留所属位置。具体展示参数沿用[视觉规范](../../../docs/02-架构与设计/09-前端视觉与交互规范.md#4-浮层与反馈)：

| 场景 | 反馈方式 |
|---|---|
| 字段校验 | 字段旁持续显示，用户能定位并修正 |
| 提交失败 | 顶部 Message 显示原因与下一步，不在表单或抽屉重复展示 |
| 首次读取失败且没有内容 | 顶部 Message 显示原因并保留可用的重试动作，内容区不伪装为空态 |
| 刷新失败但已有数据 | 保留数据，顶部 Message 提示未刷新并保留重试动作 |
| 短时操作结果 | 复用顶部 Message；来源弹层关闭后仍需看到的结果由存活的页面或应用消息层承接 |
| 长任务、等待确认或结果未知 | 显示真实状态和查看/处理入口，不用会自动消失的消息作为唯一记录 |

核对 Message 时同时检查批次内所有失败来源、去重后的每个对象动作、来源卸载及手动关闭后的恢复路径，具体归属与时长由视觉规范定义；不要只断言消息数量或 `catch` 被执行。

成功、写入后刷新失败及结果未知分别表达；失败保留输入与对象，恢复和重试资格归[错误处理](../nw-error-handling/SKILL.md)。错误文案说明发生了什么及下一步，不输出内部堆栈、秘密或无帮助的技术术语；按钮使用明确动作词，诊断详情按需展开。

首次加载、后台刷新、提交中、首次无数据、筛选无结果分别展示。加载样式沿用所在页面，保持操作区和主要内容的位置稳定；已有内容刷新不改成整页空白或反复闪烁的骨架。按钮忙碌表示真实在途操作，不显示伪造进度；表单数据与并发保护沿用[前端状态规则](../nw-engineering/references/engineering-standards.md#前端状态与接口消费)。

图片、附件预览和异步卡片按已知尺寸或宽高比预留空间，按钮切换忙碌状态不跳宽；字体加载后不应导致关键操作错位。按实际变化检查[布局稳定性](https://web.dev/articles/optimize-cls)，不为普通界面修改新增全站性能门禁。

保存结果、查询数量和后台进度等不移动焦点的动态反馈，通过组件已有的 `role="status"` 或适当 live region 提供[状态通知](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。紧急错误才采用打断式通知；流式内容按有意义的状态或段落汇总，不逐 token 播报，不用读屏通知替代可见反馈。

## 弹层、菜单与输入

按既有产品规范选抽屉、对话框或页面，关闭保护见[视觉规范](../../../docs/02-架构与设计/09-前端视觉与交互规范.md#4-浮层与反馈)。菜单、提示和弹出层需能关闭、处于视口内且不被祖先容器或相邻元素裁切；靠近边缘时使用组件的移位/翻转能力，内容仍放不下则在层内滚动，不反复翻转或无限抬高 z-index。普通菜单的外部点击关闭不能套到受保护的编辑抽屉。

模态打开后焦点进入有意义的位置，背景不可交互，Esc 只作用于最上层并遵守提交保护；关闭后返回触发入口，入口已移除时返回合理的相邻位置。控件有可理解的名称和可见焦点，图标动作有可访问名称；必要解释不能只放在 placeholder、颜色或 hover 提示中。

焦点移动与错误跳转应避开固定页头、底栏和消息条，尽量完整露出控件及焦点环；不能被作者添加的内容完全遮住，见[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)。不移除焦点样式而不提供等效提示，删除当前行后将焦点放回合理的相邻动作或列表入口。

自定义 hover/focus 提示按[悬浮内容要求](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)支持移入阅读、保持显示及不挪动焦点的关闭方式；未遮挡内容等标准例外按实际情况处理。Tooltip 只放补充说明，含按钮、链接或输入的内容采用有相应键盘与焦点行为的 Popover 或对话框。

表单校验避免在尚未完成的输入中途报错，提交后保留输入并让用户定位和修正；长表单多处错误才增加可跳转摘要，具体后台行为见[表单规则](../../../docs/03-规范与术语/05-后台系统交互规范.md#8-表单选择器和动态条目规则g)。身份验证允许密码管理器、自动填充和粘贴，验证码分格输入支持粘贴完整值；不得以安全为由禁用这些[认证辅助方式](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html)，秘密处理仍按安全契约执行。

Enter、快捷键和中文输入法采用所属输入契约，不把候选词确认当成发送；多行输入保留换行。宽度、面板和触摸变化时补读[响应式与输入适配](references/responsive-layout.md)。

## 核对改动

围绕受影响界面核对正常状态，以及本次最可能破坏的长内容、失败、禁用、窄窗口、主题或键盘路径；共享样式改动选直接消费者，不默认遍历全部页面。交互改变检查实际动作与结果，外观判断使用真实渲染；编译、DOM 断言和静态 CSS 不证明视觉或焦点体验。

间距改动同时观察容器四边、同级对齐、嵌套总留白与可用内容宽度，按[留白判据](../../../docs/02-架构与设计/09-前端视觉与交互规范.md#21-内容容器与留白)核对实际受影响状态；发现贴边或过度留白时回到负责该边界的组件修正。

按[交互回归场景](../../../docs/04-指南与运维/12-后台UI实施与验收.md#41-按受影响机制选择回归场景)选择本次改动的代表路径，包含正常、拒绝和相关恢复反例；该表不是每次执行的全量检查门禁。

沿用[后台验收](../../../docs/04-指南与运维/12-后台UI实施与验收.md)和任务约定区分自动、人工及未验证范围；截图或录制只在需要说明、对比或任务要求时提供。已批准设计内的局部调整直接实施；信息架构、主要流程或支持范围存在未决取舍时，先给出具体方案及影响，再确认依赖该取舍的部分，不为每次可见变化新增设计审批。
