# 简化与清理

本文件用于明确要求的简化、清理或相关审计，或当前交付被具体旧入口、重复事实或错误抽象阻断的情况。范围与完成条件见[开发流程](../nw-workflow/references/development-workflow.md)。

## 触发与范围

已批准架构要求的替换按[工程规范](../nw-engineering/references/engineering-standards.md#项目阶段与优先级)直接执行；其他可选简化才评估收益与代价。不因代码旧、文件长或测试少启动全仓清理。

## 消费者证据

用 `rg` 定向查找符号、wire 值、配置键和构建引用，再阅读真实入口。按目标实际暴露方式检查，不将整表变成每次固定清单：

| 暴露方式 | 检查内容 |
|---|---|
| 静态 | 生产调用、接口实现、构造依赖与构建引用 |
| 动态 | Spring 装配、反射、ServiceLoader、配置/profile、插件注册、脚本、序列化、SQL/Mapper、模板与生成输入 |
| 外部或持久化 | SDK/API、宿主扩展、部署配置、持久记录、事件/schema 与受影响环境 |
| 测试、文档、示例与生成物 | 当前目标契约、真实 smoke 入口或仅支撑旧实现的引用；生成物追到来源 |

没有静态匹配不等于没有消费者。示例和脚本可能是产品入口，测试可能保护当前拒绝路径；依据实际用途判断。

历史消费者用于确定同步替换或下线范围，不形成兼容义务。当前目标仍需要的消费者须同步接入新契约；无法取得外部或部署证据时，不宣称“无消费者”，明确受影响范围和待决操作。实际数据销毁或环境重建仍按工程规范的授权边界执行。

## 架构要求的扩展点

只检查直接相关的当前设计及同主题 Note/ADR。当前目标架构仍要求的模块边界、扩展点和依赖反转不能因仅有一个实现而删除；可收窄内部未使用方法。历史设计、已被取代的决定和未批准设想不能保护冲突旧实现。

## 取舍标准

可选简化按完整替换范围判断净收益：删除的实现、入口、配置、依赖、专属测试和文档，减去必要的新实现、替代测试及运维负担。复杂度移入 wrapper 或其他模块不算简化，行数与候选数量不决定结论。

- 行为代价：当前所需能力、公开语义、扩展点、安全、可观测性、恢复和数据正确性；历史行为兼容不作为保留理由。
- 收口范围：生产和动态调用方、配置、测试、生成输入及文档同步处理，不留下失效入口。
- 新增依赖：仅在确需替代依赖时核对语义、平台要求、维护与安全、许可证及构建成本；平台已有能力满足时优先使用。

收益明确且收口可执行才实施，否则保留或缩小候选。改变当前产品需求或已批准架构的取舍按开发流程处理，不以普通清理代替决策。

## 输出与实施

在已有任务摘要中说明所选方案、关键取舍和必要验收；仅对影响最终决策的被拒方案保留依据，不记录完整探索过程。修改与验证沿用[基础规则](../nw-workflow/references/development-workflow.md)及[验证规则](../nw-verification/references/candidate-driven-delivery.md#测试路由)，长期决策按 [Note 条件](../nw-docs/references/notes-governance.md#4-note-触发与复用)记录。
