# 模型使用体验

以模型实际收到的请求、工具定义和结果为准。运行时权限、提交与反馈语义归 [Harness 对象与状态契约](../../../harness-design/03-核心对象模型与状态机.md)，描述文字不能授予权限、绕过校验或建立另一套执行状态。

## 让动作容易选对

工具名称与描述说明用途、适用条件及可观察结果，避免以内部类名和实现步骤替代行为。参数的格式、范围和互斥关系放在参数 schema 或对应说明中；同一事实只写一处，不在工具说明、参数和提示词重复铺陈。

首次上下文先提供当前目标、必要约束和可执行动作；权限、不可逆副作用与调用前置必须在动作前可见。其余材料按需发现，并给出真实可用的查询入口或资源标识；不让模型猜路径，也不靠延迟加载藏起关键限制。

## 让结果足以决定下一步

结果优先给出状态、关键事实、操作身份及可执行的后续入口。受理、完成、部分结果、失败和未知分别表达，不能把进程退出或流结束包装成业务成功。

大结果按所属协议分页、摘要或裁剪，明确遗漏范围，并保留可继续获取详情的标识、游标或路径；关键错误和影响判断的事实不能被摘要隐藏。访问详情仍使用当前授权，不通过结果公开秘密或跨租户材料。必要的相邻上下文可随结果返回，避免为理解一条结果反复查询。

## 核对实际消费者

沿真实装配与渲染入口检查模型最终看到的文字、schema 和结果，行为变化复用相关测试或快照验证。只有需要判断选择效果或声称效率改善时，才做对应任务对照；衡量完成任务的总调用、上下文与结果质量，不只比较提示词长度。普通描述调整不自动触发付费模型调用或新增基准。
