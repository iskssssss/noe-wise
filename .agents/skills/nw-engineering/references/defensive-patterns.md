# 防御性编码模式

> 本文提供缺陷模式与示例。实现规则归[工程规范](engineering-standards.md)，失败与恢复归[错误处理](../../nw-error-handling/SKILL.md)，Runtime 契约归 [Harness 03](../../../../harness-design/03-核心对象模型与状态机.md)；示例不新增生命周期规则、旧入口或通用测试门槛。验证按[评审与验证规范](../../nw-verification/references/candidate-driven-delivery.md)选择当前风险。

## 正交的结果独立上报

超时、退出码或状态码、结果完整性分别记录，再按契约共同判断结果；单一成功信号不能覆盖超时或部分完成事实。子进程可能处理终止信号后以 0 退出，以下顺序会遗漏超时：

```java
// 反例：提前按退出码返回成功，超时事实没有参与判断。
if (exitCode == 0) { return success; }
if (timedOut) { return timeout; }
```

正确做法是保留独立事实，再判断结果（以下为分支示意）：

```java
// 超时或输出不完整时，不能仅凭退出码报告完整成功。
if (timedOut) { return timeout; }
if (exitCode != 0) { return failure; }
if (truncated) { return partial; }
return success;
```

LLM 流式输出或连接器跳过坏分块时，可汇总记录跳过数量与安全关联标识，避免逐块刷屏；结果及完成事件仍须表达部分/失败，日志不能替代完整性契约。

## 公开契约两侧对齐（规范化后再对外）

宿主适配器将不同外部协议转换为所属公开契约。恢复类输入的目标、身份和竞争结果直接引用 [Harness 03 §5.3](../../../../harness-design/03-核心对象模型与状态机.md#53-pendingentry-与-wakeintent) 与 [SDK façade](../../../../harness-design/03-核心对象模型与状态机.md#75-agent-runtime-sdk-façade)，调用方不自行猜测外部协议或异常来源。

## 异步状态 ≠ 同步状态

引擎空闲、请求流结束或上一轮恢复成功不能代表某个任务已完成。Runtime 的执行状态与完成事实见 [Harness 03 §6](../../../../harness-design/03-核心对象模型与状态机.md#6-状态机)，宿主展示只读取对应执行的受控投影。

## 释放必须到达静止，而不只是发出请求

本节的资源清理示例仅适用于调用方拥有的本地子进程、连接或监听器：发出关闭请求后，还需确认资源已经释放。SSE 连接清理不取消持久后台任务，也不删除待投递输出；持久任务取消与宿主停机见 [Harness 03 的 SDK façade](../../../../harness-design/03-核心对象模型与状态机.md#75-agent-runtime-sdk-façade)。

## 回调异常隔离在分发器

非权威、进程内通知的分发器可逐个隔离监听器异常，避免一个订阅者阻止后续订阅者；失败日志只记录安全关联标识，不转储完整事件。需要可靠投递的消费不能通过捕获异常后返回成功来确认：其失败、重投与持久事实边界见 [Harness 03 §8.3](../../../../harness-design/03-核心对象模型与状态机.md#83-sessionlogstore与-eventbusbus分离)。

## 执行环境与临时文件

向子进程、脚本或沙箱仅传递执行所需且已授权的环境变量，不默认继承平台凭据；任务所需凭据通过既定授权机制传入，变量名黑名单不能代替授权判断。

临时文件使用受当前平台访问控制保护的私有目录、随机名称和独占创建；POSIX 使用适当权限，Windows 使用对应 ACL 或已验证的安全临时目录机制。

## 按链接形态删除路径

删除前确认待删路径属于授权范围，并识别符号链接、Windows junction 或其他重解析点。链接只删除链接本身，不跟随或删除其目标。递归删除仅用于确认的普通目录，遍历中也不得跟随链接；无法可靠判断路径类型或删除范围时，停止该删除操作。具体 API 按语言与平台选择，不用单个 symlink 判断概括全部链接形态。
