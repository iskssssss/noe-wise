# 工程与编码规范

本文件定义实现要求；任务范围与授权见[开发流程](../../nw-workflow/references/development-workflow.md)，验证见[评审与验证规范](../../nw-verification/references/candidate-driven-delivery.md)，文档归属见[文档规范](../../nw-docs/references/documentation-standards.md)。

## 工程核心要求

先读本节，再按实际改动读取对应章节；目录、API、数据、配置、前端与运维要求不整表加载。设计和实现均先定位所属 Harness/docs 契约；数据结构遵守[固定结构与 JSON 边界](#固定结构与-json-边界)。

采用最小必要复杂度：针对推测的极低概率边界或并发问题增加防御，按[自主执行边界](../../nw-workflow/references/development-workflow.md#自主执行边界)先说明并获用户同意；入口校验与函数组织遵循[代码实现](#代码实现)，异常捕获遵循[错误处理](../../nw-error-handling/SKILL.md#错误与处理责任)。

### 项目阶段与优先级

按[最高优先原则](../../nw-workflow/references/development-workflow.md#项目最高优先原则)，以当前已批准架构与契约替换任务范围内的冲突实现，同步受影响的调用方、装配、测试和文档。删除仅为兼容历史实现而存在的适配层、双读双写、旧字段兜底、过渡开关和格式转换；符合目标架构的实现、扩展点及协议适配可保留。数据库改造与数据操作按[数据库与迁移](#数据库与迁移)执行。

通用规则采用“已批准领域契约 → 项目通用规范 → 类别默认值”的优先级。例外在所属领域正文说明业务或协议依据，历史实现本身不构成例外。本规范表达目标；[实施差异](../../../../docs/02-架构与设计/11-未实现功能清单.md#22-工程通用契约实施差异)归所属模块，发布规范不表示存量代码已完成改造。

## 模块与职责边界

按业务能力、运行时职责、变化原因和依赖组织模块，区分公开契约、内部实现、定义/执行/恢复责任；编排、领域规则和技术适配分离。不按行数、文件数、表数或层数强拆，小模块可扁平。

Runtime/SDK 归 [Harness 02](../../../../harness-design/02-微内核插件架构实现思路.md)，宿主与前端归[技术架构](../../../../docs/02-架构与设计/01-技术架构.md)及[共享层](../../../../docs/02-架构与设计/08-前端共享层设计.md)。归属变化同步调用方与契约；宿主 Java 业务优先组织，详细规则见[Java 专题](java-organization-standards.md)。

固定提示词按真实消费者与语义归属模块，遵循 [Harness 提示词归属](../../../../harness-design/03-上下文视图与执行优化.md#11-具名提示词模块)；不能把平台宿主的提示词模块变成所有独立宿主的依赖。`SessionPrompt.Type` 表达组合分类，不决定资源的物理模块；桌面正文冻结与跨 Run 历史处理见[独立桌面宿主设计](../../../../docs/02-架构与设计/01-技术架构.md#11-独立桌面宿主原型)。

## 接口、依赖与共享代码

- 测试、Mock、契约套件和资源放 `src/test`，跨模块共享用 `src/testFixtures` 与 `testImplementation(testFixtures(project(...)))`；不进入生产 JAR/依赖，不加测试专用生产构造器或分支，夹具经正式注入入口提供。
- 接口服务实际契约、替换或依赖反转，不机械配对 `XxxService`/`XxxServiceImpl`。跨模块只依赖公开契约，不依赖对方 Mapper、Entity 或内部实现；Java `public` 不自动等于公开 SDK API。
- 平台领域间显式导入所用类型，不用普通或 static 通配符导入隐藏跨域持久化类型；领域内组织不受该跨域检查限制。
- 宿主装配只连接实现，适配器只做技术转换，不改变状态机语义、不拥有或绕过业务规则及治理。I/O 限制按所属架构，不将 Core 纯计算约束扩大到整个 Runtime。
- 共享层范围明确，业务规则、权限、状态迁移和领域计算归所属组件，不放入无边界 Common/Utils；展示映射不拥有状态判定权。

## 依赖、构建与生成代码

优先复用现有能力；引入依赖须解决当前实际需求，核对维护状态、许可证、已知安全风险及运行平台兼容性，不为单个简单操作引入整套框架，也不自行重写成熟的安全或协议实现。版本通过所属版本目录、依赖清单与已有锁文件维护，不在多个模块散落重复版本，不依赖开发机全局安装或未声明的传递依赖。

新增或变更外部协议、SDK/API 或框架关键映射行为前，先核对与实际接口及依赖版本匹配的官方规范、文档或 Javadoc；官方文档未覆盖的关键行为，查对应版本源码或做最小真实验证，再实施依赖部分。已有依据且版本、配置和使用能力未变时直接复用；项目内部协议以所属批准契约与类型定义为准。

使用仓库 Wrapper、包管理器和所属构建入口，区分开发、测试与生产依赖；构建产物不含测试夹具、凭据或本地环境文件。新增依赖或调整打包时核对实际产物及直接消费者，源代码可导入不等于发布产物可用。

格式和静态规则以现有 formatter、lint、编译器、PMD 等配置为准，不为通过检查全局关闭规则或改松类型；有依据的局部例外注明原因。只格式化受影响文件或代码块，不夹带全仓重排。生成代码修改源定义或生成器，按所属流程再生成，不手改生成结果；相关验收按[验证规则](../../nw-verification/SKILL.md)选择。

## 数据模型归属

按业务含义、生命周期与权威所有者划分对象，不合并异义对象/状态或建立全局模型容器。同资源同契约的载体按[类型容器](java-organization-standards.md#4-按边界组织类型容器)组织，公开签名不泄漏内部类型。

账本、日志、缓存与投影的权威关系归所属设计，缓存/投影不成为第二权威；Runtime 状态见 [Harness 03](../../../../harness-design/03-核心对象模型与状态机.md)，字段、精度、空值和生命周期见[数据库字段规范](../../nw-database/references/database-modeling-standards.md)。

### Java 类型与边界映射

| 对象 | 职责 |
|---|---|
| 请求/响应 DTO | 公开传输结构、存在性及输入输出限制，不暴露持久对象 |
| 应用命令 | 已解析业务意图，可信身份经受控上下文或明确参数传入，不从 DTO 获权 |
| 领域对象 | 业务不变量与合法迁移，不承担传输信封或存储框架职责 |
| 持久化对象 | 所属存储映射，不作为跨模块业务接口 |
| 事件 | 已发生事实的身份、版本和因果，不用可变实体替代 |
| 查询投影 | 受控查询视图，明确来源，无独立写权 |

按语义分型，不按层机械复制。授权、状态迁移和领域校验归业务组件，Controller/映射/展示仅做边界转换。固定结构使用明确类型；Map、反射或通用转换不能绕过存在性、身份、精度和可变性检查，也不能把 NULL、未知或部分结果变成默认成功。

### 固定结构与 JSON 边界

**所有开发中的固定结构一律使用明确的实体类、DTO、record 或对应语言的类型定义；非必要禁止使用 JSON。** 已知字段和嵌套结构必须由类型表达，不以 `JsonNode`、`JSONObject`、通用 `Map<String,Object>` 或 JSON 字符串代替固定业务对象。按业务键组织的类型化字典不属于用 Map 替代实体。

固定边界结构在所属类型或 Schema 中明确字段的必填、可空、可省略及默认值语义，读写双方复用同一定义。普通对象往返按契约核对字段存在性、值与精度；仅具有验签、精确回放等原始字节契约的材料要求字节一致，规范编码和摘要按所属协议执行。

JSON 仅用于有明确必要性的开放业务正文、外部协议等边界。外部协议采用 JSON 时，固定部分仍定义类型并由序列化组件转换，动态部分限定在实际开放字段；不把 JSON 对象在业务层间传递后逐处取字段。API 使用 JSON、对象可被序列化，以及“快照”“草稿”“审计”等名称，均不构成内部模型或存储采用 JSON 的理由。数据库固定字段和关系使用列或表，JSON 存储的必要性、约束与原始字节边界见[字段规范 §4.6](../../nw-database/references/database-modeling-standards.md#46-固定配置动态-json-与原始材料)。

**确需 JSON 时，所有由项目维护的结构字段名必须统一维护。** 每种结构由所属类型的序列化声明或所属 JSON Schema 提供唯一字段定义；读写、校验、文档及前后端消费者引用该定义或其生成结果，不在各处手写同一字段名及嵌套路径。必须手工解析或构造时，在所属模块的 codec 中集中维护字段常量并复用，不建立跨领域的全局字段容器。真正开放的业务键由用户或外部 schema 定义，不能借动态键承载应类型化的固定字段。

变更字段时同步所属类型、序列化映射、Schema 与直接消费者，核对实际边界的读写一致性；全局命名与空值处理策略不能隐式改变已定义的协议。检查范围随本次改动选择，不因新增规则开展无关全仓重构。

## 静态定义与配置

### 魔法值与常量归属

禁止使用未命名的业务与策略魔法值。业务状态、错误码、事件名、权限、协议编码、阈值、期限和容量等使用具名常量、枚举或类型化配置；名称表达业务含义，时间与容量通过类型或名称明确单位，不能只把 `30000` 改名为 `VALUE_30000`。

所有常量按所属职责统一维护，同一含义只定义一次，调用方引用，不各自复制字面量或默认值：

- 状态、类型和错误码归领域或公共契约，使用明确枚举或类型；HTTP 头等标准协议值优先复用已有库或项目定义。
- 模块内共享值归所属模块，跨模块共享值归已有公开契约；仅单个实现使用的常量就近私有维护，不为统一而建立 GlobalConstants/CommonEnums 或扩大公开 API。
- 含义不同的值即使相同也分别维护，不因都等于 `20` 就共用一个 `DEFAULT_LIMIT`。直观的计数初值、索引步进、空集合和数学运算值可直接表达；`count == 0` 不需提取 `ZERO`，`status == 2` 必须使用所属状态定义。
- 前端颜色、间距和层级复用现有主题 token 与组件规范；字段长度、精度及约束归[字段规范](../../nw-database/references/database-modeling-standards.md#3-字段定义与命名)。跨语言、SQL、样式或脚本中的必要映射按所属契约同步，不各自重新解释。

需按环境或运行策略调整的超时、重试次数、并发、队列容量等使用类型化配置，不能仅抽成常量后继续写死；固定协议值和局部实现常量留在所属组件。默认值、示例和 OpenAPI 取值来自真实代码、配置或确认需求。

本次修改涉及这些值时，核对定义、消费者和必要映射；常量与配置检查并入差量评审，不另建登记表或触发无关代码清理。

### 配置分类与生效

配置由所属类型、校验和使用说明表达来源、合法值及生效方式；单位、覆盖顺序、写入权限或冻结时点有歧义时补充说明，不逐项另建配置说明表。固定配置的列与关系表设计遵循[字段规范](../../nw-database/references/database-modeling-standards.md#46-固定配置动态-json-与原始材料)。

| 类别 | 归属与生效要求 |
|---|---|
| 部署参数 | 使用项目实际配置绑定链；明确配置文件、环境变量等来源的优先级及是否需要重启 |
| 运营策略 | 由获授权主体维护，校验与发布后按所属业务受理边界生效 |
| 资源配置 | 归所属资源，只允许领域声明的默认值和覆盖层级；NULL 的继承语义遵循字段契约 |
| 执行冻结配置 | 在领域规定的 Run 或调用准备边界冻结版本，执行与恢复读取精确版本 |
| 凭据 | 归所属凭据管理能力，通过受控引用在调用边界解析，生命周期独立于普通配置 |

同一含义不能在环境变量、数据库和代码中分别维护默认解释。默认值只在字段缺失且契约允许时生效；显式非法值不能通过夹紧、忽略或回退默认值放行。已启用能力缺少必要配置或配置非法时，阻止对应组件启动或能力激活；未启用能力可缺少其专用配置，但启用前必须完整校验。

运营配置校验失败不发布，保留原有效版本并返回明确错误。配置必须声明重启、发布、下一次受理或显式热更新的生效方式；未声明热更新契约时不得推定即时生效。已受理 Run 和已准备外部调用遵循所属冻结边界，恢复不从当前配置重建历史；当前停用与撤权继续按授权契约检查。

### 凭据边界

凭据值只由所属管理能力保存和受控解析，不进入普通业务配置、执行快照、日志或公开响应；冻结内容保存必要的受控引用。平台模型等已有领域加密凭据版本契约仍归其安全设计，不能以通用快照复制代替凭据管理。

轮换明确新调用采用哪个凭据、在途调用的引用如何处理及旧凭据何时停用，不因重试擅自切换身份。停用后的使用按当前授权拒绝；首次签发结果未知时先核验或显式轮换，不重新签发并冒充原结果。凭据签发的一次性受控交付不属于普通业务响应；秘密不由后续查询再次返回。部署和子进程环境只提供已授权且必要的凭据。

## 设计与文档一致

设计或公开契约变化同步事实源、实现、测试及必要迁移；职责、依赖与取舍在已有摘要说明，文档与 [Note](../../nw-docs/references/notes-governance.md)按所属规则维护。

## 代码实现

构造器注入，禁止字段注入；避免 N+1 和逐条远程调用，批量复用业务校验。优先 import 与短类名，仅类型冲突或注解参数需要时用全限定名。

### 命名与类型安全

- 名称使用所属领域术语，表达对象含义和动作；同一概念跨层保持一致，不用无具体含义的 Manager、Helper、Data 或拼音缩写掩盖职责。类和类型使用 PascalCase，方法与变量使用 camelCase，具名固定常量使用 UPPER_SNAKE_CASE；协议、数据库及生成代码采用其所属命名契约。
- 方法名区分查询、修改与外部副作用，布尔值表达可判断条件；多个布尔参数或同类型位置参数含义难辨时改用有语义的参数对象或枚举，不机械封装所有参数。
- Java 使用泛型与明确返回类型，禁止以原始类型或未检查转换绕过契约；TypeScript 保持现有严格检查，外部未知值先以 `unknown` 接收并解析收窄，不用 `any`、双重断言或非空断言掩盖缺失校验。必要的第三方类型适配局限在边界，并说明依据。
- 外部数据只在实际入口完成一次解析与校验，随后向内部传递已验证、类型明确的值，不在每一层重复判断类型、格式、必填或同一不变量；解析、配置、持久化、进程及网络等入口由所属边界负责，不把每个内部函数当作新入口。按调用契约区分缺失、NULL、空集合和失败，不用默认值抹平差别。状态转换按明确类型分支，封闭状态集不能用默认成功吞掉新增状态。

### 函数、控制流与可变数据

函数围绕一个可说明的职责组织；能在一个函数中清楚写完就不拆。只用一次的简单逻辑直接写在调用处，不提前抽成函数；只有存在实际复用需求，或确实封装了一块复杂逻辑时才抽取，不为假设复用或统一行数限制拆函数。优先减少嵌套和隐藏副作用。构造与装配不隐式启动业务任务或远程操作，生命周期动作由明确入口触发。

查询、转换和格式化不偷偷修改调用方数据。共享快照、缓存值和公开返回集合明确可变性，必要时防御复制；`final`、record 或只读类型不自动保证其成员不可变。修改可变集合时遵守迭代与并发约束，不依赖未声明的 Map 顺序、默认字符集或系统 Locale；协议编码与排序采用明确约定。

复用相同语义的逻辑，抽取需要实际消费者与稳定职责；不因代码外形相似合并不同业务规则，不引入仅转发的层、无用参数或假设扩展点。行为变化同步删除范围内失效分支、未使用依赖和注释掉的代码；无关清理按[简化技能](../../nw-simplification/SKILL.md)处理。

### 代码注释

手写代码使用中文注释，保留技术标识；说明业务语义、约束和失败后果，不复述签名或直观代码。Java 契约用 Javadoc，TS/JS 用 JSDoc/TSDoc，其他语言用文档注释/docstring；局部原因写在相关实现附近。详略按风险，不按行数或标签数量。

#### 类与类型

公开类型说明调用方需要的概念与边界；内部类型仅补充命名、类型和代码无法直接表达的约束。非直观的状态所有权、生命周期、释放或线程限制就近说明，复杂理由链接来源；不为简单载体或测试辅助类型逐项补职责模板。

#### 字段与枚举值

字段、常量和枚举的非直观含义在所属契约说明，特别是单位、NULL/缺失差异、可信来源、可变性和生效时点。类型、校验或 OpenAPI 已清楚表达的事实不再复制到每个字段注释；record 可用类型 Javadoc 的 `@param` 承载必要说明。字段类型与精度取[字段规范](../../nw-database/references/database-modeling-standards.md#3-字段定义与命名)，各表示保持一致。

#### 方法、函数与构造器

公开方法说明调用方不能从签名直接得知的前置、参数语义、返回区别和失败保证，按需使用 `@param/@return/@throws`。内部方法、构造器和回调只有非直观契约或理由时才写注释，不为直观辅助方法、getter/setter 或委托逐个套模板。

副作用说明授权、写入范围、事务所有者、幂等及失败状态；异步/流式区分受理与完成、取消与中止及释放责任；并发说明写权、租约/CAS 和竞争失败。接口拥有调用契约，实现用 `{@inheritDoc}` 或引用并补特有约束，不复制全文或掩盖行为差异。

#### 关键代码块与局部变量

非直观的权限/租户校验、事务与状态迁移、外部调用与恢复、缓存/迟到回调、删除与释放、特殊算法/协议路径，在代码附近说明保护的约束、顺序原因及失败后果。必要时交代改变顺序的风险；局部变量的单位、特殊取值、来源或生命周期不直观时同样说明。

不要求每个 if、循环、赋值或局部变量都有注释，优先改善命名与职责。块注释不复制方法契约，也不代替校验或测试。

#### 维护与验收

行为变化同步相关注释、OpenAPI 与契约，删除失效说明和注释掉的旧代码；未实现目标留设计，不能靠改注释宣称符合。TODO/workaround 写原因、范围和退出条件，历史交给 Git/记录。生成注释改源契约或生成器，不手改产物、不写秘密。

在本轮差量评审中核对非直观契约和[诊断信息](#事务日志与可观测性)，不追补无关代码、不逐成员点名检查，不设注释比例、独立报告或额外轮次。直观内部方法可无注释、无日志；公开契约和必要失败信息不能因此省略。

## API 与错误契约

- HTTP 使用固定路径，禁止路径模板与 `@PathVariable`。仅 GET 用查询参数/`@RequestParam`；POST/PUT/PATCH/DELETE 的标识和业务字段用类型化请求体，上传用 multipart，原字节验签回调用专用头传递签名绑定标识。同步调用方、绑定、签名、测试和文档，不弱化归属/权限校验。
- Controller 用明确 DTO 做协议转换、入口校验与应用调用，不暴露 Entity/懒加载关联；复用授权、状态、级联与事务编排归应用服务，覆盖 HTTP、异步和内部入口。
- 公共契约语义明确、边界受控，演进按项目阶段原则；OpenAPI 匹配真实序列化，说明字段含义、约束、单位、空值和真实枚举。
- 字段命名、标识符与精度映射遵循[字段规范](../../nw-database/references/database-modeling-standards.md#3-字段定义与命名)，部分更新的字段存在性、清空和嵌套对象行为遵循[更新语义](../../nw-database/references/database-modeling-standards.md#6-部分更新的字段语义)，同步 DTO、SQL、OpenAPI 和客户端。
- 错误传播、处理责任与流式/降级结果遵循[错误处理](../../nw-error-handling/SKILL.md)；本节维护 HTTP 表示与输入输出契约。

### 输入与字段错误

请求体和查询参数默认严格校验，未声明字段、类型错误和显式越界值拒绝；只有缺失且允许默认的字段才补默认值，不静默忽略、夹紧或截断。开放文档和外部协议按其结构契约处理，扩展范围必须显式声明，不能借此放宽固定宿主字段。此要求约束请求输入，不改变已批准的响应展示字段容忍规则。

字段长度、Unicode 码点、ID 字符串和精确数值遵循数据库字段规范，入口、OpenAPI 与客户端采用同一口径。输入拒绝与领域已批准的上下文裁剪、摘要、分页和展示投影分别定义，后者不能代替入口校验或改写输入事实。

`field_errors` 保留字段路径到可公开错误说明的映射，使用 JSON 字段名；嵌套与数组路径逐段映射，例如 `resource_bindings[0].resource_id`，不能把整个 Java 属性路径直接视为对外字段名。错误不回显敏感原值，同一路径保留明确的可修正原因。只读身份、创建信息和发布事实不能被通用绑定写入。

### 查询、分页与批量

| 场景 | 默认契约 |
|---|---|
| 普通管理列表 | `page` 从 1 开始，`page_size` 默认 20、最大 200；`data` 为 `{items,total,page,page_size}` |
| 连续事件与增量读取 | 使用不透明游标；`data` 默认为 `{items,next_cursor,has_more}`，不默认计算总数 |
| 页号或大小非法 | 返回字段校验错误，不自动修正；合法页号超过末页返回空 `items` 和实际 `total` |
| 集合与筛选 | 声明未传、空字符串、空集合以及精确、模糊和集合匹配的含义，不用模糊的“空值”统称 |

领域明确的分页参数、大小边界和响应结构在所属契约说明；没有协议依据的 `limit`、`pageSize` 等存量差异按目标规范改造，不同时接受别名。分页上限不限制已批准的内容分段协议，二者各按所属单位和预算判断。

排序字段和方向采用白名单，不直接拼接客户端字段名或表达式；每个列表声明默认排序，并以唯一身份确定同值顺序。筛选按白名单映射为绑定参数。游标验证当前授权归属和对应查询条件；并发变化下的一致性、过期与恢复方式由接口声明，不能承诺游标或偏移分页天然提供历史快照。

同库同步批量修改默认同一事务原子完成；跨外部系统的长操作使用既有操作事实及逐项结果，不开启跨网络长事务。请求受理、执行完成、部分失败和结果未知分别表达，不能用“已提交”表示最终成功；数组整体替换等更新行为按字段契约执行。

### 响应与错误分类

普通 JSON 使用 `ApiResponse<T>`，确切字段及 SSE、文件、WebSocket、204/304 例外归[传输契约](../../../../docs/02-架构与设计/04-接口与事件契约.md#22-json-响应与传输例外)。错误码采用所属稳定编码，不以异常类名、数据库错误或供应商正文直接对外返回。

| HTTP 状态 | 默认语义 |
|---|---|
| 400 | 请求格式、类型、未知字段、必填、长度或范围约束错误 |
| 401 / 403 | 身份未认证 / 已认证但无相应权限 |
| 404 | 当前可见范围内的资源不存在；防枚举的隐藏策略由领域契约明确 |
| 409 | 状态、CAS 修订或同幂等键异内容冲突 |
| 422 | 结构和字段约束合法，但违反领域业务规则 |
| 413 / 415 | 请求材料过大 / 不支持的媒体类型 |
| 429 | 限流或配额拒绝，适用时提供真实的 `Retry-After` |
| 500 / 503 | 内部非预期错误 / 服务暂不可用 |
| 502 / 504 | 网关上游连接等故障 / 网关等待上游超时，具体码归传输契约 |

业务拒绝不默认包装为 HTTP 200；已批准的领域反馈例外在[错误语义](../../../../docs/02-架构与设计/04-接口与事件契约.md#9-错误语义)集中索引。`retryable` 与重试安全遵循[错误恢复规则](../../nw-error-handling/SKILL.md#重试与未知结果)。

## 身份、权限与租户

| 主体 | 可信来源与范围 |
|---|---|
| 平台管理员 | 平台认证上下文及当前管理权限；跨租户操作需要明确授权作用域 |
| 机构成员 | 机构认证上下文、当前成员关系和角色权限 |
| ServicePrincipal | 已验证凭证对应的租户、integration 及 scopes；应用治理身份按独立契约处理 |
| 终端用户 | 入口身份契约及所属租户/渠道绑定；本机引用或外部业务标识不是独立授权凭据 |
| 系统任务 | 可追踪的服务或系统主体及显式任务范围，不伪造成员身份 |

认证建立可信上下文；应用服务检查对象归属及动作权限；数据库约束和 RLS 保护存储边界。正文中的 tenant、user、role、scope 或业务 context 不能直接赋予权限；认证入口的精确映射归[宿主契约](../../../../docs/02-架构与设计/04-接口与事件契约.md#2-通用约定)，不建立第二套身份系统。

HTTP、后台任务、事件消费和内部入口共享所属授权规则。列表、详情、导出、下载、历史、SSE 和异步任务结果读取均检查对应资源范围；鉴权前不通过计数、错误或投影泄漏不可见对象。平台跨租户操作明确所选范围并记录来源，不能通过可选 tenant 参数获得无限权限。

异步显式传播主体、租户与必要追踪信息，并在作用域结束恢复或清理；不依赖线程、连接或缓存残留。当前撤权与历史冻结版本分别判断，历史快照不授予当前访问权；缓存不能绕过现行授权。审计记录真实主体、目标、动作和结果，管理资源操作者字段遵循[字段规范](../../nw-database/references/database-modeling-standards.md#5-公共字段与可信写入方)。

## 文件、网络与内容安全

来自用户、模型、供应商和导入文件的内容均按输入处理，不能成为执行权限。SQL 使用绑定参数，进程调用使用参数列表，不把未受信内容拼成 shell 命令；确需执行代码或脚本时经过已批准的沙箱与授权入口。身份与对象范围继续遵循[权限规则](#身份权限与租户)。

文件读取、写入、下载和解压限制在获授权资源范围内，按实际解析后的路径处理 `..`、绝对路径、符号链接及平台差异，不能只做字符串前缀检查。上传核对实际内容、类型和大小，解压同时限制展开量与目标路径；下载展示名不决定存储路径，读取文件仍检查当前资源权限。

受用户或模型影响的服务端 URL 使用所属出站策略，校验目标、解析地址与重定向，不能借跳转访问未授权的本机、内网或元数据服务；确需内网集成时按明确作用域放行。保持 TLS 校验，凭据只发给获授权目标，不为联调关闭全局安全检查。

HTML、Markdown、SVG 和外部链接按实际展示上下文转义、净化或隔离，禁止直接执行未受信内容；前端配置和构建产物均视为公开材料。认证、会话、跨域、请求伪造防护和密码学复用项目已有设施，不自行发明算法或通过放宽全局策略解决局部错误。

## 外部调用、超时与重试

每项调用策略明确连接、读取或流式空闲、单次尝试和整体业务期限，声明单位和权威配置。响应字节、解码后材料和业务输出预算分别受控。

重试资格、预算、幂等和未知结果归[错误恢复规则](../../nw-error-handling/SKILL.md#重试与未知结果)。取消请求、传输中止和外部操作已撤销分别表达，关闭 SSE 仅释放观察连接，不取消持久任务。

线程池、队列、并发、连接和响应材料有明确容量与释放所有者；过载明确拒绝或执行已定义降级，不静默丢弃。具体容量与期限来自所属配置、需求和测量，不由通用规范设一组覆盖所有调用的数字；降级结果仍保留部分、失败及未知语义。

## 并发、异步与资源生命周期

共享可变状态明确写入方与同步方式，检查和修改需保持原子语义；按数据归属使用已有事务、CAS、锁或租约，不以单进程锁证明跨实例互斥。资源锁范围尽量小，多个锁顺序一致，避免持锁等待无界 I/O；持久化竞争规则归[数据库规范](../../nw-database/references/database-modeling-standards.md#72-并发幂等与索引)。

异步工作有明确的执行器、父任务或持久任务所有者，异常、取消和完成能被观察；不创建无归属线程或丢弃 Future/Promise。中断按调用契约传播或恢复标记，不吞掉后继续工作；取消后阻止未获授权的后续副作用。多步结果按所属顺序或版本应用，迟到回调不能覆盖新状态。

获取连接、流、临时文件、进程、监听器或定时器后立即建立释放路径，覆盖初始化失败、正常结束、异常及取消。使用 try-with-resources、finally 或框架生命周期机制；关闭先停止接收新工作，再按既有期限处理在途工作并释放资源。关闭请求与实际静止分开判断，不能只调用 cancel/close 就报告任务已经结束；持久任务与观察连接仍遵循[外部调用规则](#外部调用超时与重试)。

## 事务、日志与可观测性

- 写操作、多步骤一致性与读取快照按语义声明事务、传播、隔离和回滚，不机械覆盖所有 Service 方法。
- 请求入口与最终结果、重要业务决策、状态迁移、外部调用、重试和恢复必须可追踪。getter/setter、纯转换和内部辅助方法按诊断需要记录，不要求逐方法入口/出口；边界已提供完整信息时不重复记录。架构要求纯计算的组件通过调用边界观测，内部不直接写日志；必要注释继续保留。
- INFO 表达有价值的生命周期变化，WARN 表达可继续的异常或降级，ERROR 表达需要处理的失败；DEBUG/TRACE 用于有诊断价值的细节。预期输入或权限拒绝不默认记录错误堆栈，必要安全审计仍执行；不能用提高级别代替结果分类。
- 使用中文事件说明和结构化字段，必要事件、结果与耗时统一表达为 `event`、`result`、`duration_ms`，按当前边界携带 `trace_id/span_id` 及所属请求、操作、Run 或外部调用身份。缺失标识不伪造，定义/节点 ID 不替代执行 ID，敏感关联标识使用安全标签或摘要。技术追踪不替代持久业务因果；异步显式传播并清理上下文，不依赖残留 MDC。
- 出口日志可标明失败，异常原因链必须保留；安全堆栈在最终处理边界记录一次，避免逐层重复。外部异常先安全转换，throwable 不得泄露响应载荷或凭据。
- 参数和返回值只记录必要、安全的摘要，不为覆盖要求输出无界对象或完整请求/响应。禁止凭据、令牌、连接串、会话原值与个人敏感信息；必要字段脱敏并清理换行和控制字符。
- 高频技术诊断事件可按声明策略采样或汇总，不能丢失判断业务结果所需的关键事实；正式审计与业务账本保持完整，应用日志不替代二者。安全、权限、敏感访问及导入/导出按所属审计契约记录主体、目标、动作和结果。
- 指标声明含义、单位、类型、聚合方式和标签范围；默认不以用户、租户、Session、Run、原始 URL 等无限增长身份作标签。需要按这些维度查询时使用授权日志、追踪或业务查询；受控有界标签例外说明容量依据。遵循适用的 OpenTelemetry 语义，不在指标名和单位字段中重复或矛盾表达单位。
- 告警关联可观察业务影响、已有 SLO/容量依据与处置入口，区分短时抖动、持续失败和业务积压；通用规范不发明新的服务等级数值。观测采样、面板可用和健康检查均不证明业务执行或审计完整。

## 前端状态与接口消费

应用依赖范围归[共享层设计](../../../../docs/02-架构与设计/08-前端共享层设计.md)，后台产品交互归[交互规范](../../../../docs/03-规范与术语/05-后台系统交互规范.md)。两个后台共享实现，独立会话端遵循相同服务端契约但不导入后台状态，不新增跨应用的通用状态容器。下列状态归属原则也适用于桌面渲染层，不能因此跨越既有组件或宿主边界。

页面负责用例编排，组件通过明确 props/events 交互，composable 封装有实际复用价值的状态与副作用，接口调用归已有客户端层；不在模板散落权限判断、URL 或复杂业务计算。派生值优先从权威状态计算，不维护易失配的第二份状态；不直接修改 props 或无归属的全局对象。组件卸载与副作用清理遵循[资源生命周期](#并发异步与资源生命周期)，布局、文案与交互反馈按 [UI 技能](../../nw-ui-ux/SKILL.md)及所属产品规范处理。

- 异步操作绑定发起时的账号、租户、对象、会话或任务快照，查询同时使用取消信号和请求代次防止旧响应回填；读取、写入和取消操作的迟到成功、失败、全局 Message 及 `finally` 均须检查更新权，不能改用返回时的当前对象。页面卸载或作用域切换释放观察、轮询和监听，并清除不再适用的数据。
- 登录与 MFA 的阶段从当前有效认证状态派生，页面因身份或授权版本变化重建后仍能继续；已通过验证但资料读取失败单独表达。不能通过取消受保护页面的身份重建来保留局部状态；失去会话更新权的旧认证结果及错误静默丢弃。
- 写请求防止连续点击、快捷键或并发入口重复提交；派发时固定命令、目标、修订与已有幂等标识，断网或超时后保留原输入和请求身份。修改字段、填入示例、关闭弹层不能隐式创建新身份来代替核对，恢复资格按[错误处理](../../nw-error-handling/SKILL.md#重试与未知结果)判断。传输重连不代表操作成功。
- 表单分别维护加载原值、当前编辑值和成功保存基线；失败保留输入，成功才推进基线。后台刷新、保存其他字段后重载、旧保存回执均不能覆盖后续草稿；保留草稿时也保留其原 CAS 基线。保存期选择禁用编辑时，检查子控件显式 `disabled` 是否覆盖父表单状态；允许继续编辑时，只合入已提交快照的回执。CAS 冲突保留草稿，明确重新加载或人工处理的后果，不静默覆盖。
- 多文件编辑按文件身份隔离正文、撤销/重做、选择与诊断状态；可重建编辑器或分别持有编辑状态。外部 `modelValue` 替换不能把另一文件带入当前撤销历史；仅阻止外部替换入历史、不清除旧文件历史并不足以隔离。
- 按 JSON 字段路径定位 `field_errors`，字段错误持续可见；无法定位或非字段的错误由当前用例的顶部 Message 承接，位置及恢复动作归 UI 规则。ID 和精确数值保持字符串，字符计数、NULL 与字段存在性遵循字段契约，不把空字符串转成清除 ID。
- 未保存保护覆盖导航、会卸载组件的本地页签、对象切换、抽屉关闭和主动退出，不能只保护路由；提交中不丢弃界面，取消离开后保留路由、草稿及原操作身份。浏览器刷新/关闭按草稿和在途状态绑定 `beforeunload`，无保护需求或卸载后移除，不依赖卸载时异步保存。身份已失效时停止受保护操作，不能以保护草稿为由继续沿用旧授权；密钥和编辑正文不进入导航存储。
- 主资源与辅助目录按各自权限、必要性独立装配；无权或失败的可选模型/成员/工具目录不阻断已有权读取的详情或列表，也不抹掉成功数据。缺少必需资料时禁用依赖动作并说明原因，不能靠扩大角色权限或伪造完整目录放行。
- 缓存声明账号、租户、资源及必要版本作用域、容量和失效条件；变更成功后按来源失效或刷新，不从缓存恢复权限。初始加载、刷新、首次无数据、筛选无结果和加载失败分别展示，失败不能伪装为空列表。

## 数据库与迁移

模型、字段、主外键、租户隔离、索引与存储增长要求见[数据库模型与字段规范](../../nw-database/references/database-modeling-standards.md)。本节维护数据访问和迁移执行规则。

- 生产访问使用 MyBatis：宿主 MyBatis-Plus，Runtime 存储适配 MyBatis Core，宿主提供 DataSource/池；框架、Mapper 不进入 Runtime 公共契约、Core 或 Session 领域逻辑。
- 业务 SQL 经所属 Mapper 执行并维护在 `*Mapper.xml`，接口仅方法/参数；禁止 SQL 注解、JdbcTemplate、直接 Statement 或提取 BoundSql 自行执行。底层 JDBC 仅允许已登记的类型处理、租户连接上下文、取消和连接观测；测试可用 JDBC 构造/断言事实。检查入口为 `backend-java` 的 `verifyMybatisAccess`。
- 原子操作共享事务所有者的会话/连接，辅助组件不另提交；后台显式绑定授权租户并恢复，不依赖残留连接状态或任意参数推身份。
- 按目标模型维护 schema、初始化和迁移链，允许改写或合并历史迁移，不为保留历史 schema、已应用版本、checksum 或旧数据读取增加兼容设计；不要求每次修改都重写全链。改写后的历史迁移链仅用于新建或明确授权重建的环境，并按[测试路由](../../nw-verification/references/candidate-driven-delivery.md#测试路由)验证完整链路。
- 实际数据销毁前明确目标、范围、授权和恢复方式；缺少环境操作授权时完成代码和脚本准备，暂停对应操作，不因此增加兼容方案。备份不产生运行时兼容义务。
- 变更涉及存储模型、数据归属、种子与版本、引用关系，或缓存、索引、文件的生命周期时，核对[清理与保留](../../../../docs/04-指南与运维/11-数据清理与保留规范.md)影响并同步受影响的规范和实现；无相关影响时无需单独声明。

## 外部规范的采用

| 原始资料 | 采用原则与项目边界 |
|---|---|
| [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html) | 用显式 schema 描述参数、必填、类型及响应；不因参考版本强制升级项目生成器，固定路径与信封仍采用项目契约 |
| [HTTP Semantics / RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html) | 方法、状态码、媒体类型及重试相关传输语义；业务幂等与结果未知由所属领域补充 |
| [OWASP ASVS](https://owasp.org/projects/asvs) | 可信身份、逐对象授权、输入验证与秘密保护；不自动引入新的角色体系、审批流程或全套认证门禁 |
| [OpenTelemetry Metrics](https://opentelemetry.io/docs/specs/semconv/general/metrics/) | 指标含义、命名、单位与属性的一致性；标签基数上限和具体观测字段由项目需求约束 |
| [Google SRE：Handling Overload](https://sre.google/sre-book/handling-overload/) | 有界负载、退避、重试预算与过载处理；实际阈值取本项目配置和测量 |

外部资料提供技术依据；分页档位、严格输入、字段错误路径和日志覆盖范围是项目选择。只采纳已在正文明确的规则，不将外部资料的全部条款自动转为工程要求。
