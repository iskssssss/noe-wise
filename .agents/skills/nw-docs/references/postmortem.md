# 事后复盘（postmortem）

> 本文拥有复盘触发条件、格式与局部编辑要求；文档事实归属统一见 [文档规范](documentation-standards.md)。

## 何时写

满足任一条件时记录复盘；已有同一事故记录则更新，不另建：

- 已造成越权、租户数据泄露、不可恢复的数据损坏，或真实用户服务/发布中断，需要追溯影响与恢复；
- 重复机制缺陷暴露现有防线缺口，记录因果与防止复发的措施有明确价值；不按人日或返工次数机械触发。

其余失败按正常任务修复并定向验证；夹具笔误、一次构建失败和规则措辞调整不自动触发复盘。先恢复服务或控制影响，再保存根因和防线；复盘文档不成为修复发布的前置 Gate，未完成调查如实标明。提交与外部动作仍按已有授权。

## 必要内容

文件放在仓库 [docs/postmortem](../../../../docs/postmortem)，命名为`NNNN-简短描述.md`（如 `0001-回调幂等键重复.md`），编号从 0001 续增。

记录影响与恢复、根因与证据、修复与验证，以及尚未完成的后续动作。保留状态、日期和涉及范围，章节可合并；以下为参考格式，无后续动作时省略该节。

```markdown
# 标题：一句话说清什么坏了

> **状态**：Closed | In Progress
> **日期**：YYYY-MM-DD
> **涉及范围**：模块/文档/流程

## 影响与恢复

实际影响、发生版本/时间窗、已执行的恢复动作及结果；未知信息标明。

## 根因与证据

直接触发、机制缺口、复现或安全日志位置，以及既有检查未发现的原因。

## 修复与验证

实际修复、验证入口及结果；尚缺的验证与遗留风险。

## 后续动作

仅列尚未完成的防线、责任方和完成条件；无则省略。
```

时间线、备选方案与教训仅在有助于解释因果或取舍时追加，不复制日志；同一事实已在修复 Note 或报告中就链接。影响已控制、根因有证据、修复及必要验证完成时可标记 Closed，非阻断后续动作单独追踪；已知风险仍阻止恢复/验收时保持 In Progress。

## 放置与链接

- 复盘只进仓库 [docs/postmortem](../../../../docs/postmortem)；不要在设计正文或进度记录中写事故叙事。
- 复盘解释事故根因；修复方案的设计取舍按[文档归属](documentation-standards.md#1-分级体系每类事实只有一个家)进入相应 Note 或 ADR，复盘链接对应记录，不复制决策正文。
- `docs/postmortem/README.md` 只保留入口，不维护重复清单。
