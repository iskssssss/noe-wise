# 文档归属与编辑规范

本文件拥有事实归属与编辑要求；执行与授权沿用[开发流程](../../nw-workflow/references/development-workflow.md)。普通编辑读 §3、§4、§8，其他章节按事实类型选取。

## 1. 分级体系（每类事实只有一个家）

先定位已有权威正文，同一事实只维护一次，其余位置链接。临时分析和可由代码直接核实的普通实现细节沿用任务摘要或代码；长期新事实补所属章节，必要时新建文档。

| 事实 | 权威位置 |
|---|---|
| Runtime 已批准需求、架构、契约与里程碑 | [Harness](../../../../harness-design/README.md)，具体分工见 [Note 治理 §2](notes-governance.md#2-文档分层与唯一事实源) |
| 精确 Java ABI、当前实现 | 源码、生成的 `public-api.javap`、配置与 schema；Markdown 不手抄签名，设计不自证实现 |
| 行为与验证结果 | 契约测试和原始报告；测试不另定义业务规则，范围与参考模型按[验证规范](../../nw-verification/references/candidate-driven-delivery.md) |
| 产品、宿主设计、非 Runtime 技术决策 | [产品概述](../../../../docs/01-产品与需求/02-产品概述.md)、[docs/02](../../../../docs/02-架构与设计)、[ADR](../../../../docs/05-架构决策) |
| Runtime/项目治理决策、阶段范围与实施状态 | 按需创建的 `.agents/notes/` 决策记录，按[触发条件](notes-governance.md#4-note-触发与复用)维护 |
| 未实现或预留主题 | [未实现清单](../../../../docs/02-架构与设计/11-未实现功能清单.md)，只维护发现入口与关联状态 |
| 操作与验收方法、环境清理 | [指南](../../../../docs/04-指南与运维)、[清理与保留](../../../../docs/04-指南与运维/11-数据清理与保留规范.md)，引用需求、授权和验证规则 |
| 任务与协作运行状态 | [单一恢复入口](../../nw-workflow/references/development-workflow.md#工作状态快照)；协作使用[交接规则](../../nw-coordination/SKILL.md) |
| 流程、工程、验证、文档规则 | 所属技能的正文或按需 references；实现示例、排障、可靠性和性能按所属技能路由 |
| 术语与 Workflow 语法 | [术语表](../../../../docs/03-规范与术语/03-术语表.md)、[工作流规范](../../../../docs/03-规范与术语/01-工作流规范.md) |
| 事故、模拟数据与生成清单 | [postmortem](../../../../docs/postmortem)、[数据与工具](../../../../docs/08-数据与工具)、[模块依赖](../../../../docs/08-数据与工具/generated/module-graph.md) |
| 历史进度与决策 | Git、所属 Note/ADR，保留当时证据，不证明当前实现或覆盖现行规则 |

总方案保存全局依赖和唯一验收索引；阶段 Note 保存本阶段范围、关键取舍、验收结果与下一步；详细命令、堆栈和报告保留在原始证据中。索引引用所属状态，不手工复制整份记录。README、AGENTS、CLAUDE 和模板只提供概述与导航，不另设规则、枚举或门禁；短技能可在 SKILL 正文拥有规则，长专题只在所属 reference 定义一次；外部参考不自动成为项目规则。

## 2. 文档分类：reference vs 指南

- reference（docs 的 01/02/03/05 及 Harness）表达所属有效事实与批准目标；目标可先于实现，变更理由归 Note/ADR。
- 指南（docs/04）按前置条件提供可执行命令或可验收结果，引用 reference 中的定义。
- 代码、配置、schema、生成物与报告证明对应版本的实现和验证；冲突修正引用方，未决取舍按开发流程。
- Note、ADR、复盘与历史记录保留因果、时间和版本，取代范围指向当前来源，不追认验证或产生历史兼容义务。

## 3. 写作规则

同一要求只定义一次，表达条件、动作和通过/停止边界，必要时链接授权与撤销依据。新规则对应实际需求或失败；按遗漏信息、顺序或条件选择简短结构，合并已有指导，不积累同义禁止条款。精简保留参与者、时序、强制性、例外、所有权、副作用及失败后果，普通实现细节保留判断空间。

- 一个物理行一个段落或条目；具体命名参与者、类型和行为，按术语表使用保留词。
- 行为、接口、架构或用法变化同步直接事实源；普通修复只更新实际变化的说明与证据，不重写设计。Runtime 语义归 Harness，docs 补产品、宿主和运维视角。
- 示例、枚举与默认值取真实代码、配置或确认需求，区分目标与实现；代码已表达的直观事实不复述。
- 正文让只看仓库当前版本的读者能核实，不依赖会话、PR 或草稿叙事。Note/ADR/复盘可保留可追溯因果与回归反事实。
- 技能描述只写职责和适用条件，必要排除项用于防止误触发；流程归正文，少见场景按需读取。规则变更做[场景核对](../../nw-verification/references/candidate-driven-delivery.md#规则场景核对)，区分静态检查、走读和实际行为证据。

## 4. 文档自检

检查本次差量的事实、重复、过时状态、手抄生成物、归属、可读性及链接，执行[文档检查](../../nw-verification/references/candidate-driven-delivery.md#文档检查)。不另建清单或业务验收要求；无关历史问题与个人风格不阻断，新增错误和实际影响仍需处理。

## 5. 生成式文件规则

[generated](../../../../docs/08-数据与工具/generated)保留生成头和重生成命令，禁止手改。输入变化运行对应生成器，多域可用 `make docs-regenerate`；纯文字不触发无关生成。CI 用 `--check` 校验逐字节新鲜度，不一致失败。

## 6. 文档质量与篇幅

事实、完整性和可读性优先，不设字数硬上限。[长度配置](../../../../tools/docs/budgets.json)可调整，仅作非阻断参考；统计的是非空白片段，不是汉字或 Token，[BASELINE](../../../../tools/docs/BASELINE.md)仅历史校准。结构精简不能弱化要求，长度变化不证明执行效率。

## 7. 事后复盘（postmortem）

触发条件、格式与局部编辑见[复盘规范](postmortem.md)。

## 8. 链接与锚点

仓库内用可解析的相对链接及锚点，不用绝对 URL；外部依据使用可核实的相关原始资料，正文保持自足，会话不能是唯一依据。GitHub slug 小写、去标点、保留 CJK/数字、空格转 `-`，重名追加 `-1`；如 `# 1. 概述与边界` 对应 `#1-概述与边界`。

## 9. ADR 状态与索引

ADR 保存自身决策状态和取代范围，索引仅摘要；状态不等于实现完成度，历史 Runtime 决策受当前 Harness 限定。

| 状态 | 含义 |
|---|---|
| Proposed | 未接受，不作实现依据 |
| Accepted | 在所属事实域有效 |
| Superseded | 已被取代，仅留背景 |
| Rejected | 已否决，不作待实施方案 |
| Unassigned | 编号空位，无决策 |
