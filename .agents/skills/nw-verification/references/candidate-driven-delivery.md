# 评审与验证规范

本文件拥有风险、测试、隔离与证据规则；授权、任务恢复和完成标准归[开发流程](../../nw-workflow/references/development-workflow.md)，业务验收归需求，证据类型见[测试策略](../../../../docs/04-指南与运维/03-测试与验收策略.md)。

## 风险路由

在已有摘要中说明验收目标、检查及通过信号，选择最低充分范围。按实际行为判风险，配置和脚本同样适用，不因目录名升级；[routing.json](../routing.json)仅索引下列标识。

| 任务标识 | 改动类型 | 评审 | 必要验证 |
|---|---|---|---|
| `docs-only` | 不影响行为的文字、注释、说明 | 主线程自检 | 格式、链接；规则变更核对代表性场景 |
| `local-feature` | 普通局部功能或修复 | 主线程自检 | 模块稳定后相关测试与必要功能检查 |
| `high-risk` | 改变权限、隔离、事务、并发、外部副作用、恢复或公共契约语义 | 一轮聚焦评审 | 关键不变量、直接回归与对应真实依赖 |
| `milestone` | 集成、发布准备或重大跨模块改动 | 按集成风险 | 组合验证，必要时全量 |

高风险做聚焦评审；有已授权独立 Reviewer 时可使用，否则主线程审查并说明。任务明确要求独立验收时遵守该要求。扩测或追加评审须有相关变化、失败或未覆盖风险，未变范围按[证据复用](#证据复用与-verification-manifest)处理；必要证据缺失只阻止对应范围完成。

## 评审规则

按[代码评审技能](../../nw-code-review/SKILL.md)审查差量；本文件只决定风险与所需证据，不另定义评审流程。

## 测试路由

按模块完成实现、测试和配置后集中验收；[关键假设](../../nw-workflow/references/development-workflow.md#实现优先)未知或编译阻断时先做最小检查。新增或改变序列化、持久化、恢复边界，且实际读写尚未证实、会影响后续实现时，先用最小真实样例验证；跨模块样例覆盖实际生产者与消费者，再扩展依赖同机制的能力。已有同输入有效证据按[证据复用](#证据复用与-verification-manifest)接续，不设每次编辑前置检查或逐编辑 TDD 要求，也不因编写顺序丢弃符合契约的实现。按当前未知选择最低充分检查，不把单测、模块测试和端到端测试设为每次必经的固定阶梯。

预期来自批准需求、契约和可观察行为，不能反推实现。替换仅保护旧行为的测试，保留当前契约的失败、安全、一致性与精度断言。缺陷优先复用可信修复前证据；缺失且安全可行时补最小复现或负控，修复后验证原问题与直接回归。无法安全复现时按[系统排障](../../nw-debugging/SKILL.md)说明证据边界。

测试名称表达场景和行为，断言结果、状态及必要副作用，不用调用次数或实现细节代替业务正确性；只有交互本身属于契约时才断言它。夹具保持最小且显式，边界与拒绝用例按实际风险选取；不通过复制被测算法、删除有效断言、更新快照或放宽时间限制掩盖回归。预期行为确已改变时核对差量再更新基线，单纯格式或局部规则编辑不新增业务测试。

| 变化 | 必要证据 |
|---|---|
| Mapper、事务、数据库约束 | 真实数据库；模型、初始化或迁移变化在新建或获授权重建环境验证完整 Flyway 链及受影响约束/RLS |
| 身份、权限与租户 | 实际认证入口与受限角色的对象授权；直接/异步入口及读取/写入拒绝，无越权副作用 |
| 公共签名、模块边界 | ABI、直接消费者与依赖；有意变更先核对生成差量再更新 baseline |
| API、序列化与字段校验 | 实际字段、状态码、存在性及错误路径，与 OpenAPI/客户端对齐，未知字段和越界不被默认值掩盖 |
| 并发、重试、恢复 | 关键竞争、故障、重复副作用及当前格式持久状态重建 |
| 外部副作用 | 受控回执与派发事实，区分拒绝、失败、未知，覆盖重复请求、取消和预算耗尽 |
| 配置与前端状态 | 活跃配置拒绝及冻结边界；对象切换、迟到响应/finally、失败保留输入、CAS 冲突和必要真实页面行为 |
| 多路径、共享行为 | 直接使用方；影响不明时扩大到最小可信模块范围 |
| 规则 | 受影响的接受、拒绝与失败退出场景 |

按实际变化选取，不执行整表或新增统一覆盖率门槛。Mock、参考模型、编译和健康检查不替代真实依赖、装配、事务、恢复或供应商执行证据；现有测试无法表达关键状态/并发语义时才引入参考模型。

在 `backend-java/` 使用 Wrapper：Windows 为 `.\gradlew.bat :<module>:test --tests <pattern>`，其他平台为 `./gradlew`。按需使用模块 check，复用增量构建和安全缓存；clean、强制重跑或换缓存须有排障/隔离依据。

宿主资源、时钟、全局状态、浏览器、异步清理或概率性失败按[测试可靠性](../../nw-test-reliability/references/test-reliability.md)选相关章节；性能任务或已有性能预算读[性能工程](../../nw-performance/references/performance-engineering.md)。

### 文档检查

定向检查用 `python -X utf8 -B tools/docs/verify_md_links.py <文件或目录...>`；广泛调整或目录/生成来源变化用 `python -X utf8 -B tools/docs/check.py`（等价 `make docs-check`）。无生产或构建变化不跑 Java/前端测试。历史检查失败按[失败处理](#失败处理)区分基线与本次新增，链接通过不证明规则语义一致。

### 测试夹具

复用模块小型 factory 和已验入口，确需跨适配器共享再进入 testkit。新增或修改夹具的参数、结果结构和必需配置，对照当前实际消费者、schema 或已验入口核实；不能仅凭工具名称、旧样例或相似接口推断。显式提供身份、版本、checkpoint、时间与配置；默认值只补合法前置，不放行权限或反推预期。

正式验证前只检查尚未证实且影响后续方向的装配：参数/类路径到达实际入口、测试被发现并启动、Provider 配置与序列化、合法等待续接、首异常采证及失败清理。新增或改变子进程测试时，按[子进程预检](../../nw-test-reliability/references/test-reliability.md#子进程与长链路预检)核对其真实配置和执行归属；同输入有效证据直接复用，不设每批前置门禁。

替代 Provider、受控依赖及附加配置声明与正式路径的差异和证明范围，夹具通过不代表正式供应商或业务通过。waiting/HITL 按实际契约续答，绑定新输入、原执行与持久进展；旧终态不冒充新结果。断言有业务歧义时保留原结果，澄清新样本，不改系统迎合测试。

数据库事实真实创建并持久化；负向用例从合法基线只改变目标拒绝条件，验证原因及无非法写入、越权或外部副作用。恢复实际重建组件并读取当前格式状态，保留身份、全值及时间精度差异；同步与资源清理由测试可靠性统一定义。

## 失败处理

先读首个相关错误与实际执行阶段，再按下表处理；诊断方法与停止条件归[系统排障](../../nw-debugging/SKILL.md)，不靠扩测代替定位。共同入口导致多场景失败时，按[设施复用与执行窗口](../../nw-test-reliability/references/test-reliability.md#设施复用与执行窗口)处理，仅暂停依赖该入口的验证。

| 类型 | 动作与完成边界 |
|---|---|
| 产品缺陷 | 修复产生错误的边界，复验原失败及直接回归 |
| 夹具或环境缺陷 | 修正装配、配置或资源隔离，优先以覆盖首个失败边界的最小入口确认；只能在真实链路确认时直接定向复验，不额外增加测试层级。已有有效证据直接复用，未进入业务的检查记未运行，保留生产约束和有效业务断言 |
| 历史 CI 问题 | 引用失败特征、基线版本、相关输入/条件及证据；相关变化或新失败才重新诊断。影响本次正确性、安全或发布要求的仍阻断对应交付 |
| 工具或基础设施故障 | 先确认检查是否实际启动与结果是否可信，再选择有依据的有界重试、等价检查或保留缺口 |

无新诊断或相关变化不重跑相同失败命令，不弱化断言换取通过。恢复长链路前，沿用已有摘要简述首个失败边界、本次相关变化和预期观察；关键原因仍未知时先采证，不叠加猜测性修补或另建检查台账。修复夹具不能抹去历史业务失败或 UNKNOWN；后续新样本成功不能证明旧外部操作的结果。

## 自动检查与规则落地

只自动化有稳定输入、可机械判断的规则；语义、授权与副作用仍按真实边界验证。新增检查有合法及目标违规样例，不镜像实现或弱化断言；已有检查先复用。

| 入口 | 能证明的范围 |
|---|---|
| [后端构建](../../../../backend-java/build.gradle.kts)及模块任务 | SQL 投影、测试源码隔离、模块依赖与 ABI；MyBatis 入口见[工程规范](../../nw-engineering/references/engineering-standards.md#数据库与迁移) |
| [Open Platform 契约流程](../../../../.github/workflows/open-platform-contract.yml) | 所覆盖契约、生成客户端与实际 springdoc 比对 |
| [文档检查](../../../../tools/docs/check.py) | 链接、结构与生成新鲜度，不证明规则一致或代码已实现 |
| `verifyDatabaseNames`（根 `check` 依赖） | 先运行命名工具的合法/违规/SQL 语义回归，再检查受控映射、独立声明和当前消费者；不能替代临时库迁移与行为验证 |

未实现的检查只能登记为后续工作，不能写成已执行或现行门禁；分别报告规范、实现、生成物及验证状态。

### 规则场景核对

规则变更选择直接受影响的场景，核对读取入口、动作和通过/停止条件，补充实际失败情形。判据归所属正文，走读只证明表述一致，不证明实际 Agent 行为、稳定性或效率。

| 场景 | 核对重点 |
|---|---|
| 只读问答或普通文档修改 | 只查相关事实与链接，不自动实现、跑业务测试或建 Note |
| 已授权局部实现或短时协助 | 简要任务说明、模块实现与必要验证；不加载完整 CSV，不重复确认 |
| 高风险数据库或权限变更 | 聚焦评审、真实依赖与拒绝副作用证据，不以单测替代 |
| 关键假设未知但有独立可做项 | 查事实源或最小实验，仅暂停依赖部分 |
| 已有可信缺陷证据或跨组件异常 | 复用原证据，沿实际输入输出找首个偏离点，核对同一业务决定的直接入口与消费者 |
| 同 HEAD 恢复，相关未提交内容可能已变 | 先读状态、查差量与活动执行，按输入决定证据复用 |
| 跨会话接替、未知派发或公共资源交接 | 按协作技能核原执行、单一状态和资源归属；已采用 CSV 的批次才读完整协议，UNKNOWN 不自动重放 |
| 规则维护源不同或活动窗口尚未结束 | 明确来源、授权和采用边界，不覆盖执行树、不热切窗口 |
| 评审要求历史兼容或实现者解释候选 | 按当前契约核实；解释、自测不替代明确要求的独立验收 |
| 子进程配置、Provider、调用结构或 Worker 归属错误 | 对照当前消费者核实夹具，按首个失败边界选择复验入口，未进入业务的场景记未运行 |
| 等待成功时已确认无法满足当前场景条件 | 按测试可靠性的等待退出规则采证并结束等待；恢复和 UNKNOWN 场景遵循各自契约 |
| 部分业务场景通过但整批任务失败 | 分别保留场景结果，只诊断失败边界，按相关输入决定证据复用 |
| 历史 CI 失败或 pending | 检查本次状态与差量，复用适用基线；只继续已授权无依赖工作 |
| 混合工作区或外部 UNKNOWN | 仅交付本任务差量，遵守终点；保留未知与原证据，后续成功不改写历史 |
| 前置已满足或剩余窗口不足 | 按原授权与预算接续；不延时、降产品预算或重放未知换取通过 |

## 启用条件

普通任务使用[基础流程的状态摘要](../../nw-workflow/references/development-workflow.md#工作状态快照)。仅在用户要求正式候选 Gate，或接续已采用该工具的受控验收时启用 manifest；不因收尾补建未触发的 Note。

## Writer 隔离

文件和接口无冲突可同树并行，共享文件或耦合状态机串行，Reviewer 只读；独立分支或可丢弃试验才用 worktree。构建输出、数据库、端口和缓存按实际竞争串行或隔离，安全缓存可共享。

验证冻结相关源码、配置与构建输入；manifest run 冻结完整声明候选，不冻结无关内容。确需公共资源交接时按[协作协议](../../nw-coordination/SKILL.md)处理。

## 证据复用与 verification manifest

相关源码、配置、测试/夹具、契约、工具链与环境条件相同，且命令、结果及输入绑定可追溯的证据必须复用；关系不明时检查最小可信范围。同 HEAD 不足以证明未提交输入相同，缺失、失败或不可信证据阻止对应完成声明。

相关输入变化只使受影响证据失效，无关文字不使业务证据失效；验收要求变化更新相关检查，不重写或重跑历史验收。不叠加定向 test、模块 test、check 和 manifest 重跑，需要工具采证时尽量在首次必要验证收集。

区分未运行、复用、本次通过、失败、skip 与未知，防止零测试误报。机器状态和命令见[manifest 用法](verification-manifest.md)；工具为可丢弃缓存，不手填成功、冒用旧报告或将普通摘要当受控证据。

## 交付前差量

远程交付或评审就绪前核对实际仓库/worktree、分支、remote、目标基线及完整提交差量，检查本任务遗漏的暂存、未暂存和未跟踪变化；其他任务仅用于隔离与误带检查。

证据须对应实际交付输入，不能依赖未交付改动宣称提交通过。PR base、依赖分支和远端 head 取当前事实；基线、rebase 或 retarget 变化后只补受影响证据。按差量映射模块、ABI、前端、文档、OpenAPI、数据库、配置及真实 E2E；动态装配、反射和子进程不能仅凭静态图排除，不追加统一全量 pre-push 套件。

push 后核对远端 SHA，读取本次 CI 与保护状态，分别报告 pending、skipped、失败或无运行。历史失败按[失败处理](#失败处理)引用基线；状态未变不反复下载分析同一日志。推送成功不证明 CI 通过，等待期间接续与阶段关闭按基础流程判断。

## 里程碑与远程写入

里程碑按集成风险验收完整能力组，远程动作遵循[阶段授权](../../nw-workflow/references/development-workflow.md#阶段交付与授权)。

### 候选集成与业务闭环

集成负责人明确目标分支/产物、纳入差量、依赖顺序及实际源码/配置/装配输入；局部自测、必要独立验收和集成后的真实组合链各证明对应范围，若干独立通过的 overlay 不自动构成正式组合。

复用未变证据，仅补受影响消费者与真实依赖。报告区分已实现、自测、独立验收、集成、业务链、部署和可发布；局部关闭不解除组合缺口。待验收或集成积压时优先完成已有闭环，协作进度从[现有记录](../../nw-coordination/SKILL.md)派生。
