# 测试可靠性

本文件定义 灵知 测试与夹具在并发、共享资源、时钟、子进程和异步清理下的可靠性做法；生产代码的对应缺陷模式仍归[防御性编码模式](../../nw-engineering/references/defensive-patterns.md)。验证范围、失败分类和证据复用由[评审与验证规范](../../nw-verification/references/candidate-driven-delivery.md)决定；本文件不新增测试层级、统一重试或固定 Gate。

## 适用条件

新增、修改或诊断的测试涉及端口、临时目录、数据库、容器、进程级状态、时钟、线程/执行器、子进程、浏览器或异步 teardown 时加载本文件。普通纯计算单测不因存在 CI 就扩大验证；诊断、修改与远程执行边界统一按[开发流程规范的自主执行边界](../../nw-workflow/references/development-workflow.md#自主执行边界)，本文件只约束已选复现如何隔离资源和形成可信证据。

只读取已选测试及其实际 lane 直接相关的 Gradle/JUnit 或 Vitest/Playwright 配置；证据指向共享主机资源时，再检查可能重叠的命令和 CI job。测试方法、worker、独立命令和同机其他任务可能重叠；JVM 或进程隔离不隔离主机端口、可预测路径、数据库 namespace、容器名和遗留子进程。

被占用资源需要明确所有者、原子分配、readiness、失败清理与静止信号；从现有夹具和测试核实即可，不另填资源检查表。现有串行或单 worker 配置可以保留为当前资源约束，但不能把它当成夹具已隔离的证明；改变并行度时才补相应隔离与并发证据。

## 隔离资源与全局状态

- 网络监听优先绑定 loopback 的端口 `0`，在服务报告已监听后读取实际地址并传给调用方。Testcontainers 使用其映射端口；需要组合启动前后端时由同一次运行分配并显式传递端口。禁止先扫描“空闲端口”再晚些绑定。
- 临时文件使用 JUnit `@TempDir`、`Files.createTempDirectory` 或工具等价能力；测试拥有的可变输出、socket 和会影响用例状态的缓存使用每次运行的私有根目录。构建工具明确支持并发共享的依赖或构建缓存按[Writer 隔离](../../nw-verification/references/candidate-driven-delivery.md#writer-隔离)复用，只有实际竞争或污染证据要求时才串行或隔离。仅作为解析输入或预期值的固定路径不是被占用资源，不为形式随机化。
- 共享数据库或容器按测试风险选择独立容器、database/schema、租户和业务标识，或使用事务回滚与精确清理隔离事实；不能依赖其他用例留下的数据或固定执行顺序。业务事实构造和负向用例基线继续按[评审与验证规范的测试夹具规则](../../nw-verification/references/candidate-driven-delivery.md#测试夹具)处理。
- `System` properties、默认时区/Locale、静态 registry、线程池、Mock server、日志钩子，以及前端 fake timers、`globalThis`、模块 mock 和 `fetch` 拦截都属于进程级可变状态。优先注入实例级依赖；必须修改时记录原值是否存在，在最小 `try/finally` 范围精确恢复，并保留失败前已注册的兜底清理。
- Java 测试不要反射修改进程环境变量；需要环境差异时通过 `ProcessBuilder.environment()` 隔离到子进程。JUnit 的资源锁或串行块只保护它能覆盖的同一进程范围，不能声称隔离了其他 worker、命令或 CI job。

## 同步与静止清理

### 设施复用与执行窗口

复用已验证的编译/启动、Provider 配置、HITL、观察、异常留存和清理入口及固定版本，保持输入和运行输出隔离。重复的共同设施失败先修共同入口，不让各条线重新修同一问题；共享维护与 Writer 边界按[协作规范](../../nw-coordination/SKILL.md)。业务预检按[测试夹具](../../nw-verification/references/candidate-driven-delivery.md#测试夹具)选择最低充分范围，不新建测试平台。

执行计划区分准备预检、环境就绪、业务执行与收尾，参考已观察的实际耗时，核对控制器、服务 readiness 与分派时限一致。已有总时间、调用和费用上限不变；派发前按剩余预算容纳正常产品执行、观察和收尾，减少本窗样本而非临时延长截止或降低产品预算来获得通过。迁移仍推进不等于可越过原截止；不足时保存当前事实，按已授权后继及新窗口边界接续。已有明确轮次继续有效，新增差量按最低充分范围选择，不把任一固定轮次变为默认门禁。

同一候选、明确所有者、有效资源权限、已确认环境状态且预算足够时，可在同一环境连续执行相关用例，独立样本仍隔离业务身份和状态；不机械逐样本重建数据库和服务。有 UNKNOWN、恢复副作用或归属不清的环境继续隔离，不为节约启动而恢复旧请求或复用不明业务状态。复用冻结设施不等于共享可变输出，资源交接不以目录相同或进程结束代替核实。

观察或控制入口异常时，在退出和清理前保存首个异常链、阶段、时间及已知派发身份，按敏感性脱敏；摘要只保留有界诊断和原报告引用。按业务场景分列结果、设施失败、断言问题、环境问题、UNKNOWN 和 NOT_RUN；整批任务失败不改写其他已证实场景的结果，按[相关输入](../../nw-verification/references/candidate-driven-delivery.md#证据复用与-verification-manifest)决定证据是否继续有效。先保留已确认事实，再标缺失证据，不能因后续捕获失败丢掉前面已确认的事实。补证与更正写新位置并引用原件，先核工具是否会回写既有报告；不得覆盖冻结原件。设施修正成功只证明该设施边界，不证明历史失败的唯一根因或业务通过。

### 子进程与长链路预检

新增或改变子进程夹具，且以下事实尚未证实时，在长业务场景前做能消除该未知的最小预检；同输入证据已足够则跳过。

- 从实际子进程确认 profile、环境/参数、模型能力与 Provider/Bean 选择，父测试的声明不证明子进程生效；重启后的配置仍须符合该测试的输入绑定。
- 证明实际领取与推进任务的是目标 Worker/进程。父测试需静止时同时覆盖轮询、事件唤醒和直接派发入口，不能仅凭关闭轮询或进程存活推定隔离。
- 确认首个异常、相关持久执行身份与必要回执能在失败清理前保存；正式场景仍保留重启、拒绝与 UNKNOWN 断言。

预检失败先修夹具装配或隔离；生产约束和业务断言保持有效。预检通过只证明已检查的设施条件，不替代完整业务验收。

### 等待与清理信号

固定 `sleep` 不能证明准备完成、竞争发生或清理结束。等待明确的监听事件、latch/barrier、future、状态迁移、数据库事实或浏览器可观察条件；timeout 只限制等待上限，不能成为断言成立的条件。竞争测试用 barrier 把双方放到目标迁移点并证明实际重叠，重复运行只能补充压力证据。

持久状态、回执或观测异常已确认使当前场景的成功条件无法成立时，立即结束该次成功等待，按[设施与窗口](#设施复用与执行窗口)保留首异常和必要执行事实，不等到总 timeout 才报告。恢复或 UNKNOWN 本就是场景预期时，按其契约继续观察或核实；后续新样本不重放原未知副作用。

获取资源后立即注册清理，使 setup 或断言失败也能释放资源。清理应停止新请求和回调、解绑 listener、恢复全局状态、终止拥有的工作，并等待 executor/thread、子进程、服务、容器、浏览器 context 或 page 的完成信号。只调用 `close()`、`shutdown()`、`cancel()` 或 `destroy()` 而不等待其静止，不算 teardown 完成；可能迟到的回调还须证明不会写入下一用例的状态。

时钟是被测对象时注入 `Clock` 或使用框架 fake timer，并在用例结束恢复真实时间。外层测试 timeout 须覆盖被测 deadline 与已识别的调度、观察和清理上限，并让失败能区分产品超时与测试框架超时；放宽 timeout 前先指出正在等待的可观察状态以及当前 lane 原有预算。

## 平台差异

优先断言 Windows 与 POSIX 都成立的行为。时间戳精度、环境变量名大小写、文件句柄释放、路径/换行、权限和 signal 语义可能不同；仅由操作系统拥有的文件元数据等平台事实可在写入后重新读取并据此断言。业务、公共或持久契约仍按权威输入断言，精度损失必须暴露，不能用平台实际值反推预期。确实依赖某平台能力的用例可显式 skip 并写明原因，不得在所有平台弱化断言。Windows 句柄释放需要等待时，使用针对已知完成条件且有上限的重试，不把通用 retry 当成稳定性修复。

## 诊断与证明

调查 flake 时保存 commit、命令、runner/平台、失败用例和首个稳定失败特征，并用相同输入比较失败与通过记录。从已有证据支持的最小相关拓扑开始；无覆盖时才在单用例、同 worker 并发、独立测试进程、模块 Gate 或共享主机任务中扩大到下一相关层级，已有可信证据排除的层级不重跑，证据直接指向高层资源碰撞时可从该层复现。根据证据区分产品并发缺陷、资源碰撞、生命周期未静止、全局污染、基于延时的同步、平台/真实入口差异、外部服务瞬态和 runner 基础设施。

修复与负控沿用[测试路由](../../nw-verification/references/candidate-driven-delivery.md#测试路由)，仅对实际风险补独立进程冲突、静止或全局状态恢复证据。增加 sleep/timeout、无条件 retry、整套串行、吞异常或归一化差异不能证明根因修复；有文档依据的供应商瞬态重试只留在该外部边界。

报告实际运行的命令、拓扑和结果，区分未运行、复用、通过、失败与 skip。压力运行不能替代确定性回归，单次 rerun 通过也不能证明 flake 已消失。
