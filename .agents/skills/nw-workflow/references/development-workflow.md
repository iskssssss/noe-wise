# 开发流程规范

本文件拥有启动、范围、授权、任务组织与恢复规则；实现、验证和文档按[技能任务表](../SKILL.md#按任务加载)进入对应专题。

## 项目最高优先原则

以下原则优先于其他项目规则与历史惯例，但不扩大范围或授权，也不免除必要验收：

1. **保障系统架构正确性，不兼容历史任何实现。** 以当前已批准架构与契约为准；历史接口、数据和配置不形成兼容义务。替换与实际数据操作见[工程规范](../../nw-engineering/references/engineering-standards.md#项目阶段与优先级)。
2. **快速推进，按模块批次实施，关键不确定性先验证，稳定后集中验收，不过度审计。** 验证选择见[评审与验证规范](../../nw-verification/references/candidate-driven-delivery.md#风险路由)，达到完成标准即交付。

## 启动顺序

首次进入任务读取本文件，再按任务表加载相关技能；先读专题核心要求，再按实际影响读对应章节，不遍历全部参考文件。链接用于定位，不要求重读已掌握且未变化的基础规则；无需另建加载台账。专题以改善当前决策为目的，入口短小，少见模式按需读取。

恢复任务先按[工作状态快照](#工作状态快照)接续，只补读上下文缺失或已变化的规则、契约和证据。

## 自主执行边界

按用户意图明确目标、必要验收和交付终点。问答、评审、诊断、方案讨论及计划模式默认只读；实现、修复、重构或优化请求在授权范围内直接执行。已有对话、设计和授权持续有效，不因阶段切换或恢复重复确认。

普通实现细节由执行者决定。现有事实源无法决定且会改变交付结果的关键取舍，或超出授权的操作，才请求澄清；仅暂停依赖部分，其余工作继续。

为推测出来、几乎不会发生的边界问题（含安全边界）或并发问题增加防御代码前，必须先向用户说明具体触发条件与后果、发生概率及判断依据、预计新增多少代码与维护成本，获得用户明确同意后再加；概率无法可靠估计时如实说明，不编造数字。严禁以“理论上更稳”为由私自膨胀代码或扩大范围；用户未同意时不添加该防御，继续其余已授权工作。已有明确授权覆盖该措施时不重复确认。

## 任务组织

| 条件 | 做法 |
|---|---|
| 目标、边界和验收明确的局部任务 | 直接实施，沿用对话摘要 |
| 已有批准设计或计划 | 核对当前入口与直接依赖后接续；有新冲突证据才调整受影响部分 |
| 跨模块、长任务或需交接 | 按可独立验收的行为拆分，先确定共享契约与真实依赖 |
| 产品意图或关键语义不明 | 先查所属事实源，再按自主执行边界处理 |

复用已有契约和计划；长期决策按[Note 条件](../../nw-docs/references/notes-governance.md#4-note-触发与复用)记录，普通任务不另建材料。

委派、跨会话接替或共享资源交接按[协作技能](../../nw-coordination/SKILL.md)处理，默认使用任务说明、结果汇报和一个状态入口；普通任务不加载完整协议。

已有授权覆盖后继，且前置通过、候选明确、资源与剩余预算允许、无影响后继的未知副作用时，直接接续。等待测试或 CI 仅阻止依赖其结果的动作，可继续无冲突的已授权工作；实质分派变化更新已有状态入口。

## 实现优先

围绕实际入口追踪调用、数据和装配依赖；依赖不明或事实冲突时定向扩大调查。功能任务交付范围内完整的实现、配置、装配和错误处理，不用接口或占位代码替代功能；不为假设需求预建框架。

影响公开契约、数据语义、权限、外部副作用或后续方向的未确认假设，先查事实源或做[最小检查](../../nw-verification/references/candidate-driven-delivery.md#测试路由)，再实施依赖部分。范围内架构冲突和阻断交付的问题同步解决；无关问题仅在有后续价值时报告。

## 阶段交付与授权

授权来自用户指令或确认的计划，Agent 自写计划不扩大权限。约定终点包含必要且范围内的常规前置动作，例如创建 PR 包含本地提交和分支推送。普通修改止于本地修改与验证；提交不含推送，PR 不含合并或部署，“完成”“收尾”沿用约定终点。

| 阶段 | 必要条件 |
|---|---|
| 本地提交 | 审查本任务完整差量，保留其他任务工作区和暂存状态，如实记录验证 |
| push、创建或更新 PR | 明确仓库、remote、源分支和适用 base；按验证规范检查完整交付差量；中间推送或草稿注明未完成项 |
| 合并 | 必要 CI、评审、分支保护与依赖满足 |
| 非生产部署 | 环境、版本、配置、迁移影响与恢复方式明确，满足环境发布要求 |
| 生产发布 | 明确授权覆盖环境与范围，完成配置、迁移和恢复准备，满足发布要求及约定窗口 |

正常远程交付完成必要验收。自动部署等额外副作用也须获授权；强推、改写共享历史、删除远程分支和破坏性数据操作须明确动作与目标。授权不替代环境审批或分支保护。

### 本地检查点

已获提交授权时按稳定模块批次提交，复用有效证据；否则保留工作区改动，不因任务长自动申请提交。撤销仅针对本任务差量或提交，禁止整体 reset 或覆盖混合工作树；数据与外部副作用恢复按[数据库与迁移](../../nw-engineering/references/engineering-standards.md#数据库与迁移)处理。

## 工作状态快照

普通短任务沿用对话与交付摘要；需长期推进、恢复或交接时只维护一个简短入口：已有 Note 可承载状态，否则使用 `.agent-work-state/`。已采用 CSV 协议的活动批次沿用公共 CSV 与角色本地状态，不再复制同一事实。

摘要保留目标与授权终点、当前位置及完成边界、实际路径/分支和相关输入版本、验证状态与证据位置、阻塞及下一步。批次完成或授权、验证、阻塞、交接发生实质变化时更新；不逐工具记账、复制规则或原始报告、手算指纹。

恢复先读摘要，再核对实际路径、分支、git status、记录后的相关差量及活动执行。接续已启动的执行；结果未知先查原事实，不盲目重放。同 HEAD 不证明未提交输入相同，证据适用性按[证据复用](../../nw-verification/references/candidate-driven-delivery.md#证据复用与-verification-manifest)判断；跨会话接替按[协作规则](../../nw-coordination/SKILL.md#接替与资源)处理。

## 工作树创建与迁移

使用 Git 创建工作树或独立 clone，不整目录复制 `.git`，不迁入旧索引、锁文件和运行缓存。工作目录、缓存和日志目录由开发者指定，避免将本地运行资料提交到仓库。分支默认使用 `codex/` 前缀，基础提交由任务明确指定。

[工作树工具](../../../../tools/dev/worktree.py)提供以下入口，在仓库根目录执行；示例分支和路径按任务替换：

```powershell
$baseCommit = git -C ../noe-wise rev-parse HEAD
python -X utf8 -B tools/dev/worktree.py create --repo ../noe-wise --path ../noe-wise-my-task --branch codex/my-task --ref $baseCommit
python -X utf8 -B tools/dev/worktree.py check --repo ../noe-wise-my-task --expected-head $baseCommit --clean
```

创建入口要求新目录不存在、来源没有索引锁或无实际差异的修改记录，并自动核对新树的基础提交与空白状态。来源存在未提交修改时默认停止；确实只需要指定提交时显式添加 `--committed-only`。创建后验收失败保留现场，不自动回滚分支或删除目录。

需要携带未提交修改时，先短暂停止来源的文件与 Git 写入，分别迁入已暂存、未暂存、删除和未跟踪文件。文件按原始字节复制，禁止通过文本读写管道重新编码；索引内容通过 Git 补丁或逐项迁入，禁止复制 `.git/index`。忽略的本地环境文件、凭据和运行数据不属于普通代码迁移清单，确需迁入时按原任务授权单独处理。迁移完成、恢复任一端写入前执行：

```powershell
python -X utf8 -B tools/dev/worktree.py check --repo ../noe-wise-my-task --source ../noe-wise
```

迁移检查要求基础提交、暂存内容与标记、变更清单、暂存/未暂存状态及文件原始字节一致；不一致即停止依赖该迁移的开发。普通检查允许真实开发变更，但“显示修改而实际差异为空”必须先查换行与索引状态，不用全部暂存或整体回滚掩盖。检查只读，不刷新索引、不删除锁。

换行以根目录 [`.gitattributes`](../../../../.gitattributes) 和 [`.editorconfig`](../../../../.editorconfig) 为准；补充规则不触发全库格式化或重新暂存。锁文件先核对活动 Git 操作；只有确认无活动进程、锁已失效且可独占打开后，才将其移到仓库外的备份目录。禁止定时或无条件删除索引锁。

## 完成标准

任务或子项达到约定目标、必要验收通过，范围内已知架构冲突及影响交付的正确性、安全或功能缺陷已解决，且无本次引入的已知回归，即可交付。按对目标和验收的实际影响判断阻断，不以测试数量、评审轮次、建议清零或总任务关闭作为子项完成条件。

## 过程沟通

更新只说明新增结论、具体问题、有效验证和下一步，不重复无变化的阻塞。交付说明实际范围与阶段、交付物、验证与限制。跨会话通信与规则采用仅在涉及交接时按[协作技能](../../nw-coordination/SKILL.md)处理。
