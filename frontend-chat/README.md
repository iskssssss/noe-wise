# 灵知 · 独立会话端

独立会话端是灵知面向最终用户的交互入口。用户在持续会话中描述目标、附上资料和图片、查看助手回复与执行进度，并在需要时补充信息、确认操作或使用正式成果。专业协作与成果面板消费后端公开投影，Agent 的判断、能力授权和任务状态由服务端运行时维护。产品角色与完整旅程见[产品概述](../docs/01-产品与需求/02-产品概述.md)和[产品需求文档](../docs/01-产品与需求/01-PRD.md)。

会话应用独立使用 Vue 3、Lucide、marked 与 DOMPurify。它不引用机构端、平台端、后台公共层、Element Plus 或仓库后台构建插件；`src/ui/controls/` 持有会话端自己的表单、选择器、抽屉、上传、折叠、表格和反馈控件。抽屉和确认框通过原生 dialog 管理模态焦点，选择器支持键盘导航与筛选。

`src/style.css` 集中定义明暗主题、8pt 间距、圆角、阴影与动效令牌，默认深色并恢复已保存的主题。桌面会话和成果采用 12 列栅格，窄屏面板使用模态布局；键盘焦点、触屏点击区域和减少动态效果偏好由同一套样式管理。

## 启动与验证

服务启动遵循仓库[开发与部署指南](../docs/04-指南与运维/01-开发与部署指南.md)的本地启动节。独立模块命令：

```sh
corepack pnpm --filter frontend-chat dev
corepack pnpm --filter frontend-chat test
corepack pnpm --filter frontend-chat lint
corepack pnpm --filter frontend-chat format:check
corepack pnpm --filter frontend-chat build
```

ESLint 使用会话端自己的 Vue 3 essential 与 TypeScript recommended flat config，检查源码、测试和本地脚本。Prettier 单独负责格式化，`format` 可写入格式修正；ESLint 最后加载 `eslint-config-prettier`，避免重复处理格式规则。

原消息结果未知后的重试恢复可在 `backend-java` 执行 `./gradlew :skillforge-institution-service:chatInputRetryBrowserE2E`（Windows 使用 `gradlew.bat`）。该任务启动隔离数据库、真实服务与浏览器，使用本地 HTTP 模型；首次受理回执受控丢失后，真实关闭会话并重试，验证拒绝不能清除原请求，随后只读恢复历史。需要 Docker、已安装的前端依赖及 Playwright Chromium；结果保存在机构服务的 `build/runtime-e2e/input-retry-*`，浏览器 trace 留存前对本次凭据脱敏。该检查不代表外部供应商验收。

开发端口默认 3200，`/api` 代理至 `http://localhost:8000`，可通过 Vite 的 `--port` 指定实际端口。构建输出为 `dist/`，静态部署示例见 `nginx.conf.example`。跨域服务须显式允许页面来源与渠道认证请求头；生产使用 HTTPS。

## 模块与交互

连接页的认证方式按收到的凭据选择：单个渠道令牌选择“渠道令牌”，配套的 API Key 和 API Secret 选择“API 凭据”。服务地址默认使用当前页面来源，仅在机构提供其他地址时修改；昵称选填，位于认证信息之后。服务地址、两种凭据和昵称分别声明输入用途与自动填充分组，保留密码管理器支持，避免把昵称识别为登录账号。连接卡片集中说明凭据来源和保存范围，字段保留必要的选择依据及校验提示。

- `protocol.ts` 声明会话端实际使用的公开 DTO。
- `client.ts` 持有 HTTP envelope、渠道令牌/HMAC 和 SSE 传输。POST 不自动重试；GET 观察使用 Last-Event-ID 有界重连。游标过期后以权威历史恢复，HTTP 5xx 时按观察的有界退避重读历史；历史返回精确的成果发布等待状态时，沿用首次读取的最多五次、可取消等待。成功后才采用新游标，权限拒绝及未分类错误保持原错误。
- `projection.ts` 按公开消息版本、过程更新序号与 Session 序号合并投影。
- `session.ts` 持有连接身份、会话选择、输入冻结、附件、历史和取消状态。
- `ui/` 为会话自身的补参、团队、成果、浏览器设备、目标与协作面板；不是后台公共资源。

连接时验证渠道并登记访问者。渠道连接信息（包括令牌或 HMAC 凭据）保存在当前标签页的 sessionStorage；主动断开时清除，关闭标签页后不再保留。访问者的 `client_ref` 与服务端签发的 `identity_token` 按服务地址和已验证渠道保存在 localStorage，用于后续连接时恢复同一访问者身份；主动断开不会清除这项记录，服务端确认身份失效时会移除。浏览器存储不可用或写入失败时，这些信息无法保证持久化。昵称不是认证凭据。重新加载同一标签页会重新验证连接，再恢复仍有权限访问的目标及会话。主题选择独立存储。

发送先创建稳定 Session，再提交一次带 client_message_id 的请求。网络结果未知时保留完整请求；“重试原请求”复用身份、正文、附件与引用。切换目标或会话只释放本地观察，不取消后端运行。停止运行调用取消接口并持续核验真正终态；等待用户输入不等于取消完成。预算或策略使运行进入 `terminated` 时显示“已终止”，停止取消状态轮询并恢复消息输入，不自动重新提交；结果未知仍保留原有状态与处理边界。

消息、图片与 Markdown 从公开数据渲染。历史分页与在线事件按版本合并，引用保留公开选择器。工具补参和 Plan 评审提交原等待身份。目标、运行补充、团队及协作控制均调用现有真实接口；命令目录支持上下键、Enter/Tab 选择与 Escape 关闭，只填写草稿，不直接执行。团队与工具使用互斥抽屉，提交期间禁止关闭，未提交修改离开前确认；切换会话同样经过抽屉保护。上传控件将一次选择的多个文件合并，再交给独立签名客户端上传。

运行补充发送中或结果未确认时保留原命令身份并暂锁会话导航，可查询或重试原补充。权威状态确认运行已停止接收且没有原命令时，提示未受理并保留原文到下一条草稿；已受理的补充仍按原回执显示消费状态，不自动重新发送。

工作流菜单直接显示返回的选项，补充说明可选；必须明确选择按钮，表单回车不会默认选择首项。确认与菜单回复同时保存可读文字和原结构化动作，恢复键、等待版本与输入身份保持不变，未知结果沿用原请求核对机制。已完成的展示卡片直接显示标题、正文、字段和 HTTP/HTTPS 链接，刷新后从公开消息恢复；历史菜单或确认卡不重新提供提交按钮。

智能体按名称选择已挂载工作流时，模型目录包含本次受理时冻结的正式版本名称、用途和准确句柄；执行轨迹的摘要显示实际调用名称。工作流等待用户操作后，已受理的选择随执行回执进入模型上下文，连续等待按提交顺序保留，外部系统回调不冒充用户选择。

菜单按钮响应中的空补充说明不代表用户没有选择或工作流没有输出，模型回执说明区分这两类事实。最终回复使用业务结果和可理解的状态，只说明影响当前任务的限制；技术状态码、修订和协议信息按用户排错需要提供。界面不删改模型正文或历史记录，实际效果须结合新会话与模型收到的上下文验证。

长文本粘贴按实际选区合入后的正文判断用途：`/goal` 等本地控制命令保留原生文本粘贴，不转换为只供普通消息消费的附件。目标正文完整交给现有命令入口，格式和长度限制在发送时校验；普通长消息继续按现有规则暂存文本附件，确认发送前不上传。目标命令反馈只显示当前状态与轮数，完整正文在“会话工具”的目标页查看，避免长目标占满顶部反馈区域。

持续目标通过“创建并开始”立即发起执行；轮数只统计后续自动继续，不包含首次执行，也不等于模型调用次数。进行中或已暂停的目标保留对应控制入口，结束前不提供重复创建表单；其他目标可在新会话创建。

运行中可以为下一条消息选择或粘贴资料与图片，已确认上传的项目保留在当前草稿；上传只准备资料，不提交新消息，也不改变当前执行已冻结的附件身份。当前运行结束后，用户明确发送才采用下一条草稿中的资料。类型、大小和会话容量限制、输入模式及切换会话后的迟到回执处理继续适用。

成果按需读取，从顶部或消息卡打开成果面板时刷新列表；已在读取时沿用当前请求，刷新失败保留已有成果并可重新读取。下载和预览每次取得受控票据，预览 iframe 使用 sandbox。恢复成果版本只加入下一条消息的引用，由用户发送。会话导航中的请求次数不包含助手回复。浏览器配对、默认设备、改名、撤销与取消使用当前访问者的真实接口。

成果和待发送附件使用相同的文件大小显示：不足 1 KB 时显示实际字节数，KB、MB 统一按十进制换算并保留一位小数。

会话工具的“执行与送达”和 `/delivery` 命令使用一致的中文状态，分别说明本次执行、会话回复能否重新读取和外部回调确认情况；可重新读取或接收方确认均不表示用户已读。

表单已报错的字段会在输入修正或关联值更新时重新校验，避免错误提示拖到下一次点击才消失；尚未校验的字段沿用失焦或提交时校验。团队只选一位成员时自动选择负责人，可直接保存。

团队保存和停用后保留当前团队及服务端返回的修订，便于继续查看或编辑。停用团队明确显示“保存并启用团队”，保存后配置立即生效并恢复对话；已停用时不再显示停用按钮，已有会话和数据继续保留。

停用团队仅可读取历史消息与运行状态；页面停止读取命令目录、工作区和成果，任务、成果与会话工具入口提示重新启用后使用，避免将停用限制误报为临时故障。重新启用后恢复相关读取，原会话保持不变。

浏览器设备面板区分适配扩展直接配对与官方扩展手动连接，并使用服务返回的安装说明地址。设备与任务查询连接不到浏览器服务时，提示稍后刷新或联系管理员；服务恢复后可刷新读取列表，不能把读取失败解释为没有设备。

新会话可以直接选择“先制定计划”；任务详情和会话工具的任务计划空态提供“开始规划”。开启后回到消息输入框并保留原草稿；描述需求后等待助手生成计划，批准后执行。空历史不显示无选项的选择框。计划变化与步骤进度通过持久工作通知更新，刷新按当前消息页恢复原计划和会话的规划选择；只有真实计划待批与对应 Run 挂起事实一致时，才显示等待批准。

团队管理按渠道公开目录展示负责人的协作范围。已选成员超出该范围时，说明具体成员和配置路径并暂不可保存；仍可调整成员或负责人。管理员发布委派配置并绑定渠道后，可在面板中刷新成员目录，保留当前草稿和团队修订。刷新只更新公开选项，不授予委派权限；保存仍由服务端校验当前发布配置。

接口事实源为后端公开 DTO 和[接口与事件契约](../docs/02-架构与设计/04-接口与事件契约.md)。本模块测试覆盖签名字节、SSE 分块、身份切换、输入幂等、排队恢复和工具补参；真实模型、真实浏览器设备及外部工具的完整验收需在对应环境另行执行。
