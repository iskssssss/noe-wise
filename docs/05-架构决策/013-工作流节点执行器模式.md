# ADR-013：工作流节点执行器模板方法模式

> **状态**：Accepted（仅节点执行器内部模式） · **日期**：2026-08-09 · **Owner**：架构
> Agent/Workflow 外部边界和引擎入口以 [Harness Design](../../harness-design/README.md) 为准。

## 当前适用边界

有效范围是节点执行器内部模式。下文的 HTTP 节点、日志三明治、旧路由与配套类记录保留当时背景，不构成现行节点类型、日志策略或宿主/SDK 依赖限制；当前节点语法见[工作流规范](../03-规范与术语/01-工作流规范.md)，日志规则见 [工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md#事务日志与可观测性)，Runtime 与装配边界见 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md#14-agent-runtime-sdk-交付边界)。

## 背景

`StateMachineEngine`（约 1992 行）是典型上帝类：单节点执行集中在
`executeNode` 的单一 `switch(node.type())`（14 个类型分支），同时承载
10+ 个私有帮手函数（插值 / 变量解析 / 卡片构建）。工具与 HTTP 节点的
on_error 三分支、human_input 与 menu 节点的卡片挂起逻辑彼此重复；
节点类型散落为字符串字面量，无集中定义。

## 决策

- **节点执行采用模板方法模式**：抽象基类 `WorkflowNodeExecutor` 固定
  执行骨架（`execute` = 日志三明治 + 委托 `doExecute`），每个节点类型
  一个子类实现业务差异点；工具/HTTP 共用的 on_error 三分支与
  human_input/menu 共用的挂起卡逻辑下沉为基类 protected 助手，组合复用。
- **注册表分派**：引擎持有 `Map<type, executor>`，按 `NodeTypes` 常量
  键分派；结构节点使用显式执行器，未知类型在发布校验或执行前拒绝，禁止静默跳过。
- **执行器装配**：节点执行器通过显式注册表装配；具体是否由 Spring 管理取决于 Workflow Runtime 的目标依赖边界，不以保留旧构造器为约束。
- **帮手函数收敛为纯静态类** `WorkflowExpressions`（插值 / resolve /
  卡片构建等），引擎条件链（evalCondition / evalUnit）与执行器共用，
  单点维护。
- **parallel / subgraph 循环骨架不迁移**：fork/join 并发与子流程解析仍由
  引擎持有，经函数式接口（`ParallelRunner` / `SubgraphRunner`）注入执行器。

## 配套（同批设计模式重构）

- **策略+工厂**：`ConnectorExecutor`（Provider 策略 + Registry 分派）；
  `NotificationChannel` 使用显式注册表，未知渠道返回校验错误，不能以日志替代真实成功。
- **模板方法**：`RerankClient`（`AbstractRerankClient` 固定调用骨架，
  两协议仅 buildBody 不同，按 Base URL 分派）。
- **责任链**：`IntentRouteHandler`（L1 关键词 → L2 语义 → 降级引导）与
  `AgentRouteHandler`（渠道 Agent 绑定 → 降级回退；Agent Group 概念已移除，
  原 GroupRouteHandler 更名，见 ADR-016），各模块最小实现，不跨模块共享抽象。

## 约束

- 节点执行器内部模式可复用；与 Harness 契约冲突的 public 方法和构造器可以直接替换。
- 节点类型常量唯一真源 `NodeTypes`；新增类型须注册执行器并更新文档。
- 未知节点类型必须失败并返回稳定校验错误；未知通知渠道不得伪装为成功。

## 理由

- 消除 230 行 switch 与三处重复分支；新节点类型 = 新子类 + 注册一行，
  不再触碰引擎主链路。
- 节点语义由契约测试保护，外部执行入口可按 Harness Design 整洁替换。
- 执行器非 bean 避免组件扫描面扩大与循环依赖风险。
