# ADR-002：实时通信协议

- **状态**：Accepted
- **日期**：2026-08-03
- **决策者**：架构组
- **关联**：接口与事件契约、核心流程设计、非功能需求、任务 1.10.x / 2.8.6

## 当前适用边界

本 ADR 保留 SSE/WebSocket 的协议分工及当时的传输参数。历史缓冲 TTL 不定义 Runtime 的持久重放窗口，也不替代 Outbox；当前对外传输见[API 与事件契约](../02-架构与设计/04-接口与事件契约.md#6-sse-事件)，持久输出与恢复语义见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#57-multi-execution-registry-与-session-mailbox)。

## 背景

文档混用 SSE 与 WebSocket：路线图写 SSE，技术栈写 WebSocket 对话 + SSE 推送，流程文档先 WebSocket 再建议改 SSE。前后端会重复实现断线恢复与负载策略。

## 决策

| 场景 | 协议 | 理由 |
| :--- | :--- | :--- |
| **C 端对话流式输出（MVP-0 及默认）** | **SSE** | 单向推送足够；天然支持 `Last-Event-ID` 重连；对代理/CDN 更友好；实现成本低 |
| **B 端人工坐席工作台双向实时** | **WebSocket** | 坐席需双向收发、输入状态、工单推送 |
| **OpenAPI 集成方** | SSE（推荐）或同步 REST | 契约明确事件格式；同步模式用于简单客户端 |

### SSE 语义（对话）

- 事件字段：`id`（单调递增）、`event`（类型）、`data`（JSON）
- 客户端断线后携带 `Last-Event-ID` 续传；服务端按 session 缓冲未确认事件（TTL 可配，默认 15 分钟）
- 心跳：至少每 15s 发送 `event: ping`
- 幂等：同一 `id` 可安全重放；客户端去重
- 错误：以 `event: error` 结束流，并附稳定 `error_code`（见 API 契约）

### WebSocket 语义（坐席）

- 鉴权：连接建立时携带 B 端 JWT；服务端校验租户与角色
- 心跳：双方 ping/pong，60s 超时断开
- 消息必须含 `message_id`；重连后按 seq 补发

## 后果

- README / 技术栈 / NFR / 任务统一上述分工。
- NFR「100,000 并发」按「SSE 连接 + 短连接 REST」建模，不再笼统写 WebSocket 连接池。
- 渠道适配器内部可将结构化消息渲染为微信模板等，与传输协议解耦。

## 不做的事

- MVP-0 不为 C 端对话实现 WebSocket。
- 不自研 Socket.IO；标准 SSE / WS 即可。
