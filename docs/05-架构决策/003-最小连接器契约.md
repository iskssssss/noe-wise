# ADR-003：MVP-0 最小连接器契约

- **状态**：Accepted
- **日期**：2026-08
- **关联**：[工作流规范](../03-规范与术语/01-工作流规范.md)、[Harness Design](../../harness-design/README.md)

## 当前适用边界

本 ADR 记录 Connector 配置与凭证边界的决策。下文的 MVP-0 Provider 清单只保留当时范围，不作为当前 Runtime 或 SDK 的交付清单；当前调用治理与宿主适配边界见 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md#14-agent-runtime-sdk-交付边界) 和 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#76-sdk-ports-与适配器责任)，实施范围见 [Harness 06](../../harness-design/06-MVP-0技术底座实施方案.md)。

## 背景

Tool 需要调用机构业务系统，Workflow 只能通过已声明的 ToolCallNode 使用 Tool。若 MVP-0 直接在节点中硬编码 HTTP 地址和凭证，后续无法统一权限、审计、幂等和替换 Provider。

## 决策

MVP-0 建立最小 Connector 边界：

- ConnectorInstance 自包含连接协议、执行器、配置 schema、租户配置和加密凭证；
- ToolDeployment 把已发布 ToolVersion 绑定到 ConnectorInstance 或其他显式 Provider；
- Provider 执行实际外部调用；Mock 只能作为测试环境的 `TEST_MOCK` Deployment；
- Workflow 使用类型化 Tool capability requirement 声明能力槽，安装时解析到精确 ToolVersion/ToolDeployment；
- 凭证不进入 Workflow 配置、模型请求、事件或日志。

Connector 作为 Tool 的提供方接入 Capability Runtime。调用前仍需通过 Scope、InvocationPolicy、PolicyChain、配额和外部副作用幂等检查。

## MVP-0 范围

- 支持显式 TEST_MOCK 与 Connector-backed HTTP Provider；
- 校验 Tool capability requirement、ToolDeployment 与 ConnectorInstance；
- 应用层加密静态凭证；
- 基础超时、重试边界和审计；
- 拒绝生产 URL 或 API Key 写入 Workflow 包。

MVP-0 不交付 MCP/gRPC/DB Provider、厂商自助市场、动态凭证系统或完整健康运营界面。

## 后续演进

后续阶段可以增加 Provider 类型、密钥系统和市场治理，但不得改变 Workflow capability 语义。Agent 和 Workflow 只能调用 ToolPortal/类型化能力槽，不能直接调用 Connector；Connector Provider 也必须经过 PolicyChain 与 ExternalInvocationGuard，凭证只在 Provider 边界解析。

## 后果

- Workflow 包保持 Provider 无关；测试与生产通过显式 ToolDeployment 绑定不同 Provider。
- 外部副作用获得稳定的权限、审计和幂等边界。
- 新 Provider 通过能力定义和契约测试接入，不修改 Kernel。
