# ADR-001：身份与多租户隔离

- **状态**：Accepted（2026-08-04 修订）
- **日期**：2026-08-03
- **决策者**：架构组
- **关联**：数据模型设计、非功能需求、技术栈与风险评估

## 背景

原方案依赖 Keycloak Organizations + 共享 SaaS Realm。实际交付收敛为「应用内身份」，仅保留 PostgreSQL / Redis / Elasticsearch 为独立基础设施。

## 决策

**默认采用应用内 JWT + 租户成员 RBAC：**

| 场景 | 方案 |
| :--- | :--- |
| **默认（绝大多数租户）** | 服务端 [ScopedJwtLogic](../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/security/ScopedJwtLogic.java) 签发并验证 access JWT；登录身份使用 Sa-Token 的登录 ID，[AuthService](../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/application/AuthService.java) 写入 `tenant_id`、`role` 等扩展声明，并校验 `iss`、`aud`、标准 `exp` 及服务端登录状态。refresh token 的随机部分由 32 字节 `SecureRandom` 生成并编码为 URL-safe Base64，不是 JWT。 |
| **企业强隔离** | 可选专属部署（On-Prem / Hybrid）；身份仍由应用内账号体系管理 |
| **平台内部员工** | 独立 `platform_members` 账号体系（2026-08-05 起），与客户租户隔离 |

## 平台运营账号体系（2026-08-05 修订）

平台运营后台与机构管理后台不再共用同一账号体系：

- 平台运营账号独立存储于 `platform_members` 表（无 `tenant_id`，不启用租户 RLS），
  登录接口为 `/api/v1/platform/auth/login|refresh|me`，不再要求 `tenant_slug`。
- 平台 JWT 与机构 JWT 完全隔离：平台服务使用独立 `token-name`（`X-Platform-Token`）、
  独立签名密钥（`PLATFORM_SECRET_KEY`）与独立 issuer/audience，两侧令牌互不识别。
- 平台运营后台通过 `/api/v1/admin/tenants` 承担机构账号全生命周期管理：
  创建机构与初始管理员、成员增查改、停用/启用、重置密码、机构停用/启用；
  机构自助注册 `/api/v1/auth/register` 已关闭。
- 平台服务使用独立数据库角色 `skillforge_platform`（`BYPASSRLS`）执行跨租户读取；
  机构服务继续使用 `skillforge` 并依赖 RLS 保持租户隔离。平台侧写入租户表前，
  先绑定目标租户上下文（`TenantContext.setTenantId`）复用既有 RLS 策略。

**应用数据隔离由以下三层强制：**

1. PostgreSQL RLS + 请求事务 `SET LOCAL app.tenant_id`
2. Redis key 命名空间 `{tenant_id}:...`
3. 向量 / Elasticsearch 检索强制 `tenant_id` 过滤

access JWT 由 `ScopedJwtLogic` 负责签名和验证；验证除签名外必须核对 `iss`、`aud`、标准 `exp` 与服务端登录状态。refresh token 按当前轮换与撤销流程处理：机构端使用 `<tenant_id>.<随机部分>`，平台端直接使用随机部分；租户前缀仅用于定位 Redis 命名空间，不能作为认证凭据。明文只在签发响应中返回，Redis 键保存随机部分的 hash，值映射成员身份，刷新时仍需核对成员归属。客户端将 refresh 作为完整凭据保存与回传，不解析为 JWT 或据此前缀授予权限。

**C 端终端身份**按「租户 + 渠道作用域」建模，**禁止**全局 `wechat_openid` 唯一约束。管理 API **禁止**仅凭裸 `X-Tenant-ID` 鉴权；开发态可有明确开关，生产关闭。

## 后果

- 任务 2.11.x 改为「内置身份与 JWT 验签」，不再部署 Keycloak。
- Token 必须校验签名、issuer、audience、标准 exp 和服务端登录状态；refresh token 轮换与撤销沿用 `AuthService`。
- 渠道访问使用 `X-Channel-Token`（哈希入库，明文仅创建时返回一次）。

## 不做的事

- 不自研 OAuth 联盟协议全集；需要时可对接外部 IdP 作为后续扩展。
- 不把 JWT claim 当作数据隔离的唯一手段。
