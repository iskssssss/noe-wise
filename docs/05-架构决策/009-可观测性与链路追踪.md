# ADR-009：可观测性与链路追踪

> **状态**：Accepted · **日期**：2026-08-05 · **Owner**：架构

## 当前适用边界

下文保留 2026-08-05 的 RequestContext、X-Trace-Id 与日志方案。它不定义当前 Runtime 的身份、异步上下文、业务因果、用量归因或审计事实源；这些边界由 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#510-端到端轨迹与用量契约) 接管，日志字段与脱敏规范见 [工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md#事务日志与可观测性)。旧 UUID trace_id 不能替代 W3C traceId 或 rootInputId/rootOperationId。

2026-10-24 起，机构和平台宿主的日志编码统一采用 Spring Boot 3.5 原生 Logstash JSON，取代下文手工 Pattern 编码及专用 XML。当前装配与运维入口见[开发与部署指南](../04-指南与运维/01-开发与部署指南.md#53-本地启动)；请求关联字段与秘密记录边界继续由上述工程规范定义。

## 背景

线上问题定位依赖请求级上下文；日志需要跨服务、跨模块关联，
并按租户/用户/功能归因成本。此前日志为纯文本，缺少统一追踪 ID 与业务上下文。

## 决策

- 新增 `RequestContext` 线程本地对象，贯穿 trace_id、tenant_id、user_id、module，
  并在入口过滤器与租户拦截器中同步到 SLF4J MDC。
- 新增 `TraceIdFilter`：请求入口读取 `X-Trace-Id`，缺失时生成 UUID，
  请求结束统一清理线程上下文，防止线程池串号。
- 日志输出改为 JSON 风格结构行，固定携带 trace_id / tenant_id / user_id / module / action。
- 关键路径（认证、对话、知识库）以结构化日志记录业务事件，便于产品与运维阅读。

## 权衡

- 日志可读性略降，但换取检索与关联能力；统一格式由 logback-spring.xml 集中维护。
- 不引入额外依赖，JSON 编码用 Logback Pattern 实现，后续可平滑替换为 Logstash Encoder。
