# ADR-011：配置分层与就近主权

> **状态**：Accepted · **日期**：2026-08-05 · **Owner**：架构

## 当前适用边界

下文保留当时的分层目标和实现设想，不代表当前存在统一的 `ConfigService`、`settings.resource_flags` 或 `scope_resource_bindings`。当前功能授权由[功能目录与机构覆盖](../02-架构与设计/19-SaaS基础底座设计.md#23-租户功能和资源配额)及其 `FeatureGate` 实现；各业务配置的默认值和覆盖关系由所属服务定义，不能推定全站都具有实体级覆盖。Runtime 的 InvocationContext、Capability Scope 与版本冻结以 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#54-类型化-capability-契约与挂载快照)、[Harness 03](../../harness-design/03-核心对象模型与状态机.md#510-端到端轨迹与用量契约) 与 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#75-agent-runtime-sdk-façade)为准。

## 背景

多租户系统需要在不重启、不影响全局的前提下为单租户或单实体调整功能开关；
权限与身份上下文也需要贯穿到深层业务逻辑。

## 决策

- 新增 `ConfigService`：按“平台默认 → 租户覆盖 → 实体覆盖”三层解析功能开关，
  业务代码只请求当前生效值，不感知配置来源。
- 租户 `settings.flags` 提供租户级覆盖，`settings.resource_flags` 支持
  `{resource_type: {resource_id: {...}}}` 实体级覆盖。
- `RequestContext` 作为统一上下文对象贯穿请求，禁止深层业务自行查询当前用户。
- 资源级授权通过 Scope 绑定（`scope_resource_bindings`）表达
  “操作 + 资源类型 + 资源标识”的粒度，为精细治理预留扩展点。

## 权衡

- 三层覆盖增加配置读取路径，换取无重启的按实体调优能力；
- 实体级覆盖以租户 settings 承载，实体规模较大时应迁移到独立配置表。
