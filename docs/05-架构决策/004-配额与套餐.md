# ADR-004：配额与套餐真相源

- **状态**：Accepted
- **日期**：2026-08-03
- **决策者**：产品 + 架构
- **关联**：非功能需求§计费、数据模型 `plans`/`tenants`、任务 2.1.5 / 3.5.x

## 背景

非功能需求写免费版「10,000 次/月、3 工作流、2 知识库」，`tenants` 表默认却是「10,000 次/日、10 工作流、5 知识库」。限流、计费、产品承诺无法统一验收。

## 决策

1. **套餐策略表 `plans` 是唯一事实源**；`tenants` 仅存 `plan_id` 与可选覆盖字段（经审批的企业定制）。
2. **统计窗口**：北京时间（`Asia/Shanghai`）自然月，租户不可配置时区。
3. **API 调用配额单位**：次/月（不是次/日）。日限流作为滥用防护单独配置（rate limit），不等于套餐配额。
4. **渠道差异**：
   - C 端（对话渠道）：配额耗尽返回 **200 + 结构化友好卡片**（非裸 429）
   - B 端管理 API / OpenAPI：返回 **HTTP 429** + `Retry-After` + 稳定 `error_code`

> **注意**：上表数值为产品草案，写入 `plans` seed 数据；商务改价不改字段结构。内部 SLO ≠ 对外 SLA。

## 2026-09-22 决策修订

系统统一使用北京时间，取消租户 `billing_timezone`；日限流、月配额与账期共享时间边界。时间契约见[全系统时间契约](../02-架构与设计/13-全系统时间契约.md)。套餐矩阵仍是商业草案，当前按量出账不收取基础费、不执行套餐额度抵扣，成本和销售应收分离；目标设计见[用量与账单](../02-架构与设计/14-用量与账单设计.md)。

## 后果

- `tenants` 删除互相冲突的硬编码默认配额，改为 `plan_id` + 可选 override。
- NFR 5.2 / 5.6 与数据模型对齐本 ADR。
- 配额检查读取 `plans`（或缓存快照），禁止各模块硬编码魔法数字。

## 不做的事

- 不在文档多处复制不同数字；变更只改本 ADR + `plans` seed。
- 不把速率限制（防滥用）与月配额（商业套餐）混为一谈。
