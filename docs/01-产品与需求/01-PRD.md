# 灵知 产品需求文档

> 本文面向产品与研发团队，定义用户目标、产品行为、分期和验收场景。产品定位、目标用户、指标与非目标以[产品概述](02-产品概述.md)为准。
> Runtime 功能编号与验收归[Harness 01][mvp]和[Harness 04][later]，状态机归[Harness 03][model]；本文不定义第二套执行契约。委派专题以[Harness 08][delegation]当前首期基线为准。

## 1. 文档范围

灵知 是面向 B 端机构的通用智能 Agent 平台。用户向 Agent 表达目标、提供材料，在同一会话中澄清问题、授权行动、获得答案或正式成果，并继续修订或跟进。Agent 根据已授权的知识、工具、技能和工作流决定如何完成任务；机构负责配置服务边界，平台负责隔离、治理和运行保障。

产品以完成用户目标为中心：对话是表达目标与协作的入口，Workflow 用于需要确定步骤和持久执行的业务过程。附件、知识检索、工具调用、产物、人工介入和委派共同服务于这个过程，不要求每条消息创建工作流或多智能体计划。Persona、关系状态和记忆支持连续服务，具体陪伴规则是可配置的产品方向。

当前处于预发布阶段。MVP-0 验收通用底座，P1 将底座产品化，P2 增强长任务与协作，P3 候选范围另行立项。目标分期与现有实现分别记录，某项能力已有局部证据不表示其所在阶段全部完成。

## 2. 核心用户旅程

### 2.1 最终用户：从目标和材料到可用结果

目标是完成咨询、研究、内容制作或机构业务办理，并知道下一步需要自己做什么。

1. 选择机构提供的 Agent，发送文字、附件或授权的已有成果引用；只有附件时，Agent 先依据可读取的真实内容概述并询问目标。
2. Agent 判断信息是否充分，按需要澄清、检索机构知识、使用工具或发起 Workflow；用户可以继续补充材料和约束。
3. 遇到需确认的行动、缺失输入或业务审批时，用户看到具体请求和相关任务；等待期间仍可继续普通对话或处理其他任务。
4. 用户查看进行中、等待、失败、取消和完成状态；对准确目标提交恢复或取消，未知外部结果保留待核实状态。
5. Agent 交付有依据的答复或已发布成果。用户预览、逐文件下载或引用指定版本，继续提出修订目标；历史版本与新版本分别可追溯。

通用会话和并行任务对应 FR-8、FR-11、FR-17、FR-18；确定性恢复对应 FR-4。附件与正式成果属于[宿主交互契约][api]和[产物设计][artifact]，不能把任务执行成功等同于成果已可下载。

### 2.2 机构建设者与运营人员：把 Agent 变成可持续服务

目标是为本机构建立可控的智能服务，并处理异常、权限、内容与成本。

1. 配置成员、权限和 Agent 的职责、人设、模型及四类能力挂载；发布可见范围和渠道部署。
2. 上传并治理机构知识，配置工具部署、凭证、授权和需确认的行动；需要确定步骤的业务使用 Workflow。
3. 在隔离测试会话中覆盖正常结果、资料不足、无权限、挂起、取消和失败，完成校验后发布不可变版本。
4. 查看真实会话、运行状态、来源、成果和费用；发现问题后定位具体运行和调用，不凭页面摘要推定底层结果。
5. 调整后发布新版本，治理记忆、数据保留和人工协助；既有运行按其已冻结版本继续处理。

能力挂载和版本约束对应 FR-5、FR-7；运营、数据和配置增强对应 FR-9、FR-10、FR-12、FR-20、FR-22。机构后台只消费受控投影，不直接操作 Workflow 内部状态。

### 2.3 平台运营方：保障机构之间的边界和运行质量

目标是提供可信、可观测且费用可解释的平台服务。

1. 管理租户、套餐、平台公共资源和可用服务，维护租户隔离与凭证安全。
2. 监控运行、外部调用、拒绝、异常和投递，区分用户任务结果、供应商响应与渠道送达。
3. 依据持久轨迹和用量核对成本、配额与待确认费用，处理追加调整和告警。
4. 对资源发布、服务变更与数据操作执行其所属验收，向机构提供可追溯的运行和审计信息。

治理基线见[非功能需求](03-非功能需求.md)、[身份与隔离 ADR](../05-架构决策/001-身份与多租户隔离.md)和[配额与套餐 ADR](../05-架构决策/004-配额与套餐.md)；轨迹费用产品化对应 FR-20。平台运营权限不能转化为用户会话的隐式执行授权。

### 2.4 开发者与集成方：扩展能力并接入完整交互

目标是提供可复用业务能力，或将 Agent 接入已有应用而保持一致的交互与治理。

1. 按规范创建 Skill、Tool、Knowledge Source 或 Workflow，声明契约、版本、输出和权限边界。
2. 配置显式部署与挂载，在隔离会话测试成功、拒绝、挂起和外部未知结果，发布版本。
3. 通过开放平台维护授权资源，将应用和机构身份绑定到会话；用户消息、附件、人工交互、控制和事件续接走公开契约。
4. 消费事件和成果，按稳定身份去重、重连与对账；需要调用外部业务系统时配置受控回环。

基础能力对应 FR-5、FR-7，应用集成和回环对应 FR-14、FR-21；Workflow 定义遵循[工作流规范](../03-规范与术语/01-工作流规范.md)。控制资源与运行会话分面授权，集成方不能直调底层 Workflow 或 Tool 绕过 Agent。

## 3. 产品功能需求

下表描述目标产品行为。阶段表示所属需求范围；验收场景须结合所引事实源实施，不能由页面存在或模型生成文案代替真实结果。

### 3.1 理解目标、使用能力并交付结果

| 用户目标 | 产品行为 | 关键约束 | 阶段与来源 | 代表性验收场景 |
| :--- | :--- | :--- | :--- | :--- |
| 连续表达和修订目标 | 同一 Agent 会话保留授权上下文，按顺序接收输入、反馈进度和最终答复 | 身份固定、重复输入不重复执行；能力与上下文按本次输入冻结 | MVP-0；[FR-8、FR-11、FR-17][mvp] | 连续追问及消息重投保持同一目标上下文；不同用户会话不串扰 |
| 用附件作为工作材料 | 支持文字加附件、纯附件以及授权的成果版本引用；资料不足时澄清 | 首次受理冻结授权材料；不可读取的内容不伪称已理解；不公开内部文件路径 | 通用消息底座属 MVP-0 FR-8；附件宿主切片按[交互契约][api]验收 | 纯文本附件触发真实内容概述；跨会话或已撤权材料被拒；重试不改变材料选择 |
| 获得有依据的答案 | Agent 根据任务选择知识模式与已授权来源，说明证据和不足，决定继续、澄清或停止 | 知识层不替 Agent 回复；检索空结果不伪造证据；写回只能提出受治理提案 | MVP-0 [FR-7][mvp]；P1 多源研究 [FR-19][later] | 资料充分、空结果、来源冲突和撤权分别产生可解释结果，不能引用未授权来源 |
| 完成需要行动的工作 | 按授权挂载调用工具与技能；确定步骤、持久业务状态和补偿由 Workflow 承载 | 只使用已挂载能力；副作用遵守确认与幂等；未知结果不盲目重试 | MVP-0；[FR-1、FR-2、FR-5、FR-7、FR-11][mvp] | 授权工具完成真实操作；缺能力或拒绝确认时不执行；超预算有明确停止反馈 |
| 获得并继续修订成果 | 展示正式成果、版本、预览和逐文件下载，允许选择已有版本作为后续材料或修订基础 | 执行结果、候选文件、工作区与正式发布成果分别表达；交付失败不展示可用成果 | Runtime 输出对应 MVP-0 FR-2/FR-3；正式成果宿主切片见[产物设计][artifact] | 多文件全部交付；下载授权与文件一致；修订生成新版本并保留旧引用；执行成功但交付失败可见 |

### 3.2 人工协作、任务控制与专业分工

| 用户目标 | 产品行为 | 关键约束 | 阶段与来源 | 代表性验收场景 |
| :--- | :--- | :--- | :--- | :--- |
| 在需要时补充或批准 | 显示具体问题、可选动作与所属任务；输入、点选、回调或超时准确恢复 | Workflow HITL、Agent 确认和 Tool 输入等待按各自契约恢复；人工协助不自动授权工具或证明完成 | MVP-0 [FR-4、FR-7][mvp]；P1 [FR-12][later]及[人工协助契约][api] | 两个任务同时等待时只恢复目标；重复或过期回复不重复副作用 |
| 等任务时继续工作 | 持续显示前后台任务，允许继续对话或发起另一个任务，按序接收结果 | Session 活动与单个任务状态分离；一个任务终态不终止整个会话事件流 | MVP-0 [FR-18][mvp]；P1 [FR-12][later] | 一个任务等待、另一个后台完成，用户仍能对话；重启后活动清单可重建 |
| 停止或恢复可控任务 | 对明确目标查询、取消和恢复，反馈请求受理及最终收敛结果 | 取消受理不是已撤销；已发生或未知外部副作用如实披露；通用任意节点续跑后置 | MVP-0 [FR-4、FR-18][mvp]；P2 [FR-13][later] | 重复取消幂等；回调与人工恢复竞争只推进一次；不能安全恢复时不静默重放 |
| 由专业 Agent 协作完成复杂目标 | 主助手在自身授权名单中直接委派或提交可选结构化计划，等待、补充、取消并整合结果 | 子 Agent 使用自身能力与独立会话，首期为不能继续委派的叶子执行者；普通消息不强制建 DAG | P2 FR-15；具体基线以[Harness 08][delegation]为准 | 范围外目标拒绝；父助手只收安全结果；等待后精确恢复，撤权仍允许必要收尾 |
| 查看计划并调整后续工作 | Todo 作为计划的可勾选视图；可调整未执行项，成果与执行结果关联 | 勾选不伪造执行完成，不回滚已发生的副作用 | P2 [FR-16][later] | 更改未执行项并保留日志；已执行项与真实结果一致，不能靠勾选重写结果 |

FR-15 的阶段归属仍为 P2。首期委派范围不包含递归链、深度与环协议或父子预算分割；相关旧表述不能作为恢复这些承诺的依据。首期名单、直接委派、结构化计划与主子生命周期按 Harness 08 验收。

### 3.3 机构服务与平台治理

| 用户目标 | 产品行为 | 关键约束 | 阶段与来源 | 代表性验收场景 |
| :--- | :--- | :--- | :--- | :--- |
| 发布可信的 Agent 服务 | 管理 Agent 职责、人设、能力、渠道和发布版本，提供隔离测试及 Problems 定位 | 草稿、校验、发布、部署与真实测试分别表达；四类能力之外的对象不注册为 Capability | MVP-0 [FR-5、FR-7、FR-17][mvp]；P1/P2 [FR-22][later] | 未发布或不合法资源不能挂载；配置更新不改变已冻结运行；测试不走旁路 |
| 治理持续服务数据 | 提供记忆来源与纠正、保留、导出、删除及会话生命周期操作 | 按租户、用户和 Agent 隔离；具体关系规则由产品 schema 定义 | MVP-0 FR-17 底座；P1 [FR-9、FR-10][later]；P2 高级记忆增量按路线图待明确说明 | 更正有来源的记忆；删除、保留及关闭会话按授权边界执行，跨租户访问拒绝 |
| 解释过程和费用 | 从会话、执行、调用、用量与审计事实展示目标相关轨迹、结果及成本 | 技术尝试与业务因果分别追踪；未知费用不当零；投影和遥测不取代权威账本 | MVP-0 [FR-3、FR-11、FR-18][mvp]基础记录；P1 [FR-20][later] | 定位一次失败及每个计费调用；供应商补报追加调整；日志导出故障不改变业务事实 |
| 接入机构业务与渠道 | 管理授权资源、知识摄取、完整会话交互、回环及事件续接 | 入站回调与出站投递分别治理；不同机构权限、费用与外部映射隔离 | P1 [FR-14、FR-21][later] | 第三方发起、补充、恢复和取消完整闭环；事件重投不重复业务；错机构请求拒绝 |
| 主动服务但可退出 | 在明确授权下配置触达、频控、安静时段、退订及审计 | Trigger 仅提供底座事件入口，触达产品规则不由 Runtime 默认推导 | MVP-0 FR-17 Trigger 底座；P1 [后续阶段需求][later] | 退订或安静时段阻止不合规触达，仍保留可核实审计 |

机构从人工服务记录沉淀话术与风格、生成可编辑回复建议的专项需求见[会话话术与风格学习需求](05-会话话术与风格学习需求.md)。该专题单独定义产品验收，不将个人记忆或历史聊天保存视为学习闭环；技术方案见[相关设计](../02-架构与设计/22-会话话术与风格学习设计.md)。

## 4. Agent Runtime 产品约束

产品旅程统一进入 Agent 会话。知识、工具、技能和 Workflow 是可挂载业务能力；模型与 Connector 配置、记忆、渠道、委派、Builder、Marketplace、计费和观测分别属于其既有边界。Agent 负责理解目标与决策，Workflow 拥有确定执行状态，客户端只消费受控投影。

资源维护 API 不构造隐式对话，用户运行不绕过统一准入与策略。授权、幂等、事实源、状态和恢复以[Harness 02][architecture]、[Harness 03][model]及[宿主交互契约][api]为准。产品界面应让用户区分材料已提交、任务已受理、执行已完成、成果已发布和消息已送达。

## 5. 阶段范围

| 阶段 | 用户可获得的目标结果 | 主要边界 |
| :--- | :--- | :--- |
| MVP-0 | 在持续会话中使用授权能力完成目标，等待时继续工作，并准确恢复和接收结果 | Stateful Agent 与 Multi-Execution 两项底座；Gate 0、M1–M7 及两个指定真实纵向样例 |
| P1 | 机构能配置、治理、运营并集成智能服务，用户可解释来源、任务与费用 | 记忆与会话治理、知识研究、任务交互、回环、开放平台、观测费用、基础 Builder/Handoff |
| P2 | 用户能持续推进复杂长任务、专业委派和可调整计划 | 高级续跑与分布式韧性、首期叶子委派、Todo、Fork、高级记忆和完整生产工具 |
| P3 | 按独立立项结果获取动态插件和生态能力 | 动态安装、热更新、跨进程隔离、生态与对等多智能体候选，不作当前承诺 |

各阶段依赖、验收出口与不包含范围见[实施路线图](04-实施路线图.md)。附件、工作区和正式成果的已交付切片单独验收，不为其虚构新的 Runtime 阶段或 FR 编号。

## 6. 验收原则

产品验收从目标、行动、反馈和结果验证完整旅程，包含正常路径、权限拒绝、资料不足、等待恢复、取消、重投与未知外部结果。多轮对话不能只检查答复文本；需要行动的目标须验证实际业务回执，成果目标须验证正式版本、授权和文件可用性。

MVP-0 的两个指定纵向样例和 Runtime 退出条件仍以[Harness 06][implementation]为准；FR 验收按其所属需求执行。组件测试、API 测试、真实渠道、浏览器体验和生产效果分别说明证据边界。内部演示或实现 Note 不替代完整阶段退出。

### 6.1 验收对象与设计入口

正式成果按[交付设计](../02-架构与设计/12-代码执行沙箱与产物交付.md)核验不可变版本、来源、逐文件交付、权限与清理；持续项目材料核验显式挂载、持久读写和备份恢复；专业协作按[委派契约](../../harness-design/08-Agent委派与多智能体运行时.md)核验父子生命周期、授权及交接。

上述文档定义验收对象，不提供运行结果。实现状态以当前源码和针对具体候选执行的验证为准，版本、环境与未执行范围分别记录。
