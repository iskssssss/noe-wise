# 会话话术与风格学习需求

> 本文定义以口腔接待为首个场景的产品目标、用户行为和验收要求。当前为待实施方案，文档落地不代表功能已实现。宿主实现见[技术设计](../02-架构与设计/22-会话话术与风格学习设计.md)，实验方法见[效果评估](../06-评估与方案/02-会话学习效果评估.md)；功能实现和场景效果需按对应版本独立验收。

## 1. 产品目标与首期范围

患者先与机构服务人员聊天，消息保存为本系统的会话事实。机构选择可信的人工服务记录，系统从中整理可复用的话术示例和表达风格，经审核、评估和发布后，Agent 在新患者咨询时生成符合机构服务方式的回复建议。服务人员可以编辑并发送，修改反馈用于后续改进。

首期交付终点是“指定人员的优秀对话形成可追溯的话术与风格版本，并用于新会话中的人工辅助回复”。首期覆盖文字对话、单机构授权来源、一个 Agent 绑定一套发布风格；同一机构可分别配置机构风格和指定人员风格的 Agent。口腔场景规则由机构配置和知识提供，不固化进通用 Runtime。

自动回复、多人风格资源独立共享和模型微调属于后续条件范围。完整坐席队列、转派和 SLA 属于后续运营能力，本功能只补齐自身需要的纯人工接待、建议回复和反馈入口。不建设跨机构共享训练集，不将联邦学习或新的 Agent 执行框架作为前置。

## 2. 学习对象与服务边界

| 对象 | 内容示例 | 产品用途 |
|---|---|---|
| 场景话术 | 回应费用疑问、澄清治疗顾虑、解释预约流程的连续对话示例 | 为相似情境提供沟通方法和表达参考 |
| 表达风格 | 称呼、语气、句式、回复长度、提问节奏、安抚方式 | 指导绑定 Agent 组织回复 |
| 当前业务知识 | 价格政策、预约规则、医生排班、经确认的服务与医疗说明 | 提供当前回复的事实依据，不由历史话术自动覆盖 |
| 患者个人记忆 | 当前患者允许保存的沟通偏好和服务需求 | 在该患者的授权范围内提供连续服务 |
| 人工反馈 | 建议回复与最终回复的关联、修改原因、采纳情况 | 识别下一轮需要改进的内容，不直接成为正确答案 |

学习服务人员与记住患者分别治理。患者明确提出的语气、长短等当前沟通要求，可以覆盖一般风格偏好，但不能改变事实、医疗边界或业务操作权限。AI 使用指定人员的风格时仍显示 AI 身份，不能标记为该人员亲自发送。

历史示例不能自动提供当前报价、排班、诊断或疗效保证。机构定义的医疗服务范围和经确认知识约束回复内容；信息不足或超出服务范围时，Agent 澄清问题或交由人工处理。

## 3. 用户旅程

### 3.1 患者与服务人员接待

1. 患者和服务人员进入同一产品会话，系统保留真实作者、消息顺序、来源和必要版本。
2. 纯人工模式只记录与投递消息；切换为辅助模式后，服务人员可以请求 Agent 生成建议。保存消息本身不等于触发 AI 回复。
3. 服务人员查看、编辑、发送或放弃建议。建议内容保持内部可见，正式发送后才成为患者可见消息。
4. 系统保留建议与人工最终回复的关联；连接恢复和重复提交不会重复发送。

### 3.2 机构配置学习来源

机构建设者选择目标 Agent、允许学习的服务人员、会话范围、时间范围和业务场景。首期优先使用人工标记的优秀会话；普通会话的自动候选筛选可以后续启用。读取会话的权限不自动授予学习、导出或跨患者复用权限。

学习范围、后台任务状态、预算消耗和来源不可用原因可查询。历史消息只有 `user/assistant` 而无法确认真实作者时，显示“来源待确认”，不能自动把助手消息当作人工示范。

### 3.3 负责人审核与发布

负责人查看候选的场景、必要上下文、回复示例、风格规则及支持来源，完成修改、合并、批准或拒绝。原始会话详情仍按当前权限读取；只读候选不扩大原会话访问权。

界面分别呈现候选生成、审核结果、知识发布与索引就绪、Agent 采用版本。已批准但尚未发布或未被 Agent 采用的内容，不能展示为线上生效。发布前可对同一组输入比较当前版本与候选版本，发布后可以切回仍有效的历史版本。

### 3.4 持续改进与退出

服务人员可以标注“太长”“语气不合适”“事实错误”“缺少追问”等反馈。负责人查看不同场景与来源人员的效果，选择下一批学习范围。AI 原样建议、未经确认的修改和成交结果不会自动升级为优质示例。

机构可以停用学习来源、话术或风格版本。撤销学习资格与删除原始记录是不同操作；系统展示受影响的派生内容，并按[技术设计的撤销规则](../02-架构与设计/22-会话话术与风格学习设计.md#6-权限来源撤销与保留)阻止后续使用、处理派生材料。

## 4. 首期界面

| 入口 | 必要能力 | 状态和反馈 |
|---|---|---|
| Agent 学习设置 | 来源选择、目标风格、范围与学习任务入口 | 当前生效版本、进行中任务、预算和失败原因 |
| 话术与风格审核 | 脱敏候选、授权来源、差异、编辑和审核 | 待审核、已批准、已拒绝、发布与采用状态分别显示 |
| 人工接待工作台 | 纯人工与辅助模式、建议预览、编辑发送、放弃和反馈 | 生成状态、发送回执、冲突与重试结果 |
| 效果对比 | 相同输入下的版本比较、分场景评分、人工修改与运行成本 | 样本范围、数据版本、未执行项及适用限制 |

界面复用[后台交互规范](../03-规范与术语/05-后台系统交互规范.md)与[UI 技能](../../.agents/skills/nw-ui-ux/SKILL.md)。具体控件和 API 在所属批次设计与实现，不把本表当成现有页面说明。

## 5. 产品验收要求

以下编号拥有本专题的业务验收语义，不替代 Harness FR 或 Runtime 状态机。工程证据与模型效果分别验收，覆盖方法见[评估方案](../06-评估与方案/02-会话学习效果评估.md#4-效果评估方法)，技术范围见[相关设计](../02-架构与设计/22-会话话术与风格学习设计.md)。

| 编号 | 验收要求 |
|---|---|
| CL-01 | 纯人工接待可完整记录真实作者与有序对话，不自动调用模型；无法确认作者的记录不能进入人工示例集 |
| CL-02 | 学习、审核、发布和导出分别检查当前权限；跨机构、越范围与撤权请求被拒绝且无新增副作用 |
| CL-03 | 片段保留回答之前必要上下文；后续反馈只参与评价；脱敏后无不必要的患者标识，仍能理解适用场景 |
| CL-04 | 话术和风格候选均有可核验来源、使用条件和独立审核结果；知识事实与个人记忆不被混入机构风格 |
| CL-05 | 发布、索引就绪和 Agent 采用可区分；新调用使用适用版本，在途执行按冻结事实恢复，撤销内容不被再次披露 |
| CL-06 | 新会话按当前问题与前文选取适用示例；没有合适示例时仍能依据有效知识回答、澄清或转人工 |
| CL-07 | 回复建议在人工发送前不对患者公开；人工修改、重连和重复提交保留准确回执及作者，不重复发送 |
| CL-08 | 建议、最终回复和修改原因可以关联；反馈不直接自动发布，获得新信息后的修改不会伪装成旧输入下的更优答案 |
| CL-09 | 来源撤销可追踪至候选、知识、风格、评估材料及索引；阻止后续使用并按保留规则处理派生内容 |
| CL-10 | 独立测试集中的风格与人工可用性相对基线改善，事实准确性不降低；无越权披露及新增无依据医疗承诺；有限样本不宣称生产零风险 |
| CL-11 | 真实链路的延迟、用量、失败与未知结果可核对；后台学习遵守独立配额，不挤占已约定的在线服务预算 |
| CL-12 | 自动回复和微调按独立场景评估后启用；人工接管条件明确，AI 身份可辨，易变事实继续从当前知识和业务工具获取 |

## 6. 场景示例

患者说“想了解种牙，但是有点怕疼”，服务人员先表示理解，再询问主要担心治疗过程还是恢复过程。可学习的策略是“回应情绪、澄清具体顾虑、一次集中问一个问题”；不由这段话推断具体治疗方案或无痛保证。

另一个患者说“一直不敢去看牙”时，Agent 应结合当前对话组织新的回应。评估关注沟通方式是否迁移成功、必要事实是否准确，不以复制原句的相似度作为主要成功指标。
