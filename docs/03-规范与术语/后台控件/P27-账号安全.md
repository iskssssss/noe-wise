# P27 账号安全逐控件规格

本页承接[P26–P32 共同原子合同](../06-后台逐控件规格.md#基础页面共同原子合同)，状态与证据归[验收索引](../../08-数据与工具/ui-acceptance-index.json)。平台/机构入口为 `/platform/foundation/security`、`/admin/foundation/security`；登录挑战和邮件恢复由 P18 登录页消费，不新增独立登录路由。

页面来源为 [SecuritySettingsPage.vue](../../../frontend-shared/src/foundation/security/SecuritySettingsPage.vue)、[SecurityChallenge.vue](../../../frontend-shared/src/foundation/security/SecurityChallenge.vue)、[AccountRecovery.vue](../../../frontend-shared/src/foundation/security/AccountRecovery.vue)，传输合同见 [security/api.ts](../../../frontend-shared/src/foundation/security/api.ts)，权威身份与敏感动作条件见 [FoundationSecurityService](../../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/security/FoundationSecurityService.java)、[FoundationSecurityController](../../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/security/FoundationSecurityController.java) 与 [FoundationSecurityInterceptor](../../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/security/FoundationSecurityInterceptor.java)。宿主注入 auth 与 `foundation/security` 客户端，组件不另取 JWT；二次验证后的轮换凭据交由宿主 store 接收并重读 me。

MFA 默认关闭；只有机构显式开启全员策略或账号自愿绑定才要求挑战。enrollment/challenge/full 是身份强度，未完成者不能进入普通基础管理 API。种子与恢复码只在当次组件内交付；密码保持原文，至少 12 字符、含字母数字、UTF-8 最多 72 字节；服务端是最终校验权威。政策、设备和成员管理仍需各自实时权限及敏感操作证明，不以 security.self 扩大管理范围。

## 稳定对象合同

| 编号 | 对象与文案/组件 | 数据、触发与权限 | 状态、异常与恢复 | 具体验收断言 |
| --- | --- | --- | --- | --- |
| P27-C01 | “账号与安全”标题、页内错误与成功提示 | h1、ElAlert；load 读取当前安全状态；act 的成功与错误分别显示 | 状态未读成功不显示假设备；busy 防重；公开错误不包含秘密 | 状态读取失败可识别；操作成功后读失败不引导重放写入 |
| P27-C02 | 二次验证状态卡 | enabled/required/mfa_state/recovery_codes_remaining；“已绑定/未绑定”“必须/自愿启用” | 0 恢复码是 0；不根据角色推定 MFA 已启用 | 默认策略关闭正常登录为 full；账号自愿绑定仍需挑战 |
| P27-C03 | 绑定/挑战标题与帮助 | SecurityChallenge.state 为 enrollment 或 challenge | 绑定文案与挑战文案分开；无私有密钥时不显示伪码 | challenge 不能创建新的种子绕过既有绑定 |
| P27-C04 | 创建验证器密钥按钮 | authApi.enroll；只 enrollment 且无 secret 显示 | busy 加载；种子只当前组件持有，失败不伪造成功 | 一次生成只一请求；网络失败不显示种子或“已绑定” |
| P27-C05 | 一次性绑定密钥只读输入 | enroll 返回 secret；readonly；不写 Web Storage | 密钥展示按当次交付，绑定成功清空 | 查询后不能重读种子；关闭/身份退出后秘密不可见 |
| P27-C06 | “在验证器应用中打开”链接 | enroll 返回 otpauth_uri，不由用户拼接账户域 | 原生链接；不自动触发外部应用；无 uri 时不出现 | URI 对应当次种子，不把它发给其他账户 |
| P27-C07 | 验证码或恢复码输入 | trim 后 code，maxlength 128；autocomplete=one-time-code；服务端验证 TOTP/单次恢复码 | busy 禁用；错误保持可修正；组合输入不误提交 | 错码不升级 full；恢复码重复使用拒绝；密码不受此 trim 规则影响 |
| P27-C08 | 验证按钮 | enrollment 调 enable，challenge 调 verify；未生成密钥的 enrollment 禁用 | 防重；成功清 code；enable 先交付恢复码再进入完整会话 | 正确挑战轮换会话凭据并 fetchMe；不能保留旧弱身份权限 |
| P27-C09 | 恢复码一次性交付告警与正文 | enable 返回 recovery_codes；纯文本 pre；每码一次 | 不可后续读取、不缓存；代码块可换行 | 离开后无法查看；日志、URL 和 storage 无恢复码 |
| P27-C10 | “已保存，继续登录”按钮 | 有 pending authentication 才 emit complete；清恢复码和临时认证值 | 不重复交付秘密；宿主接收后重读身份 | 确认之前仍展示恢复码，之后 DOM 不含旧码 |
| P27-C11 | 敏感操作二次验证输入 | 已绑定状态；proof 为 TOTP 或未使用恢复码 | 错误保留；success 清 proof；不保存五分钟计时到本地伪授权 | 服务端敏感证明过期后仍拒绝写；刷新不延长权限 |
| P27-C12 | “验证，授权敏感操作五分钟”按钮 | authApi.verify；令牌交宿主 onAuthentication | busy 防重；真实 verified_at 由服务端裁定 | 会话轮换正确，旧 proof 不重用，失败不显示授权成功 |
| P27-C13 | “关闭自愿绑定”按钮 | enabled 且 !required；authApi.disable；成功退出宿主 | 必须满足当前敏感证明；强制策略无此操作 | 必须绑定账号不能关闭；关闭撤销旧设备并要求重新登录 |
| P27-C14 | 重新生成恢复码按钮 | api.regenerateCodes；已有绑定，服务端敏感证明 | 旧码失效；新码只当次交付 | 未验证拒绝；成功新码可用、旧码拒绝 |
| P27-C15 | 新恢复码告警/正文与“已保存，隐藏” | 新 codes 非空显示；hide 清内存数组 | 不把查询状态当可恢复的秘密 | 隐藏后 DOM 不含新码，接口列表从不回显 |
| P27-C16 | 登录设备表及设备列 | 仅 full 状态 GET sessions；SecurityDevice.device_label | 列表无 access/refresh token；空设备不等于读取失败 | 不出现其他账号/体系设备，长标签可读 |
| P27-C17 | 设备登录时间列 | SecurityDevice.created_at，服务端时刻 | 显示与时间契约一致；无客户端伪时间 | 时间值来自返回，不因列表刷新改为当前时间 |
| P27-C18 | 当前/其他设备列 | SecurityDevice.current | 状态不根据行顺序推定 | 当前设备准确标识，其他设备仍可单独撤销 |
| P27-C19 | 本人设备撤销按钮 | POST sessions/revoke，session_id:string；当前设备成功 onLogout | busy 禁用；撤销精确身份；成功不可继续使用旧设备凭据 | 撤销其他设备不误退出当前；撤销当前后后台与 WS 失权 |
| P27-C20 | 机构安全策略标题与说明 | policy.manage 才显示；GET policy 返回 require_all_mfa | 说明“默认关闭”，启用与自愿绑定边界清楚 | 平台/机构体系政策不串用；无权不加载管理政策 |
| P27-C21 | 全员 MFA 复选框 | require_all_mfa:boolean，来自当前机构政策 | 不接受客户端 tenant_id；改值未保存不生效 | 取消/只改勾选不创建强制政策 |
| P27-C22 | 保存策略按钮 | api.setPolicy(all)，policy.manage + 敏感证明 | busy 防重，服务器成功才生效 | 开启后未绑定成员进入 enrollment；关闭不取消既有自愿 MFA |
| P27-C23 | 成员安全管理卡及成员 ID 输入 | invitation.manage/session.manage/mfa.manage 任一显示；memberId 为十进制字符串 | 无 ID 按钮禁用；不改为 JSON number | 大 ID 精度保持；其他机构成员被拒绝 |
| P27-C24 | 发送登记邮箱邀请按钮 | invitation.manage；api.invite(memberId) | 只受理至登记邮箱；不提供任意收件地址 | 无邮箱明确拒绝；受理不表示 SMTP 接受或已送达 |
| P27-C25 | 撤销成员全部设备按钮 | session.manage；api.revokeMember(memberId)；敏感证明 | 精确成员与同域范围；服务端设备全部失效 | 被撤销成员不能凭旧 token 继续 HTTP/WS |
| P27-C26 | 重置遗失验证器按钮 | mfa.manage；api.resetMemberMfa(memberId)；敏感证明 | 重置秘密与恢复码并撤销设备，保留强制政策 | 已强制的账号重新进入绑定，不能直接全权登录 |
| P27-C27 | 登录页“忘记密码或接受邀请”折叠区 | P18 消费 AccountRecovery；username/tenantSlug 来登录表单 | 关闭折叠不提交；无 username 恢复按钮禁用 | 登录页各宿主前缀正确，不通过 token 选择另一机构 |
| P27-C28 | 发送密码恢复邮件按钮与受理说明 | authApi.requestRecovery，登录账号/机构 slug；统一“如账号和邮箱有效…” | 防重；同响应不暴露账号/邮箱存在性 | 存在与不存在账号同公开响应，不声称邮件已送达 |
| P27-C29 | 邮件用途选择 | recovery/invitation；默认 recovery | 用途隔离；恢复凭据不得用于邀请激活 | 错用途 token 拒绝，没有降级自动改用途 |
| P27-C30 | 邮件中的一次性凭据输入 | token trim，type=password、show-password、autocomplete=off | 只内存；失败可修正；成功清除 | URL/日志/Storage 不含凭据；过期、已用、跨域拒绝 |
| P27-C31 | 新密码输入与帮助 | new_password 原文；new-password；至少 12 字符、字母数字、UTF-8≤72 字节 | 不 trim；密码失败保留，成功清空 | 中文/emoji 按 UTF-8 边界核对，不能仅按 maxlength 替代后端 |
| P27-C32 | 设置密码按钮与结果 | token/password 非空；用途决定 completeRecovery 或 activate | 防重；成功“密码已设置…已有设备已撤销”，不自动绕过 MFA 登录 | 一次性 token 只能一次；恢复后旧设备失效，既有 MFA 规则仍成立 |

## 验收边界

设备/政策/恢复等后端测试只证明相应身份、事务和凭据合同。真实邮件环境、真实验证器应用、桌面读屏、输入法、焦点、秘密展示生命周期及完整双宿主恢复流程需要各自执行证据；未执行项保持未执行，不能用默认账号登录成功代替 MFA/恢复验收。
