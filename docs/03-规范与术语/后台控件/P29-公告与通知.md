# P29 公告与通知逐控件规格

共同合同见[P26–P32](../06-后台逐控件规格.md#基础页面共同原子合同)，执行状态归[验收索引](../../08-数据与工具/ui-acceptance-index.json)。平台/机构入口为 `/platform/foundation/messaging`、`/admin/foundation/messaging`；主实现为 [MessagingPage.vue](../../../frontend-shared/src/foundation/messaging/MessagingPage.vue)，传输类型见 [messaging.ts](../../../frontend-shared/src/foundation/messaging/messaging.ts)，收件目录接线见 [FoundationPage.vue](../../../frontend-shared/src/foundation/FoundationPage.vue)。下表请求根为宿主 `foundation/messaging`。

权威边界为 [NotificationService](../../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/messaging/application/NotificationService.java)、[NotificationCommands](../../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/messaging/contract/NotificationCommands.java) 与 [FoundationRecipientDirectory](../../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/access/FoundationRecipientDirectory.java)。公告/通知受理时冻结正文与同账号体系、同租户的有效收件人；发布使用稳定 deduplication_key。SMTP“已接受”只表示邮件服务器已受理，不表示最终送达。unknown 不可盲重发；确定未接受的 blocked/rejected 才能人工重新受理。

## 稳定对象合同

| 编号 | 对象与文案/组件 | 数据、触发与权限 | 状态、异常与恢复 | 具体验收断言 |
| --- | --- | --- | --- | --- |
| P29-C01 | 页标题、SMTP 边界说明与刷新 | AdminPage“消息与公告”；刷新当前区域及获授权的 unread | 当前读取失败固定告警，可重试，旧数据不装作最新 | SMTP 接受与送达文案分开；刷新不重放发布 |
| P29-C02 | 无权限空态及读/写错误 | ElEmpty/ElAlert；当前账号无可用页签时明确说明 | task错误与resource错误分开，不输出任意秘密错误对象 | 错误消失的Toast不影响页内恢复提示 |
| P29-C03 | 五业务页签 | 我的消息inbox、公告read、通知模板/SMTP configure、投递operate | 实时权限筛选；切页签清游标；身份/权限变化清数据和草稿 | 只读账号无配置入口；旧账号写回包无新账号成功提示 |
| P29-C04 | 未读数与“只看未读”复选 | GET unread，GET inbox&unread；改条件回首游标 | 未读未知显示—，不是0 | 标记已读成功才变计数；条件变更不发写 |
| P29-C05 | 收件箱标题列 | InboxItem.title，row-key=id:string | 本人投影，纯文本 | 不包含其他成员/体系消息 |
| P29-C06 | 收件箱正文列 | InboxItem.body；溢出tooltip | 正文不解释HTML；秘密通知不进入站内正文 | 恶意HTML纯文本；安全恢复token不出现在inbox |
| P29-C07 | 接收时间列 | created_at，formatDateTime | 服务端时刻 | 展示与时间契约一致 |
| P29-C08 | 已读/未读状态列 | read_at:null/时刻 | null表示未读，不按客户端展开推定 | 刷新后依权威已读事实展示 |
| P29-C09 | 标记已读按钮 | 仅未读；inbox权限；POST read{id} | task busy禁用，写成功重读；失败不预减数 | 精确ID一次写；本人之外ID被拒绝 |
| P29-C10 | 发布公告按钮 | publish；生成当次 UUID deduplication_key，空表单基线 | 保存失败保留同键与正文，避免重复受理 | 连点不双发；网络未知按同键查证/复用 |
| P29-C11 | 公告标题列 | AnnouncementItem.title | 发布冻结值，row-key=id | 同名公告撤回仍按真实ID |
| P29-C12 | 公告正文列 | body，纯文本tooltip | 已发布正文不通过列表编辑 | 新模板或邮箱版本不改旧正文 |
| P29-C13 | 收件人数列 | recipients | 服务端冻结有效收件人数；发布时有效收件人必须为 1–10000 人 | 与同体系真实收件范围一致，不估算全租户；空收件范围拒绝发布 |
| P29-C14 | 发布状态列 | published/withdrawn 显示已发布/已撤回 | 只有权威撤回才改状态 | 请求失败不预改已撤回 |
| P29-C15 | 公告发布时间列 | created_at | 冻结时刻，不按重读更新时间替代 | 重新读取时间保持 |
| P29-C16 | 公告撤回按钮及确认 | publish且published；POST announcements/withdraw{id} | 确认说明站内隐藏、未派发取消、已SMTP接受保留；取消无写 | 账号变化确认失效；已接受投递不假撤销 |
| P29-C17 | 发布/编辑发布模板按钮 | configure；POST templates/publish，建立不可变新版本 | 新版本只影响新通知；失败保留定义 | 旧受理通知仍读取冻结模板正文 |
| P29-C18 | 模板键列 | TemplateView.key，row-key=id | 稳定业务键不等于版本ID | 同key各版本寻址正确 |
| P29-C19 | 标题模板列 | subject | 纯文本占位符，不脚本求值 | CR/LF/空字符头注入拒绝 |
| P29-C20 | 正文模板列与空态 | body；暂无模板说明安全模板首次受理初始化 | 无数据需成功读取；不把读取失败当未初始化 | 列表不含冻结邮件秘密变量 |
| P29-C21 | SMTP凭据状态说明 | credential_configured；已配置留空保持/未配置默认不发送 | 不回显密码、不提供伪清除按钮 | 查询仅元数据，密码框始终不回填 |
| P29-C22 | 启用SMTP开关与停用说明 | enabled:boolean；启用必须完整配置 | 停用暂停尚未派发，不伪取消已接受 | true/false真实传输，停用后的邮件保留真实状态 |
| P29-C23 | SMTP主机输入 | host≤256字符；启用时必填，可信主机名，无协议路径/CRLF/NUL | server校验，失败保留 | 非法主机明确拒绝，不偷改前缀 |
| P29-C24 | SMTP端口输入 | port整数1–65535；默认587 | 服务商端口，不编造连接成功 | 边界/非整数拒绝，0不作为默认 |
| P29-C25 | SMTP账号输入 | username≤256；启用必填，autocomplete=off，禁止头控制字符 | 不作为平台账号或收件地址 | 修改只发送配置字段，不换成员身份 |
| P29-C26 | SMTP新密码输入 | password只写、≤4096字符；输入空映射null保持已有密文 | type=password/new-password；成功清空；身份变化清秘密；不Web Storage | 空不清除原密码；保存迟到不回填新账号 |
| P29-C27 | 发件邮箱输入 | from_address≤256，单个已授权纯邮箱；禁止列表/头注入 | 启用需真实有效地址 | 地址格式拒绝，不能插入多收件人 |
| P29-C28 | TLS模式选择与说明 | starttls/tls；默认starttls | 强制加密并验证主机名，无明文模式 | 非允许枚举拒绝；连接真实性独立环境验证 |
| P29-C29 | SMTP保存与未保存标记 | configure；PUT mailbox完整快照；mailboxDirty才可保存 | task锁表单；写成功清密码/基线，后续读失败分开；脏稿不被刷新覆盖 | 改回基线取消dirty；失败/离开保留或确认清理 |
| P29-C30 | 投递ID列 | DeliveryItem.id:string | 不是notification_id，精确核验目标 | 重排后重试仍使用原id |
| P29-C31 | 投递状态列 | deliveryLabels映射blocked/queued/dispatching/rejected/accepted/unknown/cancelled等真实状态 | 未知枚举保留实际值；accepted不等于最终送达 | unknown仅核验，accepted无重试入口 |
| P29-C32 | 投递尝试次数列 | attempts | 0合法；不以刷新次数替代 | 实际worker次数和UI一致 |
| P29-C33 | 投递处理原因列 | error_code:string|null | 公开原因不含SMTP密码、邮件秘密正文 | 拒绝/阻塞/未知原因分别可识别 |
| P29-C34 | 投递更新时间列 | updated_at | 服务端时刻 | 核验后读返回新事实 |
| P29-C35 | 重新受理按钮及确认 | operate；仅blocked/rejected；POST deliveries/retry{id}，采用当前启用配置 | 确认期间身份变化取消；server重验状态；无盲自动重发 | accepted/unknown无入口；旧确认不得向新账号发旧ID |
| P29-C36 | 记录核验入口与警告 | operate且unknown；设置reconcileId/evidence/默认rejected | 警告先核查真实邮件服务器记录 | 仅打开表单不发写，也不改变状态 |
| P29-C37 | 核验结局选择 | accepted/rejected两种事实 | 不新增“猜测重试”；选择未提交不生效 | 保存payload为允许枚举，无队列重放 |
| P29-C38 | 核验证据输入与帮助 | evidence非空且≤1024字符；工单/服务器引用，不填写秘密 | textarea3行；错误保留证据 | 空白不提交；凭据不得进入证据/审计日志 |
| P29-C39 | 核验保存与取消 | POST deliveries/reconcile{id,status,evidence}；取消清reconcileId | busy防重，成功清证据并重读；server仅unknown可核验 | 取消无写；状态变化时拒绝而不覆盖，核验不直接发信 |
| P29-C40 | 当前条数、上一页与下一页 | inbox/announcements/deliveries limit20真实cursor；前页栈只已访问游标 | loading/无cursor禁用；改页签/条件清游标 | 不把20条称总量；回上一页请求同已应用条件 |
| P29-C41 | 发布抽屉、错误、取消与发布 | ElDrawer size="min(680px, calc(100vw - 24px))"，窄屏保留24px视口余量；不遮罩关闭；useDrawerClose脏态保护；form校验；发布前实时判权 | 提交锁表单、防重；失败保留；Esc/取消需保护与焦点恢复 | 撤权后不提交；点击快照身份/正文/幂等键一致 |
| P29-C42 | 公告标题字段 | title必填、最多240 UTF-16 code unit；站内和邮件标题 | 纯文本，头控制字符禁止；不静默截断 | 空白/上界/CRLF逐项拒绝并保留 |
| P29-C43 | 公告正文字段 | body必填纯文本；最多131072字符且UTF-8字节≤131072 | 发布后冻结；8行textarea，长文可滚动 | 字节上界与中文多字节一致；HTML不执行 |
| P29-C44 | 公告收件范围选择 | all/members/departments/roles；变范围清recipient_ids；指定目标最多 1000 项且不得重复 | 发布冻结；同体系/同租户active成员且在sender范围内，有效收件人数为 1–10000 | 跨域目标拒绝，无半受理；all不伪造所有数据库成员 |
| P29-C45 | 范围项目多选与目录加载/重试 | 非all必须非空；真实成员/部门/角色；成员远程每次最多50；收件目录需 messaging.publish 并受发送范围过滤 | 加载失败独立alert；无目录说明，不自动首选；读取世代防止旧响应覆盖 | 同名不同ID准确，切类型清旧值；无目录不提供假选项 |
| P29-C46 | 同时邮件通知开关 | email:boolean；仅登记邮箱受理；未SMTP保留blocked | 开启不代表发送完成 | 没邮箱/未SMTP与站内受理事实分开 |
| P29-C47 | 模板键字段 | key≤128字符；`[a-z][a-z0-9_.-]*` | 稳定key，新发布不可变版本 | 非法键拒绝，旧key不被重命名成另一通知 |
| P29-C48 | 标题模板字段 | subject必填≤240字符；`{{name}}`占位符，无头控制字符 | 不是脚本执行或递归求值 | 未声明/遗漏变量与头注入拒绝 |
| P29-C49 | 正文模板字段 | body必填，界限同C43 | 纯文本冻结模板版本 | 发布新版不改变旧通知 |
| P29-C50 | 必需变量字段 | 逗号分隔转string[]；最多32，`[a-z][a-z0-9_]{0,63}`、不重复、与占位符集合完全一致 | 失败保留变量草稿，不自动补名 | 重复/未用/漏声明均拒绝，不在错误中回显秘密值 |

组件故障场景见 [MessagingPage.test.ts](../../../frontend-shared/src/foundation/messaging/MessagingPage.test.ts)。站内公告主流程、SMTP真正连接/接受、unknown人工核查、模板边界、桌面键盘与完整视觉是不同证据范围；不得用站内读成功推定邮件送达或全部控件通过。
