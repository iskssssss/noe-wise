# 后台逐控件规格

> 当前后台采用单页路由与直接 Element Plus 组件。涉及应用内多标签、KeepAlive、导航右键菜单的历史细则（D37、D39–D44及对应场景）不适用当前目标；业务 Tabs 的键盘要求仍有效。旧编号用于追溯，不得沿用旧验收状态声称新实现通过。

**性质：平台后台逐控件目标规格与验收映射；与[后台系统交互规范](05-后台系统交互规范.md)配套，不记录实施进度或测试通过结论。**

## 1. 使用方式与事实边界

本文承接[后台系统交互规范](05-后台系统交互规范.md)的 A–J、P01–P20 结构和原编号，维护89条通用细则、以305条为基线继续扩展的页面子项及36个跨控件场景。实际控件绑定按页面链接到所属正文；扩展编号不得覆盖基线编号。原规范已有的规则仍然适用；不能因为本文没有重复某条原规则而删除它。

基准文档有246条带 A–J/P 编号的规则（其中226条通用规则、20条页面职责）；导航和标签右键菜单表另有15个行为，第13节有9段后端协作要求。它们与补充细则构成664条基线追踪记录；新增实际控件继续登记，当前数量以[验收索引](../08-数据与工具/ui-acceptance-index.json)的 counts 为准，不把664作为上限。

后台组件、主题、普通交互和共享边界分别以[前端视觉与交互规范](../02-架构与设计/09-前端视觉与交互规范.md)、[前端共享层设计](../02-架构与设计/08-前端共享层设计.md)、[前端组件库](../02-架构与设计/13-前端组件库.md)和[接口与事件契约](../02-架构与设计/04-接口与事件契约.md)为来源。后台基础控件采用 轻量后台公共布局与直接 Element Plus 组件；字段长度、业务枚举、接口地址、权限代码、超时预算或包大小限制仍须从实际契约逐项绑定；缺失来源的项目标记为未绑定，不能标为完成。本文件所列页面子项覆盖原文能够确定的目标对象，不冒充已经从真实路由/组件/schema穷举的全部实际控件。

**交付目标：约定范围内，UI对象无未登记项；规则无未决冲突；已发现缺陷为零（包括视觉和文案缺陷）；适用验收项全部有通过证据。有限测试不能证明一切环境和一切输入永远没有未知缺陷，因此不得把“测试通过”宣传为绝对无缺陷。**

进度、缺陷、待绑定项和证据放入独立验收台账，不写回原规范的已批准目标规则正文；职责边界见[后台系统交互规范第1节](05-后台系统交互规范.md#1-事实源与适用范围)和[第14节](05-后台系统交互规范.md#14-规则引用与验收索引)。

## 3. 每个UI对象必须填写的原子合同

对象包括静态文本、图标、按钮、链接、输入框、表格列、行、筛选、页签、菜单项、树节点、抽屉、对话框、提示、空态、状态面板和编辑器。静态对象不需要伪造“加载动作”；不适用维度写明原因。

| 合同维度 | 必须写清的内容 |
| --- | --- |
| 身份与来源 | 页面编号、区域、控件编号、真实组件/路由位置、原规则编号、事实来源版本。 |
| 位置与视觉 | 布局顺序、对齐、宽高/最小最大值的token、换行/截断、间距、图标、主题、焦点、动效。 |
| 文案 | 标题、标签、帮助、placeholder、动作、loading、成功、错误、空态、禁用原因及国际化key。 |
| 数据 | 字段路径、类型、ID语义、默认值、精度、单位、时间/时区、0/null/空字符串/未提供的区别。 |
| 可见和可用 | 角色/权限、对象状态、修订、环境、依赖加载情况，以及隐藏、禁用、只读的选择理由。 |
| 输入 | 鼠标、键盘、输入法组合、粘贴、自动填充、拖放与可访问替代。 |
| 校验 | 校验触发、必填条件、范围/长度、跨字段依赖、服务端字段路径映射、首错定位。 |
| 状态 | 正常、焦点、选中/半选/展开、加载、只读、禁用、错误、脏态的合法组合及优先级。 |
| 动作前 | 资格核验、目标ID/修订、是否确认、确认内容、快照和影响范围。 |
| 动作中 | 请求归属、防重、可中断性、锁定范围、真实进度/无进度、超时与离开行为。 |
| 动作后 | 写入成功事实、UI状态、基线、版本、相关缓存失效、列表/详情同步、焦点和滚动。 |
| 异常 | 字段错、业务拒绝、无权限、不存在、状态冲突、修订冲突、网络失败、结果未知和局部失败。 |
| 并发 | 请求乱序、连续操作、另一用户修改、多窗口、旧账号回包、旧校验和旧运行回包。 |
| 离开和恢复 | 取消、Esc、遮罩、路由、标签、刷新、浏览器退出、重新登录的行为及边界。 |
| 存储和清理 | URL/内存/会话/偏好/服务端各自存什么，账号/租户隔离，释放监听/计时器/编辑模型的时机。 |
| 可访问性 | 原生语义优先；名称/角色/状态、焦点顺序、打开/关闭落点、状态公告、拖动替代与读屏。 |
| 适配 | 桌面窗口、批准的缩放、主题、长内容、大数据、字体/资源失败和减少动效。 |
| 验收 | 前置数据、操作步骤、UI断言、网络/后端副作用断言、恢复断言、适用环境、证据位置。 |

空白合同、只有“符合通用规范”、只有截图、只有“可点击”，都不能视为定义完成。

### 3.1 状态模型应分域而不是拼成一个万能枚举

读取区域建议区分：初次加载、成功有数据、成功无数据、带旧数据刷新、带旧数据刷新失败、无权限、对象不存在、组件异常。写操作建议区分：无修改、可编辑未保存、校验不通过、提交中、确认成功、确认失败、修订冲突、结果待确认。只读、权限、可见性和版本是额外条件，不能仅靠一个loading布尔值承担全部语义。

这些是UI状态合同，不要求为了UI另建业务状态机、数据库表或全新框架；优先复用现有共享层及后端幂等/修订/错误能力。不能把某页面没有实际需求的组件强行加上。

### 3.2 原文未确定值的绑定台账

| 待绑定类别 | 需要的权威来源 | 缺失时的处置 |
| --- | --- | --- |
| 字体、尺寸、颜色、间距、层级、动效token | 前端视觉与交互规范和实际theme实现 | 按[视觉值与令牌选择](../02-架构与设计/09-前端视觉与交互规范.md#23-视觉值与令牌选择)复用或补足，不编造token键。 |
| 全量页面/路由/权限入口/共享组件消费点 | frontend-platform路由、布局、组件与权限配置 | 先清点，动态路由和仅深链页面不能遗漏。 |
| 表单字段、校验、空值、枚举与依赖 | OpenAPI、DTO、schema及直接领域设计 | 有歧义先记录决策；不得编造默认值。 |
| 包路径、编码、格式、数量、大小限制 | 能力包/导入导出契约及配置 | UI和服务端共同绑定，不凭浏览器限制推测业务限制。 |
| 角色、权限代码、账单状态、发布资格 | 认证授权与领域状态契约 | UI不能自行新增权限或业务规则。 |
| 超时、重试、轮询、性能及缓存预算 | 已批准运行/前端预算与测量环境 | 不随意填秒数/毫秒数，不用无限等待替代。 |
| 浏览器、系统和桌面环境 | 项目支持矩阵 | 验收时记录实际版本和桌面环境；不扩展为手机端或触屏支持承诺。 |

### 6.1 “机构名称输入框”应细到的实际示例

控件：`P03.UI11a/机构名称`。字段路径为 `tenant_name`，创建请求要求非空且最多 128 个 UTF-16 code unit；前后空白由请求对象统一去除，当前契约没有重复名称冲突语义，不能借 slug 冲突规则推断名称唯一。

定义应包括：可见标签与label关联；必填提示（仅当真实契约必填）；placeholder示例；单行/换行策略；默认值；前后空白处理；输入法组合期间行为；粘贴与自动填充；最大长度的计数口径；纯空白与超限错误；错误文案；blur/submit/纠错后的校验时机；服务端字段错映射；禁用与只读；加载时宽度不跳动；深浅主题；可访问名称与错误关联；桌面窗口下错误换行；脏态；保存失败保留；取消恢复；成功后服务端规范化名称同步。

验收至少实例化：未输入、仅空白、合法最短、128 个 UTF-16 code unit 边界、超界长度、超长粘贴、中文组合输入、自动填充、错误后修改、改回基线、服务端拒绝、提交期间重复动作、未知结果查证、主题切换和桌面窗口；emoji、组合字符和重复名称只有在实际 schema 另有定义时才追加边界。对不存在对应限制的边界项，明确不适用而不是编造规则。

### 6.2 “保存”必须区分的结果

| 结果 | 建议文案/状态 | 后续动作 |
| --- | --- | --- |
| 客户端校验未通过 | 标注首个错误与摘要 | 不发写请求，聚焦首错 |
| 写入确定失败 | 保存失败，显示可读原因 | 保留输入，按错误语义允许修复/重试 |
| 写入成功且视图同步成功 | 已保存 | 更新快照基线、修订与相关区域 |
| 写入成功但视图刷新失败 | 已保存，列表/详情刷新失败 | 只重试读取，不再次执行原写入 |
| 写入结果无法确定 | 请求结果待确认 | 按真实幂等/操作标识与权威查询核验 |
| 写入修订冲突 | 内容已被其他操作修改 | 保留输入，重新加载前说明损失 |
| 仅接受后台任务 | 已受理，处理中 | 仅按真实任务能力跟踪；不能立即称完成 |

## 7. 验收与交付规则

### 7.1 覆盖不能只用一个百分比

下表用于整体迁移或明确约定的完整模块验收，范围以本次交付约定为准；局部修改采用[局部完成标准](../04-指南与运维/12-后台UI实施与验收.md#6-完成标准)，不扩大登记、映射和场景分母。两类任务均如实记录必要验证与剩余缺口，不能把范围外对象计为已通过。

| 指标 | 定义 | 通过条件 |
| --- | --- | --- |
| UI对象登记覆盖 | 真实路由/DOM/组件/schema清点中的对象，已有控件合同的比例 | 范围内100%，无未登记对象 |
| 规则映射覆盖 | 原规则、菜单动作、后端协作段落、新增批准规则，已映射用例的比例 | 100%，不适用需逐项理由 |
| 场景执行通过 | 所有适用场景在承诺环境下有可追溯通过证据 | 100%，待验证/环境阻塞/失败不算通过 |
| 真实链路覆盖 | 读写/权限/并发/幂等/错误在真实前后端组合中验证 | 每种必要真实契约有证据，mock不替代 |
| 已发现缺陷 | 登记缺陷中尚未复验关闭的数量 | 0，包括文案、对齐、焦点、布局和功能缺陷 |
| 规则未决项 | 未绑定字段、未决冲突、未批准范围项 | 交付范围内为0 |

“不适用”只用于确实不存在的能力，例如没有真实批量操作的列表不强制显示复选框；不得用来排除已经承诺的移动布局、无障碍或错误状态。变更范围必须明确批准，不能靠缩小分母让覆盖率通过。源码行覆盖率高不能替代上述指标。

### 7.2 自动化与人工证据分工

组件测试覆盖状态组合、键盘、选择器、动态行和弹层。端到端测试覆盖路由、表单、对象状态、权限及真实副作用。故障注入覆盖超时、乱序、断网、冲突、局部失败与结果未知。视觉回归覆盖布局、主题、加载、错误、空态及弹层，须固定浏览器/操作系统/字体/数据/时区等环境，基线变化需审核，不用一键更新截图掩盖缺陷。Playwright官方文档提供自动等待断言与截图比较能力，并明确渲染环境会影响截图。[W6/W7]

验证方式和实施者职责按[验收分工](../04-指南与运维/12-后台UI实施与验收.md#4-测试要求)执行；改动涉及的键盘、读屏或真实输入法专项不能用自动扫描代替，也不对每次局部修改机械要求全套专项。Playwright官方明确自动检测只能发现部分问题，不能替代人工评估。[W11]

测试重试后通过要单独标记不稳定；不能无限增加重试、超时或截图容差来抹平真实问题。截图遮罩只覆盖已说明的真正动态非验收区域，不能遮掉出错控件、提示或金额。截图/trace/日志证据全部脱敏。

### 7.3 环境矩阵

支持矩阵只登记批准的桌面浏览器、窗口高度、缩放、浅色/深色/跟随系统、键盘/鼠标、减少动效、长名称/长ID/空值、高精度金额、大列表和大文件；模板自带响应式能力不形成手机或触屏支持承诺。

浏览器与系统版本要在执行时记录。不是要求机械执行全部维度的笛卡尔积；主流程逐页逐项全走，高风险交互状态完整枚举，外围兼容组合可采用经过评审的覆盖设计，并明确哪些组合没有承诺。真实设备交互不能仅靠修改viewport代替。

### 7.4 独立验收台账字段

规则ID、控件ID、需求来源版本、实现位置、适用状态、测试ID、测试数据、环境、预期UI、预期请求与副作用、实际结果、截图/trace/日志位置、缺陷ID、复验结果。允许状态：未实现、已实现未验证、验证失败、环境阻塞、验证通过、不适用（有理由）。不得把“测试脚本已写”记为通过。

共享组件通过只证明组件本身；每个页面仍需检查真实接线、业务文案、权限、字段映射、对象ID、回包处理和布局组合。后端协作不能只看HTTP状态码，还要核对实际业务写入、精度、租户隔离、修订和审计。

### 7.5 发布/回退

候选构建标明源码提交、规范版本、契约版本和执行矩阵；全部失败项修复并复验。发布前演练可执行回退路径，明确前端静态资源与接口版本不匹配、缓存旧资源、会话失效的处理。性能预算、监测采样与异常告警从批准运维合同绑定；监测不能代替发布前验收。确认风险例外可另行审批，但存在已知缺陷的例外版本不得标为“零已知缺陷交付”。
