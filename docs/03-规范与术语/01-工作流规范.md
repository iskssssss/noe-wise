## 1. 概述与边界

灵知 将可安装业务能力定义为 Workflow 包，唯一声明文件是包含顶层 `meta` 的 `workflow.yaml`。解析器、校验器和 Graph Builder 只接受本规范定义的语法。

| 项 | 约定 |
| :--- | :--- |
| 编码 | UTF-8 |
| YAML | 1.2；frontmatter 使用 `---` 包围 |
| 语义版本 | `MAJOR.MINOR.PATCH`（Workflow / ToolVersion / workflow `version`） |
| 工具路径 | Workflow ToolCallNode → requirement slot → frozen ToolDeployment → ToolPortal → Provider |
| 禁止 | 在示例或模板中硬编码生产 URL / API Key；在 `WorkflowInstance.config` 存密钥 |

本规范定义的节点类型：`start` / `tool` / `knowledge_query` / `human_input` / `llm` / `output` / `assign` / `parallel` / `subgraph` / `script` / `agentic` / `menu` / `card` / `async_task` / `end`；
`condition` 为装饰节点（引擎 no-op，仅用于可视化分支文档化，条件写在边上）；
`start` / `end` 为结构性节点（流程入口 / 终止标记，引擎 no-op 语义见 §4.3）。
节点语法与执行器需保持一致；内部执行器模式的历史决策见 [ADR-013](../05-架构决策/013-工作流节点执行器模式.md)，当前 Runtime 边界以 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md) 为准。
其他引擎类型配置不在本文展开；Runtime 执行边界见 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md)。

`parallel`、`subgraph` 和 `agentic` 保留为已批准的目标语法及语义；当前生产发布准入校验拒绝包含这三类节点的 DefinitionVersion。它们的目标执行语义仍按本文和 Harness Design 维护，拒绝准入不删除已批准语法。

**卡配置语义矩阵**（节点 `card` 字段的合法使用者，其余节点不接受该配置）：

| 节点 | `card` 配置 | 语义 | 挂起 | 引擎消费 |
| :--- | :--- | :--- | :--- | :--- |
| `card` | 是（核心，必填*） | 展示卡 `type=info`（fields / actions 链接 / style） | 否 | `buildInfoCard` 完整 |
| `human_input` | 是（核心，与 `prompt` 至少其一） | HITL 交互挂起卡（`type=confirm` 等，等待用户确认/输入） | 是 | `buildCard` 完整 |
| `menu` | 否（配置即校验失败） | 选择卡内容由 `actions` 决定 | 是 | 生成选择投影 |
| `output` | 否（配置即校验失败） | 仅文本输出，展示卡由 `card` 节点承担 | 否 | 生成文本结果 |
| 其余节点 | 否 | — | — | — |

## 2. 工作流包结构

> **存储模型**：工作流定义以发布后的不可变 DefinitionVersion 为准。上传 zip 仅为传输格式，运行时不从仓库业务样例或宿主目录回退读取定义。

```plaintext
<workflow-package>/
├── workflow.yaml         # 必填：唯一声明文件（顶层 meta 段 = 原 WORKFLOW.md frontmatter）
├── scripts/              # 选填：script 节点引用的可执行脚本
└── README.md             # 选填：开发者说明（不进入运行时）
```

`WORKFLOW.md` 不属于当前包契约。上传包必须提供包含完整 `meta` 的 `workflow.yaml`；解析器不得从旧文件或顶层散落字段回退补齐。

| 文件 | 何时必填 |
| :--- | :--- |
| `workflow.yaml` | 始终（含 `meta.name`；`type: state-machine` 或 `type: hybrid` 另需 nodes/edges） |
| `scripts/*` | `script` 节点引用时 |
| 其他类型配置 | 按类型（rag / agentic / notification 等） |

script 节点在无网络、无凭证的执行沙箱中运行，只能读写当前 Execution 的显式变量。任何模型、知识、HTTP、Connector 或其他外部调用必须使用对应类型化节点并经过统一守卫。

脚本资源随 DefinitionVersion 一起冻结在顶层 `resources` 数组，每项只包含 `path`、`content_base64`、`sha256`。路径必须为 `scripts/` 下的相对 `.py` 或 `.js` 路径，禁止绝对路径、反斜杠、空段、`.`、`..` 和重复路径；`args.script` 必须精确引用其中一项。正文为原始 UTF-8 字节的规范 Base64，摘要为这些字节的 SHA-256 小写十六进制；导入和发布核验摘要，导出保持原始字节。每个定义最多 128 项，单文件最多 1 MiB，总计最多 4 MiB。运行时只能读取冻结资源，不能回读可变资源表或宿主文件。

设计器中的脚本编辑内容须先“保存资源”加入当前工作流，再保存工作流草稿。编辑器相对已读取或已保存基线有修改时，切换资源或从本地读取脚本不能覆盖这些修改；用户须先保存资源或明确清空编辑器。将原脚本路径和正文都删空仍属于未保存修改，父页面继续保留待处理状态。

“导出定义”和冲突状态的“导出当前内容”只导出已纳入定义的内容；脚本编辑尚未保存为资源或治理 Schema 无效时，先保留编辑并提示处理，不能生成暗示已包含这些修改的文件。保存资源和修正 Schema 后可继续导出，无需保存服务端草稿或解除冲突。

脚本节点使用 `args.script` 指定入口、`args.input` 显式映射 JSON 对象输入；未填写 input 时传空对象，不自动注入 Session、凭证或整个运行上下文。`args.output_schema` 可声明输出 JSON Schema，未填写时仍要求单个 JSON 对象。输入经变量插值后随节点调用准备冻结；脚本摘要、环境版本、执行策略和截止时间属于同一次准备。提交前持久化 DISPATCHED；重启和响应丢失只查询原 taskId，禁止盲目重新提交。结果通过 schema 校验后写入 `result_to`。

## 3. workflow.yaml meta 段规范

### 3.1 文档形态

workflow.yaml 顶层新增 `meta` 子段（原 WORKFLOW.md frontmatter，字段带 `meta.` 前缀引用）：

```yaml
version: "1.0"          # 语法版本（const "1.0"），与 meta.version（包版本 SemVer）严格区分
entry: greet
nodes: [...]
edges: [...]
meta:                   # 原 frontmatter：包元数据
  name: structure-example
  type: state-machine
  version: 1.0.0        # 包版本（SemVer）
  display_name: 流程助手
  ...
```

解析器输出 `ParsedWorkflow`：`meta`（workflow.yaml 顶层 meta 段）+ `workflow`（nodes/edges 流程定义）。

### 3.2 meta 字段

#### 必填

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `name` | string | 工作流标识，kebab-case，`^[a-z][a-z0-9-]{1,62}$`，包内唯一 |
| `type` | enum | 当前校验器实际支持的 Workflow 类型；未实现类型不得只靠文档声明进入发布契约 |
| `version` | string | SemVer，如 `1.0.0` |
| `description` | string | 工作流简介；用于市场展示与意图路由语义匹配 |
| `tools` | array | 工具声明列表；无工具时为空数组 `[]` |

#### 选填

| 字段 | 类型 | 默认 | 说明 |
| :--- | :--- | :--- | :--- |
| `author` | string | — | 作者标识 |
| `author_type` | enum | `platform` | `platform` \| `isv` \| `tenant` |
| `category` | string | — | 如 `medical` / `legal` |
| `tags` | string[] | `[]` | 检索标签 |
| `price_type` | enum | `free` | `free` \| `paid` \| `enterprise` |
| `config_schema` | array | `[]` | 安装时业务参数（**不含** API Key / URL） |
| `capability_requirements` | array | `[]` | 安装时必须解析为已发布版本和 Deployment 的类型化能力槽 |
| `required_permissions` | string[] | `[]` | 安装审批用权限声明 |
| `display_name` | string | `name` | 展示名 |
| `icon_url` | string | — | 图标 |
| `min_platform_version` | string | — | 最低平台版本 |

> 有工具或知识节点的 Workflow 必须声明对应 `capability_requirements`；运行时不得按名称搜索租户全局资源。

### 3.3 `config_schema` 项

| 字段 | 必填 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| `key` | 是 | string | 配置键，`^[a-z][a-z0-9_]{0,63}$` |
| `label` | 是 | string | B 端表单标签 |
| `type` | 是 | enum | `string` \| `integer` \| `boolean` \| `number` \| `enum` \| `textarea` |
| `required` | 否 | bool | 默认 `false` |
| `default` | 否 | any | 默认值 |
| `description` | 否 | string | 帮助文案 |
| `enum_values` | 条件 | string[] | `type=enum` 时必填 |
| `min` / `max` | 否 | number | 数值约束 |

安装与测试均按声明物化默认值：未提供的字段采用默认值；可选 `string/textarea` 明确填写的空字符串保留为空，不省略后重新采用默认值。必填文本的空字符串或纯空白仍拒绝，`false` 与 `0` 是有效输入。

### 3.4 `capability_requirements`

Workflow DefinitionVersion 只声明能力槽，不包含 ConnectorInstance、凭证、URL 或租户 Deployment。安装时每个必需槽显式绑定已发布 CapabilityRef；Tool 槽还必须解析为 ToolDeployment。Workflow Execution 启动时冻结全部解析结果。

每次安装、升级或配置变更生成新的不可变 `installationRevision`，其中保存完整 config、custom prompt、能力槽、子 Workflow 和 Agent 槽绑定。`instanceRevision` 仍表示精确 DefinitionVersion ID；两种 revision 分别进入冻结目标、权限资源和持久快照，不能互相替代。业务参数按 `config_schema` 校验并物化默认值，未声明字段不得写入安装修订。

安装请求的 `bindings` 包含 `capabilities`、`workflows`、`agents` 三个数组。能力项用 `slot` 和精确 `capability` 标识版本；Tool 项另含 `tool_deployment_id` 与 `tool_deployment_revision`，Knowledge 项另含已发布 `knowledge_revision`。子图项包含 `workflow`、`instance_id`、`definition_version_id`、`installation_revision`，并在安装时检查整个依赖闭包无环；Agent 项包含 `slot`、`agent_id`，不增加 Capability 类型。执行只使用原冻结修订，安装配置更新不改变已启动 Execution。

组合节点创建子 Execution 时，以父 Execution、节点、访问序号和调用序号保存不可变准备事实，原子保存完整子创建命令及来源映射。子执行使用同一 Run 身份，不伪造 Agent Action 或委派来源；创建前按 Run → 父 Execution 锁序核验当前租约、revision、取消与冻结节点。`parallel` 分支为 1 至 32 个唯一入口，各自拥有稳定执行身份及独立状态，结果按分支 ID 收集。`subgraph` 仅接收显式 `args` 与入边 `transfer_context`，不隐式传递父消息或知识证据；入口边随游标持久化，恢复时仍须属于原冻结定义。子执行来源只证明创建依据，不授予运行或写权限；父取消、嵌套输入和外部等待必须继续经过各自的权限与恢复边界。

| 字段 | 必填 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| `slot` | 是 | string | Workflow 内稳定槽名，`^[a-z][a-z0-9_]{0,63}$` |
| `type` | 是 | enum | `tool` \| `knowledge_source` |
| `capability_id` | 是 | string | 逻辑能力 ID，不是显示名称 |
| `version_constraint` | 是 | string | 安装时允许选择的版本约束；执行时必须解析为精确 versionId |
| `label` | 是 | string | 安装向导展示名 |
| `required` | 否 | bool | 默认 `true`；`false` 表示可选绑定 |
| `description` | 否 | string | 补充说明 |

### 3.5 `tools` 与能力槽

| 字段 | 必填 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| `name` | 是 | string | 工具名；须与 workflow 中 `tool` 节点引用一致 |
| `description` | 是 | string | 给人/LLM 的说明 |
| `requirement` | 是 | string | 引用 `capability_requirements[].slot`，且目标类型必须为 `tool` |
| `input_schema` | 否 | object | 允许进一步收窄 ToolVersion 输入 schema，不能放宽 |

```yaml
capability_requirements:
  - slot: record_query
    type: tool
    capability_id: query-record
    version_constraint: "1.x"
    label: 记录查询
tools:
  - name: query_record
    description: 查询业务记录
    requirement: record_query
```

解析规则：每个 `tools[].requirement` 必须唯一命中一个 tool 类型槽。安装完成前校验精确 ToolVersion 与 ToolDeployment 的租户、状态、schema 和 Provider 要求；运行时节点只使用冻结槽，不重新查询 Registry。

### 3.5.1 平台内置工具

平台内置工具同样发布 ToolVersion，并创建 `providerType=PLATFORM` 的 ToolDeployment；Workflow 不按保留名称、优先级或隐式分支调用平台实现。

| 工具名 | 参数 | 说明 |
| :--- | :--- | :--- |
| `report_task_result` | `execution_id`、`action`、`context`；具体必填与默认值以实现 schema 为准 | 把任务结果提交到统一 Inbound/Recovery 链；工具不得直接读取 checkpoint 或调用旧恢复方法 |
| `get_current_time` | `timezone?` | 返回指定 IANA 时区的 ISO 8601 时间与 Unix 毫秒时间戳 |
| `calculate_expression` | `expression` | 使用受限四则运算语法计算十进制结果；不执行脚本或任意表达式 |
| `convert_datetime` | `datetime`、`target_timezone`、`source_timezone?`、`output_format?` | 解析 ISO 8601 时间并转换时区；输出格式限于平台定义的枚举 |
| `json_query` | `value`、`pointer` | 以 RFC 6901 JSON Pointer 从 JSON 值读取一个节点 |
| `json_schema_validate` | `value`、`schema` | 按平台支持的 JSON Schema 子集校验值，并返回至多 100 条校验错误 |
| `template_render` | `template`、`data?` | 使用 `{{path.to.value}}` 占位符渲染纯文本；不执行循环、函数或表达式 |
| `http_request` | `method`、`url`、`query?`、`headers?`、`body?` | 向沙箱允许的 HTTPS 地址发起 GET 或 POST；禁止重定向、URL 用户信息与改写 Host。`body` 仅 POST 且必须为 JSON 对象 |

平台默认工具由统一目录初始化为 `tenant_id = null` 的只读工具定义，因而可在工具管理页查看并按通常能力绑定流程挂载到 Agent。
平台 Handler 名称、保留名与目录条目必须来自同一注册表，避免新增 Handler 后遗漏保留名或不可见的工具定义。

`code_execute` 也通过同一目录发布：参数为 `mode`、`language`、inline 的 `code` 或 skill 的 `skill_handle`/`script_path`，以及可选结构化 `dependencies`。它是非幂等调用，不自动重执行；默认关闭，管理员启用并挂载后才可用。普通对话不需要 Skill，脚本引用要求当前 input 的精确冻结版本已激活。执行与产物操作见[运行指南](../04-指南与运维/09-代码执行与产物运行指南.md)。

```yaml
# 示例（C 端工作流上报下发任务）
meta:
  capability_requirements:
    - slot: task_report
      type: tool
      capability_id: report-task-result
      version_constraint: "1.x"
      label: 任务结果上报
  tools:
    - name: report_task_result
      description: 上报任务结果
      requirement: task_report
nodes:
  - id: report_task
    type: tool
    name: 上报下发任务 agent
    tool: report_task_result
    args:
      execution_id: "${state.ctx_execution_id}"
      action: "feedback"
      context:
        response_text: "${state.reply}"
        requester_name: "${state.ctx_requester_name}"
        intent: "${state.intent}"
```

### 3.6 禁止的隐式上下文声明

- `memory` 不属于 Workflow meta schema。Workflow 不能声明或读取用户画像、Session 历史、MemoryPort、RelationshipState 或 AgentContextSnapshot。
- 知识访问只能使用声明过的 `knowledge_source` 能力槽和 KnowledgeQueryNode，或解析 DispatchOrder 中的冻结 EvidenceRef。
- Workflow 只接收显式业务参数、只读身份元数据、必要引用和已声明能力绑定。

### 3.7 禁止的 `meta.body`

- `meta.body` 不属于当前 schema，出现时校验失败。
- Prompt Injection 防护由 PolicyChain 和能力边界执行，不通过修改 Workflow 正文实现。

## 4. workflow.yaml 规范

仅当 `meta.type` 为 `state-machine`（或 `hybrid` 主骨架）时使用。

### 4.1 顶层结构

```yaml
version: "1.0"
nodes:
  # ...
edges:
  # ...
entry: check_user          # 必填；显式声明入口节点 ID
```

| 字段 | 必填 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| `version` | 是 | string | workflow 语法版本，当前 `"1.0"` |
| `nodes` | 是 | array | 节点列表，至少 1 个 |
| `edges` | 是 | array | 边列表 |
| `entry` | 否 | string | 入口节点 `id`；未提供时取唯一 start 节点，否则取首个 node id |

未在当前 schema 中定义的字段直接校验失败。解析器不接受 `start_node`、`source`/`target`、`tool_name`/`input_mapping` 等历史别名。

### 4.3 节点类型（`nodes`）

公共字段：`id`（必填）、`type`（必填）、`name`（选填）。

#### `start`（开始节点）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `name` | 否 | 展示名，如「开始」 |

**运行时语义**：流程入口标记。引擎执行时 no-op，沿出边进入首个业务节点；同时声明 entry 与 start 时二者必须一致。

**结构约束**（SF-WF-008）：至多一个；无入边；须有出边（否则流程空转立即结束）。

start 节点可省略；省略时建议显式声明 entry，避免节点重排改变入口。

#### `tool`

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `tool` | 是 | 引用 `meta.tools[].name`（平台内置工具名同样适用，见 §3.5.1） |
| `args` | 否 | 入参映射；值支持变量替换（嵌套 Map / List 递归插值，如内置工具的 `context` 参数） |
| `result_to` | 否 | 将响应写入 `state.<field>` 或 `extracted.<field>` |
| `on_error` | 否 | 工具调用失败策略：`fail`（默认，抛错终止）/ `goto:<node_id>`（错误信息写入 `state.last_error` 后跳转指定节点，目标须存在，SF-WF-007）/ `message`（追加一条错误消息并结束流程） |

#### `knowledge_query`

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `requirement` | 是 | 引用 `meta.capability_requirements` 中 `knowledge_source` 类型的槽 |
| `query` | 是 | 显式查询模板；可引用当前 Execution 的输入与状态变量 |
| `budget` | 是 | 节点允许的条数、token、字符、耗时和来源预算，不从 Session 或 Agent 隐式继承 |
| `result_to` | 是 | 把受控 EvidenceItem 结果写入 `state.<field>` 或 `extracted.<field>` |
| `on_error` | 否 | 复用 tool 节点失败策略 |

KnowledgeQueryNode 只能经 KnowledgePortal 与统一外部调用守卫执行。节点不能读取 SessionLog、MemoryPort、RelationshipState 或任意未挂载来源；结果只有进入 exportFields 并落为 SessionLog Observation 后才能生成写回提案。

#### `human_input`

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `prompt` | 是* | 追问文案；与 `card` 至少其一 |
| `card` | 是* | HITL 卡片结构（见 §6） |
| `timeout_seconds` | 否 | 挂起超时秒数；超时由 scheduled Inbound 驱动 Recovery，并以明确 timeout 动作恢复 |
| `result_to` | 否 | 用户响应写入目标字段 |
| `actions` | 否 | 允许的动作：`confirm` / `cancel` / `select` |

**运行时语义**：到达 human_input 节点时生成 Pending 与交互投影，流程挂起等待输入。点选、用户文本、回调和超时都先进入 Unified Inbound；Recovery 唯一命中后调用 WorkflowPortal，Workflow 根据 action 与输入继续执行。无法唯一命中的自由文本先澄清，不随机恢复。timeout 动作必须有明确条件边或失败策略。

#### `async_task`

异步任务节点（发起挂起，非 HITL）。

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `timeout_seconds` | 否 | 挂起超时秒数；未配置则不设超时 |

**运行时语义**：执行到 async_task 节点时创建无交互卡的 Pending。完成回调或超时先进入 Unified Inbound，再由 Recovery 与 WorkflowPortal 恢复；挂起期间 Session 仍可处理普通对话和其他 Execution。

等待保存节点访问身份和首次提交等待时计算的绝对截止时间；未配置 `timeout_seconds` 时只等待回调。进程重启、租约续领和扫描不得延长截止时间。回调沿 Runtime 已登记的签名 callback delivery 进入 ExistingRun，携带精确 `suspendRef/actionKey/expectedRevision/checkpointRevision`，签名投递使用现有 `skillforge.runtime.callback.execution-result.v1` 七项数组封套，固定租户、Execution、Run、actionKey 和 Execution revision；封套第六项直接声明业务 schema `skillforge.runtime.workflow-async-response.v1`，第七项为该 schema 的 JSON 正文，宿主须将它列入回调业务 schema 白名单。成功正文为 `{"status":"completed","result":{...}}`，失败正文为 `{"status":"failed","reason_code":"stable_reason"}`；用户 ACTION 不能冒充该来源。`result_to` 与其他外部节点一致，缺省写入 `state.<节点ID>`。

后台到期观察只产生持久系统恢复信号，不直接推进 Engine。完成回调与超时沿同一原等待 revision 竞争，重复恢复返回原结果；逾期完成回调拒绝。超时原因 `workflow_async_timed_out` 与失败回调均遵循节点 `on_error`，缺省确定失败。该节点不负责发起外部业务请求，外部副作用仍由明确的 Tool 等节点承担。

外部集成通过[接口契约的回调注册入口](../02-架构与设计/04-接口与事件契约.md#41-回调)取得当前等待的安全描述，再使用原服务凭据签名投递。普通消息创建独立 Run，不隐式消费已挂起的人工或外部等待；恢复必须携带明确的目标和等待身份。


#### `llm`

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `prompt` | 是 | 提示模板（支持变量替换，§7） |
| `extract` | 否 | 从 LLM 输出 JSON 中提取的键列表，逐个写入 `result_to` 目标集合 |
| `result_to` | 否 | 默认 `state`；`extracted` 表示写入提取变量 |

LLM 节点将冻结的 `custom_prompt` 与原始 `prompt` 模板作为配置指令，`${路径}` 的运行值只通过独立 USER 消息中的 `variables` JSON 对象交付，不拼入指令正文。变量沿用 §7 的路径解析规则，只发送模板显式引用的值；字符串保留原文，对象/数组保留 JSON 类型，缺失值为 `null` 并按空文本理解，重复引用共用同值，材料内的占位符不递归解释。固定边界声明要求模型仅将变量当作待处理材料；节点自身的纯文本输出或 `extract` 所要求的 JSON 对象输出保持原契约。这一消息分层只适用于 LLM 节点，不改变工具、查询或展示节点的文本插值。

> `purpose`（extract/classify/generate）字段不被使用，解析器忽略。

#### `condition`

推荐条件写在 **edges** 上；`condition` 节点仅用于显式分支文档化（可视化编辑器中的菱形装饰）。可选 `expression` 字段；引擎执行时该节点 no-op，分支逻辑全部由出边条件决定。

#### `menu`（行动点节点）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `prompt` | 是* | 菜单提示文案（支持变量替换）；与 `actions` 至少其一 |
| `actions` | 是 | 行动点列表：`{id, label, to}`；`id` 唯一，`label` 为会话页展示文案，`to` 为点选后的目标节点 id（须存在，SF-WF-006） |
| `timeout_seconds` | 否 | 挂起超时秒数；未配置则不设超时。超时恢复以 `action="timeout"` 触发，行动点无匹配时回退普通出边 |

**运行时语义**：到达 menu 节点时生成选择卡片与 Pending。用户点选后，Workflow 按 actionKey 匹配 `actions[].id` 并路由到对应 `to`；未知或过期 action 拒绝，不回退猜测普通出边。

> 输入恢复：点选、用户文本、回调和定时器都先进入 Unified Inbound。确定性输入按 `sessionId + executionId + actionKey` 路由；自由文本只有唯一命中时才恢复，多候选时先澄清。增强语义唤醒属于 P1。

> 边界：menu 节点只承载 prompt 与 actions；配置 `card` 时校验失败。结构化展示由独立 card 节点负责。
>
> 限制：包含 `menu` 或 `human_input` 的定义必须声明支持 HITL，并在发布校验阶段拒绝不一致配置。Workflow 只能由 Agent 通过 DispatchOrder 调用，不存在“直连时禁用挂起”的第二套语义。

#### `card`（展示卡片节点）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `message` | 否 | 随卡片展示的文本消息 |
| `card` | 是* | 卡片结构（§6）：`title` / `body` / `fields` / `actions`（含 `type=link` 跳转）/ `style`，全字段支持变量替换 |

**运行时语义**：到达 card 节点时生成 `type=info` 展示卡（不挂起、不等待用户），经受控消息投影进入 Outbox，随后沿显式出边继续。

**回放渲染**：card 的语义数据与消息关联后写入 SessionLog/Outbox 投影；直播与回放使用同一投影函数，不从 Workflow 节点表直接渲染。

#### `output`

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `message` | 否 | 文本消息模板 |

output 节点不接受 `card` 或 `terminal` 配置，未知字段校验失败。结构化展示使用 card 节点，终止使用显式 end 节点。

#### `end`（结束节点）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `name` | 否 | 展示名，如「结束」 |

**运行时语义**：流程终止标记。引擎执行到 end 节点时立即结束且不再评估出边。允许多个 end 对应不同分支；end 节点不产生业务输出，终态由规范化执行结果形成 BattleReport。

**结构约束**（SF-WF-008）：无出边。

end 节点可省略；无出边节点表示该分支自然终止。显式 end 用于让终止语义在图上可见。

### 4.4 边（`edges`）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `from` | 是 | 源节点 id |
| `to` | 是 | 目标节点 id；不接受历史别名 |
| `condition` | 否 | 安全子集表达式；缺省为默认边 |
| `priority` | 否 | **数值越大越优先**；不写默认 0 |
| `transfer_context` | 否 | 跨工作流流转参数（变量可替换）：key → 变量路径映射，经该边进入 `subgraph` 节点时插值后合并进子流程初始 `state` |

规则：同一 `from` 至多一条无 `condition` 默认边；带条件边按 `priority` 降序求值（大者优先）；图须从 `entry` 可达；禁止无条件自环。

## 5. 条件表达式安全子集

**只允许**对 `${state.*}` / `${extracted.*}` 的比较运算，**禁止**任意代码、函数调用、深层属性链、`eval`、导入模块。

### 5.1 语法（BNF 摘要）

```plaintext
expr     := ( "!" )* or_expr                          -- 前缀取反可叠加
or_expr  := and_expr ( "||" and_expr )*
and_expr := unit ( "&&" unit )*
unit     := operand ( op literal )?                   -- 裸 operand 按真值判断
op       := "==" | "!=" | ">" | ">=" | "<" | "<=" | "contains" | "matches" | "in"
operand  := "${state." path "}" | "${extracted." path "}"
path     := ident ( "." ident )*                      -- 点路径嵌套，如 state.ctx_requester_info.name
ident    := [a-zA-Z_][a-zA-Z0-9_]*
literal  := "true" | "false" | number | '"' string '"' | "'" string "'" | "null"
          | "[" literal ( "," literal )* "]"          -- 数组字面量（in / contains 右操作数）
```

运算符语义：`contains`（左字符串包含右 / 左数组含右元素）、`matches`（左文本正则匹配右模式）、
`in`（左值 ∈ 右数组字面量）；`>=`/`<=` 数字按数值、字符串按字典序。

### 5.2 允许 / 禁止

| 表达式 | 合法 |
| :--- | :--- |
| `${state.is_registered == true}` | 是 |
| `${extracted.date != null}` | 是 |
| `${state.retry_count >= 3}` | 是 |
| `${state.status == "ok"} && ${extracted.slot != null}` | 是 |
| `!${state.phone} matches "^1\\d{10}$"` | 是；支持取反与正则 |
| `${state.ctx_requester_info.name}` | 是；点路径按嵌套 Map 逐层取值 |
| `${state.tags} contains "vip"` / `${state.city} in ["beijing", "shanghai"]` | 是 |
| `${config.api_key}` | 否；条件中禁止 config |
| `len(state.x) > 0` | 否；禁止函数 |
| `__import__("os").system("x")` | 否 |

解析器编译为 AST；运行时仅解释该 AST，不调用 `eval` 或任意代码执行。

> 注意：`${config.*}` / `${user.*}` / `${runtime.*}` 仅用于 **变量替换**（§7），不得出现在 **condition 表达式** 中。

## 6. HITL 节点卡片结构

`human_input.card`（及 SSE `message.card` / `hitl.required` 的 `data.card`）统一结构：

```json
{
  "card_id": "hitl_confirm_request",
  "type": "confirm",
  "title": "确认申请信息",
  "body": "审核人：${state.reviewer_name}\\n申请摘要：${state.request_summary}",
  "fields": [
    { "key": "reviewer_name", "label": "审核人", "value": "${state.reviewer_name}" },
    { "key": "request_summary", "label": "申请摘要", "value": "${state.request_summary}" }
  ],
  "actions": [
    { "id": "confirm", "label": "确认申请", "style": "primary" },
    { "id": "cancel", "label": "取消", "style": "secondary" },
    { "id": "detail", "label": "查看详情", "type": "link", "url": "https://service.example.com/requests/${state.request_id}" }
  ],
  "style": { "accent": "#ff6a1e", "layout": "compact" },
  "meta": {
    "execution_id": "${runtime.execution_id}",
    "timeout_at": "${runtime.hitl_expires_at}"
  }
}
```

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `card_id` | 是 | 卡片模板 id |
| `type` | 是 | `confirm` \| `select` \| `form` \| `info` \| `quota_exceeded` |
| `title` | 是 | 标题 |
| `body` | 否 | Markdown/纯文本 |
| `fields` | 否 | 只读字段列表 `{key,label,value,description?}`；`description` 为可选的公开补充说明 |
| `actions` | 否 | `type=select` 时的行动点 `{id,label}`（menu 节点自动生成，字段与节点配置一致） |
| `actions` | 是* | 可操作按钮；`info` 类型可省略 |
| `style` | 否 | 自定义样式（受控字段：`accent` 强调色、`layout` 布局等；渲染端白名单应用，禁 HTML 注入） |
| `meta` | 否 | 运行时元数据 |

`type=info` 且没有交互按钮或选项时，`style.layout=metrics` 使用指标卡布局，依次展示标题、Markdown 正文以及字段的标签、值和补充说明。数值与说明必须来自显式卡片字段，前端不从自由文本猜测或提取业务金额；其他卡片继续使用普通布局。

**插值范围**：`body`、`fields[].value`、`actions[].label/url`、`title` 与 `meta` 全部支持变量替换（§7，同一来源体系）；
`actions[].type=link` 表示链接跳转，`url` 支持占位符插值（与展示数据同源，如申请详情页带 `state.ctx_requester_info.id`）。
渠道适配器负责渲染；与传输协议解耦（ADR-002）。

## 7. 变量替换语法

在 `args`、`prompt`、`card`、`message`、`transfer_context` 中支持：

| 语法 | 来源 | 说明 |
| :--- | :--- | :--- |
| `${config.<key>}` | WorkflowInstance 安装配置 | 来自 `config_schema` |
| `${state.<field>}` | 工作记忆状态 | 隐式字段（运行时写入，无需声明）；支持点路径嵌套（如 `state.ctx_requester_info.name`） |
| `${extracted.<field>}` | LLM / HITL 抽取结果 | |
| `${user.<path>}` | DispatchOrder 只读身份元数据 | 白名单：`id` / `display_name`；不得由 Workflow 读取用户画像、关系或记忆补全 |
| `${runtime.<key>}` | 引擎注入 | `session_id` / `execution_id` / `run_id` / `workflow_instance_id` |

规则：未解析变量默认空串并打 warning；`user.` / `runtime.` 白名单外引用解析为 null + warning；禁止替换结果改变 HTTP method / 主机名；密钥永不进入变量命名空间。

## 8. 版本与预发布变更

### 8.1 Workflow 模板版本

| 变更类型 | SemVer | 行为 |
| :--- | :--- | :--- |
| 文案 / Prompt / 不改变契约的修正 | PATCH | 创建新不可变定义版本 |
| 新增可选配置或能力 | MINOR | 创建新定义版本；运行中 Execution 继续使用已固定版本 |
| 删除/重命名 tool、必填配置、节点 id 或状态语义 | MAJOR | 创建新定义版本并执行发布前校验 |

Session 和 Execution 必须记录实际使用的定义版本。更新配置只影响后续 dispatch，不修改运行中 Execution。

Builder 与 Marketplace 只负责编辑、校验、发布、审核、安装和显式升级不可变版本，不提供 Tool invoke 或 Workflow run/resume。开放管理 API 同样只能管理定义、Deployment、Instance 与 Mount；会话中的执行请求必须从 Unified Inbound 进入 Agent Runtime，再由 Agent 产生 DispatchOrder。

### 8.2 workflow `version`

当前规范版本取值必须与校验器和 JSON Schema 一致。未知版本或未知节点类型直接校验失败，不允许 no-op 跳过或从历史格式回退。

### 8.3 ToolVersion 与 ToolDeployment

- ToolVersion 发布后不可修改；新增可选字段使用 MINOR，破坏输入/输出或副作用语义使用 MAJOR。
- ToolDeployment 切换 Provider 或 ConnectorInstance 只改变后续 Execution；已启动 Execution 使用冻结 Deployment revision。
- Deployment 不得把不兼容 ToolVersion 绑定到原 requirement slot。

### 8.4 迁移检查清单

1. 校验目标 `workflow.yaml`、能力声明、工具依赖和节点引用。
2. 发布新的不可变 definitionVersion。
3. 验证新 dispatch 使用新版本、运行中 Execution 仍使用固定版本。
4. 预发布阶段直接删除冲突解析回退和旧格式适配；若真实数据需要保留，使用一次性转换脚本。

### 8.5 Builder 编写与发布约束

- Builder 节点目录、导入器和服务端校验器必须使用同一规范版本与节点类型清单；目录必须包含 `knowledge_query`，不得包含 `http`，未知类型不能以占位节点保存或发布。
- Tool 节点先引用 `meta.tools[].name`，再经 `tools[].requirement` 绑定 tool capability slot；KnowledgeQueryNode 直接引用 knowledge_source slot。编辑器不能按显示名称、Connector、URL 或租户全局搜索补全缺失绑定。
- Builder 保存的是带 revision 的 draft，允许保留待修复问题；发布前必须完成 schema、图结构、变量、能力槽、租户/状态/版本和策略校验，并生成新的不可变 DefinitionVersion。
- 节点 layout 与画布 viewport 保存为关联 draft revision 的 BuilderSnapshot，引擎忽略且发布定义不因拖动原地变化；已发布版本只读，编辑必须创建新 draft。
- Builder 测试只能创建隔离 Session 并经 Unified Inbound、Agent Runtime 与 WorkflowPortal 执行；不得提供 Workflow run/resume、原始 dry-run、checkpoint 或隐式会话上下文入口。
- 测试面板按初始化后的默认值判断未提交修改，覆盖测试消息、业务参数、安装配置、能力选择与预算；未编辑的默认内容不触发丢弃确认。切换测试来源后暂存的其他来源草稿同样受离页和刷新保护；关闭面板保留本页草稿，不将正文持久化到浏览器存储。已确认创建的测试保留原请求恢复入口，不能因离页保护产生新的执行请求。
- 测试面板的公开消息按需分页读取；有较早记录时提供加载入口，读取失败保留当前消息与原游标。查询最新测试状态保留已加载的历史，待办以最新状态为准；查看历史只读原测试 Session，不创建、重发或恢复执行。

## 9. 最小结构示例

以下片段仅展示通用包元数据与 start、output、end 的结构，不提供可安装业务资源或外部工具部署。

```yaml
version: "1.0"
entry: start
meta:
  name: structure-example
  type: state-machine
  version: 1.0.0
  description: 工作流包结构说明
  tools: []
nodes:
  - id: start
    type: start
  - id: output
    type: output
    message: "流程已完成。"
  - id: end
    type: end
edges:
  - from: start
    to: output
  - from: output
    to: end
```

测试工具需要显式绑定已发布的 ToolVersion 与 `providerType=TEST_MOCK` 的 ToolDeployment；仅可在测试环境使用，生产发布校验必须拒绝，不能为通过校验伪造凭证。

## 10. 约束速查（JSON Schema 等效表）

### 10.1 `meta`

| 路径 | 约束 |
| :--- | :--- |
| `meta.name` | required, pattern `^[a-z][a-z0-9-]{1,62}$` |
| `meta.type` | required, enum 见 §3.2 |
| `meta.version` | required, SemVer |
| `meta.description` | required, minLength 1, maxLength 4000 |
| `meta.tools` | required, array |
| `meta.tools[].name` | required, unique |
| `meta.tools[].requirement` | required；引用 tool 类型的 capability requirement slot |
| `meta.capability_requirements[].slot` | required, unique |
| `meta.capability_requirements[].type` | enum: `tool`\|`knowledge_source` |
| `meta.capability_requirements[].capability_id` | required；逻辑 ID，不使用显示名称 |
| `meta.capability_requirements[].version_constraint` | required；安装时解析为精确 versionId |

### 10.2 workflow.yaml

| 路径 | 约束 |
| :--- | :--- |
| `version` | required, const `"1.0"` |
| `entry` | optional；存在时引用 node id；缺省规则见 §4.1 |
| `nodes` | required, minItems 1；`id` unique |
| `nodes[].type` | enum: `start`\|`tool`\|`knowledge_query`\|`human_input`\|`llm`\|`condition`\|`output`\|`assign`\|`parallel`\|`subgraph`\|`script`\|`agentic`\|`menu`\|`card`\|`async_task`\|`end` |
| `edges` | required；`from`/`to` 必须引用存在的 node id |
| `edges[].condition` | 若存在，须通过安全子集校验 |

### 10.3 校验器额外规则

| 规则 ID | 描述 |
| :--- | :--- |
| `SF-WORKFLOW-001` | 每个 `tools[].requirement` 唯一引用一个 tool 类型 capability slot |
| `SF-WF-001` | 从 entry 可达性分析 |
| `SF-WF-002` | 无条件自环检测 |
| `SF-WF-003` | tool 节点引用的 tool 名存在于 workflow.yaml meta.tools |
| `SF-WF-004` | 条件表达式 AST 合法 |
| `SF-WF-005` | 同一 from 至多一条默认边 |
| `SF-WF-006` | `menu` 节点 `actions[].id` 唯一且 `to` 指向存在的节点 |
| `SF-WF-007` | `tool` 节点 `on_error: goto:<id>` 目标节点存在 |
| `SF-WF-008` | start 节点至多一个、无入边、须有出边；end 节点无出边；同时存在 entry 与 start 时必须一致 |
| `SF-WF-009` | 无 end 的流程允许在无出边节点自然终止；入口与终止规则必须可确定 |
| `SF-WF-010` | `http` 节点属于非法类型；外部 HTTP 操作必须发布为 ToolVersion 并绑定 ToolDeployment |

| `SF-VAR-001` | 变量引用字段在 schema/config 中声明或为隐式白名单 |

## 11. 与数据模型 / ADR-003 的衔接

| 概念 | 落点 |
| :--- | :--- |
| WorkflowDefinitionVersion / CapabilityRequirement | Workflow 定义域；由 `meta` 解析并在发布时固定 |
| WorkflowInstance.snapshot + bindings | 安装时把每个 slot 绑定到精确 CapabilityRef；Tool 槽额外绑定 ToolDeployment |
| ToolVersion / ToolDeployment / ConnectorInstance | Tool 契约、部署和凭证实现分离；Connector 不等于 Tool |
| Execution Ledger + HITL | 状态以 Harness Design 为准，交互投影经 [API 与事件契约](../02-架构与设计/04-接口与事件契约.md) 下发 |
| TEST_MOCK ToolDeployment | 仅测试环境显式创建，永不作为运行时未命中回退 |

**变更流程**：语法变化同步本文、解析器、Schema、相关契约测试与示例 Workflow。Note 的触发与复用按 [Note 治理规范](../../.agents/skills/nw-docs/references/notes-governance.md#4-note-触发与复用)，不为普通语法修正额外建 Note。
