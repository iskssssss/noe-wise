## 1. 架构约束来源

按当前改动定位 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md) 或 [Harness 03](../../harness-design/03-核心对象模型与状态机.md) 的直接章节；需要实现状态时核对当前源码、测试及对应候选的原始运行结果。上下文加载范围按[开发流程规范](../../.agents/skills/nw-workflow/references/development-workflow.md)，不因模块名称触发全文阅读。

## 2. 模型分层

数据对象归属、公开契约与适配器边界遵循 [工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md#数据模型归属)。Runtime SDK 的公开类型与内部协作边界见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#75-agent-runtime-sdk-façade)；精确 Java ABI 的事实归属见 [Note 治理规范](../../.agents/skills/nw-docs/references/notes-governance.md#2-文档分层与唯一事实源)。

## 3. 验证

- 编码规则检查按 [工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md) 执行。
- Runtime Note 的触发、复用与生命周期按 [Note 治理规范](../../.agents/skills/nw-docs/references/notes-governance.md) 判断；不以本索引额外要求建 Note。
- Workflow 语法变更同步 [工作流规范](01-工作流规范.md) 和校验器测试。
- 文档检查命令见 [文档规范](../../.agents/skills/nw-docs/references/documentation-standards.md)。

历史审计结果和已修复违规保留在 Git 历史或对应的决策记录中，不在规范文档维护易过期计数。
