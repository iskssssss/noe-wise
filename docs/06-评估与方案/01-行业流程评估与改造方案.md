# 行业场景评估与改造需求

> 本文把 资料整理、申请确认、批量核验与跨角色协作场景整理为平台需求输入。
> Agent Runtime 的实现边界以 [Harness Design](../../harness-design/README.md) 为准；本文不定义旧类、旧入口或旁路恢复方案。

## 1. 评估范围

评估覆盖四类典型流程：

| 场景 | 核心特征 |
| :--- | :--- |
| 资料整理 | 长时生成、进度卡更新、完成后结果交付 |
| 申请确认 | 申请人与审核人跨角色协作、多个等待点、超时分支 |
| 批量核验计划 | 批量/单个任务、后台执行、状态汇总 |
| 业务系统回环 | 外部回调、身份映射、业务上下文和主动通知 |

评估目标是识别平台通用能力，不把具体业务实现、接口或前端组件复制进 Runtime。

## 2. 共性需求

| ID | 需求 | 验收结果 |
| :--- | :--- | :--- |
| SC-1 | 结构化消息 | 文本、卡片、任务摘要和动作使用稳定语义投影 |
| SC-2 | 同消息更新 | 进度变化可以更新同一语义对象，不产生重复卡片 |
| SC-3 | 外部回调 | 回调完成签名、租户、幂等校验后准确路由目标 Pending |
| SC-4 | 定时超时 | 超时作为 scheduled Inbound 进入 Recovery，并走 Workflow 的超时动作 |
| SC-5 | 后台任务 | 长任务不阻塞 Session，对话可继续，完成后按序通知 |
| SC-6 | 多任务并存 | 一个 Session 中多个 Execution 状态互不污染 |
| SC-7 | 跨角色协作 | 不同用户/角色的输入通过明确身份与业务关联键进入对应 Session |
| SC-8 | 主动消息 | 通过授权、PolicyChain、SessionLog 和 Outbox 投递 |
| SC-9 | 业务上下文 | Agent 只把 Workflow 所需白名单参数写入 DispatchOrder |
| SC-10 | 自定义渲染 | 平台输出语义数据，集成方选择自己的视觉实现 |
| SC-11 | 可重建 | 服务重启后活动任务、Pending、进度与待投递结果可恢复 |
| SC-12 | 可审计 | 输入到结果按 rootInputId 关联持久业务因果；traceId 用于定位具体技术尝试 |

## 3. Runtime 能力映射

| 场景需求 | Harness 能力 |
| :--- | :--- |
| 消息、回调、超时和完成通知 | Unified Inbound |
| 长时生成与多个任务 | Multi-Execution Session Runtime |
| 等待申请人、审核人或外部系统 | PendingEntry、WakeIntent、Recovery |
| 后台完成通知 | recovery Inbound（稳定 source 判别值）、Session Outbox |
| 进度与终态 | ExecutionEvent 受控投影 |
| 业务参数 | DispatchOrder.params |
| 用户与角色连续性 | Session 绑定、ChannelIdentity、RelationshipState |
| 记忆与近期上下文 | ContextPipeline、MemoryPort、SessionLog |
| 外部 API | Tool 能力；ToolDeployment 绑定 Connector Provider |
| 定时与业务触发 | TriggerPort |
| 查询和取消 | ExecutionRegistry、WorkflowPortal |
| 重启恢复 | Execution Ledger、Inbox/Outbox 与 Registry 重建 |

## 4. 资料整理流程

### 4.1 目标流程

1. 用户向 Agent 提交资料整理任务。
2. Agent 校验权限和输入，后台 dispatch 资料整理 Workflow。
3. Workflow 发布 queued、started 和 step 事件。
4. Session Outbox 投递任务摘要，前端按 executionId 更新同一任务视图。
5. 用户可以继续对话或查询任务。
6. Workflow 完成后发布 completed，Agent 决定发送摘要、卡片或下一步动作。
7. 重复完成事件不重复生成结果消息。

### 4.2 必要能力

- background 执行模式；
- 任务摘要投影；
- 输出 sequence；
- 生成结果的结构化卡片；
- 外部副作用幂等；
- 失败、取消和 loop_terminated 的明确展示。

## 5. 申请确认流程

### 5.1 目标流程

1. 发起方 Agent 创建申请确认 Execution。
2. Workflow 经声明的 ToolCallNode 与 ToolPortal 调用已绑定 Connector Provider，完成业务读取或写入。
3. 需要申请人、审核人或外部系统确认时写 Pending。
4. 对应渠道输入通过统一身份映射进入目标 Session。
5. Recovery 根据 executionId/actionKey 精确恢复。
6. 多个 Pending 并存时，确定性动作精确路由；自由文本无法唯一命中时先澄清。
7. 超时生成 scheduled Inbound，并执行 Workflow 定义的超时分支。
8. 完成结果回注发起方 Session，Agent 决定通知内容。

### 5.2 边界

- 跨角色不等于共享 Session；每个 Session 仍绑定一个用户与 Agent。
- 业务关联使用显式 task/reference id，不通过消息文本猜测。
- 外部系统不能直接写 checkpoint 或执行状态。
- 一个角色的输入不能恢复另一个租户或无授权的 Execution。

## 6. 批量核验与批量任务

批量批量核验应拆成可独立观察的 Execution 或由一个 Workflow 内部管理的确定性子任务，两种方式不得同时保存权威状态。

选择原则：

- 需要独立取消、重试、通知和配额时，使用独立 Execution。
- 只在单个确定性流程内部聚合时，由 Workflow Runtime 管理子任务。
- 前端清单消费统一投影，不直接查询节点表。
- 批量完成汇总由 Agent 根据 BattleReport 和执行摘要生成，不从历史消息倒序拼接。

## 7. 外部业务系统回环

### 7.1 入站

外部系统调用回调入口时必须提供稳定回调标识、签名材料和幂等键。适配器只负责验证并生成 callback Inbound。

### 7.2 出站

平台调用外部业务系统时通过 Tool/Connector Provider，并传递 executionId/actionId 等稳定幂等键。凭证由 ConnectorInstance 管理，不进入 Workflow 包或模型上下文。

### 7.3 主动通知

主动通知先经过授权、频控、安静时段和退订策略。MVP-0 提供 TriggerPort 与策略扩展点，完整运营配置属于 P1。

## 8. 渲染契约

渲染对象、标识与直播/回放投影直接引用[API 与事件契约 §7](../02-架构与设计/04-接口与事件契约.md#7-渲染契约)。行业集成方选择视觉实现，并用稳定对象标识更新同一张进度卡；不重新定义执行状态。

## 9. 分期

### 9.1 MVP-0 底座

场景所依赖的输入、并行任务、挂起恢复、输出投递和重建能力直接引用 [Harness 01](../../harness-design/01-Agent-Workflow协作引擎-MVP需求分析.md) 与 [Harness 06](../../harness-design/06-MVP-0技术底座实施方案.md)。后台完成使用 Runtime 定义的 recovery 输入，不增加 completed 输入种类。

### 9.2 P1 产品化

- 回调注册、签名轮换和重试运营；
- 主动触达配置、频控、安静时段和退订；
- 增强语义唤醒；
- 任务运营视图；
- 行业 Persona、关系 schema 和记忆规则；
- 批量任务与跨角色体验配置。

P2/P3 能力按 [后续阶段需求](../../harness-design/04-后续阶段需求扩展-P1-P3.md) 管理，不由行业场景单独提前。

## 10. 验收场景

- 资料整理后台生成期间用户连续发送两条普通消息，回复与任务通知顺序稳定。
- 申请确认存在两个 Pending，点选只恢复指定 Execution。
- 用户文本同时匹配两个 Pending 时返回澄清，不随机恢复。
- 回调与超时并发时只有一个 CAS 成功。
- 外部回调重放不重复执行业务写入。
- 服务在 waiting_hitl 和 background execution 并存时重启，活动清单可重建。
- 跨租户伪造 executionId、sessionId 或 callbackId 被拒绝。
- 完成事件重复投递不产生第二条结果消息。
- 自定义前端与平台前端对同一语义投影得到一致状态。

## 11. 不采用的实现路径

- Callback Controller 直接调用 Workflow 恢复；
- Scheduler 直接修改执行状态；
- 用户通过 workflowId 直连 Workflow；
- Agent 或业务适配层拼装 pendingState/checkpoint；
- 用 Agent Group 表达跨角色任务；
- 用旧 Planner/ReAct 分支作为回环路由；
- 直接操作 SSE 连接实现可靠主动消息；
- Session 和 Workflow 同时保存执行权威状态。
