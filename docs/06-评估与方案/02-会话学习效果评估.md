# 会话学习效果评估

本文定义会话学习的实验方法，不构成功能完成或效果已验收的声明。产品要求见[会话学习需求](../01-产品与需求/05-会话话术与风格学习需求.md)，实现边界见[会话学习设计](../02-架构与设计/22-会话话术与风格学习设计.md)。

## 2. 学习方法与演进条件

### 2.1 首期：风格规则与示例检索

以人工确认的风格规则和脱敏优质示例建立基线。提取由受控模型任务辅助，审核后的材料通过现有 Agent 发布和知识检索消费。历史对话的作用是教会模型如何沟通，事实回答仍受当前有效知识约束。

### 2.2 离线提示词和示例优化

有稳定数据集、评价标准和可重复基线后再使用 离线优化器。优化范围限定在表达指令、示例组合和选择参数；医疗范围、权限、工具授权、数据隔离与预算不作为优化器可改写的变量。模型生成的合成示例标记来源并独立筛选，不能冒充真实人工记录。

优化器使用训练集生成候选，在开发集选型；最终候选只在锁定测试集验收。导出候选配置后经 Java Runtime 的真实渲染、知识检索和模型调用链验证。Python 程序内的提升不自动证明产品链路提升，评估工具也不直接改写线上发布指针。

### 2.3 可选微调

只有当检索与提示词方案仍存在可重复的风格缺口，或实际调用规模与测量成本支持专用模型收益时，才评估 LoRA/SFT。DPO 需要同一输入下经过确认的优劣回复对；坐席获得新信息后的修改不能直接用作偏好对。

训练材料来自经批准的脱敏数据，记录数据、模型、训练配置和评估版本。价格、活动、排班等易变事实继续检索，不固化为训练知识。部署、数据使用与后续撤销影响在专项批次评估；没有训练结果时不宣称学习已改变模型参数或可删除样本即遗忘。

## 3. 检索与模型实验

以现有平台模型和知识检索为基线，比较关键词、向量、混合检索及重排的边际收益。优先评估“费用异议、治疗顾虑、预约澄清、投诉升级”等相似词语但不同意图和阶段的困难样本，区分命中相似句子与找到可用沟通示例。

每路召回约 20 条、重排后注入 3～5 个互补示例，可作为首轮实验初值；它们不是生产默认、容量承诺或已验证最优值。按相关性、场景覆盖、去重、上下文预算和在线延迟选择最终参数，允许没有适用示例。

评估记录 embedding 模型及维度、关键词分析配置、融合方式、重排模型、召回数量、过滤条件和实际注入版本。排名分、相似度或模型自报置信度不当作事实正确概率，也不单独决定是否自动发送。

## 4. 效果评估方法

### 4.1 数据集与对照组

建议先构建覆盖核心场景的数百条人工确认样本；实际规模由场景、人员差异和统计不确定性决定，不以条数作为上线证明。保留人员、场景和接待阶段分布，并覆盖信息不足、过期知识、错误示范、作者未知、提示注入和跨租户负例。

按患者或完整会话分组划分训练、开发和测试集，同时保留较新的时间段做测试。近似重复片段不能跨集合；检索库、风格归纳和优化器只消费允许的训练材料，测试回答不能回流成为检索示例。数据版本和划分冻结后再比较方案。

| 对照组 | 变化 | 目的 |
|---|---|---|
| A | 现有 Agent | 建立当前真实链路基线 |
| B | A 加已审核风格规则 | 测量风格规则的独立作用 |
| C | B 加场景示例检索 | 测量示例与检索的增量价值 |
| D | C 使用 离线优化器 优化后的候选 | 判断离线优化是否在实际产品链路保留收益 |

初次 A/B/C 比较固定业务知识版本、基础模型、数据范围和评价规则；对有随机性的输出使用一致采样安排并报告波动。D 只在对应能力批次开展，不能用外部数据集成绩替代本地结果。

### 4.2 指标、评价者与发布判据

本节说明测量方法；业务通过要求归[CL-01–CL-12](../01-产品与需求/05-会话话术与风格学习需求.md#5-产品验收要求)。开始实验前确定场景权重、评分量表、允许的非劣界限、延迟和成本预算，之后不能根据结果改门槛来宣称通过；当前没有实测数值或已确定的数值门槛。

| 维度 | 测量方法 | 证据边界 |
|---|---|---|
| 风格一致性 | 隐去版本标识，服务负责人按语气、组织、长度、追问与场景适配评分 | 文本复制率不能替代沟通风格迁移 |
| 事实与医疗表达 | 对照当前知识和工具结果，医疗相关样本由相应负责人审核 | LLM 评分只能辅助筛查，不能作为唯一正确性依据 |
| 人工可用性 | 采纳、修改原因、修改时间及最终回复可用性 | 采纳或成交单项指标不能证明整体质量 |
| 检索有效性 | 标注相关示例，观察召回、重排和实际注入质量 | 读取或注入不等于模型真正使用 |
| 隐私与隔离 | 来源撤权、跨患者、跨租户、未知作者和删除传播用例 | 有限测试集无错误不表示生产绝对无风险 |
| 运行质量 | 正式链路的检索与模型延迟、用量、费用、失败和未知结果 | 本地、模拟与真实供应商结果分别记录，不以受理当作完成 |

如果引入 实验记录系统，数据集维护、实验评分与调用记录采用同一版本标识关联；本系统保留自身执行回执和批准记录。仅上报有明确用途的脱敏内容，遥测采集失败不阻断业务事实提交。不得通过评估平台扩大患者原文访问范围。

### 4.3 工程与场景验收

工程验收覆盖真实数据库权限和修订竞争、来源版本去重、撤销传播、进程中断恢复、内部建议不公开、正式发送幂等，以及后台学习与在线服务配额隔离。UI 验收覆盖设置、审核、发布状态、建议编辑发送和版本比较的完整旅程。

真实模型验收使用冻结数据与授权模型配置，记录任务、供应商回执、费用和停止边界。只读源码、链接检查和模拟模型用例不能证明风格效果；自动回复须按具体场景独立验收，人工辅助通过不自动授权自动发送。

## 5. 成本与部署评估

首期沿用 Java 服务及现有 PostgreSQL、检索设施和模型接入；脱敏和离线评估按需要增加内部处理进程，离线优化器 不进入患者等待回复的关键路径，实验记录系统 不作为发送或发布的权威存储。新组件只有在所属批次使用其能力时部署，避免为可选微调预置 GPU 训练集群。

离线成本按新增片段量、脱敏处理、提取调用和评估调用核算；在线成本按示例注入 Token、检索/重排和回复调用核算。扩展前对比每批处理成本、每次建议成本、人工修改时间及关键延迟分位数，不给出未经运行测量的节省比例或容量保证。
