# 代码执行与产物运行指南

代码执行边界与最终成果生命周期见[代码执行沙箱与产物交付](../02-架构与设计/12-代码执行沙箱与产物交付.md)。功能默认关闭，现有 Agent 不自动获得执行工具。

## 本地装配

全项目启动顺序、根环境导入、进程管理和验收统一遵循[开发与部署指南 §5.3](01-开发与部署指南.md#53-本地启动)。本节只维护沙箱与产物的专项配置；已有健康沙箱不重复构建，不在普通启动时轮换服务令牌或票据密钥。

需要 Java 21、Docker Engine 28 或更新版本，以及支持 `internal` 网络 `gateway_mode_ipv4=isolated` 的 Linux Docker 执行宿主。Windows 开发使用 Docker Desktop 的 Linux 容器。生产使用专用执行宿主；机构进程不持有 Docker socket。Sandbox 服务持有的 Docker 权限不能视为普通应用权限，控制面只对机构宿主开放。

1. 在 `backend-java` 执行 `./gradlew :skillforge-sandbox-service:bootJar`；Windows 使用 `.\gradlew.bat`。若 Windows 用户目录含中文导致 `GradleWorkerMain` 类加载失败，使用 `-g E:/gradle-cache --no-parallel` 指定现有英文路径缓存。
2. 复制 `deploy/sandbox/.env.example` 为同目录 `.env`，将 `SANDBOX_SERVICE_TOKEN` 替换为至少 32 个随机字符。该值只提供给机构服务与 Sandbox 服务。
3. 在仓库根目录执行 `docker compose --env-file deploy/sandbox/.env -f deploy/sandbox/compose.yml --profile runtime-images build`，再执行 `docker compose --env-file deploy/sandbox/.env -f deploy/sandbox/compose.yml up -d sandbox-service`。运行镜像在 Sandbox 服务初始化时解析并缓存为固定 image ID；任务过程中不临时拉取镜像。若只更新了 Python/Node 运行镜像，`up -d` 不会自动重建控制服务，须在活动执行结束后执行 `docker compose --env-file deploy/sandbox/.env -f deploy/sandbox/compose.yml restart sandbox-service` 并复验执行。
   任务记录格式发生不兼容变化且已获授权重建开发环境时，在沙箱 `.env` 中设置新的 `SANDBOX_TASK_VOLUME`，让控制服务与任务容器使用同一新卷；保留旧卷和旧镜像供回滚，不直接混读旧任务记录。
   固定运行依赖归 [运行镜像 Dockerfile](../../deploy/sandbox/runtimes/Dockerfile)。Python 镜像在构建时依据 [Docling 依赖锁](../../deploy/sandbox/runtimes/docling-requirements.txt) 和 [OpenCV 补充锁](../../deploy/sandbox/runtimes/docling-extra-requirements.txt) 安装精确 wheel，并执行 `pip check`；[模型下载脚本](../../deploy/sandbox/runtimes/download_docling_models.py) 依据 [模型锁](../../deploy/sandbox/runtimes/docling-models.lock.json) 核验固定布局、表格模型的大小与 SHA-256，同时安装 Tesseract 中英文词库。Node 镜像固定 `playwright-core@1.62.1`，构建时安装匹配的 Chromium 到 `/opt/skillforge/browsers`。镜像构建需要外网取得已锁定依赖和模型；任务执行使用离线本地模型与浏览器，不在任务中下载模型或浏览器。更新任一锁或运行依赖后，在活动执行结束后按本步骤重新构建、刷新 Sandbox 缓存的 image ID，并复验真实文档读取与离线网页检查；构建成功或镜像标签变化本身不代表控制服务已使用新镜像。
4. 为机构服务配置下表，启动机构服务。建立 PostgreSQL 新环境时执行完整 Flyway 链；不得将改写迁移直接覆盖未经处理的已有数据库。
5. 前端设置 `VITE_ARTIFACT_PREVIEW_ORIGIN` 与预览源一致后重新构建。管理员在 Agent 的 Tool 挂载中显式选择 `code_execute`，不必挂载 Skill。工具版本与字段以 [PlatformToolCatalog](../../backend-java/skillforge-core-capability/src/main/java/com/skillforge/core/capability/connector/PlatformToolCatalog.java) 为准；升级 Handler 后同时创建匹配版本的 ToolDeployment，并更新 Agent 挂载引用。发布目录新版本不会自动升级既有挂载，已受理输入仍使用冻结契约。旧契约在派发前返回 `platform_tool_contract_changed`，不得继续执行后才校验结果。先用 inline 生成 `/workspace/output/report.txt` 和 `/workspace/output/index.html`，同时声明 `output_files: ["report.txt", "index.html"]`，检查下载与预览。

机构也通过 Compose 运行时，显式合并 `deploy/docker-compose.java.yml` 与 `deploy/code-execution.compose.yml`；覆盖层将机构连接到已有的 Sandbox 控制网络，不向任务网络开放机构服务。基础 Compose 的 `artifact-files` 卷独立保存产物。前端 Docker 构建传入 `--build-arg VITE_ARTIFACT_PREVIEW_ORIGIN=...`。独立预览反向代理示例见 [`deploy/artifact-preview.nginx.conf`](../../deploy/artifact-preview.nginx.conf)，下载入口与预览路径都应关闭访问日志，防止泄露票据。

| 环境变量 | 约束或默认值 |
| :-- | :-- |
| `SANDBOX_ENDPOINT` | 控制面地址，本地为 `http://127.0.0.1:18200` |
| `SANDBOX_SERVICE_TOKEN` | 与独立服务一致，不进入任务容器 |
| `ARTIFACT_ROOT` | 独立持久目录，默认 `./data/artifacts`；不要指向 Sandbox 短期卷 |
| `ARTIFACT_TICKET_KEY` | 至少 32 个随机字符，用于签发预览 5 分钟、下载 1 小时的受限 URL |
| `PLATFORM_ORIGIN` | 平台页面源，例如 `http://localhost:3000`，不带路径和尾斜线 |
| `ARTIFACT_DOWNLOAD_ORIGIN` | 下载 API 源，本地可用 `http://localhost:8000`；默认回退到 `PLATFORM_ORIGIN`，该源必须能路由到下载 API |
| `ARTIFACT_PREVIEW_FRAME_ORIGINS` | 允许嵌入预览的额外页面源，逗号分隔；本地同时使用机构端与会话端时列出实际访问的 localhost／127.0.0.1 来源 |
| `ARTIFACT_PREVIEW_ORIGIN` | 独立主机名，例如 `http://preview.localhost:8091`，不能只换平台端口 |
| `ARTIFACT_PREVIEW_PORT` | 独立静态监听端口，例如 `8091`；默认 `0` 不监听 |
| `AGENT_RUNTIME_WORKER_LEASE_DURATION` | SDK 默认 `30s`；启用代码执行时显式配置为至少 200 秒，例如 `210s`；Handler 与 Worker 共用 `agent-runtime.worker-lease-duration` 绑定 |
| `SKILLFORGE_WEB_ALLOWED_ORIGINS` | 明确的平台 CORS 来源，逗号分隔；禁止通配符、`null` 和预览源 |

执行与传输容量由平台运营配置发布，在受理与调用时冻结；`ARTIFACT_RETENTION`、`ARTIFACT_TRANSFER_TIMEOUT` 环境变量不再是有效入口。默认值归 [ExecutionLimits](../../backend-java/skillforge-execution-contract/src/main/java/com/skillforge/execution/ExecutionLimits.java)，配置字段及范围归 [OperationalSettingsRegistry](../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/settings/OperationalSettingsRegistry.java)。

| 平台配置 | 默认值与约束 |
| :-- | :-- |
| `sandbox.execution_timeout_seconds` | 默认 900 秒，可配置至 3,600 秒，实际执行仍受根／Run 剩余时长和可信调用截止时间约束 |
| `artifacts.transfer_timeout_seconds` | 默认 900 秒，可配置至 3,600 秒；实际传输不得超过可信调用截止时间 |
| `artifacts.retention_days` | 候选产物默认 7 天，从完整发布时起算；正式成果与来源文件按 Session 保留 |
| `artifacts.max_files` | 默认 2,048；输入、输出与收集同时遵守执行传输契约的文件和字节限制 |

本地宿主运行的非敏感配置示例（写入根 `.env`；服务令牌和票据密钥另行生成并保存，不能直接复制示例令牌）：

```dotenv
SANDBOX_ENDPOINT=http://127.0.0.1:18200
ARTIFACT_PREVIEW_ORIGIN=http://preview.localhost:8091
ARTIFACT_PREVIEW_PORT=8091
PLATFORM_ORIGIN=http://localhost:3000
ARTIFACT_DOWNLOAD_ORIGIN=http://localhost:8000
ARTIFACT_PREVIEW_FRAME_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,http://localhost:3200,http://127.0.0.1:3200
AGENT_RUNTIME_WORKER_LEASE_DURATION=210s
```

机构端与会话端各自的 `.env.local` 设置 `VITE_ARTIFACT_PREVIEW_ORIGIN=http://preview.localhost:8091`。配置变更后确认 Vite 已重载，后端环境变更必须重启机构服务。平台运营配置 `sandbox.enabled` 与实际部署分别检查：工具已挂载、开关已开启也不能代替沙箱连接与产物配置。

平台页面 CSP 仅允许配置的预览源作为 iframe 目标，阻止产物通过自身 frame 导航向外发请求。预览监听器不提供平台 API，不接收 Cookie 或 Authorization。反向代理不得为预览源添加平台登录 Cookie，不得记录票据路径；保持 `Referrer-Policy: no-referrer`、CSP、`nosniff` 和 `no-store` 响应头。

## 执行与下载

脚本确定失败时，检查工具结果中的 `diagnostic`：`available` 表示同次执行经过保护检查的有界 stderr 尾部（最多 4,096 字符），结合退出码修改输入；同一参数错误不能靠原样重试解决。`unavailable` / `withheld` 表示诊断未取得或被隐藏，应明确缺口，不能猜测日志引用。日志计数不是可供模型读取的公开文件引用；完整日志仍留在内部，诊断不自动成为聊天公开过程。诊断读取失败不改变已知失败事实，不会重新执行脚本；未知结果继续遵循原有禁止盲目重放规则。

返回 `state=rejected`、`phase=admission` 表示该调用在提交执行前被拒绝；此时 `diagnostic.available` 提供稳定的 `code`、受控 `field`、中文 `message` 和 `hint`，并非 stderr。先修正明确字段，不继续修改尚未进入脚本的内容；例如 skill 携带 `code` 时应删除整个字段，不用空字符串、null 或 noop 占位。只按宿主受控文案显示“尚未执行”，不直接公开诊断。普通传输失败和执行结果未知不具备此语义，仍先查原任务。

`code_execute` 的模型参数包括模式、语言、代码或冻结脚本引用、结构化精确版本依赖，以及可选的 `artifact_inputs`、`input_files`、`output_files`。inline 无需 Skill，Node.js inline 使用 `.mjs` ES module 和 `import` 语法，必须省略 `skill_handle/script_path`；skill 必须是当前 input 已挂载并激活的精确包，并省略整个 `code` 字段，空字符串、null 和 noop 仍拒绝。冻结包的 `manifest.dependencies` 由宿主在内容与 SHA 校验后自动提供，可以省略 `dependencies`；显式提供只允许冻结清单中同名同版本子集，由宿主补齐，不允许额外依赖或覆盖版本。未声明 manifest 依赖的自定义 Skill 可继续显式提供精确依赖。Python 使用 wheel-only，Node 禁止安装脚本。依赖仓库只由执行服务管理员配置。最终输出写入 `/workspace/output`，通过 `output_files` 指定文件清单（资源目录可用 `assets/` 声明）；未声明不发布。仅成功执行交付文件，失败、取消或超时的半成品不发布。临时输入用 `input_files` 传入 `/input/data`，临时文件留在 `/workspace/work`。普通 `code_execute` 已知成功且无结果协议错误时，print/console.log 的 stdout 经宿主保护检查后最多返回 32,768 字符，供模型观察实际读取或计算值；被隐藏、不可用或截断的部分保持未知，assert 或显式抛错仍用于验证条件。宿主不把 stdout 自动展示为公开工具结果或正式成果，助手可依据实际观察解释业务值；stderr 保持既有失败诊断边界。需要公开业务文字或表格时，可将类型化结果写入固定 `/workspace/output/result.json`，成功后自动返回，无需另传路径参数；该保留文件不能列入 `output_files`，文字项的format仅为plain或markdown，JSON业务值先序列化放入text且format仍为plain；结构与公开边界见[执行传输与业务结果](../02-架构与设计/12-代码执行沙箱与产物交付.md#41-执行传输与业务结果)。最多收集 2,048 个普通文件，单次传输总量 1 GiB；公开检查、运行及磁盘资源限制继续生效。

每次调用使用独立工作目录。复用本会话此前生成的文件时，传入 `artifact_inputs: [{"artifact_id":"真实产物 ID","path":"records.json"}]`，代码从 `/input/artifacts/<artifact_id>/records.json` 读取。产物结果的 `paths` 给出可选择的清单内相对路径；单次最多选择 2,048 个文件，只读输入不能覆盖，修改后写到本次 `/workspace/output`。跨会话、已过期、清单外路径或摘要不匹配均拒绝；文件不存在或外部来源失败时应报告缺失来源，不能编造替代数据。

需要跨轮次续接产物时，同时为 Agent 部署并挂载 `list_artifacts`，工具版本以 PlatformToolCatalog 为准。该只读工具从可信调用身份限定当前租户和会话，分页返回有效产物的 ID、来源 Run、文件路径、大小及摘要，不返回正文或访问票据。已有上下文包含准确清单和版本时可直接选用 `artifact_inputs`；需要查找、复用或修改已有产物而信息不足时再查询，不把查询写成每个 Skill 的固定步骤，不能靠搜索新沙箱目录发现历史文件。`offset` 默认 0，`limit` 默认 30、最大 100；按到期时间和 ID 稳定排序，`has_more` 只表示可以继续分页，当前请求已满足即停止。清单只证明产物存在，数据真实性仍须对照原始来源。

工具清单先按原租户、会话、公开检查、就绪状态及文件可读性计算有效集合与总数，再按页读取材料；被正式引用保护的文件继续按原保留规则判断。仅对本页产物清单和来源输入执行摘要校验，本页损坏仍拒绝，页外材料损坏在选中该页或实际读取时报告，不阻断其他页。当前正式成果 `current_deliverables` 独立返回，不随产物页裁剪。用户展示的全量产物清单及单文件、票据、实际读取的权限与完整性检查保持各自原合同。

需要程序化组合工具时，为目标 Agent 显式发布并挂载 `run_code builtin:16`；需要按需发现时再挂载 `search_tools builtin:1`。机构服务和 Sandbox 必须同时部署支持程序 RPC 的版本；`run_code` 参数为 `code`、可选 `dependencies`、`artifact_inputs`、`input_files`、`output_files`，语言固定为 Node，无需手动导入内置 `tools`。例如先用 `const result = await tools.call('tool:实际已显示句柄', {});` 取得工具结果；需要向模型返回时，将最小必要业务值写入固定 `/workspace/output/result.json` 的类型化 `results`。stdout 不是返回通道。使用请求所需的最小摘要，生成文件仍写入 `/workspace/output`；未知结果先查看历史执行记录，不能整体重跑程序。

发布后使用只读[组合检查脚本](../../tools/runtime/check_agent_readiness.py)核对每个目标 Agent，例如 `python tools/runtime/check_agent_readiness.py --agent-id AGENT_ID --required-tool run_code --required-tool search_tools`；多个 Agent 重复传入 `--agent-id`。凭据从本地环境读取。报告 `ready=true` 只证明工具发布与挂载组合一致，不能代替沙箱连接、镜像和网络隔离验证。

Sandbox 控制面以 Bearer 认证保护 `POST /internal/executions/artifact-inputs`、`GET /internal/executions/detail?taskId=TASK_ID`、`DELETE /internal/executions/delete`（JSON 请求体 `{"taskId":"TASK_ID"}`）、`GET /internal/executions/files?taskId=TASK_ID` 与内部日志分页 `GET /internal/executions/logs?taskId=TASK_ID&stream=stdout&offset=0&limit=32768`。所有代码与 Workflow 输入共用类型化流式 ZIP，首项 `request.json` 元数据最多 16 MiB，文件正文合计最多 1 GiB，不嵌入 JSON。同任务重复提交只返回原事实，参数变化拒绝；断线、恢复与重启不能重新运行代码。取消仅确认后续执行停止，不撤销已发生的公网副作用。

机构服务与 Sandbox 必须部署同一内部协议版本。执行控制 JSON 使用 `taskId`、`programTools` 等 camelCase 字段，所属 DTO 固定命名；宿主公开 API 的 snake_case 设置不能改变内部传输。收到类型化 `submission=NOT_SUBMITTED` 准入回执时，宿主据实记录“请求未提交执行”；普通 HTTP 400/500、断线或超时仍需查询原任务状态，结果未知时不得重新提交整段代码。准入回执范围与错误类型见[执行传输与业务结果](../02-架构与设计/12-代码执行沙箱与产物交付.md#41-执行传输与业务结果)。

机构 API 通过以下接口提供候选执行产物，供查找、复用和定向恢复：

- `GET /api/v1/chat/sessions/artifacts?sessionId=SESSION_ID`：受控元数据与清单。
- `POST /api/v1/chat/artifacts/download-ticket`：`{"id":"ARTIFACT_ID","payload":{"path":"report.txt"}}` 下载文件，`{"id":"ARTIFACT_ID","payload":{"zip":true}}` 下载完整目录。
- `POST /api/v1/chat/artifacts/preview-ticket`：请求体 `{"id":"ARTIFACT_ID"}`，静态网站预览入口。
- `GET /api/v1/chat/artifact-content/detail?ticket=TICKET`：浏览器原生流式附件读取，不能由前端先缓冲 Blob。

候选产物票据签发与下载进入审计记录，票据本身不进入普通日志或模型。签发票据前检查当前成员状态、角色、Session 租户归属和到期状态；机构成员必须仍处于 active，且具有 admin、developer、operator 或 auditor 角色。签名 URL 不代表登录身份，预览和下载服务只按签名范围、有效期、文件状态与撤权状态放行，不能把 URL 请求当作机构成员重鉴权。外部渠道和 Open Platform 主体不能冒充机构成员申请这些票据。

### Skill 导入与执行准备

通过现有 Skill 工作台导入目录或 ZIP，并保留上游 `SKILL.md` 和配套资源的原始内容。平台 `versionKey` 标识平台发布版本；上游 `metadata.version` 属于包内容，可以不同或缺省，不要求为接入平台改写它。包校验通过只证明格式和平台发布配置有效，不证明任意 Agent 已具备运行环境。

查看工作台校验结果，区分阻止发布的 `ERROR`、不支持声明的 `WARNING` 和未验证环境的 `INFO`；警告不阻止合法专业内容发布。声明 `allowed-tools` 或 `compatibility` 不会自动挂载工具、安装依赖或取得凭据。导入和加载不自动执行包中的 hooks、内联命令或初始化命令，也不以工具名称字符串替换伪装适配完成。

新 Run 激活后，按 `resourceIndex` 中的准确相对路径读取需要的参考、模板、输入示例或脚本；`resourceAccess` 指明使用既有 `read_skill_resource` 读取冻结包内容。索引属于冻结包资源，不是宿主或会话目录；已有正文不重复读取，不为了使用设计指导而强制运行生成器。目录的 `active_in_current_run` 表达当前 Run 状态，历史激活不代表本轮已激活。索引中的脚本语言只是文件事实，是否可执行以实际已授权工具、支持的语言和依赖准入结果为准；读取成功不等于执行就绪。

Python、Node 包内脚本可使用 `code_execute(mode=skill)` 的冻结脚本与依赖路径；需要 Bash 访问整包资源时，在已授权的 `workspace_exec` 中传当前已激活的 `skill_handle`，命令通过 `$SKILL_DIR` 读取只读包。目录保持原相对结构，限本次容器使用；Shell 不自动安装声明依赖，不承诺已有镜像之外的语言或程序。已知执行回执中的 `skill_resource_base` 只描述本次真实挂载位置，不能用于后续调用或当作宿主路径。出现准入拒绝时先修正原因；结果未知不重跑原命令。

### 官方 Skill 独立发布与采用

系统启动不安装任何 Skill，技能目录可以为空。[官方技能包](../../official-skills/README.md)独立构包和发布，不进入后端生产 JAR。平台人员在能力目录创建 Skill 定义，通过技能工作台编辑或导入 ZIP、校验、发布新版本，再由机构或 Agent 采用；具体构包与发布入口见[工具指南](../../tools/skills/README.md#确定性构包与显式发布)。已发布版本不可原地覆盖，切换默认版本不改写已固定版本的挂载，已接纳 Run 继续消费原冻结版本。系统升级不安装、覆盖或删除已有 Catalog 技能及挂载。

输出 Skill 维护专业方法、自带脚本输入与资源用法，平台统一提供执行和交付协议。主 Agent 直接理解用户任务、当前 Goal 与适用批准计划，按需选择已授权 Skill；生成和收集不以独立要求解释、任务预分类或首轮 requirements 为前置。生成与修改文件后，用 `output_files` 收集受管候选，检查后以 `finalize_task_outputs` 提交完整选择，由宿主核验所选真实对象、冻结并在 Run 成功后发布；候选不自动成为正式交付。Skill 的默认格式是任务建议，主 Agent 负责遵循用户与适用计划要求并检查质量，宿主不再用自然语言义务契约证明其已完整满足。脚本与声明依赖随 Skill 发布，新增浏览器、OCR、原生库等能力仍须准备对应沙箱环境；移出预置包不自动缩小镜像。执行与交付工具应按当前 PlatformToolCatalog 的精确版本与 Handler 一同部署，旧挂载须显式升级。

### 最终成果发布

文件交付按以下顺序执行：

1. 按用户任务直接生成并检查文件，用 `code_execute.output_files` 收集实际候选，不预先登记成果计划。候选可供后续受控读取，不等于最终必须交付；临时文件、日志和仅作校验的材料不混入正式文件。
2. 内容与格式检查完成后，一次调用 `finalize_task_outputs` 提交完整 `deliverables`，每项填写 `key`、`title`、`kind`、可选真实 `base_revision_id` 和 `representations`。修改同一成果沿用原逻辑键；模型不传决策来源、消息来源或 `required`。宿主核验明确选中的文件、归属、格式组合、来源、版本及预算，不重新解释任务或证明自然语言义务已穷尽；主 Agent 依原任务决定最终选择并如实说明未完成项。保证范围见[宿主成果契约](../02-架构与设计/12-代码执行沙箱与产物交付.md#8-多形态成果与官方-skill-package)。
3. 表示使用 `source`、`export`、`bundle`；`source_files` 引用真实转换输入，HTML 指定 `entry_path`，每项成果恰有一个 `primary_preview`。宿主核验实际文件、冻结完整选择并预留目标；拒绝时修正完整选择，无法交付则明确 `abandon_reason`。
4. `finalize_task_outputs` 成功后只发送最终回复，不再调用工具。对应 Run 真实成功且报告引用匹配 task result 后，宿主在同一事务发布结果、不可变 Revision、表示、来源和当前 Revision 指针。失败或取消释放预留；SSE 重连只重发持久事件，不重跑执行。

用户需要原始文件时按每个文件下载。没有明确格式要求时可选 Markdown 文档，网站优先单体 HTML，将必要样式、脚本和静态资源内联；也可将入口和全部本地引用资源作为同一 `source` 表示提交，宿主逐文件检查并核验资源闭合，默认不依赖 CDN。明确单文件要求必须内联，“单页”不等于单文件。Word、PDF、ZIP 或其他导出格式按用户要求纳入最终交付选择。内容、文件集合、入口或下载名改变时生成新 Revision；同一轮草稿、验证证据和预览变化不生成新版本。每项成果恰有一个 `primary_preview=true`，HTML 的 `entry_path` 必须匹配所选真实入口；`bundle` 仅用于 ZIP，导出 `export` 必须提供并核验实际转换的 `source_files`。清单中的确定性字段组合错误在预留、持有文件或冻结之前合并反馈，修正全部所列字段后重提完整清单。

ZIP 表示的压缩包根目录必须包含 `manifest.json`。`files` 逐项列出包内除 manifest 外的所有文件，`entry` 为可选入口路径，`includes_originals` 必须为 `true`：

```json
{
  "files": [{"path": "...", "sha256": "...", "bytes": 123}],
  "entry": "...",
  "includes_originals": true
}
```

`sha256` 使用 64 位小写十六进制，`bytes` 与实际解压后字节数一致；非空 `entry` 必须出现在 `files` 中。缺少 manifest、漏项、多项、摘要或大小不符、路径不安全、未包含原始文件都会拒绝冻结。

正式成果列表和票据使用以下接口，成果卡片不能沿用候选产物的 `/artifacts/*-ticket`：

- `GET /api/v1/chat/sessions/deliverables?sessionId=SESSION_ID`：读取当前正式 Revision；需要历史版本时增加 `includeHistory=true`。
- `POST /api/v1/chat/deliverables/download-ticket`：请求体 `{"id":"REVISION_ID","file_id":"FILE_ID"}`，为精确 Revision 文件签发下载票据。
- `POST /api/v1/chat/deliverables/preview-ticket`：请求体同上，为精确 Markdown、文本或 HTML 表示签发预览票据。
- `GET /api/v1/chat/deliverable-content/detail?ticket=TICKET`：流式读取非 HTML 成果；HTML 使用预览票据返回的隔离源 URL。
- `POST /api/v1/chat/deliverables/recovery-inputs`：请求体 `{"revision_id":"REVISION_ID"}`，重新鉴权当前 Revision 并返回下一轮可用的 `artifact_inputs` 和 `base_revision_id`。

正式成果票据绑定 Revision、表示和文件；使用时重新核验当前 Session、请求主体和底层候选文件权限。默认预览票据 5 分钟、下载票据 1 小时，撤权后即使票据未过期也拒绝访问。

验收先覆盖计划、候选、冻结、发布、版本、下载、撤权和失败释放的业务接口，再运行一次最小无头浏览器测试，确认隔离预览 CSP 使用哈希许可内联内容且不包含 `unsafe-inline` 或 `unsafe-eval`。上述为目标成果发布操作契约；实际接口、配置和部署可用性以对应版本实现为准。

## 容量、清理与恢复

监控执行卷、产物持久卷剩余空间和 inode、staging 积压、执行容器数量，以及 `产物清理失败`、`任务产物收集失败` 等失败事件。文件正文以固定缓冲流式传输，网关默认路由不使用响应体聚合过滤器；multipart 的 Skill 导入大小限制不作用于下载与内部 ZIP 响应。

机构每小时清理到期候选产物与独立证据，默认保留 7 天；正式 Revision 的交付文件及 `source_files` 来源文件随 Session 保留，不按候选到期规则处理。冻结中的交付文件、来源文件和证据文件由 hold 阻止清理；清理器锁定文件后还会重新核对 hold、正式交付引用、正式来源引用和有效证据，清理与发布竞争时先保留再重试。超过一天的 staging 与没有发布元数据的 ready 孤儿目录可回收。Sandbox 每小时清理已确认静默且超过默认一天保留期的工作目录，持久任务身份继续保留，重复请求不会重新执行。Sandbox 重启先确认遗留受管容器已停止，再将原未完成任务保留为 unknown，不重放代码；未知结果不能收集或下载产物。不要直接删除正在运行任务的工作目录。

备份时暂停新执行，等待运行任务收敛，然后一致备份 PostgreSQL 的 `nw_execution_artifacts` 元数据与 `ARTIFACT_ROOT`；独立备份任一侧不能证明可恢复。恢复到新环境后核对目录清单摘要、租户成员与 Session 归属，继续执行原到期时间，不能通过恢复延长保留期。票据密钥轮换使旧票据失效，不改变产物本体。

关闭功能时，通过平台运营配置发布 `sandbox.enabled=false`，停止新受理任务获得执行能力；已经受理的任务保留原冻结配置，停止 Sandbox 服务前等待或取消当前任务。保留产物卷、元数据与预览配置，已授权且未到期的历史产物仍可访问。不要执行带 `--volumes` 的 Compose 删除命令作为普通停用步骤。
