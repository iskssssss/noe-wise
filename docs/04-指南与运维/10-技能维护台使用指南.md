# 技能维护台使用指南

机构管理员、开发者在机构端维护自有技能；平台管理员在平台端维护公共技能。维护台的草稿与发布规则见[技能维护台设计](../02-架构与设计/15-技能维护台设计.md)。

## 创建与编辑

1. 机构端进入“技能工作台”，平台端进入“Skill 工作台”，点击新建技能入口，填写标识、名称和说明后，一次创建并进入工作草稿，再编辑技能包。该操作需要同时具备能力创建和技能草稿创建权限；平台端创建公共技能，不提供选择或覆盖机构的字段。已有自有技能可直接打开活动草稿；查看自有历史版本时可以从该版本创建草稿，机构端的平台公共版本只读。
2. 在工作草稿中导入 ZIP 替换当前文件，或按包内相对路径新建文件；新建技能表单不上传包。入口文件为 `SKILL.md`，脚本、参考资料、模板和字体按包内相对路径放置。当前工作台没有独立目录导入或单文件上传入口。
3. 在文件树中选择文件进行编辑；工作台按扩展名区分文本与其他文件，其他文件显示其 Base64 内容，不提供二进制文件的单独上传替换。需要更换二进制资源时，准备完整 ZIP 并导入；导入会替换草稿文件，先处理未保存修改。维护台不执行包内脚本、网页或字体。
4. 点击“保存草稿”。入口或 frontmatter 尚未完成时也可保存，但不允许路径穿越、编码错误或超出包限制。关闭页面前处理未保存提示。

文件树根据文件的相对路径按目录分级显示，点击目录可展开或折叠。“新建文件”填写相对于包根的路径，例如 `scripts/main.py`；当前没有独立的新建目录按钮。文件树来源于文件清单，不单独保存空目录。

## 校验与发布

填写版本号与宿主配置，保存后执行校验，根据问题位置修正 `SKILL.md` 或配置。发布会重新校验所保存的内容；保存成功并不表示包可执行。

平台发布版本号与 `SKILL.md` 中包作者的 `metadata.version` 相互独立。导入 ZIP 后，在发布设置中填写平台版本号并保存，再校验和发布；不需要为了平台版本改写上游文件。已有 Catalog 版本草稿的编号固定；从已发布版本创建草稿时，平台版本号会清空，需要填写新的编号。版本名称与描述来自 `name`、`description`；`compatibility`、`metadata.homepage` 属于包说明，不自动转换成权限或依赖。

发布后包内容只读。修改已发布技能时从版本开启新草稿并填写新版本号；维护已有版本草稿时保留原版本号。机构端查看已选发布版本时可下载技能包；当前平台工作台没有下载或文件差异对比入口。

需要在执行任务前先提交结构化计划的技能，在现有文件编辑器中为 `SKILL.md` 的 frontmatter 增加以下声明：

```yaml
metadata:
  skillforge-plan: "required"
```

仅接受字符串 `required` 或 `optional`，区分大小写且不允许首尾空白；未声明时为 `optional`。校验和发布会拒绝其他值。该要求随发布包冻结；修改新草稿不会改变已发布版本或正在恢复的执行。版本详情展示从该版本包解析的计划要求。正文继续描述步骤如何拆分、预期产物和核查要求；编号列表或“必须先计划”等正文表述不会自动变成系统约束。

切换当前发布版本不会改写已受理 Run 的冻结包。新执行使用的版本取决于 Agent 的配置和绑定方式：机构公共 Agent 部署的资源槽位按能力定义解析当前发布版本；其他已发布配置的变更需按其挂载与发布流程核对，不能将已有 Run 的版本推断为新执行的版本。脚本执行还需相应工具授权和运行环境，见[代码执行与产物运行指南](09-代码执行与产物运行指南.md)。

## 冲突与恢复

机构端与平台端新建技能成功但页面跳转失败时，使用原创建结果的入口继续编辑，不再次创建。新建请求超时或断连、结果尚未确认时，页面保留原请求身份并冻结重复提交；使用“核对创建结果”只读查询该请求的回执。同一标签页刷新后，在当前主体具备技能读取权限时页面会尝试核对；尚未查到回执仍是未知结果，列表中的同名或同标识对象不能证明原请求成功。确定拒绝时保留输入并按提示修正；Definition 或草稿任一步失败由服务端整体回滚，不采用“定义已创建、继续补草稿”的两阶段重试。新建只产生定义和空工作草稿，导入、校验和发布仍在工作台分别完成；具体接口与 scope 见[技能维护台设计](../02-架构与设计/15-技能维护台设计.md#4-接口)。

多人同时保存时，旧 revision 会收到冲突提示，本地编辑内容保留。当前没有下载未保存草稿的入口；重新加载前应先将需要保留的本地修改另行保存，再读取服务端内容并手动合并，不能将重新加载当作自动合并。包文件和宿主激活配置均需核对。

网络故障后先重新读取草稿状态；相同草稿 revision 的重复发布返回既有发布结果。发布失败时编辑草稿保留，不会留下半发布版本。发布成功后仍不能挂载时，应检查版本状态、Agent 授权和激活预算。
