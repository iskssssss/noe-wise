# 技能维护台使用指南

机构管理员、开发者在机构端维护自有技能；平台管理员在平台端维护公共技能。维护台的草稿与发布规则见[技能维护台设计](../02-架构与设计/15-技能维护台设计.md)。

## 创建与编辑

1. 机构端进入“技能工作台”，平台端进入“技能维护台”，点击新建技能入口，填写标识、名称和说明后，一次创建并进入工作草稿，再编辑技能包。该操作需要同时具备能力创建和技能草稿创建权限；平台端创建公共技能，不提供选择或覆盖机构的字段。已有自有技能可直接打开活动草稿；查看自有历史版本时可以从该版本创建草稿，机构端的平台公共版本只读。
2. 在工作草稿中独立导入目录或 ZIP，也可以直接新建文件；新建表单不上传包。入口文件为 `SKILL.md`，脚本、参考资料、模板和字体按包内相对路径放置。
3. 在文件树中选择文本文件进行编辑；二进制文件使用上传替换或下载，维护台不执行包内脚本、网页或字体。
4. 点击保存草稿，或按 Ctrl/Cmd+S。入口或 frontmatter 尚未完成时也可保存，但不允许路径穿越、编码错误或超出包限制。关闭页面前处理未保存提示。

文件树按目录分级显示，点击目录可展开或折叠。选中目录后输入名称或相对路径，使用“新建目录”“新建文本”或上传文件；点击“包根目录”可回到根目录新增。新建空目录通过空的 `.gitkeep` 文件保留，保存、刷新和导出均不会丢失；目录内有实际文件后可删除该占位文件。

## 校验与发布

填写版本号与宿主配置，保存后执行校验，根据问题位置修正 `SKILL.md` 或配置。发布会重新校验所保存的内容；保存成功并不表示包可执行。

平台发布版本号与 `SKILL.md` 中包作者的 `metadata.version` 相互独立。导入 ZIP 后，在发布设置中填写平台版本号并保存，再校验和发布；不需要为了平台版本改写上游文件。已有 Catalog 版本草稿的编号固定；从已发布版本创建草稿时，平台版本号会清空，需要填写新的编号。版本名称与描述来自 `name`、`description`；`compatibility`、`metadata.homepage` 属于包说明，不自动转换成权限或依赖。

发布后包内容只读。修改已发布技能时从版本开启新草稿并填写新版本号；维护已有版本草稿时保留原版本号。可以查看相对基础版本的文件变更和文本差异，也可以下载已发布包。

需要在执行任务前先提交结构化计划的技能，在现有文件编辑器中为 `SKILL.md` 的 frontmatter 增加以下声明：

```yaml
metadata:
  skillforge-plan: "required"
```

仅接受字符串 `required` 或 `optional`，区分大小写且不允许首尾空白；未声明时为 `optional`。校验和发布会拒绝其他值。该要求随发布包冻结；修改新草稿不会改变已发布版本或正在恢复的执行。版本详情展示从该版本包解析的计划要求。正文继续描述步骤如何拆分、预期产物和核查要求；编号列表或“必须先计划”等正文表述不会自动变成系统约束。

设置默认版本不会自动升级 Agent 的精确挂载；需要使用新版本时到 Agent 的能力挂载配置中显式更新。脚本执行还需相应工具授权和运行环境，见[代码执行与产物运行指南](09-代码执行与产物运行指南.md)。

## 冲突与恢复

机构端与平台端新建技能成功但页面跳转失败时，使用原创建结果的入口继续编辑，不再次创建。新建请求超时或断连（包括网络错误、408 或 5xx）、结果尚未确认时，保留原输入并冻结重复提交，通过只读列表核对；列表中的同名或同标识对象不等于原请求回执，不自动重发创建。确定拒绝时保留输入并按提示修正；Definition 或草稿任一步失败由服务端整体回滚，不采用“定义已创建、继续补草稿”的两阶段重试。新建只产生定义和空工作草稿，导入、校验和发布仍在工作台分别完成；具体接口与 scope 见[技能维护台设计](../02-架构与设计/15-技能维护台设计.md#4-接口)。

多人同时保存时，旧 revision 会收到冲突提示，本地编辑内容保留。先下载本地包备份，再重新加载服务端内容并合并自己的修改；不要将重新加载当作自动合并。ZIP 备份包含包文件，宿主激活配置需自行核对。

网络故障后先重新读取草稿状态；相同草稿 revision 的重复发布返回既有发布结果。发布失败时编辑草稿保留，不会留下半发布版本。发布成功后仍不能挂载时，应检查版本状态、Agent 授权和激活预算。

## 部署

新表通过 V162 Flyway 迁移创建，发布前应让当前完整迁移链成功执行；无需修改既有技能包、版本或 Runtime checkpoint。本文不授权部署或数据清理。
