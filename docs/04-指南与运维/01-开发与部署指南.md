## 1. 当前状态与范围

仓库包含 Java 后端（Spring Boot 3）、三个 Vue 3/Vite 前端、Flyway 迁移、
Docker Compose、CI 和 Helm chart。部署清单提供可审查的配置，仍须在目标环境
完成镜像构建、数据库迁移和验收；本文不把文档视为已完成生产发布的证据。

仓库当前处于预发布阶段，Agent Runtime 正按 [MVP-0 实施方案](../../harness-design/06-MVP-0技术底座实施方案.md) 重构。旧入口或旧表能运行不代表目标底座已完成，实现及支持范围需核对当前源码与对应候选的验证。

SDK 与平台模块应分别验证独立发布、PostgreSQL/SQLite 构件消费、平台领域、双宿主启动、签名回调恢复与重点接口；这些检查不自动覆盖全仓 CI、真实模型供应商或生产部署。使用当前目标迁移链的环境前提见 [§3.1](#31-sdk-数据库初始化)。

数据服务由 PostgreSQL（含 pgvector）、Redis 和 Elasticsearch 提供。它们可以
通过开发 Compose 启动，也可以由平台或机构在生产环境外部托管。

## 2. 当前技术栈

版本与组件以 [ADR-005](../05-架构决策/005-技术栈版本锁定.md) 为依据；实现和
部署范围如下：

| 领域 | 锁定选择 |
| :--- | :--- |
| 后端 | Java 21 + Spring Boot 3 + Spring Cloud Alibaba + MyBatis-Plus |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus（`frontend-admin` / `frontend-platform` / `frontend-chat`） |
| 编排 | 应用内 Agent Runtime + Workflow Runtime；边界以 Harness Design 为准 |
| API | Spring MVC + record DTO；OpenAPI（springdoc） |
| 数据 | PostgreSQL 16 + pgvector + RLS；Redis 7.x |
| 迁移 | 平台完整 Flyway 历史（`backend-java/skillforge-migration`）；独立 SDK 使用 JDBC 适配器自有 Runtime schema |
| 队列 | Redis（无 Celery；后台任务使用 Spring 调度） |
| LLM | 平台模型目录维护 Provider、端点、认证、加密凭据、能力和计价版本；机构只选择平台模型引用 |
| 身份 | 机构 JWT 使用 `SECRET_KEY`，平台登录 JWT 使用独立的 `PLATFORM_SECRET_KEY` |
| 密钥 | 平台与机构宿主共享 `SECRET_KEY` 以加解密平台模型等跨宿主业务密文 |
| 可观测 | OpenTelemetry → OTLP；日志采集 **Grafana Alloy**（非 Promtail） |
| 网关 | Spring Cloud Gateway（`skillforge-gateway`，8080）按路径分发 |

Keycloak、Kong 和 Vault 都不是当前部署的必需或已部署组件。Code Node、script 节点与 Sandbox 已有实现；是否启用由对应服务和 Agent Tool 配置决定，部署检查与功能验收分别按[代码执行与产物运行指南](09-代码执行与产物运行指南.md)执行。联邦学习仍待架构设计。

### 3.1 SDK 数据库初始化

独立使用 SDK 的宿主按 [Runtime 交付边界](../../harness-design/02-微内核插件架构实现思路.md#14-agent-runtime-sdk-交付边界)选择适配器并提供身份、授权、模型绑定与能力等必需端口。Spring Boot Starter 只装配 SDK 组件，平台默认配置由 `skillforge-*` 宿主组合根提供。

PostgreSQL 宿主先创建目标数据库并配置驱动、`DataSource` 和角色，再显式调用 [RuntimeJdbcSchema](../../backend-java/agent-runtime-adapter-jdbc/src/main/java/com/skillforge/runtime/adapter/jdbc/schema/RuntimeJdbcSchema.java)。适配器构造与 Starter 启动不安装数据库，不能据此期待缺表自动修复。

| 场景 | 操作与前置条件 |
| :-- | :-- |
| 新建空库，或与当前目标链一致的已纳管 Runtime | 用初始化 `DataSource` 调用 `install`；连接须有创建 Runtime 对象和安装 pgvector 扩展的权限，已有库须先核对迁移链适用性 |
| 启动前预检 | 调用 `validate`，只读核对 Runtime 结构；差异由部署负责人确认，不自动补齐 |
| 已有完整 Runtime 结构且尚未纳管 | 维护窗口停止其他 DDL/迁移，以至少支持两条连接的初始化 `DataSource` 显式调用 `adopt`；接管在表锁内严格核对结构，任何差异拒绝，不静默 baseline |
| 正常执行 | 提供非超级用户、`NOBYPASSRLS` 应用角色及必要对象权限，按宿主身份与租户上下文执行 |

Runtime 使用适配器自带迁移位置和独立 `agent_runtime_schema_history`，不执行平台 Flyway 资源；平台使用 `skillforge-migration`。SDK 与平台的业务表命名空间、元数据例外见[数据库规范](../../.agents/skills/nw-database/references/database-modeling-standards.md#21-sdk-与平台存储命名空间)。平台数据库若保留不同的宿主函数或 trigger，会被严格结构检查拒绝，不能只凭 Runtime 表已存在直接接管。

名称统一采用目标初始化与迁移全链同步方案。重写后的历史链仅用于新建或另行明确授权重建的环境，不能直接升级既有开发库或生产库；启动当前构件不代表已获得现有库迁移授权。已有环境先核对 schema、Flyway 历史与构件适用性，未满足时停止依赖该库的新版本启动，不修改旧 checksum、不静默 baseline，也不自动执行 `install`、`adopt`、清理或重建。本轮变更不自动升级当前数据库，环境地址和角色仍以 [§5.3.2](#532-环境与依赖)的已配置值为准。

## 4. 环境变量表

后端通过 Spring Boot 绑定这些变量。`.env.example` 是本地模板；生产环境从
受控的 Secret 或密钥管理系统注入。

### 4.1 应用与运行

| 变量 | 必填 | 示例 / 默认 | 说明 |
| :--- | :--- | :--- | :--- |
| `INSTITUTION_SERVICE_PORT` | 否 | `8000` | 机构服务端口 |
| `PLATFORM_SERVICE_PORT` | 否 | `8100` | 平台服务端口 |
| `GATEWAY_PORT` | 否 | `8080` | 网关端口 |
| `DEBUG` | 否 | `true` | 调试模式 |

### 4.2 数据存储

| 变量 | 必填 | 说明 |
| :--- | :--- | :--- |
| `SPRING_DATASOURCE_URL` | 是 | `jdbc:postgresql://.../skillforge` |
| `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD` | 是 | 机构服务数据库账号（受 RLS 约束） |
| `SPRING_FLYWAY_USER` / `SPRING_FLYWAY_PASSWORD` | 是 | 两个宿主共用的迁移对象 owner，独立于机构运行账号 |
| `PLATFORM_DATASOURCE_USERNAME` / `PLATFORM_DATASOURCE_PASSWORD` | 是 | 平台服务数据库账号（`skillforge_platform`，BYPASSRLS） |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DATABASE` | 是 | Redis 连接 |

### 4.3 安全与身份

| 变量 | 必填 | 说明 |
| :--- | :--- | :--- |
| `SECRET_KEY` | 是 | 机构 JWT 签名及跨宿主业务数据加解密密钥；平台服务与机构服务必须配置为同一值，仅安全注入，禁止入库 |
| `PLATFORM_SECRET_KEY` | 是 | 平台登录 JWT 签名密钥，必须与 `SECRET_KEY` 不同；两个宿主配置同一值，机构仅在平台部署管理入口验证平台 JWT，不用于业务凭据加解密 |
| `PLATFORM_ADMIN_USERNAME` / `PLATFORM_ADMIN_PASSWORD` / `PLATFORM_ADMIN_EMAIL` | 否 | 平台账号表为空时创建首个平台管理员 |

双后台使用 [SaaS 基础底座](../02-架构与设计/19-SaaS基础底座设计.md)的权威安全会话、正式多角色和当前动作/对象授权。MFA 对管理员与普通成员默认关闭，用户可自愿绑定，显式全员策略由安全管理入口发布。数据库环境先满足 [§3.1](#31-sdk-数据库初始化)的目标链前提，再验证 V274–V279 对应的账号、资源归属与撤权行为；不能把旧 JWT 的 role 声明当作有效权限。

公共文件使用宿主持久根 `skillforge.foundation.files.root`，默认 `./data/foundation-files`；单文件上限由 `max-bytes` 配置，默认 20 MiB，未引用文件 `orphan-hours` 默认至少 24 小时。SMTP 在公告与通知设置中登记真实服务并验证投递；Prometheus 使用 `/actuator/prometheus`，需验证部署网络抓取和告警接收，p95 需要宿主 HTTP histogram。显式备份、隔离恢复及 WAL 演练命令见 [运维工具指南](../../tools/operations/README.md)，工具不读取项目 `.env`、不覆盖已有恢复目标、不自动切流。

### 4.4 LLM

`LLM_API_BASE`、`LLM_API_KEY`、`LLM_MODEL` 和 `LLM_EMBEDDING_MODEL` 不再提供宿主模型来源。平台管理员通过平台后台或 [`/api/v1/admin/models`](../02-架构与设计/04-接口与事件契约.md#51-平台模型运营配置与运营查询)维护 LLM、Embedding 与 Rerank 的不可变模型版本，连接凭据加密保存；机构管理员只从平台已启用模型中保存引用。LiteLLM 仍可作为平台模型目录中的一个 OpenAI-compatible 端点，但不是部署必需组件。

长推理流出现传输预算错误时，检查 `agent-runtime.model-maximum-response-bytes`（标准环境变量 `AGENTRUNTIME_MODELMAXIMUMRESPONSEBYTES`）。模型传输默认上限为 16,000,000 字节，包含 SSE 帧开销；可根据实际响应量调整。工具 HTTP 的 `http-maximum-response-bytes` 与解码后 payload 限额独立生效，调整模型传输预算不会同步放宽它们。

SDK 部署配置统一使用 `agent-runtime.*`；平台身份授权、可信认证和回调入口使用 `skillforge.agent-runtime.*`，由宿主拥有。两者启动时绑定，变更后重启生效。直接使用 Spring 环境变量绑定时，按[官方规则](https://docs.spring.io/spring-boot/3.5/reference/features/external-config.html#features.external-config.typesafe-configuration-properties.relaxed-binding.environment-variables)将点转为下划线、删除连字符并转大写；本指南的 `AGENT_RUNTIME_WORKER_LEASE_DURATION` 和 `AGENT_RUNTIME_JDBC_OBSERVATION_ENABLED` 则是宿主 YAML 显式映射的部署入口。

模型管理的 `max_output_tokens` 控制单次调用；平台 `task_budget` 分组只配置普通、协作、团队场景的五项根额度；主 Agent、成员、维护及阶段档由代码策略派生。宿主根据实际产品目标与冻结委派能力选择场景，任务受理时冻结根预算；补充输入、成员和同一 Goal 续行继承原账本，不通过重启重置额度。业务模型与辅助模型次数独立，全部 Tokens 和活跃时长仍归根总账，下一实际请求同时受根余额、Run 上限、阶段额度与动态收尾保护约束。配置和结算契约见 [Harness 共享任务预算](../../harness-design/03-上下文视图与执行优化.md#24-共享任务预算与持久结算)。

有效模型输入为窗口减本次输出预留，再减窗口 5% 向上取整的安全余量；不再提供运营输入上限覆盖。候选内容和 tokenizer 统一采用部署资源参数 `skillforge.context-content-characters`，默认 32 Mi 字符，随不可变准备 Profile 冻结。普通与收尾采用同一单次输出上限，不能通过截断工具参数适配容量。上下文字符、`max-payload-code-units` 等仍保护解析和物理资源，不形成第二个业务窗口。工具、知识与工作流结果的内容及恢复校验由各自冻结的执行契约约束；模型单次输出策略不替代外部响应或 payload 的物理限制。HTTP 响应限制独立生效。


#### 4.4.1 系统提示词维护入口

宿主提示词统一从 [skillforge-prompts 目录清单](../../backend-java/skillforge-prompts/README.md) 进入，正文以其 UTF-8 资源或已发布配置为准。本节列调用入口；Runtime 动态投影和工具 Schema 仍归所属模块，完整清单见该模块 README。

| 用途 | 来源 | 维护边界 |
| :--- | :--- | :--- |
| Agent 决策策略 | 平台运营配置 `prompts.agent_decision_policy` | 平台后台修改后供下一次模型或工具动作读取；角色、业务目标和运行时数据不写入该字段 |
| 固定交互协议 | [ChatPrompts](../../backend-java/skillforge-prompts/src/main/java/com/skillforge/prompts/ChatPrompts.java) | 核心规则与模块资源统一组合；输入为已冻结的平台策略和数据库 Agent 正文。只有宿主标记 parallel_safe=true 且独立的只读调用可每批至多 8 项，数量由 ToolCallLimits 统一维护；整批冻结资格，逐项计量 |
| Agent 业务角色 | [AgentRuntimeHostProvisioner](../../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/runtime/AgentRuntimeHostProvisioner.java) 读取已发布 Agent 配置 | 角色与业务目标按内容冻结到准备配置，不重复宿主动作协议 |
| 通用系统 Agent 动作协议 | [SystemAgentPrompts](../../backend-java/skillforge-prompts/src/main/java/com/skillforge/prompts/SystemAgentPrompts.java) | SystemAgentModelProvisioner 传入冻结用途正文；JSON 动作协议独立于机构聊天，不用于 MODEL_TASK |
| Tool / Skill | [PlatformToolCatalog](../../backend-java/skillforge-core-capability/src/main/java/com/skillforge/core/capability/connector/PlatformToolCatalog.java)、已发布工具定义与 Skill 包 | 挂载的能力才进入目录；激活的 Skill 才注入正文。运营配置更新不修改 Skill 包、发布版本或挂载关系 |
| 对话消息与 Workflow 节点 | [AgentExecutionProgram](../../backend-java/agent-runtime-session/src/main/java/com/skillforge/runtime/session/AgentExecutionProgram.java)、[WorkflowNodeProgram](../../backend-java/agent-runtime-session/src/main/java/com/skillforge/runtime/session/WorkflowNodeProgram.java) | 活跃材料持有准确消息与上下文增量引用，恢复消费原材料；Workflow 节点沿用独立冻结配置和参数，记忆治理见[记忆管理](../02-架构与设计/07-记忆管理.md) |
| 输出规则、纠正与准备拒绝 | [AgentExecutionOutputs](../../backend-java/agent-runtime-session/src/main/java/com/skillforge/runtime/session/AgentExecutionOutputs.java)、[AgentExecutionProgram](../../backend-java/agent-runtime-session/src/main/java/com/skillforge/runtime/session/AgentExecutionProgram.java) | 实际请求保存自身输出义务和有界纠正计数；超限、非法准备或能力结果拒绝按当前执行边界处理，不恢复旧观察装配器 |
| 记忆候选提取 | 平台“系统智能体”的 `memory-extraction` 已发布配置与 [MemoryExtractionAgent](../../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/memory/MemoryExtractionAgent.java) | 只负责候选分类；用户身份与原文放在独立输入 JSON 中 |
| 任务纠正 / 历史压缩 | 平台“系统智能体”的 `task-context`、`context-summary` 已发布配置 | `task-context` 只为机构端显式 `correct` 处理已指定任务的选择、更新与纠正，不是普通聊天前提；`context-summary` 仅输出背景摘要正文，不输出 JSON，也不决定覆盖范围或执行历史待办 |
| 画像摘要 / 合并 | 平台运营配置 `prompts.chat_summary_prompt`、`prompts.profile_merge_prompt` | 两个独立后台任务；会话、旧画像及近期摘要只作为 user 数据传入一次 |

平台策略和系统用途默认正文统一由 [PromptDefaults](../../backend-java/skillforge-prompts/src/main/java/com/skillforge/prompts/PromptDefaults.java) 读取资源。[V171](../../backend-java/skillforge-migration/src/main/resources/db/migration/V171__system_agent_prompt_defaults.sql) 保留当时的初始化快照；后续默认正文调整不回写旧迁移、不自动覆盖数据库，已维护或发布配置通过管理 API 更新并保留版本与操作者审计。修改机构聊天正文后，同步更新 [完整请求占位符快照](../../backend-java/skillforge-institution-service/src/test/resources/prompts/agent-runtime.expected.txt)。主 system 正文由 `AgentRuntimePromptsTest` 验证拼装一致性；说明不是生产请求内容，快照不代表真实模型效果评估。

通用系统 Agent 的 [动作协议正文](../../backend-java/skillforge-prompts/src/main/resources/com/skillforge/prompts/system-agent/action-protocol.md) 不设身份或回复语言；固定协议为独立 HOST 模块，数据库用途正文为独立 SYSTEM_PURPOSE 模块，业务 JSON 放在 `respond.output` 字符串中。该严格 JSON 调用链不装配聊天计划政策。`MODEL_TASK` 直调不经过此协议，其结果格式由独立调用契约和用途提示词规定。

平台运营配置的更新和回滚都追加版本。所有会话、进行中或暂停任务在下一次模型或工具调用时读取当前版本，不需要新建会话；已经发出的调用及其重试、结果处理和恢复保持原调用快照。模型、工具或运营配置更新不会清零累计 Usage Ledger 用量。修改代码内固定协议时同步更新准备配置引用版本。验证覆盖动作示例可解码、实际模型消息的角色与数据分离、空结果和拒绝路径；真实模型的轮次、工具调用与 Token 变化需单独实测，文案缩短不等于效果已改善。

#### 4.4.2 供应商缓存服务选择与验证

平台模型表单从 SDK Provider 目录取得服务和 profile，不增加独立缓存开关。需要显式缓存策略时创建或发布独立模型版本，选择下表服务；机构和 Agent 继续选择平台模型引用，已冻结调用保持原绑定。模型发现只列账号候选，不能替代具体缓存模式的模型支持校验。

| Provider / 服务 | 编码与适用范围 | 验证边界 |
| :-- | :-- | :-- |
| DeepSeek / `deepseek-api` / Chat Completions | 自动前缀缓存；适用于该协议已支持的文本、JSON 和原生工具调用 | 不从 Messages 的能力声明推断 Chat 支持历史更新；构建延迟、TTL 与命中按供应商实际 usage 验证 |
| DeepSeek / `deepseek-api` / Messages | 选择 `anthropic-messages`、`anthropic-api-key`；方言 `deepseek-messages-v1`，根地址仍为 `https://api.deepseek.com`，Provider 编码 `/anthropic/v1/messages` | 文本、原生工具、流式与 HIGH/LOW 私有状态续接需按具体型号验证；图片输入与工具结果图按具体型号能力配置并单独验收，结构化响应不支持。按模型能力投影完整系统快照；按具体型号独立验收，不外推到所有型号 |
| 百炼 / 原有服务 | 保持普通自动缓存，沿用原服务、地域与能力声明 | 不自动增加缓存写入费用 |
| 百炼 / `bailian-cn-beijing-explicit-cache` | profile `2026-10-08-explicit-cache-v1`；固定北京 endpoint，在首条 system 及最新 user/tool 文本设置 ephemeral 标记 | 含缓存写入计费，模型集合见 [百炼 Provider](../../backend-java/agent-runtime-adapter-model/src/main/java/com/skillforge/runtime/adapter/model/aliyun_bailian/AliyunBailianModelProvider.java)，服务 CONFIGURABLE_UNVERIFIED |
| 自定义基础协议 | 显式授权端点可选择 Chat Completions 或原生 Responses，不继承其他供应商专属缓存字段 | Responses 的续接、用户图与工具结果图按授权端点、具体型号和协议能力独立配置并验收。协议兼容不证明具体端点的续接、视觉或缓存能力 |

[百炼显式缓存指南](https://help.aliyun.com/zh/model-studio/explicit-cache-guide)说明 Qwen3.5 及后续模型会整体合并多条 system，无法在这些 system 之间建立独立缓存断点。当前 Runtime 保留记忆、Skill 与可信时间的原文和角色；尾部时间未设置标记只证明出站编码位置，不能证明供应商内部缓存已经排除它。此类多 system 布局的收益必须实测，不能为了命中改写指令信任边界或省略动态事实。

DeepSeek 协议选择以[官方模型能力](https://api-docs.deepseek.com/api/list-models/)和[Messages 支持范围](https://api-docs.deepseek.com/guides/anthropic_api/)为依据。Messages 中最新 SYSTEM 是完整有效快照；Provider 必须保留平台核心、业务指令及可信动态事实，不能将尾部时间或成果状态单独作为替换快照。投影新增的文本进入准备预算计量；供应商 `input_tokens` 是未缓存输入，完整输入须合计已报告的缓存读取和写入，缺失分量保留未知。新协议不自动替换既有模型配置；平台显式发布模型，机构或 Agent 按任务所需能力采用。协议更新能力不等于缓存收益，完整快照可能增加输入，应比较同任务的未命中 Token、总费用和完成质量。

百炼北京普通及显式服务的 qwen3.7-plus / qwen3.7-plus-2026-05-26 默认开启思考；冻结 reasoning=DISABLED 时 Provider 编码顶层 enable_thinking:false，DEFAULT 省略并采用供应商默认。其他模型或服务只在官方支持明确核实后扩展，不能向只支持思考的模型透传关闭参数。此开关与缓存策略独立，短输出预算不应依赖未生效的禁用声明。

推理档位由 SDK 当前服务与协议的 reasoningOptions 给出，并携带官方 source/sourceUrl；宿主表单动态展示有效选项，发送前按冻结配置校验，不能把 DEFAULT 解释为统一关闭。正式服务使用目录声明的端点，自定义端点需显式授权。同一 Run 的恢复和工具续接保留原生私有状态；跨新 Run 从公开历史建立新 series，不自动复用旧私有状态。Messages 可返回带 signature 的空 thinking，验收检查私有状态保存与回放，不要求每轮非空推理文字。所需协议能力应按服务与型号独立验证，不能从表单可配置推断真实供应商行为。

真实缓存对照可显式启用 [LiveProviderPromptCacheTest](../../backend-java/agent-runtime-adapter-model/src/test/java/com/skillforge/runtime/adapter/model/provider/LiveProviderPromptCacheTest.java)：SKILLFORGE_LIVE_PROMPT_CACHE=true，并指定仓库外 SKILLFORGE_PROMPT_CACHE_CREDENTIALS_FILE 与 SKILLFORGE_PROMPT_CACHE_EVIDENCE_DIR；默认 CI 不访问外网。该测试每服务最多八次短输出请求，保存合成编码和原始 usage；配额拒绝停止该服务剩余调用。每次对照固定输入、模型配置与调用条件，按实际 usage 和费用解释结果；历史结果不作为当前模型的命中或收益保证。动态 system 频繁改变的百炼场景，应先核对读取收益与写入 token，再决定选择显式模式。

验收使用同一会话、绑定版本、模型和工具集合，分别比较普通调用、多轮工具、Skill 激活/停用、参数输入、动态记忆及压缩场景。先核对脱敏原始编码前缀，再按首次写入、连续复用和到期后重建记录 input/cache read/cache write tokens、总费用与首 token 时延；按供应商最小 token 和构建等待条件执行。缺失 usage 标记 UNKNOWN，读取命中率以该场景实际报告的读取子集除以输入量，写入费用单独核对。本地 HTTP 测试与真实付费验证分别记录；没有真实数据时不填写收益比例。机制与授权边界见 [Harness §13.1](../../harness-design/03-上下文视图与执行优化.md#131-供应商-prompt-cache-与前缀稳定性)。

### 5.3 本地启动

本节是本项目本地服务启动的权威入口。后续人工操作和 Agent 会话接到“启动服务”“启动所有前后端”“重启聊天”等请求时，必须先读取本节；不能用旧会话中的 PID、临时命令或默认环境替代当前配置。专项沙箱配置由[代码执行与产物运行指南](09-代码执行与产物运行指南.md)维护。本节适用于 Windows PowerShell：依赖与沙箱运行在 Docker Desktop Linux 容器，业务后端和 Vite 运行在宿主机；不要混用容器内地址。

在仓库根目录使用受支持的 [Windows 本地服务入口](../../tools/dev/services.ps1)。默认 `status` 只读检查六个组件；未由此入口启动的监听显示为 `unmanaged`，即使 HTTP 正常也不会自动接管或停止。入口持有的服务同时核对工作区、PID、创建时间、可执行路径、命令行、监听归属和 HTTP 200。重启会影响在途聊天，应先说明影响；恢复后检查原请求状态，不自动重发业务指令。

```powershell
$repo = (Get-Location).Path
pwsh -NoProfile -File tools/dev/services.ps1 status
pwsh -NoProfile -File tools/dev/services.ps1 start
pwsh -NoProfile -File tools/dev/services.ps1 stop -Component chat
pwsh -NoProfile -File tools/dev/services.ps1 start -Component chat
# 单组件自定义端口；需与既有允许来源配置一致
pwsh -NoProfile -File tools/dev/services.ps1 start -Component chat -Port 3201
docker compose -f deploy/docker-compose.java.yml ps
```

`-Component` 支持 `all`（默认）、`institution`、`platform`、`gateway`、`admin`、`platform-web`、`chat`。多组件选择使用 PowerShell 原生调用 `& ./tools/dev/services.ps1 start -Component institution,platform,gateway`，省略组件参数启动全部。`-Port` 仅允许单组件。`-TimeoutSeconds` 默认 90 秒。占用端口直接拒绝启动；已由本入口持有且健康的服务复用。就绪超时保留进程、元数据和日志，先 `status` 排查，再显式 `stop`。失效或不匹配记录不会触发杀进程，确认旧进程已退出后才可手工移走对应记录。不要并发操作同一个组件。

入口不管理 Docker、沙箱或浏览器服务，不构建、不安装依赖、不执行数据库准备或迁移。服务启动仅适用于已配置且结构匹配的数据库，后端通过命令行关闭 Flyway；需要迁移时按 §3.1 的独立授权流程执行。六组件状态不证明依赖、沙箱或业务链已经验收。

需要 Java 21、Node/npm 和 Docker Desktop Linux 引擎；代码沙箱要求 Docker Engine 28 或更新版本。Docker 管道或构建缓存访问被执行环境权限限制时，使用获准的工具提权，不把权限错误误判为服务未安装。

#### 5.3.2 环境与依赖

仅首次缺少根 `.env` 时从模板复制并完成配置，禁止覆盖已有密钥。操作者须先在本地环境配置独立的 `PLATFORM_ADMIN_PASSWORD`；公开模板不提供默认管理员密码，Compose 在该值未填写时即拒绝启动。平台与机构必须使用同一 `SECRET_KEY`。入口默认读取根 `.env`，可通过 `-EnvFile <路径>` 指定已有文件；显式进程环境优先，文件仅解析每行 `KEY=VALUE`，不执行文本、不打印变量。入口不会覆盖数据库、Redis、Nacos 或 Elasticsearch 的已配置地址，也不会生成或轮换密钥。端口优先使用 `-Port`、已有服务记录、对应后端环境端口、默认端口。前端自定义端口使用 `-Port`，Vite 继续读取自身 `.env.local`。

缺少根环境时先手工配置；按已配置部署启动依赖并检查健康：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# 完成真实地址、角色、密钥与媒体目录配置后再启动
docker compose -f deploy/docker-compose.java.yml up -d postgres redis nacos elasticsearch
```

跨宿主媒体根通过已有 `SKILLFORGE_MODEL_MEDIA_ROOT` 配置指向同一 E 盘工作区目录。服务入口为本次操作及子进程加载环境，在正常返回或异常退出时移除本次从文件导入的键，保留调用终端原有变量；下一次操作重新读取文件。后文专项验收需要在当前 PowerShell 导入根环境时使用下例，显式环境优先且不输出正文：

```powershell
foreach ($line in Get-Content .env) {
    if ($line -match '^\s*([A-Za-z_][A-Za-z0-9_]*)=(.*)$') {
        $settingName = $matches[1]
        $settingValue = $matches[2].Trim().Trim('"').Trim("'")
        if ($null -eq [Environment]::GetEnvironmentVariable($settingName, 'Process')) {
            [Environment]::SetEnvironmentVariable($settingName, $settingValue, 'Process')
        }
    }
}
```

数据库地址、角色、密码与 Elasticsearch 地址沿用已配置值，不能用示例覆盖；已切换到新建数据库的环境保留根 `.env` 中的地址。确认依赖健康后继续；不得通过删除卷或 本地持久数据目录 来解决普通启动失败。Compose 首次空库由[角色初始化脚本](../../deploy/pg-init/01-platform-role.sql)创建独立的平台与机构开发角色，并授权迁移 owner 创建的对象；该脚本仅在空数据目录初始化时运行。其他环境先由 DBA 创建数据库和三个角色，生产密码从受控秘密来源注入。管理员初始化使用本地环境配置，账号密码不写入本文。

机构数据库账号使用 `SPRING_DATASOURCE_USERNAME/PASSWORD`，平台数据库账号使用 `PLATFORM_DATASOURCE_USERNAME/PASSWORD`；平台用户名默认 `skillforge_platform`，密码必填且无公开默认值。两个服务共享 `SPRING_DATASOURCE_URL`。平台启动时将专用账号配置放在系统环境变量之前，防止同一根环境中的机构账号覆盖平台账号；不需要在启动脚本中改写机构变量。显式命令行 `spring.datasource.*` 配置和测试的 `DynamicPropertySource` 仍优先，缺失平台密码不会回退到机构密码。

两个宿主显式设置相同的 `SPRING_FLYWAY_USER/PASSWORD`，使完整迁移链始终由同一 owner 创建对象。机构运行角色必须为 `NOSUPERUSER NOBYPASSRLS`，不得拥有数据库、public 对象或继承迁移 owner/平台特权角色。平台角色需 `BYPASSRLS`。更换数据库地址不复制旧库授权；新建空库在首次启动前设置默认权限，已有目标链数据库在启动前同步当前对象权限。执行前先满足 [§3.1](#31-sdk-数据库初始化)的链适用性前提。

在仓库根目录执行正式准备入口，读取根环境中的实际数据库、机构角色、平台角色与 Flyway owner；显式进程环境优先。该入口仅补授当前对象和 owner 的默认权限，不建库、不创建角色、不执行迁移、不改根环境。使用本机 `psql` 时省略 `--container`；容器模式会核验 loopback URL 与容器的 5432 映射端口一致。

```powershell
python -X utf8 -B tools/dev/prepare_database.py --env-file .env --container skillforge-java-pg
```

权限 SQL 的唯一入口是 [runtime-grants.sql](../../deploy/pg-init/roles/runtime-grants.sql)，也供 Compose 初始化调用。DBA 可用具备目标对象授权和默认权限管理能力的管理员连接，通过 `psql -v migration_owner=<实际 owner> -v platform_role=<实际平台角色> -v institution_role=<实际机构角色> -f deploy/pg-init/roles/runtime-grants.sql` 执行；连接参数和密码由受控进程环境提供。表、序列和函数均覆盖现有对象与未来 owner 对象；机构仅获表 DML，不授予 TRUNCATE、DDL 或 RLS 绕过权限。已有机构角色若保留历史 `GRANT ALL` 的 TRUNCATE/REFERENCES/TRIGGER 权限，或拥有 CREATE、CREATEROLE、对象所有权或特权角色成员关系，准备入口会拒绝；由 DBA 核对授权来源和有效权限后显式撤销，再重新准备，不静默保留或自动撤权。迁移显式撤回 `PUBLIC` 函数执行权后，宿主仍依赖直接 `EXECUTE` 授权。授权后核验两个宿主的对象权限及机构角色 RLS 拒绝行为，再继续启动；仅检查 readiness 不能证明租户隔离。

应用本地调试能力使用 `SKILLFORGE_DEBUG`，包括允许沙箱访问 loopback HTTP；Spring Boot 的日志调试由框架 `DEBUG` 单独控制。普通本地启动使用模板中的 `SKILLFORGE_DEBUG`，避免同时打开框架高频调试日志。

两个宿主共享 `SKILLFORGE_MODEL_MEDIA_ROOT` 指定的媒体正文目录，保存供应商已生成且经认证下载的图片、音视频和转写文件。默认值为工作目录下的 `./data/model-media`；本地启动在已有环境中显式指向当前 E 盘工作区，临时文件及日志也放在 E 盘。Compose 已为两个宿主配置共享的 `model-media-files` 持久卷；Docker Desktop 数据盘同样应位于 E 盘。目录不得以公网静态文件服务暴露，访问继续经过原任务归属检查。

#### 5.3.4.1 个人远程浏览器

个人远程浏览器启用时，按[BrowserSkill 专题](../../docs/02-架构与设计/18-BrowserSkill远程浏览器接入.md)核对适配扩展与个人设备归属。源码提供独立 Browser service、单实例持久卷和代理配置；跨机器远程接入需要已配置的 HTTPS/WSS 域名，构建通过不代表就绪。本机隔离验收可使用官方协议支持的 loopback WS，不能据此宣称公网代理与个人设备已验收。

在根环境文件配置 `BROWSER_SERVICE_TOKEN` 与 `BROWSER_PUBLIC_BASE_URL`，后者是已有 HTTPS 代理对外的 `wss://主机` 基址。机构服务本机接入配置 `BROWSER_SERVICE_URL=http://127.0.0.1:18300`，并使用同一服务令牌。服务默认二进制路径是 `/opt/bsk/bsk`，Compose 使用固定上游提交与 `cargo +1.90.0 build --locked` 构建，避免上游 `rust-toolchain.toml` 的 stable 自动升级；镜像内关闭上游自动升级。`BROWSER_DATA_ROOT` 保存个人 `BSK_HOME`、绑定和回执，不能用临时目录代替持久卷。容器默认持久目录为 `/var/lib/bsk`；自定义根目录必须保留足够的 Unix Socket 路径长度，完整 `BSK_HOME/run/daemon.sock` 的 UTF-8 路径须短于 108 字节。个人归属采用 64 位十六进制摘要，过长根目录会使上游 daemon 无法绑定 socket。

```powershell
Push-Location backend-java
.\gradlew.bat :skillforge-browser-service:bootJar
Pop-Location
docker compose --env-file .env -f deploy/browser/compose.yml build browser-service
docker compose --env-file .env -f deploy/browser/compose.yml up -d browser-service
Invoke-RestMethod http://127.0.0.1:18300/actuator/health
```

Docker 配置的镜像源不可达时，可显式从官方 `registry-1.docker.io/library/rust:1.90-bookworm` 和 `registry-1.docker.io/library/eclipse-temurin:21-jre-noble` 拉取，并分别设置本地 `rust:1.90-bookworm`、`eclipse-temurin:21-jre-noble` 标签供同一 Dockerfile 复用；不为本任务改全局镜像源。

上述命令仅用于明确启用的浏览器服务，普通后端重启不自动创建 Browser service。将[扩展反向代理配置](../../deploy/browser/reverse-proxy.nginx.conf)纳入已有 HTTPS server，保留 `/extension/…` 路径、Upgrade、Origin、Authorization 与子协议；`/internal/browser/**` 不对外。

网页连接交接使用“灵知 · BrowserSkill”适配扩展，固定官方上游 `3f10983c09fcd443c7420830ab984c9d409954bf`。在仓库根目录构建，前置依赖、固定归档及产物摘要见[适配扩展构建说明](../../tools/browser/extension-adapter/README.md#构建与产物)：

```powershell
python -X utf8 -B tools/browser/extension-adapter/build.py
```

构建成功后，按[浏览器压缩包与构建产物说明](../../tools/browser/extension-adapter/README.md#构建与产物)选择 Chrome 或 Edge 对应的压缩包。按[开发者模式加载步骤](../../tools/browser/extension-adapter/README.md#开发者模式加载)解压并选择包含 `manifest.json` 的目录，在独立 profile 加载；核对扩展名称、上游与适配版本后，打开会话页，在 popup 明确信任完整站点 origin。回到连接卡发起配对，再打开 popup 核对请求站点、目标服务及身份范围并逐次确认。独立设备管理不创建虚假连接等待；原版官方扩展仍可在 Remote 设置手动粘贴配对串。网站身份凭据不传入扩展，配对串与设备密钥不写入日志。

配对提示 `paired` 只证明官方配对调用返回；继续核对服务端准确设备关联、设备在线、原工具等待恢复以及实际浏览器任务。可关闭会话页后观察服务端续跑，再打开同一会话核对状态；用户取消连接等待时不应启动浏览器任务或撤销独立设备授权。未知配对或网络结果不能自动重发。接口与状态含义见[个人浏览器连接 API](../02-架构与设计/04-接口与事件契约.md#37-个人浏览器连接控制)；构建和加载步骤不自证这些真实场景已验收。

代理显式使用 64 MiB 文本和二进制消息缓冲，与固定上游 tungstenite 消息上限对齐；真实验收须包含超过 8 KiB 的截图或录制 JSON，检查没有 WebSocket 1009 断连及截图字节完整性。Dockerfile 专用忽略文件只允许实际 bootJar 与构建文件进入上下文，根环境和业务数据不发送给构建器。配对/WSS失败、固定CLI不可用、持久卷不可写或图片不能被模型消费时，不能报告浏览器接入验收完成；不打印令牌或完整配对链接。无 HTTPS/WSS 域名的本地开发可用 `ws://127.0.0.1:<浏览器服务宿主端口>` 作为 loopback 基址。独立 profile 的成功也不证明用户日常浏览器与外部 WSS 可用。

#### 5.3.6 验收与报告

机构 Runtime 通过直接唤醒、持久到期记录与下一到期时间驱动执行，另以固定 5 秒周期进行恢复扫描。当前 Worker 的扫描批次上限为 100；这些节拍与批次属于执行器实现常量，没有对应的部署配置项。租户从宿主的持久恢复查询发现，不通过固定租户列表配置。

当前共享 Worker 的单实例活动执行槽上限固定为 20；持久租约保护同一执行的归属，超出容量的到期记录保持持久化，等待空闲槽位。机构数据库池默认 64（`INSTITUTION_DB_POOL_SIZE`），为 IAM 和 Runtime 独立短事务保留余量。20 个执行槽不等于已证明 20 路供应商吞吐，仍需按实际模型、数据库和资源配置压测；停止时会停止接收新任务并收敛活动执行。

任务活跃时间、单次外部调用期限、持久等待窗口与租约分别控制所属行为；配置归属及生效边界见[技术架构](../02-架构与设计/01-技术架构.md#3-宿主边界)，驱动停止与原事实恢复见 [Harness 03 §15.1](../../harness-design/03-上下文视图与执行优化.md#151-驱动期限与停止)。当前执行器没有独立的 Session 无进展超时配置，调整旧环境变量不能改变模型或工具超时。

需要定位 Runtime 数据库成本时，可在启动进程设置 `AGENT_RUNTIME_JDBC_OBSERVATION_ENABLED=true`；默认关闭，不为普通运行安装 JDBC 计数代理。分段字段及线程、嵌套、连接与锁耗时边界见 [Harness 03 §15](../../harness-design/03-上下文视图与执行优化.md#15-统一计量与诊断)，启用后的样本包含观察器开销。机构配置将 `org.springframework.jdbc` 及 `org.springframework.jdbc.core.JdbcTemplate` 日志级别设为 INFO；后者防止 `DEBUG=true` 的 Boot 调试设置覆盖包级配置。排障时按需临时调整，不长期输出逐条 JDBC DEBUG。

机构和平台宿主均使用 [Spring Boot 原生 Logstash JSON 编码](https://docs.spring.io/spring-boot/3.5/reference/features/logging.html#features.logging.structured.logstash)，由 `logging.structured.format.console` 和 `file` 配置选择。每条日志独占一行，消息中的引号、反斜杠与控制字符，以及异常堆栈均交由编码器转义；已绑定的 `trace_id`、`tenant_id`、`user_id`、`module` 和 `action` 从 MDC 写入 JSON。该配置不采集环境变量或请求正文，调用方继续遵守秘密与外部异常的安全记录边界；请求关联 ID 不代替 Runtime 的持久业务因果。

同一观察开关还会每约 30 秒按后台来源输出 `Runtime worker JDBC` 聚合日志，区分 Workflow 恢复、Session Inbox、工具未知结果领取、WorkQueue、调度领取、Callback 领取、状态事件与事件投递。`polls`、`connections`、`executions` 及耗时只覆盖当前线程的该来源区间，包含空轮询和失败尝试；不记录 SQL、参数或凭据，不包含子线程、数据库触发器或租户发现查询。领取区间也不包含其后独立的 ACK/投递。这些来源计数用于定位恢复扫描和业务执行的数据库成本，不能将其称为整个应用的 SQL 总数；普通运行关闭观察器后不建立这些统计样本。

启动后等待应用初始化，再检查 HTTP 状态、后端 readiness、Compose 状态及最新错误日志。平台端 readiness 使用上表实际入口，不套用机构端路径。以下检查只覆盖服务可访问性：

```powershell
$checks = @(
    @{Port=8000;Path='/health/ready'}, @{Port=8100;Path='/actuator/health'},
    @{Port=8080;Path='/health/ready'}, @{Port=3000;Path='/'},
    @{Port=3100;Path='/'}, @{Port=3200;Path='/'}
)
foreach ($check in $checks) {
    $response = Invoke-WebRequest "http://127.0.0.1:$($check.Port)$($check.Path)" -UseBasicParsing -TimeoutSec 10
    Write-Output "$($check.Port): HTTP $($response.StatusCode)"
}
```

首次配置或修改沙箱时，使用专项指南的 inline 示例生成测试文本和 HTML，确认 Python/Node 所需运行镜像可执行；无效预览票据应被拒绝。沙箱执行成功不等于机构产物入库、下载票据、页面预览的全链路成功，未验证部分应明确说明。普通重启可复用配置未变时的执行验证，不必每次创建业务任务。

需要聊天可用时，先确认所选主模型探测成功。主 Agent 直接理解用户请求、当前 Goal 与适用批准计划，按需使用已授权 Skill；不配置或发布已退出的 `output-requirements`，也不以专属要求解释、任务分类、搜索、修复或 `task-context` 已发布为普通聊天前提。机构端显式任务 `correct` 的配置见[任务续接配置](08-任务续接配置.md)，真正触发上下文摘要时另外要求 `context-summary` 已配置并发布。平台模型和运营配置通过版本化接口管理，启动不擅自恢复为旧会话的参数。平台接口使用 `X-Platform-Token: Bearer <token>`；机构接口使用 `Authorization`。禁止输出登录令牌和模型 API Key。

完成报告列出实际可访问地址、启动或复用的服务、检查结果及未完成项。健康检查成功不能表述为聊天或业务任务成功；未通过检查的服务不能列为“全部启动完成”。

```powershell
} finally { Pop-Location }
```

证据只保存终态、失败原因码、模型计量及冻结/结算检查结果，不保存凭据、提示和回答。该验收证明当前代码与指定供应商在独立新库中的运行结果，现有开发环境升级仍按其环境发布范围执行。

Session 缓存连续性的真实供应商验收使用 [SessionPromptCacheLiveAcceptance](../../backend-java/skillforge-institution-service/src/liveChatCapacityAcceptance/java/com/skillforge/institution/integration/SessionPromptCacheLiveAcceptance.java)。同样只读来源库的精确已发布模型连接，在独立 PostgreSQL/Redis 中运行当前初始化链与真实聊天入口。固定场景为八个连续 Run：前两个使用真实计算工具，后六个直接短答；模型自行决定工具和收尾步骤，实际调用数以证据为准。测试限制最多十八次模型发送、四十万总 Tokens 和十分钟，未知结果或失败停止后续发送，生产预算账本继续生效。仅在隔离模型夹具中将输出上限设为 1,024 Tokens，不修改来源配置。

```powershell
$env:SKILLFORGE_LIVE_SESSION_PROMPT_CACHE_ACCEPTANCE = '1'
$env:LIVE_PROMPT_CACHE_SOURCE_MODEL_ID = '<当前已发布模型 ID>'
$env:LIVE_PROMPT_CACHE_SOURCE_MODEL_REVISION = '<精确发布修订>'
$env:LIVE_PROMPT_CACHE_EVIDENCE_FILE = Join-Path $repo '.runtime-logs/session-prompt-cache-live-evidence.json'
Push-Location (Join-Path $repo 'backend-java')
try {
    .\gradlew.bat :skillforge-institution-service:liveSessionPromptCacheAcceptance --no-parallel --max-workers=1 --console=plain
    if ($LASTEXITCODE -ne 0) { throw '缓存真实验收失败，检查安全证据与测试报告，不盲目重放' }
} finally { Pop-Location }
```

该入口记录全部样本的供应商 usage 数值、输入缓存命中率、首个有效流式增量时间、请求耗时、前缀摘要和功能检查。报告不保存模型凭据、提示词或回答；缺失的缓存计量、首增量时间或实际费用保留为未知。来源模型未提供缓存定价、供应商响应未返回费用时，不用本地销售金额或通用输入单价代替实际账单。此场景证明当前宿主在指定模型上的实测表现；与不同输入的历史小时统计比较时，只能作为参考，不能声称同工作量 A/B。已有环境的冻结格式切换仍按[数据清理与保留规范](11-数据清理与保留规范.md#连续上下文与模型能力格式切换)执行。

##### 双端轨迹真实供应商与浏览器验收

统一执行树的真实验收入口为 [TrajectoryLiveAcceptance](../../backend-java/skillforge-institution-service/src/liveChatCapacityAcceptance/java/com/skillforge/institution/integration/TrajectoryLiveAcceptance.java)，由显式任务 `:skillforge-institution-service:liveTrajectoryAcceptance` 选择，普通 `test` 不执行该供应商场景。入口在 Testcontainers 新建 PostgreSQL／Redis 中运行完整当前初始化链，机构服务使用随机端口；任务依赖当前平台 `bootJar`，将其复制到独占临时目录，以关闭 Worker 的独立平台进程读取同一新库。退出时先停止平台进程并确认退出再删除副本，Spring 与测试基类随后释放临时资源，不使用现有业务库承载测试运行数据。

共享该新库的两个宿主须使用不同的正式 `SNOWFLAKE_WORKER_ID`：验收任务在测试 JVM 启动前显式分配机构端为 `1`，平台子进程通过自己的进程环境显式分配为 `2`，并核验机构实际环境。该隔离分配不修改生产 ID 算法；证据记录两端实际 worker ID。

来源仅从 `SPRING_DATASOURCE_URL`、`PLATFORM_DATASOURCE_USERNAME/PASSWORD` 与 `SECRET_KEY` 读取当前已发布模型的精确 ID／修订及连接；在只读事务中核对来源，并拒绝来源地址与临时目标相同。按 §5.3.2 导入根环境后，仅在验收进程通过 Env provider 删除 `SPRING_FLYWAY_USER/PASSWORD/URL`，使新库迁移不借用来源 owner；空字符串不等于环境键缺失，退出时按原键是否存在分别恢复，不改根 `.env`。仅临时模型夹具将输出上限设为 1,024 Tokens，来源模型配置保持只读。

场景覆盖直接使用真实计算工具和委派子 Agent 使用真实计算工具，并通过机构与平台的真实认证 HTTP 核对入口、执行树、父子关系、内容引用、分页及供应商用量。夹具直接走正式主 Agent 与成果链，不再配置或发送已退出的 `output-requirements` 专属解释调用；其他辅助用途只在其真实流程触发时使用。全批最多 24 次实际模型发送、40 万总 Tokens 和 10 分钟模型窗口，包含业务、实际辅助调用及父／子运行；辅助调用同样经过生产预算，按真实父预算作用域与冻结用途版本核对。UNKNOWN、失败、缺失供应商 usage 或来源漂移会停止新发送。重跑属于新的实际调用，仍需计入同一任务的总预算，不能按失败次数重置预算。

```powershell
$trajectoryEvidenceDirectory = Join-Path $repo ('.runtime-logs/trajectory-live-' + [Guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $trajectoryEvidenceDirectory | Out-Null
$env:SKILLFORGE_LIVE_TRAJECTORY_ACCEPTANCE = '1'
$env:LIVE_TRAJECTORY_SOURCE_MODEL_ID = '<当前已发布模型 ID>'
$env:LIVE_TRAJECTORY_SOURCE_MODEL_REVISION = '<精确发布修订>'
$env:LIVE_TRAJECTORY_EVIDENCE_FILE = Join-Path $trajectoryEvidenceDirectory 'evidence.json'
$env:LIVE_TRAJECTORY_FIXTURE_PASSWORD = [Guid]::NewGuid().ToString('N') + 'Aa7!'
$trajectoryFlywaySettings = @{}
foreach ($trajectorySettingName in @('SPRING_FLYWAY_USER', 'SPRING_FLYWAY_PASSWORD', 'SPRING_FLYWAY_URL')) {
    $trajectoryFlywaySettings[$trajectorySettingName] = @{
        Present = Test-Path -LiteralPath ('Env:' + $trajectorySettingName)
        Value = [Environment]::GetEnvironmentVariable($trajectorySettingName, 'Process')
    }
}
Push-Location (Join-Path $repo 'backend-java')
try {
    foreach ($trajectorySettingName in $trajectoryFlywaySettings.Keys) {
        Remove-Item -LiteralPath ('Env:' + $trajectorySettingName) -ErrorAction SilentlyContinue
    }
    .\gradlew.bat :skillforge-institution-service:liveTrajectoryAcceptance --no-parallel --max-workers=1 --console=plain
    if ($LASTEXITCODE -ne 0) { throw '真实轨迹验收失败，先检查安全证据与清理结果，不盲目重放' }
} finally {
    Pop-Location
    foreach ($trajectorySettingName in $trajectoryFlywaySettings.Keys) {
        $trajectoryOriginalSetting = $trajectoryFlywaySettings[$trajectorySettingName]
        if ($trajectoryOriginalSetting.Present) {
            [Environment]::SetEnvironmentVariable($trajectorySettingName, $trajectoryOriginalSetting.Value, 'Process')
        } else {
            Remove-Item -LiteralPath ('Env:' + $trajectorySettingName) -ErrorAction SilentlyContinue
        }
    }
}
```

`LIVE_TRAJECTORY_EVIDENCE_FILE` 必须是本次唯一的新绝对路径，写入采用 `CREATE_NEW`，不能覆盖旧报告。证据记录标识、枚举、用途／提示哈希、业务与辅助调用计数、实际父关联、全量外调与持久用量核对及结论，不保存提示、回答、令牌或模型凭据；平台启动日志另存同目录随机文件。业务模型审计、辅助模型发送与实际 HTTP 发送必须共同对齐，不能把仅业务模型的 usage 当作整条轨迹的完整用量。既有模型接入成功不替代本场景，读取投影不会派发模型的检查也与真实模型完成分别留证。

需要接入真实浏览器时，在启动上述任务前成对设置新的 `LIVE_TRAJECTORY_READY_FILE` 与 `LIVE_TRAJECTORY_BROWSER_FINISH_FILE`。模型及双端 HTTP 检查结束后，夹具关闭新模型发送，写入不含口令／令牌的 ready JSON，并最多保留双端后端 10 分钟。ready 中包含两端随机后端 URL、合成登录用户名和准确轨迹身份；浏览器只登录并读取已完成轨迹，不重发业务输入。两端 Vite 由执行者单独持有，使用 loopback 端口 14340／14341，并在启动 Vite 前设置其 `E2E_BACKEND_URL` 为 ready 中相应后端地址。

| 浏览器进程环境 | 含义 |
|---|---|
| `E2E_BASE_URL` | 当前机构／平台 Vite 地址，分别为 `http://127.0.0.1:14340`／`http://127.0.0.1:14341`。 |
| `E2E_BACKEND_URL` | ready 中对应的 `institutionBackendURL`／`platformBackendURL`，同时用于该 Vite 进程的真实代理。 |
| `E2E_ARTIFACT_DIR` | 本次、当前端独立的新证据目录。 |
| `E2E_TRAJECTORY_FIXTURE` | 本次 ready JSON 的绝对路径。 |
| `E2E_PASSWORD` | 同一次夹具的 `LIVE_TRAJECTORY_FIXTURE_PASSWORD`，从受控进程环境传入，不写 ready 或报告。 |
| `E2E_TRAJECTORY_PRIVATE_DIAGNOSTICS` | 平台可选设为 `1`，额外检查独立私有诊断入口；机构端不获得该能力。 |

两端分别运行 `corepack pnpm --filter frontend-admin exec playwright test --config playwright.trajectory-real.config.ts` 与 `corepack pnpm --filter frontend-platform exec playwright test --config playwright.trajectory-real.config.ts`。配置不启动服务、不拦截 API，也不保存包含登录或私有诊断响应的 trace／video。两端实际通过后，执行者才向本次 finish 文件以新建方式写入 `{"state":"PASSED"}`；失败、超时或缺少一端回执时不能补写成功标记。仅运行后端任务时不设置这对握手参数，证据中的浏览器结果保持未验证。

本入口证明指定当前模型在隔离新库中的执行与观测，浏览器回执进一步证明相应前端真实登录、检索、执行树、受控结果、刷新及布局路径；它不证明已有环境的数据升级、生产部署、所有可选操作或全部界面已验收。

##### 持久联调环境的真实轨迹页面验收

[持久验收入口](../../tools/observation/persistent_acceptance.py)只连接显式指定的本地机构／平台宿主与 PostgreSQL 容器，不迁移、清理或重建数据库。执行前完成本节的环境升级与就绪检查，使用当前已发布的真实模型；它通过正式管理 API 新建独立验收机构、Agent、连接器和会话，沿正式主 Agent、委派与故障恢复链执行，不再配置已退出的专属要求解释用途；原平台模型连接不改。

按 §5.3.2 导入根环境后，在仓库根目录设置以下进程变量；密码不写命令字面量或报告：

```powershell
$env:SF_PLATFORM_USER = $env:PLATFORM_ADMIN_USERNAME
$env:SF_PLATFORM_PASSWORD = $env:PLATFORM_ADMIN_PASSWORD
$env:OBSERVATION_MODEL_ID = '<当前已发布模型 ID>'
$env:OBSERVATION_OUTPUT_DIR = Join-Path $repo ('.runtime-logs/trajectory-persistent-' + [Guid]::NewGuid().ToString('N'))
$env:OBSERVATION_PG_CONTAINER = 'skillforge-java-pg'
$env:OBSERVATION_PG_USER = $env:SPRING_FLYWAY_USER
$env:OBSERVATION_PG_DATABASE = ([Uri]($env:SPRING_DATASOURCE_URL -replace '^jdbc:', '')).AbsolutePath.TrimStart('/')
python -X utf8 -B tools/observation/persistent_acceptance.py
```

该入口保留明确的写入 intent，不自动重试 POST；每次业务写入和运行轮询读取精确新机构的只读外调／供应商用量事实，覆盖辅助用途与成员运行。全批上限为 64 次调用尝试、40 万 Tokens 和 30 分钟；每个新输入还需要保守调用余量。UNKNOWN、供应商模型失败或最终缺少 usage 会停止新写入，不把超时当作重发授权。调用仍计入执行者已有的任务总预算，不能按新目录重置总预算。

`ready.json` 仅记录身份与场景，`private.json` 仅保存新机构独立口令，均放在新的 ignored 批次目录；平台口令来自现有受控环境。自有 MCP 只读故障服务在采证后关闭，已生成的会话、调用与结果保留供页面读取；其测试工具连接不是长期业务服务。失败记录和先前请求身份保持原样，不用后续成功覆盖原样本。

[用户新轮重试入口](../../tools/observation/user_retry_acceptance.py)仅适用于已确认完成且外调结果已知的前批。通过 `OBSERVATION_PRIOR_BATCH` 指定前批、另给新的 `OBSERVATION_OUTPUT_DIR`，它恢复该批原只读测试服务，复用已验证的多轮与委派证据，并在原会话提交全新 `client_message_id`；原失败不重放、不改记。公开 fixture 用 `recoveryMode=USER_NEXT_INPUT` 区分用户新轮重试与同一 Run 的自主重试。

两端使用专用 `playwright.trajectory-persistent-real.config.ts`，接收 `E2E_BASE_URL`、`E2E_ARTIFACT_DIR`、`E2E_TRAJECTORY_PERSISTENT_FIXTURE`；机构口令通过 `E2E_INSTITUTION_PASSWORD`、平台口令通过 `E2E_PLATFORM_PASSWORD` 提供。浏览器仅正式登录和 GET，按真实轨迹验证多轮、成员父边、失败／成功状态、长名称、受控结果、刷新及明暗／窄窗口。自动截图、trace、video 关闭，手工截图遮住正文；收据不保存凭据、原正文、snapshot 或 content_ref。模拟数据、健康检查与已完成的业务链分别说明，不将本入口冒充生产发布验收。

#### 5.3.7 常见启动故障定位

| 现象 | 首先检查 |
|---|---|
| 模型凭据解密失败 | 平台与机构是否导入同一 `SECRET_KEY`，是否遗漏根 `.env` |
| 模型设置很长超时但调用仍提前结束 | 模型超时与平台 `calls.chat_timeout_seconds` 取较小值；已有调用保持冻结快照 |
| `code_execution_deployment_unavailable` | 沙箱地址、令牌长度、预览端口与 Worker 租约，按专项指南整体检查 |
| `task_lease_busy` | 是否有在途请求持有任务；不要直接删除数据库租约 |
| 页面停更但 Run 仍推进 | SSE 连接断开、代理或前端重连；对照运行事件，不仅看 HTTP 200 |
| `INVALID_DECISION` / `task_fact_source_missing` | 输出协议或来源校验问题，不能以延长超时代替实现修复 |
| 端口被占用或 Vite 启动到其他端口 | 查明占用进程，复用本项目健康实例；禁止结束未知进程 |

#### 5.3.8 上下文与执行优化版本的发布核查

本节用于实现[上下文与执行优化目标](../../harness-design/03-上下文视图与执行优化.md)后的版本发布操作；设计批准不表示当前服务已有这些能力。先核对[相关设计](../../harness-design/03-上下文视图与执行优化.md)与实际代码/schema，不能对尚未提供的用途或字段编造 API 请求。

1. 核对在途 Run 和目标协议版本。旧活动 Run 先排空或明确终止，记录已知及未知外部结果；不得通过重发原业务消息迁移到新协议。按目标版本执行 schema 变更，不增加旧格式兼容配置；数据操作遵循[工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md)。
2. 在平台“系统智能体”配置独立 `context-summary` 用途，选定平台可用模型、Prompt 和调用限制；先调试结构、输出和来源引用，再发布。该用途不得挂业务工具，也不由默认主模型隐式替代。发布后读取确认模型/配置版本；缺失或失败应按目标契约明确降级或拒绝。任务 `correct` 使用 `task-context` 时，另核对其已发布版本；普通聊天和显式 task_id 选择不依赖它。
3. 通过正式运营/能力配置核对有效输入预算、外置阈值与已批准默认值；只对受信且独立的只读工具启用 parallelSafe。配置定义只在[目标契约](../../harness-design/03-上下文视图与执行优化.md)及实际配置/schema 维护，本指南不复制另一份数值表。
4. 按 §5.3.2–§5.3.6 加载根环境、构建并启动后端、三个前端及已启用沙箱，核对就绪结果，不复用旧 PID 或仅凭端口监听判定可用。
5. 通过正式接口创建小规模测试数据，按[验收矩阵](../../harness-design/06-MVP-0技术底座实施方案.md#102-聚焦验收矩阵)核对普通聊天直达主模型、显式 task_id 选择、按需任务/记忆工具、诊断和恢复。模型额度不足立即停止，保存已完成结果；报告实际发布版本、已验证与未验证项，不自动重跑 1000 会话。

配置发布通过正式工作台或对应管理 API 执行：先核对实际会话使用的目标 Agent、已有修订和本次工具范围，在草稿中显式选择需要更新的工具挂载，校验并发布新版本，再回读真实能力版本、挂载和部署状态。名称相近的 Agent 各自拥有独立配置，不能用其中一个的验收结果代表其他对象；局部工具更新不隐式替换提示词或全部 Skill。通用计划场景核对模型原生 `plan` 协议及运行准备版本，并验证澄清、精确版本审批和批准前不执行；Skill 强制计划核对已发布元数据 `skillforge-plan`，文字评审另核对 `exit_plan_mode` 的挂载与版本。记录实际目标、范围与回读版本，旧 Run 的冻结配置、调用和结果不随发布改写。

Session 前缀连续性的 V269 已包含在目标初始化链中；当前重写后的链遵循 [§3.1](#31-sdk-数据库初始化)，不能按旧表名版本的原地迁移步骤应用于现有库。目标环境中新聊天受理会从已发布 Agent/模型配置追加格式 4 的绑定 revision，无需为格式变化重新发布业务 Agent 或平台模型。使用正式新建 Session 验证跨 Run 回复、实际工具结果、前缀诊断与 usage。旧会话事实保留、读取与恢复限制见[格式切换与保留](11-数据清理与保留规范.md#连续上下文与模型能力格式切换)；新会话通过不证明旧格式兼容。

#### 5.3.9 业务 Agent 模板维护

非系统 Agent 与业务模板的提示词只维护在数据库。平台服务启动和 Flyway 迁移不创建通用助手或行业业务模板；新环境的业务模板列表为空，已有数据库模板由管理员继续维护。系统固定指令的编辑入口见[提示词导航](../../backend-java/skillforge-prompts/NAVIGATION.md)。

添加平台提供的业务 Agent 时，在平台后台“智能体模板”创建草稿，填写角色正文、公开角色说明、模型、预算、公共基础能力和可选资源/委派槽位，执行校验并发布。自动化配置可以调用[平台模板管理 API](../../backend-java/skillforge-platform-service/src/main/java/com/skillforge/platform/controller/PlatformAgentTemplateController.java)，使用同一创建、更新、校验和发布流程；不要把业务正文加入源码资源或迁移脚本。缺少模型、能力或其他必填配置时保留草稿，发布校验给出字段问题。

机构从已发布模板列表安装 Agent，并按授权绑定本机构资源与已有协作 Agent。安装实例保持独立；模板改版生成新版本，不覆盖已安装 Agent。外部操作、消息发送、文件归档及真实经营数据访问仍需机构接入已授权能力。环境保留的业务模板与历史版本裁剪见[数据清理与保留规范](11-数据清理与保留规范.md)。

## 6. 健康检查契约

后端已实现以下端点；部署验收应在目标环境实际调用并保存结果，本文不粘贴
未经该环境验证的成功 JSON。

| 端点 | 用途 | 成功语义 | 失败语义 |
| :--- | :--- | :--- | :--- |
| `GET /actuator/health`（平台） | 平台健康与就绪 | 200，平台服务可用 | 连接失败或非 200 |
| `GET /health/live`（机构） | 进程存活（K8s liveness） | 200，`{"status":"ok"}` | 进程未起则连接失败 |
| `GET /health/ready`（机构） | 机构就绪（K8s readiness） | 200，PostgreSQL 与 Redis 就绪 | 503，body 列出未就绪依赖 |
| `GET /health/deps`（机构） | 运维诊断 | 200，逐项状态 | 200 或 503；**不得**在依赖失败时仍报整体 ok |

机构 `/health/ready` 检查项（MVP-0）：

| 依赖 | 探测 |
| :--- | :--- |
| PostgreSQL | `SELECT 1` |
| Redis | `PING` |

模型 Provider 和 Connector 探测不计入机构 readiness；需要诊断时使用 `/health/deps` 或对应连接器健康检查。

禁止事项：

- 依赖失败时返回 200 且 `status: ok`。
- 在文档中粘贴未在真实环境跑过的「成功输出」充当验收证据。

## 7. Cloud / Hybrid / On-Prem 责任边界

对齐非功能需求 §5.3。

| 职责 | Cloud | Hybrid | On-Prem |
| :--- | :--- | :--- | :--- |
| 对话 / 编排引擎运行位置 | 平台 | 平台 | 机构内网 |
| 会话 / 用户 PII 存储 | 平台（租户隔离） | **机构侧** | 机构侧 |
| 工作流市场与模板分发 | 平台 | 平台（可离线同步包） | 可选拉取或离线导入 |
| LLM | 平台网关或租户自带 | 平台或机构模型 | 机构模型 / 本地开源 |
| 连接器出站 | 平台出口访问机构 API | 按合规路径 | 内网直连 |
| 身份 | 应用内 JWT（机构/平台两套） | 应用内 JWT | 应用内 JWT |
| 密钥 | 受控环境变量或机构密钥服务 | 机构安全边界注入 | 机构安全边界注入 |
| 升级与补丁 | 平台负责 | 平台引擎 + 机构数据面协同 | 机构运维负责，平台提供制品 |
| 计费 | 套餐 + 用量（ADR-004） | 合同约定 | 节点/年订（不按量亦可） |
| 可观测 | 平台统一 | 引擎侧平台 + 数据侧机构 | 机构自建，可上报匿名指标 |

## 8. 配置与密钥

| 项 | 要求 |
| :--- | :--- |
| 密钥来源 | 环境变量 / 密管；禁止提交 `.env`、凭证 JSON |
| JWT 与业务加密密钥 | 平台登录 JWT 使用独立 `PLATFORM_SECRET_KEY`；平台与机构宿主必须共享同一个 `SECRET_KEY`，使平台写入的业务密文可由机构宿主解密 |
| 历史业务解密密钥 | 两个宿主共享 `SECRET_KEY_DECRYPTION_KEYS`；默认空，最多 4 个显式历史主密钥的标准 Base64，逗号分隔；仅用于解密，不能用于新加密或 JWT 验签 |
| 平台模型凭据 | 只通过平台模型管理入口写入并使用共享 `SECRET_KEY` 加密保存；机构可见模型摘要与选择引用不含 endpoint、认证或凭据 |
| 渠道 token | 创建时明文仅返回一次；日志脱敏 |
| Connector 凭证 | `auth_credential_encrypted`；WorkflowInstance.config 禁止存 Key（ADR-003） |

### 8.1 业务加密主密钥轮换

当前 `SECRET_KEY` 必须非空、至少 32 字符且不含 `change-me` / `change_me` 公开占位标记。历史解密 keyring 不放宽该校验，也没有默认旧密钥。`SECRET_KEY_DECRYPTION_KEYS` 的每项是历史主密钥**原始 UTF-8 字节**的标准 Base64；不得先 trim 或归一化。Base64 只避免环境列表分隔与空格处理破坏原密钥字节，不是保密措施。超过 4 项、重复当前/历史密钥、空项或非法 Base64/UTF-8 都会使宿主启动失败。

新加密操作只使用当前主密钥，输出 `sfenc:1:<key-id>:<Base64(IV+密文+tag)>`；完整封套头作为 AES-GCM AAD 认证。`key-id` 使用独立摘要域生成，不能直接把作为 AES 密钥的 `SHA256(SECRET_KEY)` 暴露为身份。版本化密文按身份只选择一个已配置密钥，未知版本、未知身份及认证失败均拒绝，不退回旧格式。无前缀历史密文保留原 AES-GCM 字节，只在当前及最多 4 个显式历史密钥中做有界认证解密。

平台模型历史、运营配置历史以及 Runtime 模型/MCP/事件路由是不可变事实。Runtime 模型与 MCP 绑定摘要包含密文，模型摘要还派生 Session 已保存的冻结目标；不能通过禁用 trigger、只替换密文或重算单表摘要完成轮换。keyring 允许这些事实保持原字节。沿用凭据的模型发布、配置回滚或邮箱版本复制也不会自动重加密已有密文；历史密钥只有在对应所有持久密文及恢复引用已按所属契约处理后才能移除。

1. 停止目标环境写入与后台派发，备份数据库和与其配对的密钥配置；确认备份可读、只读密文盘点和恢复路径。平台与机构必须切换为相同当前主密钥及历史解密列表。
2. 在受控密钥存储中生成强新主密钥，把仍被存量密文使用的旧主密钥按原字节编码为历史解密项。只保存到受控环境或密管，不打印密钥、密文、凭据原文或连接密码，不提交实际 `.env`。
3. 在切换前后用最终 `CryptoService` 对实际密文只读解密，比较原文摘要及表级成功计数。必要范围包括模型草稿/全部历史版本、Connector、渠道 HMAC、ServicePrincipal、集成应用签名、Session Webhook、机构用量对账、运营配置 `billing` 分组中的两项 `$encrypted`，以及三类 Runtime 冻结密文；已存在的 MFA seed、全部邮箱版本和邮件通知正文也须盘点。只读核对 Runtime 冻结行、内容摘要和恢复引用前后未变化，禁止以当前源配置代替历史绑定验证。
4. 配置切换后按本指南执行两个宿主的就绪与功能验收；覆盖旧模型/连接器凭据、历史配置读取、既有 Session 恢复，以及新凭据写入后在另一宿主解密。`SECRET_KEY` 同时用于机构 JWT，新 key 会使旧机构 JWT 失效；历史业务 keyring 不恢复旧 JWT 的有效性。
5. 如需回退，停写后恢复与数据库对应的配置和版本。如果切换后已有新密文写入，不能只还原旧 key：须恢复配对的数据库快照，或使用仍满足强主密钥校验且包含新旧解密 key 的配置；回退数据库属于单独的数据操作授权。

若历史 key 曾公开或过弱，保留它用于历史解密只是保证数据可恢复，**不会消除旧密文可被该 key 解密的泄漏风险**。需要恢复凭据机密性时，还须在凭据提供方轮换真实凭据，并按对应不可变历史与保留契约处理旧密文；本机制不自动改写历史、不清理数据库，也不宣称旧凭据已重新保密。

## 北京时间部署检查

时间语义以[全系统时间契约](../02-架构与设计/13-全系统时间契约.md)为准。Compose 的 PostgreSQL 服务显式配置 `timezone` 与 `log_timezone`；应用 Hikari 每次创建连接执行 `SET TIME ZONE 'Asia/Shanghai'`。修改容器配置后重建对应服务，不需要清空数据卷。

本地非容器启动时设置 `TZ=Asia/Shanghai`，Java 启动参数添加 `-Duser.timezone=Asia/Shanghai`。不要把 Windows 的时区名称直接作为 Java `ZoneId`。日志日期格式与 Jackson 时区在各服务配置中固定。

连接业务数据库执行 `SHOW timezone;` 和 `SHOW log_timezone;`，结果应为 `Asia/Shanghai`；执行 `SELECT now(), current_date;` 核对北京时间。浏览器切换为 UTC 或其他时区后，同一业务记录仍应显示相同北京时间。

历史无时区字段转换前，先核实字段类型和写入方时区并备份目标环境。已有 `timestamptz` 不做加八小时更新；只有确认来源语义的无时区字段才转换。清库、重建和历史数据转换是独立运维操作，不由时区配置更新自动执行。


### 平台系统智能体维护

1. 平台管理员进入“系统智能体”，选择预置“记忆提取”，或创建自定义智能体。
2. 编辑草稿中的 Prompt、模型和调用限制。记忆提取必须选择平台可用 LLM，首次配置不会自动发布。
3. 通用智能体可挂载已发布公共 Skills 和内置平台工具。先在“系统智能体工具部署”登记工具版本与对应内置工具名；草稿调试使用 TEST 部署，生产发布使用 PRODUCTION 部署。
4. 保存草稿后选择“草稿”调试，检查结果与运行记录。记忆提取调试仅返回候选，不写真实用户记忆。
5. 点击发布后，新后台任务才使用该版本。后续编辑仍保留为草稿；已受理任务和重试继续使用其冻结版本。停用阻止新任务，重新启用恢复最后发布配置。

未发布、停用、模型不可用或输出校验失败时任务明确失败，不回退到旧运营 Prompt 或机构默认模型。平台调试记录不展示机构生产输入和输出。

通用系统 Agent 调试由平台服务的 Runtime Worker 在内部执行空间运行；请求最多短暂等待 15 秒，返回“运行中”后由后台回收终态，页面只轮询历史。平台 Worker 租约配置为 3700 秒，覆盖最长 3600 秒运行预算；进程中断时由 Runtime 的租约与恢复规则接管。记忆提取首次使用前必须选择模型并发布预置配置。
