# 后台 UI 实施与验收执行要求

> 当前重构按模块集中完成实现后再审查与测试，基础控件直接使用 Element Plus；两个后台共享业务与交互保护，会话端独立。已取消的应用多标签、导航右键菜单与缓存场景标为不适用，不能借此标记其他业务能力已完成。

后台通用组件 API 以 [Element Plus](https://element-plus.org/zh-CN/component/overview.html) 官方文档及项目[组件契约](../02-架构与设计/13-前端组件库.md)为准；本文约束业务字段、状态和验收编号。设计判断与响应式处理见 [UI 技能](../../.agents/skills/nw-ui-ux/SKILL.md)。

配合[交互规范](../03-规范与术语/05-后台系统交互规范.md)及[逐控件规格](../03-规范与术语/06-后台逐控件规格.md)，基于轻量后台公共布局与 Element Plus 定义、实现并验证交付范围内 UI 对象的业务、状态、行为、异常、权限、并发、桌面键盘/焦点和恢复。

UI 修改由实施者（开发者或 Agent）完成与改动相称的验证：自动检查覆盖类型、业务结果与数据保护，外观及交互变化补充实际浏览器渲染和可执行的操作核对。用户最终体验验收按任务约定进行，不能代替实施者可完成的检查；也不为普通局部修改额外增加用户批准步骤。逐页截图、像素比对、全量视觉 E2E 和手机适配不默认纳入范围。登记只反映实际结果，不推定未运行场景通过。

## 1. 事实源与范围

按改动读取已有交互、视觉、组件、接口或领域规范的相关章节；已有记录保存所依据版本，不另建规则加载台账。保留 A–J、P01–P20 原编号，不改变事实源职责；新增细则和页面子项按[后台逐控件规格](../03-规范与术语/06-后台逐控件规格.md)执行。规则、进度、缺陷和证据分别存放，不把目标文档变成执行日志。

整体后台迁移盘点 frontend-platform 全部真实路由（含深链）、菜单、页面、弹层、共享消费点、动态 schema、权限分支、异步入口与后台协作；局部修改按[评审与验证规范](../../.agents/skills/nw-verification/references/candidate-driven-delivery.md#风险路由)覆盖直接影响，不追加全量盘点。机构后台只覆盖任务涉及的共享能力及回归。

将实际发现的对象与规格中的305项页面子项、89项通用细则、36项场景及原规则对照；这些登记项不是实际控件总量上限。实际还有控件就新增登记；原文有目标而代码缺实现就记录缺口。不能用删除已批准目标控件、隐藏已承诺能力或缩小支持环境来获得“全部通过”。

## 2. 每个对象必须定义

整体迁移使用下列登记维度；局部修复沿用已有对象定义，只更新行为或证据变化的部分。未影响的字段不反复登记，已有明确批次验收约定继续有效。

登记页面/区域/控件ID、实现位置、规则来源、真实字段或动作、文案/i18n、上游组件来源、可见/可用/只读权限、完整合法状态组合、数据类型与空值语义、校验与错误定位、鼠标/键盘/输入法、请求目标与快照、幂等/防重、成功/失败/待确认、并发、脏态、离开、焦点、滚动、状态恢复、缓存隔离与资源清理、桌面窗口和验收断言。

不适用必须有理由；空白不是默认。字段长度、数值范围、包大小、角色、权限代码、账单状态、版本来源、重试时间和性能预算从实际契约取值。缺失即登记为待绑定/待决，不编造数据使页面看起来完整。

聊天执行过程按 `session_id + root_run_id` 登记为一个复合对象：公开 `commentary` 与执行记录按服务端顺序交错，最终答复位于过程容器外。验收必须覆盖默认展开、用户折叠后的增量更新、根 Run `completed` 且最终答复就绪时的一次自动收起、刷新/历史恢复、无过程直接答复，以及折叠期间仍可见的等待、错误和确认/补充输入卡。子 Agent 只核对已授权 delegation 摘要和 TeamWorkPanel 详情，不把独立 Session 原始日志或子结果当作父聊天最终答复。

## 3. 实现约束

按 [UI 技能的修改归属](../../.agents/skills/nw-ui-ux/SKILL.md#复用与视觉层级)区分单页组合问题与共享组件缺陷，在拥有问题的层级修复；共享改动核对直接消费者的真实接线和业务语义，共享组件通过不能代替页面验证。不为UI另建不必要的状态机、数据库表、通用框架或假后端。

允许按批准UI目标补齐后端能力，但同步接口、类型、权限、幂等、并发、审计、精度和错误契约。没有真实能力的导出、批量、测试、取消、进度和成功提示不能伪造。

保存/发布/启停/审核/封账的确认绑定对象ID、版本/修订和内容快照。连续点击、快捷键、重连和多窗口都不能造成额外业务效果。写入成功但随后读失败必须分开反馈；写入结果未知必须查证，不直接自动重发写请求。

应用内离开入口共享未保存检查。浏览器原生关闭/刷新、进程强制结束具有平台边界，不承诺永远可拦截，不以卸载时的异步保存作为可靠保证。不把编辑正文或凭据塞进标签存储。

## 4. 测试要求

整体迁移逐页走完交付范围内主流程和控件适用状态；局部修改核对受影响行为与直接回归，按改动选择禁用原因、错误、极值、桌面键盘、焦点或滚动。高风险交互按涉及的风险加入响应乱序、提交快照、并发冲突、身份变化、部分成功、结果未知、资源失败或恢复测试，不因纯样式变化运行全部场景。

每条用例同时有可观察UI断言；涉及读写的还要有请求目标、请求范围、业务效果、修订、精度或权限断言。不能只检查HTTP200、按钮能点击或Toast出现。

验证方式与证据边界按下表区分；只选择改动涉及的项目，不把每种方式变成每次必跑的检查。

| 验证方式 | 实施者应核对的内容 | 证据边界 |
|---|---|---|
| 类型、组件与接口自动检查 | 受影响的数据、状态、请求和业务断言 | 编译、DOM 和样式断言不证明实际外观或操作体验。 |
| 浏览器渲染与操作核对 | 实际字体、内容、留白、主题及相关窗口下的显示；受影响的鼠标、键盘、焦点和滚动路径 | 可由开发者或 Agent 执行；脚本点击成功不等于已观察布局，静态截图不证明交互成功。 |
| 专项设备与体验验证 | 改动涉及的真实输入法、读屏、触屏或指定设备行为 | 只报告实际使用的环境和方式；模拟事件或语义树检查不替代对应的真实专项验证。 |
| 用户最终体验验收 | 任务明确约定的产品取舍和使用体验 | 与实施验证分开记录；未约定时不额外设置用户确认关卡。 |

环境不足时说明未验证项目及其对完成结论的影响；缺少本次必要证据时不能标记相应子项完成，也不能笼统转交“用户自行验收”。任务明确包含视觉回归时固定环境并审核截图基线，不扩大容差、遮罩错误、增加重试或更新基线掩盖缺陷；模板响应式不产生手机/触屏支持与专项验收承诺。

真实前后端接口组合的验证单独留证。mock通过只证明受控场景，不替代真实契约、权限、租户隔离、幂等或并发验证。环境不可用记为环境阻塞/待验证，不写通过。

### 4.1 按受影响机制选择回归场景

下表将常见交互缺陷转成可观察检查，规则仍归[工程状态](../../.agents/skills/nw-engineering/references/engineering-standards.md#前端状态与接口消费)、[反馈与排版](../02-架构与设计/09-前端视觉与交互规范.md)及[后台交互](../03-规范与术语/05-后台系统交互规范.md)。按本次改变的机制选行；共同原则可用于会话端和桌面渲染层，不复制后台控件或扩大设备支持范围，也不为局部修改遍历全表。

| 受影响机制 | 代表性触发 | 应观察的结果 |
|---|---|---|
| 登录与 MFA | 密码成功后身份版本改变，分别进入绑定、挑战、完整会话；验证后资料读取失败 | 用真实 App、路由和认证 Store 验证阶段不丢，恢复码先交付再离开；不会削弱受保护页面的身份清理，错误说明准确 |
| 异步操作与全局反馈 | A 对象或旧会话的读取、取消、登录资料请求未返回时切到 B，再返回成功或失败 | UI、Message、令牌、刷新目标与 `finally` 均不污染新作用域；不能只测成功回调 |
| 并行读取与部分成功 | 两个接口同时失败，或主资源成功而辅助读取失败 | 顶部反馈不重复，已成功内容仍显示；首个拒绝被捕获不等于整个批次已承接 |
| Message 动作与寿命 | 两个对象同文案失败，移除首来源；超过普通消息时长，再手动关闭并重新打开恢复入口 | 每个存活对象的动作仍正确，带操作消息不会自动消失；失败占位可辨认，重新打开不自动发送请求 |
| 表单草稿与保存基线 | 编辑配额后切功能开关；保存中再编辑或切页签；回执迟到 | 未提交草稿和原 CAS 不被重载覆盖；实际输入、开关及页签遵守已选择的 busy 策略，不只检查父表单属性 |
| 本地页签与离开 | 有草稿或在途上传时切页签、关抽屉、导航、退出；分别取消和确认 | 使用真实 RouterView 或所属宿主接线，取消保留原状态；真实在途不能绕过，确认次数符合一次离开意图，不能只直接调用保护函数 |
| 浏览器刷新与关闭 | 正文、附件或待答表单未保存时刷新；清空草稿或卸载后再触发 | 有需要时出现原生离开提示，取消后草稿保留；无脏态后监听已清理，不依赖异步卸载保存 |
| 写结果未知与核对 | 创建、安装或调试响应丢失，核对再失败、409 或返回非终态；尝试编辑、新建和离开 | 原命令和操作身份不变，不产生未经核实的新操作；核对依真实契约，UNKNOWN 不等于永久 busy，离开确认明确不会撤销原操作 |
| 权限与辅助目录 | 仅授予所属业务读取权限，拒绝模型或挂载等辅助目录权限 | 有权详情/列表仍可读；缺少必要写入资料时动作不可用且原因明确，没有通过扩大权限或伪造目录放行 |
| 分页、筛选与首次失败 | 第二页或切页大小失败；新筛选失败；首次读取工作区/详情失败 | 旧数据与分页、已应用条件一致，待提交输入保留；失败不会被空列表条件隐藏，原页存在可用恢复入口 |
| 文件编辑与上传 | A 切 B 后立即撤销/重做，再切回；上传明确拒绝后再次选择同文件 | 文件内容与历史不串写；文件和草稿仍保留，同文件可以由用户再次选择，未知写入不会自动重传 |
| 弹层和长内容 | 长选项、动态参数行、长数值与单位，在相关窄窗口/缩放下显示并操作 | 实测弹层左右边界、正文及操作区均在可用范围内；无裁切、不可读截断或意外整页横向滚动，数据仍可完整查看/编辑 |
| 原生模态与主题 | 在 dialog 中打开 Tooltip/Message 并点击动作；深浅主题分别查看代码语法 | 浮层可见也可交互，不被顶层或 inert 隔离；语法文字按真实颜色测量，不只检查背景或 CSS 类 |
| 多任务状态与操作 | 同一会话同时存在运行任务和排队任务，分别取消；请求在途切换会话 | 状态摘要与实际任务一致，每个停止/取消入口的可见名称、可访问名称、请求 ID 和影响范围对应同一任务 |

几何和视觉断言应在字体及相关过渡完成后观察稳定状态，同时核对动作是否可达；不靠任意延时、放宽容差或隐藏内容掩盖问题。jsdom、路由 mock、DOM 数量断言和组件 props 不能替代对应的浏览器层级、禁用交互或实际路由装配证据。受控 IPC/HTTP 复现与正式 Electron、真实后端或供应商验收分开记录；未运行的层次不写通过。

## 5. 交付物

整体迁移沿用已有对象清单与验收台账；局部修改使用交付摘要，说明受影响对象、实现变化、实际验证的浏览器/视口/主题、证据与剩余缺口。仅在真实运行或任务要求时提供接口证据、截图、trace 或日志；不为凑齐材料制作空报告。设计变化同步所属规范，有长期取舍再维护决策记录。

台账记录需求版本、代码版本、控件ID、规则ID、测试ID、环境、预期、实际、证据和复验。不能将“已实现”“已写测试”“已验证”混成一种完成状态。

实际控件正文由[逐控件规格](../03-规范与术语/06-后台逐控件规格.md)按 P01–P20 索引。新增控件使用稳定编号；执行[索引同步脚本](../../tools/docs/sync_ui_acceptance_index.py)登记名称和来源，不更改已有实现、验收或证据状态。运行 `python -X utf8 -B tools/docs/sync_ui_acceptance_index.py --check` 检查遗漏；已登记对象从正文移除时检查失败，不能静默删除其未完成验收。

静态[控件候选清单](../08-数据与工具/platform-ui-control-inventory.json)由[源码盘点脚本](../../tools/docs/generate_platform_ui_control_inventory.py)生成，运行 `python -X utf8 -B tools/docs/generate_platform_ui_control_inventory.py --check` 检查新鲜度。候选节点、目标规则和已验证场景分开计数；静态提取成功不代表动态 schema、权限分支或运行时 DOM 已穷举。公开初始索引不携带内部历史通过结论，相关对象需按当前候选独立复验；部分自动验证只证明 observed 中的子场景，整项尚未走完时保持 `verification_status=not_executed`，不能批量标通过。

## 6. 完成标准

按任务范围选择完成标准，不将整体迁移台账要求套到局部修复：

- **整体迁移或明确约定的完整模块验收**：交付范围内 UI 对象全部登记、适用规则全部映射、承诺矩阵中的适用用例均有通过证据，真实核心链路验证完成；影响本次交付的未绑定或未决项已解决。
- **局部修改**：受影响行为达到约定目标，必要的直接回归与外观/交互核对通过，范围内已知问题已闭环，未引入已知回归；使用交付摘要即可，不补做全站盘点或重复登记无关对象。纯样式修改不要求重跑无关业务链路，涉及接口、权限或生效行为时补对应真实链路证据。

两类任务都需处理影响交付的已知功能、文案、对齐、遮挡、焦点、主题和数据保护问题；无关历史问题明确列为范围外，不据此宣称全站无缺陷。已有证据按[证据复用规则](../../.agents/skills/nw-verification/references/candidate-driven-delivery.md#证据复用与-verification-manifest)核对输入和适用范围后复用，仅补变化或缺失部分。

接受的风险例外另行显式记录，但存在例外缺陷时不得标为零已知缺陷。未完成、失败、待验证和环境阻塞必须如实列出，不能用“基本完成”“建议后续优化”“组件已经支持”替代。

最终结论只陈述实际验证过的范围和证据，不宣称有限测试证明所有可能环境永远无缺陷。
