## 2. 证据类型

| 类型 | 用途 |
| :--- | :--- |
| 单元测试 | 验证纯计算、校验、策略与局部状态处理 |
| 契约测试 | 验证公开输入输出、序列化与调用方和提供方的一致性 |
| 集成测试 | 验证真实存储、事务、消息、外部适配与装配边界 |
| 架构与 ABI 检查 | 验证依赖边界、公开签名和入口约束 |
| 数据查询 | 验证 schema 约束、迁移结果及权威数据与投影的一致性 |
| E2E 与故障演练 | 验证实际用户路径、跨模块组合与恢复结果 |
| 文档检查 | 验证引用、结构、生成来源与表达；不证明业务功能已实现 |

### 2.1 E2E 分层与完成语义

涉及 UI 的产品主链路验收使用“API 级真实 E2E + 浏览器关键冒烟”的组合证据；不要求每个 Runtime 状态组合都从浏览器启动。SDK 或适配器切片按实际公开入口验证真实组合，不因使用本指南追加浏览器或 HTTP 层；这些证据应称 SDK/适配器集成测试，不能宣称产品 E2E。

API 级真实 E2E 是所选产品链路的主要证据：测试通过真实网络端口、真实鉴权和公开 HTTP/SSE API 发送与前端序列化结果一致的请求，运行该链路实际使用的 Spring Bean、Flyway schema、数据库、消息与图谱等依赖，以及 Inbox、Execution Ledger、Usage Ledger、Outbox 和渠道投递的相关部分，不得用 Controller/Service 直调、MockMvc、内存数据库或 Runtime mock 代替受测业务与持久化路径。

直接模拟前端 API 参数仅在同时满足以下条件时可作为 E2E：请求形状由同版本 OpenAPI、共享类型或前端契约测试约束；测试走真实 HTTP；业务执行和持久化不被 stub；结果同时断言 API/SSE、权威数据库事实与 Outbox/Webhook 等传输事实。

浏览器冒烟只覆盖客户端独有风险：登录和 Token、开发/部署代理、请求序列化、SSE 解析、页面渲染、HITL 点击参数、刷新与回放。浏览器用例不得拦截或伪造 `/api` 响应；Runtime 的并发、幂等、重启、计量和故障矩阵保留在 API 级真实 E2E 与集成测试中。

当浏览器冒烟证明 UI → API 接线，API 级真实 E2E 证明同一契约版本的 API → Runtime → 数据库 → 页面投影/渠道链路时，可以组合判定产品主链路通过；只有单次运行以同一 runId/rootInputId 贯穿全部层时，才可表述为“浏览器起点的整链 E2E”。

本地确定性 OpenAI-compatible Provider 和本地 Webhook Receiver 可以用于 PR 门禁；真实供应商或外部渠道凭据联测属于独立的受控环境 smoke，不得把密钥写入仓库，也不得用其不稳定性阻塞可重复的主门禁。

当前测试入口与文件清单以仓库源码为准；每次验收记录实际候选、环境、命令和原始结果，设计导航不提供运行证据。

机构配置模型、知识资源与 ReAct Agent 后，应验证配置即用链路：从真实请求到检索、模型调用、持久化和响应。确定性 Provider 测试与真实供应商 Smoke 分开记录，不能以设计文档证明运行结果。

### 2.2 Agent 行为评测

Agent 工具行为评测按[行为评测指南](../../tools/chat_regression/BEHAVIOR.md)执行，发布矩阵固定验证 18 类场景各 3 次（54 个样本），并把部署修订、模型、套件、评测器、配置摘要和最多 60 秒的结算窗口写入 binding；这套评测补充 API 级真实 E2E，不拥有 Agent、Tool 或 Runtime 契约。

本地真实测试可通过 `local-run` 连接现有服务，并选择场景、重复数和单轮时限；所选实验全部通过时退出码为 0，报告仍不具备发布资格。`evaluate` 仅重评保存的证据，不重放 Runtime。正式发布验收必须连接按[权威启动指南](01-开发与部署指南.md#53-本地启动)准备的受控 Windows 环境，并提供绑定部署 revision 的环境收据；行为评测 workflow 不部署业务服务。每 30 秒仅回读模型、受测 Agent 和已发布系统 Agent 配置，不重验部署 JAR。已选矩阵未完成、未稳定结算或缺少必要证据时，结果只能是 `unknown` 或带阻断原因的失败。

`select --impact` 是无副作用的只读选择入口，`local-run --impact` 与 `--cases` 互斥；影响标签、core/stress 套件和默认重复数的精确映射见[行为评测指南](../../tools/chat_regression/BEHAVIOR.md)。core 54 样本与 stress 18 样本分别冻结、计量和判定，不能跨候选或跨套件拼接。细计量由离线 `behavior_measurements.py` 从冻结证据派生；Opik 2.2.82 本机 PoC 只接收脱敏派生视图，受控 Python 执行器、账本、冻结报告和 `release-check` 仍是权威，Java 不引入 Opik 依赖。

五类阻断原因可以同时存在：`failed_behavior`、`invalid_environment`、`invalid_config_drift`、`incomplete` 和 `budget_exceeded`；通过样本数不能覆盖其他阻断原因，也不能把未运行样本计入分母。

`behavior_status` 只反映样本代码硬断言；`release_eligible` 还要求 finalized、无聚合阻断原因和完整 binding。因此环境或预算失败可以保留已知的 `behavior_status: passed`，但发布资格必须为 false。`model_version` 未知不单独阻断发布 binding 匹配，但会使跨报告比较为 `comparability_unknown`，且成本不可比。

初始 core 54 样本和 stress 18 样本均不自动运行 Judge；Judge 只对少数明确的语义维度作为独立预算的可选补充，结果非阻断，不能覆盖硬断言、未知或其他发布阻断。人工校准、自动门禁和额外语义维度属于后续改进，不因存在标签或达到未经批准的比例阈值而改变当前发布资格。实现、真实环境验收和可选语义评审分别记录实际完成范围。

发布资格还要求 `behavior_main.py release-check` 使用 `GH_TOKEN` 经 GitHub.com API 验证成功的 `workflow_dispatch` run、候选 `head_sha`、精确 workflow 路径 `.github/workflows/agent-behavior-eval.yml`、run attempt、`agent-eval` environment 的 `required_reviewers` 保护规则和对应 `approved` 审批，以及 artifact `agent-behavior-evaluation-public` 中 `summary.json` 与本地公开报告的一致性。API 信息、权限或 artifact 任一项无法验证时失败关闭；这项来源核验不由开发者本地运行或 pull request 单元 job 替代。

## 3. 组织当前验证

1. 从 §1 的所属事实源选择当前要求和关键不变量，定位相关代码、已有测试及有效证据。
2. 按评审与验证规范的风险与测试路由执行最小充分验证；需要 E2E 时使用 §2.1 的方法。局部修改不因进入合并阶段就自动追加全模块编译、完整文档检查或浏览器套件。
3. 将观察到的结果与对应要求关联，记录实际范围、版本与限制；失败分类和证据复用直接按评审与验证规范处理。

Gradle Wrapper、定向测试、完整文档检查和 manifest 的命令统一见[评审与验证规范](../../.agents/skills/nw-verification/references/candidate-driven-delivery.md#测试路由)。实际 CI 入口见 [Java CI](../../.github/workflows/java-ci.yml)、[前端与 Helm CI](../../.github/workflows/ci.yml)、[Runtime E2E](../../.github/workflows/runtime-e2e.yml)、[Agent 行为评测](../../.github/workflows/agent-behavior-eval.yml)和[文档 CI](../../.github/workflows/docs-ci.yml)；工作流触发范围由配置定义，不能用指南中的省略覆盖必需检查或分支保护。
