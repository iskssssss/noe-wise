# 数据清理与保留规范

## 1. 用途与边界

本文是 灵知 数据清理的唯一操作事实源，适用于已明确授权的开发、测试环境业务数据重置和历史版本收敛。清理保留可登录、可配置的系统基础环境；业务模型与 Runtime 契约仍归[数据模型设计](../02-架构与设计/03-数据模型设计.md)和 [Harness](../../harness-design/README.md)。功能变更时的同步维护要求归[工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md#数据库与迁移)。

执行前确定数据库、租户、关联存储和保留范围。本文不自动授权其他环境清库；单租户清理不能使用全环境整表清空方案。服务停启统一遵循[开发与部署指南 §5.3](01-开发与部署指南.md#53-本地启动)。

默认保留平台管理员、指定验收租户及管理员、系统内部租户、必要套餐、当前可用模型及加密凭据、租户模型选择、平台运营设置和系统 Agent。保留官方 Skill、当前代码内置工具及当前环境明确指定保留的业务模板；删除清理范围内的业务、测试记录与运行产物。账号密码、密钥、临时 PID、数据数量和执行对象 ID 不写入本文。

## 2. 数据登记与保留规则

### 普通保留与累计正文预算

普通终态 Session/Run 历史、被替代的 Memory 历史及终态通知/投递材料默认保留 30 天；撤销或过期安全会话默认保留 90 天；审计沿用 180 天策略。期限是进入所属事实域资格判断的条件，活跃、等待、结果未知、有效记忆、冻结准备、恢复/发布/重建/调查引用继续受保护。30 天不缩短原幂等键和精确重放的有效保障，也不授权批量删除现有环境。

Session 展示历史退役绑定真实 CLOSED Session 修订、精确关闭时间和完整 owner。受控 DELETE 先核保护闭包，并以同事务来源锁排斥新引用；保留完整原命令摘要与 eventId/sequence 墓碑，旧命令精确重放不产生新事件，异命令不得重新绑定原身份。诊断回收同样保留墓碑。受保护项后续重查，扫描水位不能让它们永久跳过；公开退役水位不回退。普通退役不表示 checkpoint、journal、receipt 或全部恢复来源已经释放。平台诊断须提示 owner 推理历史不完整，owner 累计退役数量不证明某次 attempt 曾有或丢失推理。

R5 在 V287 增加 Owner 有界退休：`retireOwners` / `OwnerBatch` 接入宿主清理，每批最多 4 个 Owner、16 个对象及 8 MiB 正文预算；Session 必须真实 CLOSED 满 30 天，各 Run 的自身终态事实也须满 30 天。事务按 Owner `NO KEY UPDATE`→Session→有限 Run/对象锁定并重查保护闭包，`agent_runtime_session_owner_retirements` 保存可续接进度。热 Owner 根、Session 创建及 CLOSED CAS 的小审计事实继续保留；九类大字段转为薄热身份并保留完整精确归档，当前有效 command、receipt、checkpoint 通过 resolver 读取原值。UNKNOWN、未 ACK 发布、恢复、Task、Memory、调查及其他实际引用仍保护来源，退休不能重新执行效果。checkpoint/body 冷读以二次 SELECT 核完整身份和摘要；新 checkpoint 复用仅存于冷层的正文时以内联完整 TypedPayload 保存。

正文保留以实际引用为条件：phase10 只选择有精确热 body-ref 的正文，冷 INSERT 门禁再次核对并锁住引用；phase11 先保存对应冷引用，再删除热 checkpoint 及热引用，直接删除热引用也须同样证明；phase12 在行锁后重查引用并删除零热引用正文。没有真实引用的正文直接回收，不产生冷副本；并发创建真实引用时保护正文并允许后续有界续接。Owner/Run FK 只证明归属，旧 getter、旧 record 或旧格式不构成永久保留理由。上述条件不授权既有环境转换或清理，目标环境须独立验证。

| 保留类 | 所属 owner 与实际责任 | 合法释放条件 |
|---|---|---|
| Owner、Session 生命周期及退休进度 | 完整租户/target/Session 身份、关闭修订、重复受理与有界续接事实 | 普通正文退休不释放根身份；所属 Session 的整体生命周期按明确范围处理 |
| input/admission、commit、Run/inbox、mutation 与可靠发布事实 | 当前输入/操作键和原回执、Run 状态与提交来源、未 ACK 发布及恢复/Task/Memory/调查引用 | 热大字段只有精确归档证明才能置为引用；完整事实沿当前有效幂等及 Session 恢复责任保留，不依据表名规定永久期限 |
| checkpoint 与正文引用 | Run 当前记录、提交日志和操作结果持有精确 checkpoint；热/冷 body-ref 持有精确正文引用 | 热 checkpoint 退出前必须形成同身份冷 checkpoint 与所需冷引用；剩余真实引用继续保护正文 |
| 零引用 checkpoint 正文 | tenant/Run 仅定位归属；没有 body-ref 即没有 checkpoint 恢复引用 | 原 collector 或有界退休在锁内重查后实际 DELETE；不先复制到冷层，不为归属关系创造恢复义务 |

上述类别描述当前责任，并非对 13 张表统一永久保留或统一删除。冷复制、冷引用新增、热字段缩小和真实 DELETE 分别计量，逻辑热退休字节不代表热加冷净减少或数据库物理空间回收。

图片 unused 资源按真实 pin、Run、有效后代和共享正文引用判定。仅从未 pin、无 Run 且精确闭包无保护引用的根和变体，满足所属 CLOSED owner 的 30 天及更严格媒体保留条件后，才可在 owner→tenant→metadata 锁下重查并释放正文；同 Session 无关的永久历史不单独构成该图的引用。保留必要媒体 UUID 墓碑，pin 和 Run 绑定单调，已使用正文不得解除保护，晚到重试不能复活或重绑定。

累计 Session/机构媒体与机构知识正文预算默认只观测。显式配置额度后，在所属租户和资源事务锁内核验新增正文，超额拒绝且完整回滚；同域精确正文复用和不增加正文的操作按实际增量计量。低于已有占用的新限额只约束后续新增，不隐式回收已有正文。实际机制需核对当前源码，媒体与知识契约分别归 [多模态专题](../../harness-design/03-多模态内容与媒体引用.md)和[知识存储设计](../02-架构与设计/20-知识不可变内容与存储治理.md)。

正文引用、块和暂存关系必须纳入下列关联登记。新建环境按完整正式迁移链验证；既有环境切换前先确定目标库/构件、源库与文件/索引的恢复点、停止新受理及 UNKNOWN 保全方式。恢复回到仍保留的源库和对应旧构件，另行协调新环境期间已经发生的外部调用；不得回滚数据库后盲目重放这些调用。

### 工具接入原命令与回执

`nw_tool_onboarding_receipts` 保存机构、原请求身份、操作者、连接器与有序工具选择、请求指纹、唯一处理权及状态；成功回执只冻结工具、定义、版本和部署身份，不复制工具说明或连接凭据。`PROCESSING` 可能表示执行中或结果未知，必须保留，不得按普通 TTL 删除或重新派发。`SUCCEEDED` 和 `REJECTED` 是原命令终态，继续支持原身份核对和防止同键重用；当前没有已验证的安全删除条件或自动清理，不能因对象改名、删除、关闭页面或普通保留期限届满删除。将来清理须先明确幂等保证、恢复和调查引用的释放条件与授权，不删除或改写历史事实。

### 技能创建回执

`nw_skill_create_receipts` 每次成功创建只保存请求 UUID、作用域、操作者、请求指纹、定义和草稿标识及初始修订，不保存技能文件或描述正文。回执与技能、草稿同事务提交，供原主体只读核对及同键去重；当前没有已验证的安全删除条件或自动清理，不按普通 TTL 删除。新增写入的数据库开销与成功创建次数线性相关。

### 机构智能体创建回执

`nw_agent_create_receipts` 每次成功创建保存机构、请求 UUID、操作者、请求指纹和智能体标识，不保存提示词或配置正文。回执与草稿同事务提交，用于原主体核对及同键去重；当前没有已验证的安全删除条件或自动清理，不按普通 TTL 删除。新增记录数量随成功创建次数增长。

### 知识库组合发布回执

`nw_knowledge_revision_publish_receipts` 保存机构、原请求 UUID、知识库身份、操作者、请求指纹和状态；成功回执随知识库修订、能力版本及活动指针在同一事务提交。`PROCESSING` 是已登记但尚无最终回执的事实，可能仍在执行，也可能因中断而结果未知；必须保留原身份，不按普通期限删除或重新派发。`SUCCEEDED` 和 `REJECTED` 支持仍有知识库及对象读取权限的原操作者按原请求核对，也阻止同一 UUID 绑定不同参数或操作者；关闭页面、知识库改名或普通保留期限届满均不是释放条件。当前没有自动清理或已验证的安全删除条件；未来清理前须明确原命令防重、结果核对和调查引用的释放条件，并取得针对目标环境与范围的授权。发布回执不表示知识库已挂载或检索质量已验收。

### 业务演示数据与本地回执

业务演示与验收资源通过管理 API 创建，按普通业务对象治理。需要保留可复演示环境时，整体保留其 Agent 有效发布版本、团队、知识来源版本/分块/索引、自建 Skill、MCP 部署、Workflow 定义与安装、渠道、角色和体验用户；明确清理全部业务资源时，按实际关系一并删除，不将演示对象误作系统内置资源。仓库不再提供业务 Workflow、行业 MCP 与演示数据种子；系统 Skill 包、平台通用工具及其管理/执行机制继续保留。

演示会话、根/子执行、Workflow 待办与检查点、工具回执、记忆、模型用量和成果按各自现有生命周期保存；等待、取消中或结果未知的执行不得当作过期演示缓存删除。业务清理需要先停止相关执行，核对未知操作及引用，再依当前 API 和所属存储顺序处理。共享平台模型、已发布官方 Skill 和工具不得随单一演示机构删除；演示曾修改的共享运营设置只能在确认无其他使用方后按记录恢复。

Git 忽略目录 `.runtime-logs/capability-demo/` 中，`resources.json`、`documents.json` 和验证回执用于幂等核对与追溯，不应在保留线上资源时先删掉；丢失后必须通过管理 API 确认归属和版本，不能直接重新创建。原始资料缓存与文档快照按固定版本和摘要保留，分发时附上许可及来源；可重建不等于可以删除仍用于验收的证据。

`access.local.json` 和 `providers.local.json` 含本地账号、渠道或模型凭据，不提交或复制到公开报告。明确结束演示并获准撤销访问时，先撤销实际账号/令牌或轮换临时密钥，再删除相应本地秘密；只删文件不能撤销服务端访问。证据归档应脱敏，保留资源、执行与成果关联及失败原因。该目录清理仍须核对解析后的绝对路径并限定到已授权范围。

通用图片媒体与 BrowserSkill 的目标生命周期见[多模态内容与媒体引用](../../harness-design/03-多模态内容与媒体引用.md)和[远程浏览器接入](../02-架构与设计/18-BrowserSkill远程浏览器接入.md)。原图、规范化图片、请求变体和截图证据沿用所属会话、附件或产物的归属；只要有效消息、冻结请求、恢复事实或成果仍引用材料，就不能单独按缓存 TTL 删除。图片从模型视图卸载不解除持久引用、不删除原图；请求变体可在引用解除后重建或回收，不能把已冻结变体指向新字节。浏览器配对凭据、设备绑定、任务、调用回执和待清理意图按个人空间隔离，未知调用及未完成清理不能当作过期成功任务删除。新增表与存储目录在实现迁移时补入下列登记；本段是已批准目标，不表示这些存储已经存在。

`config.memory.automatic_extraction` 随 Agent 发布快照保留，工作草稿的修改不改变生效权限。关闭已发布配置的自动提取不删除既有 MemoryFact 或队列记录；跳过的 extraction jobs 继续按原 Session 来源保留，不以关闭开关作为数据清理授权。

Memory extraction job 的五元去重键、完整 source/result 外键和稳定 outcome 持续保留。宿主以成功 `finish` 写入 COMPLETED/SKIPPED 作为 job 领取执行材料结束的事实，同时清空 `candidate_data` 与 `claimed_at`；它不表示来源 SessionOwner 已退休。当前模型的旧成功终态须有 `completed_at`，现有租户事务内的 `limit 200 / FOR UPDATE SKIP LOCKED` 补压缩涵盖候选已为空但领取时间尚未清空的行，最终 UPDATE 再核资格和剩余材料，重复调用为零写。READY、PROCESSING、FAILED 及缺少完成事实的异常行保留，不新增 job TTL、整行删除、旧状态/格式兼容或来源/结果解除。验证应覆盖成功 finish、分页续接、重复零写、锁竞争、租户与回滚保护。释放执行材料不代表删除 job 行，也不保证物理容量下降。

业务资源使用稳定身份与独立发布历史，运行生效规则见 [Harness 对象模型 §2.3](../../harness-design/03-核心对象模型与状态机.md#23-稳定资源身份与发布快照)。历史清理必须同时核对当前发布指针、运行快照、模板安装、能力和工作流安装引用；正在运行、等待、结果未知或需恢复的任务所引用版本不能按“不是最新版”删除。历史恢复只生成工作草稿，不解除原执行的引用。旧环境存在同 key 多业务身份或多工作草稿时，新唯一约束不自动推断合并或删除数据；重建、清理目标与恢复方式须先明确授权。

MemoryFact revision 与 head 按记忆 scope 保留归属，来源会话 target 由 `agent_runtime_memory_fact_sources.source_target_kind/source_target_id` 及其事件外键保留。[V252](../../backend-java/skillforge-migration/src/main/resources/db/migration/V252__memory_fact_scope_ownership.sql) 只删除事实表和 head 表上误加且无消费者的 `target_kind/target_id` 列、对应检查约束及引用这些列的错误 Session target 触发器，保留记忆历史不可变、head 版本递增和来源必需约束；不删除事实、来源、操作回执或提取任务，不改变租户 RLS 与保留期。DDL 使用 `RESTRICT`，额外外部依赖会阻止迁移，不能以级联删除扩大修正范围。

[V258](../../backend-java/skillforge-migration/src/main/resources/db/migration/V258__memory_restore_decay_projection.sql) 在记忆从非 ACTIVE 恢复为 ACTIVE 的同一事务中重置派生衰减投影，不删除事实、来源或操作回执，不改变保留期；幂等重放不会重复重置。

模型私有推理与上下文快照保留在原 Runtime 事实中用于协议续接，沿用所属 Session/Runtime 表的生命周期；公开 Chat/Trace 隐去正文不删除或改写这些事实，也不产生新的副本或保留期。聊天 `commentary`、执行过程和最终消息沿用既有 SessionLog/Session Outbox 生命周期，不新建独立存储或单独保留期。历史 Outbox 经当前公开投影过滤后传输，不通过清库消除泄漏。任何原始冻结测试证据继续按受限运行目录规则保留，不以公开脱敏结果覆盖原证据。

公开投影成功检查点（来源水位、事件、政策、已受理输入与跨批过程状态）及永久格式拒绝回执保存在既有 `nw_chat_session_outbox_sequences` 锁行，随所属 Session/Outbox 统一清理，不增加独立保留期。该处理回执不改变原日志、运行终态或投递状态；来源仍需恢复时，不单独清除拒绝记录以制造反复投影，也不删除来源来伪造处理成功。

原文回收材料 `agent.context-material` 与准备预算事实 `agent.preparation-budget` 使用原 SessionLog 生命周期。只要关联的运行、准备或精确原文引用仍需恢复，就不能单独删除材料、预算来源或替换冻结内容。预算根、Run 分额、attempt、缺报预留、结算回执和活跃区间是恢复依据；未结算或结果未知不得按 TTL 回收。清理所属会话/任务时按外键依赖统一处理，旧根的未知调用不能迁移到新任务，也不为历史版本补造预算。

长过程上下文的来源索引、正文摘录和已核验回读范围是 `agent.context-view` 的派生内容，与原 SessionLog 材料及冻结准备共同保留和清理，不新增表、独立 TTL 或自动长期记忆；机制见[上下文专题](../../harness-design/03-上下文视图与执行优化.md#5-可恢复的内部原文引用)。

准备操作的可信时间样本沿用原 instructions 与 SessionLog 生命周期，恢复所需时不能单独替换或删除。命令内 checkpoint 解码复用及固定 Loaded/revision/fence 范围内的不可变准备缓存仅存于进程对象，不新增表、TTL、清理任务或持久保留期；动态 IAM、租约与取消不进入缓存。 checkpoint 的持久引用存储与进程缓存是不同所有者；`agent_runtime_session_checkpoints` 的二进制正文、准备表独立 payload 及准备来源引用的原输入账本、Profile 与 SessionLog 事件必须保持原字节和身份，随所属 Session 及全部引用统一清理，不新增自动 TTL。新持久格式仅在新建或明确获授权转换/重建的环境启用，不直接应用于仍使用旧格式的开发库。

产物 `public-output-v5` 策略升级保留旧文件、来源与检查证据；旧检查记录不能直接升版作为公开依据，真实重新检查后才取得新凭据。策略升级不构成文件删除或业务清理授权，正常生命周期继续按[产物设计](../02-架构与设计/12-代码执行沙箱与产物交付.md#52-元数据与原子发布)执行。

Knowledge 决策中的有界 `query` 与调用快照中的查询文本按原 Session 决策、准备 journal 和 Knowledge 结果生命周期保留，不新增表或独立查询日志；清理时与所属会话事实一起处理，不能单独改写查询文本导致冻结指纹失配。

显式启用内部证据采集后，测试目录的 `trace.json`、逐轮 trace 与 `evidence.json` 可包含完整模型上下文和私有推理；只保存在当次验收清单定位的本地行为回归运行目录或 `.runtime-logs/` 受限子目录，沿用原始测试证据保留和清理规则。禁止直接上传到 Opik、CI artifact 或提交 Git；对外仍使用独立脱敏导出。数据库 DSN 仅存在进程环境，不写入采集来源清单、配置摘要或报告；采集器不写数据库、不新建数据库对象。

### 连续上下文与模型能力格式切换

Session 连续上下文的有效契约见 [Harness §13.1](../../harness-design/03-上下文视图与执行优化.md#131-供应商-prompt-cache-与前缀稳定性)。投影选择快照与 APPEND/REBASE/REPLACE 事件使用既有 SessionLog，指向不可变 preparation、原模型最终结果和冻结提交命令；它们不是可独立删除的供应商缓存。`agent.preparation-controls` 的完整授权目录映射、目标摘要、模块选择与当前 Run 事实，以及原 instructions、能力 Snapshot、input ledger、context view/材料、Run checkpoint 的 adoptedOperations 和 commit journal，共同组成恢复引用闭包。终态、ACK、进程缓存释放和新的模型准备均不解除这些引用；仍需恢复的任何一环不得单独删除、回填或改指向。

模型绑定格式 4 由 [V269](../../backend-java/skillforge-migration/src/main/resources/db/migration/V269__model_binding_prompt_prefix_capabilities.sql) 前向迁移增加三个类型化前缀能力字段，并纳入新绑定摘要；V106/V138 保持原文。旧格式 3 行只保留原字节，新列为 NULL，不提供旧绑定恢复；结构约束验证封存行与新格式的完整性，`model_binding_current_format` 的 `NOT VALID` 只跳过旧行扫描，仍强制所有新写入为格式 4。新受理从当前受信模型配置发布下一绑定 revision，旧精确引用不改指向。绑定格式切换时对应的 Core context、invocation、请求指纹与 Agent 渲染也作为完整闭包替换，精确版本由各生产组件拥有。这些格式直接替换旧格式，不提供旧 binding、旧准备或旧投影的原地兼容。不能给旧 revision 补默认能力、按当前 Provider 目录推断支持、更新 digest 后继续原调用，或用新渲染重组旧冻结请求。精确版本归各生产组件，格式检查失败是切换条件未满足，不是清库理由。

NativeConversation 协议替换同步使用 Core `model-request.v2`、`context-snapshot.v7`、`model-outcome.v5`，Session `prepared-model-request.v2`、`execution.context.v2`、`execution.completed.v2`、`preparation-profile.v4` 与 `input-log.v33`；精确 schema 前缀与编码仍由对应源码拥有。桌面配置使用 `noewise.desktop.configuration.v4`，显式冻结 ObserveOnly 累计策略，并从同一原 Run 来源构造 LoopBudget；DesktopPolicy 保留宿主准入、单次输入输出、调用期限和租约，移除累计任务上限。Session 只计量模式要求显式的单次最大输出，不能把累计限制删除为缺失的输出保护。旧 v1/v2/v3 桌面配置只保留原事实并拒绝恢复和继承。新版本不接受旧 NativeDecision、旧终结工具映射或旧冻结格式继续执行，不为旧记录补新默认值或重建动作；不清空数据库、不转换旧 Run，也不重放未知外部调用。旧记录保留原字节和既有终态；平台的旧完成事件因缺少新必需引用身份而明确拒绝，不补造 citationId，桌面 getSession 继续只读展示原已提交事件。需要旧执行对象的恢复或续接明确拒绝，使用新建会话进入新协议。

SQLite 预算根、Run 与余额表明确保存 `ENFORCED/OBSERVE_ONLY`；只计量的累计上限为 SQL NULL，真实收尾保护仍保存其数值。首次打开旧数据库时，[初始化迁移](../../backend-java/agent-runtime-adapter-sqlite/src/main/java/com/skillforge/runtime/adapter/sqlite/SqliteDatabase.java)在同一个 IMMEDIATE 事务中复制并重建原三表，将旧有限账本逐项标记为 Enforced，保留原消耗、UNKNOWN 预留、attempt、回执、阶段、活动区间与引用，外键检查通过后才提交；失败回滚原结构和原值。该物理迁移不授权旧桌面配置继续运行，也不把旧预算改成 ObserveOnly；重开读取持久模式，不依赖运行时回退或当前默认。PostgreSQL/JDBC 当前仅支持 Enforced，在访问连接或加入写事务前明确拒绝 ObserveOnly，本次不增加 PostgreSQL 预算模式迁移。

业务调用预算改名不改写既有计量事实；旧 Agent 覆盖 wire 字段明确拒绝，物理列沿用原存储映射。Workflow 的步骤与节点回访终止原因独立后，私有 invoke/recover outcome 使用 v2，旧 v1 明确拒绝恢复，control outcome 仍为 v1；保留旧材料及原结果，不通过清库、补值或当前枚举重解释旧回执。

切换前先确认目标环境及是否包含需保留的旧冻结事实；盘点在途、等待、结果未知、待采用和可重试操作及其完整依赖，形成备份与恢复范围。新建环境按目标迁移链创建；已有环境需要明确授权的转换或重建方案，单独定义旧执行如何结束或保全、未知外调如何协调、新受理何时停止及恢复，以及哪些历史仅作为原版本归档保留。不能将未知操作搬到新任务重新执行，也不能让未经验证的新格式继续承接旧恢复责任。

原地升级可以保留旧库全部历史，使用正式新建 Session 验收新格式，无需关闭或删除旧会话。保留数据不等于新版本兼容其展示与恢复：普通新输入在没有活跃 Run 时可创建新 Run，但历史澄清、旧输入重放及部分聊天详情仍会读取旧冻结对象，可能明确拒绝。历史访问如需原版本能力，应使用保全的旧构件与对应备份，在隔离、禁止外部副作用的恢复环境中处理，不能让新旧服务同时写同一执行事实。升级后的新调用及外部结果必须保留，不能通过回滚数据库把它们当成未发生。

落实切换时按已授权方案停止相关写入并核对静止状态，保全原不可变字节及精确引用，再处理明确环境和依赖闭包。不得在普通启动中自动清库、改 Flyway checksum、运行 `repair`、跳过 schema 校验或升级旧绑定。切换验收同时覆盖新受理、准备来源全值回读、journal/CAS 采用、进程重建、未采用事实协调、分支恢复及主体隔离；没有旧格式转换证据时，只能声明新格式环境通过。本文规定切换方法，不构成服务重启、数据库转换、环境重建或历史数据删除授权。

### 2.1 PostgreSQL 表登记

应用关联、执行凭证、Agent 部署和用量导出遵循各自事实生命周期。暂停应用或撤销凭证只阻止新的受理与访问，不删除机构、Run 冻结版本、会话、原始用量或已发布事件。单机构清理只处理已明确授权机构的实例和执行事实，不删除共享应用、公共 Agent 定义或其他机构的关联。用量确认、调整、导出游标和消费者幂等回执在对账或恢复仍需使用时共同保留，不能因消费成功单独删掉原始用量。

多机构场景示例的本地凭证和钱包状态使用指定运行目录保存，属于敏感访问与幂等恢复材料；不提交到仓库。结束示例时先在服务端撤销访问，再按授权范围处理关联业务对象与本地文件。重新开始消费不能通过清空游标或钱包流水消除未知扣款，应先核对事件关系和已有账本。

工具定义由 `nw_capability_definitions` / `nw_capability_versions` 承载，旧 `tool_definitions` 与 `invoice_line_items` 不再属于现行模型。模型费用直接只读原用量账本；按已批准的销售功能退役范围，[V339](../../backend-java/skillforge-migration/src/main/resources/db/migration/V339__remove_sales_billing.sql)使用 `RESTRICT` 删除 `nw_billing_price_audit`、`nw_billing_sales_prices`、`nw_billing_invoice_usage_claims`、`nw_billing_invoices` 及两项销售保护函数，旧销售数据全部删除且不保留归档。发现未声明依赖须停止，不扩大级联范围；目标环境是否已执行以实际迁移回执为准。

基础表中的账号、租户、套餐按已确认名单保留，不能仅凭创建时间或名称前缀判断。混合表必须按对象保留，不能整表清空。旧销售价格、审计及账单按上述 V339 删除且不归档；不再登记为保留配置。模型价格随原模型不可变版本保留，原始用量、成本确认、导出游标及未终结回执仍按各自原规则处理。`nw_model_price_overrides` 已由 V236 移除，不再属于保留对象。保留的主对象，其身份、加密凭据、状态和有效配置保持一致。

普通 Agent 按 `tenant_id + agent_id` 稳定身份定位，机构内 `agent_key` 唯一；发布历史按 `nw_agent_publications.id` 和所属 Agent 的发布修订定位。保留对象的发布配置与挂载快照不改写，工作草稿不代替当前发布指针，也不以最大编辑或历史修订推断生效版本。清理时核对当前发布指针、ChannelBinding、Session、团队和 Run 冻结引用：当前生效及被执行引用的发布快照必须保留，其他历史仅在明确授权并解除引用后处理。发布在稳定 Agent 行上协调并发，不存在独立 revision 1 根行的保留要求。

带 `request_id` 的保存发布记录同时是原命令的成功身份，随 Agent 稳定身份保留，不作为单独历史清理候选；否则删除后同键重试可能再次发布。`request_fingerprint/request_actor_ref` 与该行同生共存，不另建响应正文、TTL 或清理任务。删除 Agent 或清空已授权租户数据时按原外键及执行引用一并处理；原 Agent ID 不复用，后续核对返回资源不存在，不因缺少回执重建对象。

`nw_platform_billing_scans` 是 [V230 迁移](../../backend-java/skillforge-migration/src/main/resources/db/migration/V230__platform_billing_scan_receipts.sql)定义的平台非租户套餐配额状态扫描永久回执表，主键为 `(actor_id, operation_id)`；`actor_id` 来自平台认证主体，不能由客户端指定。表启用并强制 RLS，平台策略只允许平台管理员身份访问。领取、机构状态变更和完成回执在同一事务中提交；回执不能随旧销售账单删除，也不能删除后复用旧操作键。只有已授权的全量环境清理可以删除该表记录，且必须同时记录旧操作键已失效、清理完成后客户端不得继续以旧键重试，并重新核对平台审计与机构套餐配额状态边界。

套餐配额状态扫描回执只记录操作键、扫描数量、状态变化数量和完成时间，不包含密码、密码哈希、密钥或密码日志。密码和其他凭据不属于本文登记的清理/保留对象；任何排障输出也不得把请求体密码或校验失败的原始值写入报告。

历史发布隔离 schema 中的旧 Runtime 表也属于数据库业务数据。例如旧 `agent_runtime_session_tool_projections` 可能仍有跨 schema 外键指向当前动作账本，须与当前运行事实在同一事务中清空，保留表结构。先核实隔离用途，在当次清单逐项登记 schema 与表名，不按 schema 前缀批量删除。外置 dump、文件归档属于恢复备份，与这些仍参与数据库引用的旧表区别处理。

审核决定 `nw_workflow_review_decisions` 属于追加审计事实，正常业务不得修改或删除。其模板外键为 `RESTRICT`；仅在已授权的环境业务数据清理中，按第 4 节先归档并清理审核记录，再删除目标模板，恢复不可变触发器。UI 的页签、查询和列偏好仅保存非敏感状态；退出账号清理其业务会话缓存，不清理无关用户偏好。

`nw_knowledge_documents` 只保存稳定文档身份、当前 `source_version` 指针与软删除时间；标题、正文、来源元数据和完整分块集分别由 `nw_knowledge_document_versions` 与 `nw_knowledge_chunks` 按版本留存。正常编辑、分块变更、重索引和文档删除不得原地改写或删除 ready 版本，也不得清理其外部索引。只有已授权的环境业务数据清理可连同 Runtime 冻结副本和 Knowledge Base revision 一起删除这些历史；操作时先按引用关系清理冻结与发布记录，再以明确表名处理分块、来源版本、文档身份和知识库，并按第 4 节记录不可变触发器的临时解除与恢复。

全库重建的文档项引用原始来源版本，批次向量与未知调用历史保留其确切模型身份和计算归属。失败、取消以及显式重试均不构成清理授权；成功批次不能因重试重新计算或覆盖。获授权清理所属知识库时，先终止并确认任务写权失效，解除 `nw_knowledge_bases.rebuild_job_id` 引用，再按批次、文档项、任务及来源版本的依赖顺序处理。模型身份新增字段不推断或回填旧向量所属模型；V256 的非空来源模型约束面向新建或明确授权重建的数据库，有旧知识版本的数据库需先制定独立迁移／重建操作，不能在普通服务重启中自动清空。

人工协助正文的聊天和模型权威来源是 SessionLog 中的 `human.assistance` 事件。`nw_handoff_reply_requests` 保存受理正文、作者快照、请求指纹和事件回执用于可靠提交，不另建聊天事实；事件已提交但响应未保存时必须按同一命令恢复。清理时先处理受理记录与工单引用，再按所属产品 Session 的统一生命周期处理历史、Outbox 和冻结准备，不能只删回执导致同键消息重复。人工消息进入冻结准备后，即使工单解决也不得改写对应正文。

| 模型、运营配置和平台系统工具部署 | 当前配置主表的有效版本指针；保留其所需依赖。运行时冻结快照及调用历史不属于配置 |

系统启动不安装或重发 Skill，官方与机构自建 Skill 均由管理流程独立发布；内置工具启动会发布代码声明的版本。Skill 的有效状态以 Catalog 及挂载的精确版本为准，清理保留仍被引用的包、所需发布历史与仍在维护的编辑草稿。取消系统预置不授权删除已有 Skill 定义、发布版本或挂载。清理工具版本前核对运行 JAR 与源码目录一致，防止重启又生成被删版本。非系统 Agent 和业务模板只由管理流程写入数据库，启动及迁移不创建、不覆盖、不重新发布业务模板；删除业务模板后重启不会自动补回。源码整理不授权删除数据库中已有模板或安装实例。

通过管理接口创建的机构、成员、测试模板、Agent、团队、渠道及终端用户属于普通业务数据，不因名称带“测试”或存在准备回执而成为内置保留项。业务演示准备脚本已移除；环境重置后旧资源回执仅为历史证据，不能继续作为在线资源或重放依据。系统 Skill 与项目开发规则不属于这类业务种子，清理自建 Skill 不删除系统包、系统版本和仍需维护的系统草稿。

供应商 Prompt Cache 不新增本地缓存表、存储目录或第二份 Skill 正文。缓存范围哈希只派生在本次受控 Provider 调用中，不单独持久化；既有冻结请求、记忆来源、Skill 版本和 SessionLog 继续由各自事实域保留。停用 Skill 释放新视图正文不删除原事实。显式删除 Session 必须先停止其执行并按原引用顺序清理，不能把改变哈希或删除本地 Session 宣称为已经清除供应商缓存；供应商侧到期与删除由对应服务政策控制，选择方法见[开发指南](01-开发与部署指南.md#442-供应商缓存服务选择与验证)。

### 2.4 行为评测与 Opik 本机 PoC 数据

行为评测原始批次位于当次验收清单定位的本地行为回归运行目录；导出目录默认位于 `.runtime-logs/opik-exports/`，导入收据位于 `.runtime-logs/opik-import/<目标地址摘要>/receipts.json`。这些内容不是 灵知 业务表或可在线查询的 Runtime 事实。清理前先按[行为评测指南](../../tools/chat_regression/BEHAVIOR.md)核对批次是否仍需追溯，并按批次的候选版本、环境与原始结果区分历史证据、当前冻结候选和待验证路线图；不能用删除原始证据来消除失败或未知结论。

只有脱敏后的导出内容可以导入本机 Opik；受控 Python 执行器、账本、冻结报告和发布检查仍是行为评测权威。Opik 的展示数据属于派生视图，平台故障不能触发 Runtime 重跑，也不能把导入成功当作评测或发布通过。计量未知只在报告中保留未知状态，不使 export/import 非零；只有导入错误或未完整读回才非零。批量便利接口不保证去重，清理或重建时不能重复生成同一批次的 UUIDv7 映射和收据编号。

Product 合成数据批次还包含候选池、全部生成尝试、拒绝和选择结果、冻结数据集、生成计量、浏览器证据及人工待评记录，应与同批执行证据共同保留。`generation/resources.json` 和 `browser-resources-private.json` 属于私有恢复资料，后者含一次性返回的渠道令牌，禁止提交 Git 或导入 Opik。生成 Agent、业务测试 Agent、终端用户、知识库版本、Skill、Workflow、Team、渠道及报告文件通过既有业务 API 创建，以批次前缀和资源日志识别；清理必须按实际挂载、发布版本、会话和产物引用顺序进行，不按名称模糊匹配批量删除，也不得清理共享平台模型目录或系统 Agent。

Opik PoC 由[本机管理说明](../../deploy/opik-local/README.md)定义，使用独立 Compose project 和命名卷。执行 `down` 只停止服务并保留卷；删除卷、清除导出目录或清理历史收据必须在明确授权的环境清理中核对绝对路径、批次范围和恢复需要，不能触及 灵知 的数据库、Compose 卷或其他应用数据。PoC 关闭后端 usage/OTel 上报、远程模型注册、Python evaluator、AI/演示数据生成和代码执行；不对前端 Statsig 或其他前端 telemetry 作关闭结论。

### 2.5 最终成果生命周期

文件公开检查凭据由[V245 迁移](../../backend-java/skillforge-migration/src/main/resources/db/migration/V245__artifact_public_output_inspection.sql)定义，随精确文件和Session保留，由文件外键级联清理；未结算 Goal 完成请求的文件及其凭据保持恢复保护。消息版本与结构化引用由[V246 迁移](../../backend-java/skillforge-migration/src/main/resources/db/migration/V246__chat_message_versions.sql)定义，引用冻结材料与公开拒绝事件沿用所属 Input/SessionLog 生命周期，不新增保留期。

最终成果的 11 张表由 [V231 最终成果生命周期迁移](../../backend-java/skillforge-migration/src/main/resources/db/migration/V231__final_deliverable_lifecycle.sql)定义。`nw_task_output_plans` 的候选状态和 `nw_task_evidence` 的独立证据默认仅保留 7 天；`nw_deliverables`、`nw_deliverable_revisions`、`nw_deliverable_representation_files` 的交付文件引用和 `nw_deliverable_representation_sources` 的来源文件引用随所属 Session 保留。`nw_deliverable_file_holds` 保护准备和发布阶段已冻结的文件，以及 `goal_completion_state=pending` 尚未收尾的交付文件、来源文件和证据文件；发布已提交或计划已 finalized/abandoned 不解除 pending 请求的恢复保护。清理任务遇到 hold 或 pending 完成请求时跳过并在后续周期重试，避免破坏发布后 Goal CAS 与回执恢复。请求 settled/superseded 后才能按成果引用及正常期限解除保护。

成果链收敛通过 [V335 专属要求契约退出迁移](../../backend-java/skillforge-migration/src/main/resources/db/migration/V335__retire_output_requirement_contracts.sql)按准确依赖闭包退出 V326 的八张 `output_requirement_*` 语义契约表及其专属函数，不改写历史 Flyway 文件，不保留旧契约双读或重跑模型重建。退出对象仅为候选要求、接受表达式、来源证据和修订／Run 绑定等专属结构；原用户输入、Goal／批准计划、Run、文件、正式成果版本、发布／完成请求、模型原始记录、外调回执、UNKNOWN、用量及安全审计按各自原生命周期保留，不能随八表级联删除。

`output-requirements` 系统用途停止新受理并归档配置，历史不可变版本、执行和计量事实继续保留；其他系统用途不随其删除。已有环境实施该迁移前，按本规范确认准确目标、恢复点及在途／结果未知的执行处理，代码收敛和文档变更不表示已清理或升级任何业务数据库。新执行不依赖旧接受契约，旧历史证据也不转换成当前要求或新的执行许可；实际成果 hold、发布恢复及 Goal 完成请求仍按前后段保护规则处理。

完成请求绑定原 Goal/revision/Run/result_ref 和稳定操作 ID，只表示投递进度；Goal 状态仍以 SessionLog 为唯一事实。恢复先核查原操作回执，再判断 revision 竞争，不恢复模型续行许可。显式删除 Session 前必须先停止其模型执行与完成请求处理，再按完整 Session 归属删除请求和成果关系；不允许常规到期任务提前删除 pending 请求或其来源文件。跨版本旧数据库不形成兼容义务，改写迁移链只在新建或明确授权重建的隔离环境验证；已有环境重建须先确认目标、影响与恢复方式。

候选文件清理分两次判断：先筛选已到期且无引用的文件，再锁定对应 `nw_execution_artifact_files` 行；标记为 `expired` 前必须在同一事务重新核对有效 hold、正式交付文件引用、正式来源引用和未到期 `nw_task_evidence`。任一关系存在即跳过，不能依赖锁前查询结果删除。物理文件只在成功标记过期后删除，随后标记为 `deleted`；删除失败时保留可重试的过期状态。

`nw_deliverable_revisions`、`nw_deliverable_representations`、`nw_deliverable_representation_files` 和 `nw_deliverable_representation_sources` 由迁移触发器禁止原地 `UPDATE`；所属 `nw_task_results.status` 不再是 `pending` 后，也禁止追加表示、交付文件引用或来源引用。正常保留期清理应按引用关系 `DELETE`，不能改写已发布正文或向已结束结果补引用。

删除 Session 前先撤销其成果下载和预览能力，阻止后续签名 URL 访问，再按成果引用关系删除；不能让物理文件清理早于数据库引用解除。当前用户仍在使用的 Agent 渠道保持可用，清理 Session 成果不删除该用户的当前 Agent 渠道绑定。

## 4. 操作顺序与恢复

1. 读取本文及启动指南，核对目标环境、保留对象、实际表清单、关联存储及执行权限；输出不含凭据的保留清单和预计删除数量。复用当前配置，从实际端口重新发现服务，不能沿用历史 PID。
2. 暂停网关和相关后端、后台调度与沙箱写入，核对无在途 Run、执行容器或数据库写连接；用户明确要求全部取消时先完成取消，不自动重放业务请求。
3. 在独立执行目录生成 PostgreSQL custom-format 全库备份，检查退出码与 `pg_restore --list`；备份关联 Redis 数据、产物和沙箱任务。备份成功前不删除。操作 SQL、数量报告与备份位置存执行目录，长期结论按 [Note 治理](../../.agents/skills/nw-docs/references/notes-governance.md)归档。
4. 在单个维护事务中锁定已登记对象，按明确表清单清空运行事实、业务引用、审计和待删除主对象，再裁剪混合表与配置版本。整表 `TRUNCATE` 只用于确认全部清空的依赖闭包，不使用无边界 `CASCADE`；混合表按保留名单 `DELETE`。
   删除最终成果时，先将 `nw_deliverables.current_revision_id` 置空，再依次删除 `nw_task_result_deliverables`、`nw_task_evidence`、`nw_deliverable_file_holds`、`nw_deliverable_representation_files`、`nw_deliverable_representation_sources`、`nw_deliverable_representations`、`nw_deliverable_revisions`、`nw_deliverables`、`nw_task_results`、`nw_task_output_plans` 与 `nw_execution_artifact_files`。交付文件和来源物理快照仅在所有成果文件关系、来源关系、有效证据和 hold 清除后删除；不得先删文件再依赖失效外键补救。
5. PostgreSQL 发布版本、账本和审计有不可变触发器。V231 的四个成果正文触发器只禁止 `UPDATE` 或非 `pending` 结果的追加，按第 4 步顺序删除时应保持启用；其他对象确有删除触发器阻挡时，记录其原状态并只对必要对象临时解除删除限制。数据修改完成后先执行 `SET CONSTRAINTS ALL IMMEDIATE` 检查引用并排空延迟约束事件，再用 `ALTER TABLE` 恢复原触发器状态，避免 pending trigger events 阻止恢复。不使用全局 `session_replication_role=replica`，不关闭外键。提交前检查保留引用、版本唯一性和触发器状态；事务内错误立即回滚。
6. 数据库提交后处理关联存储。Redis 按命名空间删除；搜索按已确认索引处理；文件操作先核对解析后的绝对路径属于目标根目录，停止写入后清理子项，保留根目录及归档备份。Windows 只使用同一 PowerShell 中的原生文件操作，不跨 shell 拼接删除命令。
7. 跨存储清理没有全局事务。某一步失败时保持业务停写，按执行记录重试未完成步骤；需要恢复时同时恢复数据库及对应文件/索引快照，再重启。Redis 可从数据库重建的临时缓存不恢复旧业务状态，不能先开放部分恢复的环境。
8. 按启动指南恢复服务，复用未变化且已验证的构建产物；确认初始化器没有重建测试数据或历史版本，再执行接口验收。备份保留至已批准的保留期，不作为在线业务数据使用。

常用只读入口如下；连接参数使用本地实际值，不能把示例当作目标确认。

```sql
SELECT current_database(), inet_server_addr(), inet_server_port();
SELECT schemaname, tablename FROM pg_tables
WHERE schemaname NOT IN ('pg_catalog', 'information_schema')
ORDER BY schemaname, tablename;
SELECT conrelid::regclass, confrelid::regclass, pg_get_constraintdef(oid)
FROM pg_constraint WHERE contype = 'f';
SELECT c.relname, t.tgname, t.tgenabled
FROM pg_trigger t JOIN pg_class c ON c.oid = t.tgrelid
WHERE NOT t.tgisinternal ORDER BY c.relname, t.tgname;
```

备份使用 `pg_dump -Fc`，恢复前用 `pg_restore --list` 核对清单；在 Windows 通过 `docker cp` 或二进制文件流保存 dump，不能经文本管道转码。恢复先暂停应用，并使用已核对版本的 PostgreSQL 工具；已有库的 `pg_restore --clean --if-exists --exit-on-error --single-transaction` 仅在恢复授权和目标再次核对后执行。

## 5. 接口验收与完成标准

- 平台及保留租户管理员重新登录成功；机构、平台和网关就绪接口正常，已启用沙箱与产物预览监听正常。
- 模型、运营设置、系统 Agent、官方能力和指定保留的业务模板能通过管理接口读取；版本列表符合每对象一个版本，默认或发布指针可解析。
- Agent、团队、会话、知识库、工作流、渠道、集成、账单和运行历史等业务列表为空；旧业务对象与旧产物读取返回不存在或拒绝访问。
- 清理脚本提交前的引用与空表断言负责覆盖未公开接口的底层表；接口验收不为查空而增加管理接口，不创建新的聊天或产物。
- 登录、限流及后台健康检查可能产生新的必要临时记录，与被清除的历史业务记录分开统计。报告保留数量、删除数量、实际覆盖、备份位置与未验证项；不输出凭据。

验收使用接口，不要求浏览器、全量构建或重复完整测试；文档维护集中检查改动范围的链接。后续清理必须依据最新本文和实际 schema，历史成功报告不能代替当前清单核对。

### 本地 JAR 与验收临时文件

本地服务的新运行副本通过就绪检查后，及时清理已停止且不再被进程、待启动操作或必要复现引用的旧 JAR。删除前重新读取完整进程命令行，核对实际副本的绝对路径；保留当前运行 JAR，不覆盖运行中的归档。旧版本仍用于缺陷复现时，先保全所需最小库、输入及来源摘要，确认复现不再依赖整个运行副本后再删除。清理回执记录删除路径、文件摘要和释放字节，不删除诊断日志来代替清理 JAR。

已完成验收的可重建字节码缓存和与保留包摘要完全一致的检查副本可及时回收；未知用途文件、失败证据、幂等回执、正式成果及恢复仍引用的数据按其所属生命周期保留。文件清理限定到已核对的本地目录，使用同一 PowerShell 的原生文件操作；数据库和关联存储清理仍按本规范的明确环境、对象及引用顺序执行，不能依据文件名称或“旧数据”标签扩大范围。

### 最终交付文件与临时执行文件

`nw_execution_artifacts` 及其 ready 目录只登记 `output_files` 声明且执行成功的最终目标文件（含 HTML 必需资源）；不能按 JSON、TXT 或其他扩展名识别临时文件。`input_files` 和附件按类型化清单流式写入沙箱 `input/data`，工作临时文件位于 `work`；stdout/stderr 留在内部持久执行日志，固定 `output/result.json` 是仅供类型化业务结果采用的内部输出文件，不能同时登记为交付产物，均按沙箱任务保留期清理。请求期 ZIP 在提交结束或失败后立即回收，不拥有恢复任务状态；崩溃遗留 staging ZIP 沿用 staging 孤儿清理规则。失败、取消及超时的输出同样按任务工作目录清理，不提升为 ready 产物。历史已发布快照不可通过修改 manifest 原地删减；需要处理时按已确认的产物 ID 和整体快照执行保留/删除规则，先核对引用关系。

用户上传的输入附件由 `nw_chat_session_attachments` 保存元数据，[V284 共享正文](../../backend-java/skillforge-migration/src/main/resources/db/migration/V284__session_media_attachment_body_storage.sql)以租户、摘要、长度及格式绑定 `nw_chat_attachment_bodies` 的单一不可变二进制正文。普通输入附件最长保留正文 7 天，到期后所有查询和执行立即拒绝读取。受理输入与构造传输清单以元数据为基础；无文字目标的纯附件输入按[附件文本准备预算](../02-架构与设计/12-代码执行沙箱与产物交付.md#用户上传的会话附件)冻结已授权小文本读取事实，大文件或其他类型不批量加载到模型上下文。传输当前文件时重新授权并校验冻结大小、摘要和有效期。[附件清理器](../../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/attachment/SessionAttachmentCleanup.java)按稳定租户水位执行有界、可续接批次；每批在同一租户锁和事务内解除过期正文引用，再回收全部附件及媒体均不再引用的正文。积压快速续批，空闲恢复十分钟巡视，物理回收可能晚于七天逻辑失效。元数据保留必要 UUID、归属、路径身份、摘要、长度和时间，去除名称等非必要展示字段，墓碑不能被迟到上传或重试重新绑定；删除所属会话时按其生命周期级联删除元数据，共享正文仍须核对全部引用。沙箱中的附件副本按任务工作目录保留期清理；已冻结的小文本读取事实随所属 Runtime input ledger 保留和清理，不因附件原件到期改写既有执行事实。元数据清单和公开执行证据不返回附件正文。


### 会话项目文件与快照

会话持久工作区的归属、执行和快照设计见[沙箱设计 §4.3](../02-架构与设计/12-代码执行沙箱与产物交付.md#43-会话持久工作区)。独立项目卷中的 `/workspace/project` 随所属产品会话保留；主、委派子 Session 的工作区分别授权。任务级 `/workspace/work`、`/workspace/output` 和 `/input` 继续按冻结任务保留期清理，临时任务 Janitor 不得扫描或删除项目卷。

[V268](../../backend-java/skillforge-migration/src/main/resources/db/migration/V268__session_workspaces.sql) 的 `nw_chat_session_workspaces.cleanup_state` 使用 `active/pending/complete`：active 允许授权操作，pending 保留待清理意图，complete 阻止迟到调用重建。`nw_chat_session_workspace_imports` 保存关联操作来源，不包含文件正文。两表启用并强制租户 RLS；产品会话关联不使用级联外键，清理记录不会随产品行删除而丢失。

空闲本地副本仅在无活动写入、无冻结/恢复操作且最新修订已经完成云端备份后可归档回收。最新修订未备份、上传失败或云端不可用时保留本地数据，磁盘压力通过拒绝新写入处理。成功快照按工作区政策保留最近版本，淘汰前核对在途上传、恢复和引用；删除失败持久记录重试，不改写当前备份指针。快照 ZIP、上传暂存与恢复暂存分别检查所属操作，不能按目录年龄删除仍参与恢复的数据。

显式删除产品会话时先拒绝主、子工作区新访问，收敛相关 Run、容器与子进程，再持久登记全部关联工作区的删除意图。物理清理独立重试，删除墓碑阻止迟到调用重新建目录；不得仅依赖删除 `chat_sessions` 的级联消除清理意图。云端只能按精确工作区前缀删除，不清空整个 Bucket 或服务卷；结果未知和未完成清理记录不能当作普通缓存回收。

已发布正式成果持有独立不可变文件及来源引用，工作区归档、快照淘汰和命令修改不删除或改写这些文件。会话整体清理仍按成果与 Runtime 引用顺序处理；关闭工作区能力只阻止新操作，不清除已有文件、快照或清理回执。

### 通用图片与浏览器执行证据

[V284 附件与图片正文](../../backend-java/skillforge-migration/src/main/resources/db/migration/V284__session_media_attachment_body_storage.sql)由 `nw_chat_session_attachments` 保存各自元数据身份，通过精确外键复用租户内 `nw_chat_attachment_bodies` 的不可变正文；每张原图、规范化图、裁剪图和请求变体仍保留独立 owner、MIME、来源及转换事实，正文复用不合并媒体身份。`mime_type IS NULL` 的普通输入附件继续按七天逻辑失效及后续有界引用解除处理；图片的 `expires_at` 为 NULL，不套用普通附件 TTL。原图不因生成变体被覆盖，已有冻结请求采用的变体不随当前策略更新。`runtime_session_id` 保存逻辑媒体归属，`session_id` 保存产品会话生命周期，`media_run_id` 记录工具图的可信来源；委派会话图片不会凭产品展示关系自动成为父 Agent 可读材料。[累计正文容量](../../harness-design/03-多模态内容与媒体引用.md#7-请求计量与容量)默认只观测，显式正额度在租户锁和外层事务内拒绝超额新增正文或会话正文归属，精确复用按实际增量计量；调低限额不回收已有正文，也不使已绑定的精确重试失效。

媒体保护与未使用资源退役归[多模态专题 §9.1](../../harness-design/03-多模态内容与媒体引用.md#91-媒体保护与未使用资源退役)。未使用上传图须已保存至少 30 天，产品与逻辑媒体的完整 Runtime owner 均有真实 `CLOSED` 满 30 天的事实；原图及可退役规范化后代还须从未 pin、无 Run 绑定，且精确闭包不存在冻结、恢复、读取、发布、调查或其他有效保护引用。Run/Action 的活跃、等待或结果未知（UNKNOWN）状态、有效裁剪或请求变体等后代继续保护；缺少可靠 owner 关闭事实时保留。[V286 专属门禁](../../backend-java/skillforge-migration/src/main/resources/db/migration/V286__runtime_session_storage_lifecycle.sql)与[媒体退役服务](../../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/media/SessionMediaReclamation.java)在同一事务按 owner→tenant→metadata 锁定并重查，解除可退役闭包的正文引用；共享正文仅在全部附件和媒体引用消失后回收，精简 UUID 墓碑阻止复活或重绑定。普通附件过期任务不处理 `expires_at IS NULL` 的图片，已使用或仍受保护的媒体继续随所属生命周期保留。显式删除 Session 前先停止相关根/子 Run，撤销访问、核对引用并按所属 Runtime 事实清理顺序处理，再清理图片和变体元数据及无引用正文。实现及验证需针对当前候选分别核对；目标与源码存在不代表整批已验收。

浏览器机构回执由 [V254](../../backend-java/skillforge-migration/src/main/resources/db/migration/V254__browser_call_receipts.sql)持久化；browser-service 持久卷保存按 `tenant + end_user` 隔离的 BSK_HOME、tracked-start 绑定、调用回执、取消意图、设备偏好和截图/录制输出。已提交但结果未知的回执不能作为普通临时文件清除，否则相同调用可能重新产生外部副作用。普通界面刷新只读已有回执，截图注册到媒体后不重新执行浏览器截图。

按需连接请求及恢复身份随来源 Session/Run 保留；活动等待、恢复尚未确认及结果未知时不得按普通缓存清理。Browser service 只保存一次性配对凭据摘要、连接请求关联和准确设备结果，不保存额外原始配对串。关闭网页不删除连接请求；取消或 Run 终结使请求停止恢复，但不撤销用户已经建立的独立设备授权。连接关联与原执行回执分开保留，清理关联不能解除 unknown 回执的防重放保护。扩展可信站点和官方设备凭据由浏览器 profile 管理，服务器清理不直接删除用户扩展存储。

授权控制的成员/渠道操作者审计复用 `nw_audit_logs`，按已有审计保留策略处理；个人目录的 `authorization-audit/events` 追加保存控制阶段及脱敏设备集合观察，`last-observation.json` 只作为下一次差量的基线。撤销授权和服务重启不删除这些记录，未知控制结果或未归因授权丢失调查中的记录不得作为普通缓存清理。只有按精确个人归属获授权清理、且相关调查证据已归档后，才随该个人目录处理；不保存或备份额外的原始配对凭据。

知识库 ES 投影修复不创建新来源版本、模型调用或 PG 发布事实，只按既有分块身份覆盖可重建索引。部分修复失败保留已提交 PG 来源，可对同一来源显式重放。原来源及分块仍按知识版本引用与重建任务保留规则清理，不能为了修复索引删除活动或历史引用中的 PG 版本。

撤销设备授权不等于删除回执；服务重启也不自动清空持久卷。首版没有浏览器证据自动到期清理：只有明确授权清理时，先停止该个人任务、撤销设备、确认拥有的进程静止，再按精确个人目录与机构回执范围清理；媒体中的截图副本继续遵守 Session 生命周期。不要删除整个服务卷来清理单一会话，也不能用本地图片留存声称外部网页被固定。


### 配置精简后的冻结引用与技术清理周期

Run 的 `nw_host_run_settings` 和动作冻结配置保存不可变准备 Profile 的精确引用；Profile 与 tokenizer 保存实际策略、模型窗口、内容字符资源限额及历史分页。引用仍被执行或恢复事实使用时，不得单独删除 Profile。运营配置只维护任务根额度及资源、产品行为，技术清理调度由组件代码管理：任务临时目录与产物清理均每 60 分钟执行；保留周期继续使用运营配置。会话项目目录使用独立工作区归档与备份政策，不套用任务临时目录周期。容器控制超时默认 15 秒，画像摘要批量默认 20。改写历史迁移链只用于新建或明确授权重建环境，不对已有环境自动清库、更新 checksum 或转换旧冻结格式。
