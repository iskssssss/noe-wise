# 通用任务续接配置

Runtime 契约见 [ConversationTask](../../harness-design/03-核心对象模型与状态机.md#561-conversationtask-与跨会话续接)。

## 启用

1. 在新建或已批准升级的环境应用迁移 V166、V167；本功能不要求删除业务数据库。
2. 只有需要通过机构端管理面执行任务 `correct` 时，才在平台系统智能体页面配置并发布 purpose 为 `task-context` 的模型。该用途不参与普通聊天；未发布不会阻止聊天或按需任务工具运行。
3. 使用机构端 Agent 会话。在聊天右侧“任务”页点击“管理当前会话任务”，进入任务进展页面；页面选择有权访问的来源会话后可查询任务。需要将任务带入新输入时，在入站 `extraParameters.task_id` 中显式指定任务 ID；管理页的“设为当前任务”不等于后续聊天输入自动携带该字段。

普通聊天直接调用主模型，不在入站分类、搜索或修复任务，也不在回复、暂停或外部动作前自动创建、更新或保存任务。跨会话任务只在同一 tenant、用户和助手内可见；缺少显式 task ID 时不会读取 current 任务或把旧任务接到本轮。

显式 `extraParameters.task_id` 先验证归属，再读取并冻结对应快照；该快照只提供参考，不授予工具执行权或替代当前身份校验。任务候选列表只提供定位所需的标题、摘要、状态和修订，所选任务单独提供完整业务状态。事实值、来源事件引用、确认标记和待办均保留，完整身份与来源账本继续持久化并由恢复和合并路径校验。

`SessionTaskContext v3` 只保存可选的只读选择，不以 `TurnMode` 门禁聊天、记忆、Skill 或业务工具。主模型按需使用 `search_tasks`、`read_task`、`update_task`；每项调用重新校验当前身份、来源、revision 与幂等。记忆默认也不自动查询，需时由模型调用 `search_memory`。问候不会清除已保存任务，失败、取消、终止或没有回复不等于本轮待执行，执行中的请求由原 Run 推进。

任务工具不因标题相似、近期发生或模型推断自动选择旧任务。一次性查询不要求存在候选任务，也不自动授予业务写入权限。任务路由和来源修复提示词资源已不参与机构聊天或系统用途调用。

## 管理和失败处理

任务管理入口位于聊天任务面板。管理页面必须携带一个有权访问的来源会话，列表不默认展示整个机构的用户任务。纠正、结束、重新打开均生成事件；并发更新冲突时刷新核对后重新操作。

任务工具调用失败、任务修订变化或 `correct` 所需系统用途未发布时，都不视为业务已完成。恢复任务不会自动重发旧业务调用；外部操作结果以原工具或 Workflow 结果为准。任务信息不能取代实时号源、库存等业务查询，也不能代替用户提交确认。

通过挂起引用与版本校验的 Agent HITL 回复属于用户输入，可作为明确纠正事实的确认来源；普通 action 或工具结果不能因此获得用户确认语义。

管理面的 `correct` 使用 `task-context` 系统用途处理受控纠正；它必须保留并校验来源事件、任务归属和预期 revision。普通聊天不会调用该用途，也不会发起来源修复。纠正不重发失败或结果未知的模型调用。

通用任务续接按已发布 Agent、Workflow 和能力挂载配置运行。

当前实现采用通用 facts、pending 和摘要结构。按 Skill 注册业务状态 schema、绑定 Skill 版本、动作级确认失效以及外部业务回执适配尚未实现；不能将事实的 confirmed 字段作为业务操作授权。
