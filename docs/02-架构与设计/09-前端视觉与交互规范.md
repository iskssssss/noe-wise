# 前端视觉与交互规范

> 本文定义后台双端与独立会话端的视觉边界；共同的状态、反馈与排版原则也适用于桌面渲染层，后台专用控件和尺寸不跨应用套用。共享职责见[前端共享层设计](08-前端共享层设计.md)，组件契约见[前端组件库](13-前端组件库.md)。

## 1. 设计来源与适用范围

两个后台采用轻量自建布局与 Element Plus。普通按钮、输入、表单、表格、分页、选择器、抽屉、对话框、菜单及反馈直接使用 Element Plus；公共层不重复实现同类基础控件或包装 API。

后台公共样式负责品牌、页面层级、间距、内容区和主题，Element Plus 负责控件内部状态、键盘与焦点。独立会话端维护自己的样式与组件，不导入后台公共资源。

后台支持范围按[桌面交互规范](../03-规范与术语/05-后台系统交互规范.md#1-事实源与适用范围)执行；独立会话端保留自身窄屏面板与触屏交互，当前组织见[会话端说明](../../frontend-chat/README.md)。设计与评审方法由 [UI 技能](../../.agents/skills/nw-ui-ux/SKILL.md)维护，宽度、截断与输入适配按其[响应式专题](../../.agents/skills/nw-ui-ux/references/responsive-layout.md)选择相关场景，尺寸不能跨产品直接套用。

## 2. 页面、导航与标签

后台使用单页路由、侧栏与面包屑，浏览器原生多标签用于并行任务。不实现应用内多标签、页面缓存、拖拽标签和导航右键菜单。菜单使用可访问链接，当前页面及详情所属入口清晰可见。

页头包含明确的业务标题和主要操作，必要说明就近展示，正文按当前任务组织筛选、数据和编辑区。以适中密度区分标题、主要内容和辅助信息，避免重复卡片、重边框和冗长说明占据首屏。长表单按业务分组，低频配置可折叠并展示当前值摘要；页面内容区滚动，列表不强制固定高度。加载、失败、空结果与无权访问均应有可辨识状态及可执行下一步。

### 2.1 内容容器与留白

页面内容区、卡片、表单分组、编辑区、标签面板、折叠面板、弹层及空态应有与层级和内容密度相匹配的内边距，文字、输入与操作不直接贴靠容器边界。按所属产品复用现有公共样式、组件默认值及间距令牌，同级容器保持一致；不对所有元素统一设置一个 padding 值，也不为增加留白强制套卡片。

- **容器负责边界留白**：明确由哪一层提供内边距，子级已获足够留白时可不重复设置；相邻元素的距离使用 gap 或 margin，文字行距使用 line-height，避免用空格、空行或异常行高撑开布局。嵌套容器检查最终可用宽度，防止多层内边距累加挤压内容。
- **控件与状态保持完整**：表单标签、辅助说明、错误提示、编辑器首末行和操作区均保留必要留白，焦点环不被裁切。空态、加载和失败状态沿用所属容器的边界留白，检查表格或列表继承的行高与高度，避免说明文字行距过大、操作被无意义空白推离内容。
- **窄窗口与缩放仍可用**：在所属产品支持范围内按现有间距尺度调整，优先换行、重排或局部滚动；不能通过清零必要内边距、缩小文字或点击区域来塞入内容。展开折叠区、显示错误或出现长文本后，内容仍可读、操作仍可达，整页不产生意外横向滚动。
- **贴边设计有明确对象**：满幅图片、分隔线、表格外框或编辑器外壳可按设计贴合父容器；其中的文字、单元格、编辑内容和操作仍由所属组件提供内部留白。例外不扩展到同一区域的其他内容。

调整留白后，在实际渲染中核对受影响容器的四边、同级对齐和嵌套总间距，并检查相关的长内容、错误或空态及窗口变化；通过标准是内容不贴边、不裁切，且无过度留白挤压主要内容。CSS 声明了 padding 或单个尺寸截图通过，不等于完成视觉验收。

### 2.2 内容宽度与信息密度

按任务选择内容宽度：单列表单和长篇说明保持便于阅读、定位字段的行宽，不随大屏无限拉长；表格、多列比较和文件编辑区利用可用工作区，按信息关系分配列宽与面板宽度。优先沿用同类页面和组件的宽度约束，不规定全项目统一最大宽度。

标题、辅助说明和主要操作靠近其作用的内容；表单按业务分组，避免相关字段被大段空白或装饰分隔。调整密度时同时检查内容较少与较多的状态：少量内容不为填满屏幕强制拉高，多量内容不靠缩小字号、挤压点击区或层层嵌套容器提高密度。窄窗口优先换行或重排，滚动边界按[响应式规则](../../.agents/skills/nw-ui-ux/references/responsive-layout.md#空间分配与信息保留)处理。

筛选区的同组动作作为整体换行，避免“刷新／重置”等关联按钮各自散落；动态参数行、图表名称、数值与单位允许按可用宽度收缩、换行或改为上下排列。宽度约束作用到实际抽屉、下拉弹层和内容区，不能只约束外壳；长选项的名称与说明应可完整阅读或明确展开，固定像素宽度和 `flex-shrink: 0` 不得使必要字段落到视口之外。

### 2.3 视觉值与令牌选择

新增或调整字号、尺寸、间距、圆角等视觉值时，先确认组件默认值是否适用，再复用所属产品已有公共样式或语义匹配的令牌；不为复用而套用含义不同的令牌，也不编造尚不存在的键。已有明确设计约束时以该约束为准。

现有值不能表达局部需求时，允许在所属组件设置有设计或实际渲染依据的局部值，必要时就近说明原因；不为单个尺寸新增全局配置或要求额外审批。只有多个消费者具有相同语义和变化原因时才提取公共令牌，并核对直接消费者。共享令牌更新时清除覆盖同一语义的过时副本，保留有独立用途的局部值；颜色、层级与可访问性约束仍按所属规范执行。

## 3. 主题、文本与可访问性

后台主题由 `--admin-bg`、`--admin-surface`、`--admin-text`、`--admin-muted`、`--admin-border`、`--admin-accent` 和 `--admin-hover` 定义；挂载前应用偏好。表单控件和弹层同步 Element Plus 明暗主题。

专业编辑器的语法高亮随主题切换，分别核对字符串、数值、布尔值、关键字和注释的真实前景/背景对比度；只切换编辑器背景及普通正文颜色不算完成深色适配。

交互控件有明确的可访问名称，图标按钮有 aria-label，焦点可见。危险、成功、等待和错误同时有文本，不只依赖颜色。按系统减少动画偏好关闭非必要动效。

图标与文字的对齐按 [UI 技能的视觉对齐规则](../../.agents/skills/nw-ui-ux/SKILL.md#视觉对齐)核对实际轮廓、基线与视觉重心，容器几何居中不作为视觉对齐的充分证据。

### 3.1 可访问性尺度

以下作为受影响界面的设计要求，按具体改动核对；引用标准用于解释尺度与例外，不要求每次修改遍历全部条款，也不代表产品已通过完整 WCAG 认证。

| 对象 | 要求与适用边界 |
|---|---|
| 文字对比度 | 普通文字至少 4.5:1，符合标准定义的大字号文字至少 3:1；辅助文字和禁用原因仍需可读。非活动控件、纯装饰及标志按[文字对比度标准](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)例外处理，不能把实际说明文本都视作禁用控件。 |
| 控件与图形 | 识别控件、状态所必需的视觉信息及有含义图形，对相邻颜色至少 3:1；纯装饰边框不一律加深，非活动或未修改的原生控件按[非文字对比度标准](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)例外处理。 |
| 点击区域 | 通常至少 24 × 24 CSS px，约束实际命中区域而非图标图形；密集操作保持独立，不重叠热区。小目标若采用间距例外，以其边界框中心的直径 24 CSS px 圆检查，不能与其他目标或其他小目标的对应圆相交；行内链接、等效入口等按[目标尺寸标准](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)处理。 |
| 文字缩放与重排 | 文字放大至 200% 不丢内容或功能；垂直阅读内容在等效 320 CSS px 宽度重排，避免双向滚动。必要的二维表格、图形或编辑区域可局部滚动，不豁免整页；这属于[文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)和[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)要求，不把后台扩展为手机完整功能承诺。 |
| 用户文字间距 | 对适用文字，覆盖为行高 1.5 倍、段后距 2 倍、字距 0.12 倍、词距 0.16 倍字号时，不裁切、重叠或丢失功能；[文字间距标准](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)约束覆盖后的容纳能力，不要求默认使用这些数值，语言不适用的属性除外。 |

## 4. 浮层与反馈

抽屉与对话框直接使用 Element Plus，页面拥有开关、表单与提交状态。普通创建和编辑从右侧抽屉打开，复杂配置进入独立维护页，删除、发布和丢弃修改使用确认对话框。后台普通抽屉宽度为 680px，大型详情为 960px，最大宽度不超过视口；挂载到 body，标题和底部操作区保留在可达位置，正文独立滚动。

编辑抽屉不因点击遮罩关闭。取消、关闭按钮、Esc、路由离开和主动退出使用同一未保存检查；提交中禁用关闭和重复提交，失败后保留输入。只读展示抽屉可通过遮罩关闭，有回复或编辑字段的详情按编辑抽屉处理。会话端根据自身面板布局实施同一关闭语义，保持资源独立。

原生 `dialog` 使用浏览器顶层；其中的 Tooltip、下拉及带操作的 Message 应处于正确的顶层/模态归属中，同时可见、可点击且不处于 `inert`。不能只靠提高普通 `z-index` 或一律传送到 `body` 处理；模态关闭或触发对象销毁后清理或回迁相关浮层。

确认说明对象与影响，按钮使用“删除”“发布”“丢弃并关闭”等明确动作词；取消返回原处。补充详情在原确认内展开，不叠模态；一次仅一个活动确认，重复入口不重复写请求。取消不是业务错误。

操作成功、失败、警告及读取失败统一使用页面顶部 Message，后台复用公共反馈入口，独立会话端使用自身 Message 实现。同一反馈只展示一次，不在页面、登录表单或抽屉内重复展示，也不另用 Notification。Message 仅放简短主文案、必要动作及“排查信息”入口；安全诊断在可用 Esc 关闭的独立只读 MessageBox 展示。消息去重且最多三条；普通消息 4 秒，错误或含详情/后续动作默认手动关闭。写成功与随后读取失败分开，不诱导重复创建/发布；下载只提示“已发起下载”。

反馈责任按用例或批次确定：并行请求中的每个拒绝都由同一边界承接，再聚合用户可操作的原因；不能只认领 `Promise.all` 的第一个错误，或用 `allSettled` 吞掉异常后仍让 HTTP 层重复提示。批次中已成功的内容继续保留。文案匹配当前动作，登录失败不能套用业务写入的“核对结果”，安全诊断与主提示分开。

同文案去重不能合并或丢失对象身份。多个来源共享一条 Message 时，各对象的恢复动作仍正确可用且目标可辨认，来源卸载后移除或交接其动作，不保留失效闭包；直接 `action` 与插槽操作采用相同的持久时长规则，后来加入动作也不能被旧计时器关闭。用户手动关闭提示后，失败区域仍有可辨识占位及重新打开恢复操作的入口，重新打开本身不自动发请求。

提交忙碌仅表示真实在途的提交或核对，UNKNOWN 保持可见的原操作记录与核对入口，不当作成功、失败或永久 busy。无请求在途时，允许通过具体后果确认离开；说明离开不撤销原操作、不能把未知当失败重新发起。取消离开仍保留原视图、输入和操作身份，具体恢复资格见[错误处理](../../.agents/skills/nw-error-handling/SKILL.md#重试与未知结果)。

字段校验仍在字段旁持续显示；静态说明、长任务状态及结果未知的业务记录保留在所属内容区。表单提交和读取失败由顶部 Message 承接，需要重试时保留明确动作；页面已有消息承接时通用请求层不重复提示，过期请求或换号结果不提示。GET 可明确重读，写结果未确认先核对原操作。刷新失败保留旧数据，首次加载失败不伪装空态。

字段单位、留空含义、依赖关系、不可修改条件和危险影响使用可见辅助文字，后台统一使用 `admin-field-help`，通过 `aria-describedby` 关联对应输入；不能只依赖 placeholder 或 Tooltip。补充解释可使用 Element Plus Tooltip，触发入口同时支持鼠标和键盘。名称等含义明确的字段不堆砌无帮助的提示。

单行查询和普通表单保留合理的 Enter 提交；中文输入法确认候选词不触发提交，多行文本和代码编辑器保留换行。禁用按钮需要在附近说明当前缺少的条件，提交中显示真实状态。

## 5. 列表与表格

后台表格使用 Element Plus 的自动表格布局，按字段内容分配宽度，不将所有列均分。名称、说明和关联对象保留较大的最小宽度，状态、时间、数值及操作按内容设置宽度；操作按钮不折行。单行长文本设置溢出提示，初始内容宽度按 360px 上限参与分配；表格分配剩余空间后，文本填满实际列宽再省略，完整信息通过提示或详情读取；空间不足时使用表格自身横向滚动。复合内容、编辑控件和结构化正文保留各自排版。

需要多对象比较或批量操作的列表直接使用 ElTable、ElTableColumn、ElPagination，页面明确绑定查询、列展示与动作；少量概况、任务引导和配置摘要可按业务分组展示，不为统一外形强制套表格。服务端不支持的排序、导出和批量能力不提供虚假入口。分页、筛选与操作必须绑定当前对象和查询范围。

金额保留精确字符串，空值、日期时间、状态使用领域规则。长文本可展开或进入详情，表格横向溢出由容器滚动，不把业务内容截断为不可访问文本。

## 6. 聊天、Markdown 与技能工作区

独立会话端根据会话、消息、公开过程、等待、确认和成果组织界面，输入区保持易访问；执行中允许继续编辑下一条草稿，但不能重复发送。恢复连接、核实状态与取消执行分别显示真实含义。

同一会话存在运行与排队任务时，会话摘要优先反映实际运行/等待状态，并说明排队情况；“停止当前任务”和“取消排队任务”标明各自任务及影响范围，视觉文字、可访问名称和实际请求目标一致，不能提供多个无法辨认对象的“停止”按钮。

新内容到达时，仅在用户原本跟随末尾阅读的情况下继续跟随；查看历史内容时保留阅读位置，提供新内容提示及回到最新入口。图片、附件与流式内容变化不应把正在阅读的内容推出视野，切换会话后的滚动位置属于各自会话。

只展示服务端公开 presentation，最终答复与中途过程分开，等待与需要操作的卡片不能被过程折叠隐藏。成员详情受父任务授权限制，子任务完成不代表主会话完成。协议与恢复约束见[前端共享层设计](08-前端共享层设计.md#5-聊天与过程投影)。

后台专业编辑直接使用 CodeMirror 与 Element Plus。代码、文件路径、语法、发布版本与只读状态清晰可见，Markdown 清理不可信 HTML，文件编辑不能用不受约束的 JSON 文本框替代专业字段。

## 7. 业务与安全不变量

页面重构不能弱化鉴权、租户隔离、版本并发控制、幂等、金额精度、会话归属和授权成员边界。账号变化释放旧页面和请求，迟到结果不能出现在新身份页面；网络异常不能导致写请求自动重放。

## 8. 适用边界

本文定义目标设计，不证明实现或验证完成。模块验证遵循[后台 UI 实施与验收](../04-指南与运维/12-后台UI实施与验收.md)，页面业务职责以[后台系统交互规范](../03-规范与术语/05-后台系统交互规范.md)为准。
