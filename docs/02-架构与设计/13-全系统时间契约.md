# 全系统时间契约

## 业务时间

系统业务时间固定为北京时间 `Asia/Shanghai`。数据库连接会话、后端、前端、日志、统计、导出和日历调度使用同一时区；租户与浏览器不能改变业务日界、月界和账期。

自有业务 API 的日期时间输出带 `+08:00` 的 ISO 8601 字符串。绝对时刻输入必须带偏移；明确表示本地日期时间的输入按北京时间解释。纯日期使用 `YYYY-MM-DD`，不附加时区。自然日和自然月查询使用北京时间起点包含、下一周期起点不包含的区间。

页面日期显示格式和日期控件约束见[交互规范 F14](../03-规范与术语/05-后台系统交互规范.md)。可读展示与协议序列化分开，原始诊断 JSON 和业务正文保留原值。

## 绝对时刻与协议边界

`Instant`、Unix 时间戳和 PostgreSQL `timestamptz` 表示绝对时刻，改变显示时区不改变存储时刻。不得对已有时间戳直接加八小时。持续时间、超时、租约与单调时钟保持原来的度量语义。

HTTP Date、JWT、外部签名及供应商协议要求 UTC、GMT 或 epoch 时遵守协议，在进入业务显示或日历计算时转换为北京时间。工作流显式转换时区的工具属于数据处理能力，不改变系统业务时区。

Runtime 核心消费显式时刻，不依赖宿主配置。宿主在业务计算边界使用统一时区和可注入时钟；测试不得依赖执行机器的默认时区。

## 存储与部署

PostgreSQL 服务、日志和应用连接会话设置 `Asia/Shanghai`；JVM 使用相同默认时区。容器提供时区数据，前端日期格式化显式指定北京时间。只设置服务器 `TZ` 不能替代接口序列化或浏览器格式化。

历史无时区字段必须先确认写入方语义，再准备转换：来源是北京时间才使用 `AT TIME ZONE 'Asia/Shanghai'`，来源是 UTC 才使用 `AT TIME ZONE 'UTC'`。无法确认的字段保留待核实状态，不猜测转换。部署操作见[开发与部署指南](../04-指南与运维/01-开发与部署指南.md)。

## 验收

在 UTC、北京时间及其他服务器／浏览器时区下，同一时刻的 API 与页面结果一致。覆盖北京午夜、月末、年末、闰日、日期筛选、数据库往返、调度和日志；验证时间戳、租约和签名没有八小时偏移。计费边界见[用量与账单设计](14-用量与账单设计.md)。
