# 用量与账单设计

本文定义已批准的宿主计费目标；具体可用接口和实施完成度以代码及验证记录为准，不以目标设计代替实现证据。

## 用量与成本

Usage Ledger 保存不可变原子事实，查询默认按请求汇总并允许展开调用明细。`request` 根记录仅承担配额计数与链路关联，属于“不计费”，模型、Token 与金额显示“不适用”。没有调用、执行中、失败和用量缺失必须区分，不能把缺少调用流水解释为零成本。

请求次数、模型调用次数和追加调整分开计算。供应商成本保留原币、高精度金额和冻结汇率，汇总后舍入；缺用量、价格或汇率分别显示缺口。确认记录引用原事实，调整记录表达增减额，同一成本不得因确认和原流水重复累计。

未携带冻结模型版本的非媒体计量，按本次 provider/model 精确读取匹配的模型草稿及其时间价格规则，不读取无关模型目录。保留全部匹配项以检查重复价格是否一致，不因未启用或未发布而新增筛选；没有匹配价格时保留未定价，不补零。携带精确模型版本的计量仍读取原不可变 revision，不以当前目录重算历史费用。

OpenPlatform 的普通消息首次通过身份、内容及 Runtime 准入后，在该 Run 的受理事务中保存一条 `request` 根事实及可靠待发布记录；使用原稳定输入身份去重，绑定准确 Run、Session、rootInput、EndUser、Agent 和已冻结的 integration／业务范围与授权链。根事实 `quantity=1`、单位 `request`，Token 与金额为空、金额状态为 `not_applicable`，不生成模型调用或钱包扣费。同键同内容只返回原受理，同键异内容、拒绝或事务失败不新增请求计数；查询旧 Run 不补记历史。Context-only 历史、动作回复、取消、回调及正式 Workflow 调用不借普通消息入口误计请求根，原生会话入口保持所属记录方式。

LLM 与 Embedding 的 Token 计量只取供应商接口响应的 `usage`，不使用字符数或本地 tokenizer 估算落账。千问百炼和 DeepSeek 的聊天输入、输出分别取 `prompt_tokens`、`completion_tokens`；流式请求开启 `stream_options.include_usage=true`，继续读取内容结束之后 `choices=[]` 的最终用量块。零值为已报告零，缺失为未知并在月度模型费用中显示缺口。缓存和推理 Token 是输入／输出子集，不重复加入总量。调用前上下文预算计算不作为实际消费。

供应商契约参见[千问百炼 Chat Completions](https://docs.bailian.console.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)与[DeepSeek Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion)。

## 缓存输入成本

LLM 模型使用可空的 [`cache_pricing`](../../backend-java/skillforge-core-model/src/main/java/com/skillforge/core/model/ModelCachePricing.java) 选择输入计价方式，价格属于原币分/百万 Token，沿用六位小数单价与十二位小数分金额精度。整体为 null 时使用总输入统一价；`CACHE_READ` 配置缓存命中单价；`CACHE_READ_WRITE` 分别配置命中和写入单价。普通输入、输出单价继续归模型原有字段，非 LLM 不配置该结构。写入价格表示该写入部分的完整单价。缓存单价可以为空，表示未知；明确零价使用字符串 `"0"`，不根据供应商品牌、模型名称或是否开启缓存推导单价。

设供应商归一化后的总输入为 `I`、缓存命中为 `H`、缓存写入为 `W`。本项目的 `I` 包含缓存子集：命中分价的普通输入数量为 `I-H`，命中与写入分价的普通输入数量为 `I-H-W`。各桶乘对应单价并除以百万后相加，输出仍按原输出 Token 计算，推理 Token 不另加一次。缓存桶与总输入的包含关系必须与供应商归一化适配保持一致。

命中分价要求真实报告 `I/H`，读写分价还要求真实报告 `W`；数量缺失、负数或子集超出总输入时，输入费用保持未知，不能补零、夹紧或按普通输入价回退。某桶明确报告数量为零时，该桶费用为零；非零桶缺对应价格时保留输入费用未知。仍可保存已知输出费用，总费用在任一必要部分未知时为空。金额超出持久化容量时保留真实用量和费用缺口，不丢弃调用事实。

缓存配置与价格随模型不可变 revision 冻结，并参与价格快照标识；终态费用只按原版本写入一次。编辑、发布新价格或读取月度费用不重算旧金额；后续真实用量及成本确认仍沿原 Invocation/Attempt 和追加对账契约处理。LLM 使用价格快照及原 Run 冻结模型绑定追溯，媒体专用模型引用列不因本项扩展用途。

供应商语义依据为[DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)与[百炼上下文缓存](https://help.aliyun.com/zh/model-studio/context-cache)。不同型号、地域或缓存合同的价格分别由管理员明确配置；多 TTL、存储时长等未完整报告的收费维度不能套用本项读写桶声称完整成本。峰谷价格属于另外的时间计价合同，本项不自动折算。

## 峰谷时间成本

LLM 模型的 `time_pricing` 为空时不启用时段倍率；非空时，由管理员配置时区、覆盖日期、峰时星期和时段、额外峰日与整日谷时日期、峰谷倍率、适用供应商/服务/接口代际/模型范围及价格与日历来源。供应商名称、年份、节假日、时段、倍率和适用型号属于可管理配置，不进入 Java 算法常量。现有模型输入、输出及缓存单价是倍率作用前的基准价格，不另设销售价格。

原外调账本的 `started_at` 是分类依据，转入规则时区后先检查日期覆盖范围，再识别整日谷时例外；额外峰日或峰时星期只在配置的时间段内为峰时，其余为谷时。日期端点包含当天，时段包含开始、不包含结束；跨午夜时段拆为同日时段，峰谷日期例外不得相交。缺少原开始时间或日期超出规则覆盖范围时分类未知，不用记录费用的当前时间代替。所选时段倍率为空表示未知，字符串零倍率表示明确免费，两者不能互换。

统一输入价、缓存命中分价和缓存读写分价均可组合时段规则；先计算完整输入桶和输出成本，再分别乘所选倍率，按十二位小数分舍入并检查金额容量。必要用量、基准价格或时段倍率未知时，相应费用保持未知，不以零倍率掩盖缺报。来源和倍率均进入规则身份，价格快照同时记录规则身份、时段及原开始时间；外币仍使用原开始时间的汇率依据。内部结果仍是基于配置的估算，不作为供应商实扣确认。

规则及星期、时段、日期例外和适用范围以类型化列和关系表保存；模型草稿和不可变发布版本保存精确规则外键，新增固定结构不写入模型 JSON。模型发布及 Run 冻结后按精确规则版本计价，编辑当前规则、改变日历或发布新模型不重算原用量。供应商预设有独立草稿与不可变发布历史；采用预设将某个已发布版本的内容复制到模型草稿，模型仍须单独保存和发布。预设发布不追随更新既有模型，过期规则不自动推测新年份日历。管理动作沿用模型管理的读取、创建、更新和发布权限；机构运行角色对规则及预设仅有读取权限，迁移和标准数据库准备入口保持同一边界。

初始 DeepSeek 预设仅将[供应商价格说明](https://api-docs.deepseek.com/quick_start/pricing/)与[国务院 2026 年节假日通知转载](https://www.wuhan.gov.cn/zwgk/tzgg/202511/t20251105_2672471.shtml)作为配置来源；后续供应商变化通过编辑、校验和发布配置生效。供应商价格变化通过发布修订生效；未提供的价格与用量保持未知，不按固定倍率推算。

## 媒体供应商用量

图片生成、视频生成、语音识别和语音合成分别使用 `media.image`、`media.video`、`media.transcription`、`media.speech` 原子事实。外层 `tool.call` 记录工具执行，媒体事实记录实际供应商操作，两者使用独立 Invocation/Attempt，不能将工具成功次数直接当作媒体消费。媒体 Invocation 固定为 `media-job:<jobId>`，原创建 Attempt 为 `media-job:<jobId>:create:1`；供应商和模型字段保存实际供应商及模型标识，服务配置或工具名称不替代模型身份。供应商请求、任务回执保存在原 Job 和外调账本，不另造费用身份。

供应商创建请求发送前，宿主通过发送前观察回调，在同一事务中登记原媒体 Invocation/Attempt、未知开始用量和可靠待发布记录；登记失败不发送 HTTP。事务提交后再次检查原期限与取消，再发送供应商请求，不跨网络等待持有事务。开始事实冻结原执行机构、入口与责任主体、Run/Session/根输入、Agent 发布修订、有序授权链及定价模型 ID/revision；后续观察继承这些来源和原发生时间，不读取查询 Run 或当前授权链重建历史。

媒体计量保留供应商实际报告的六维值：输入 Token、输出 Token、图片数、视频数、字符数、秒数。只接受合法非负值；`null` 表示未知，零表示供应商明确报告零，秒数保留原十进制精度，不四舍五入成整数。部分观察合并时，缺失字段不能擦除既有报告；不按请求图片数、原文字数、文件数量、本地音频时长或模型输出推算消费，不反推缺失 Token。公开媒体数量、字符数、秒数与定价模型 ID 使用十进制字符串传输，模型修订保持整数；定价模型引用仅冻结原依据，不产生价格或支付事实。

开始事实记录一次待确认供应商调用，原始计量和金额为空，`usage_source=UNKNOWN`、`amount_status=unresolved`。后续观察只追加不可变事实，观察序号来自原 Job 的内部并发版本，不冒充供应商修订；同一观察重读不重复入账，冲突内容拒绝覆盖。有效用量按原 Attempt 归并，累计报告与终态快照不重复计算调用或消费。只有供应商结果明确终结才追加 `measured` 并按原模型不可变版本计算内部成本；不能用一次调用或通用数量单价替代媒体计价单位。

媒体成本使用独立的 `media_pricing`，整体为空表示缺价；配置时明确选择输出图片、输出视频、计费视频秒、输入音频秒、输出音频秒、计费字符或输入输出 Token 双价。非 Token 单价为原币分/所选单位，Token 单价为原币分/百万 Token，价格通过十进制字符串传输并沿用六位单价精度；零价必须显式配置。Token 成本要求输入、输出价格及两侧真实计量完整，缺任一项不能补零。媒体与非媒体价格结构不能混用，媒体始终按精确模型修订取价，不进入非媒体按供应商/型号匹配的兜底目录。

视频秒价还须明确适用分辨率，与原 Job 冻结的请求分辨率精确匹配；缺少条件或档位不符时继续原媒体能力并保留缺价。只使用供应商报告的计费秒数，不累加本地文件时长。百炼 Wan3 的该量包含输入参考视频与输出视频，声音开关同价，依据[官方 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)与[北京价格表](https://help.aliyun.com/zh/model-studio/wan3-0-video)；不能照搬其他渠道的音轨加价。需要输入/输出图像双计费等未完整报告维度的模型，不能套用单一输出图片价。

实际计量乘原单位价后，内部金额按 `HALF_UP` 保留十二位小数分；超出金额列容量时保存实际用量并保持 `unpriced`，不让价格溢出丢失消费事实。外币使用原开始时间的汇率快照，缺汇率保持 `unresolved`；`priced` 仍只表示按所配依据计算的内部成本。已有终态不因编辑或发布新价格而重算，历史无开始事实的任务不追补成本。

超时、连接中断及其他无法证明未发送的结果保持 `UNKNOWN`，保留原调用与用量缺口，不自动重建供应商任务。登记后再次取消或到期，且明确没有发送供应商创建请求时，保留原开始事实，追加原 Attempt 的 `quantity=0`、`amount_status=not_applicable` 终态；其来源仍为 `UNKNOWN`，六维计量及金额均为空，不能补造供应商报告零，也不能覆盖已有供应商计量。月度模型费用不将该明确未发送事实计入模型调用和缺价数量。

查询只读取原 Job 或查询其已有供应商任务，并将新观察追加到原媒体身份；查询不创建新的生成任务、不取得新的创建发送权，也不将费用归因到查询者的 Run。查询请求自身未发送不改变原任务结果。历史 Job 缺少原开始用量时不借当前查询来源补账；结果未知的历史任务不因读取或恢复而自动重放。

已发生的媒体用量及其内部成本进入统一账本、有效汇总、可靠导出和只读月度模型费用；供应商未报告的计量与金额继续显示缺口。模型费用只消费原成本事实，不再生成独立销售应收或钱包扣费；Runtime 执行预算与模型费用分别承担数量准入和实际费用查询职责。

## 计费数值契约

模型配置、用量成本和月度费用使用各自明确的计量单位。模型价格的 JSON 字符串不会改变价格单位；`null` 表示未配置，零价必须显式保存。模型单价在 Java 中使用 `BigDecimal`，最大值为 `9223372036854775807` 小数分，最多6位小数，发布时验证并规范尾零，不能转为 `double` 或整数后计价。

| 边界 | 单位与精度 | 消费规则 |
| :--- | :--- | :--- |
| 模型 `inputPricePerMillionCents` / `outputPricePerMillionCents` | 原币分/百万 Token；最多6位小数分 | 按受理时冻结的模型 revision 读取；LLM、Embedding 与按输入 Token 定价的 Rerank 使用已报告 Token 乘单价，再除以 `1000000` |
| 模型 `pricePerQuantityCents` | 原币分/计量单位；最多6位小数分 | 明确按数量定价的 Rerank 按文档数、其他数量计量按实际单位相乘 |
| Usage `input_amount` / `output_amount` / `total_amount` | 原币分，`numeric(24,12)` | 保存写时精确金额；十二位整数及十二位小数的容量独立于单价最大值，超出容量不能当零或截断 |
| Usage `*_amount_cents` | 原币整数分，`bigint` | 单条金额的 `HALF_UP` 整数投影；不得替代精确列做累计结算 |
| 月度 `known_amount` / `total_amount` | CNY 元的精确十进制字符串 | 从原账本精确分金额换算为元并汇总；存在缺口时 `total_amount=null`，`known_amount` 仅表达已知部分 |

例如供应商标价 `0.125 CNY/百万 Token` 对应模型配置 `"12.5"` 分/百万 Token；1 Token 的精确金额为 `0.000012500000` 分，`1000001` Token 为 `12.500012500000` 分。对应单条整数分投影可以是 `0` 或 `13`，精确金额仍保存上述小数，不能用投影反算单价或当作供应商实际扣款。6位单价小数再除以百万基数，最多产生12位小数分，可由精确金额列无损保存。

Rerank 供应商成本的计量单位由冻结价格字段唯一确定：仅 `inputPricePerMillionCents` 非空时按输入 Token 计费，仅 `pricePerQuantityCents` 非空时按文档数量计费；两者同时配置（包括一个显式零价）属于冲突，模型写入拒绝，计价读取也不选取任意一项。两者均未配置保持缺价。单位不随本次响应是否带 `usage` 改变：Token 合同缺输入 Token 继续缺价，不能回退到文档数；数量合同也不因出现 Token 改用另一价格。月度费用沿用原成本事实，不另行选择或发布售价。

百炼 [`qwen3.7-text-rerank` API](https://help.aliyun.com/zh/model-studio/text-rerank-api) 返回 `usage.prompt_tokens` 与 `usage.total_tokens`，[模型价格](https://help.aliyun.com/zh/model-studio/qwen3-7-text-rerank)为 `0.5 CNY/百万输入 Token`，对应配置 `"50"` 分/百万输入 Token。排名与用量使用类型化响应一并交给终态计量；79个已报告输入 Token 的内部成本为 `0.003950000000` 分，供应商账单确认仍独立。只接受非负 JSON 整数且不超过 `Long.MAX_VALUE` 的 Token；字段缺失、非法或超限保持未知。仅有 `total_tokens` 时保留总量，不反推输入，不将缺失输出补零；明确矛盾的 `total_tokens < prompt_tokens` 不能作为有效计量，保留排名并将用量置为未知。通用兼容端点报告总量大于输入时保留各字段，不以百炼示例相等替代其他供应商的契约。历史缺失的 Token 和费用不能因解析修复而回填，后续只接受具有原事件身份和真实依据的追加对账事实。

Runtime 执行预算预留七维调用数及 Token 数，不含货币金额。`reserve → markSent → saveResult → settle` 释放和结算该执行预算；其中 `settle` 不代表供应商账单确认或支付。配置价格不参与这些 Token 预留的数量计算，调用前的上界不能作为消费落账。

## 成本状态与对账依据

`usage_report` 只保存某个 Invocation/Attempt 的供应商累计计量观察，金额为空且状态固定为 `unresolved`；报告成功、Token 完整或配置了价格均不把它自动改成供应商账单。`measured` 在调用终态保存数量和冻结价格计算的内部金额：具备价格、所需计量及必要汇率时为 `priced`，缺计价条件为 `unpriced`，外币金额缺汇率时为 `unresolved`。`priced` 说明该条事实可按其依据计价，不表示已经取得供应商扣款账单或付款成功。

原始事件不可修改。成本确认通过具有原事件身份、金额、币种、价格/账单依据以及必要汇率的 `reconciliation` 追加事实推进；有效成本投影采用最新确认替代原金额，`adjustment` 仅追加增减额。未收到供应商账单、结果未知或汇率缺失时继续保留相应缺口，不能根据模型配置补造确认。仅收到新的 Token 报告不会重写旧金额或签发新的外部调用权。LLM/Embedding 原始计量不是 `PROVIDER_REPORTED` 时，有效成本投影保持 `unresolved`；已确认成本与未知、缺价及未换算币种分别汇总。

## 月度模型费用

模型费用只使用调用时冻结的模型价格和原始用量账本；模型维护是价格配置的唯一入口。读取月份、修改当前模型价格、重新发布或查询原任务均不能重算已有终态金额。月度查询不创建账单副本、草稿、封账状态或销售调整记录。

月份按[北京时间](13-全系统时间契约.md)自然月划分，范围为月初含、次月月初不含，以原调用 `occurred_at` 归属。查询涵盖聊天、Embedding、Rerank 和四类媒体模型事实，不将外层工具或请求根再次计入模型费用。尚未产生终态的报告按原 Attempt 归并为一个待核实调用；明确未发送的媒体事实不计入调用次数和缺口。

月度响应提供模型调用次数、输入/输出 Token、已计算费用、费用待核实数量和分页明细。金额为精确十进制元字符串，汇总币种为 CNY；有任一成本缺口时总费用保持空值，已计算费用只显示已知部分，不能显示为完整总额。明细保留原币金额、换算金额、状态、原事件和 Invocation/Attempt、价格快照及媒体定价模型修订，便于核对费用依据；不把内部 `priced` 宣称为供应商扣款或支付完成。

没有该月调用、查询失败、用量未知、缺少价格和缺少汇率分别呈现。迟到的原用量或有依据的成本确认通过既有追加事实反映到所属月份的后续读取，不生成补充销售单，不覆盖原始事实。

独立销售定价和商业出账已撤销。[V339](../../backend-java/skillforge-migration/src/main/resources/db/migration/V339__remove_sales_billing.sql)删除旧销售价格、销售审计、账单归账和账单表及其保护函数，不保留业务数据归档；具体执行结果以目标环境迁移回执为准。通用套餐、额度、机构状态扫描和原始用量保留规则不属于该删除范围。

## 多机构可靠用量交付

平台直管多机构目标不再使用 Application 用量维度、应用关联或应用 stream/export 分区。UsageEvent 与可靠待发布记录同事务写入，提交后由当前部署的平台发布流分配单调游标；平台仅查询获准机构集合，机构读取按 Tenant 和接入范围授权。原生渠道/系统后台没有外部 integration 时按真实入口和责任身份授权及计量，不能因缺应用来源而漏导出。同一源事件在平台/机构视图保持相同稳定身份，不能生成重复费用事实，平台或总部定义所有权不改变实际执行机构的成本归属。

总部汇总读取使用独立管理动作和明确下级目标集合；组织关系或 Agent 授权不直接授予汇总、明细或导出权限。普通机构执行接口仍固定 Tenant/integration，明细/增量导出须另有授权；平台/总部/下级视图保持同一事件身份，不复制成本。来源保存源所有者、定义/版本、授权依据与实际实例，组织迁移不把过去用量改记到新总部，也不隐含代付或配额池。

总部通过 `/tenant/usage/summary`、`/tenant/usage/details`、`/tenant/usage/events` 分别消费独立动作 `tenant.sub_institutions.usage_summary.read`、`usage_details.read`、`usage_events.read`。平台用现有机构管理许可显式授予一个当前直属目标上的单项动作；人员当前 FoundationAccess 或机构服务凭据还须拥有对应动作。读窗口保留总部 Tenant，数据库仅允许用量事实、发布引用与冻结授权链的受限读取；许可撤销或关系换代后不能借旧授权快照读取。用量身份始终属于实际执行机构，源定义所有者和当前总部均不成为默认付款方。

Agent 用量在入账时从原 Run 的实际执行者绑定投影源所有者、共享定义稳定 ID、定义版本、实际 Agent 发布记录及修订、部署与末端授权修订；有序授权链与原用量同事务保存，确认和调整继承原链，不读取当前定义、授权或机构树重建历史。自有 Agent 不冒充共享定义，非 Agent 来源不补造 Agent 身份。公开 ID 和精确金额使用十进制字符串；修订及有序位置保持整数。

平台 SystemAgent 从 typed Run、原系统请求者及宿主已冻结的 capability source 投影责任身份、平台所有者和原 prompt 发布引用；它没有机构 Agent 发布记录或共享定义授权链，相应字段为空。计量仍由原 Invocation/Attempt 写入同一 Usage 账本，不另建后台用量权威源；缺失或冲突的持久来源拒绝入账。

`quantity` 与 `measurement_unit` 表达调用方实际计量：模型调用次数和普通 MCP/知识/外部动作使用 `call`，请求根使用 `request`，Rerank 文档数量使用 `document`；模型输入/输出 Token 另列。已知调用次数不因 Token 未报告而变成未知或零；音视频供应商没有报告的秒数、Token 与费用保持缺口。MCP 在业务请求真正派发前登记原 Invocation/Attempt 的未知占位，事务返回后再次检查原期限、取消和当前授权，握手不冒充工具业务调用；已发送失败或结果未知保留实际调用次数与未知费用，不自动重放。`input_required` 和其后 continuation 分别按实际发送的原 Attempt 记账，Runtime 执行状态仍由原 Store 管理。

游标表达扫描位置，并绑定主体、机构/integration、筛选及授权版本；过滤无匹配项时仍按实际扫描位置推进。权限或消费范围变化需显式重建读取范围，不能复用旧筛选水位跳过新增机构历史。时间和源账本主键不能作为发布水位；确认/调整追加关联事件，未知保留未知。

## 钱包结算交付契约（目标）

独立消费适配器与模拟钱包不属于当前模型费用账单。当前模型账单只读原成本，不维护销售应收、结算指令、扣款或退款；外部消费的 UNKNOWN 和幂等回执仍按所属生命周期保留，不能借销售表退役清空。

## 权限与验收

平台按明确机构查询模型费用，机构端固定当前机构，两端均要求 `foundation.billing.read`；模型价格写入继续使用模型管理的授权和不可变发布版本。明细、用量导出和跨机构汇总分别按当前动作及范围授权，JWT 中角色不能代替 FoundationAccess 的当前账号、权限和授权版本。撤权后清除旧显示并拒绝后续读取，旧游标不能扩大或保留已撤销范围；数据库 RLS 和事务级机构身份仍有效。

集中验证原账本唯一计价、精确模型版本、媒体单位与分辨率、原时间汇率、缺口和显式零、北京月界、累计报告去重、明确未发送和 UNKNOWN、分页及跨机构访问。查询只能读取，不能改写原用量或价格；暂停、取消与接管不删除已发生调用及费用。数值、SQL、事务与租户隔离使用相应真实依赖验证，页面显示和只读请求使用前端验收；测试不代表供应商账单或实际支付已确认。

## 接口与部署边界

机构端使用 `GET /api/v1/billing/monthly` 查询当前机构，平台端使用 `GET /api/v1/platform/billing/monthly` 并明确 `tenant_id`。查询参数为 `month`、`page`、`page_size`，月份格式 `YYYY-MM`；无月份时使用北京时间当前月，分页默认20条、上限200条。接口及投影以[ModelBillingService](../../backend-java/skillforge-core-billing/src/main/java/com/skillforge/core/billing/application/ModelBillingService.java)、[月度响应类型](../../backend-java/skillforge-core-billing/src/main/java/com/skillforge/core/billing/dto/billing/ModelBillingContracts.java)和[控件合同](../03-规范与术语/后台控件/P05-模型费用账单.md)为直接入口。

部署包含销售表退役迁移和同版本前后端，旧销售接口和页面不继续提供写入口。V339 使用 `RESTRICT`，发现额外依赖即停止，不级联删除模型用量或其他业务对象。缺失历史计量与金额继续显示缺口；本设计不授权另行删除原始用量，也不以只读月度查询触发新的生成、结算或支付动作。
