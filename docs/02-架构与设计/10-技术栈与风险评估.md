# 技术栈与风险评估

> 技术版本的决策记录见 [ADR-005](../05-架构决策/005-技术栈版本锁定.md)。
> Agent Runtime 架构风险与对策见 [Harness 02 §8](../../harness-design/02-微内核插件架构实现思路.md#8-风险与对策)。

## 1. 当前技术栈

| 层 | 选择 |
| :--- | :--- |
| 后端 | Java 21、Spring Boot 3、Spring Cloud Alibaba、MyBatis-Plus、Flyway |
| 数据 | PostgreSQL 16、pgvector、Redis 7 |
| 前端 | Vue 3、TypeScript、Vite |
| LLM | OpenAI-compatible 端点与应用内 Provider |
| 部署 | Compose、Helm、Kubernetes 可选 |
| 可观测 | 结构化日志、Prometheus、OpenTelemetry/OTLP 可选 |

具体版本只在 ADR-005 维护，本文不复制 patch 版本。

## 2. 自研边界

### 2.1 自研

Runtime 自研职责与宿主适配边界见 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md#14-agent-runtime-sdk-交付边界)，不以现有 Spring 服务集合代替 SDK 分层。

### 2.2 复用

- Spring 生命周期、依赖注入与配置；
- PostgreSQL 事务、约束、RLS 与持久队列模式；
- Redis 缓存、租约或短期传输缓冲；
- OpenTelemetry、Prometheus 和标准日志基础设施；
- 既有 Workflow 节点、边和条件求值逻辑，但仅在符合新边界时复用。

## 3. 主要风险

Runtime 架构风险与对策直接引用 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md#8-风险与对策)；宿主引入基础设施时评估故障影响、数据保留和运维恢复，不重复维护 Session、插件或恢复规则。

## 4. 阶段依赖

里程碑和 SDK 交付依赖见 [Harness 06](../../harness-design/06-MVP-0技术底座实施方案.md#3-实施总路径)，P1–P3 的能力边界见 [Harness 04](../../harness-design/04-后续阶段需求扩展-P1-P3.md)。当前基础设施或类的存在不能证明相应目标已经交付。

## 5. 评审门禁

- 新依赖必须解决已确认的里程碑需求。
- 新基础设施必须有故障、回滚、数据保留和运维方案。
- 任何“临时兼容”必须视为架构缺陷，除非用户明确改变预发布策略。
- 非 Runtime 选型决策归 ADR；Runtime 主文档与 Note 的同步、触发和复用按 [Note 治理规范](../../.agents/skills/nw-docs/references/notes-governance.md)。评审和验证范围按[评审与验证规范](../../.agents/skills/nw-verification/references/candidate-driven-delivery.md)。
