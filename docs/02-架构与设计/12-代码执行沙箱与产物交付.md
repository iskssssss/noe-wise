# 代码执行沙箱与产物交付

本文定义代码执行、会话工作区与正式成果的宿主架构，功能默认关闭。Runtime 装配边界见 [Harness 02](../../harness-design/02-微内核插件架构实现思路.md#通用代码执行装配)，调用与恢复见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#通用代码执行-tool)。实际实现、部署启用和验收需针对当前候选核对，不以设计文档或代码存在推定已通过。

## 1. 范围与职责

用户的文本与数据文件附件、用于代码执行的输入文件、以及模型可见图片是不同用途。沙箱输入清单负责执行任务的只读文件绑定，不能凭文件 MIME 自动授予模型图片消费；图片上传、有序图文内容和受管媒体引用的已批准目标归[多模态内容与媒体引用](../../harness-design/03-多模态内容与媒体引用.md)。同一真实文件可按明确用途形成执行输入或媒体引用，身份、来源与授权由宿主核验，不将图片二进制伪装成文本附件注入模型。

个人远程浏览器经独立 Browser service 执行，装配与回执见[BrowserSkill 接入](18-BrowserSkill远程浏览器接入.md)，不复用代码沙箱运行 `bsk`。浏览器截图进入通用媒体材料；远程浏览器的文件上传和下载不支持，不因沙箱已经具备文件输入与产物下载就对外宣称支持。

`code_execute` 是普通对话和 Skill 共用的 PLATFORM Tool。用户直接要求生成文档、生成网站或执行计算时，Agent 可在已挂载授权范围内调用，不要求先有 Skill；Skill 只提供指令、模板、资源或脚本引用，不拥有另一套执行器。首批交付文档下载、静态网站预览和网站目录 ZIP 下载，不包含后端网站托管、长期进程或公开发布。

Skill 拥有专业方法、质量标准、模板和自带脚本的输入约定；Agent 根据本次任务、已有文件事实和已授权能力选择工具。平台通用的文件传递、执行结果、版本引用与成果提交协议由 [PlatformToolCatalog](../../backend-java/skillforge-core-capability/src/main/java/com/skillforge/core/capability/connector/PlatformToolCatalog.java) 和[统一成果说明](../../backend-java/skillforge-prompts/src/main/resources/com/skillforge/prompts/output/preparation.md)维护，不复制到每份专业 Skill，不把一种可选查询方式设为所有任务的固定前置。

| 组件 | 职责 | 不承担的职责 |
| :-- | :-- | :-- |
| 机构宿主的 Platform Tool Provider/Handler | 接收可信调用上下文、解析脚本资源、发起任务、转换受控结果 | 不在机构服务进程内执行用户代码，不向模型暴露服务凭证 |
| `skillforge-execution-contract` | 宿主、Workflow 与沙箱共用的执行控制、文件清单、公开业务结果 DTO 及容量常量；不依赖宿主业务 | 不拥有任务状态、权限、预算或计费 |
| 独立 `skillforge-sandbox-service` | 任务登记、Docker 容器执行、出网约束、输出采集、取消与清理 | 不接受来自模型的租户归属，不作为任意 Docker API 代理 |
| 宿主产物服务 | 元数据、不可变文件持久化、鉴权下载、保留期与清理 | 不把整个文件装入 Runtime 事件、数据库字段或模型上下文 |
| 隔离预览服务 | 在独立源提供已发布静态目录 | 不运行生成的服务端代码，不共享平台登录态 |
| 聊天前端 | 实时及历史产物卡片、下载链接、隔离 iframe | 不把生成的 HTML 插入平台 DOM，不用整文件 Blob 缓冲下载 |

## 2. 执行环境与部署

独立服务优先使用 Docker Runner，支持 Python 3.12 与 Node.js 24；运行时镜像固定可追溯版本和摘要。生产运行在专用执行宿主机，开发环境通过 Compose 装配。Docker 控制权限只留在执行服务，不暴露给机构服务、用户容器或生成的代码；容器只挂载本次任务需要的只读输入、独立可写任务目录，以及显式授权的会话项目目录，不挂载宿主业务目录、Docker socket 或平台密钥。

容器使用非 root 用户、只读根文件系统、最小 capabilities、禁止提权和适用的 seccomp 配置，独立约束 CPU、内存、进程数、标准输出及运行时间。生成文件放在任务独立的磁盘工作目录，不使用大小受限的 tmpfs 承载产物。Docker 隔离不等于虚拟机级强隔离，专用执行宿主与受限网络是部署前提。

能力默认关闭；服务、镜像、资源约束、网络隔离、存储和预览源配置就绪后，管理员才可启用并显式挂载。不得自动给现有 Agent 增加执行权限；配置缺失时拒绝执行，不回退到本机进程或无隔离容器。运行手册和实际可用命令随实现交付，目标架构不冒充现有部署步骤。

## 3. 网络与动态依赖

容器允许经强制出站代理访问公网 HTTP/HTTPS；网络层拒绝绕开代理的直连和任意协议隧道。代理对 DNS 解析结果、IPv4/IPv6 地址和重定向重新判定，阻止 loopback、私网、链路本地、宿主机、平台内部服务及云元数据地址，避免 DNS 重绑定绕过。代码与依赖安装使用同一出网边界，不能仅靠设置代理环境变量宣称隔离有效。

动态依赖采用结构化的包名和精确版本声明，由 Runner 通过参数数组调用包管理器；模型不能传递安装命令、额外参数、任意仓库或 VCS/本地路径依赖。Python 仅安装 wheel，拒绝源码构建；Node.js 禁止依赖安装脚本。仓库由管理员配置，解析后的直接及传递依赖版本和摘要留存供追溯，缓存不得执行另一租户写入的可变内容。禁用安装脚本不意味着依赖代码可信，最终导入和执行仍在相同沙箱中。

Skill 模式的依赖声明来自当前 input 冻结的精确 SkillVersion。宿主在验证包内容和 SHA 后读取 `manifest.dependencies` 并向执行请求提供完整精确清单，模型可以省略 `dependencies`；显式提供时只接受冻结清单中同名同版本子集，并由宿主补齐，拒绝额外依赖和版本覆盖。没有 manifest 依赖声明的自定义 Skill 仍可按相同精确版本与 Runner 规则显式提供依赖。自动提供清单不授予工具或 Skill 权限，也不允许切换到当前默认版本或 latest；inline 继续使用显式依赖。

不注入平台、连接器或用户凭证，服务间认证材料不能进入执行容器或返回结果。该保证不代表代码没有公网副作用，也不能防止用户自行把秘密字面量写入代码；日志和受控投影继续执行既有脱敏规则。

## 4. 任务阶段与中断

同步短任务分为准入与准备、安装与执行、产物收集与持久化、结果发布。依赖安装和代码执行共享冻结策略的执行预算，默认 900 秒，可配置至 3,600 秒，并服从根/Run 剩余时长；镜像准备不能通过临时拉取形成无限等待，其他阶段均有独立的有限截止时间。

产物传输超时独立配置，默认 900 秒、可配置至 3,600 秒，不挤占代码执行预算；同时必须落在可信 Runtime 调用总 deadline 和有效 lease 内。接入时同步调整 Tool/Provider 总超时与租约续持关系，总调用 deadline 必须覆盖允许的阶段，不能用延长租约替代持久恢复。无论阶段是否完成，总 deadline 到达或失去有效写权后，都不得继续提交 Runtime 结果。

服务持久记录任务身份、容器标识、阶段和已知终态。取消、超时及进程异常必须终止容器及子进程，并在确认静默后清理；只中止 Docker CLI 或 HTTP 请求不视为终止执行。服务重启按任务标识检查并清理孤儿容器，不能自动重跑代码。状态查询、已提交结果读取及不重新执行代码的文件传输恢复可以去重，不能据此把 `code_execute` 宣称为幂等操作。

已知执行结果与产物交付状态分别记录：代码退出码已知但持久化失败时，返回执行已知、交付失败，不抹掉已有事实，也不重跑。连接丢失且没有可靠终态时按 Runtime 未知结果契约处理；已经杀死容器不证明先前公网副作用未发生。

沙箱部署配置只提供认证、存储、Docker 控制、网络、镜像和包仓库等环境事实；运行超时、资源容量、输出限制和任务临时工作目录保留期使用任务冻结的 `executionPolicy`，不再提供同名但未生效的服务级覆盖项。服务启动检查和容器清理继续使用部署侧 `dockerControlTimeout`；会话项目目录的备份与本地归档由独立工作区政策管理，见 §4.3。

任务临时工作目录清理由持久任务记录派生候选集合，只扫描尚未标记目录删除的任务，并继续检查静止资格、冻结策略和保留期。成功删除后持久标记并移出候选；失败保留候选以重试，重启从记录重建集合。永久任务身份、请求摘要和终态继续保留，用于拒绝重复执行；该清理器不能删除独立会话项目卷。

### 4.1 执行传输与业务结果

普通代码、Skill 脚本、程序工具与 Workflow 共用 `skillforge-execution-contract` 的类型化清单及 `POST /internal/executions/artifact-inputs` 流式 ZIP。首项 `request.json` 最多 16 MiB，只冻结控制字段和 `{path,size,sha256}` 元数据；普通后续成员传输 `data/`、`scripts/` 或 `artifacts/` 文件；冻结 Skill 包还可传输 `examples/`、`references/`、`assets/` 等相对资源路径，但每项必须与已核验的冻结 inputs 在路径、大小、摘要上完整匹配。工作区准备按清单逐流核验大小、摘要、安全路径与截止时间，执行源码严格校验 UTF-8；STANDARD Skill 的二进制模板保持原始字节，Workflow 脚本仍全部校验 UTF-8；缺项、多项、重复或摘要变化拒绝调度。删除 `dataFiles`、文件 `content` 和编码正文的执行 JSON 入口；inline 源代码仍属于执行控制，Skill/Workflow 的资源正文只在 ZIP 中传输。

内部执行控制 JSON 固定使用 camelCase，由所属 DTO 显式约束；`taskId`、`programTools`、`executionPolicy` 等字段不受宿主公开 API 的 JSON 命名策略影响。执行请求与响应、程序工具 RPC、取消和日志控制契约按同一命名规则部署，不能通过双格式读取掩盖协议不一致。具体准入回执由 [ExecutionAdmissionRejection](../../backend-java/skillforge-execution-contract/src/main/java/com/skillforge/execution/ExecutionAdmissionRejection.java) 定义：ZIP 首项、读取或元数据在进入执行器前被拒绝，以及相同 task 锁内确认尚无登记时的策略拒绝或截止时间失效，才返回包含 `submission=NOT_SUBMITTED` 的类型化准入回执。已有任务仍以原请求摘要为权威，非法重投返回冲突；任务登记后不能补称未提交。普通 HTTP 400/500、断线与超时不能证明未执行；宿主依据原任务事实读取和恢复，保留失败或结果未知，不整体重跑。

控制响应最多 16 MiB，仅包含真实任务状态、文件与日志引用及明确业务结果。完整捕获日志留在沙箱内部持久记录，通过受认证 `GET /internal/executions/logs` 按页读取，不自动进入聊天过程、成员摘要或模型公开正文。Workflow 的显式 JSON 业务结果最多 8 MiB，仍按节点输出 Schema 核验。

普通代码和程序可使用固定 `/workspace/output/result.json` 返回公开类型化业务结果，无需另传结果选择参数；`public_result_file` 不再属于工具或执行请求契约。STANDARD 执行成功后，公开业务结果采纳仅读取这个保留文件，最多 8 MiB；文件不存在表示没有公开业务块，纯断言检查仍可成功，不扫描其他文件或将 stdout 自动转成公开结果。普通 `code_execute` 在已知成功且无结果协议错误时，另将经宿主保护检查的 stdout 最多 32,768 字符作为模型内部观察返回，无需为此补写结果文件；withheld、unavailable 或 truncated 表示相应内容不可用或不完整，不能据此推定全量值。宿主不把该观察自动展示为公开工具结果或正式文件，助手可依据实际观察解释业务值；不扩大 `run_code`/program 与 `render_artifact` 的既有输出契约。结构固定为 `{"results":[...]}`，仅允许 `{kind:"text",format:"plain"|"markdown",text}` 或 `{kind:"table",columns:[{key,label}],rows:[标量列表]}`；JSON业务值序列化放入text时format仍为plain，不能用format=json。拒绝额外字段、非标量单元格、重复 JSON 字段及脚本自报状态、owner、Run、成果身份或引用。保留文件存在但非法、超限或为链接时明确失败，不能按缺失忽略；`output_files` 不得选择该文件或同名目录，它不成为下载成果。Shell 与 Workflow 使用各自返回协议，不采纳此通道。沙箱将合法业务结果与执行成功事实绑定后冻结；宿主按相同公开政策检查业务结果后才允许候选成果进入 ready。工具标题来自能力定义，状态来自执行事实，成果引用由宿主核验文件后构造。

### 4.2 程序工具 RPC

`run_code` 复用相同执行器、依赖安装、产物输入和交付路径，仅接受 inline Node 程序。机构宿主在请求中设置 `programTools=true`，沙箱为执行容器生成 `tools.call` SDK 和独立消息目录；普通执行与依赖安装容器不挂载该目录。子调用的 Runtime 授权与账本契约见 [Harness PTC](../../harness-design/03-上下文视图与执行优化.md#22-程序化工具调用)。

机构宿主使用内部受认证端点 `GET /internal/executions/tool-calls?taskId=…` 拉取待处理请求，再以 `POST /internal/executions/tool-results` 提交 `{taskId:…,ordinal:…,result:…}`。接口与取消、终态使用同一任务锁；终态查询返回空请求列表，宿主继续读取最终状态和产物，不能将状态查询与消息轮询之间的正常完成误判为 RPC 失败。终态写入仍拒绝；活动任务的相同响应重放返回 204，变更响应拒绝。消息为连续序号的普通文件，检查符号链接、文件数量和 64 KiB 大小上限；SDK 串行调用，最多 256 次，外层执行与每次子调用分别预留和计量，不隐式重试。

RPC 失败或未知时宿主尽力取消原任务，并保持结果未知。重启只恢复已知执行事实与清理，不重新运行程序，也不将程序完成状态覆盖已成功子工具的事实。模型输出、依赖与公网访问仍受同一沙箱边界约束。

### 4.3 会话持久工作区

每个实际 Runtime Session 延迟创建一个独立工作区，包括 `delegation:*` 子 Session；工作区归属绑定可信 tenant、Session、endUser，并保存产品会话关联用于状态展示和整体清理。主、子 Session 不共享可写目录，产品展示关系不授予跨 Session 文件访问。用户数量不决定容器数量，容器按调用创建并在结束后回收，项目文件跨调用保留。

机构宿主保存归属、授权和持久清理意图；[V268](../../backend-java/skillforge-migration/src/main/resources/db/migration/V268__session_workspaces.sql) 的 `nw_chat_session_workspaces` 保存 Runtime Session 与产品会话关联及清理墓碑，`nw_chat_session_workspace_imports` 保存显式导入的来源证据。两表沿用租户 RLS；产品会话删除不级联删除工作区归属，否则会丢失尚未完成的物理清理意图。Sandbox 保存项目文件、操作事实、修订与快照状态，其状态查询是备份与本地可用性的事实源，宿主不另建同义执行状态机。

独立项目持久卷默认名 `skillforge-sandbox-projects`，服务端根目录 `/var/lib/skillforge-projects`，执行时仅当前项目子目录挂载为 `/workspace/project`；`/workspace/work`、`/workspace/output` 与 `/input` 继续属于单次任务。依赖安装容器不挂载项目目录，代码执行仅在 `use_workspace=true` 且重新核验当前 Session 的 `workspace_files` 授权时挂载；默认 `false`。输入附件与受权产物只有显式导入后才成为项目文件，导入时复验当前授权、有效期、大小和摘要，并保留来源。

| 工具 | 宿主能力 |
| :-- | :-- |
| `workspace_files` | 列目录、分段读取 UTF-8 文本、创建、覆盖、精确替换、建目录、移动、删除及导入已授权文件；修改校验基准摘要或修订，不匹配时拒绝覆盖 |
| `workspace_exec` | 在相对项目目录执行完整 Bash，支持管道、重定向及脚本，使用受控 Shell profile 和镜像，不接受宿主路径或 Docker 参数 |
| `workspace_checkpoint` | 查询工作区状态与快照、请求即时备份，以及匹配当前修订后显式恢复指定快照 |

三个工具沿用 PLATFORM 显式挂载和可信调用身份。基础镜像提供 Bash、coreutils、grep、findutils、ripgrep 与 Git；Shell、Python 和 Node 对授权项目目录使用同一协调边界。UTF-8 文件读取按字符分页，单页最多 32,768 字符；Shell 结果向模型投影 stdout、stderr 各最多 32,768 字符并保留截断事实，完整捕获日志继续保存在内部记录。公开聊天过程只消费既有受控呈现，不直接公开文件或日志正文。此能力不承诺 Shell 变量、进程、临时软件和当前目录跨调用保留。

`workspace_exec` 的可选 `skill_handle` 将当前 Run 已激活的精确冻结包接入现有执行输入清单与流式 ZIP，逐文件核验路径、大小和摘要，保留包内相对目录并只读挂载为 `/input`。命令通过本次容器的 `SKILL_DIR=/input` 使用脚本、模板和资源，仍须具备 `workspace_exec` 授权；包内路径不转成宿主路径或可写项目文件。宿主保留执行入口 `main.sh`，包内同名顶层文件发生冲突时拒绝，不覆盖资源或入口。该路径仅在本次调用有效，只有沙箱确认已执行且退出结果已知的回执才返回 `skill_resource_base=/input`，准入拒绝和结果未知不返回。此路径不安装包声明依赖，Shell 使用现有镜像实际支持的运行时；Python、Node 脚本继续可经 `code_execute(mode=skill)` 使用其结构化依赖准入。

同一工作区的文件操作、命令执行、快照冻结和恢复统一串行，不同工作区可以在已有容量内并行；等待工作区不占用执行容量，仍服从原调用取消和 deadline。可能修改文件的操作结束后推进项目修订，失败、超时与取消保留可能存在的部分修改；任意命令的结果未知不自动重跑。服务重启或释放占用前，先确认原容器及子进程静止；不能仅凭调用超时启用第二个写入者。文件 API 与快照拒绝路径逃逸、符号链接和特殊文件，Bash 仍受现有容器挂载、资源、网络与取消隔离。

程序工具子调用具有可信来源标识。子调用中的三个工作区工具，以及 `use_workspace=true` 的 `code_execute`/`run_code` 明确拒绝，防止外层已占用项目目录时嵌套等待；其他程序工具保持既有契约。成员成果交接继续核验委派关系及原产物授权，再显式导入接收方目录，不挂载另一成员的可写工作区。

又拍云仅保存版本快照，不作为项目文件系统。写入静止后流式形成全量 ZIP，内含文件路径、大小和 SHA-256 清单，冻结完成后即可开放下次执行；后台上传只读取不可变快照。每个版本使用唯一对象路径，远端上传和校验成功后才推进已备份修订；恢复先在独立暂存目录核验完整清单，再替换项目目录并产生新修订，失败不覆盖当前文件。又拍云凭据只注入可信备份服务，不进入执行容器、镜像、模型或日志。

工作区运营组由现有 [OperationalSettingsRegistry](../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/settings/OperationalSettingsRegistry.java) 初始化，无需额外种子迁移；`workspace.enabled` 默认 `false`。管理员需校验项目卷、受控镜像、内部认证和云存储配置后启用，仍不自动给已有 Agent 挂载工具。默认 `checkpoint_interval_seconds=300`、`local_idle_hours=24`、`snapshot_history=10`；相同项目修订合并快照，显式检查点立即冻结当前修订。统一后台 Worker 默认单并发、存储请求限速 1 次/秒，429 优先遵守服务端 `Retry-After`，否则带扰动指数退避，本轮最多等待 60 秒；服务端要求更久时结束本轮并持久登记其要求的下次时间，不按固定间隔提前请求。单轮最多 5 次，失败持久记录后续重试。这些是客户端政策，不是又拍云平台额度。

本地归档仅在无活动写入且最新修订已备份时删除项目副本；后续访问恢复原快照，云端失败不能创建空目录冒充恢复成功。云端不可用时本地操作可以继续，未备份最新修订不得自动回收；异步备份不保证节点磁盘丢失时保留尚未备份的修改。用户状态区分本地可用、当前修订与已备份修订，不把本地保存显示为云端备份完成。清理与会话删除顺序见[保留规范](../04-指南与运维/11-数据清理与保留规范.md#会话项目文件与快照)。

已初始化工作区的持久状态缺失时返回 `WORKSPACE_STATE_MISSING` 并拒绝重新创建空目录。正常归档依赖仍保留的修订与快照登记恢复；整个项目卷及状态损坏需要人工恢复。首期不枚举云端对象重建状态，不提供灾难接管，不能把 OSS 中存在某个快照解释为已自动恢复该工作区。

工作区文件与快照不自动成为正式成果。交付时从确定项目修订生成或复制到本次 `/workspace/output`，继续按 `output_files → finalize_task_outputs` 收集并创建不可变 Revision；后续项目修改不改变旧成果。首期为单 Sandbox 执行节点，不增加文件编辑器、容器池、NAS、多节点接管或增量快照。

## 5. 产物存储与生命周期

### 5.1 收集与容量

输入、输出、引用与收集清单最多 2,048 个普通文件，单次文件传输总量最多 1 GiB。任务默认内存 1 GiB、CPU 2、PIDs 256、并发 4；stdout 与 stderr 各捕获 4 MiB并保留截断事实。文件公开检查仍独立约束单文件及解析资源，Skill 导入包沿用其所属契约。

宿主在执行提交前拒绝参数时返回 `state=rejected`、`phase=admission` 及类型化 `diagnostic`，使用稳定原因码、受控字段路径、原因和修正提示，不包含输入值。模式互斥继续严格执行：skill 不接受 `code`，空字符串、null 或 noop 也必须删除；inline 不接受 Skill 句柄或脚本路径。冻结资源错误和参数错误分别表达；未知配置缺口使用 `unavailable`，不泄露授权细节。模型先依据本轮契约修正具体字段，尚未执行时不以修改文件内容代替参数修正。公开过程只采用宿主受控的“参数校验未通过，尚未执行”等事实文案，不直接复制私有诊断。

代码工具在已知执行失败时，由机构宿主使用本次调用计算出的内部 taskId，只读取得 stderr 最后最多 4,096 字符作为 `diagnostic` 工具数据。读取最多占用 2 秒且不超过原调用截止时间，剩余不足 100 毫秒或已取消时不读取。模型诊断经过现有私有值范围检查，凭据和内部任务标识命中时隐藏，Python traceback 的脚本路径只保留文件名；返回截断标记。完整 stdout/stderr 不自动公开，诊断也不进入 `public_presentation`；stdout 不作为失败回退正文。诊断为空、读取失败或已无预算时标记 `unavailable`，受保护时标记 `withheld`，均保留已知执行状态和退出码，不转为结果未知、不重执行代码。结果未知的既有恢复与禁止盲目重放契约不变。

仅执行成功且退出码为零时收集 `output_files` 显式声明的最终目标文件。路径相对 `/workspace/output`，目录声明必须以 `/` 结尾且仅包含目标必需资源（例如网页 assets）；未传或空列表不发布产物。声明缺失、空目录或不安全路径会使交付失败。临时输入、摘要、调试输出、检查文件和失败半成品不得作为交付项，也不通过扩展名猜测目标类型；用户要求的 JSON、代码和配置本身可以是最终文件。机构宿主复验返回清单符合声明。

收集时拒绝绝对路径、路径穿越、符号链接、特殊文件及逃逸输出根目录的引用。收集前停止代码写入，使用受控文件句柄校验和读取，避免检查后替换。超过文件数或遇到不合法条目时明确失败，不静默丢文件后报告完整交付。

收集、跨服务传输、校验、持久化、下载与 ZIP 打包均流式处理并计算摘要，内存消耗不随单文件大小线性增长；不得整文件 `readAllBytes`、Base64 返回、JSON 内嵌二进制或前端 `response.blob()` 缓冲。无字节上限不承诺无限磁盘或无限耗时：磁盘耗尽、传输超时/中断和写入失败须有可识别错误、清理及运维告警。

单会话与已授权多会话的产物清单在同一事务内，按本次返回的精确产物 ID 集合批量读取文件可读性，不逐项追加查询；结果仅用于当前清单的状态投影。公开检查、文件状态及到期或正式引用的判定保持相同谓词，输入来源和 manifest 摘要仍逐项校验。单个产物元数据、票据和实际文件读取继续即时复核；清单结果不作为后续读取凭据。此处不改变模型工具的排序、offset/limit 或总数语义，也不将内存分页称为数据库分页。

### 本次执行的临时输入

`input_files` 是安全相对路径到 UTF-8 文本的映射（最多 256 项、合计 16MiB），写入只读 `/input/data/<path>`。它不创建产物元数据，不出现在下载或产物列表；内容与 `output_files` 均参与沙箱请求摘要，同任务变更声明或输入拒绝重放。计算过程的临时文件写入 `/workspace/work`，摘要打印 stdout。官方 Skill 仅从 data 或显式 artifact 输入定位数据，不能自动使用包内 examples。

### 用户上传的会话附件

机构端和独立聊天端通过 `POST /api/v1/chat/sessions/attachments/upload` 上传文件，multipart 字段为 `session_id`、稳定的客户端 `upload_id` 与 `file`；通过 `GET /api/v1/chat/sessions/attachments?session_id=...` 查询有效附件。接受 UTF-8 CSV、TSV、TXT、MD、JSON，以及 PDF、DOCX、PPTX、XLSX、PNG、JPG、JPEG，每文件最多 50MiB，每条消息最多选择 16 个，合计最多 200MiB。两端通过已授权的 `GET /api/v1/chat/limits?session_id=...` 读取附件、引用及文件选择容量；后端仍在受理与传输时校验。上传和查询均复用当前成员或渠道的会话访问校验。相同上传 UUID 只能绑定同一名称和正文；未知结果先查询原 UUID，不能以新 UUID 盲目重传。 上传原请求返回 `SESSION_ATTACHMENT_UPLOAD_REJECTED` 表示文件名称、大小、类型或内容在任何附件写入前被拒绝；客户端可显示原因并允许用户重新选择。仅该原请求的明确回执可解除对应待核对记录，其他错误和查询未找到均不能证明上传失败。

附件独立保存于 `nw_chat_session_attachments`，不登记为执行产物。普通聊天消息使用 `context.attachment_ids` 引用；HITL 确认或纯控制命令携带附件时明确拒绝，避免附件被静默忽略。宿主移除客户端自填的附件清单和读取事实，冻结服务端名称、路径、大小、摘要及到期时间。带文字目标的输入只准备元数据，生成代码通过 `code_execute` 或 `run_code` 的 `attachment_ids` 选择文件。上传和每次正文传输均按扩展名核验实际类型：文本严格校验 UTF-8；PDF 实际解析并拒绝加密、空文件与超过 100 页的文件；图片实际解码并核验 PNG/JPEG 类型与 4000 万像素上限；Office 核验主 XML 根节点和命名空间，并约束 ZIP 项数、展开字节、压缩比与 XML 大小，拒绝 DTD、实体、宏、ActiveX、嵌入对象和非超链接外部关系。包含嵌入图表工作簿的 PPTX 同样拒绝上传。宿主保留二进制原始字节，不将整批附件转换为常驻字符串；依据可信执行身份重新校验精确租户与会话、有效期、字节数及 SHA-256，通过类型化清单和流式 ZIP 写入沙箱只读 `/input/data/attachments/<uuid>/input.<extension>`。HTTP 上传、查询和消息输入冻结使用当前登录主体的会话授权；后台执行在选择非空附件及每次打开正文流时，根据可信 RunRef 查持久化 RunBinding，核对完整 SessionOwner 和执行 Agent，并复验冻结请求者或渠道的当前访问权，不依赖 HTTP 登录线程。空附件的内联执行不追加附件访问要求。禁止跨会话或隐式继承父会话的附件权限；与内联输入路径冲突时拒绝执行，合并输入服从统一 2,048 项、1GiB 文件传输预算。

没有文字目标的纯附件消息，在首次受理冻结时准备 CSV、TSV、TXT、MD、JSON 的完整小文本，单文件上限 32KiB、每条消息读取正文合计上限 64KiB，按提交顺序预算；不截取大文件前缀冒充全文。每件读取重新校验当前会话权限、有效期、冻结元数据、字节数、SHA-256 和严格 UTF-8，正文不修改原件。读取事实保存于现有 input ledger 的 `extraParameters.attachment_readings`，字段为 `id/status/truncated/text/reason`：`status=complete` 且 `truncated=false` 才携带完整 `text`；未读取时为 `status=not_read`、`truncated=false`，`reason=file_byte_limit`、`message_byte_limit` 或 `requires_document_parser`，不携带正文。读取事实不包含租户、宿主或存储路径，文件定位继续使用授权清单中的正式 `input_path`。受理重放只重新核验当前可用性并复用原冻结读取事实，不重复读取或以新内容替换；读取校验失败不得受理伪造的已读事实。正文以 USER 角色的不可信输入参与原有上下文预算，不成为系统指令、工具调用或执行授权，不额外增加模型调用。模型先基于实际已读内容简短概述主题或数据，再询问目标；未读附件先使用已有受控读取能力，能力缺失或解析失败时说明真实限制，不声称已读、不循环重试，也不要求重发已有原件正文。

工具结果的 `attachment_inputs` 仅包含实际注入文件的来源元数据，可作为评测的数据来源证据。上传后最长 7 天失效，过期立即拒绝使用，后台分批清除正文并保留 UUID 墓碑，禁止旧引用重新绑定内容。

已安装并挂载的 [document-read Skill](../../official-skills/document-read/SKILL.md) 通过受管 Docling、固定本地布局/表格模型和 Tesseract 提取 PDF、Office 与图片正文。读取返回类型化正文片段、页范围、表格数和完整性，不为普通问答生成交付文件；仅用户明确要求时导出 Markdown 或结构化 JSON。Office 读取原生结构，XLSX 使用缓存值，不重算公式；OCR、图表、SmartArt、备注及嵌入图片文字的限制归 [读取契约](../../official-skills/document-read/references/input-contract.md)。图片作为沙箱文档输入不自动授予模型视觉消费。真实上传至模型调用的开发验收入口为 [verify_document_read_live.py](../../tools/skills/verify_document_read_live.py)，使用会话附件接口与 `context.attachment_ids`，以实际 `attachment_inputs`、固定 Skill 激活和类型化读取结果核对来源，不能用产物挂载替代上传验收。

### 跨调用产物输入

`artifact_inputs` 只包含已发布产物 ID 和清单内相对路径。宿主以可信 Tool 执行上下文校验同租户、同 Session、ready 状态、有效期、清单摘要及文件内容摘要；模型不能指定身份、磁盘根目录或远程下载 URL。文件通过鉴权控制面的流式 ZIP 输入协议传递，正文不进入 JSON、模型上下文或 Runtime 事件。宿主仅维护请求期临时传输文件，结束或失败即回收。

Sandbox 将选中路径、大小、摘要纳入任务请求幂等摘要；输入完整流式校验后才调度代码，并写入本次任务 `/input/artifacts/<artifact_id>/<path>` 的只读目录。拒绝清单外项、重复路径、路径逃逸、缺失或内容摘要不符，准备失败清理半成品工作目录。同任务重复提交不再次调度，不共享此前任务的可写工作目录。

每个 ready 产物集合同时构成一个不可变版本快照。使用 `artifact_inputs` 生成新产物时，宿主将每个父产物 ID、父文件路径、字节数和内容摘要保存为显式多父来源图，不按展示名或文件名推断线性版本，也不另建 checkpoint 系统。来源关系与子产物元数据在同一事务发布，其规范摘要参与 Tool invocation 重放冲突校验；同一 invocation 改变父关系会失败，不能改写既有来源图。

### 5.2 元数据与原子发布

PostgreSQL 保存元数据，文件存放在独立持久卷，不复用短期执行目录。产物归属至少关联 tenant、Session、Run、Tool invocation，并记录不透明产物 ID、类型、展示名、目录清单、文件大小与摘要、静态入口、创建时间和到期时间；存储路径不是公开 API。

写入先进入 staging，完整传输、摘要校验、文件落盘及首次公开检查通过后才在同一事务提交 ready 元数据与检查凭据；网站目录按完整集合发布。调用结果只引用已 ready 的产物，不能暴露半文件或半网站。文件落盘但数据库提交失败时，文件保持不可见并由孤儿清理回收；重试登记必须校验同一调用与摘要，不覆盖已发布文件。Runtime 结果提交失败不授权再次运行代码，已发布记录可用于后续受控查询。

公开检查使用 `public-output-v5`，以宿主已知私有路径、显式敏感值与明确凭据格式为范围，不将普通运行、调用、能力或文件标识当作秘密，检查文件名、可提取正文、元数据及网站资源。API key 字段（包括 `api_key`、`api-key` 与 `apikey`）在完整正文及跨片段预览中均受保护。完整合法单根 JSON 中的原生布尔观察值按实际类型识别，字符串凭据和宿主明确标记的私有值仍受检查。凭据绑定文件 hash、字节数、范围摘要、策略和提取器版本；未通过文件不可进入清单、预览、下载或票据。正式冻结核验不可变文件及来源凭据，范围扩大时重新检查，不静默改写内容。策略或提取器版本变更不自动升级历史凭据；原文件和来源继续保留，取得当前版本的真实检查凭据前不作为可公开文件。

明确凭据格式包括 Authorization 的 Bearer/Basic/Token/ApiKey 值、token/password/passwd/pwd 键的赋值与 private-key PEM 头。完整单/双引号值保留符号与转义边界，无引号值和未闭合伪占位也检查；仅精确的固定技术示例白名单与完整 `${ENV_VAR}` 格式豁免，任意 `<...>` 前缀不构成豁免。普通字段说明和业务标识不触发格式拒绝。v3 不能把旧检查凭据直接改标为通过，必须取得当前策略的真实检查结果。

文字、HTML/SVG、JSON/XML、Office、PDF 与 ZIP 使用有界流式解析。单文件最多 256MiB、单批最多 1GiB，同批共享 120 秒协作式检查、32Mi 字符提取文字与 16,384 个成员条目预算；保留展开比例和嵌套深度保护。读取块及提取片段之间保留足够重叠，不能因已知私有值被拆在边界两侧而漏检。解析失败、加密或超限不能记为通过。图像及音视频只检查名称、可提取元数据与来源，不含 OCR，不证明像素或音轨中的文字安全。

公开文字命中已知实际私有值时阻断交付，以稳定拒绝事实使 Run FAILED；保留已发生成功、失败与未知结果，不追加模型调用、自动重写或重复执行。公开提示不回显命中值。业务 UUID、编号、代码与任务所需 API 字段保留，不按字段名或 UUID 形状删除。

候选执行文件和独立证据默认保留 7 天；到期后先阻止访问再异步删除文件及按留痕策略清理元数据，删除失败仍保持不可访问并重试清理。正式成果版本的交付文件和 `source_files` 来源文件都建立持久引用并随所属 Session 保留，不能按候选到期规则删除；处于 `planned` 或 `finalizing` 的交付文件、来源文件和证据文件另由 hold 保护。清理器锁定候选文件后必须在标记过期前重新核对 hold、正式交付文件引用、正式来源引用和未到期证据。历史聊天保留卡片及过期提示，不把失效链接当作可用交付。提前失去 Session 访问权同样立即拒绝下载与预览，不等待文件到期。

父产物到期或失去访问权不会改变已发布子文件；来源元数据继续说明子产物生成时核验过的父文件。正式成果视图的 `artifact_inputs` 投影已授权交付文件的持久来源图并去重，不能固定返回空列表，也不根据文件名推断来源。任何后续比较或定向恢复都重新检查当前 Session 授权、父产物有效期、清单摘要和文件内容摘要，父产物过期、撤权、缺失或摘要不符时失败关闭。

### 5.3 版本比较与定向恢复

`POST /api/v1/chat/artifacts/diff` 接收 base/target 两个 `{artifact_id,path}` 引用，仅比较同一 Session 中分别通过当前授权与摘要核验的文件。服务完整核验每个来源文件，但只对每文件不超过 128 KiB、每边不超过 2000 个逻辑行的文本计算结构化行差异；严格 UTF-8 解码，不用替换字符掩盖非法字节，空文件按零行处理，CRLF、LF、CR 和其他 Unicode 行分隔符按相同逻辑行比较。响应状态固定为 `comparable`、`binary`、`too_large` 或 `too_many_lines`，可比较结果的行类型固定为 `added`、`removed`、`unchanged`；响应和日志均不记录超出请求所需的产物正文，应用日志不记录任何差异正文。

`POST /api/v1/chat/artifacts/recovery-inputs` 接收可信当前 Session 和一个或多个 `{artifact_id,path}` 引用，重新鉴权并核验完整文件后返回包含大小与摘要的 `artifact_inputs` 验证结果。响应提供服务端可读标签和 typed `artifact_files` 引用，客户端通过顶层 `references` 提交，不能把恢复 JSON 或实际 ID 拼入正文。原文件核验结果供内部来源冻结使用，不重跑旧 invocation，不修改旧文件，不承诺已经生成新版本；新执行成功发布产物后才形成新的不可变版本快照和来源关系。

## 6. 下载与隔离预览

下载、目录清单和 ZIP 请求均按当前登录主体重新校验租户归属及 Session 访问权；知道产物 ID 不等于有权限。候选执行文件继续使用 `/api/v1/chat/artifacts/*` 接口查找和恢复；正式成果通过 `GET /api/v1/chat/sessions/deliverables` 读取，并由 `POST /api/v1/chat/deliverables/download-ticket` 或 `POST /api/v1/chat/deliverables/preview-ticket` 为精确 Revision 与文件签发票据。非 HTML 文件由 `GET /api/v1/chat/deliverable-content/detail?ticket=...` 流式读取，正式成果卡片不得沿用候选产物票据路径。浏览器通过鉴权下载入口流式接收文件，文件名安全编码，文档以附件下载并禁止 MIME 嗅探。ZIP 动态流式生成，读取安全清单，不将目录整体装入内存；流中断即表现为未完成下载，不返回成功页掩盖错误。

下载在释放任何文件或 ZIP 字节前，流式核验本次实际读取内容的字节数与 SHA-256，并从同一次读取形成的请求期私有副本传输；ZIP 全部条目通过后才开始响应正文。持久正文与已发布清单不符属于服务端完整性故障，返回 HTTP 500、`ARTIFACT_INTEGRITY_MISMATCH`、`retryable=false` 的 JSON 错误，不回显正文、路径或摘要，不授权重新执行原生成任务。缺失、过期与撤权继续使用原可用性拒绝语义。临时副本在成功、拒绝或客户端断开后回收，磁盘与读取失败保持明确失败。

静态网站仅提供已发布 HTML/CSS/JS 和资源文件的预览。预览使用与平台隔离的 origin，且不接收平台登录 Cookie；宿主在签发时完成身份和 Session 权限校验，签发仅限指定成果表示的预览 URL，有效期为 5 分钟。签名 URL 是受限访问能力，不是身份访问：预览服务按签名范围、有效期、文件状态和撤权状态处理请求，不重新执行机构成员身份鉴别。下载 URL 的有效期为 1 小时；票据不得进入模型上下文、普通日志或跨源 Referer。

前端以 sandbox iframe 嵌入，允许页面所需脚本但不赋予 `allow-same-origin`、弹窗、顶层导航或表单外发等权限。预览响应使用 CSP，仅允许该成果表示中声明的资源及其哈希许可的内联脚本和样式，禁止 `unsafe-inline`、`unsafe-eval`、公网网络请求、WebSocket、外部嵌套及外部资源；平台 API 不向预览 origin 开放凭证 CORS。预览服务同时校验路径与签名范围，不能只依靠 iframe 属性。未打包外部依赖的网站应展示缺失资源提示，不临时放开出网。

## 7. 运维与交付边界

实现时提供执行服务就绪检查、磁盘/暂存区/孤儿任务观测、容器清理、产物过期清理及持久卷备份恢复说明；元数据和文件备份必须匹配，恢复后仍执行归属和有效期检查。关闭功能阻止新执行，不隐式删除已授权保留的产物。存储压力下可以拒绝新任务并报告原因，但不得将此伪装为已约定的单文件大小上限。

首批以本地实现和必要验证为交付终点，不自动推定远程部署、生产开放或公开网站发布。Kubernetes Runner、多语言扩展及长期服务不作为此批验收前置。团队成果能力增量与官方模板包见下节。

## 8. 多形态成果与官方 Skill Package

平台与 Runtime 提供 Skill 加载、工具执行、权限、沙箱和成果协议，生产发行物不携带或启动安装任何 Skill。官方技能内容保存在[独立包目录](../../official-skills/README.md)，通过现有平台草稿编辑或 ZIP 导入、校验、发布机制独立维护；机构自建 Skill 使用相同版本契约。空技能目录是合法状态，模型只使用实际授权并挂载的能力；缺少读取或生成能力时明确说明，不按包名自动补装。

发布新版本和采用新版本是两个动作：默认版本指针变化不改写固定版本挂载，已受理执行继续消费原冻结版本。取消预置不删除已有 Catalog 定义、版本和挂载。包的运行依赖仍受沙箱镜像、语言及安装准入限制，在线更新 Skill 不等于可任意安装原生环境。具体步骤见[官方 Skill 发布指南](../04-指南与运维/09-代码执行与产物运行指南.md#官方-skill-独立发布与采用)。

成果表示任务产生、用户可查看、使用或继续加工的结果，不等同于所有生成文件。一个任务可以关联多项成果，一项成果可以关联可编辑源、预览和导出格式。业务用途（如销售分析）与交付形态（如表格、文稿或看板）分开；没有文件也可交付文字结论或真实操作回执。

没有明确格式要求时，Skill 可以建议 Markdown 文档或可直接打开的单体 HTML，不依赖 CDN；这些默认建议不自动构成文件交付义务，也不继承到后续任务。用户明确要求的其他格式必须覆盖，不默认压缩或截断。本地多文件网站允许将入口 HTML 与必要的 CSS、JavaScript、图片作为同一表示的文件集合提交，宿主逐文件鉴权、检查并验证相对资源引用闭合；文件可来自不同受管产物。用户明确要求单文件、单体或自包含 HTML 时，必要资源必须内联，普通“单页网站”不表示单文件约束。

主 Agent 直接结合当前用户请求、完整 owner 与当前 Run 绑定的 Goal 原目标，以及适用的已批准或按契约免批计划理解任务，按需加载已授权 Skill、生成成果并检查内容。普通无文件请求直接进入同一主执行链，不增加任务预分类、首轮必填 requirements、专属要求解释模型或自然语言义务接受快照。Goal 的执行包装、模型进展、工具结果和任意 Skill 正文不成为新的用户授权；Workflow 与 DAG 继续使用真实任务和批准计划身份，不通过输出正文授予权限。

文件交付先生成、检查实际文件，由 `code_execute.output_files` 收集受管候选，再以一次 `finalize_task_outputs` 提交完整最终选择。每项 Selection 包含 `key`、`title`、`kind`、可选 `base_revision_id` 和 `representations`；模型不提交 `decision_source`、`source_message_id`、`required` 等伪语义来源或约束声明。候选只表示受控可读，不自动要求全部发布。模型负责根据本次任务选择实际需要交付的格式、文件名和内容；Skill 的方法与 `manifest.outputs` 是能力说明，不生成宿主强制交付义务。

`finalize_task_outputs` 收窄为实际成果交付：宿主核验明确选中的成果、表示、真实文件及转换来源，检查当前 owner／会话读权、文件状态、路径与摘要、字段组合、格式和资源闭合、数量及字节预算，以及既有成果的当前基版本；通过后冻结完整选择、文件 hold 与发布预留。它不解析用户自然语言、不接受或修订 `All`／`Any`／`Artifact` 要求表达式，也不以专属语义契约决定是否允许首次模型调用、是否遗漏了用户义务或是否完成业务目标。

系统保证所选真实对象经过授权和技术核验，并按原 Run 与正式发布事实交付；不再声称宿主已机械证明任意自然语言要求、所有交付格式或专业质量均已满足。主 Agent 必须依据原任务与实际检查说明完成情况和限制，关键语义不明确时澄清，不能用 finalize 成功替代语义验收。无文件答复无需调用 finalize；无法形成交付时沿原放弃协议如实报告，不生成空的“要求已通过”契约。

实际成果收尾继续受原预算准入保护：模型调用次数和 Token 分别预留，多个收尾模型调用共用一个持久累计的模型时间窗口，并另加真实本地核验、传输窗口；业务 deadline 扣除必要保护。不得将两次模型调用各自的完整超时相加而在主模型前误拒绝可执行任务，具体计算及原子不足事实见 [Harness 共享任务预算](../../harness-design/03-上下文视图与执行优化.md#24-共享任务预算与持久结算)。真实不足由双端任务概览展示原事件中的具体维度，不重跑模型或改变已发生的调用来补齐显示。

本次设计移除 `system-agent.output-requirements`、八张专属 `output_requirement_*` 语义契约表及其接受、修订、冻结引用和恢复消费，不保留旧正则、双读或专属用途配置作为聊天前置。已有系统用途历史版本、原 Run、审计、外调、模型原始记录和用量事实按所属生命周期保留；数据库退出与发布恢复边界见[最终成果生命周期](../04-指南与运维/11-数据清理与保留规范.md#25-最终成果生命周期)。本节表达当前批准目标，实际实施与验收范围以对应源码、迁移和对应候选的原始运行结果为准。

修改已有正式成果时，最终选择必须沿用逻辑键并携带真实当前 `base_revision_id`；遗漏、空白或过期基版本在冻结前拒绝。宿主锁定成果、核对当前版本并冻结完整选择与目标预留，正式发布时仍复核当前版本，防止并发覆盖。确定拒绝可在原权限与预算内提交修正后的完整选择；不能更换 key 规避版本冲突。

后置 Run 输出上下文和 `list_artifacts.current_deliverables` 提供同会话正式成果的逻辑键、版本和真实文件引用；`artifact_id` 与 `file_id` 不具有版本语义。已有上下文足够时直接使用，信息缺失或版本冲突时按需查询，指代仍不明确时澄清，不要求修改已有文件一律先调用 `list_artifacts`。生成和收集不需要独立模型计划调用。内部冻结记录用于幂等与发布恢复，不能成为生成或收集的前置条件。

冻结后不再读取活动目录补造选择，仅允许最终回复。任务结果状态为 `pending`、`published`、`failed`、`cancelled`，不替代 Runtime Run 的执行状态或未知结果语义。决定放弃本次文件交付时显式提交空 `deliverables` 与非空 `abandon_reason`，保留放弃事实，不能同时请求完成 Goal；是否满足原任务仍须由主 Agent 据实说明。

成果 `title` 仅作为展示标题，不用于改写文件名。正式文件的 `download_name` 采用已选择受管文件路径的安全 basename，保留原扩展名；同一成果内重名时沿用确定性后缀消歧。用户明确命名的交付文件必须以该名称生成并被最终选择。多文件网站继续使用原相对路径和入口路径解析资源，下载名单段化不改写包内目录结构。

正式发布才创建不可变 Revision；同一轮的候选和草稿不创建版本。成果标题或下载名、内容、文件集合、入口路径变化时创建新 Revision，证据与展示变化不创建版本。每个表示使用 `source`、`export` 或 `bundle` 角色，`primary_preview` 与入口路径各自表达展示选择和可启动文件；导出文件按其实际 `source_files` 引用及摘要核验，而不以全局相同 source hash 推断来源。

V231 对 `nw_deliverable_revisions`、`nw_deliverable_representations`、`nw_deliverable_representation_files` 和 `nw_deliverable_representation_sources` 禁止原地 `UPDATE`。表示、交付文件引用和来源引用只允许在所属任务结果仍为 `pending` 时追加；任务结果转为 `published`、`failed` 或 `cancelled` 后，数据库拒绝继续拼接版本正文。后续变化必须产生新 Revision，不能修改旧行或向已结束结果补文件。

显式 ZIP 成果的压缩包根目录必须包含 `manifest.json`，并逐项覆盖包内除 manifest 外的全部文件：

```json
{
  "files": [{"path": "...", "sha256": "...", "bytes": 123}],
  "entry": "...",
  "includes_originals": true
}
```

`entry` 可以为 `null`，非空时必须指向 `files` 中的实际文件；摘要使用 64 位小写 SHA-256，`includes_originals` 必须为 `true`。ZIP 只在最终选择包含真实 `zip` 文件且表示角色为 `bundle` 时发布，并接受相同的文件、归属、格式及安全核验。

`finalize_task_outputs` 先冻结候选选择并预留目标成果，真实 Run 成功结束后在同一事务发布 Revision、表示、文件引用、任务结果与当前 Revision 指针。失败、取消或发布冲突释放预留，不留下可访问半成果。SSE 重发读取已发布事实，不重新执行代码、渲染或外部操作。

Runtime 的原始 `Run COMPLETED` 只证明该Run执行终结，保持原日志、报告、用量与恢复事实不变。带 `task_result` 的最终结果还须由宿主按精确 owner、run 与 result_ref 核对所属成果发布事实；其他Run、旧Revision、相同文件名或模型自述不能代替本次发布凭据。不带task_result的普通最终回复沿原公开路径处理。

发布为pending时，最终业务正文与公开completed状态暂不交付，也不推进越过该结果的durable checkpoint；不得把暂未发布转成永久拒绝、丢弃最终结果或重新执行模型、代码及外部动作。发布为published后交付原已核验最终正文及真实成果引用；发布failed时由宿主展示发布失败，原模型报告保留审计和恢复归属，不以失败展示改写原Run终态或清洗原正文。

历史查询、activity与实时SSE使用同一发布门禁，重连和重放不能从另一公开入口提前取得被暂缓正文或completed。 pending的历史/API读取返回503、稳定码 `TASK_OUTPUT_PUBLICATION_PENDING` 与 `retryable=true`，不伪装成公开running或completed；SSE follow同样保留该可重试原因且不发送 `execution.completed`。客户端只能按该明确暂态读取或重连，不能因此重提交业务输入。durable投影遇到pending时整批事务回滚，既不推进checkpoint，也不登记永久拒绝；后续按原源事件收敛。failed的公开状态为failed，固定展示“成果发布未完成，本次交付失败。”，原Runtime COMPLETED/report保留；published分支交付原正文。公开投影及其Outbox提交复用已有成果发布事实与事务机制，不新增发送账本；成功执行、候选ready或清单冻结都不等于发布成功。门禁控制公开时序，不增加模型回合，也不以自然语言禁词判定发布。

文件目标通过 finalize 的可选 `goal_completion.expected_revision` 请求自动完成。成果服务在冻结事务持久化可信完成请求与处理标记；正式发布事务提交后，宿主才通过独立 SessionGoal CAS 完成目标，并记录处理回执。发布前 Goal 仍为 ACTIVE，界面由匹配的 pending 请求显示“收尾中”；恢复只收敛已受理请求，不增加模型调用。状态所有权、两类中断窗口与用户 revision 竞争的契约见 [Harness 持续 Goal](../../harness-design/03-上下文视图与执行优化.md#231-成果发布后的完成请求)，清理保护见[最终成果生命周期保留规则](../04-指南与运维/11-数据清理与保留规范.md#25-最终成果生命周期)。

| 提供层 | 职责 |
| :-- | :-- |
| 平台内置基础设施 | 任务关联、成果登记、来源核验、权限、版本引用、下载与隔离预览 |
| 官方或外部 Skill Package | 专业说明、检查方法、脚本、模板、依赖及示例；不另行维护平台执行与交付协议 |
| Tool 与运行环境 | `code_execute`/`run_code` 执行受控代码；`render_artifact` 将真实产物转换为 PDF、页预览或静态表格 |
| 专业服务与连接器 | 按实际安装和授权提供图片/视频、设计源对象或外部操作；未接入不能声称开箱可用 |

六类官方包是预装数据，不是枚举、Java 按技能名分支或数据库专用列。资源索引列出可变数量的包，经现有 SkillPackageValidator、Catalog Definition、不可变 Version 和 Mount 生命周期发布。平台 `versionKey` 独立标识平台发布版本，包内 `metadata.version` 保留上游含义，二者可以不同或包内省略版本，不改写原始文件和摘要。内置发行者在首次安装时使用自己声明的 `metadata.version` 作为默认平台编号，这不是外部导入约束。首次安装不存在的定义可发布基线；定义已存在时，无论草稿、已发布、停用或归档，应用启动/升级均不替换默认版本、不重新发布。后续内容编辑、包导入、校验、发布和停用统一由平台后台维护。预装和 `allowed-tools` 只声明能力需求，不自动给 Agent 授权或挂载工具。

标准目录或 ZIP 导入保留包原文及逐文件摘要。合法但未解释的 frontmatter 扩展以警告说明；hooks、指定 Agent/模型、Shell 和内联命令等扩展不在导入或加载时解释、展开或执行，也不改变平台授权。校验结果以 `ERROR`、`WARNING`、`INFO` 区分包错误、未支持声明和未核实环境，仅错误阻止发布。标准字段类型、路径、摘要和容量校验继续严格执行；导入或内容可读不代表其全部产品扩展、脚本依赖和运行环境可用。

`render_artifact` 使用固定受信脚本与同一隔离执行通道，只接受 artifact ID、清单路径和格式，不接受任意命令。Office 渲染环境包含 LibreOffice、Poppler 与中文字体；转换临时目录不进入成果文件清单。模型提交的路径不能绕过产物归属、有效期与内容摘要检查。

任务成果登记只接受分工声明的输出名，以真实 Run/Action/文件来源核验；中间文件不自动变为任务成果。文本成果保留限制说明；操作成果引用已结束的上游 Action 回执，登记调用不能自证业务完成。动作成功与用户目标完成仍分别判断。未知外部结果不得自动重试。

本地网页、隔离预览与公开发布分别表达；生成 HTML 不等于应用已上线，配置文件不等于配置已生效，代码文件不等于已提交仓库。公开链接只有在已核验执行事实明确返回公开地址时才能引用。可编辑设计源与导出图片保持不同 representation，未接入设计服务时不虚构可编辑对象。

成果权限与引用来源独立检查；当前可见投影不暴露内部授权凭据。团队的输入绑定、并行执行及唯一工作答复规则见 [Harness 团队 DAG 基线](../../harness-design/08-Agent委派与多智能体运行时.md#20-agent-原生委派与结构化计划首期基线)。
