# Agent 与 Harness 项目设计总览

NoeWise 以 Agent 理解目标、选择受授权能力并交付结果，以 Runtime 维护身份、上下文、执行状态、预算和恢复事实。本文提供阅读路线，不复制接口定义或声明所有目标均已实现。

## 1. 产品与宿主

最终用户通过持续会话描述目标、提供材料、查看进度并参与必要确认。机构后台建设和运营 Agent，平台后台维护公共资源及机构治理。平台和独立桌面宿主组合使用同一 Runtime，各自提供配置、权限、模型、工具与持久化端口。

产品边界见[产品概述](../01-产品与需求/02-产品概述.md)，用户旅程见[PRD](../01-产品与需求/01-PRD.md)，宿主集成见[技术架构](01-技术架构.md)。Java 模块中的 `agent-runtime-*` 提供可独立消费的 SDK，`skillforge-*` 承担平台业务职责；技术标识不影响产品名称。

## 2. 输入、决策与执行

入站消息先通过身份、权限和幂等边界，再形成供本轮使用的上下文。Agent 在 Action/Observation 循环中决定回答、检索、调用工具、启动 Workflow、请求确认或委派子任务；模型提出动作，Runtime 校验与提交实际执行事实。

Session 承载长期会话，Run 表达一次任务推进，Execution 及等待对象维护所属执行生命周期。普通对话、Workflow 等待和后台工作可以共存，后续输入通过明确身份定位要恢复或控制的目标。失败、取消和结果未知分别保存，恢复读取已提交事实，不自动重发未知外部效果。

- 全局装配和端口见[微内核架构](../../harness-design/02-微内核插件架构实现思路.md)。
- 对象、状态机、幂等和持久化见[核心对象模型](../../harness-design/03-核心对象模型与状态机.md)。
- HTTP、SSE、公开投影和错误边界见[接口与事件契约](04-接口与事件契约.md)。

## 3. 上下文、知识与记忆

上下文由用户输入、已提交历史、任务选择、能力、知识证据和记忆材料形成。来源、顺序、预算和冻结由 Runtime 统一维护，Provider 编码冻结输入。摘要与结果回读不能覆盖权限、精确版本、失败或 UNKNOWN 事实；恢复不以新配置重新构造原请求。

Knowledge 提供带来源的机构知识证据，Memory 保存有归属和治理边界的持续事实，Skill 提供程序性工作方法。资料、提示词和历史对话不能自行授予外部操作权限。按需加载减少无关上下文，读取过的历史材料不自动成为本轮指令。

详细契约见[上下文专题](../../harness-design/03-上下文视图与执行优化.md)、[多模态专题](../../harness-design/03-多模态内容与媒体引用.md)和[记忆管理](07-记忆管理.md)。图谱、GraphRAG 与图谱运营属于产品非目标。

## 4. 能力与专业协作

| 能力 | 职责 | 边界 |
|---|---|---|
| Skill | 按需提供指令、脚本和资源 | 包内容本身不授予执行权 |
| Tool | 执行明确操作 | 部署、身份、策略与副作用许可独立校验 |
| Knowledge Source | 提供可引用的证据 | 来源、版本和租户范围受控 |
| Workflow | 推进确定步骤、等待和回调 | 执行状态与 Session 对话分别维护 |
| Agent 委派 | 将明确子任务交给获授权的专业 Agent | 首期子 Agent 为叶子执行者，父子生命周期和交接独立维护 |

工作室由固定主助手组织协作，内部委派与业务共享群聊是不同关系。专业 Agent 的能力快照、授权、父子唤醒和恢复见[委派运行时](../../harness-design/08-Agent委派与多智能体运行时.md)，业务流程语法见[Workflow 规范](../03-规范与术语/01-工作流规范.md)。

MCP 是外部工具协议适配，不能由协议连接替代业务授权。当前模块装配与后续动态插件生态按[Runtime 架构](../../harness-design/02-微内核插件架构实现思路.md)区分，不因模块存在就承诺热安装或任意宿主隔离。

## 5. 代码执行与正式交付

平台代码执行通过独立 Sandbox、受控依赖与出网、产物存储和下载交付。执行成功、公开业务结果与正式成果发布是不同事实；失败、取消或超时的半成品不发布。预览与下载按每次访问重新授权，产物版本和来源保持可追溯。

平台容器执行与桌面本地文件/命令工具采用不同装配和权限边界，不能相互推定隔离能力。设计及操作见[代码执行沙箱与产物交付](12-代码执行沙箱与产物交付.md)、[运行指南](../04-指南与运维/09-代码执行与产物运行指南.md)和[桌面客户端](../../desktop-client/README.md)。

## 6. 评估与当前阶段

验证分别检查确定性契约、真实基础设施、业务链路和模型效果。测试数据与配置冻结，观察结果、用量和副作用回执；本地测试、模拟模型和文档检查不能证明真实供应商效果或生产就绪。评估方法见[测试与验收策略](../04-指南与运维/03-测试与验收策略.md)。

仓库处于预发布阶段。产品分期见[路线图](../01-产品与需求/04-实施路线图.md)，Runtime 范围见[实施方案](../../harness-design/06-MVP-0技术底座实施方案.md)，宿主剩余主题见[未实现功能清单](11-未实现功能清单.md)。设计描述目标与契约，源码和对当前候选执行的验证证明实际行为。
