# 知识不可变内容与存储治理

本文定义知识领域的正文所有权、版本引用和容量受理。知识与 Memory 的边界见[数据模型](03-数据模型设计.md#6-记忆与知识分离)，Runtime 的知识请求与证据语义见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#59-knowledge-runtime-契约)。引用化改变持久表示，检索仍按精确 `source_id/source_version` 返回出处。

当前表结构入口见 [V285 迁移](../../backend-java/skillforge-migration/src/main/resources/db/migration/V285__knowledge_immutable_body_references.sql)；表或迁移存在不代表目标环境已经完成迁移或全部治理场景验收。

## 1. 正文所有者与版本

| 事实 | 权威所有者 | 引用与不变量 |
|---|---|---|
| 文档原始正文 | `nw_knowledge_document_contents` | 同租户、同文档的完整原文、格式及摘要；来源版本引用 `content_id`，保留原文件布局，不从分块反推原文 |
| 分块正文 | `nw_knowledge_chunk_contents` | 同租户、同文档的不可变正文；摘要只筛选候选，全值相同才复用 |
| Embedding | `nw_knowledge_chunk_embeddings` | 精确正文身份、模型 ID/revision/dimensions 及完整向量；同维度不能替代模型空间身份 |
| 分块集合 | `nw_knowledge_chunk_sets` 与 `nw_knowledge_chunks` | 不可变有序成员，保存正文/向量精确引用；NULL 向量表示仅关键词分块 |
| 来源元数据版本 | `nw_knowledge_document_versions` | 当时标题、文件与来源元数据、原始正文引用、集合引用和模型空间；ready 后禁止原地 UPDATE |
| Runtime 知识冻结 | `nw_runtime_knowledge_sources`、`nw_runtime_knowledge_chunks` | 冻结所属租户、来源版本、集合、文档、分块和顺序；不复制完整正文；外键保护原不可变材料 |
| 重建成功批次 | `nw_knowledge_rebuild_batch_embeddings` | 顺序向量身份与既有调用回执分别持有，向量正文只有知识向量表一个所有者 |

`knowledge_chunk_values` 是 PostgreSQL 16 `security_invoker` 只读关联投影，继承底层 RLS。它按来源版本解析集合、正文与向量，不具有独立写权。关键词查询只投影所需字段，向量检索使用该来源冻结的模型空间；所有版本筛选在 topK 之前执行。宿主 SQL 关键词回退与 Runtime 的 KEYWORD 均按不区分大小写的连续字面子串匹配，`%`、`_` 和反斜杠按普通字符处理，不读取向量；该规则不表示 Elasticsearch、语义或混合检索具有相同的匹配和排序行为。

管理端语义检索启用相关度阈值时，向量候选按未舍入的相似度过滤。存在向量候选但全部低于阈值时返回空结果；没有向量候选或向量检索不可用时仍可使用关键词回退。混合检索继续使用其融合评分和阈值规则。

新生成的分块统一使用知识库的分块大小和重叠长度。句间合并与超长单句硬切均保留上一块的重叠后缀，后缀内有句末或换行边界时从边界后开始，否则按字符保留；硬切不能跳过重叠，以便在配置的重叠范围内保留跨边界短语。调整算法或配置不改写既有不可变集合与 Runtime 冻结引用；重新分块产生的新来源须按原流程明确发布后使用。

只改标题时追加元数据版本并复用原 `content_id/chunk_set_id`，不新增原文、集合成员、分块正文或向量。服务端比较完整正文实际值；省略正文和回送未变化正文采用同一复用路径，无须客户端删去字段。正文实际变化时才按当前分块配置重新分块；新来源版本仍独立生成索引投影，旧来源保持原标题和正文。完全相同的标题/正文或分块正文不新增版本，也不调用 Embedding。编辑一个分块时创建完整新集合关系，只新增变化的正文及向量，未变化材料继续引用原身份；旧版本的标题、正文与出处保持可解析。删除分块同样建立新集合，不改写旧集合成员。

原始文档和派生分块有不同格式与恢复用途，分别各保存一次；改变完整原文时仍保存新的完整原文，不以重新拼接分块丢失原布局。单块编辑按既有编辑语义生成新的完整文档原文，此原文与新集合在同一版本事务提交。

文件上传完成与来源可检索是不同状态。上传回执为 `SUCCEEDED` 表示文档已创建并可按原请求读取回执，不保证已形成有效分块；零分块来源保留为 `failed`，不作为 ready 来源发布。机构后台对这类上传给出补正文提示，列表显示“无可检索正文”并提供“补充正文”，不引导重复索引相同空内容。操作者在原文编辑器补充有效正文并保存，确认来源变为 ready 且已有分块后，再按新来源版本准备知识发布；后续 Runtime 使用发布中明确选择的版本，旧回执读取不重新上传。

上传准备入口在解析文件和调用模型前检查知识库是否可写。已有重建写锁等明确前置拒绝形成 `REJECTED` 回执，按原请求查询仍返回该终态；发布重建结果或取消重建后，操作者可重新选择文件发起新上传。准备阶段复用本次检查取得的知识库配置，持久化时仍在短事务内核对写锁与模型修订。模型执行或事务提交的未确认异常不归为前置拒绝，保留原请求身份与 `PROCESSING` 回执用于核对。

## 2. 事务、冻结与重建

知识编辑和发布沿用知识库行锁、当前版本 CAS 与既有版本原子事务。正文和集合引用在当前指针推进之前保存；失败回滚正文、集合、版本和指针，外部索引只在数据库提交后发布。

外部投影 `_id` 使用租户、知识库、精确来源版本、分块组合身份的稳定摘要，`_source.chunk_id` 仍是原分块身份，标题复用集合不会覆盖旧版 ES 投影。混合检索按知识库、文档、精确来源版本、分块融合双命中分数，共享分块的两个来源版本仍分别返回。启用索引时在网络派发前持久登记来源 hold；完整逐项确认后只释放本次 hold，未确认转 UNKNOWN，不能靠 TTL 或另一次修复成功解除旧 UNKNOWN。显式来源修复同样先锁知识库并登记 hold，来源已回收时在任何外部派发之前拒绝。

同租户的新增正文和回收再持有知识容量行锁。持锁后读取一次容量，按本事务实际新增材料累加，不为每个分块重新汇总整个租户。摘要查找不跨租户或文档，也不能用摘要相同绕过正文全值核对。

Runtime 冻结时锁定所属知识库，并验证完整来源清单、ready 状态和实际分块数。一个集合被两个元数据来源版本复用时，冻结关系的身份仍包含精确来源版本；查询或恢复不能替换成当前版本。

Embedding 外调继续在写事务以外执行。成功结果通过原 job fence 事务写入唯一向量表、顺序引用和 READY 回执；崩溃后读取引用，不复制向量或再次调用成功批次。STARTED 丢失结果继续转 UNKNOWN，显式重算仍要求原成本确认。目标版本完成与发布沿用原检查和 CAS。发布成功后解除批次暂存引用，正式集合继续保护向量；失败、取消和 UNKNOWN 材料保留恢复引用，未确定所属保留规则前不自动释放。

## 3. 累计容量与预算

机构知识累计额度默认只观测。`nw_knowledge_storage_budgets` 的 NULL 额度表示该维度未配置；不会推断生产上限或默认拒绝。配置后按租户锁及来源事务拒绝超额新增正文，版本事务整体回滚。

逻辑字节额度统计唯一原始文档及分块的 UTF-8 字节，加唯一向量的 `dimensions × 4` 浮点载荷字节；另一个可选额度统计唯一分块正文数量。标题修订、纯引用复用和内容相同的请求不新增正文，不重复占用额度。关系与来源版本仍分别展示数量，不为它们暗加未批准的硬额度。

容量接口同时返回来源版本、集合成员、Runtime 冻结引用、重建暂存引用、索引 hold/清理意图和唯一正文/向量数量。`physical_bytes` 是所属租户正文与向量列的 `pg_column_size` 汇总，不包含表、索引或整库磁盘开销；不能据此推算生产总磁盘容量。

## 4. 历史回收

回收要求明确的 `before` 和 `limit`，不提供知识历史默认 TTL。每轮最多 200 个候选来源及各类孤立正文，以 `(created_at,id)` 顺序重新扫描，已删除材料退出下一轮候选，受保护材料不阻塞后续可回收材料。

以下引用完整保护来源和正文：文档当前指针（包括软删除容器）、任何仍保留的发布/归档 revision 清单、Runtime 冻结来源及分块、任何仍保留的重建来源/目标和成功批次恢复引用、进行中或 UNKNOWN 的索引 hold。终态、归档、软删除或 ACK 不能单独解除这些引用。回收先持知识库锁，再持租户容量锁，在同一事务内重新核对关系；数据库守卫和外键再次拒绝被引用的删除。

只在获授权知识库内回收无引用版本、无版本持有的集合，以及没有集合或重建暂存引用的孤立向量/正文。集合被其他元数据版本复用时不会删除。来源删除事务同时登记精确 ES 投影清理意图；既有知识调度器每租户有界消费，网络删除不占数据库事务，未确认保留意图并重试，同代次确认才收尾。索引停用时不领取或更新清理意图。单版本删除只匹配租户/知识库/来源版本，不能按共享 `chunk_id` 删除其他版本；全部 chunk 投影删除只供已经核实无任何受保护引用的孤立分块使用。

## 5. 机构治理接口

| 接口 | 输入与行为 | 权限与范围 |
|---|---|---|
| `GET /api/v1/knowledge/storage/capacity` | 读取本机构真实容量与当前可选预算 | `foundation.knowledge.read`，机构成员且当前数据范围为 all |
| `POST /api/v1/knowledge/storage/budget` | `observation_only=true` 时两额度为空；false 时至少一个正数额度；整体替换预算，不清理已有材料 | `foundation.knowledge.update`，机构成员且当前数据范围为 all |
| `POST /api/v1/knowledge/storage/recycle` | `kb_id/before/limit/dry_run` 全部必填；预览返回来源版本身份，执行返回各类真实删除行数 | `foundation.knowledge.delete`，当前机构成员及该知识库 manage 授权 |

请求体不携带租户或成员身份，平台主体与独立外部凭据不能使用这些机构治理入口。预览不删除材料；实际执行重新检查当时引用，不依赖旧预览结果解除保护。上述接口只定义显式受理路径，不自动操作任何存量环境。

## 6. 迁移与验证边界

前向迁移保留版本和分块身份，按同租户/同文档/完整正文/模型空间转换引用。冻结正文无法与原来源全值匹配时停止迁移，不从当前版本补写旧材料。既有成功重建向量移入唯一所有者，原调用身份和 UNKNOWN 回执保留。

存量环境转换须停止知识写入，保全数据库及相关派生索引快照，并明确环境操作授权。恢复使用迁移前数据库与配套应用包，不允许旧包继续写新模型。源码、迁移草案及已准备测试不证明数据库已经迁移或额度已经实际限制；真实约束、RLS、恢复、并发及同控实际行数/字节结果以对应隔离环境验证为准。
