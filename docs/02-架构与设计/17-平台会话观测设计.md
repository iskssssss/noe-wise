# 平台与机构会话观测及轨迹设计

> 本文定义平台与机构后台对会话、问答执行、轨迹和模型用量的只读观测边界。
> Agent Runtime 的身份、状态机、用量对象、恢复和持久化契约统一引用 [Harness 03：核心对象模型与状态机](../../harness-design/03-核心对象模型与状态机.md)，本文不复制或改写内核契约。

## 1. 目标与边界

平台运营人员需要跨机构定位一次会话中的问答、执行轮、模型调用、工具调用和异常，而不取得可执行权限。平台和机构后台均可在当前会话及来源授权范围内查看已保存的原始输入、输出、模型响应与工具详情；这些记录沿用会话读取授权，不另要求平台诊断权限。平台管理员还可使用 §2.3 的独立扩展诊断入口。

观测投影消费宿主会话、Runtime 轨迹和用量账本的已提交事实；它不保存另一份 Session、Execution、Action 或 Usage 权威状态，也不从显示状态反推调用结果或费用。

平台后台拥有跨机构筛选、详情和诊断页面；机构端只能在自己的显式租户及会话数据范围内消费相同语义的受控投影。两个前端各自拥有路由、业务 API 和权限语义，执行树与详情控件由后台共享层复用，边界见 [前端共享层设计](08-前端共享层设计.md)。

执行观察按 Session、Run 和实际调用关系组织，轨迹只读投影已提交事实。阅读、检索与诊断均使用当前主体的明确权限，不依赖外部观测平台维护业务权威状态。

| 对象 | 本项目中的用途与边界 |
| :--- | :--- |
| Trace | 由技术追踪上下文关联的一次调用过程；不同请求、恢复和回调保留自己的 Trace 身份。 |
| Session | 连续交互的会话定位；同一会话可以包含多个问题与多条 Trace，不能据此自动认定属于同一个任务。 |
| Trajectory | 以 `tenant_id + session_id + root_input_id` 定位、从权威事实整理的业务轨迹；通过明确执行关系纳入续接和子轨迹，不另建可修改的任务状态。 |

## 2. 查询资源

以下资源均为 `GET`，路径相对于 API 根路径；分页 cursor、snapshot 与深层资源必须绑定原查询的授权作用域、机构、会话和根输入，不能跨资源复用。

| 资源 | 路径 | 用途 | 必填定位键 |
| :--- | :--- | :--- | :--- |
| 会话列表 | `/platform/sessions` | 按机构、会话、用户、Agent、团队、渠道、状态、时间和摘要筛选会话。 | 分页参数；平台可选 `tenant_id` |
| 会话详情 | `/platform/sessions/detail` | 返回会话身份、参与者、状态、时间、活动执行和用量快照。 | `tenant_id`、`session_id` |
| 问答与执行轮 | `/platform/sessions/rounds` | 按根输入展开真实 Run 与 Loop/iteration。 | `tenant_id`、`session_id` |
| 会话消息 | `/platform/sessions/messages` | 在受控范围内分页读取会话消息，可按根输入收窄。 | `tenant_id`、`session_id` |
| 会话原始事件 | `/platform/sessions/trace` | 分页读取一个根输入下的原始安全事件及其来源，用于诊断；执行树使用下表的统一轨迹节点资源。 | `tenant_id`、`session_id`、`root_input_id` |
| 会话事件内容 | `/platform/sessions/trace/content` | 按已授权且属于该根输入的内容引用读取可展示载荷。 | `tenant_id`、`session_id`、`root_input_id`、`content_ref` |
| 会话用量 | `/platform/sessions/usage` | 主 Agent Core MODEL attempt 的会话级供应商用量，可按根输入收窄；含辅助和成员的完整问答用量使用统一轨迹详情。 | `tenant_id`、`session_id` |

列表只提供摘要；详情页以问答、消息、轨迹和用量资源按需加载，原始调用正文通过所属内容引用读取，不能通过列表字段推断未加载材料。

两个后台的统一轨迹资源分别位于 `/platform/trajectories` 与 `/chat/trajectories`；机构端的目标租户由当前授权作用域提供，不从客户端参数获取。资源包括列表、`/detail` 概览、`/nodes` 节点页与 `/content` 受控正文。详情与节点页按同一轨迹的固定来源上界读取，正文读取仍执行当前授权；刷新建立新的快照。

快照使用 Redis 的有界短期查询缓存，客户端只持有绑定主体、作用域和完整轨迹身份的不透明引用，不把完整来源闭包放入请求。`skillforge.trajectory.snapshot-ttl` 默认为 `PT10M`，`skillforge.trajectory.snapshots-per-actor` 默认为 `32`；超出主体容量时淘汰较早快照。缓存仅保存安全来源引用、时点状态和计量，不保存正文、执行许可或另一份业务权威状态。过期、容量淘汰或缓存缺失时明确要求刷新后重试，不把旧 cursor 静默接到新快照，也不把读取失败显示为空轨迹。

`detail` 提供输入、公开输出、状态、消息、用量与 snapshot；`nodes` 提供语义节点、必要祖先骨架、节点覆盖状态和续页 cursor。节点使用稳定 `node_id` 和明确 `parent_node_id`，保留来源会话、根输入、Run、Action、Step、attempt、Trace、源事件与内容引用。原始事件是操作的来源，不为每条事件再创建一次模型或工具调用。接口的精确字段和类型以所属 DTO 与客户端为准，不在本文复制 ABI。

### 2.1 Turn 与 Step 观察视图

业务问答轮次导航保留真实 `root_input_id`；展开轮次后使用统一的执行树与节点详情。树按实际执行关系组织，展示序号只用于阅读，不成为持久身份。一次轨迹可以包含多个 ENTRY；恢复与回调清楚标识所属 Trace，并通过同一 Run 的续接身份关联，不显示为一次跨等待的连续技术调用。

轮次响应的 `round_number` 为十进制字符串，按同一 Session 各根输入的 `first_sequence` 升序从 1 编号，在分页 cursor 或指定根输入筛选前计算。导航按 `first_sequence` 倒序显示，最新请求在前；页面采用服务端编号，不从当前数组下标计算。分页和深链定位沿用冻结上界内的 `first_sequence` 顺序，按指定 `root_input_id` 定位或合并续页时保留该根输入的正式编号，后续 Run 事件不改变已有轮次的先后关系。

| 类型 | 父子关系与阅读含义 |
| :--- | :--- |
| ENTRY | 一次真实外部请求或交互；其下为本次触发的 Agent 执行。 |
| AGENT | 主 Agent 或子 Agent 的真实运行；由工具派发的子 Agent 位于对应 TOOL 下。 |
| STEP | 原模型决策身份所确定的 ReAct 轮次，保留所属 Run、Loop 和 iteration；attempt 重试不增加轮次。 |
| LLM | 真实模型逻辑调用；在详情中逐次查看 attempt 和报告状态。 |
| TOOL | 真实工具逻辑调用；保留每次尝试、失败、修正与反馈。 |
| RETRIEVAL / MEMORY | 固定流程触发时位于 AGENT 下；模型通过工具触发时位于相应 TOOL 下。 |
| GUARDRAIL | 已执行的策略或校验，注明对象、阶段和结论；按实际顺序紧邻被保护操作。 |
| COMPACTION | 实际发生的上下文压缩；摘要模型调用属于该节点的 LLM 子节点。 |
| WORKFLOW | 按实际节点、分支、并行与子流程展开，保留 Workflow 执行语义。 |

可选环节未发生时不创建占位成功节点。操作父子关系来自真实执行上下文及受信的父 Action、attempt 与子 Run 关系；`caused_by_event_id` 表达因果引用，不自动作为操作父节点。缺少精确身份的事实单列并标明缺失，不按时间、名称或相邻 Action 猜测归属。并行同级操作不因排列顺序被解释为先后依赖。

不属于压缩等专用操作的固定辅助模型调用直接属于 AGENT 的 LLM 节点；归属通过真实外调 attempt、父预算作用域及根输入验证，不人为增加 ReAct Step。辅助调用按真实 attempt 进入模型次数、供应商用量及费用覆盖，与主循环重复引用的 attempt 去重。缺少精确根输入或关联材料时保留覆盖缺口，不能按调用点名称或时间补齐关系。已退出的系统用途不产生新调用，但其历史真实 attempt、模型原始记录及用量继续按原事实展示。

概览先展示用户目标与公开结果，再展示步骤数、模型／工具调用和用量。节点显示类型、名称、状态、实际起止时间、耗时与已报 Token，输入、输出、attempt、重试及原始记录按需读取。每个真实模型 attempt 分别提供原始请求与原始返回的内容引用，两个后台均可按当前会话授权读取；正文入口位于可选的 attempt 明细折叠之外，不因折叠或缺少平台诊断权限而隐藏。调用已登记、实际执行、结果已提交分别表达；事件记录跨度、排队／等待与供应商调用耗时不能混用。响应 ID、系统指纹、finish reason 或 TTFT 缺失时显示未记录，不以内部标识替代。

两个后台复用任务概览的终止原因与预算不足展示，读取原 `execution.completed` 的 `skillforge.runtime.execution.completed.v2` 事实。收尾不足的 `budget_failure` 与该终态同事件原子保存，schema 为 `skillforge.runtime.execution.closing-budget-failure.v1`，code 为 `execution_output_closing_budget_insufficient`；页面按原 `phase` 和 `shortfalls` 显示根／Run 作用域、维度、单位、总需求、原总额度、差额、已消耗及已预留。`shortfalls.required` 包含已用量，`available` 为原总额度，不能分别标成“未来需求”和“剩余可用”；`consumed`、`reserved` 独立展示，不再次从 available 中扣减。

`time_calculation` 展示冻结模型调用次数、单次超时、共享模型窗口、本地处理窗口及未来收尾时间；其中 `required_ms` 是未来窗口之和，不是前述包含已用量的总需求。计算规则统一引用 [Harness 共享任务预算](../../harness-design/03-上下文视图与执行优化.md#24-共享任务预算与持久结算)。概览同时显示原终态记录的业务模型、工具与辅助模型登记尝试次数，不能把登记次数等同实际发送或成功次数，也不能因终止发生在主模型前就按推测添加调用。历史事件缺少结构化不足项或具体数值时保留原原因并显示“未记录”，不读取当前 Agent 配置、预算余额或价格补算历史。

初始展开入口、主 Agent、失败、运行中和定位路径，手动折叠优先于后续页和刷新；正文不随折叠偏好持久化。搜索步骤在服务端覆盖当前快照的全部节点，匹配名称、工具、可见摘要和错误信息，最多接受 256 个 Unicode 码点，命中后返回必要祖先链，不只过滤浏览器已加载页。宽窗口采用树与详情分栏，窄窗口改为纵向布局，保留键盘展开、选择与焦点定位。

“查看轨迹 JSON”显示当前授权的结构化投影及内容引用，并标记快照、节点覆盖和加载范围，不表示已内嵌全部原文或提供 ATIF 兼容导出。已保存的系统提示词、上下文消息、供应商返回的 `reasoning_content`、模型输出和工具交换可由相应原始内容入口按需读取；正文完整显示已保存且当前可读的结构，不受节点摘要长度限制，也不按 LLM 类型统一限制读取。公开回复缺少精确 Step 身份时保留在轮次范围，不能据文字顺序补造关联。刷新失败保留已有内容；切换账号、机构、会话或根输入时取消旧请求并清除不再适用的正文。

### 2.2 公开消息与回答状态

消息列表合并宿主已提交消息与 Runtime 公开回答，以稳定 `message_id` 去重，Runtime 投影覆盖同身份宿主消息。两端复用 [RuntimeCompletedAnswerReader](../../backend-java/skillforge-core-chat/src/main/java/com/skillforge/core/chat/integration/publicread/RuntimeCompletedAnswerReader.java) 和当前公开内容检查；Runtime 最终正文的唯一事实源是已提交 `run.completed` 的 `report.output`。完整模型结果及本地引用门禁通过前不展示最终正文；完成事件没有非空 output 时不生成 final 消息，状态终结本身不补造正文。消息保留 `phase`、`state` 和十进制字符串 `message_version`。

`message_count` 表示合并后的可见消息条数，不复用宿主按输入递增的计数；`root_input_count` 保留问答轮次数。回答状态按当前根输入的同一公开投影判断，列表状态筛选和总数必须在分页前应用该语义。消息续页同时冻结宿主消息 ID 上界与 Runtime 会话序号上界，并使用包含来源及稳定消息身份的顺序，防止跨来源 ID 相撞、续页混入新消息或重复完成消息。

### 2.3 平台管理员单次模型调用诊断

`GET /platform/sessions/model-attempt/detail` 是独立的管理员扩展诊断资源，必填 `tenant_id`、`session_id`、`attempt_id`，可选 `root_input_id`。调用方必须是当前已认证且拥有 `foundation.sessions.diagnostic_read` 的平台主体；服务按真实外调 attempt、来源事实和 Runtime 冻结身份核对机构、会话、根输入、Run、Action 及准备包归属，不能仅凭轨迹节点 ID 或时间相邻放行。该权限只约束此扩展诊断资源，不作为两个后台读取已保存原始请求、响应及工具详情的附加条件。

页面仅在当前独立诊断动作有效且该 attempt 的 `diagnostic_available=true` 时显示扩展诊断入口；权限撤销会关闭扩展诊断并取消旧请求，原始记录入口仍按当前会话与来源授权判断。用量已记录不表示正文材料也已持久化，缺少扩展诊断材料时保留 `diagnostic_available=false`，不影响已保存的独立请求／响应引用。节点及各 attempt 的输入、结果分别按实际可用性展示：`NOT_RECORDED` 表示未记录，`REDACTED` 表示当前授权或来源限制，不能按 LLM 类型统一替换为受限。新发生的固定辅助模型调用按其真实原始结构保存请求和响应；历史缺失材料不根据 Token、公开回复或当前配置补造。服务端每次读取仍执行完整权限与来源核对。

从父轨迹使用扩展诊断查看独立子 Session 的模型调用时，同时提供 `parent_session_id` 与 `parent_root_input_id`，并提供子调用实际的 `session_id`、`root_input_id` 和 `attempt_id`。父参数必须成对出现；服务先重验父产品会话和当前真实后代闭包，再核对该子 Session、根输入及 MODEL attempt 的准确归属，最后读取扩展诊断。父轨迹参数只定位授权核对路径，不能代替平台管理员身份、子调用事实或当前来源读权；审计保留父子关联，不记录正文。统一轨迹的原始内容引用同样绑定真实子调用归属，沿当前可读后代闭包校验，不借此签发子运行的执行权限。

每次调用的 Token 摘要保留供应商权威计量与未知语义，并按需展开输入消息、模型返回的思考内容、模型输出和能力调用。输入取该次冻结的 provider-neutral 模型请求，保留消息角色、顺序、正文、工具定义和实际已记录参数；它不是 HTTP 报文录制，不声称包含供应商最终收到的逐字节请求。模型思考仅展示已持久化的供应商返回内容，没有记录时明确显示未记录，不根据公开回答或推理 Token 数重建。模型文字输出与 Runtime 记录的模型动作分别展示，保留各自来源；工具调用时文字为空不代表没有模型决策。结束码读取该次已持久化的 `finishReasonCode`，不推测未记录的响应 ID、系统指纹或首 Token 延迟。

可调用能力定义与实际能力调用分开展示。实际调用必须通过原模型 operation、冻结决策、子项序号及 Action/attempt 身份关联，分别表达参数、结果、执行状态及其可用性；内部生成的续接 ID 不得标为供应商原始 tool call ID。输入、思考、输出或调用结果缺失、格式不可读取及尚未完成各自保留事实状态，不提供历史格式兼容解码，不触发模型、工具、重试或运行恢复。

原始持久格式由 Runtime 所属类型化读取组件解码并校验，宿主负责授权、精确持久事实查询、诊断 DTO 和审计。模型请求保留当次实际冻结的结构，响应保留当次实际保存的返回内容，不把结构化请求宣称为供应商逐字节 HTTP 报文。正文安全与缓存要求统一见 §6；切换账号、机构、会话、轮次或 attempt 时取消旧请求并清除旧正文。

### 2.4 轨迹列表与检索

两个后台均提供独立的“Agent 轨迹”列表，默认查询近 7 天、按开始时间倒序，每页支持 20／50／100 条。一行对应一个根输入的业务轨迹，显示可见输入与输出摘要、Agent、实际模型／工具、状态、步骤与调用数量、Token 和耗时；点击进入相应轨迹详情，也可由会话记录按根输入进入。

筛选支持 TraceID、SessionID、Agent、模型、工具、状态、开始时间范围、耗时上下限、输入关键词和输出关键词；平台端额外支持机构。条件取交集，TraceID／SessionID 精确匹配，关键词按普通文字匹配，不把通配符当作检索表达式。模型、工具和 TraceID 必须属于该轨迹的真实执行事实；输入与输出检索使用当前可见的会话输入和公开回答，不内联遍历按需读取的模型原始正文。筛选与授权在分页和计数前使用同一语义。

列表耗时为主执行从受理至终态的跨度，包含排队与等待，不累加并行节点耗时。未终结或缺少边界的记录明确显示可用性，不能以零值通过耗时范围筛选。运行状态、调用结果和业务目标是否完成分别表达：回答“完成”、工具受理或子 Agent 结束不能单独证明业务结果。

首版检索使用项目现有 PostgreSQL／MyBatis 查询，不引入外部搜索服务。语义搜索、加入数据集、Pipeline、ATIF 交换适配和耗时瀑布不属于本次轨迹观测交付范围。

## 3. 身份与执行关系

一次可回答的问题以 `tenant_id + session_id + root_input_id` 标识，其中 `root_input_id` 是问答归属和时间线过滤的稳定锚点，不以显示顺序、消息 id 或当前 Agent 代替。

一个根输入可以关联多个真实 `run_id`，归属通过该根输入的 Runtime 事件关联，不把 Run 的因果输入等同于根输入；每个 Run 再由实际的 `loop_id + iteration` 标识执行轮。轨迹节点保留 Run、Execution、Action、因果事件和会话序号引用，以还原调用和重试的真实关系。

操作身份与父操作、Step、attempt、入口及 Trace 关联由 Runtime 在现有业务提交边界记录为类型化、版本化的安全观测事实。投影从所属类型化读取组件解码，不能解析私有冻结协议反推执行关系。缺少明确身份时保留 Run、来源事件与序号并标记未关联，不能按相邻模型 Action 的顺序重建 Step。

采集附着于现有 ExecutionStore／SessionLog，沿用租约、幂等和恢复边界；已提交事实不会因为刷新、重建投影或缺少观测而重新执行。子轨迹必须沿已保存的委派、程序工具或 Workflow 父子 Run 关系读取，逐资源复核当前授权。分页快照冻结各来源的上界，续页按稳定节点身份合并并补充必要祖先，不混入后续新执行。

## 4. 显式作用域与双端授权

查询服务只接收授权器生成的显式作用域，不从请求中的 `tenant_id`、正文角色或前端路由推导权限。

`PLATFORM_ADMIN` 作用域不带 tenant id，允许平台管理员在资源请求中指定目标机构；每次深层查询仍必须验证目标会话和根输入属于该机构。

当前跨机构读取由 [PlatformObservationAccess](../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/access/PlatformObservationAccess.java) 先核当前平台身份与实时动作权限，再在原事务内为精确目标机构建立领域 SELECT 白名单的临时数据库窗口；线程身份仍是平台主体及空租户，不伪装为机构用户，也不依赖 `app.platform_admin` 绕过 Runtime RLS。窗口只绑定目标读取所需的数据库租户，退出时恢复连接设置并清理一级缓存，不能将范围扩展到任意 Mapper 或写操作。[ObservationReadAudit](../../backend-java/skillforge-core-foundation/src/main/java/com/skillforge/core/foundation/access/ObservationReadAudit.java) 在独立事务中记录安全读取审计，避免审计的租户绑定污染外层观测快照；审计失败仍阻止正文返回。

`TENANT` 作用域必须携带正数 tenant id；列表筛选和所有资源定位都必须通过该租户校验。当前主体还必须满足已有本人／部门等会话数据范围，签发租户作用域不等于可读全租户会话。调用方提供其他 `tenant_id` 时请求失败，不能降级为平台作用域或忽略该参数。

快照不冻结授权。每次节点续页、内容读取及子调用诊断重新核对父会话、持久父子关系和当前来源的历史读权；机构成员、Agent／团队来源等读权撤销后，受限子运行及其后代的事件、正文和计量不再进入投影。父操作可保留不披露来源身份的“内容受限”占位，不能凭缓存恢复已撤销内容。历史读取判断不签发续行或外部调用权限。

平台端跨机构诊断和机构端本租户查看是两条宿主授权路径。两端都不得把客户端隐藏字段、前端菜单状态或会话摘要当作服务端授权证明。

## 5. 五字段模型用量口径

每个外部模型 attempt 的供应商计量可包含 `prompt_tokens`、`completion_tokens`、`cached_input_tokens`、`cache_write_input_tokens` 和 `reasoning_output_tokens` 五个字段。

所有 token 数以十进制字符串传输和展示，不经 JavaScript `Number` 或浮点数转换；缺失字段为 `null`，不是零。

`UNKNOWN` 表示该 attempt 没有供应商报告的用量事实；`PARTIAL` 表示已报告但 `prompt_tokens` 或 `completion_tokens` 至少一个未知；`ZERO` 表示这两个主字段均由供应商明确报告为零；其余完整报告为 `REPORTED`。`ZERO` 计入已报告次数，不能被渲染为空值或合并到未知。

会话覆盖状态以已开始 attempt 为分母：没有 attempt 为 `NO_CALLS`；全部未知为 `UNKNOWN`；存在未知或部分报告为 `PARTIAL`；其余为 `COMPLETE`。服务端按 attempt 去重并选择有效修订，不把同一 attempt 的重复报告累计两次。

汇总只累加已有字段，因此某一字段未知时该字段汇总仍可为未知；缓存命中率只对同时报告 `prompt_tokens` 和 `cached_input_tokens` 的 attempt 计算。输入为零时不计算比例，缓存读取、缓存写入和推理输出也不折算进输入或输出主字段。缓存同时返回可用性与配对调用覆盖数；未知、供应商明确零值和不适用分别展示。供应商分帧或跨修订产生的子项大于对应总量时，该子项在有效投影中保持未知，不能展示超过 100% 的命中率。

用量报告按 attempt 和 report revision 幂等追加到既有 `nw_usage_events`，初始未知报告与外调开始事实在同一独立事务提交。供应商已返回用量后发生正文校验失败、超时或中断，保留已提交报告；快照不相加，金额视图仍只消费 measured 及其金额对账/调整。

轨迹分页只限定显示节点；执行轮和模型节点的 Token、缓存与覆盖摘要按精确关联的全部 attempt 在服务端计算。父子节点可能引用相同用量，不能把祖先汇总与子节点再次相加。无法归属的 attempt 单独标注，缺报不补零。统一轨迹快照内的摘要不随节点续页重算；独立查询的 `read_at` 各自表示读取时间，不承诺任意两个 HTTP 请求共享数据库事务。

选择具体问答时，执行树和 Token 用量页消费同一个统一轨迹详情的 `usage`，包含当前可读主运行、固定辅助用途及成员运行的真实模型 attempt。未选择根输入的会话级用量仍采用主 Agent Core MODEL 范围，界面明确标注该范围，不将其当作含辅助和成员的完整轨迹汇总。

费用摘要消费[用量与账单设计](14-用量与账单设计.md)中的有效计价、对账与追加调整事实，按事件身份去重并限制在当前可读轨迹闭包内；对账替换原有效金额，调整仅累加差额。`amount_by_currency` 的 CNY 金额以人民币分的精确十进制字符串传输，保留亚分和负调整，前端精确换算为元，不经 JavaScript `Number`。费用覆盖独立返回 `NO_COSTS／UNKNOWN／PARTIAL／COMPLETE` 及已计价、未确认和缺少金额事件的模型 attempt 数，空金额字典不代表免费或已知零。页面的“已确认费用”是该有效成本投影，不表示供应商实际扣款、机构应收或支付完成。

## 6. 只读与内容安全

所有观测资源不创建、恢复、取消或重试会话与执行，也不修改用量账本；读取消息正文或轨迹内容的安全审计另行记录，不能据此变更业务事实。

消息和轨迹内容必须先验证 `tenant_id`、`session_id`、`root_input_id` 与内容引用的从属关系；引用签名绑定当前主体、授权作用域和完整资源身份，每次读取重新核验当前会话及来源读权。`NOT_RECORDED` 表示实际未保存的材料；`REDACTED` 表示当前对象、知识源或其他来源授权限制。两者分别返回真实可用性，不能由页面、导出、错误信息或模型补齐正文，也不能仅因为记录属于 LLM 而标为受限。

管理观测原始内容包含当前授权范围内已保存的模型输入、系统提示词、准备指令、上下文消息、供应商返回内容及工具入参和结果，不另以“私有模型材料”为由限制读取。连接凭据、认证头、连接串、签名密钥、执行票据、checkpoint 和其他可执行授权材料不随正文返回。普通聊天消息仍使用其公开回答投影；原始内容通过独立引用按需读取，不混入消息或节点摘要。

记忆及知识检索原文还需通过当前来源授权与遗忘状态核验，不能用历史快照或会话读权恢复已遗忘、已撤权的事实。内置记忆 TOOL 的真实冻结绑定同时满足 `PLATFORM` 与 `providerRef=toolName=search_memory`，且历史材料无法完成当前事实来源核验时，使用已有安全元数据投影：保留成功／失败状态、有限枚举的检索模式与状态及原快照事实数组计数，标记为历史元数据与 `availability=PARTIAL`，不返回未经核验的事实正文或来源标识。工具输入和其他已保存内容按各自受控引用读取，不因工具名称一概隐藏原文；MCP 同名工具不套用内置绑定规则。读取不重搜、不调用模型，也不新增当前事实读取能力来补齐历史。

原始内容与扩展诊断读取均记录操作者、准确目标及各区块可用性的安全审计，不记录正文；审计失败阻止正文返回。响应使用 `Cache-Control: no-store`，前端只保存在当前页面内存，不写入本地偏好或持久缓存；关闭正文或切换主体、机构、会话、根输入及 attempt 时取消请求并清除旧材料。

## 7. 发布前置条件

观测查询依赖五字段用量和可验证的 Runtime 关联事实。发布前核验 Runtime 持久对象满足当前五字段与冻结格式契约。旧双字段 usage/旧 checkpoint 由严格 codec 拒绝，不自动转换、不推测回填或删除。存在这类状态时，应在发布窗口单独处理数据与运行状态，并以当前契约验证后再启用新 Runtime；本次本地实现不执行存量数据库操作。

迁移窗口结束后旧格式不得继续写入；查询和恢复路径不得保留双读、双写、旧 DTO 转换或按猜测兼容旧身份的分支。迁移的实施顺序、恢复和数据验收由 [Harness 03：核心对象模型与状态机](../../harness-design/03-核心对象模型与状态机.md) 及其关联实施方案定义。

## 8. 实施状态

本设计表达批准目标，不声明数据库迁移、双端页面或模块验证已经完成。当前实现与验证以所属源码、测试及对应候选的原始运行结果为准；设计和源码入口不证明统一轨迹改造已验收。

真实供应商、双端 HTTP 和可选真实浏览器验收使用[本地轨迹验收入口](../04-指南与运维/01-开发与部署指南.md#双端轨迹真实供应商与浏览器验收)。该入口在独立 PostgreSQL／Redis 中运行当前初始化链，仅从来源环境只读取得精确当前模型连接；实际模型发送、管理读取、浏览器交互与清理结果分别留证。只有对应运行的退出结果及完整安全证据能够证明该范围通过，入口存在、编译或健康检查不代表真实验收成功，也不证明现有环境已部署或升级。

采集覆盖以实际提交的观测事实为准；挂起恢复缺少入口或技术 Trace 关联时明确保留缺口，不能按目标层级补造完整链路。压缩或摘要代码只有被当前主执行链真实调用并留下事实时才属于该次轨迹，存在配置、类或接口本身不证明已执行。
