### 2.1 宿主数据库模型与字段契约统一

[数据库模型与字段规范](../../.agents/skills/nw-database/references/database-modeling-standards.md)已定义目标，存量代码和 schema 尚未完成跨模块统一。实施需按具体模块同步宿主 ID 的字符串接口、Unicode 码点长度校验、管理资源的可信操作者字段、固定配置的列与关系表建模，以及部分更新的字段存在性，并验证对应数据库约束及直接消费者；规范发布不代表上述改造已完成。

存量 JSON 字段按[必要性要求](../../.agents/skills/nw-database/references/database-modeling-standards.md#46-固定配置动态-json-与原始材料)逐模块评估。已知对象包括 [V263](../../backend-java/skillforge-migration/src/main/resources/db/migration/V263__stable_agent_publications.sql) 的 `nw_agent_publications.snapshot`，以及 [V266](../../backend-java/skillforge-migration/src/main/resources/db/migration/V266__platform_current_publications.sql) 的 `nw_platform_models.draft`、`nw_agent_template_publications.snapshot`、`nw_platform_agent_tool_deployments.draft`；该列表是待评估入口，并非完整清单或 JSON 豁免。固定内容按列、版本表及子表建模，必要的开放文档补齐例外依据；实施时同时保持发布原子性、精确版本恢复及不可变正文引用，避免拆表后重复存储。

可核实的接口差异包括 [UpdateAgentRequest](../../backend-java/skillforge-core-agent/src/main/java/com/skillforge/core/agent/dto/request/UpdateAgentRequest.java) 中空字符串清除模型选择、空对象重置预算的约定，目标行为以[部分更新规范](../../.agents/skills/nw-database/references/database-modeling-standards.md#6-部分更新的字段语义)为准。源驱动的逐控件规格描述当前实现，不构成保留这些行为的领域例外；对应模块完成代码、OpenAPI、客户端与验收后同步更新其事实源及本索引。

### 2.2 工程通用契约实施差异

[工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md)已确定严格输入、查询分页、授权、配置、外部调用、关键路径日志及前端状态的目标；[自动检查规范](../../.agents/skills/nw-verification/references/candidate-driven-delivery.md#自动检查与规则落地)区分已有检查和后续工作。规范文档验收不代表业务代码、OpenAPI 或自动检查已完成改造。

| 已核实入口 | 差异与后续实施边界 |
|---|---|
| [PlatformTenantAccountService](../../backend-java/skillforge-platform-service/src/main/java/com/skillforge/platform/service/PlatformTenantAccountService.java) | 列表将 `limit` 自动夹紧到合法范围；按严格输入规范改为缺失使用默认、显式越界拒绝，并同步 Controller、客户端和错误契约 |
| [BillingController](../../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/controller/BillingController.java)及 [BillingRecordQuery](../../backend-java/skillforge-core-billing/src/main/java/com/skillforge/core/billing/dto/billing/BillingRecordQuery.java) | 查询中存在 `pageSize` 命名及分页容错；按实际绑定方式统一普通列表的 `page_size`、响应和 OpenAPI，不能只修改 Java 属性或依赖 JSON 命名策略处理查询参数 |

该表是具体实施入口，不是全库违规清单。未知字段拒绝、配置生效、重试策略、关键路径日志和前端竞态按实际模块逐项核验，不凭规范发布推定它们已合规或已存在缺陷；新增机械检查需有可验证样例，未实现检查不作为现行门禁。改造同步直接消费者并完成对应边界验证后，更新本索引；已有明确领域例外继续归所属契约。

### 2.3 宿主代码组织与类型容器

[Java 代码组织与类型容器规范](../../.agents/skills/nw-engineering/references/java-organization-standards.md)已定义业务能力目录、服务职责和按契约边界聚合的类型规则；其 Agent 示例是目标结构，存量源码尚未按该结构完成迁移。

| 已核实入口 | 差异与后续实施边界 |
|---|---|
| Agent 的 [请求](../../backend-java/skillforge-core-agent/src/main/java/com/skillforge/core/agent/dto/request)、[响应](../../backend-java/skillforge-core-agent/src/main/java/com/skillforge/core/agent/dto/response)与 [SystemAgentTypes](../../backend-java/skillforge-core-agent/src/main/java/com/skillforge/core/agent/systemagent/SystemAgentTypes.java) | 独立 DTO 与 Types 容器并存；后续按资源和消费边界确定 HTTP、应用与内部执行类型的归属。SystemAgentTypes 同时含公开视图与 FrozenRun，不能仅统一容器后缀就视为完成 |
| Agent 的 [model 包](../../backend-java/skillforge-core-agent/src/main/java/com/skillforge/core/agent/model) | DO、AgentTemplateDefinition/AgentDelegationConfig 与 JsonbTypeHandler 共用目录；按领域语义与持久化职责分开，具体存储变化仍归 §2.1，不因移动 Java 类型保留或取消 JSON 使用契约 |
| [AgentService](../../backend-java/skillforge-core-agent/src/main/java/com/skillforge/core/agent/AgentService.java) | 继承 ServiceImpl/IService 提供通用 CRUD，同时执行可编辑性检查和草稿变更规则；后续以明确应用入口承载业务约束，数据库访问封装在所属能力内部，不继续跨模块公开任意 CRUD |

这些入口只证明所列结构差异，不构成全库违规统计。实际重组按明确模块同步扫描、XML 类型引用、序列化、校验、OpenAPI 和直接消费者，完成[对应验收](../../.agents/skills/nw-engineering/references/java-organization-standards.md#6-后续改造与验收)后更新索引；当前规范交付不包含代码搬迁、Gradle 模块拆分、接口行为或数据库改造。
