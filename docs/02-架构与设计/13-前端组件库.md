# 前端组件库

> 本文定义两个后台的公共组件与独立会话端边界，架构见[前端共享层设计](08-前端共享层设计.md)。

## 1. 组件分层

| 层 | 责任 | 使用范围 |
| --- | --- | --- |
| Vue、Vue Router、Pinia | 渲染、单页路由、身份状态 | 各应用自行装配 |
| Element Plus | 通用控件、表单、浮层与反馈 | 机构端与平台端直接依赖 |
| 后台公共资源 | 布局、页面、离开保护、请求状态 | 机构端与平台端 |
| 后台专业组件 | 代码与文件包编辑、Markdown、账单明细、智能体基础字段 | 机构端与平台端 |
| 会话端本地实现 | 消息、流观察、历史恢复、附件、确认、团队与成果 | 独立会话端 |

## 2. 选型与使用规则

后台使用单页路由与面包屑；导航保留原生链接，不建设应用内多标签缓存体系。普通表单直接组合 Element Plus 字段，公共层不提供 schema 表单解释器、Vben 兼容函数或第二套基础控件库。

只有两个后台确有相同职责的组件才进入公共资源。领域页面拥有接口绑定、权限、版本和事务结果处理；共享组件不推断业务成功。

已有基础组件直接使用：面包屑用 `ElBreadcrumb`，文件选择导航用 `ElMenu`，上传和文件导入用 `ElUpload`，折叠用 `ElCollapse`，详情字段用 `ElDescriptions`，统计用 `ElStatistic`。不使用 `label.el-button` 或原生控件加同名样式模拟组件。工作流画布、代码编辑器、Markdown 和聊天领域布局保留专业实现。

## 3. 表单、反馈与浮层契约

`AdminPage` 组合标题、说明、操作区与默认内容；抽屉与对话框直接使用 Element Plus。公共 `useDrawerClose` 提供关闭保护，开关和表单值由页面管理。关闭、Esc 与路由离开统一执行未保存检查，提交中拒绝关闭和重复确认。

`useTask` 管理单个写操作的 busy/error，卸载后的结果不交给页面。`useResource` 管理读取、取消和请求序号；后发读取拥有更新权。身份变化仍由宿主清空业务状态并废弃旧请求。

表单保持后端字段类型与精度，校验失败保留输入。保存成功后的刷新失败必须与写入失败分开；未知结果不能自动重发。

表单忙碌状态通过 `ElForm :disabled` 传递，不能用原生 `fieldset` 代替 Element Plus 的禁用上下文。`ElUpload` 只负责选择和展示文件，实际请求继续使用业务认证客户端；文件导入保留覆盖确认和修订约束。两个后台加载官方暗色变量，公共布局颜色引用 Element Plus 主题变量。

## 4. 列表与数据展示契约

页面直接使用 `ElTable`、`ElTableColumn` 与 `ElPagination`，在模板中明确字段、单元格、操作、分页事件与状态。是否分页、排序或批量操作由真实接口决定，不创建通用表格配置解释器。

列表提供空态、加载、错误、重试和对象详情入口。状态提供文本，金额按精确字符串展示，时间与空值遵守所属业务契约。

## 5. 领域组件语义

`CodeEditor` 使用 `modelValue`、`language`、`readonly`、`height`；`PackageFileWorkbench` 使用 `files: Record<string,string>` 与 `readonly`，通过 `update:files` 更新文件集合。文件路径为包内相对路径，禁止空段、上级目录和绝对路径。

`MarkdownContent` 接受 `content` 并清理不可信 HTML；`BillingInvoiceDetails` 接受公开 `Invoice`；`AgentConfigFields` 组合名称、说明、模型与系统提示，预算、挂载和发布规则归业务页面。

## 6. 共享层与宿主边界

会话端不使用本文后台公共组件或任何共享层源码、样式、类型、测试和构建入口。接口与事件的语义由服务端公开契约保证，两类应用分别验证身份、权限、取消和恢复。

视觉及交互要求见[前端视觉与交互规范](09-前端视觉与交互规范.md)与[后台系统交互规范](../03-规范与术语/05-后台系统交互规范.md)。
