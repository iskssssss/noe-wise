# BrowserSkill 远程浏览器接入

本文定义已批准的宿主接入设计。源码提供独立 `skillforge-browser-service`、个人设备接口和浏览器任务面板；构建与局部测试不证明官方扩展、WSS 和真实个人浏览器已验收。Runtime 的图片内容、媒体引用、模型编码与恢复语义归[多模态内容与媒体引用](../../harness-design/03-多模态内容与媒体引用.md)，本专题只定义浏览器宿主接入。

## 1. 范围与固定版本

接入腾讯 BrowserSkill，固定上游提交 `3f10983c09fcd443c7420830ab984c9d409954bf`。用户在自己的电脑安装 Chrome 或 Edge 扩展，通过远程 WSS 连接个人设备。灵知适配扩展以该提交的最小补丁提供可信站点配对交接，沿用官方执行、设备授权、续期与撤销协议；适配包独立命名并标记上游和适配版本。原版官方扩展仍可手动粘贴配对串。个人浏览器不由服务端 Chromium 替代。

首版提供该版本上游支持的全部远程工具，包括页面操作、脚本执行、录制、debug、请求改写、mock 和重放。官方工具的名称、参数与远程可用性以固定提交为准，适配发布时逐项保留其语义，不将脚本或调试工具裁成另一套执行能力。远程文件上传和下载不支持，不对外声明这些动作可用。平台截图接入通用图片材料，不表示提供视频流。

## 2. 模块与执行路径

机构宿主通过现有 Tool 挂载、版本冻结、PolicyChain 和 ExternalInvocationGuard 调用 PLATFORM handlers，handlers 访问独立 `skillforge-browser-service`。该服务以固定 `bsk` 可执行入口和参数数组调用上游 CLI，并维护常驻 daemon；不拼接 shell 命令，不通过代码沙箱或 MCP 绕行。

Browser service 负责设备连接、上游任务生命周期、CLI 调用、持久回执和截图文件接收。机构宿主负责认证身份、用户归属、工具授权、Session/Run/调用关联、公开投影和媒体持久化。Runtime 沿用通用 Tool 行动与调用账本，不新增浏览器专属 Core Action、Session 状态或执行引擎。

## 3. 个人设备与连接

设备及任务归属由现有认证上下文解析的 `tenant_id + end_user_id` 决定，不能由模型参数或请求正文改写。每个归属使用独立 `BSK_HOME` 和 daemon，任务引用只能解析当前归属下的设备与绑定。设备断开、重新配对和服务重启不改变原任务所属用户。用户可修改显示名并明确选择默认设备；选择入口接受个人 `device_id`，实际 `browser_id` 由服务端从授权设备解析。未选择时不自动挑选首个在线设备。每个个人最多保留五个活动任务，同一任务的不同调用串行执行。

配对入口和扩展 WSS 通过外部访问入口提供，CLI 命令及执行服务内部接口仅供宿主访问。第一版保留现有登录、个人归属和工具挂载授权，不引入新增审批或逐调用二次确认；已挂载工具的执行能力不由 Skill 正文授予。

连接在线不代表设备仍被授权。新任务、启动恢复及非清理操作在实际派发前，通过所属用户的官方 daemon 设备接口复核当前有效 `browser_id`；撤销已完成后，新调用返回 `failed / browser_not_authorized`。授权查询失败保留 `unknown` 且不派发，查询和后续操作共用原调用截止时间。已完成回执的幂等读取不产生新副作用，停止任务、取消和停止录制继续允许清理。此边界不将撤销与已经在途的浏览器操作宣称为原子中断；原调用结果和清理回执仍各自保留。

官方设备目录包含已过期的持久授权，派发前同时校验公开 `expires_at`；过期拒绝执行，无法解析的到期时间按授权未知处理。机构端配对和撤销先独立提交既有审计账本中的 `started`，再派发一次控制调用，结果记录 `succeeded` 或 `unknown`；操作者来自成员或渠道认证，服务器生成的 `request_id` 关联 Browser service 控制记录。审计意图持久化失败时不派发，结果未知不自动重试。

Browser service 在个人持久目录保存脱敏授权观察和控制记录；扩展配对/续期代理仅记录动作、HTTP结果与设备摘要，不保存配对链接、令牌、正文或设备显示名。设备集合差量仅证明两次观察之间发生变化，不将相邻调用推定为删除者。配对响应路径不等待 CLI 设备观察或其他控制调用；官方成功响应仍须交还扩展保存凭据，结果审计写入失败保留原 `started` 并告警。绕过服务执行的官方 CLI 或外部文件改写不具有宿主操作者审计，须结合部署访问控制与系统证据归因。

## 4. 任务绑定与调用恢复

使用上游 tracked-start 的 prepare/start、持久绑定和 claim 流程。宿主先持久化稳定准备身份及任务归属，再提交上游启动；获得的上游任务身份与绑定凭据持久记录，恢复优先 claim 已绑定任务，不在内存中保存唯一绑定事实。

每项任务调用使用与原 Runtime 调用关联的稳定标识，并保存请求摘要、提交事实及可回读结果回执。同键同体重试读取已有事实，同键异体拒绝；已结束调用返回原结果。服务重启、网络断开或返回丢失时，先查询持久回执和上游任务事实，不能把超时直接解释为未执行。

`browser_call` 沿用 [Runtime 平台命令的参数化调用身份](../../harness-design/03-核心对象模型与状态机.md)：同一任务上已确定结束的导航、点击和截图可以分别形成独立 Action，保留非幂等写分类与串行执行。同参写操作复用原结果；已核证纯观察在新的模型 operation 下读取当前状态，原目标存在未决调用时不以不同命令绕过，不把重连当作重放权限。

无法确认上游结果时记录 unknown，并在工具结果和任务面板表达结果未知。unknown 不自动重放有副作用的脚本、页面操作、录制控制、请求改写或重放；查询和恢复只收敛已有提交，不自行授权新的副作用。浏览器任务状态属于宿主与上游，不替代 Runtime Run 的成功、失败或恢复状态。上游明确拒绝或脚本返回 `ok:false` 形成 failed 回执和工具错误；超时、协议中断及不能证明执行情况的返回保留 unknown。

启动调用未指定 `browser_id` 且本人没有默认浏览器，或显式选择为空、无效选项时，在派发前形成 `rejected / browser_selection_required` 持久回执，提示用户配对并选择默认设备；不创建任务、准备令牌或浏览器绑定，也不将该前置条件拒绝转为 HTTP 500 或 unknown。后来设置默认设备不改变原调用的拒绝结果；新的启动意图使用新的调用标识。

任务引用无效、任务不存在或非活动，以及封闭命令参数不满足契约时，在页面操作下发前返回结构化 `rejected` 回执。机构工具将确定拒绝作为可纠正的工具错误交给模型；非预期服务故障、超时和已派发后结果未确认仍保留未知语义。同一调用的异体请求被拒绝且不覆盖原回执，不能用后来的拒绝改写原执行事实。

固定版本 daemon 的会话注册表保存在内存中；持久卷中的任务 `active` 不能证明服务重启或扩展重连后原绑定仍有效。新页面命令在原截止时间内以一次有界会话列表核对冻结的 `session_id + browser_instance_id + agent_window_id`。明确失效则保存本次 `rejected / browser_task_binding_lost`，任务变为 `inactive`，但不宣称旧窗口已清理；查询失败保留未知，不自动重绑或重放。新任务的五个活动槽限额仅排除已确定失效的绑定，未知及未完成启动仍占用槽位。

内部 `/task-states` 和模型 `browser_tasks` 从任务快照及当前会话列表投影可用状态，查询不改写任务或原调用回执。任务目录保留真实 task、来源会话、绑定与稳定错误，不混入无任务的参数拒绝或页面正文。原 `/tasks` 调用回执及完整工具来源保留原执行事实；任务失效不将原已完成或结果未知的调用改判。

宿主把调用 `deadlineAt` 传入执行服务，各步骤和录制后台等待使用剩余预算；异步提交不延长 Run 上限。录制未知或到期时按已保存的个人录制绑定与输出目录停止并保留未知结果，清理是否完成单独呈现。

用户主动取消使用 `/api/v1/chat/browser/cancel`，提供身份选择器和原 `invocation`。先持久化取消意图，再取消原准备令牌、停止原窗口或原录制并中断该目标的 CLI 进程。取消回执以原调用标识加 `:cancel` 保存；只有精确清理完成才显示 cancelled，失败显示 cleanup_failed 或 unknown，重试只清理原目标。取消不回滚已发生的页面副作用。

预算收尾仍须能够结束已启动的准确任务。机构宿主依据本轮可信的 `browser_stop` 挂载，预留停止工具、后续答复、停止回执输入和冻结超时，并把准确目标加入收尾工具集合；没有该挂载的 Run 不增加此项预留。停止使用实际返回的 task，沿用原归属、授权、调用账本和未知不重放规则，不授权新建或继续页面业务。模型可见停止结果采用有界事实投影，完整原回执仍先持久保存；未确认停止时不得宣称浏览操作已结束。终态不自动清理所有个人浏览器任务，人工取消后的成功清理也不改写原答复事实。

中断已派发的业务命令使用固定上游支持的父进程取消管道：启用 `BSK_CANCEL_ON_STDIN_CLOSE`，关闭准确归属 CLI 的 stdin，让 CLI 发送对应 RPC 的取消，再有界等待。直接强杀 CLI 不能证明浏览器中的命令已取消；超过取消等待上限的强制终止保留未知结果，不能据进程退出宣称任务清理成功。

## 5. 工具与 Skill 发布

固定版本的 `bsk record start` 自行创建录制窗口，不接受已绑定的 `--session` 或 tracked-start 参数。接入保留官方流程，录制作为归属原个人任务的独立持久调用异步执行，返回调用句柄与 submitted 状态；停止录制按该个人任务保存的唯一录制绑定和输出目录调用 `record stop`。unknown 不重新启动录制，也不以 daemon-wide stop 取消；普通任务的 tracked-start 绑定不伪装成录制窗口的绑定。

录制绑定同时保存准确的启动与停止回执关联。固定上游的两端可能在已导出同一 trace 后竞争清理窗口；单独的 trace、`window_closed` 字段或会话目录缺席均不能证明清理成功。仅当明确识别该清理竞争，且同一次录制另一端以正常退出证明清理成功、输出目录和 trace 完全一致时，收敛相应待确认回执并保存确认来源；不得将这一规则推广到其他超时、断连或未知错误。

官方远程工具按现有 PLATFORM Handler 名登记并发布版本，机构 Agent 通过原能力挂载使用。平台发布适配 Skill，正文说明远程工具、任务用法、截图消费和文件传输限制；适配 Skill 通过数据库版本发布和精确挂载，不在 `skillforge-prompts` 保存业务说明，也不由启动初始化替换线上版本。

`tools/browser/publish_browser_skill.py` 从无本地修改的固定上游 Skill 目录生成适配包，并可通过平台现有草稿、校验、发布 API 发布数据库版本。离线生成不等于发布；生产正文不复制到仓库提示词目录，也不由启动初始化写入。

公共 Skill 的维护与发布复用[技能维护台](15-技能维护台设计.md)，工具与 Skill 版本分别冻结。Skill 的 `allowed-tools` 说明依赖，不创建执行权；实际工具授权由挂载和调用政策决定。工具业务说明与官方参数语义集中维护，不能另建只覆盖页面点击的隐藏子集。

### 5.1 工具契约一致性与专业内容边界

本项目发布的工具结构必须在可读能力目录、原生模型工具定义、调用前本地校验、Handler 和拒绝反馈中表达相同的关键约束。`browser_call.command` 和 `command.parameters` 都是 JSON 对象；无参数操作使用真正的 `{}`，不能使用字符串占位符或字符串化 JSON。导航字段放在 `command.parameters` 内，操作判别字段声明明确的字符串类型；任务只使用实际返回的完整 UUID，归属和有效状态继续由宿主验证。

`browser_start` 省略 `browser` 时，由宿主按当前个人设备默认配置选择；显式设备值按本人真实设备标识校验，空字符串、字符串化的空对象和浏览器产品名不表示默认选择。本地参数校验拒绝同样需要提供准确的修正信息：通用诊断仅在原参数副本删除对应字段后仍能通过原冻结 schema 时，才提示模型可以省略该字段。该判断不修改实际参数或设备选择，不把非法显式值转换成默认设备，也不由 Runtime 解释浏览器业务。

启动 Schema 用互斥 `oneOf` 明确表达封闭空对象的默认选择分支，以及必填非空字符串 `browser` 的显式选择分支；根对象不另加会遮蔽分支字段的封闭约束。两种选择的允许参数范围不变，非空字符串仍须经过宿主本人设备校验；Schema 接受一个字符串不证明该设备真实存在或已获授权。

浏览器操作的封闭联合保留 `oneOf` 分支、`required`、字段类型、操作判别值和 `additionalProperties=false`。可读目录和本地校验不能把这类已声明支持的结构静默投影为无约束 `{}`。本地 `oneOf` 要求恰好一个分支匹配，`anyOf` 要求至少一个；同级类型及字段约束同时生效。选择联合中的失效、循环或超深引用明确拒绝；`allOf` 只允许没有其他结构约束的单分支展开，同节点联合与 `allOf`、联合内多分支交集均不支持。引用目标与兄弟节点的同名已支持约束不一致时明确拒绝，相同约束可以合并；不通过覆盖模拟尚未实现的交集，也不表示实现完整 JSON Schema 标准。合法的显式空 schema 仍保留其原语义。拒绝诊断只包含受限字段路径与固定关键字，不回显地址、脚本、凭据或候选参数值。已拒绝调用没有派发浏览器操作，模型可按准确结构纠正；未知结果不因参数纠正或重连变为可重放。

专业 Skill 的可移植性与特定运行环境的适配分别维护。上游包保留来源、版本和专业正文；本平台的入口、参数、能力限制与运行事实由宿主的版本化工具 descriptor、冻结 ToolBinding 及模型准备路径提供。目标接管入口是机构宿主的 `AgentRuntimePublishedCapabilities` 与通用 `SessionPreparationMaterializer`，由它们按准确挂载版本交付工具能力事实；权限、身份及调用转换仍由宿主代码承担，不能靠专业正文授予或让模型猜测 CLI 映射。

原生函数使用可读安全前缀与稳定摘要，函数描述以 `logical_name`、`qualified_name` 和可用标题保留同一冻结目录的发现信息，以便模型准确对应工具间的引用；这些名称不是函数别名，执行仍通过原冻结映射。浏览器工具自身说明完整生命周期：尚无任务时先用 `browser_start`，无参数调用为 `{}`；后续操作和停止使用实际返回的完整 task，缺少已有任务时查询 `browser_tasks` 或回读来源。连接等待中不另行启动；停止参数错误不提示新建任务，确定拒绝与未知副作用分别处理。该说明随工具版本发布、计量和冻结，不依赖用户提供 task 或设备标识。

当前 `publish_browser_skill.py` 仍在适配包内生成 PLATFORM 依赖声明与 transport 说明，属于过渡实现。在上述平台消费路径完整接管并经过外部包与资源执行验收前，保留这份可运行说明，不宣称 Skill 可移植性治理已经完成。成果要求来源与内置 Skill 清理是独立工作线，不是验证浏览器只读操作和模型图片消费的前置条件。

离线适配包不声明调用方的平台 Tool 版本；准确版本由当前挂载、Deployment 和冻结 ToolBinding 提供。生成器更新只影响后续新包，旧已发布包与旧冻结请求保持原内容。

生成的参数 Schema 保留固定上游字段说明，身份选择器不能只暴露基本类型而丢失语义。`tab_id` 是浏览器返回的真实标签页 ID，不是从 1 开始的序号；省略可选 `tab_id` 时使用当前 Agent Window 的活动标签页。需要指定目标时先通过观察或标签页列表获取准确 ID，宿主不猜测或自动替换模型传入的错误 ID。

浏览器工具的模型文字摘要优先保留真实 `task`、操作状态及目标标签页；完整公开回执保持可回读。`task` 与绑定中的上游 `session_id` 是不同身份，缺少任务引用时查询本人任务或回读完整来源，不从摘要中的其他标识拼接任务。通用执行历史只按已验证的文字内容形成有界预览，不解析浏览器专用业务字段。

`click` 与 `press` 在原调用截止时间内附加绑定 Agent 窗口的前后标签页观察，返回源页面、新增页和活动页等事实；新增页仅是导航候选，列表差量不证明因果或授权。模型结合用户目标选择真实标签页，切换后重新读取页面及元素引用；不默认选择最后一页，不将点击成功当作已进入目标页。额外观察失败单独表达，不推翻已确认的点击结果、不重新点击；未获控制范围的页面继续遵循官方借用与授权流程。

页面交互先消费当前 `observe` 或 `snapshot` 返回的结构与引用；导航、切换标签页和页面变化后重新观察，不凭站点的历史选择器推定当前元素。输入、点击失败时先区分元素状态与控制范围，不能用 `evaluate` 绕过可见性或借用授权。脚本返回成功只证明该脚本调用完成，搜索、提交及导航仍需从实际页面结果确认；需要正文时优先使用观察结构，源码确有必要时按范围读取 `get-html`，不为提取少量结果把整页 HTML 当作默认输入。

固定上游 `observe` 中的 `[→ 域名]` 只是链接域名提示，不能作为完整 URL。平台工具定义和观察结果旁的能力提示说明该边界；用户要求链接时，在停止任务前用当前实际 ref 的 `get-html` 读取 href，或在原控制范围内通过仅作读取的 `evaluate` 提取准确标题与 href。`get-html` 支持 `tab_id/ref/max_bytes`，不接收 selector；裁剪或截断结果不能当作完整链接，不能从标题或域名猜造路径、查询串及省略号占位。读到重定向 href 时可以原样交付，未经跳转核验不能声称已确认最终目标。该说明不把 `evaluate` 变为只读工具，也不新增成果发布硬门禁。

同一已观察页面需要多个目标的链接或字段时，平台适配说明优先引导一次仅作读取的 `evaluate` 返回这些目标的标题、完整 href 及所需字段，减少逐条源码读取的模型往返；准确 `tab_id` 和目标仍来自当前页面观察，不按网站或固定选择器猜测。单目标定位、源码或 HTML 核验继续使用 `get-html`。这是对读取方式的指导，不改变 evaluate 的实际副作用分类、授权或预算，不允许借求值绕过权限及可见性边界。

浏览器宿主从原冻结 PLATFORM `browser_call` 绑定和完整合法参数核证当前读取资格：静态 `observe`、`snapshot`、`get-html`、`tab-list`，以及无 ref、未开启全页模式的根视口截图。开启 hover 探测、滚动全页或 ref 定位截图、脚本执行及页面交互不进入该资格。依照 [Harness 的当前读取契约](../../harness-design/03-核心对象模型与状态机.md)，新的模型 operation 必须获取当前观察，不用点击前的同参旧结果代替点击后的页面；原 operation 恢复、写操作重复保护及 UNKNOWN 收敛保持不变。目录分类只消费原冻结材料，不查询新目录、不授予浏览器控制权。

页面交互错误回执保留固定上游公开原因码及副作用、清理状态，已确认失败的模型摘要同步呈现；自由文本错误、任意 `data` 和子进程 stderr 不进入公开回执。`permission_denied` 可以表示元素不可见或窗口范围限制，不能仅凭一级错误码要求重新配对。上游明确 `effect_state=unknown`、结果未知原因或普通超时与协议故障时，调用保持 `unknown`，宿主继续通过异常保留 Runtime 的未知 Action 边界，诊断保存在原 invocation 的宿主回执中；`browser_tasks` 表示当前任务绑定状态，不能替代原操作结果。后续连接、观察或成功调用不改写原事实，也不自动重放动作。旧回执缺失的细节不能追补为已知原因。

## 6. 截图与用户界面

截图经机构宿主持久化为有摘要和来源关联的图片材料，关联原任务及调用回执；工具观察通过[通用媒体引用](../../harness-design/03-多模态内容与媒体引用.md)进入模型输入。截图可在用户端展示，也可由支持图片的模型读取；只返回图片路径、下载链接或 Base64 文本不构成模型图片输入闭环。

用户端提供个人设备管理与浏览器任务面板。设备管理展示配对、连接与当前归属，任务面板展示任务绑定、真实调用进度、结果、截图及 unknown。公开投影不暴露 `BSK_HOME`、内部命令端点或配对凭据。实时与历史从相同持久事实投影，截图按图片展示，不虚构视频或持续直播。任务读取及取消同时复核产品会话与委派来源当前可读权限，个人身份匹配不替代来源授权。查询刷新仅使用 GET，不重复提交原动作。

## 7. 首版部署与交付边界

首版为单实例 Browser service，使用持久卷保存各用户的 `BSK_HOME`、上游绑定与执行回执；daemon 可随所属用户实例重新启动，原临时会话仍按当前绑定事实核验。首版不设计多实例路由、共享 daemon 或分布式租约。实际服务模块、配置、启动顺序和健康检查见[开发与部署指南](../04-指南与运维/01-开发与部署指南.md)，实际配对与真实远程执行需独立验收。

完整接入的验收覆盖个人设备配对、固定版本官方远程工具、持久绑定恢复、unknown 不重放、个人归属隔离、截图模型消费及用户端实时与历史展示。源码构建、Mock 接口或图片 UI 展示分别提供局部证据，不能代替官方扩展与远程浏览器的真实组合验证。

自有网络高级场景、Chrome/Edge 隔离 profile、官方扩展安装与人工前置条件见[本地 BrowserSkill 验收](../../tools/browser/README.md)。

## 8. 按需连接与自动续跑

按需连接与自动续跑适用于 Agent 原生 Tool input continuation。Workflow tool node 保留在线有效设备的直接 `browser_start`；没有选择、设备离线或授权需要重建而必须等待时，确定返回 `rejected / browser_connection_workflow_not_supported`，不创建连接请求或上游任务。Workflow 使用独立 Execution 等待与恢复协议，不能借用 Agent 的 `GenericToolInputPending`；本设计不宣称 Workflow 节点支持按需连接续跑。来源由 Provider 解码已持久化调用的 `WorkflowNodeOrigin` 后传入可信上下文，与程序子调用标记独立，不接受模型参数指定。

浏览器设备是当前个人身份的独立配置，跨对话共用。`browser_start` 在首次启动派发前检查有效设备：在线默认设备或显式指定的本人设备直接使用；未选择设备、已授权设备离线、授权需要重建时，使用现有交互式 PLATFORM Tool input continuation 持久等待。服务不可用、证书错误和授权查询故障不伪装成缺少配对；非法参数和非本人设备仍确定拒绝。等待不创建上游任务或准备令牌，不占用长期 HTTP 请求。

模型未指定设备时使用空参数对象 `{}`，`browser` 只在已取得本人真实 `browser_id` 时提供；空字符串、`default` 和浏览器产品名称不代表默认选择。`browser_start builtin:5` 将该语义写入字段说明并拒绝空字符串，确定参数拒绝的正文指明纠正方式；没有任务回执时不能构造 task 调用后续工具。交互式完成及拒绝回执沿用通用平台媒体 Handler 的有序 Text/Image 输出，输入等待仍走原 Tool continuation，不将等待包装成成功结果。

宿主连接请求绑定原 Session、Run、Action、invocation、发起者和当前等待身份。用户在连接卡选择本次设备，是否设为默认是独立选项；普通设备目录变化不隐式改换等待目标。恢复前复核当前等待版本、Run 状态、当前授权、工具挂载及准确设备，沿既有 Session 输入和 Tool continuation 创建新 attempt，保留原 Action 与 invocation。人工等待沿用 TOOL_INPUT 生命周期，实际外调受各自执行窗口与超时约束。

Session 的通用交互投影接纳已授权 Ledger 中宿主定义的 `elicitation/create` 请求，不限定为 MCP schema；仍排除模型采样、roots 等后台请求。具体 schema 校验和浏览器连接卡的安全字段投影由宿主负责，Runtime Core 不识别浏览器业务状态。服务端恢复正文使用既有 Runtime 规范编码器，不能继承 HTTP 的字段命名策略。

宿主通过公开 `AgentRuntimePayloadSchema` SPI 登记连接请求和结果的 schema。Starter 先执行通用 JSON 资源限额与语法校验，再调用宿主的具体字段校验；未登记的 schema 仍由原 Runtime 注册表处理，重复登记在装配时拒绝。机构模块不直接依赖 Core，也不把浏览器 schema 写入通用 Runtime 注册表。

请求配对时，Browser service 将一次性配对凭据摘要与宿主连接请求在个人目录中关联；官方授权代理按原凭据摘要记录成功响应的准确 device_id。机构服务从该关联和当前设备目录核对 browser_id、有效授权及在线状态，再以稳定恢复事件自动续跑。因此网页关闭或刷新不影响恢复；网页回调和设备列表差量不构成配对归属证明。重复观察、重启和重复恢复事件只推进一次；取消或已结束 Run 不恢复。

连接等待与原执行回执分别保存：已经形成的 rejected 不改写；已经派发且结果未知的页面操作保持 unknown，不因重连重放。原绑定已失效时按既有任务绑定失效规则处理。

## 9. 可信站点与扩展交接

用户首次在适配扩展中确认当前会话站点，信任范围为准确 scheme、host 和 port；生产站点要求 HTTPS，HTTP 仅用于 loopback。桥接只接收顶层受信任页面的能力探测和配对交接，校验来源及请求关联，不开放任意浏览器 RPC。配对须在扩展自身界面确认会话站点和目标服务；身份 scope 或目标服务变化不能复用旧确认。

网站凭据不传给扩展。配对串仅受控交付给扩展，设备密钥只由扩展的官方凭据存储管理；页面、模型、日志与连接请求不保存密钥或原配对串。扩展仅向网页返回版本、请求状态和安全错误；服务端独立确认准确配对结果。

适配源码、固定补丁与构建入口归 `tools/browser/extension-adapter/`，首版交付 Chrome/Edge ZIP 和开发者模式加载指南，商店发布单独处理。以上为已批准目标，实际实现和验收需核对当前候选源码及相应运行结果。
