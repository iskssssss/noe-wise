# 前端共享层设计

> 本文定义机构后台、平台后台与独立会话端的依赖边界。组件契约见[前端组件库](13-前端组件库.md)，视觉规则见[前端视觉与交互规范](09-前端视觉与交互规范.md)。

## 1. 目标与边界

`frontend-admin` 与 `frontend-platform` 使用 Vue、Vue Router、Pinia、Element Plus 和项目自有的轻量后台公共资源。后台采用单页路由与面包屑，不设置应用内多标签、页面 KeepAlive 缓存或导航右键菜单。浏览器原生多标签、前进后退与链接操作继续可用。

`frontend-shared` 只服务两个后台。公共资源按明确的复用职责组织：后台布局与页面、未保存保护、异步请求状态、专业编辑器、格式化与公开业务契约。机构或平台独有的业务规则仍由所属页面或领域模块拥有。

`frontend-chat` 是独立应用，维护自己的组件、样式、国际化、身份状态、请求客户端、协议类型、流式事件合并与恢复。不导入 `frontend-shared`，不通过相对路径、构建 alias、类型导入或测试间接依赖后台代码。通用开源 npm 依赖可以一致；服务端接口是应用间的一致性来源。

不维护 Vben、VXE、schema 表单引擎及其兼容 API。交互按当前业务接口与需求实现，不保留旧框架调用形式。

## 2. 依赖与装配

两个后台通过 `@skillforge/shared/admin` 使用公共布局、页面和交互 composable。应用入口自行装配路由、身份、权限和国际化；菜单仅表达当前身份的导航入口，后端始终负责最终授权。 当前导出入口为 [admin/index.ts](../../frontend-shared/src/admin/index.ts)，异步任务与资源状态见 [tasks.ts](../../frontend-shared/src/admin/tasks.ts)，抽屉关闭保护见 [drawer.ts](../../frontend-shared/src/admin/drawer.ts)。这些公共能力的存在不代表所有页面均已接入。

后台表单直接使用 Element Plus `ElForm`、`ElFormItem` 与具体控件。表格、分页、抽屉和对话框直接使用 `ElTable`、`ElPagination`、`ElDrawer`、`ElDialog`，不另建包装 API。公共 `useDrawerClose` 只协调未保存和提交中保护，业务页面拥有开关和表单状态。

同一 pnpm workspace 可统一第三方依赖版本，但不形成应用源码共享义务。独立会话端使用本地构建配置，不消费后台公共构建入口。

## 3. 主题、文案与可访问性

后台公共资源维护布局、明暗主题、间距、页面标题、内容区及状态色；基础控件的焦点、键盘和浮层行为由 Element Plus 提供。主题在挂载前应用，业务页面不复制后台布局。

控件须有可访问名称，状态不能只靠颜色表达。菜单使用真实路由链接，保留浏览器新标签行为。表单状态和错误消费遵循下节引用的工程规则。

## 4. 反馈、表单与数据展示边界

请求取消与代次、迟到 finally、写入防重、表单基线、字段错误、身份切换与缓存失效的通用要求归[前端工程规则](../../.agents/skills/nw-engineering/references/engineering-standards.md#前端状态与接口消费)。后台公共 composable 实现跨页面的技术行为，页面持有业务对象、编辑状态和权限；独立会话端按相同服务端契约实现自己的状态，不复用后台容器。

未保存保护的页面交互归[后台交互规范](../03-规范与术语/05-后台系统交互规范.md)，浏览器刷新与关闭通过原生 `beforeunload` 提示。字段精度、字符数和清空语义引用[字段规范](../../.agents/skills/nw-database/references/database-modeling-standards.md)，不由控件另设存储类型或空值解释。

三端日期展示统一遵循[交互规范 F14](../03-规范与术语/05-后台系统交互规范.md)：两个后台使用 `frontend-shared` 的日期展示函数，独立会话端在应用内实现同一显示规则。日期控件按北京时间解释选择并向既有接口提交带偏移的绝对时刻；显示转换不改写存储值、模型输入输出及原始 JSON。

## 5. 聊天与过程投影

后台会话观察和独立会话端分别实现自己的界面与状态；共同遵守服务端[接口与事件契约](04-接口与事件契约.md)，不共享前端实现。

过程按 `session_id + root_run_id` 归属，通过 `root_input_id` 关联发起消息；记录使用稳定身份与服务端版本合并，不能将迟到记录挂到最后一条消息。只显示公开 presentation，不显示隐藏推理、内部工具参数或未授权成员日志。

一次提交只发出一次 POST，后续通过 GET 观察。断线带游标恢复，游标失效重新读取权威历史；切换身份或会话停止旧观察并丢弃迟到结果。恢复连接不能被表示为任务成功，子成员结束不能推断主任务结束。

需要确认、补充输入、计划评审和执行取消使用真实服务端动作及绑定标识。提交失败或结果未知保留原内容并先核实状态，不靠清空界面推断成功。

## 6. 共享层与宿主边界

公共代码必须有明确消费者和职责，不能把平台管理权限、机构业务规则或独立会话端状态集中到无边界的工具模块。相同业务契约下可复用的表单字段、专业编辑和展示由两个后台统一使用；不同领域的权限与流程不强行合并。

实现与验证规则见[后台系统交互规范](../03-规范与术语/05-后台系统交互规范.md)及[后台 UI 实施与验收](../04-指南与运维/12-后台UI实施与验收.md)。本文只定义目标架构，不宣称页面已经完成或验证通过。
