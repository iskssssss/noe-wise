# 技能维护台设计

技能维护台属于宿主控制面，负责技能包编辑和发布；Runtime 的版本冻结、渐进加载及执行权限仍由 [Harness 核心对象模型](../../harness-design/03-核心对象模型与状态机.md)定义。

## 1. 归属与入口

机构端维护当前机构自有技能，只读访问平台已发布公共技能；平台端维护公共技能。服务端从认证上下文取得作用域，不接受请求体中的租户归属。维护台不提供将公共技能复制为机构技能的动作。能力目录保留查询和维护台链接，文件维护只有一个入口。

双端页面路由、API、权限和业务文案归各宿主，通用文件树、代码编辑器和差异组件遵守[前端共享层设计](08-前端共享层设计.md)。

机构端与平台端“新建技能”均以一次 metadata 命令创建 SKILL 定义及其活动编辑草稿，成功后直接进入工作台；`foundation.capabilities.create` 与 `foundation.skills.create` 必须同时具备。机构接口使用当前租户 scope，平台接口固定 `CapabilityCatalogScope.platform()`，不接受请求覆盖 tenant。服务在同一事务中复用定义创建和空草稿创建，失败整体回滚，不生成包文件或发布版本。能力目录的通用定义创建、已有定义的手动草稿创建和历史恢复仍独立保留。

## 2. 编辑态与发布态

`nw_skill_editing_drafts` 保存定义、归属、基础版本、编辑修订号、文件及宿主配置、发布时间回执。每个定义至多一个活动编辑草稿；发布后保留只读回执，允许再从自有版本开启下一份草稿。

编辑草稿与 `CapabilityVersion` 分离，允许空包、缺失入口和不完整 frontmatter。保存仍校验相对路径、重复路径、文件与目录冲突、文件数量、体积、Base64 和文本 UTF-8；现有包大小限制继续适用。文件以 Base64 保存原始字节。草稿不出现在挂载版本列表，不能作为 Runtime 输入。

ZIP 导入校验尾记录及中央目录边界，最多 256 个文件、512 个总条目，单文件最多 2 MiB、包总量最多 10 MiB；目录条目不得携带负载。限制与解包规则见 [SkillPackageValidator](../../backend-java/skillforge-core-capability/src/main/java/com/skillforge/core/capability/SkillPackageValidator.java)。合法空 ZIP 可导入为尚未完成的草稿，截断或损坏 ZIP 不替换原内容。在线保存保留文件相对路径，只有导入时处理包含 `SKILL.md` 的单层外包装目录。

发布使用完整包校验与既有能力目录生命周期，由服务端从 `SKILL.md` 解析标准元数据并计算摘要及预计 Token。宿主激活模式、调用策略、冲突组和精确依赖引用与标准文件分离。已发布版本不可原地编辑，default 切换与 Agent 精确挂载更新是不同操作。

`name`、`description` 是版本名称与描述的唯一来源；它们不修改技能定义的稳定标识。`compatibility` 与 `metadata.homepage` 保留为包信息，不推导执行授权或宿主依赖。包作者的可选 `metadata.version` 与平台发布版本号相互独立：编辑、ZIP 导入保留包内信息，平台维护者单独填写发布版本号，不要求为平台修订改写上游文件。未完成的 YAML 仍允许暂存，发布前按完整包规则校验。

已有 Catalog `DRAFT` 版本的编号不可改变。从已发布版本创建草稿时保留原包版本信息，并清空平台版本号，维护者须填写新的平台版本号；不自动改写包文件或升级已有挂载。

机构维护台的历史下拉仅读取版本 ID、版本号和状态三个摘要字段，不预读所有历史包；版本按创建时间倒序，同值时按 ID 倒序。选择后才通过现有精确版本接口读取文件和宿主配置，读取失败保留原选择及内容。计划要求随同一个精确版本回执的 `requires_plan` 返回，true 为必须先计划、false 为按需；普通工作草稿返回 null，表示未解析，不能据此推断为按需。该字段仅属于读取模型，不写入编辑草稿或保存命令。切回工作草稿后不展示上一个历史版本的计划要求。

`metadata.skillforge-plan` 声明任务计划要求，仅接受精确字符串 `required` 或 `optional`，缺省为 `optional`。发布校验、目录/ZIP 摄取和冻结描述恢复共用此约束；该值与包文件及其摘要共同冻结，并核对冻结元数据与 `SKILL.md` 内容一致。Runtime 读取激活版本的冻结声明，不解析正文来推断要求，也不读取当前草稿。版本详情展示解析结果，维护仍通过已有 Skill 文件编辑器完成，不增加独立配置入口。`required` 的动作准入、计划审批和子步骤上下文属于通用任务计划 Runtime 契约。

技能不携带独立的 `intents` 标签。适用场景写在 `SKILL.md` 的 `description` 中，宿主不要求重复填写意图集合。

依赖配置直接选择能力，不要求另选版本。两端按能力类型读取 `/capabilities/requirements/options`（平台增加 `/admin` 前缀），权限为 `foundation.capabilities.read`；目录仅包含当前作用域内已发布定义及其精确默认发布版本，返回 `definition_id/name/capability_key/description/version_id/version_key/version_name/skill_estimated_tokens`。其中 `name` 是定义名称，`version_name` 是该发布版本的名称；`skill_estimated_tokens` 是同一发布版本 descriptor 的技能入口估算整数，其他能力类型为 null；目录不返回 descriptor 正文或包文件。机构可选自有及平台已发布能力，平台仅选公共能力；没有有效当前发布版本的定义不作为选项，测试隔离能力不进入目录。每类目录一次读取，不为每个依赖另查完整版本；Agent 挂载技能和工作流也直接使用该摘要展示名称、说明及标识。保存命令提交能力类型和稳定定义 ID，由服务端解析当前发布版本并写入依赖引用；选项返回的版本 ID 用于展示，不能视为客户端提交的冻结版本。不可用的旧选择仍保留待修正，不自动替换为其他能力或最新历史版本；目录读取失败保留草稿并提供重读入口，运行时仍按既有当前发布与冻结契约处理。

## 3. 并发与事务

保存使用草稿 `revision`/`If-Match`；冲突返回 409，不覆盖当前内容。创建和发布统一先锁定义，再读取或锁定草稿。发布同时核对草稿 revision 与定义 revision，事务内创建或更新版本、发布版本、关闭草稿并持久化发布回执；任一步失败全部回滚。

以既有 `DRAFT` 版本为基础时更新并发布同一版本，版本号不能改变；以已发布版本为基础时须填写新版本号。相同草稿及 revision 的发布重试返回原版本和发布时定义 revision，不再次创建版本。发布推进定义的默认版本，不修改现有挂载或运行快照。新 Run 按 Skill 挂载的精确版本准入，显式修订 Agent 挂载并发布后才采用新版本；已受理 Run 继续使用原冻结版本。

表的强制 RLS 仅允许本租户或平台管理员访问各自草稿，公共版本的可见性不扩展到公共技能的编辑草稿。数据库约束保持一个活动草稿，并核验基础版本、发布结果和定义归属一致。

## 4. 接口

机构前缀为 `/api/v1/capabilities/skill-drafts`，平台前缀为 `/api/v1/admin/capabilities/skill-drafts`；JSON 采用 snake_case。

平台技能列表通过 `GET /api/v1/admin/capabilities/skills/catalog` 一次读取专用摘要，权限仍为 `foundation.capabilities.read`。摘要仅包含定义标识、名称、状态及精确默认版本 ID/版本号，不读取包文件正文；默认版本按当前指针关联，不替换为最新版本，也不额外过滤定义或默认版本状态。列表按更新时间倒序，同值时按定义 ID 倒序；详情与文件编辑继续使用完整读取接口。

机构历史摘要入口为 `GET /api/v1/capabilities/skills/versions/summaries?definition_id=...`，同样要求 `foundation.capabilities.read`，只接受当前机构可见的 SKILL 定义，并沿用版本可见范围：自有版本保留各状态，公共版本只读已发布项；不可见或非 SKILL 定义返回 404。该列表不读取 descriptor；完整版本接口和平台工作台的精确版本路由保持独立。

| 方法与路径 | 行为 |
| --- | --- |
| GET 根路径，`definitionId` | 获取自有活动草稿，不存在返回 204 |
| POST 根路径 | 为自有定义创建草稿，可指定同定义基础版本 |
| POST `/create-with-receipt`，机构与平台端 | 接收 `request_id` 和包含 `capability_key`、`name`、`description` 的 payload，原子创建定义、空草稿及回执；GET `/create-with-receipt/result` 只读查询原请求 |
| GET `/detail`，`draftId` | 读取草稿或已发布回执快照 |
| GET `/version`，`versionId` | 读取可见版本的完整包及配置，只读 |
| PUT 根路径，`If-Match` | 原子替换草稿文件和配置并递增 revision |
| POST `/import-zip`，`If-Match` | 安全解包，替换文件，保留宿主配置及独立的平台版本号 |
| POST `/validate` | 对指定已保存 revision 返回校验问题，不写入版本 |
| POST `/publish` | 校验并发布，返回精确版本 ID 和定义 revision |

校验问题包含 `path`、`line`、`code`、`message`；只有解析器提供有效位置时才返回行号。接口的精确请求字段以[控制器](../../backend-java/skillforge-institution-service/src/main/java/com/skillforge/institution/controller/SkillDraftController.java)、[平台控制器](../../backend-java/skillforge-platform-service/src/main/java/com/skillforge/platform/controller/SkillDraftController.java)和[服务](../../backend-java/skillforge-core-capability/src/main/java/com/skillforge/core/capability/SkillDraftService.java)为准。

当前页面通过 `/create-with-receipt` 提交请求 ID 和创建内容，以回执中的 `definition_id`、`draft_id` 和 revision 承接导航。发送前按主体将请求 ID、名称和标识保存在 sessionStorage；存储失败时不发送，说明正文不存于该记录。结果未知时冻结重复创建并查询原请求回执；查无回执或同名目录项均不能证明结果。`POST /new` 仍是独立入口，不是当前页面创建链路；草稿恢复和 ZIP 导入继续使用各自接口。

技能对象的创建操作统一由表单提交入口负责，成功后再进入后续编辑；ZIP 文件导入是独立操作。事务、机构与平台权限、平台 scope 及 UNKNOWN 边界由所属服务与控制器校验。

运行操作见[技能维护台使用指南](../04-指南与运维/10-技能维护台使用指南.md)。
