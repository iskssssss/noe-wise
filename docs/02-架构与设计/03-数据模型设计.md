## 1. 设计原则

宿主领域模型遵循[数据库模型与字段规范](../../.agents/skills/nw-database/references/database-modeling-standards.md)，数据访问与迁移执行见[工程规范](../../.agents/skills/nw-engineering/references/engineering-standards.md#数据库与迁移)；Runtime 的调用快照、状态迁移和权威存储关系见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md)。本文维护领域含义和关系，不复制通用字段、CAS 或迁移规则；目标规范不自证存量 schema 与接口已经完成统一。

## 2. 数据域

| 数据域 | 主要对象 | 权威职责 |
| :--- | :--- | :--- |
| 身份与租户 | Tenant、TenantMember、EndUser、ChannelIdentity | 租户归属、成员权限和渠道身份映射 |
| SaaS 基础底座 | 正式组织/多角色/资源授权、权威安全会话、菜单字典/功能配额、通知 Outbox、公共文件/管理任务、审计保留 | 当前治理事实按 V274–V279 分域持有，不接管 Runtime 的 Session/Run 权威状态 |
| Agent 配置 | Agent、AgentTemplateDefinition/Version、PersonaProfile、Preset、CapabilityMount、AgentExecutionConfig、AgentTemplateInstallation | Agent 模板发布、机构安装、不可变能力组合和运行预算 |
| 平台模型与运营配置 | PlatformModel/Version、TenantModelSelection、OperationalSettingGroup/Version、模型与工具调用快照 | 平台模型连接和运营策略的不可变版本、机构选择引用及单次外部调用的解析结果 |
| 能力注册 | CapabilityDefinition/Version、SkillDefinition/Version、Skill Catalog/Activation、ToolDefinition/Version、Tool Registry/Deployment、Workflow/Knowledge Source Version | 四类能力共同身份、Skill 标准目录、Tool 调用契约和 Provider 部署 |
| Workflow 配置 | WorkflowTemplate、WorkflowInstance、WorkflowInstallationRevision、DefinitionVersion、CapabilityRequirementBinding | Workflow 定义、安装配置、能力槽和发布版本 |
| Session Runtime | SessionTable、InputIdempotencyLedger、SessionLog、Inbox、Outbox | 会话归属、交互事实和可靠收发 |
| Execution Runtime | Execution Ledger、PendingEntry、Action Ledger | Workflow 执行状态、挂起、恢复与动作幂等 |
| Agent 状态 | RelationshipState、MemoryFact | 关系 schema、记忆事实、revision 和来源 |
| 知识 | KnowledgeBase、Document、Chunk、Index Revision | 检索内容、文档索引与发布 revision |

| 开放平台集成 | 平台管理机器身份、外部机构映射、BusinessScope、ServicePrincipal、IntegrationResourceMapping、ControlOperation、EventSubscription | 平台直管机构、固定执行身份、可信来源、外部映射和可靠事件；旧 Application 及其关联/凭证已由当前迁移链退役 |
| 计费、审计与轨迹 | UsageEvent、模型费用投影、AuditLog、TraceProjection | 原子用量、模型费用查询、安全审计和可重建端到端查询；不生成销售应收账单 |
| 产品运营 | Builder 草稿/快照、Marketplace 审核/安装记录、Handoff 工单、模型费用与合规审计记录 | 生产版本化资源或消费受控投影；不保存 Session/Execution 权威状态 |

CapabilityDefinition.type 只能取 `SKILL / TOOL / WORKFLOW / KNOWLEDGE_SOURCE`。Agent 委派授权、Persona、MemoryFact、RelationshipState、Channel、Connector、Builder、Marketplace、Handoff、Billing、Trace、Usage 和 Audit 不使用 CapabilityDefinition/Version 表表达。

宿主 `nw_chat_session_outbox` 保存已提交的公开输出、稳定事件身份及会话内顺序，不保存 Web 领取、发送确认或已读状态；SSE 和历史续读直接消费这些事实。实际 Webhook 投递的重试、确认和失败归独立 `nw_chat_session_outbox_webhook_deliveries`，不得把其状态混入 Web 输出或 Runtime 执行状态。

## 3. 身份与隔离键

后台当前授权使用 scope 隔离的部门、岗位、成员组织资料、正式角色、成员角色、角色权限、资源所有权与明确共享；账号表仍持有密码和启停，旧单 role 字段不参与当前授权。security 表独立保存 MFA、一次性凭据摘要及访问/刷新共同引用的设备会话。catalog 将套餐功能关系、机构覆盖和资源容量与运行配置分开保存；messaging、assets/jobs、operations 分别保存外部投递回执、公共文件引用/管理任务和只追加审计。物理表、迁移与引用保护见 [SaaS 基础底座 §8](19-SaaS基础底座设计.md#8-api-与持久化入口)，当前撤权与历史冻结边界见其 [授权分层](19-SaaS基础底座设计.md#2-身份动作对象与商业授权分层)。

个人浏览器设备、任务绑定、连接请求与调用回执属于宿主数据域，以认证上下文的 `tenant_id + end_user_id` 隔离；任务及截图关联真实 Session/Run/调用来源。已批准目标与独立服务持久卷边界见[BrowserSkill 接入](18-BrowserSkill远程浏览器接入.md)，通用图片材料的内容身份与引用见[多模态专题](../../harness-design/03-多模态内容与媒体引用.md)。当前存储入口为 `nw_browser_call_receipts`、下述 `nw_browser_connection_requests` 与独立 browser-service 持久卷，实际运行验收状态见所属实施记录。

通用图片复用 `nw_chat_session_attachments`：图片元数据保存实际 MIME、像素宽高、摘要及 `source_media_id/media_transform`；二进制正文由 `nw_chat_attachment_bodies` 持有并通过引用关联。`runtime_session_id` 是 Runtime 逻辑归属，`session_id` 是产品保留外键；工具图的 `media_run_id` 用于重新确认委派来源。文本附件仍有到期时间，图片行随 Session 保留。原图、规范化图、裁剪和请求变体分别不可变，不以历史引用触发改写。

模型版本配置及 Runtime binding 保存明确 `image_policy`，包含用户/工具图片开关、数量、字节和传输预算、尺寸、视觉 token 参数与版本；模型名不构成能力证据。冻结请求持有实际采用的政策和媒体变体，新的配置发布不会改写旧请求。

### 3.1 Session 绑定

宿主通过 ChannelIdentity 将渠道身份映射到统一用户；Session 绑定与各配置的冻结时点见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#51-session) 和 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#54-类型化-capability-契约与挂载快照)。

渠道业务配置和 UI 配置只保存动态业务内容。OpenAPI 凭据使用渠道专用列：API Key 保存 SHA-256 哈希，HMAC 密钥保存加密密文，两者必须成对存在且仅用于 OpenAPI 渠道。通用配置入口不能写入凭据；签发、轮换、吊销经渠道应用服务的事务和行锁执行。管理响应只公开 `api_key_issued`，明文仅在签发或轮换成功时返回一次。

### 3.2 RelationshipState 隔离

宿主拥有关系产品 schema，Runtime 的隔离键、版本和并发更新要求见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#56-stateful-agent-context)。

### 3.3 租户表约束

机构私有表、公共资源共表、RLS、唯一性与引用约束遵循[租户与引用规范](../../.agents/skills/nw-database/references/database-modeling-standards.md#71-租户与引用)，时间及操作者字段按[表的职责](../../.agents/skills/nw-database/references/database-modeling-standards.md#5-公共字段与可信写入方)配置。

全局模板表没有 tenant_id 时必须具备明确发布状态和不可变版本语义；机构侧 `nw_agent_template_installations` 必须具备 tenant RLS、模板版本引用、请求幂等键和原子安装结果。

机构成员的 Agent 保存发布命令复用不可变 `nw_agent_publications` 行保存成功身份。[V343](../../backend-java/skillforge-migration/src/main/resources/db/migration/V343__agent_publication_command_identity.sql) 增加 `request_id` UUID、`request_fingerprint` SHA-256 和 `request_actor_ref` 三个类型化可空列：普通独立发布均为空，组合命令成功时必须同时写入；机构、Agent、请求 ID 的部分唯一索引保证同键只生成一个发布。摘要包含操作版本、可信机构/Agent/成员及规范化原更新参数，保留 null、空集合与数组顺序；不另存请求正文或响应 JSON。原发布 ID、修订和时间组成回执，精确查询不读取快照正文、不移动当前指针。存续与清理见[保留规范](../04-指南与运维/11-数据清理与保留规范.md#21-postgresql-表登记)。

### 3.4 开放平台身份与资源映射

ServicePrincipal 属于单一 tenant 和 integration，保存凭证状态、scope 集、轮换版本与可选网络策略；会话调用同时记录 ServicePrincipal actor 和解析后的 EndUser actor。

IntegrationResourceMapping 使用 `tenant_id + integration_id + resource_type + external_ref` 唯一定位三方资源，映射到平台内部资源 id 与当前 revision。external_ref 不能承担租户隔离或内部外键职责。

目标模型移除 Application、应用关联/策略/治理凭证及 application_id。外部机构映射在当前部署内按“namespace＋external_institution_ref”唯一定位 Tenant，绑定已有 Tenant 需平台明确管理授权；机构创建、默认策略、映射及幂等事实原子提交。平台管理机器身份与固定 Tenant/integration 的 ServicePrincipal 生命周期独立，前者不形成机构执行主体。BusinessScope 保存在 Tenant/integration 及授权闭包内，不能通过外部门店标识扩大资源访问。

Session、Run、委派和 ControlOperation 持久化真实 Tenant/integration、操作者/EndUser、业务范围及实际实例；后台任务保留明确责任身份，消息 context 无权覆盖。私聊稳定 EndUser；共享群目标由 GroupBinding 独立表达归属，多作者/服务 Agent 不伪造群用户。群持久化、Memory owner 及公开类型目标以[§12](#12-多机构接入目标-schema-与约束)及其 Harness 引用为准。

实施差异：现有 [V270](../../backend-java/skillforge-migration/src/main/resources/db/migration/V270__integration_applications.sql) 和 [V272](../../backend-java/skillforge-migration/src/main/resources/db/migration/V272__integration_session_provenance.sql) 是旧应用模型的 schema 证据，不是新目标约束。GI-14 同步目标 schema、初始化、RLS/FK/唯一性及来源消费者，完整迁移链仅在新建或明确获准重建环境验证，不保留默认应用或双读双写。

### 3.5 模型、运营配置与调用准备

| 对象 | 权威关系 |
| :--- | :--- |
| PlatformModel / PlatformModelVersion | 稳定平台模型身份保存工作草稿和当前发布指针；保存不切换发布，发布追加完整连接、认证、加密凭据、能力和计价的不可变快照。历史恢复写回草稿，明确发布后才生效。 |
| 模型时间价格规则 / 预设版本 | 峰谷规则的时区、覆盖日期、倍率和来源使用规则主表，星期、时段、日期例外及适用范围使用有序明细表；规则及明细不可变。模型草稿和发布版本各以类型化外键引用精确规则，API 可完整投影，但新增固定规则不写入模型 JSON。预设草稿和发布历史独立保存，采用某个发布版本后模型单独保存发布，不实时继承预设当前指针。计价语义归[峰谷时间成本](14-用量与账单设计.md#峰谷时间成本)。 |
| TenantModelSelection / Agent.modelConfigId | 机构分别保存 LLM、Embedding、Rerank 的稳定平台模型引用，Agent 可覆盖机构默认 LLM；这些引用不复制 endpoint、认证或凭据。新 Run 在受理边界解析当前已发布模型。 |
| OperationalSettingGroup / OperationalSettingVersion | 每个注册分组以当前指针定位不可变完整快照；CAS 更新和回滚都生成新 revision，审计账本记录操作者与版本迁移。敏感字段只在版本快照中加密保存。 |
| 模型与工具调用快照 | 每次外部调用从本次 Run 或 Execution 的冻结配置生成模型或 Provider target、运营配置 revision 与策略；持久请求材料不含凭据，调用准备及其重试、结果处理和恢复继续原配置。 |

平台模型发布与运营配置生效更新只推进当前指针并追加不可变 revision。Agent 的五项运行预算覆盖在 NewRun 时与平台 task_budget 场景根额度及代码角色比例统一装配并冻结；模型选择、提示词、调用策略、沙箱、成果与其他运行配置分组同样从原 Run 快照准备后续动作。聊天和开放平台新 Run 均需记录可信请求者和冻结配置，不允许以缺失绑定为理由在每次动作读取当前值。已经发出的调用及其重试、结果处理和恢复读取原调用快照。Runtime 的 ModelBindingRef 由宿主根据该 Run 采用的精确模型 revision 发布，SDK 与 adapter 不从当前配置指针补读。配置变更不删除 UsageEvent 或重置累计用量，累计用量继续由只追加的账本聚合；实时停用与撤权继续检查。

知识运营配置移除没有真实超时消费者的 `embedding_timeout_seconds/rerank_timeout_seconds`，实际期限归冻结模型目录版本。升级迁移 [V317](../../backend-java/skillforge-migration/src/main/resources/db/migration/V317__knowledge_operational_timeout_cleanup.sql)仅在旧 current 含上述键时，锁定该组并追加 `system_release` 新修订，删除两键且保留其他值，再切换当前指针；无组或已采用新契约时不写入，原修订和冻结材料不改写。该迁移的仓库源码不等于现有数据库已执行。历史管理列表对精确旧知识契约返回 `contract_status=RETIRED`、原 revision/时间/actor 元数据及空 values，现行可用契约为 SUPPORTED；旧正文仍在原表保留，详情和回滚明确拒绝，不能经新类型读取器恢复执行。其他未知损坏不按已停用契约放行。

模型的 `inputPricePerMillionCents`、`outputPricePerMillionCents` 和 `pricePerQuantityCents` 使用 `BigDecimal` 保存小数分，完整冻结在模型版本 JSONB 中。精度、最大值、金额列与单位关系见[计费数值契约](14-用量与账单设计.md#计费数值契约)。

### 3.6 个人浏览器连接请求

`BrowserConnectionRequest` 对应 [V290 的 `nw_browser_connection_requests`](../../backend-java/skillforge-migration/src/main/resources/db/migration/V290__browser_connection_requests.sql)，持有原工具等待的用户连接进度；不替代 Runtime Action、ToolInputWait、Session Inbox 或浏览器执行回执。完整连接状态机归[BrowserSkill 设计 §8](18-BrowserSkill远程浏览器接入.md#8-按需连接与自动续跑)，宿主传输归[个人浏览器连接 API](04-接口与事件契约.md#37-个人浏览器连接控制)。

| 字段组 | 含义与约束 |
| :--- | :--- |
| `tenant_id + request_id` | 机构内主键；请求 UUID 从原 tenant/Run/invocation 稳定派生，同一来源重试不创建新请求 |
| `end_user_id/session_id/run_id/invocation_id` | 原始个人、逻辑 Session、Run 与工具调用；另有 `(tenant_id,run_id,invocation_id)` 唯一约束 |
| `reason/status` | 首次等待原因和连接生命周期；成功提交恢复与业务执行成功分开表达 |
| `device_id/browser_id/make_default` | 明确选择或准确配对关联的设备、冻结浏览器目标，以及用户是否要求保存默认配置 |
| `pair_dispatched` | 已派发一次配对意图；不因超时或未知结果重新签发一次性凭据 |
| `wait_snapshot` | 首次观察的 `actionId/pendingId/wakeId/waitRevision/runRevision/checkpointRevision`，只保存准确恢复身份，不保存请求正文 |
| `revision/created_at/updated_at/error` | 行 CAS、稳定恢复输入时间、最近推进时间与安全错误码；迟到选择、取消或观察不能覆盖新版本 |

表启用并强制机构 RLS，个人归属及来源授权在服务层继续校验。`WAITING / READY / RESUMING / CANCELLING` 由部分索引支持有界后台扫描；`RESUMED / CANCELLED / FAILED` 不参与轮询。后台以稳定 `browser-connection:<request_id>` 查询 Runtime 已受理原事实后再推进本表，因此受理后、保存前退出不重放恢复或实际启动。

原配对串和设备密钥不进入本表。独立 Browser service 在各 owner 的持久目录维护连接请求与原配对 Bearer SHA256 的绑定及 `NOT_FOUND / WAITING / PAIRED / UNKNOWN` 查询投影；只有官方成功响应的准确 `device_id` 可以确认关联，不根据设备集合差量回填。配对授权事实、连接进度及 Runtime 恢复事实各有权威来源，不能用其中一层的状态替代另外两层。

### 3.7 群控制与跨服务回执（目标）

群控制在 Tenant/integration/GroupBinding 内保存权威期望状态、范围、单调 revision、command_id/指纹/CAS 结果及真实操作者；命令、审计和待传播记录原子落库。必需参与方集合来自受控端点注册，ACK 按端点世代和 revision 幂等保存，保留最后确认、失联及在途边界；不能用单个 paused 布尔值同时代表已受理与全局已生效。

GI-04 中心门禁采用类型化关系：`nw_group_control_states` 保存每个群或准确 Run、独立 scope 的当前状态；`nw_group_control_command_scopes` 保存原命令的范围集合；`nw_group_sender_endpoint_flights` 逐项保存注册端点最后 ACK 或退役时报告的在途/UNKNOWN 引用；`nw_group_delivery_release_boundaries` 用含 Tenant/integration/群的外键连接具体 delivery 放行与原阻止边界。读取时可以聚合为协议数组，固定关系不存 JSON 列。端点报告只反映外部发送账本的最后确认，不能代替 Runtime Attempt 或发送端派发账本的权威，也不提供重发许可；`last_confirmed_at` 与 `connection_state=UNKNOWN` 分别表达最后持久 ACK 时点与缺少实时连通观察，不把注册 ACTIVE 或旧 APPLIED 当作当前联网证明。

`nw_group_control_commands.response_json`、`nw_group_control_requests.response_json` 是精确回放首次协议 `data` 对象的例外：受理后参与方、ACK、世代及嵌套 current 快照会变化，若仅重新拼装当前类型化数据，就无法兑现同键同参返回原回执。它们保存 snake_case JSON object 的字段值、显式 null 与数组顺序，UTF-8 编码上限为 4 MiB；超过容量必须整笔回滚，不能删减参与方或截断在途后受理。该快照与命令/管理动作同事务创建，数据库禁止更新或删除；当前查询、授权、派发和放行始终读取类型化权威表，不能用原 response 推导当前状态。它们与原命令、ACK、退役及 delivery/release 依据共同保留，只有所属业务范围完成显式归档/删除闭包时才可一并治理，不单独清除幂等回执、UNKNOWN 或原阻止依据；此处不授权实际数据清理。

Runtime 调度门禁与示例发送端本地门禁分别持久化，发送服务以稳定 delivery_id 保存队列、DISPATCHING、结果/UNKNOWN 和取得资格时的控制版本。最终派发资格转移与本地控制门禁串行化，旧积压标识不因恢复被清除；跨数据库传播不假设分布式事务。数据保留支持回执丢失、重复传播、端点换代及进程重建后核验，未知外发不能重置成未发送。

端点逻辑身份、当前有效世代、退役待确认状态、持久隔离边界和退役回执分开保存；同逻辑端点各代共用权威派发账本，世代变更与新 DISPATCHING 资格竞争同一持久门禁。旧代在途引用、稳定 delivery_id、本地阻止及去重事实跨换代保留；不能以新代空账本或注册表删行表示旧代已退出。

自动发送资格关联稳定根输入/Run、可信触发顺序或资格代、适用群/Run 的发送阻止边界，并传播到具体消息及 delivery。暂停时尚无输出行的触发也保留可判定归属；明确放行保存目标消息版本/集合、所覆盖边界、操作者和回执，后续生成或补拉不刷新原资格。具体字段见[§12.2](#122-群消息memory-与控制)，不以业务时间作为权威顺序。

本地安全阻止按 local_intent_id 独立保存范围、根来源边界、本地 revision、操作者及状态；关联命令尝试分别保存原 command_id/指纹/CAS、结果证据、远端受理 revision 与新尝试关系。远端未受理终结回执阻止旧 command_id 迟到受理，与受理竞争同一权威边界；对账、放弃、解除有独立幂等/CAS 和审计；远端未知、明确未受理、已受理与本地有效阻止不能压成一个状态，换代/重启不丢失关联。

状态及失败/恢复的唯一行为契约见[接口与事件 §2.6](04-接口与事件契约.md#26-暂停与接管跨服务生效目标)；[§12.2](#122-群消息memory-与控制)固定目标类型与 schema，GI-04 交付实现及模拟发送消费者，后继业务工具和记忆 Worker 消费既定范围。

## 4. Agent Runtime 逻辑存储

Runtime 逻辑存储直接引用 [Harness 06](../../harness-design/06-MVP-0技术底座实施方案.md#51-逻辑存储)；SDK 存储适配器职责见 [Harness 03](../../harness-design/03-核心对象模型与状态机.md#76-sdk-ports-与适配器责任)。宿主物理 schema 是实现证据，不在本文另维护一份存储字段或状态表。

### 4.1 Agent 模板与安装

`AgentTemplateDefinition` 是平台拥有的稳定模板身份，包含系统提示词、公开角色说明、名称、头像、默认 LLM、运行预算、公共基础能力、可选 `resource_slots` 和可选 `delegation_slots`。编辑复用同一工作草稿；发布追加不可变快照并更新当前发布指针，必须选择已发布模型、引用已发布的公共基础能力并通过技能依赖完整性校验。机构安装读取当前发布快照，模板 ID 与 key 不随发布改变。

`AgentTemplateInstallation` 是机构安装事实，保存租户、模板版本、创建的 Agent、请求幂等键、请求指纹、安装状态和安装时间。`resource_bindings` 只允许把 `TOOL`、`WORKFLOW` 或 `KNOWLEDGE_SOURCE` 槽挂到当前租户已发布且有效的资源；公共 `SKILL` 与内置 `PLATFORM TOOL` 由模板基础能力提供。`delegation_bindings` 只引用当前租户已有 Agent，不在安装时自动创建配套 Agent。安装完成后实例独立，模板后续版本变化不改写实例。

Agent 实例保存 `icon_url` 和独立的 `AgentExecutionConfig`。模板安装只把模板版本和安装时的解析结果写入实例，不保存凭据；凭据仍由资源及其部署持有。

平台公共定义及机构共享定义经相应授权部署到目标 Tenant 的稳定 Agent 实例，部署保存定义稳定身份、FOLLOW_PUBLISHED 模式、目标机构及受控外部映射；本地参数/资源/委派槽以 revision CAS 维护。新 Run 解析当前发布及本地绑定，受理后冻结，恢复不改读当前发布；缺绑定拒绝新 Run，下架和当前撤权仍生效。机构资料及凭据不写回定义。

该公共部署与独立模板安装保持明确更新语义，不再使用 application_managed 标记决定开放目录或独立安装，也不保留应用 grant/部署分区。现有 [V271](../../backend-java/skillforge-migration/src/main/resources/db/migration/V271__application_agent_deployments.sql) 为待替换实现；目标关系及直接消费者由提案 GI-14/GI-01 验收。

目标分发策略由定义所有者通过服务端维护，首版只支持两种互斥语义：

| 分发策略 | 消费契约 |
|---|---|
| `OPEN_INSTALL` | 平台明确允许普通独立安装；仍检查当前发布、机构动作/功能/容量及资源权限。安装后按独立 Agent 发布，源更新不改写既有副本，也不赋予跨机构资源权限。 |
| `AUTHORIZED_DEPLOY` | 平台或机构维护的受控定义，只能经当前有效授权形成 FOLLOW_PUBLISHED 部署；不得走普通独立安装、无来源复制或导出为独立实例。获准部署不等于获准复制。 |

策略在首次发布前必须明确，缺失/非法值禁止发布与消费，不从 applicationManaged、标签或调用方 mode 推断。首版平台定义可选择两者，机构共享定义只允许 AUTHORIZED_DEPLOY；首次发布后不允许切换策略，需要另一稳定定义和显式部署，不自动改源或转换既有实例。目录、详情、历史版本消费、独立安装及授权部署统一检查服务端策略和当前权限；普通安装目录不暴露受控定义，受权消费目录仅展示可用发布。引用旧快照、伪造 mode 或拥有部署权都不能绕过该检查。

GI-14 必须将策略持久化、现有定义的明确分类及所有直接消费者守卫与 applicationManaged 移除作为同一交付单元；未分类定义失败关闭，不能先删除旧守卫，留待 GI-16 补授权。GI-01 验证平台生命周期，GI-16 扩展机构来源与授权链。以上目标字段/schema 见[§12.1](#121-管理关系定义与部署)，不代表已实现。

### 4.2 Agent 运行预算

`AgentExecutionConfig` 对外包含 `max_business_model_calls`、`max_tool_calls`、`max_knowledge_calls`、`max_total_tokens` 和 `max_wall_time_seconds` 五项覆盖，分别表示业务模型次数、工具次数、知识次数、累计总 Tokens 和累计活跃秒数；空值使用场景与角色派生额度，非空值为正整数，受理时明确拒绝超过真实任务根的覆盖。AgentDO 的业务模型字段通过显式映射继续使用既有物理列 `max_iterations`，不增加公开旧字段别名，也不为内存和 wire 命名调整执行 DDL。各层输入与输出计量上限均等于该层总 Tokens 额度。`NewRun` 受理时同时保存平台预算版本和 Agent 覆盖，恢复继续使用该快照，不因平台或 Agent 后续修改漂移。团队 `FrozenMember` 携带相同配置并复用 Runtime，不创建新的执行引擎。

### 4.3 普通 Agent 身份与发布历史

普通 Agent 的 `id` 是稳定业务身份，`(tenant_id, agent_key)` 唯一。`nw_agents` 保存工作配置与当前发布指针，发布历史单独保存不可变配置和能力挂载快照；新增修订不创建新的 Agent 身份。机构主列表一身份一行，当前发布修订和未发布修改分别展示，历史从详情进入。运行时生效及恢复语义见 [Harness 对象模型 §2.3](../../harness-design/03-核心对象模型与状态机.md#23-稳定资源身份与发布快照)。

`/agents/revise {agent_id}` 打开该身份的工作草稿。保存提示词、模型、预算、委派和挂载不直接修改已发布内容；发布在身份锁内追加完整快照并更新指针。渠道、Session 和工作室绑定稳定 Agent ID，下一主 Run 解析当前发布快照，进行中的 Run、子任务和恢复继续原快照。停用和归档作用于稳定身份并实时限制执行；已发布历史不因编辑或恢复被覆盖，仍被执行引用的对象不能直接删除。

### 4.4 Workflow 安装修订

WorkflowInstance 保存安装身份与当前安装修订指针；定义版本、业务配置和自定义提示词由不可变 WorkflowInstallationRevision 持有。安装和升级生成修订，Runtime 绑定读取精确修订，不从可变实例字段或市场模板重建运行事实。WorkflowTemplate 负责市场展示与审核，Builder 草稿与 DefinitionVersion 分别负责设计态和发布态，不能互相充当运行时权威。

### 4.5 机构共享定义与授权（目标）

GI-15 的机构关系复用 `nw_tenants.parent_tenant_id`，维护权威 `relation_revision`、全树修订、不可变关系历史及原成功回执，实际表与约束见[§12.1](#121-管理关系定义与部署)。单父 FK 不能代替无环及并发验证；关系写入先锁定树修订行，再检查当前路径和 child CAS，数据库触发器执行最终无环及有下级不可删除约束。直属创建同事务写入机构、策略、外部映射、关系、明确目录 read grant、幂等事实及审计；已有机构仅由平台授权挂接。GI-16 的机构共享定义、完整授权链与独立目标部署管理许可分别持久保存，不由机构树自动获得。

定义归属区分平台与创建机构，机构所有者引用真实 Tenant；机构 Agent 的发布不自动产生共享资格。共享发布复用稳定身份和不可变修订，但形成安全可部署内容：源机构的私有正文、本地工具/知识/Workflow 挂载不能直接复制，依赖表达为允许的公共能力或目标本地槽位；无法合法转换则校验失败。普通独立 Agent 和独立模板安装保留自身契约，受控共享部署不得转成无来源副本以规避撤销。

授权事实保存稳定身份、源定义/所有者、授予者及 actor、目标 Tenant、动作/有效期/状态/revision、转授权限制与父授权引用、所依赖关系依据及幂等指纹。源机构直属授权与平台直授分别表达；转授权逐跳只收窄，必须可追溯到原始许可。关系、grant 和发布版本分别有生命周期，不以一条 parentTenantId 或只存最后一跳证明可执行权限。固定字段名/表及关键索引约束见[§12.1](#121-管理关系定义与部署)，具体持久字段和约束以该节及所属迁移为准。

下级部署保存自己的稳定 Agent 身份、源定义及授权引用、FOLLOW_PUBLISHED 和本地绑定；Run 冻结具体源所有者/定义/发布、授权依据、实例及本地绑定版本，当前执行仍查撤权。部署唯一性、外部映射幂等和换源冲突沿用同一服务，父机构 AgentId、密钥或私有资源不进入目标执行绑定。当前有效性必须由权威关系/整条授权链判定，不能等异步实例状态更新才拒绝。

一个受控实例在一个部署修订中明确绑定一条授权依据；平台直授与总部转授同时有效时也不自动择优、合并或回退。重新授权创建新的授权事实，不改写原已撤销授权；同源实例通过显式授权绑定变更形成新部署修订，记录前后授权、操作者和幂等回执，保留 Agent ID、外部映射、本地配置、群服务关联及历史。保留关联不授予新的群或资源权限。不同源定义仍按换源冲突拒绝。

完整链以 grant_chain 保存源 definition_id/owner_kind/owner_tenant_id 及有序 hops；各跳固定 grant_id、原 revision、grantor/target、父 grant/revision 和关系引用/revision。当前检查沿相同身份逐跳核验动作、期限和转授边界，父许可收窄后仍覆盖后代范围时保持可用，不用当前 revision 必须等于历史 revision 代替范围判定。部署创建要求 deploy＋execute，绑定/换授权要求 deploy，新 Run 和后续派发要求 execute。

新 Run 冻结受理时部署修订及其完整授权依据；切换授权不改写已受理 Run、子任务或用量的原依据。旧依据仍有效时原 Run 可按原权限继续，旧依据撤销/到期/关系失效时不能借新绑定继续派发。切换、撤销与新 Run 受理的并发规则归[接口契约 §2.5](04-接口与事件契约.md#25-机构层级与-agent-授权目标)。

迁移和撤销保留旧关系/授权修订及回执，不搬移下级业务数据、重写费用或删除未知调用；重新挂回和旧请求重投不能复活旧授权。GI-15 目录 grant 必须匹配当前父及精确 relation revision，原回执只表示当时成功，不证明当前可见或可执行；GI-16 的 Agent 授权链另按其契约验证。源所有者不等于执行机构或付费方，来源与用量维度归[用量设计](14-用量与账单设计.md)，复用现有 AgentPublication 与解析器而不建第二 Runtime。

## 5. Workflow 定义与执行分离

- WorkflowTemplate 表示可复用模板。
- WorkflowInstance 表示租户安装与配置。
- DefinitionVersion 表示发布后不可变的执行定义。
- CapabilityRequirementBinding 把 Workflow 槽绑定到精确 CapabilityRef；Tool 槽额外绑定 ToolDeployment。
- DispatchOrder 在执行前固定 definitionVersion。
- Execution Ledger 表示某次执行，不因模板更新改变。
- Pending 和 checkpoint 属于 Execution，不属于 Agent 或 Session 消息。
- Workflow 不持有 Memory、Session 历史或 RelationshipState；外部 HTTP 必须建模为 ToolCallNode，知识必须使用已声明 KnowledgeQueryNode。

Workflow 包的声明格式见 [工作流规范](../03-规范与术语/01-工作流规范.md)。

## 7. 开放平台资源版本与控制操作

| 对象 | 权威语义 |

| KnowledgeRevision | 文档与索引构建形成 ready revision，发布时原子切换 active；EvidenceItem 仍记录实际 sourceVersion |
| KnowledgeIngestionJob | 保存 accepted/processing/review_required/ready/published/failed 状态、逐项结果和重试信息 |
| ControlOperation | 保存发布、摄取、批量同步或期望状态对账的根操作、子步骤、部分失败和最终资源引用 |
| EventSubscription / DeliveryAttempt | 保存出站订阅、签名版本、过滤条件、sessionSequence/eventId 和至少一次投递状态 |

ControlOperation Log 是非会话资源操作事实源。资源当前状态由各自容器和不可变 revision 权威保存，ControlOperation 不复制完整资源定义；出站事件由 Outbox/DeliveryAttempt 权威保存，不能用 EventBus 送达记录替代。

### 12.3 发布流、RLS 与迁移交接

Usage 原子账本保持原稳定 event_id/attempt/report 引用，新增来源列按执行 Tenant 归属；`nw_usage_publication_pending` 与 Usage 事实同事务，`nw_usage_publication_events` 保存 event_id 唯一、部署流 stream_revision＋sequence 唯一、不可变投影和来源引用，`nw_usage_publication_state` 保存当前流尾。发布 Worker 锁定流尾，在一个事务分配下一 sequence、插入事件并完成 pending；锁持有到提交，下一发布不能越过未提交前驱，回滚无可见发布，重启按 pending 幂等接续。不得以数据库 sequence/源主键/发生时间直接作已发布水位。GI-14 交付基础流，GI-09 增加群/后台/授权来源和总部汇总。

租户私有表启用 FORCE RLS，读写都检查当前 tenant；集成对象同时带 integration FK/过滤，FK/唯一性使用包含 tenant/integration 的组合键，不能只用雪花全局唯一代替隔离。平台映射、关系和跨机构 grant 的管理表使用专用管理 repository/受控事务及 FoundationAccess/机器目标授权，普通机构 SQL 不获得全表读取；向机构提供的授权目录是经当前目标关系过滤的消费投影，不因树祖先开通业务 RLS。消息、Memory、控制、派发和成果另有当前群/成员/动作检查，RLS 不替代对象授权。

GI-14 移除 integration_applications、integration_application_tenants/credentials/audit、application_agent_template_grants、application_agent_deployments、ApplicationContext 及所有 application_id/application_managed FK/策略/默认种子，按本节重建保留职责；Tenant、ServicePrincipal、BusinessScope、定义/版本、原子计量、确认/调整机制保留但去掉应用所有权。旧 V270–V273 不作为必须保留的历史格式，后继按新建/明确获准重建环境完成完整 Flyway 链、受限角色/RLS 和持久往返；实际修改历史迁移或新增迁移由对应实施批次按工程规则决定。不得机械删除 V273 的后台计量冻结来源和不可变约束，须迁入真实 origin/责任身份目标。

本节不授权操作现有数据库。先交付 DDL、初始化和真实新隔离库验证，再随获准环境发布同版本宿主、OpenAPI/SDK、三个前端及示例；停止/恢复以精确候选和持久状态为依据，不能为回滚启动旧格式兼容或重放未知外部效果。钱包适配器和独立钱包各自 schema、事务及 HTTP 归[用量与账单](14-用量与账单设计.md#钱包结算交付契约目标)，不写入 SkillForge Runtime 数据库。
