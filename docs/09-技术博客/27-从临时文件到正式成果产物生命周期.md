# 产物生命周期：从沙箱里的文件到用户能取得的报告

前置阅读：[09 课](09-通用代码执行沙箱的隔离设计.md)、[20 课](20-幂等外部副作用与未知结果.md)、[22 课](22-审批回调与挂起恢复.md)、[26 课](26-跨Run任务连续性与持续Goal.md)

沙箱成功写出了 report.html，助手却只回复一个临时路径。用户换一台设备就打不开，任务清理后文件还会消失。计算完成和成果交付之间，缺少了一段明确的生命周期。

研究助手需要把临时文件登记为可管理的产物，检查内容和归属，再按审批结果发布。路径说明文件在哪里，产物身份说明它是什么、来自哪次任务、谁能使用，以及它是否已经正式交付。

## 临时输出不能直接充当下载入口

执行结束后，运行时从受控输出清单收集文件，校验路径、类型、大小和必要的安全规则，将其复制到独立存储，再记录稳定的产物标识、内容摘要和来源 Action。若直接把沙箱目录映射到下载路由，任务清理、路径穿越和跨租户访问都会变得难以控制。

可以采用如下教学状态：

| 产物状态 | 已经确认 | 尚未表示 |
| :-- | :-- | :-- |
| staged | 文件已收集，归属已确定 | 内容通过检查 |
| validated | 检查通过，内容版本固定 | 用户已批准发布 |
| published | 指定范围的发布已确认 | 永远公开或永不过期 |
| revoked / expired | 访问被撤销或期限到达 | 所有副本都已从外部消失 |

这是建模示例，不要求所有系统使用这些名称。状态的意义在于避免“文件存在”被误当成“用户已经收到”。

## 将内容版本和可见性分开

草稿 D1 生成产物 P1，修订 D2 生成 P2。审批应绑定固定内容或其可靠版本引用，不能在批准之后继续覆盖 P1 的字节内容。否则用户批准的对象会在同一个下载地址背后变化。

发布记录可以引用某个不可变内容版本，并保存可见范围、有效期和访问策略。链接只是访问方式，不是权限本身。匿名公开链接、短期 bearer 链接和需要登录的下载入口有不同语义，应在产品中明确选择。

下面是发布前的产物描述示例：

```json
{
  "artifact_id": "report-P2",
  "draft_version": "D2",
  "content_type": "text/html",
  "validation_status": "passed",
  "publication_status": "awaiting_approval",
  "audience": "internal-team",
  "source_refs": ["source-a@v1", "source-b@v2"]
}
```

它没有给出一个假下载地址，因为真正的入口应由存储和访问层生成。模型也不能把 artifact_id 拼接成未经确认的公开 URL。

## 存储和数据库之间也有半完成状态

对象上传成功，数据库登记失败，可能留下孤立文件；登记成功，复制却失败，则会留下不可下载的产物。不要把这两步假装成天然原子操作。

一种做法是先登记准备状态，通过稳定对象键执行复制，确认对象摘要与大小后再标记可用。清理器按明确保留期处理未完成记录和孤立对象，并在删除前检查是否仍被有效成果引用。稳定键可以降低重试成本，内容校验则防止同名对象被误复用。

正式产物的保留策略应独立于沙箱临时文件。用户已取得的成果不能因为计算容器退出就立即消失；敏感资料又不能因为“以后也许要审计”而无期限保存。保留、撤销和删除需要各自可解释的条件。

## 提示词只报告已确认的交付状态

使用时机是产物收集完成、发布结果返回或用户询问交付进度时。输入来自产物登记、审批状态与发布 Observation，追加以下片段：

```text
[新增：成果交付]
只使用运行时返回的产物标识和访问入口，不自行拼接链接。
区分临时文件、已校验草稿、等待审批和已发布成果。
介绍成果内容、适用范围、证据缺口及访问方式。
部分文件失败时列明未完成项；发布 unknown 时说明待核对。
只有确认可访问的正式结果，才报告为已交付；不要把成功生成当成功发布。
```

设计理由是让成果说明对应用户真正能获得的东西。预期行为是“D2 草稿已生成，等待批准后向内部团队开放”。失败对照是沙箱打印了一行“saved”，模型就宣布报告已发布，并编造下载地址。

交付也不必强制等待每个附属文件。主报告已完成、附件计算失败时，可以按用户验收先交付部分成果，但必须把缺失范围写清楚。是否满足 Goal，由约定的完成条件判断。

## 推演一次清理与重试

练习：P2 已复制到对象存储，但可用状态尚未提交时进程崩溃；恢复后发现相同内容仍在。随后沙箱临时目录被清理。说明恢复流程与用户可见状态。

预期结果：按稳定产物身份核对对象摘要和大小，满足条件后完成登记，不重复生成新成果冒充第一次；沙箱清理不影响独立存储中的有效产物。审批未完成时仍只交付草稿状态，不能因为文件已持久保存而宣布发布成功。
