# 持续 Goal：下一次 Run 如何接着做，而不是重新猜

前置阅读：[13 课](13-Token预算压缩与历史摘要.md)、[19 课](19-持久化状态机与事实源设计.md)、[20 课](20-幂等外部副作用与未知结果.md)、[24 课](24-运行中纠正取消与限流重试.md)

> 本课的 Goal 和跨 Run 唤醒是教学模型，不表示灵知已提供对应的持久目标或自动唤醒功能。项目当前运行契约及实现入口见[课程索引](README.md#与项目实现的关系)。

报告还有一个证据缺口：方案 B 的更新周期尚未确认。用户说：“等我补上资料，再把报告完成。”当前 Run 可以结束或挂起，但选型报告这个目标仍然存在。下次进来时，助手需要继承进度，不能把所有聊天再看一遍就假设自己理解了现状。

Goal 用来保存跨 Run 的目标、完成条件、进展和剩余工作。它不是一个永不退出的 while 循环，也不是默认允许后台工作或自动发布的授权。

## 将目标和某次推进分开

Run 回答“这次做了什么”；Goal 回答“整个目标还差什么”。本例的 Goal 可以要求：比较约定维度，重要判断有证据，缺口要有明确处理，报告发布需有效批准。它可以关联多个 Run，保留每次贡献的结果。

完成条件应由用户意图决定。用户接受“无法找到更新周期，但报告明确说明限制”，目标可能仍可完成；如果用户要求必须核实该数据，缺口就阻止完成。不能把“模型没有更多想法”作为目标成功条件。

以下是续接摘要的教学示意：

```json
{
  "goal": "形成可供内部团队使用的 A/B 选型报告",
  "goal_revision": 3,
  "completed": ["查询方式比较", "草稿 D1"],
  "remaining": ["核实 B 更新机制", "更新草稿并取得有效审批"],
  "evidence_refs": ["source-a@v1", "source-b@v1"],
  "unresolved_effects": [],
  "next_trigger": "用户提供补充资料",
  "stop_conditions": ["用户取消", "达到预算", "满足约定验收"]
}
```

字段不能只写“继续完善报告”。下一次 Run 需要知道缺哪项证据、已有哪版草稿、在等什么，以及哪些效果仍未核实。摘要是导航，来源与动作记录才是可回查的事实。

## 续接先核对变化，再决定动作

新 Run 开始时，读取 Goal 当前版本与关联成果，核对新输入、当前权限、预算及未决动作。资料可能更新，授权可能撤销，用户也可能换了验收标准。旧 Run 的快照说明历史，不为新 Run 提供永久权限。

如果 Goal 关联一个结果未知的发布 Action，续接的优先任务通常是核对它，而不是再生成一份新报告并发布。否则“长期连续性”反而成为重复副作用的来源。

多个 Run 同时更新 Goal 时，应使用版本条件或明确的协调者，避免一个 Run 把另一项刚完成的工作覆盖回未完成。终态也需一致：用户已经取消的 Goal，迟到的子任务不能把它重新激活。

## 什么时候才应该唤醒

用户补充资料、指定时间到达、某个依赖完成，都可以成为新 Run 的触发条件。调度器需要保存触发身份、去重和领取记录，避免重复事件启动相同推进。

周期运行还需要频率、截止条件和授权范围。用户只说“等我补材料”时，不能顺势解释成每分钟联网检查。没有新事实时重复调用模型，通常只会反复生成相近建议。

阻塞也应有原因：等待资料、等待审批、预算不足或外部效果待核对。系统可以根据不同条件决定是否自动恢复，而不是把所有未完成 Goal 都投入同一个重试队列。

## 给下一次推进一份诚实摘要

在新 Run 受理后，追加续接提示词。输入来自已提交 Goal、成果和动作记录，用户新输入单独保留。

```text
[新增：目标续接]
读取当前目标版本、已完成项、剩余项、证据引用和未决效果。
已有成果先核对后复用，不重复宣称或执行已经确认完成的工作。
新增输入只改变其覆盖的条件，保持仍有效的约束。
存在 unknown 副作用时先说明并核对，不把它当作“尚未执行”。
达到停止条件时报告实际进展、限制与需要的下一触发，不自动扩大目标。
只有约定验收得到满足，才建议将 Goal 标为完成。
```

设计理由是把长期工作转化为有限的一次推进。预期行为是收到 B 新资料后补充相关段落，再进入对新稿的审批。失败对照是为显得持续有产出，重复查询已有证据，或者把“草稿形成”直接汇报成“目标已完成”。

Goal 状态由运行时更新。模型可以提出完成建议，但程序仍检查必要成果、审批和未决效果，尤其不能把流畅的总结当作完成证据。

## 从第二天的视角续写

练习：昨天已有 D1，B 更新周期未核实，发布尚未开始；今天用户提供 source-b@v2，明确批次更新，但仍无延迟测量。写出新 Run 的工作和停止点。

预期结果：固定并引用 v2，更新相关比较生成 D2；不能新增性能结论，也不能借用 D1 的审批。若发布属于目标，推进至 D2 等待审批后挂起；若用户只要草稿，按其验收交付并结束。没有必要重新做与新资料无关的全部研究。
