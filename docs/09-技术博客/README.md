# Agent 工程学习路线：从资料问答到可靠交付

这套 43 课面向有开发经验、希望系统学习 Agent 工程的读者。我们从一个小任务开始：读取两份资料，比较检索方案 A/B，为内部技术团队写一份选型报告。随着任务变长，再加入工具、知识、记忆、专家委派、审批恢复和成果交付。

贯穿案例全部使用虚构资料：source-a@v1 描述关键词匹配与批次更新，没有延迟测量；source-b@v1 描述语义检索，没有更新周期或性能测量。后续课程需要新资料时会明确给出新的教学输入。助手可以起草，正式发布必须取得对相应版本有效的审批。

系列性质是**通用设计教程**。其中的状态、字段、伪代码与策略用于推演，不构成统一产品协议，也不表示已经执行了真实模型评测。示例结果是读者可核对的教学预期。Java、Vue 片段用于解释边界，不配套可运行工程。

## 怎样沿路线学习

按编号阅读即可形成完整路径。每课开头列出必要前置，结尾有相邻课程导航；前置关系只指向更早的课程，上一课不必都是强制依赖。

核心学习可顺序读 01–30，跳过 31 后读 32–33，跳过 34 后读 35–39，跳过 40 后读 41–43。**31 Vue、34 Java SDK、40 计费为按需进阶**：它们分别服务于特定前端、Java 集成和商业化需求，不是理解 Agent 的前提。平台化阶段也可以等到需要服务多个团队时再深入。

不要急着搭建一套平台。各课练习可以先用纸面状态表、伪代码和小样本完成。阶段验收关注“能否解释这个结果如何产生”，不是是否安装了所有依赖。

## 一套贯穿全程的教学术语

| 名称 | 本系列含义 | 不要混同 |
| :-- | :-- | :-- |
| Session | 长期会话，承载持续交流与归属 | 一次模型请求或一次任务 |
| Run | 一次 Agent 任务推进，可含多轮交互、等待与恢复 | 必须只运行一个 HTTP 请求 |
| Execution | 一次 Workflow 执行 | 工具调用、线程或任意执行动作 |
| Action | 一个有明确目的与身份的动作 | 已经成功发生的效果 |
| Attempt | 一次实际调用尝试 | 新的业务意图 |
| Observation | 已提交、供后续决策消费的观察 | 模型自行声明的成功 |
| Goal | 跨 Run 维护的目标与完成条件 | 永不停止的自动循环 |

这是一种教学建模选择。落地到其他系统时可以换名称，但要保留职责和生命周期之间的区别。权限、预算、幂等、审批和状态迁移由运行时执行；提示词指导模型判断与表达，不提供这些硬保证。

## 八个阶段

### 01–05 · 建立单 Agent 基础

前置知识：具备接口调用、结构化数据与基本错误处理经验。

阶段目标：从两份资料形成一次有来源、有缺口说明的问答；分清模型决策与运行事实。

| 课 | 主题 | 学完能解释什么 |
| :-- | :-- | :-- |
| 01 | [从问题回答走向有状态助手](01-从聊天接口到有状态Agent平台.md) | 为什么只保存聊天文本不足以恢复任务 |
| 02 | [Session、Run、Execution、Action 与 Attempt](02-Session-Run与Execution为什么需要分开.md) | 用不同生命周期解释并存任务和调用尝试 |
| 03 | [提示词分层、组装与验证](03-提示词设计总览分层组装与验证.md) | 建立稳定指令、任务、工具、状态、材料、输出六层 |
| 04 | [Agent Loop 与模型输出失败](04-Agent-Loop的动作观察与模型输出失败处理.md) | 选择工具、澄清、等待或结束，消费观察而非计划 |
| 05 | [Agent 与 Workflow 协作](05-Agent与Workflow如何协作.md) | 把探索交给 Agent，把审批和发布交给固定流程 |

阶段验收：给出A/B草稿，引用各自来源；缺少更新数据时不强下结论；审批等待不能被表述为已发布。

阶段目标：接入模型端口，再加入能力发现、受控HTTP、隔离计算和只读并行。

前置知识：能够说明工具结果如何回到下一轮模型输入。

阶段目标：让输入有预算、证据可回读、历史可续接，区分知识与个人记忆。

| 课 | 主题 | 学完能解释什么 |
| :-- | :-- | :-- |
| 16 | [原生 Agent 委派与父子生命周期](16-原生Agent委派与父子生命周期.md) | 给子任务完整输入，等待并消费真实结果 |

## 提示词沿课程逐步生长

[第 03 课](03-提示词设计总览分层组装与验证.md)提供组装总览。后续只加入当前问题需要的片段：

| 决策场景 | 对应课程 | 练习要核对的行为 |
| :-- | :-- | :-- |
| Loop 和流程交接 | 04–05 | 何时调用、澄清、等待、结束；不把受理当完成 |
| 能力发现、HTTP、计算、并行 | 07–10 | 参数满足前提，失败与空结果分开，依赖不被打乱 |
| 上下文、回读和摘要 | 11–13 | 约束与未决事项不丢，必要证据可回原文核验 |
| 知识与长期记忆 | 14–15 | 不跨范围引用，临时要求不永久化，冲突与删除有处理 |
| 委派与团队协作 | 16–18 | 任务可独立理解，结果可核对，失败不被编成成功 |
| 未知结果、审批与运行控制 | 20、22、24 | 不盲重发，不替人审批，不把取消当回滚 |
| 持续目标与成果 | 26–27 | 续接有剩余工作和停止条件，交付状态诚实 |
| 行为验证 | 41 | 核对正常、缺证据、工具失败、未知副作用、委派失败、记忆冲突、越权材料 |

这些课程会交代提示词的使用时机、输入来源、示意模板、设计理由、预期行为和失败对照。数据持久化、前端组件等没有模型决策的地方，不另外塞一段提示词。

完成路线后，可以挑一个自己的只读研究任务，把目标、证据、动作、等待和交付记录画出来。只在遇到具体问题时引入相应机制，更容易判断哪些复杂度有必要保留。
