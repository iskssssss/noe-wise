# Token 不够时，压缩历史但保留因果链

前置阅读：[03 课](03-提示词设计总览分层组装与验证.md)、[11 课](11-模型上下文视图与冻结请求.md)、[12 课](12-工具长输出截断与原文回读.md)

研究与报告助手已经读取两份教学构造资料：`source-a@v1` 支持关键词匹配和批次更新，没有延迟测量；`source-b@v1` 支持语义检索，没有更新周期或性能测量。它要为内部技术团队比较 A/B，并把报告留在待用户审批状态。

随着 Run 推进，上下文里出现用户目标、检索 Action、多个 Attempt、长结果预览、原文回读和草稿修订。若超出模型窗口，最简单的“从最早消息开始删”会把任务为何受限、某条结论来自哪里一并删掉。压缩真正要解决的是模型视图大小，不是清除 Session 中的事实。

## 先划出不能被摘要吞掉的控制事实

上下文内容至少分为两类。控制事实直接影响下一步是否合法，例如当前任务、用户纠正、允许的工具、待处理 Action、审批状态和剩余预算；证据事实支撑报告判断，例如来源版本、原文引用和检索缺口。它们可以缩短表达，却不能被一段“总体来看”替代。

对话寒暄、重复解释和已经闭合的探索过程更适合摘要。工具调用则要按因果单元处理：提出 Action、运行时准入、Attempt 结果、对应 Observation 和模型据此形成的判断应一起保留或一起被摘要。只留下“搜索成功”而删掉查询条件，会让后续模型无法判断成功意味着什么。

下面是压缩前状态的教学示意：

```json
{
  "run_id": "run-report-24",
  "goal": "形成 A/B 检索方案选型报告",
  "facts": [
    {"source": "source-a@v1", "supports": ["关键词匹配", "批次更新"], "missing": ["延迟测量"]},
    {"source": "source-b@v1", "supports": ["语义检索"], "missing": ["更新周期", "性能测量"]}
  ],
  "pending": {"type": "report_approval", "status": "not_requested"},
  "context_tokens_estimated": 14600,
  "context_limit": 12000
}
```

压缩后，运行时仍保存原始事件，只在新模型请求中放入摘要、必要原文引用和当前控制事实。摘要应有自己的版本、覆盖范围和输入引用，例如 `summary-3` 覆盖事件 1—38，但不覆盖事件 39 的用户纠正。恢复时不能因为看见摘要，就把原始事件标成已删除或已失效。

## 用预算分配表达取舍

预算器先按模型协议为输出及必要余量留出空间。输入预算中，稳定指令、当前任务、工具说明与输出约束占用必要额度，当前状态和关键证据也要有保留空间；历史使用剩余额度。具体数字依模型和任务而变，不宜写死在提示词里。

本例中，A/B 的版本、已确认能力、明确缺口和发布需审批必须进入视图。三轮重复搜索的逐字讨论可以压成“相同查询未产生新证据”，但不能压成“已充分验证”。若关键引用仍过长，使用第 12 课的 `result_ref` 回读，而不是把原文复制进摘要。

压缩自身也可能使用模型，因此摘要不是天然可信。运行时应检查引用是否存在、覆盖游标是否连续、待审批事项是否遗漏，并在后续请求里把摘要标成历史投影。权限、Action 预算、Attempt 幂等和审批状态继续由运行时强制，摘要里的“可以发布”不会改变真实状态。

## 生成摘要和消费摘要要分别说明

压缩器使用模型生成摘要时，输入应限定为指定事件范围，另附当前控制事实供核对。可以追加下面的生成片段；它不承担数据库迁移，也不把候选摘要直接变成权威状态。

```text
[新增：生成续接摘要]
只概括指定覆盖范围，保留目标、当前约束、用户纠正、已完成项和未决事项。
每个重要判断保留证据引用；区分工具失败、空结果和尚未读取。
标明等待对象、未知效果及剩余工作，不把计划改写成已完成事实。
不复制无关敏感正文，不用摘要创造新授权。
```

预期输出能让下一轮继续任务，而不丢失“暂不发布”等约束；失败对照是把“拟发布”缩写成“已发布”。候选摘要通过引用与控制字段核对后，才成为可用投影。

## 消费摘要时仍能回到证据

下面的片段在模型视图包含历史摘要时使用。摘要内容和覆盖范围来自压缩器，当前任务、未决事项及预算来自运行时。

```text
[新增：历史摘要使用规则]
history_summary 是对已提交历史的替代视图，不是新的证据来源。
重要结论仍须引用 summary 中列出的 source/version 或原文 result_ref。
current_state 与 events_after_summary 的事实优先于较早摘要；出现冲突时指出冲突，不自行合并。
不得把“未找到测量”改写为“性能较差”，也不得把“待用户审批”压缩成“已批准”。
需要摘要未保留的精确内容时，提出最小范围的回读候选；回读不可用则报告缺口。
```

使用时机是受控压缩完成、下一次 Attempt 准备之前。设计理由是阻止模型把摘要的流畅文字误当成新增事实，同时明确新事件可纠正旧摘要。预期行为是基于版本化证据继续撰写，并保留未知项。失败对照是从“B 没有性能测量”总结出“B 性能领先”，或因摘要出现“准备发布”就宣称审批已经完成。

## 失败路径决定能否重试

若计量器在发送前判断超限，运行时可以先压缩再创建新的模型 Attempt；原来未发送的准备记录不能伪装成供应商已接收。若供应商明确以输入过大拒绝，系统可依据同一任务事实生成更小视图后有限重试，并记录新的 Attempt。

情况在流式调用开始后不同。连接中断时，模型是否已经生成或消费计费可能未知，不能把它简单归类为“超限后安全重发”。运行时要按调用语义处理未知结果；提示词无权宣布重试幂等。

摘要生成失败也不应临时拼接“差不多”的历史。输入引用缺失、覆盖范围断裂或摘要超过自身预算时，可以退回仍能放入窗口的原始最小视图，或者停止准备并说明无法保留哪些必要事实。一个短但丢失审批状态的上下文，不比超限更正确。

## 练习：压缩一条待审批报告链

给定 40 条历史事件，其中 20 条是重复讨论措辞，A/B 各有一次检索和一次原文回读，新近的一条是用户要求“只生成草稿，暂不发布”。请写出压缩视图应保留和可摘要的部分。

预期结果：视图直接保留当前目标、两份资料版本、已证实能力、证据缺口、关键 `result_ref` 和“暂不发布”；重复措辞可摘要，工具 Action 与 Observation 以完整因果单元表示。模型产出内部选型报告草稿，既不虚构性能比较，也不把压缩前的发布建议当成审批事实。
