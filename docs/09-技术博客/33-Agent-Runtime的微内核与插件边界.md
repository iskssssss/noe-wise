# Agent Runtime 的微内核与插件边界

前置阅读：[19 持久化状态机与事实源设计](19-持久化状态机与事实源设计.md)、[32 从运行事实构建执行轨迹与审计视图](32-从运行事实构建执行轨迹与审计视图.md)。

研究与报告助手已经能检索、核验、起草并等待发布审批。随着工具和交付渠道增加，原本围绕 A/B 选型报告写出的逻辑开始承接多个团队的需求。若把这些能力都塞进一个聊天处理器，下一次接入新检索器、审批渠道或团队空间时，改动会迅速互相牵连。

微内核的切入点不是“做一个插件市场”，而是先划出一块不应随业务变化的执行语义。它负责身份、状态迁移、预算、取消、动作账本与恢复顺序；资料检索、文档导出、审批通知和模型协议通过边界接入。这里把长期对话称为 Session，一次 Agent 任务推进称为 Run，一次 Workflow 执行称为 Execution。经受理并登记的动作是 Action；一次实际调用是 Attempt。

## 报告助手的最小内核

报告助手先建立 Run，再依次发起“检索资料 A”“检索资料 B”“比较证据”“请求发布审批”等 Action。内核不需要理解 A/B 的领域内容，却必须保证每个 Action 有稳定身份、当前预算和取消检查。资料 A 的检索器超时，内核只看到可重试、不可重试或结果未知；至于 HTTP、向量库还是本地索引，由适配器翻译。

端口返回外部调用事实，运行时才负责将其归类并提交为 Observation。一个足够小的端口可以这样表达：

```text
invoke(authorized_attempt, deadline) -> completed(raw_result)
                                      | rejected(reason)
                                      | outcome_unknown(receipt)

runtime: validate -> record Attempt -> invoke -> classify -> commit Observation
```

`raw_result` 是适配器给出的外部结果，可能带供应商字段或不可信正文。`Observation` 是运行时用 Action 身份、来源版本和结果分类归一后提交的事实，下一轮模型只能消费这种已提交观察。`receipt` 则是结果未知时留下的查询线索，不是成功凭证。端口没有暴露某家供应商的异常对象，内核因此能用同一条恢复规则处理不同检索器。

## 插件只能扩展能力，不能绕过约束

假设团队新增“引用格式化”插件。它可以声明一个工具、所需资源与输出类型，却不能直接拿到资料库凭据或把报告标为已发布。实际 Action 仍须经过当前权限、预算、幂等与审批检查。可加载不等于可执行；可发现也不等于对当前 Run 可用。

插件版本变化也不该影响已经开始的报告。Run 在准备阶段冻结工具定义和策略引用；新版本供后续 Run 采用。否则报告写到一半，格式化工具换了参数含义，恢复时就无法解释旧 Attempt 实际做了什么。这里冻结的是解释历史所需的版本，并不永久冻结权限：用户撤销资料访问、团队禁用有漏洞的插件或审批窗口到期后，恢复时创建新 Action 仍须按当前授权和安全策略重判。

## 失败处理与取舍

微内核不追求把所有失败吞掉。资料检索返回结果未知时，助手可标记“证据待核实”，不能把它包装成“方案 B 无资料”；审批渠道不可用时，报告保持待发布，而不是绕过审批直接分发。核心的严格，会让外围能力显得受限，却换来可恢复和可审计的边界。

## 内核如何把失败留在正确的位置

资料 A 的检索器超时，可能表示请求根本未发出，也可能已到达外部服务但回包丢失。适配器应提供足以分类的线索；内核再把明确未发出、明确拒绝、可重试失败与结果未知写成不同事实。把它们全压成“没有资料”，会让报告把系统故障伪装成研究结论。

审批通知也不能替代审批状态。通知发送失败时，报告仍待审批；发送结果未知时，系统可以按通知端口的幂等契约查询或重试，却不能宣称审批人已经收到。发布插件只有在内核确认审批、预算和稳定请求键后才会收到调用请求，不能自行把草稿分发出去。

微内核的价值不在于把每种业务都抽象成插件，而在于让变化频繁的实现遵守稳定的事实链。检索器可以从本地索引换成远程服务，审批可以从表单换成回调；只要外部结果回到运行时、由运行时提交 Observation，恢复和审计就不用跟着供应商异常细节重写。

练习：为报告助手列出三个端口：资料检索、报告发布、审批通知。分别写出授权输入、成功、拒绝和结果未知时要返回的最少信息，并标明由谁提交 Observation。

预期结果：三个端口都不携带页面对象或供应商异常作为内核状态；发布端口能用稳定请求键去重；审批通知失败不会改变报告的待审批状态；所有外部结果均由运行时分类、记账并提交 Observation，插件不直接写入 Run 事实。
