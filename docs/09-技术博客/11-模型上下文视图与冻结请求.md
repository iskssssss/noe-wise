# 模型上下文视图：固定这次输入，核对当前准入

前置阅读：[03 课](03-提示词设计总览分层组装与验证.md)、[10 课](10-程序化工具调用与只读并行.md)

研究助手已经会调用工具，现在遇到一个不容易从聊天界面察觉的问题：准备请求时用的是资料 B 的 v1，发送前目录更新成 v2；断线重试时，工具定义又变了。如果程序每次都把“当前聊天”和“当前配置”拼起来，就无法解释同一次任务究竟根据什么作出判断。

上下文视图是面向某次模型决策的输入投影。冻结请求则固定这一次准备的内容和引用。它们既不是全部历史，也不应该成为绕过当前授权的凭证。

## 准备输入，需要挑选而不是倾倒

研究助手当前要比较查询方式和更新信息。source-a@v1 支持关键词匹配与批次更新，没有延迟测量；source-b@v1 支持语义检索，没有更新周期或性能测量。上一次工具调用的原始返回可能很长，模型本轮却只需要与这两个维度有关的片段。

运行时从当前任务版本、已提交 Observation、允许的工具和版本化材料组装视图。模型自行写出的计划不进入“已完成事实”；尚未完成的流式参数也不能作为下一轮已执行动作。

第 03 课的六层边界继续适用：稳定指令定义行为，任务输入说明目标，工具说明提供候选能力，运行状态提供控制事实，参考材料提供证据，输出约束说明消费者需要什么。这里新增的是每一层怎样指回自己的来源，以及何时固定下来。

下面是准备清单的 JSON 示意，不是某个供应商的请求格式：

```json
{
  "request_ref": "request-17",
  "task_revision": "T2",
  "instruction_version": "instruction-3",
  "tool_set_version": "tools-5",
  "observation_refs": ["observation-11", "observation-12"],
  "source_refs": ["source-a@v1", "source-b@v1"],
  "summary_ref": null,
  "output_contract": "comparison-draft-1"
}
```

仅有引用能否重建原请求，取决于被引用内容是否不可变且仍可取得。需要重现实际发送字节时，可以保存规范化请求或其受控存储引用。哈希可以校验内容一致，却不能从不存在的原文中恢复内容。

## 冻结一个请求，不冻结整个会话

冻结完成后，该请求的消息、工具映射、模型配置和引用不应静默变化。源资料更新时，旧请求仍解释旧判断；采用新材料需要一次新的准备记录，可以在当前 Run 的新决策点发生，也可以按任务范围创建新的 Run。

这与固定任务资料范围不冲突。若用户明确要求“全篇只依据 v1”，就不能仅因发现 v2 而自动换版；若用户补充新材料修订任务，则记录新的任务版本，再组装下一份请求。变化需要可追踪，不需要假装永远不能变化。

冻结也不等于保存所有正文直到永远。敏感资料、记忆和工具结果各有保留与删除规则。记录可以保留必要元数据、内容摘要或不可恢复的删除标记；原文不再可用时，应诚实说明无法重现完整输入，而不是自动找一份相似材料补上。

## 发送前还有一次当前准入

准备时允许的动作，在发送时可能已经不允许。用户取消、权限撤销、预算用尽或能力停用，都需要执行端再次检查。

```text
# 伪代码：冻结内容和当前准入承担不同责任
prepared = assemble(current_task, committed_observations, allowed_sources)
frozen = persist_preparation(prepared)
if not admissible_now(frozen, current_permissions, cancellation, budget):
    mark_not_sent(frozen)
else:
    attempt = record_attempt(frozen)
    send_exact_prepared_request(attempt)
```

校验与实际发送之间仍可能存在竞态，执行器应尽量缩短窗口，并按动作风险设计撤销语义；冻结记录不会消除这个物理边界。若请求已发送，系统不能声称权限撤销让模型从未看过材料，而应限制后续动作及结果披露。

资料读取权限与报告发布权限也要分开判断。撤销发布权限，不一定禁止继续处理仍获准的资料；撤销资料访问，则可能阻止把相关内容继续发送到模型。明确目标与效果，才能避免用一个笼统的 denied 解释所有情况。

## 模型需要知道视图有哪些限制

使用时机是当前请求包含裁剪资料、历史摘要或被排除内容时。输入来源是准备器给出的覆盖范围、当前状态和引用清单。追加到基础模板的片段如下：

```text
[新增：当前视图的范围]
current_task_revision 与 current_state 表示本轮生效的任务和已提交状态。
reference_materials 只覆盖 preparation_manifest 中列出的来源版本。
未进入视图的内容不代表不存在；需要关键细节时提出受控读取候选。
历史摘要、工具预览与原文分开引用，不把概括当逐字证据。
若运行时返回引用失效或当前禁止使用，说明限制，不用记忆补写原文。
```

设计理由是让模型知道“我本轮看到了哪些材料”，而不是误以为上下文等于整个世界。预期行为是只根据 A/B 的已展示证据生成草稿，必要时回读；失败对照是把新目录中的 B@v2 当成自己在旧请求里已经看过的内容。

## 检查两种恢复方式

练习：请求 request-17 已固定 B@v1，但尚未发送；随后用户撤销 B 的读取权限，并提供 B@v2 作为另一个待处理任务。说明旧请求与新任务各自如何处理。

预期结果：旧请求保留其准备身份，发送准入因 B 的权限变化失败，不能用 v2 偷换；新任务单独核对材料授权并准备新输入。若旧原文后来按策略删除，记录说明不可重现，不声称已完整回放。任何报告发布仍须有针对对应版本的有效审批。
