# 多租户与服务身份权限范围

前置阅读：[33 Agent Runtime 的微内核与插件边界](33-Agent-Runtime的微内核与插件边界.md)、[36 模板安装](36-Agent模板发布与机构安装.md)。

研究与报告助手要为甲团队比较两个虚构方案：方案 A 使用关键词匹配并支持批次更新，方案 B 使用语义检索但缺少更新机制说明。报告只供团队内部使用，发布前必须由审批人确认。此时最危险的错误不是结论写得不漂亮，而是检索到乙团队资料，或让一个后台服务替用户发布报告。

本文所有案例、字段与伪代码均为教学示意，不代表任何具体系统的当前行为。

## 认证先建立可信租户上下文

请求里的 `tenantId`、模型生成的资源 ID、附件中的指令都属于不可信输入。认证层应从登录凭据、服务端成员关系和受控配置中建立 `TenantContext`，随后把它交给应用层。即使请求参数声称属于甲团队，也不能覆盖认证结果中的乙团队身份。

一次有效授权可以理解为以下交集：调用者权限 ∩ 租户策略 ∩ Agent 获准能力 ∩ 当前 Action 所需范围 ∩ 资源自身访问规则。交集之外的资源必须在读取点被拒绝，而不是先读出全文再靠模型“自觉忽略”。认证回答“是谁”，授权还要回答“能以什么身份对哪项资源做什么”。

Session 是长期会话，可保存甲团队这个不可跨越的归属；Run 是一次“比较 A/B 并生成报告”的任务推进。Run 内的检索、生成和提交审批分别是 Action，每次真实外调是 Attempt。它们都引用可信租户上下文，但执行每个 Action 时仍要重新核对成员是否停用、策略是否收紧、资源是否移出范围。历史身份快照用于审计，不能充当永久授权。

下面的 JSON 是消息信封示意，语法可直接解析；实际字段应由服务端写入并防篡改：

```json
{
  "tenantId": "tenant-a",
  "runId": "run-compare-a-b",
  "actionId": "action-retrieve-evidence",
  "actorId": "user-17",
  "servicePrincipalId": "sp-retrieval-worker",
  "scopes": ["document:read"],
  "policyVersion": "policy-8"
}
```

## 让隔离进入每个数据入口

关系查询应把租户和资源授权条件写入查询本身；向量检索也必须在候选召回阶段按可信租户元数据过滤，不能从全局向量结果中事后删掉越权片段。若向量库无法可靠执行过滤，应按租户分区或改用能证明隔离的索引结构。返回的文档引用还要再次核对归属，防止脏索引把乙团队片段标成甲团队资源。

缓存键至少要区分租户、资源、权限相关版本和结果形态。只用“比较方案 A/B”作为键，可能让甲团队命中乙团队生成的摘要。缓存命中不是授权证据；读取缓存时仍应验证当前上下文，权限收紧后也要避免继续供应旧结果。

异步边界会丢失线程局部变量，因此入队时要记录受保护的身份引用，消费时重新加载主体、租户、策略和资源状态。若信封缺租户、租户与 Run 归属不一致、策略版本已失效，worker 应失败关闭。审批回调即使签名正确，也只能恢复原租户、原 Run、原等待项和匹配版本的 Action；它不能凭一个合法签名推进任意报告。

## 服务身份要小到无法被借权

检索 worker 的 ServicePrincipal 只需要读取获准资料，不需要发布报告；发布服务只需要读取已审批成品并执行发布，不需要访问原始资料库；通知服务只需要收件人与状态摘要。若三者共用管理员身份，攻击者只要让模型或用户参数提供一个乙团队资源 ID，就可能诱使高权限服务代为读取，这就是混淆代理问题。

防线不只是“检查一次 tenant”。资源定位必须以可信上下文为根，服务身份与发起用户权限取交集，写入目标也要绑定原 Run。错误投影同样需要隔离：用户可以看到“方案 B 的更新信息不足”，但不能看到乙团队文档标题、索引路径或原始异常。运维诊断权限应另行授予并留痕。

按案例推演：甲团队提交 Run 后，检索 Action 只召回甲团队的 A/B 资料；B 的更新说明缺失，生成 Action 把它写成证据缺口；提交审批 Action 产生甲团队等待项；审批人在权限撤销后回调，即使签名有效也会被拒绝；只有身份、租户、等待项、版本和当前状态全部匹配，发布 Action 才能启动。

## 小练习：找出三个拒绝点

教学设定：可信上下文是 `tenant-a`，检索 worker 只有 `document:read`；模型请求读取 `tenant-b/doc-9`；缓存中存在由旧策略生成的甲团队摘要；审批回调指向正确 Run，但审批人已被移出甲团队。

请分别判断检索、缓存读取和审批恢复能否继续，并说明检查位置。

预期结果：检索在资源查询前因租户不匹配被拒绝，不能先取回文档；缓存不能仅凭命中直接返回，必须按当前权限与策略复核；旧版本不再有效且无法确认可复用时，应失效并重新读取；审批恢复因当前成员关系失效而被拒绝。三个结果都不依赖模型声明的租户，且任何拒绝响应都不泄露乙团队资源是否存在。
