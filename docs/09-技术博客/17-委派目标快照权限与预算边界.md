# 委派目标快照：记住当时要做什么，不把当时权限变成永久通行证

> 本文关于预留或划分子任务预算的讨论是通用设计选择；当前委派不提供父子预算分割协议，实际按角色比例派生并共享根账本。

前置阅读：[03 课](03-提示词设计总览分层组装与验证.md)、[16 课](16-原生Agent委派与父子生命周期.md)

研究助手把资料 B 的核验委派给子 Agent。资料 B 只说明语义检索，没有更新周期或性能测量；父任务要把它与采用关键词匹配、批次更新但没有延迟数据的资料 A 比较，并为内部技术团队形成选型报告。子任务创建后，系统可能更新资料版本、撤销读取权限，父任务也可能已经消耗大部分预算。恢复时若只看“B 核验任务”这几个字，我们既无法重现当时目标，也容易误用现在的环境。

目标快照用于回答“这个子 Run 当时被要求根据什么完成什么”。它固定任务说明、输入引用、结果合同、委派关系和初始限制。它不复制整个父 Session，也不把父任务曾经拥有的能力变成子任务的永久授权。身份快照用于追溯，当前权限和剩余预算仍由运行时在每个 Action 前强制检查。

## 快照应该固定哪些输入

下面是教学示意，不是统一存储协议：

```json
{
  "delegation_id": "dg-b-01",
  "parent_run_id": "run-report-07",
  "objective": "核验资料 B 的查询方式、更新信息与性能证据",
  "input_refs": [{"source_id": "source-b", "version": "v1", "scope": "full"}],
  "result_contract": ["facts", "missing", "citations", "status"],
  "capability_ceiling": ["read:source-b"],
  "reserved_budget": {"model_tokens": 12000, "tool_calls": 4},
  "created_at": "示意时间"
}
```

`input_refs` 应引用确定版本，而不是“读取最新 B”。否则同一个子 Run 在重放时可能看到另一份内容，父任务却以为结果仍来自原资料。`capability_ceiling` 是父任务允许委派的最大范围，不是实时权限票据；它表示子任务永远不能超过这条上限。真正读取前还要检查调用主体当前是否有权访问 B、该版本是否仍可披露，以及预算是否仍可用。

预算也不只是一个 Token 数。模型调用、工具次数、执行时长、费用和可创建子任务数都可能受限。父任务给两个子任务各“无限使用剩余预算”，会造成并发超卖。更稳妥的做法是预留或划分额度：子任务消费自己的上限，未使用部分在终态后释放；追加额度必须形成新的受控决定，并且不能超过父任务当前可支配范围。

## 看一遍权限变化的时序

t0，父 Run 有权读取 A、B，但没有发布权，于是创建 B 子 Run 并固定 B@v1。t1，子任务读取 B@v1 成功，持久结果是“语义检索；更新周期缺失；性能测量缺失”。t2，管理员撤销该主体对 B 的读取权限。t3，子模型为了补证，提出重新读取 B 的 Action。

t3 的 Action 必须被运行时拒绝。目标快照能证明 t0 的任务范围，却不能证明 t3 仍有权限。已经提交的 t1 事实是否还能进入父结果，要按当前披露策略判断；至少不能偷偷发起新的读取。若策略允许使用既有结果，父任务可以在 D1 中引用已取得的 B@v1 事实并记录来源；若当前策略禁止披露，就只报告该分支受限，不把内容带回父任务。

t4，子模型又请求资料 C 来推测 B 的性能。即使父任务当前能读 C，这也超过委派快照的输入范围和能力上限。运行时应拒绝或要求父任务显式修订目标，不能让一句“完成任务所需”无限扩张授权。t5，父任务汇总 A/B，写出 D1：可以比较检索方式，不能比较速度或更新及时性。之后按审阅意见形成 D2，发布仍需单独审批。

## 给委派提示词补上边界意识

下面的片段接在第 03 课基础模板和第 16 课委派片段之后，用于子模型选择下一动作时。目标与输入引用来自委派快照；当前可用工具、权限检查结果和剩余预算来自运行时，不能由模型或快照自报。

```text
[新增：委派范围与资源]
只处理委派目标列出的子问题，并以指定版本的输入引用作为证据范围。
快照中的能力范围是上限，不代表当前仍获授权；只能从本轮工具说明选择候选动作。
权限被拒绝或预算不足时，返回已完成部分、具体缺口和阻塞原因，不改写目标来绕过限制。
不得自行请求范围外资料、创建新的子任务或发布最终报告。
结果中区分：已核验事实、没有提供的信息、因权限或预算未能核验的信息。
```

设计这段提示词，是为了让模型在受限后仍能形成诚实、可汇总的结果。预期行为是 B 子任务在预算只剩一次调用时优先核对目标所需证据，并在读取被拒后返回 `blocked` 与缺口。失败对照是把创建时的 `read:source-b` 当作永久授权，或在预算耗尽后继续生成调用。运行时必须拒绝这些 Action；提示词只能改善候选选择，不能承担安全控制。

## 快照越完整，代价也越真实

固定输入有助于审计和恢复，但会增加存储与版本保留成本。过度复制父上下文还会把无关敏感材料带入子任务。实践中应固定可解释任务所需的引用和约束，并让材料正文留在受治理的版本存储中。快照保存“引用了什么”，不必总是复制“所有内容”。

预算切得过细会让子任务频繁申请追加，切得过松又降低父任务对总成本的控制。可以按风险和可预估性选择：稳定核验任务预留固定额度，探索任务设置硬上限并允许父任务在看到阶段结果后追加。无论采用哪种策略，并发扣减都要由运行时原子处理，不能让多个模型凭提示词协调余额。

## 小练习

B 子任务在创建时获准读取 B@v1，预留三次工具调用。它已调用两次；随后读取权限被撤销，模型请求读取资料 C，并声称 C 可能包含 B 的性能数据。父 Run 仍能读取 C。系统应怎样处理？

预期结果：拒绝这次 Action，因为 C 不在目标快照范围内；即使改回读取 B，也会因 B 的当前权限已撤销而被拒绝。已消耗预算保持两次，不把拒绝伪装成一次成功读取。子任务返回已核验事实与缺口；父任务可形成带限制的 D1，但不能声称 B 的性能已比较，更不能发布报告。
