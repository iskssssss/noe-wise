# 长期记忆不是聊天摘抄：从候选提取到受控使用

前置阅读：[03 课](03-提示词设计总览分层组装与验证.md)、[11 课](11-模型上下文视图与冻结请求.md)、[14 课](14-知识检索版本固定与证据追踪.md)

研究与报告助手正在比较两份教学构造资料：`source-a@v1` 支持关键词匹配和批次更新，没有延迟测量；`source-b@v1` 支持语义检索，没有更新周期或性能测量。报告面向内部技术团队，发布需要用户审批。

用户在当前 Run 中说“这次报告不要营销语言”，这是一条临时约束。若用户明确说“以后给我的内部技术报告都避免营销语言”，才出现长期偏好候选。把每句话都永久记住，会让一次性的要求污染未来任务，也会积累不必要的敏感内容。

长期记忆应拆成提取、召回和使用三条链。提取判断一句话是否值得成为候选；召回在新 Run 中按主体、范围和当前授权筛选；使用决定它怎样影响当前输出。三条链分开，才能处理纠正、删除、冲突和披露边界。

## 提取：先形成候选，不直接改写用户画像

以下用户话语均为教学构造。当前 Run 的“这次不要营销语言”保留在任务输入；跨任务表述“以后内部技术报告都避免营销语言”可以形成候选，但仍需经过产品策略规定的确认或写入规则。

提取模板在一轮输入被受理后使用。输入来自已提交的用户消息及其 Session、Run、主体和用途元数据；设计理由是让模型标注证据与适用范围，而不是生成无来源画像。

```text
[记忆提取候选]
只从用户明确表达或经确认的事实中提取，不从助手推测中创建偏好。
区分 run_constraint、durable_preference、profile_fact 和 do_not_store。
输出候选的 subject、scope、source_event、sensitivity、suggested_value 与置信依据。
含凭据、完整私密正文或与未来任务无关的细节时，选择 do_not_store 或最小化表达。
“这次”“本报告”等局部措辞默认属于 run_constraint，除非用户明确扩展范围。
```

预期行为是把“这次不要营销语言”留在当前 Run，把“以后内部技术报告……”标成待治理的长期候选。失败对照是直接保存“用户讨厌营销”这种扩大范围的推断，或者把整份报告正文复制进记忆。

## 召回：相似不等于有权使用

新的 Run 要写另一份内部技术报告时，召回器先按当前主体、租户或空间、用途、有效版本、敏感度和删除状态过滤，再做相关性排序。向量相似度只能在允许集合内排序，不能跨越权限边界。

召回模板在模型请求准备之前使用。输入来自当前任务和运行时已经过滤的记忆投影；设计理由是避免模型看见本不应披露的候选后再被要求“自行忽略”。

```text
[记忆召回筛选]
仅评估运行时提供的 allowed_memory_candidates，不请求或猜测其他主体的记忆。
优先选择与当前任务 scope 直接匹配、仍有效且来源可追踪的条目。
run_constraint 不跨 Run 召回；deleted、superseded 或 pending_confirmation 条目不可作为偏好使用。
候选互相冲突时同时返回冲突标识，不按更新时间或相似度自行决定用户真实意图。
在当前任务不需要时返回空集合，避免为了“个性化”强行加入记忆。
```

预期行为是仅为新的内部技术报告召回“避免营销语言”，而不给普通聊天强加这一风格。失败对照是因为词语相似，在公开营销文案任务中套用内部报告偏好，或继续召回已经删除的旧值。

## 使用：记忆提供默认值，当前指令可以覆盖

记忆进入模型视图后仍不是最高优先级命令。当前用户指令可能临时覆盖长期偏好，例如“这次需要一页有说服力的管理层摘要”。系统应保留覆盖范围，不应据此把长期偏好反向改写。

使用模板在组装当前任务提示词时加入。输入来自本 Run 的明确约束和已授权召回结果；设计理由是让冲突处理可见，并防止模型把偏好当发布授权。

```text
[记忆使用规则]
memory 是当前任务可用的辅助上下文，只在其 subject 与 scope 匹配时采用。
当前用户明确指令优先于可覆盖的长期偏好；只对本 Run 生效的覆盖不修改长期记忆。
记忆与当前指令冲突且适用范围不清时，提出最少澄清问题，不暗自选边。
不得从偏好推导权限、身份、事实结论或发布批准。
输出无需披露无关记忆内容；需要说明个性化来源时，采用最小必要表述。
```

预期行为是让 A/B 报告保持克制表达，同时仍明确指出证据缺口；发布继续等待用户审批。失败对照是根据“内部技术报告偏好”自动公开报告，或在回答中复述用户过去的敏感原话。

## 纠正、删除与冲突都要改变新请求

用户说“纠正一下，我只是不希望选型报告使用营销语言，其他内部报告不限制”，系统应创建范围更窄的新版本，并把旧条目标为被取代。新的模型请求只召回修正后的投影。若用户直接要求删除，召回索引和可用投影应及时不可见；缓存也不能继续返回旧值。

审计可以保留“某条记忆在某时被创建、纠正或删除”的最小事件，以解释状态变化，但这不意味着永远保存敏感全文。保留期、脱敏和删除义务由治理策略决定。冻结的已发送请求可以记录当时引用过哪个记忆版本，却不因此获得未来披露许可；尚未发送的请求在删除或权限撤销后必须重新检查并停止使用。

冲突不一定能靠“较新者胜出”。“技术报告要简短”和“选型报告要包含完整证据表”可能分别适用于不同范围；“以后都写详细”则可能真正修正旧偏好。运行时保存版本关系和状态，模型在范围仍不清时询问用户。权限、预算、幂等、删除状态与发布审批均由运行时强制，提示词只指导候选判断和表达。

## 练习：删除偏好后继续同一 Session

先让用户明确建立“以后内部技术报告避免营销语言”的长期偏好，在新的 Run 中召回并生成 A/B 草稿；随后用户删除该偏好，并要求再生成一版。设定第一版模型请求已发送，第二版尚未准备。

预期结果：第一版的审计记录可说明它使用了哪个记忆版本，但不会把敏感全文当作永久审计附件，也不会授权继续披露；删除后召回投影和缓存不再返回该偏好，第二版请求不使用它。A/B 事实仍严格来自两份资料，报告发布状态也仍由用户审批决定。
