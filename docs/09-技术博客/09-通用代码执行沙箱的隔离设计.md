# 代码沙箱：让报告计算拥有可控的输入和出口

前置阅读：[04 课](04-Agent-Loop的动作观察与模型输出失败处理.md)、[07 课](07-Skill按需加载与工具发现.md)

用户补充了一份样本 CSV，希望研究助手统计不同查询类型的数量，放进报告。模型直接心算很容易出错，调用代码工具更合适。可是，一旦允许生成的代码执行，文件、网络、进程和资源就都进入了讨论范围。

本课把代码执行限定为一项受控能力：读取获准的输入，在隔离环境中计算，把声明的结果交回运行时。它不是让模型获得应用服务器的普通 shell。

## 隔离进程只是开始

代码不应在承载业务服务的进程里直接运行。独立执行环境还需要明确的文件挂载、进程权限、网络策略、CPU/内存/运行时间和输出大小限制。

容器能够提供一部分隔离，但“用了容器”不能概括全部安全边界。宿主内核、挂载方式、特权配置和运行时漏洞仍然影响风险。高风险、多租户的任意代码可能需要更强隔离；具体方案取决于威胁模型和可接受成本。

研究助手的计算任务可以从很小的能力集合开始：一个只读输入目录，一个单独的可写输出目录，默认不出网，不挂载宿主凭据。输入来自上传文件的受控引用，而不是模型随意传入的主机路径。

## 输出文件也需要检查

代码生成 report.csv，不意味着它已经成为正式成果。执行端应校验文件确实位于允许的输出目录，限制数量和大小，防止路径穿越、符号链接或其他间接引用绕到宿主文件。

执行返回至少要区分退出状态、标准输出、错误摘要和产物清单。标准输出写了“成功”，但进程非零退出或产物缺失，不能按成功处理。反过来，有警告文本也不一定表示计算失败，应用应按明确契约判断。

下面是任务规格伪代码，不对应某种沙箱产品：

```text
sandbox_task:
  inputs: [authorized_csv_reference]
  input_mount: read_only
  writable_area: isolated_output
  network: disabled
  runtime: pinned_environment
  limits: cpu, memory, duration, process_count, output_bytes
  expected_outputs: [summary_csv]
result:
  exit_status, error_kind, stdout_reference, output_manifest
```

固定环境有助于复现，但不能保证所有程序确定性。随机种子、依赖、时钟和输入版本都会影响结果；任务需要可比较结果时，应把相关条件记录下来。

## 让模型描述计算，而不是扩大访问面

使用代码工具前，在第 03 课模板中增加计算约束。输入来自用户任务、已经核验的文件引用、运行时提供的沙箱能力和结果清单。

```text
[新增：代码计算]
说明要从哪些已提供字段计算什么结果，不补造缺失值或单位。
只使用授权输入引用和声明的输出位置。
缺少字段时报告数据缺口，不通过网络寻找替代的私有数据。
执行失败时读取结构化错误；允许修正时只改变与失败相关的代码或参数。
只有 exit_status 与产物清单满足工具契约，才报告计算已完成。
报告注明统计范围；样本统计不能直接推广为真实生产性能。
```

设计理由是让代码能力服务于明确计算。预期行为是先核对 CSV 的 query_type 列，再统计各类数量。失败对照是发现列不存在后随机猜测列名，或将样本中较多的一类写成“业务用户普遍更喜欢”。

提示词不能限制真实文件权限，也不能结束失控子进程。执行器负责强制限制、回收资源和校验产物，模型只负责提出计算方案并解释可确认的结果。

## 超时之后，怎样继续才合理

对于只在隔离临时区计算的任务，超时后可以终止整个任务环境，保留错误记录，并在检查输入和资源需求后重试。重试前要确认残留进程和旧输出不会混入新结果，不能仅仅杀掉父进程就假设子进程都结束了。

如果代码能够调用外部写接口，超时就可能产生未知副作用，恢复会复杂得多。本阶段默认关闭网络，正是为了让计算与外部发布分开。确需外部写入时，应通过独立工具表达动作，而不是藏在任意脚本里。

## 手算一份很小的输入

练习：构造三行样本，query_type 分别为 keyword、semantic、keyword。让示意程序输出分类计数；随后删除列名，再推演一次执行。

预期结果：正常输入得到 keyword=2、semantic=1、总数=3；报告说明这是给定样本的统计。缺少列名时应得到明确错误或数据澄清，不能继续生成貌似正确的表格。输出位于受控临时区，尚未自动发布为正式报告。这项练习可在纸上核对，不要求搭建运行环境。
